# 分析与实验

用 `skill_reference_read` 先读取本 Skill 的 `resource-map.md`，再按数据声明、统计、科研图件或实验日志选择对应 Nature 资源。可重复的图件检查与后端选择使用已集成脚本；任何上游模板或示例都不能替代本 Skill 的真实执行和结果核验。

## 专业工具

使用科研数据库或专业工具前，严格调用 `scientific_tool` 的 `discover → inspect → run`；不得只凭工具名称猜参数。记录工具 ID、版本、真实参数、输入数据来源、数据更新时间、许可证/引用要求、开始/结束时间和原始状态。工具未配置、限流、超时或许可未知时返回真实 `unavailable`/错误码，不得模拟结果。

## 数据分析检查与执行

1. 开始分析前先检查输入文件是否存在且位于当前工作区、文件格式、字段名、字段类型、记录数、缺失值、重复值、数据版本/哈希和分析目标。保留检查结果；字段缺失、类型不符、数据损坏或缺失处理策略未确定时，停止相关分析并请求用户决定，不猜测、静默填补或改变数据。
2. 对 CSV、TSV、JSON、JSONL、XLSX 等简单表格查询，优先使用 `dataframe_query`；只有需要统计、机器学习或领域软件时才生成脚本并用 `exec` 实际运行。图表通过 `chart` 生成时同样记录输入和参数。
3. 代码生成后必须实际运行，检查完整命令、工作目录、退出码、标准输出、错误日志、输出文件和生成文件。代码“看起来正确”、模型给出一个数字或没有日志，都不等于实验完成；退出码非零、输出缺失或指标无法读取时禁止报告成功，不能报告成功。
4. 每次分析通过 `research_record` 保存：输入数据 SHA-256/版本、代码或补丁、命令、工作目录、依赖版本、参数、随机种子、退出码、stdout/stderr、指标和生成文件。输出写入 `research/<task_id>/experiments/<run_id>/`，原始数据保持只读。

## 算法想法验证

只有以下启动条件全部具备时才自动验证算法想法：可运行代码或明确修改位置、固定数据/开发集、能成功运行的基线、唯一主指标、`maximize`/`minimize` 优化方向，以及用户指定或验收配置给出的迭代/时间/费用预算。缺少任一条件时只提出方案并列出缺口。

最小循环：

```text
检查数据与代码
→ 使用同一评价命令运行并锁定基线
→ 基于论文、代码或误差分析提出一个候选
→ 在隔离副本应用补丁
→ 使用同一数据口径和主指标执行候选
→ 从真实指标文件/日志读取并比较
→ 记录接受/拒绝及理由
→ 未耗尽预算时再进入下一候选
```

- 每轮只提出一个候选；通过 `research_record.experiment_start`/`experiment_finish` 记录基线与候选的补丁、命令、日志、退出码、数据哈希、指标和决定理由。指标必须来自真实 JSON 文件或已保存 stdout 的确定性解析，不接受模型直接提交数值。
- 基线失败、指标解析失败、数据哈希变化、命令口径变化或预算耗尽时立即停止；没有超过基线时如实返回“本轮无改进”，不选择最接近成功的结果。
- 候选在独立实验副本运行，默认不覆盖原始代码或数据；获胜补丁作为 Artifact 交付，只有用户明确要求才应用回原项目。最终测试集只在候选选择后运行一次，不参与生成候选或开发阶段调参。
- 数据含可识别患者/受试者信息时禁止发送外部服务；外部写入、付费调用和受管制计算遵守权限与人工确认边界。
