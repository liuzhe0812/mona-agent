# 引用与文献真实性审计

## 适用边界

用于用户给出参考文献、DOI/PMID、稿件引用或具体论据，要求确认文献是否存在、引用信息是否准确、原文是否支持该论据、是否有冲突/更正/撤稿记录时。首次建立文献候选集使用 `literature-search`；要系统提取论文内容使用 `paper-reading`。只审计用户指定的引用和论据，不主动改写整篇稿件。

用 `skill_reference_read` 先读取本 Skill 的 `resource-map.md`，按单条、批量、文稿引文提取、补引用或格式导出选择对应 Nature 资源。批量分段、检索和导出优先使用已集成 `nature_citation.py`；脚本返回的候选仍必须按正文规则核验内容支持。

## 审计工作流

1. 先逐条保留用户提交的原始引用和上下文，规范化 DOI、PMID/PMCID、题名、作者、期刊和年份；不能因格式可疑而静默修正或替换引用。
2. 优先用稳定标识符获取官方或权威元数据；没有标识符时用完整题名、首位作者和年份检索。核对题名、作者、期刊/会议、年份、版本、标识符和 URL 是否指向同一作品；重复发表、预印本/正式版和更正版本要明确区分。
3. 将“文献存在”和“文献支持论据”分开判断。存在性可由可信元数据确认；支持关系必须读取原文相关段落、图表、表格或摘要，并记录精确定位。仅有题名、搜索摘要或二手转述时，不得判为内容已支持。
4. 对每条论据给出 `supports`、`partial`、`contradicts`、`not_addressed` 或 `insufficient_evidence`，说明证据文本、定位、适用人群/条件和限制。若原文与引用表述的强度、因果方向、样本范围或结论边界不一致，指出具体差异。
5. 检查元数据冲突、撤稿/更正、版本和作者/年份错配时，只依据已核验的权威记录报告。来源超时、限流、不可达、全文缺失或需要登录时保留 `source_unavailable`、`fulltext_unavailable` 或 `user_action`；不能把“无法核验”写成“引用不存在”或“论据不成立”。

## 记录与交付

用户要求研究记录或可交付成果时，使用 `research_record` 保存核验来源和声明。引用真实性和内容支持的审计表至少包含：

```text
原始引用/引用键
匹配的 source_id、DOI 或 PMID
元数据核验状态
内容支持状态
证据文本与 locator（页码/章节/图表；仅摘要标记 abstract）
不一致、限制或缺失原因
建议动作
```

关键声明写入 `claims.jsonl` 时遵守记录模型：`fact` 必须有 `source_ids` 和定位，`inference` 必须有依据，`hypothesis` 必须保持待验证；`supports` 仅填写真实的 `support`、`conflict` 或 `context`。把审计结果与实际来源 ID 关联，保留核验时间和 provider。

审计状态至少区分：

- `verified`：身份和所声明的内容均有可定位原文支持。
- `metadata_verified_content_unverified`：文献身份确认，但尚未获得足以判断论据的原文。
- `mismatch`：引用与实际作品的作者、题名、年份、版本、标识符或论据不一致。
- `not_found`：在已说明的可用来源和检索边界内未找到匹配，不代表文献绝对不存在。
- `source_unavailable`：关键核验来源不可用，不能下存在性结论。

交付时逐条列出通过、待核验、冲突和不匹配项；未被用户要求时只给修正建议，不直接改动稿件。严禁编造 DOI、PMID、作者、期刊、页码、原文引语、撤稿状态或“已核验”结论。
