# 学术评审与回复

## 适用边界

用于投稿前模拟审稿、评估稿件风险、解析真实审稿意见、制定修改计划和起草逐条回复。普通段落润色使用 `manuscript-editing`；未要求审稿时不要主动扩大为全稿评审。

用 `skill_reference_read` 先读取本 Skill 的 `resource-map.md`，再根据“模拟审稿”或“真实审稿回复”只加载对应 Nature Reviewer/Response 资源。LaTeX 回复包需要一致性检查时运行已集成脚本。

## 模拟审稿

1. 仅依据用户提供的稿件、补充材料和可核验来源评价，不假设不存在的数据、实验或期刊要求。
2. 每个问题使用稳定编号，包含：位置、问题、证据、严重性、为何影响结论、最小可执行修复和无法判断的信息。
3. 区分致命方法问题、主要问题、次要问题和编辑性建议；不要用角色扮演制造没有证据的反方意见。
4. 明确评审边界：未获得原始数据、代码、伦理材料或目标期刊要求时，不声称已验证复现性、统计正确性或合规性。

## 审稿回复

对每条原评论保持一一映射：

```text
评论编号与原文：
处理决定：修改 | 解释 | 补实验 | 不同意
证据/实验依据：source_id、证据定位或成功 run
修改位置：章节、段落、图表或待办
回复草稿：
剩余风险：
```

- 只有实际读取修改后的文件或真实实验输出后，才能写“已修改”“已补充”或“结果表明”。尚未执行时使用将来时并列为待办。
- 不同意审稿意见时保持合作语气，以方法、范围或证据解释，不揣测审稿人动机。
- 引用或事实存在争议时临时追加 `citation-audit`；不要在本 Skill 内自行假定引用有效。

交付前检查每条评论均有响应、修改位置可定位、承诺与实际完成状态一致，并列出仍需作者确认或执行的事项。
