# 科研文本起草与编辑

## 适用边界

用于论文或基金文本的大纲、起草、重写、压缩、扩写、润色和翻译。用户只要求编辑一段文字时，只处理该段，不自动扩展为整篇论文、文献综述或投稿流程。引用真实性核验使用 `citation-audit`，评审意见处理使用 `review-response`。

用 `skill_reference_read` 先读取本 Skill 的 `resource-map.md`。根据任务只加载 Nature Writing 或 Nature Polishing 的核心层，以及一个匹配的论文类型、语言、期刊和章节片段；不要把全部示例和期刊规则同时注入上下文。

## 事实边界

1. 优先使用用户提供的原文、当前任务的 `sources.jsonl`、`claims.jsonl` 和成功实验记录。事实性陈述必须能追溯到来源、证据定位或成功 run；缺失时保留待核验标记，不补写。
2. 严格区分来源作者陈述、已验证事实、Agent 推断、研究假设、方案建议和待补信息。不得为增强语气而改变证据强度、因果关系、样本范围、统计结果或研究局限。
3. 润色与翻译保持原意、数字、单位、引用标记和术语一致。原文存在逻辑跳跃、过度推断或证据缺口时指出问题，不静默修成看似成立的结论。

## 按请求交付

- 大纲、引言和相关工作：呈现问题、研究价值、已有路线和证据缺口，不虚构研究空白。
- 方法：只写已记录的对象/数据、变量、流程、参数和统计方法；未知项标记待补。
- 结果：只写真实成功实验的指标和统计结果；未运行或失败内容不得写成结果。
- 讨论和局限：区分解释与事实，保留替代解释、冲突证据和适用边界。
- 基金文本：设备、样本、数据、伦理批准和预期结果分别标为已具备或拟议；创新点必须有相近工作差异支撑。

交付前检查事实定位、数字单位、引用标识、实验状态和用户要求的篇幅/语言/格式。AI 不列为作者，研究者负责最终审阅、署名、引用和伦理责任。
