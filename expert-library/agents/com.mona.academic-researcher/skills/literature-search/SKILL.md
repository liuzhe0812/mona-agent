# 文献检索与筛选

## 适用边界

用于用户要查找文献、制定检索式、筛选候选文献、梳理研究领域或形成基于检索结果的证据概览时。若用户要解释某篇论文的方法/结果，使用 `paper-reading`；若要核验 DOI、参考文献或“论据是否被文献支持”，使用 `citation-audit`。单元事务完成后停止，不主动扩展成完整研究项目。

开始非简单检索前，用 `skill_reference_read` 读取本 Skill 的 `resource-map.md`，再按当前任务只加载匹配的 Nature 检索、格式转换或合法全文获取资源。需要确定性批处理时优先运行已集成脚本，不临时重写同类转换器。

## 检索要求

1. 先明确问题、对象/人群、干预或暴露、结局、时间范围、语言、研究类型、纳入/排除条件和交付边界。信息不足时列出必要假设，不把模糊问题直接当成“没有文献”。
2. 将问题拆成概念组，并保留用户原始术语。中文查询必须同时生成中文和英文检索式；英文术语可使用已核验的同义词、缩写和医学主题词，不能凭空编造术语。至少保留一个原词查询和一个扩展查询。
3. 按来源可达性选择检索通道：大陆普通网络优先使用可见浏览器访问的中文学术入口（如机构允许的 CNKI、万方、SinoMed 或百度学术），结构化学术源再使用 `academic_search`。某一来源失败时，继续检索其他与问题匹配且当前可达的来源；不预设固定的机械降级链。用户需要登录、验证码或机构权限时，说明 `user_action`，不绕过访问控制。普通网页只能发现线索，不能独立支撑关键学术结论。
4. 对每个“查询式 × 来源”记录检索时间、筛选条件、结果数量或页面状态。遇到限流时，仅按工具提供的有限重试和服务端等待提示重试；达到重试或等待上限后停止该来源，不循环，有其他来源结果时记为 `partial`，并继续其他来源。来源返回错误、超时、限流、不可达或全文缺失时，保留真实错误和覆盖范围；将数据库/来源覆盖失败与单篇文献全文获取失败分开记录和报告；`provider_errors` 非空时不得把零结果解释为“没有相关文献”。
5. 按 DOI、PMID/PMCID、arXiv ID、NCT ID 或其他稳定标识符去重；没有标识符时按规范化标题、作者和年份核对。保留正式论文、预印本、注册研究等来源类型和版本，不把预印本当成正式发表论文。
6. 只根据实际获得的元数据、摘要或全文筛选。标题/摘要筛选不能推断全文方法、数值或结论。标记 `fulltext_unavailable` 前，若已有 PMCID/PMID、DOI 或准确标题，检查 Europe PMC/PMC、期刊官网或合法公开入口，并记录实际尝试及结果；仍不可得时标记 `fulltext_unavailable` 或 `insufficient_evidence`，不得用搜索摘要补写细节。

## 记录与交付

用户要求研究记录或可交付成果时，使用 `research_record` 初始化 `research/<task_id>/`，至少保存：

```text
manifest.json
search_log.jsonl
sources.jsonl
```

将每个实际发现的来源写入 `sources.jsonl`，保存标题、作者、年份、期刊/来源类型、DOI/PMID 等已知字段、来源 provider、版本和检索时间。对来源不可用、全文缺失或元数据冲突写明 `missing_reason`，不删除失败记录。

交付至少包括：问题与范围、双语检索式、来源与时间、纳入/排除边界、去重规则、候选文献清单、各来源可用性和缺口。若提供主题概览或研究空白，每条事实都关联真实 `source_id`；没有完成全文或引用核验时明确降低结论强度。需要知识地图时，只使用真实论文/概念/方法/数据节点及有来源的关系，不创建悬空节点。

## 结果状态

区分以下状态并在回答中说明：

- `found`：至少有可核验的匹配来源。
- `no_match`：检索过的来源可用、查询边界明确且确实没有匹配；这不等同于全领域不存在文献。
- `partial`：部分来源失败但仍有结果；说明失败来源和可能影响。
- `sources_unavailable`：所有关键来源均不可用；只能报告无法判断，不能报告“没有文献”。
- `user_action`：需要登录、验证码、机构权限或用户提供文件后才能继续。

严禁编造文献、作者、日期、DOI、PMID、摘要、研究空白或“已验证”的结论。需要逐篇阅读或引用真实性审计时，停止本 Skill 的检索交付并切换到对应事务。
