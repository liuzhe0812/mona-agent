# 音乐创作与编曲

本 Skill 服务于“想法 → 音乐方案 → ABC 乐谱 → 结构化评审 → 修改”的闭环。它把音乐目标拆成可检查的结构和声部，而不是只凭一句风格形容词续写音符。

需要吉他六线谱（TAB）、吉他指法/把位或扫弦节奏型时，改用 `guitar-tab` Skill：本 Skill 的 ABC 子集不输出六线谱。可以先用本 Skill 确定调性、和声与结构，再用 `guitar-tab` 出吉他谱。

## 资源路由

按任务读取最少的参考资料：

- 首次创作、和声或节奏问题：读取 `references/theory.md`。
- 需要流派转换、时代语汇或多风格方案：读取 `references/styles.md`。
- 需要配器、钢琴/吉他演奏性或声部安排：读取 `references/instruments.md`。
- 需要比较草稿、给修改意见或复盘：读取 `references/review.md`。
- 需要生成、修正或检查 ABC：读取 `references/abc-output.md`。

资源只能通过 `skill_reference_read` 读取；不要把资源路径交给用户作为可执行指令，也不要假设未读取的规则。

## 创作顺序

1. 把用户请求整理为创作简报：用途、受众、情绪、风格、时长/小节数、曲式、调性、拍号、速度、乐器和难度。
2. 先写一句核心审美目标，例如“短句、留白多、每四小节有一次向属和弦的推进”，再决定动机、音区和密度。
3. 建立 1–2 个短动机，说明节奏细胞、音程轮廓和落点；通过重复、移位、扩展、缩减、转调或配器变化发展，而不是无理由增加新材料。
4. 规划段落功能：引入、陈述、发展、对比、高潮、回归和收束。每段至少给出小节范围、主导声部、张力等级和和声作用。
5. 编排声部：明确主旋律、低音、和声填充和节奏骨架，避免所有声部同时占满同一音区。按 `instruments.md` 检查实际演奏限制。
6. 按 `abc-output.md` 写文件并做符号检查，调用 `music_score` 检查每次修改后的文件，再按 `review.md` 做一次独立评审。若发现问题，先修改文件并重新校验，再报告结果。

## 风格与审美

风格是节奏、和声、旋律句法、音区、织体、配器和动态的组合。回答中要指出采用了哪些可观察特征、哪些特征被刻意弱化，以及这些选择怎样服务于情绪和段落。可以创作流行、民谣、摇滚、布鲁斯、爵士、古典/电影配乐、R&B 和电子等风格方向；电子的音色设计只能作为文字编曲说明，不能假装 ABC 能表达完整的声音合成。

不复制具体歌曲的旋律或歌词，不按在世音乐人的名字生成“完全一样”的作品。用户给出参考曲时，提炼节拍、曲式、和声密度、音区和制作目标等高层特征，改写成新的动机。

## 评审与诚实边界

评审必须把“结构证据”“音乐判断”“修改建议”分开。没有音频输入或试听工具时，只能评估乐谱可见的拍子、音程、和声、曲式、声部密度、音域和演奏性；不能声称听过、试听过、确认了音色或确认了混音效果。若用户反馈“听起来不对”，把反馈作为新的创作约束，并指出需要用户实际试听确认的部分。

## 交付格式

用户要乐谱时，交付一个 UTF-8 `.abc` 文件和简短说明。文件必须使用 `abc-output.md` 的受限子集，以便右侧预览器稳定渲染。可另外交付结构表或分析 Markdown，但不能用一张图片冒充可编辑乐谱。用户要修改时保留版本差异，指出改变了哪些小节/声部及其目的。
