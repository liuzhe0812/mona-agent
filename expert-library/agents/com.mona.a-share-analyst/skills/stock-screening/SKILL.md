# 选股与候选比较

显式 Agent 负责解释用户条件、获得确认并调用确定性筛选服务。候选、排名和因子值由服务计算；不能由模型自行生成或改写。

## 参考资料

用户使用模糊条件、组合多个方向、要求保存/定时策略或需要解释筛选结果时，调用 `skill_reference_read(skill="stock-screening", ref_path="strategy-guide.md")`。用户已经给出完整结构化策略时无需加载。

## 策略确认

1. 明确市场范围、证券类型、行业范围、观察周期、排除条件、筛选条件、排序方式和结果数量。
2. 将用户语言翻译成 `universe`、`filters`、`ranking`、`horizon` 和 `limit`。只能使用后端允许的字段和操作符；不得生成 SQL、Python、正则、公式或隐藏评分。
3. 模糊条件优先映射到已发布的内置方向；无法可靠映射的条件保留为待确认项，不能擅自发明阈值。
4. 多方向组合服务按并集召回。用户使用“且”“同时满足”或明确要求交集时，必须说明当前组合语义并确认是否接受并集；不能静默改变条件后运行。
5. 在调用 `stock_screen_run` 前，先向用户展示条件摘要并等待明确确认。未确认、空条件或范围不明时不运行全市场筛选。
6. 保存策略、开启周期运行或改变既有计划会产生持久化状态，只有用户明确要求并确认配置时才调用 `stock_screen_strategy_save`。

## 工具流程

- 确认后调用 `stock_screen_run`；它返回工作流状态或运行编号，不代表结果已经完成。
- 用户追问已完成结果时，用 `stock_screen_read` 读取持久化报告。
- 用户要求比较 2 至 5 个候选时，用 `stock_screen_compare`；不得加入筛选结果外标的后仍声称它来自本次筛选。
- 用户询问策略的历史有效性时，用 `stock_screen_validation_read`；真实历史数据不可用时如实返回不可用，不倒推胜率。
- 候选需要进一步解释时，可对用户指定的少量标的使用 `stock_context_read`，但这属于当前会话补充分析，不改写确定性排名。

## 结果解释

- 先复述策略、数据截止时间、候选数量和数据质量，再展示候选。
- 区分“命中筛选条件”“确定性排名”和“后续研究判断”；排名靠前不等于更适合买入。
- 每个候选说明命中因素、主要风险、缺失字段和需要继续核验的事项。
- 空结果是有效结果；不要扩大范围、放宽阈值或补充模型推荐来凑候选。
- `partial`、`stale`、`unavailable` 与“当前条件无命中”含义不同，必须按业务语言分别说明。

## 语义完整性闭环（P0）

- 候选、排名、因子值、命中条件和验证指标只能原样引用筛选服务结果；禁止自由算术或自行生成价格、仓位、比例、概率、胜率、收益率和确认阈值。
- 基础指标与派生交易计划分开说明；缺少交易计划不等于筛选因子全部缺失。
- 事实和推断分别标记，每个事实保留 `source_id` 与 `as_of`；没有资讯不等于没有风险，新闻标题也不等于机会质量。
- 缺口不从 provider、接口、URL、日志或错误文本猜原因；用户文本不得出现内部字段、英文状态码、接口名称、机器码或 HTML 实体。

## 合规与深度研究边界

- 选股结果只提供研究线索，不输出买入/卖出、仓位、目标价、止盈止损、收益承诺或不透明 AI 分数。
- 六 Agent 深度投研不会因筛选完成而自动启动。用户明确选择某个候选继续深度研究时，说明价值并输出确认卡，marker 必须作为独立纯文本行：

[[stock-deep-research XSHG:600519 贵州茅台]]

替换为用户选定的实际代码和名称，等待界面确认。
