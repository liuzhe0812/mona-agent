# 市场与自选简报

把分散的行情、事件和数据质量信息压缩成可追溯简报。常驻推送和自动复盘由工作流或通知服务负责，本 Skill 不自行创建定时任务。

## 使用范围

- 市场、板块、单股或用户给出的股票集合的盘前、盘中、盘后简报。
- 指定时间窗内的近期变化、催化、风险和后续观察项。
- 用户只问一个数值时改用 `stock-data-query`；要求找股票时改用 `stock-screening`；要求解释已有报告时改用 `stock-report-explaining`。

## 参考资料

生成多标的简报、正式盘前/盘后简报或用户没有指定格式时，调用 `skill_reference_read(skill="market-briefing", ref_path="output-template.md")` 读取推荐模板。简单单股摘要无需加载模板。

## 工作顺序

1. 明确覆盖范围、时间窗和截止时点；用户没有给时间窗时，说明本次采用的数据截止点。
2. 单股即时行情用 `stock_quote`；需要量价、财务、市场背景或新闻时，用 `stock_context_read` 读取必要 sections。不要为了填满版面加载无关分区。
3. 先整理“发生了什么”，再判断“可能影响什么”，最后列出“还需要确认什么”。新闻标题、涨跌幅和事件数量不能直接充当因果结论。
4. 事件需要原文核验时，只能使用本次 context 返回的 `context_id + source_id` 调用 `stock_source_open`。
5. 多标的简报保持相同的时间窗、字段口径和单位；不能比较的项目单独说明，不强行排序。

## 语义完整性闭环（P0）

- 只引用工具返回的、带 `source_id` 和 `as_of` 的事实；禁止自由算术、单位换算或生成新的价格、仓位、比例和确认阈值。
- 基础指标与派生交易计划分开说明；派生计划缺失不等于基础指标缺失。
- 资讯是催化或风险素材，不等于行业趋势、行业周期或公司经营发展已确认；缺少行业供需、周期或公司证据时不得越级下结论。
- 数据缺口只按工具明确字段说明，不从 provider、接口、URL、日志或错误文本猜原因；用户文本不得出现内部字段、英文状态码、接口名称、机器码或 HTML 实体。

## 输出要求

- 结论先行，并明确简报的覆盖范围与截止时间。
- 将事实、条件化影响判断、风险/反证和待确认事项分开。
- 每个数值和事件保留 `source_id` 与 `as_of`；推断同时说明依据。
- 原样反映 `data_quality` 和 `missing_fields` 的业务影响，但把内部状态翻译成自然语言。
- 结尾附上：仅供信息研究与学习参考，不构成投资建议。

## 深度研究边界

用户要求“全面研究”时，不用简报冒充深度投研。标的明确且六 Agent 互证有价值时，只说明能补充的价值并输出确认卡；marker 必须作为独立纯文本行，不加反引号、代码块或列表符号：

[[stock-deep-research XSHG:600519 贵州茅台]]

替换为实际代码和名称，等待用户点击后由界面启动；标的不明确时先澄清，不要声称研究已经开始。
