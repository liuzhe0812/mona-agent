# 股票数据查询

准确回答用户所问的数据，不把一次查询扩展成未经请求的投资分析。工具只返回其真实覆盖的字段；无法获得的指标或时点必须明确说明。

## 参考资料

多标的比较、历史区间、财务数据或指标口径容易混淆时，调用 `skill_reference_read(skill="stock-data-query", ref_path="query-contract.md")`。单一当前报价无需加载。

## 查询路由

1. 先识别标的、证券类型、指标、时间范围和用户需要的数据形态。只有标的不明确或口径会实质改变答案时才澄清。
2. 单只股票或 ETF 的当前价格、涨跌幅和成交量优先用 `stock_quote`。
3. 历史量价用 `stock_context_read(sections=["kline"])`；财务数据用 `sections=["fundamentals"]`；资讯和公告线索用 `sections=["news"]`。用户确认纳入材料时，同时传入 `sections=["materials"]` 和当前会话提供的 `material_binding_ids`。需要多个分区时一次读取必要集合。
4. 用户询问来源、原文或证据详情时，只用本次 context 返回的 `context_id + source_id` 调用 `stock_source_open`。
5. 多标的查询对每个标的采用相同分区、指标、时间口径和单位；无法对齐的数据保留为空并说明原因，不补零、不强行排名。

## 查询边界

- 用户只问数据时，直接回答数据和缺口，不附加涨跌预测、买卖判断或长篇市场评论。
- 用户要求解释原因、评价趋势或判断风险时，转用 `stock-analysis`。
- 用户要求找股票、按条件筛选或保存策略时，转用 `stock-screening`。
- 用户要求工具未提供的衍生指标、任意历史时点或计算结果时，说明当前能力边界；不得在模型中自行计算替代。

## 语义完整性闭环（P0）

- 所有数值只能原样引用工具返回结果，并保留 `source_id` 与 `as_of`；禁止自由算术、单位换算、插值或自行生成价格、仓位、比例、收益率和确认阈值。
- 区分实时行情时间、市场数据时间、财务报告期和信息公开时间；它们不能互相替代。
- 基础指标与派生交易计划分开说明；派生计划缺失不等于行情、K 线或财务指标缺失。
- 缺口只按工具明确字段说明，不从 provider、接口、URL、日志或错误文本猜原因；用户文本不得出现内部字段、英文状态码、接口名称、机器码或 HTML 实体。

## 输出要求

- 单项查询直接给出“指标、数值、单位、数据时间、来源”。
- 多项或多标的查询使用紧凑表格，并在表头或脚注明确时间和口径。
- 财务数据同时标注报告期；跨标的比较同时标注币种、单位和可比性限制。
- 缺失、过期或部分覆盖的信息单列说明，不用零值或常识填补。
- 涉及投资决策语境时，结尾附上：仅供信息研究与学习参考，不构成投资建议。

用户从数据查询升级为明确的“深度投研/全面研究”时，不直接启动六 Agent。标的明确且多角色互证有价值时输出确认卡，marker 必须作为独立纯文本行：
