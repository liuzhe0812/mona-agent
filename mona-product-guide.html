Mona 产品功能说明书

一个功能完备的个人 AI 代理，支持多渠道通信、多模型供应商、丰富的工具生态和智能记忆系统

📋 产品概述

Mona 是一个开源的个人 AI 代理平台，旨在成为用户的智能助手。它以 Agent Loop 为核心引擎，通过工具调用实现与外部世界的交互，通过多渠道适配器覆盖主流即时通讯平台，通过记忆系统实现长期知识积累。

🔄 Agent Loop 代理循环

Agent Loop 是 Mona 的核心处理引擎，负责接收消息、构建上下文、调用 LLM、执行工具、返回结果。每个用户请求经历以下状态流转：

状态说明
RESTORE从持久化存储恢复会话历史
COMPACT检查并执行上下文压缩（如需要）
COMMAND处理内置命令（如 /help、/status）
BUILD构建 LLM 请求上下文（系统提示 + 历史 + 工具定义）
RUN调用 LLM 并执行工具调用循环（最多 200 轮迭代）
SAVE保存会话状态到持久化存储
RESPOND将最终响应发送到通信渠道

核心特性

  • 多轮工具调用：支持最多 200 轮工具迭代，可处理复杂的多步骤任务
  • 自动上下文压缩：当上下文接近 token 预算时，自动压缩历史消息
  • 统一会话模式：支持 unified_session 模式，跨渠道共享同一会话
  • 模型预设：通过 model_presets 快速切换不同的模型配置
  • 进度推送：实时推送代理思考进度和工具调用提示到渠道
  • 推理控制：支持 reasoning_effort 参数（low/medium/high/adaptive/none）

💾 会话管理

Mona 通过 SessionManager 管理所有对话会话，每个会话以 JSON 文件持久化存储。

会话特性

  • 会话隔离：每个渠道 + 聊天 ID 对应独立会话
  • 统一会话：启用 unified_session 后，所有渠道共享同一会话（单用户多设备）
  • 自动压缩：空闲会话在配置的 TTL 后自动压缩（session_ttl_minutes）
  • 消息上限：可配置最大回放消息数（max_messages，默认 120）
  • 压缩比：压缩后保留原始 token 预算的 50%（consolidation_ratio）
  • 目标状态追踪：通过 long_task / complete_goal 追踪长期目标

🧠 记忆系统

Mona 拥有多层记忆架构，从短期对话上下文到长期知识积累，实现信息的持久化和智能检索。

📜
SOUL.md
Bot 人格与沟通风格定义，由 Dream 自动管理
👤
USER.md
用户画像与偏好设置，由 Dream 自动管理
📝
MEMORY.md
长期事实记忆（项目上下文、重要事件），由 Dream 自动管理
📊
history.jsonl
追加写入的 JSONL 格式历史记录，支持 grep 搜索

Consolidator 压缩器

当上下文接近 token 预算时，Consolidator 自动将旧消息压缩为摘要，保留最近的消息不变。压缩过程使用 LLM 生成高质量摘要，确保关键信息不丢失。

💭 Dream 记忆整合

Dream 是 Mona 的后台记忆整合服务，定期运行以整理和优化长期记忆文件。

配置项默认值说明
interval_h2 小时Dream 运行间隔
max_batch_size20每次处理的最大历史条目数
max_iterations15Phase 2 最大工具调用次数
annotate_line_agestrue在 Phase 1 中标注行龄（git blame）
model_overrideNoneDream 专用模型覆盖

两阶段处理

  • Phase 1：读取 MEMORY.md 和历史记录，使用 LLM 分析需要更新的事实
  • Phase 2：通过工具调用执行更新操作（编辑文件、写入新记忆等）

🤖 子代理系统

Mona 支持通过 spawn 工具创建后台子代理，处理独立且耗时的任务。

子代理特性

  • 独立执行：子代理拥有独立的工具注册表和文件状态追踪
  • 状态追踪：实时追踪子代理状态（initializing → awaiting_tools → tools_completed → final_response → done/error）
  • 并发控制：可配置最大并发子代理数（max_concurrent_subagents，默认 1）
  • 结果通知：子代理完成后自动向原始渠道发送结果通知
  • Token 统计：追踪每个子代理的 token 使用量

📁 文件系统工具

提供完整的文件操作能力，所有路径均通过 _resolve_path 校验，确保在工作区内操作。

  • read_file：读取文本/图片/二进制文件，支持行范围和偏移
  • write_file：写入文件，自动创建中间目录
  • edit_file：精确搜索替换，支持单次替换
  • list_dir：列出目录内容，显示文件大小和修改时间
  • apply_patch：结构化补丁编辑，支持多文件批量修改、行级增删

启用 restrict_to_workspace 后，所有文件操作限制在工作区目录内。

💻 Shell 执行工具

通过 exec 工具执行 Shell 命令，支持丰富的配置选项。

配置项默认值说明
timeout60s命令超时时间（最大 600s）
sandbox""沙箱后端（如 bwrap）
allow_patterns[]允许的命令模式
deny_patterns[]禁止的命令模式

跨平台兼容：Windows 使用 cmd /c，Unix 使用 sh -c。内置危险命令检测（如 rm -rf /、mkfs、dd 等）和安全命令白名单。

🌐 Web 搜索与抓取

提供 web_search 和 web_fetch 两个工具，让代理能够访问互联网信息。

  • web_search：支持 DuckDuckGo 和自定义搜索后端，可配置最大结果数和超时
  • web_fetch：抓取网页内容，支持 Jina Reader 模式提取纯文本
  • 所有 HTTP 请求经过 SSRF 防护校验，重定向限制为 5 次
  • 外部内容标记为 [External content]，防止提示注入
  • 支持代理配置（proxy）和自定义 User-Agent

🎨 图像生成

通过 generate_image 工具实现 AI 图像生成和编辑。

  • 支持文本生成图像（text-to-image）和图像编辑（reference_images）
  • 可配置供应商（OpenRouter / AiHubMix / Gemini 等）、模型和默认尺寸
  • 支持宽高比（1:1, 16:9, 9:16, 4:3）和尺寸（1K, 2K, 4K）
  • 每轮最多生成 4 张图像（可配置至 8）
  • 生成结果持久化存储为 artifact，支持迭代编辑

⏰ 定时任务

通过 cron 工具管理定时提醒和周期性任务。

  • 提醒模式：消息直接发送给用户
  • 任务模式：代理执行任务描述并返回结果
  • 一次性：在指定时间运行一次后自动删除
  • 支持三种调度方式：every_seconds（间隔）、cron_expr（Cron 表达式）、at（一次性）
  • 支持时区配置（IANA 时区标识符）
  • 支持列出和删除已有任务

🔍 代码搜索

提供 grep 和 glob 两个搜索工具。

  • grep：文件内容搜索，支持正则表达式、大小写忽略、文件类型过滤、上下文行显示
  • glob：文件名模式匹配，支持 *.py、**/*.ts 等模式
  • 内置 30+ 文件类型映射（py, js, ts, go, rs, java, html, css 等）
  • 自动跳过二进制文件
  • 支持分页（head_limit / offset）

🩹 补丁编辑

apply_patch 工具支持结构化的多文件批量编辑。

  • 支持添加行、删除行、上下文匹配验证
  • 路径必须为相对路径，禁止 .. 和绝对路径
  • 自动生成 diff 摘要，显示每个文件的增删行数

🗄️ 数据库查询

db_query 工具提供只读 SQL 查询能力。

  • 仅允许 SELECT / SHOW / DESCRIBE / EXPLAIN / WITH 语句
  • 结果限制为 100 行
  • 支持表结构查看、索引信息、查询计划等常见操作
  • 通过 Tauri IPC 与前端数据库连接交互

🔌 MCP 服务器

Mona 支持 Model Context Protocol (MCP) 协议，可接入外部工具服务器扩展能力。

  • 支持三种连接方式：stdio（子进程）、sse（Server-Sent Events）、streamableHttp
  • 每个 MCP 服务器可配置工具超时（默认 30s）
  • 支持工具过滤（enabled_tools），支持通配符 ["*"]
  • 自动重连和瞬态错误重试
  • Windows 路径分隔符自动规范化
  • MCP 工具名自动添加 mcp_<server>_ 前缀以避免冲突

通用渠道特性

  • 语音转写：所有渠道支持语音消息转文字（Groq Whisper / OpenAI Whisper）
  • 进度推送：可配置推送代理思考进度（send_progress）和工具提示（send_tool_hints）
  • 推理展示：可配置展示模型推理过程（show_reasoning）
  • 消息重试：发送失败自动重试（send_max_retries，默认 3 次）
  • 配对码认证：支持设备配对码认证机制
  • 插件扩展：通过 entry_points 注册外部渠道插件

💚 微信

个人微信渠道，通过 HTTP 长轮询 API 实现，无需本地微信客户端。用户通过扫描 QR 码登录后即可使用。支持文本、图片、文件消息收发。

🐦 飞书 / Lark

使用 lark-oapi SDK 的 WebSocket 长连接模式接入。支持富文本、分享卡片、交互消息等多种消息类型。支持 @提及识别和群聊场景。

🔵 钉钉

使用 dingtalk-stream SDK 的 Stream Mode 接入。支持文件上传（最大 20MB）、Markdown 消息和富媒体内容。

🟢 企业微信

使用 wecom_aibot_sdk 接入企业微信 AI 机器人。支持图片、视频、音频和文件上传（最大 200MB）。

🐧 QQ

使用 botpy SDK 接入 QQ 机器人平台。支持 C2C 私聊和群消息，支持富媒体上传（base64 上传）。

📧 邮件

通过 IMAP 轮询接收邮件，SMTP 发送回复。支持 SSL/TLS 加密连接，附件自动下载到媒体目录。

🔌 WebSocket

Mona 作为 WebSocket 服务器，客户端通过 WS 协议连接。支持 HMAC 认证、配对码认证、SSL 加密。适合自建前端或集成到 Web 应用中。

💬 Mochat

基于 Socket.IO 的通信渠道，支持 HTTP 轮询降级。具备消息游标持久化、去重和消息历史同步能力。

🔄 模型降级

FallbackProvider 实现透明的模型降级机制，当主模型出错时自动切换到备用模型。

降级策略

  • 可降级错误：超时、连接错误、服务器错误、限流、过载
  • 不可降级错误：认证失败、权限拒绝、内容过滤、上下文超长
  • 熔断器：主模型连续 3 次失败后进入冷却期（60 秒），期间直接使用备用模型
  • 通过 fallback_models 配置降级链，支持引用模型预设名

🎯 技能系统

技能（Skills）是扩展 Mona 能力的 Markdown 文档，通过 SKILL.md 文件定义，教代理如何使用特定工具或执行特定任务。

技能格式

每个技能是一个包含 SKILL.md 的目录，文件结构为：

---
name: skill-name
description: 技能描述
metadata: { ... }
---

# 技能标题

技能指令内容...

技能加载

  • 内置技能：位于 mona/skills/ 目录
  • 工作区技能：位于 ~/.mona/workspace/skills/ 目录
  • 工作区技能优先级高于内置技能（可覆盖）
  • 支持通过 disabled_skills 禁用特定技能
  • 技能可声明依赖（如需要 gh CLI），不满足条件的技能自动过滤

📊 Mona PPT

AI 驱动的多格式 SVG 内容生成系统，可将源文档（PDF/DOCX/URL/Markdown）转换为高质量 SVG 页面并导出为 PPTX。

  • 多角色协作：Strategist（策略师）+ Executor（执行者）+ Quality Gate（质量门）
  • 完整流水线：源文档转换 → 项目创建 → 可选模板 → 策略设计 → SVG 生成 → 质量检查 → PPTX 导出
  • 丰富模板：内置 40+ 图表模板（柱状图、饼图、流程图、甘特图等）和品牌模板
  • 图像支持：AI 生成图像、Web 搜索图像、SVG 图标库
  • 动画与音频：支持 PPTX 动画和 TTS 旁白
  • 实时预览：SVG 编辑器实时预览（端口 5050）

🐙 GitHub

通过 gh CLI 与 GitHub 交互。支持 PR 管理、Issue 操作、CI/CD 检查、API 高级查询等。需要安装 GitHub CLI。

⏰ Cron 定时

使用 cron 工具创建定时提醒和周期性任务。支持三种模式：提醒、任务执行、一次性。支持 Cron 表达式和 IANA 时区。

🦞 ClawHub

公共技能注册中心，支持自然语言搜索（向量搜索）、安装、更新技能。通过 npx clawhub 命令操作。

🎯 长目标

通过 long_task / complete_goal 管理多回合持续目标。目标描述遵循幂等性原则，确保在压缩、重试或恢复后仍然有效。

  • 目标应面向状态而非叙述
  • 自包含，不依赖上下文中的对话
  • 可安全重复执行
  • 范围有界，有明确的完成标准

📝 记忆技能

双层记忆系统，由 Dream 自动管理。SOUL.md 定义人格，USER.md 存储用户画像，MEMORY.md 积累长期事实，history.jsonl 记录完整历史。代理可通过 grep 搜索历史记录。

🛡️ 安全机制

Mona 实现了多层安全防护，确保代理操作在安全边界内执行。

🔒
SSRF 防护
所有出站 HTTP 请求通过 validate_url_target 校验，阻止访问私有网络地址（10.x, 172.16.x, 192.168.x, 127.x, 169.254.x 等）
📁
工作区隔离
文件系统工具通过 _resolve_path 校验路径，启用 restrict_to_workspace 后限制在工作区内
⚠️
命令审批
Terminal 工具支持审批模式（approval），危险命令自动拦截，安全命令白名单放行
📦
沙箱执行
支持 bwrap 沙箱后端，工作区绑定挂载，配置目录隐藏，媒体目录只读
🔑
密钥保护
API 密钥通过环境变量引用（${VAR_NAME}），不硬编码到配置文件；MyTool 属性黑名单阻止访问敏感运行时状态
🌐
重定向限制
HTTP 请求最多 5 次重定向，重定向目标同样经过 SSRF 校验

SSRF 防护详情

validate_url_target 执行以下检查：

  • 仅允许 http/https 协议
  • 必须包含有效域名
  • DNS 解析后检查 IP 是否为私有地址
  • 支持 CIDR 白名单（如 Tailscale 的 100.64.0.0/10）

⚙️ 配置系统

Mona 使用 Pydantic 构建类型安全的配置系统，所有配置模型继承自 Base 类（配置了 camelCase 别名生成）。

配置结构

{
  "agents": {
    "defaults": {
      "model": "anthropic/claude-opus-4-5",
      "provider": "auto",
      "maxTokens": 8192,
      "contextWindowTokens": 65536,
      "temperature": 0.1,
      "timezone": "UTC",
      "botName": "mona",
      "botIcon": "🐈",
      "dream": { "intervalH": 2 }
    }
  },
  "channels": { "sendProgress": true, "showReasoning": true },
  "providers": { "anthropic": { "apiKey": "${ANTHROPIC_API_KEY}" } },
  "tools": {
    "web": { "enable": true },
    "exec": { "enable": true, "timeout": 60 },
    "mcpServers": {}
  },
  "api": { "host": "127.0.0.1", "port": 8900 },
  "gateway": { "host": "127.0.0.1", "port": 18790 }
}

配置特性

  • 双格式支持：JSON 中使用 camelCase，Python 中使用 snake_case
  • 环境变量：敏感信息使用 ${VAR_NAME} 引用
  • 环境覆盖：支持 MONA_ 前缀的环境变量覆盖配置
  • 模型预设：通过 model_presets 定义可复用的模型配置
  • 验证：Pydantic 自动验证配置类型和约束

💓 心跳服务

HeartbeatService 定期唤醒代理检查是否有待处理任务。

两阶段决策

  • Phase 1（决策）：读取 HEARTBEAT.md，通过虚拟工具调用让 LLM 判断是否有活跃任务（skip / run）
  • Phase 2（执行）：仅在 Phase 1 返回 run 时触发，通过完整代理循环执行任务
配置项默认值说明
enabledtrue是否启用心跳
interval_s1800 (30 分钟)心跳间隔
keep_recent_messages8保留的最近消息数
