📋 项目概览

Nanobot 是一个用 Python 编写的生产级 AI Agent 框架，其核心设计理念是事件驱动 + 状态机 + 工具循环。它能够同时接入多个聊天平台（Telegram、Discord、Slack、微信、飞书等），通过统一的 MessageBus 进行消息路由，使用 LLM 进行推理和工具调用，并具备长期记忆、上下文压缩、子代理调度等高级能力。

🔗 多通道接入

支持 15+ 聊天平台：Telegram、Discord、Slack、微信、飞书、钉钉、QQ、WhatsApp、Signal、Matrix、MS Teams、Email、WebSocket WebUI 等

🛠 丰富工具集

文件读写、Shell 执行、代码搜索、Web 搜索/抓取、图片生成、MCP 协议、定时任务、消息发送等，支持插件扩展

🧠 智能记忆

长期记忆 (MEMORY.md)、会话压缩 (Consolidator)、自动整理 (Dream)、历史归档，支持 Git 版本追踪

🤝 子代理调度

支持后台异步子代理执行，结果通过消息总线注入主代理上下文，实现并行任务处理

🔄 核心处理循环

AgentLoop 是整个系统的核心处理引擎，它承担以下职责：

  1. 从 MessageBus 消费入站消息
  2. 构建上下文（历史、记忆、技能）
  3. 调用 LLM 进行推理
  4. 执行工具调用
  5. 将响应发送回 MessageBus

消息处理主循环

async def run(self):
    while self._running:
        msg = await self.bus.consume_inbound()  # 阻塞等待消息

        # 1. 优先级命令直接处理（如 /stop）
        if self.commands.is_priority(raw):
            await self._dispatch_command_inline(msg, ...)
            continue

        # 2. 如果该会话已有活跃任务，注入 pending queue
        if effective_key in self._pending_queues:
            self._pending_queues[effective_key].put_nowait(msg)
            continue

        # 3. 否则创建新任务处理
        task = asyncio.create_task(self._dispatch(msg))

关键设计：每个会话（session_key）有独立的 asyncio.Lock，保证同一会话的消息串行处理，不同会话之间并发执行。同时通过 _concurrency_gate（Semaphore）限制全局并发请求数。

中途消息注入 (Mid-turn Injection)

当一个会话正在处理消息时，新到达的消息不会排队等待，而是被路由到 pending_queue。AgentRunner 在每次工具执行完毕后，会通过 injection_callback 检查是否有待注入的消息，将其作为后续 user 消息追加到对话中，实现"边处理边接收"的能力。

# AgentRunner 中的注入检查点
# 1. 工具执行完毕后
_drained, injection_cycles = await self._try_drain_injections(
    spec, messages, None, injection_cycles, phase="after tool execution")

# 2. 最终响应后
should_continue, injection_cycles = await self._try_drain_injections(
    spec, messages, assistant_message, injection_cycles,
    phase="after final response", iteration=iteration)

⚙️ 状态机机制

AgentLoop._process_message() 使用事件驱动的有限状态机来处理每条消息。每个状态有对应的 handler 方法，handler 返回事件字符串，驱动状态转换。

状态定义

状态Handler说明
RESTORE_state_restore恢复检查点、提取文档媒体、初始化会话
COMPACT_state_compact自动压缩空闲会话（AutoCompact）
COMMAND_state_command命令路由：快捷命令直接返回，否则进入 BUILD
BUILD_state_build构建 LLM 上下文：历史、系统提示、工具上下文
RUN_state_run执行 AgentRunner（LLM+工具迭代循环）
SAVE_state_save保存回合消息到会话、触发后台压缩
RESPOND_state_respond组装出站消息（处理 MessageTool 抑制等）
DONE—终态，返回出站消息

状态转换表

_TRANSITIONS = {
    (RESTORE,  "ok"):       COMPACT,
    (COMPACT,  "ok"):       COMMAND,
    (COMMAND,  "dispatch"): BUILD,      # 非快捷命令 → 构建上下文
    (COMMAND,  "shortcut"): DONE,       # 快捷命令 → 直接返回
    (BUILD,    "ok"):       RUN,
    (RUN,      "ok"):       SAVE,
    (SAVE,     "ok"):       RESPOND,
    (RESPOND,  "ok"):       DONE,
}

设计优势：状态机模式使消息处理流程清晰可追踪，每个状态的职责单一，便于调试和扩展。通过 StateTraceEntry 记录每个状态的耗时和事件，支持性能分析。

🏃 AgentRunner 执行引擎

AgentRunner 是 LLM + 工具的迭代执行引擎，负责核心的"推理→工具调用→结果反馈→再推理"循环。它是无状态的，所有配置通过 AgentRunSpec 传入。

执行流程

构建请求
→
调用 LLM
→
解析响应
→
有工具调用?
→ 是
执行工具
→
构建请求
有工具调用?
→ 否
返回最终响应

上下文治理 (Context Governance)

每次迭代前，AgentRunner 会对消息列表进行多层治理，确保不超出上下文窗口：

  1. 清理孤立工具结果 (_drop_orphan_tool_results)：移除没有匹配 assistant tool_call 的 tool 消息
  2. 回填缺失工具结果 (_backfill_missing_tool_results)：为没有对应 tool 消息的 tool_call 插入错误占位
  3. 微压缩 (_microcompact)：将旧的 compactable 工具结果替换为一行摘要
  4. 工具结果预算 (_apply_tool_result_budget)：截断过长的工具结果
  5. 历史裁剪 (_snip_history)：当 token 估算超出预算时，从头部裁剪历史消息

工具并发执行

工具调用支持并发执行。通过 concurrency_safe 属性标记只读工具，多个只读工具可以在同一批次并发执行，非并发安全工具串行执行。

# 工具分批策略
def _partition_tool_batches(self, spec, tool_calls):
    for tool_call in tool_calls:
        tool = spec.tools.get(tool_call.name)
        can_batch = bool(tool and tool.concurrency_safe)
        if can_batch:
            current.append(tool_call)  # 加入并发批次
        else:
            batches.append([tool_call])  # 独立批次，串行执行

错误恢复机制

  • 空响应重试：LLM 返回空内容时，最多重试 2 次，之后尝试 finalization retry（不带工具调用）
  • 输出截断恢复：finish_reason=length 时，追加恢复消息让 LLM 继续
  • 运行时检查点：在工具执行期间定期保存检查点到会话元数据，中断后可恢复

🛠 工具系统

Nanobot 的工具系统采用插件化架构，支持内置工具、MCP 工具和外部插件三种来源。

Tool 抽象基类

class Tool(ABC):
    @property
    @abstractmethod
    def name(self) -> str: ...          # 工具名称

    @property
    @abstractmethod
    def description(self) -> str: ...   # 工具描述

    @property
    @abstractmethod
    def parameters(self) -> dict: ...   # JSON Schema 参数定义

    @property
    def read_only(self) -> bool: ...    # 是否只读（可并发）

    @property
    def concurrency_safe(self) -> bool: # 是否可并发执行
        return self.read_only and not self.exclusive

    @abstractmethod
    async def execute(self, **kwargs) -> Any: ...  # 执行工具

工具注册与发现

ToolLoader 通过 Python 包扫描 + entry_points 插件机制自动发现和注册工具：

  1. 包扫描：遍历 nanobot.agent.tools 包下的所有模块，发现 Tool 子类
  2. Entry Points：加载通过 nanobot.tools 组注册的外部插件
  3. 作用域过滤：通过 _scopes 属性区分 core/subagent 作用域
  4. 启用检查：通过 enabled(ctx) 类方法根据配置决定是否注册

🧠 记忆与上下文管理

Nanobot 拥有三层记忆体系，从短期到长期逐级管理：

1. 会话历史 (Session History)

存储在 SessionManager 中，每个会话独立维护完整的消息历史。支持 token 预算限制和历史回放窗口。

2. 上下文压缩 (Consolidator)

当会话 prompt token 接近上下文窗口限制时，Consolidator 自动触发：

  1. 估算当前 prompt token 数
  2. 若超出预算，选取用户轮次边界作为压缩点
  3. 将旧消息通过 LLM 总结为摘要
  4. 摘要写入 history.jsonl，旧消息从会话中移除
  5. 最多执行 5 轮压缩，直到 token 在安全范围内

3. 长期记忆 (MemoryStore)

基于文件系统的持久化记忆：

  • MEMORY.md — 长期事实记忆，由 Dream 自动维护
  • SOUL.md — Agent 人格定义
  • USER.md — 用户偏好信息
  • history.jsonl — 追加式历史日志，带 cursor 游标

上下文构建 (ContextBuilder)

每次 LLM 调用前，ContextBuilder 组装完整的系统提示词：

def build_system_prompt(self):
    parts = [
        self._get_identity(channel),       # 身份 + 平台策略
        self._load_bootstrap_files(),       # AGENTS.md / SOUL.md / USER.md
        render_template("tool_contract.md"),# 工具使用契约
        self.memory.get_memory_context(),   # 长期记忆
        always_skills_content,              # 常驻技能
        skills_summary,                     # 技能摘要（按需加载）
        recent_history,                     # 最近历史条目
        session_summary,                    # 归档上下文摘要
    ]
    return "\n\n---\n\n".join(parts)

渐进式技能加载：技能分为"常驻"（always=true）和"按需"两种。常驻技能完整注入系统提示词，按需技能仅提供摘要，Agent 可通过 read_file 工具按需读取完整内容，有效节省 token。

📡 多通道系统

Nanobot 通过 BaseChannel 抽象和 ChannelManager 管理器实现多平台统一接入。

BaseChannel 抽象接口

class BaseChannel(ABC):
    async def start(self) -> None: ...       # 启动通道监听
    async def stop(self) -> None: ...        # 停止通道
    async def send(self, msg) -> None: ...   # 发送消息
    async def send_delta(self, ...) -> None: # 流式发送（可选）
    async def send_reasoning_delta(self, ...): # 推理流（可选）

    async def _handle_message(self, sender_id, chat_id, content, ...):
        # 权限检查 → 配对码 → 发布到 MessageBus
        if not self.is_allowed(sender_id): ...
        await self.bus.publish_inbound(msg)

ChannelManager 职责

  • 通道初始化：根据配置自动发现和实例化启用的通道
  • 出站消息分发：从 MessageBus 消费出站消息，路由到对应通道
  • 流式消息合并：合并连续的 stream_delta 消息，减少 API 调用
  • 重复消息抑制：基于内容指纹去重，避免重复发送
  • 发送重试：指数退避重试（1s, 2s, 4s）

权限与配对

通道支持三种权限模式：

  1. 白名单模式：allowFrom: ["*"] 或指定用户 ID
  2. 配对码模式：未授权用户收到配对码，需在配置中确认
  3. 拒绝模式：群聊中未授权用户的消息被静默忽略

💾 会话管理

SessionManager 负责会话的持久化和检索，每个会话通过 session_key（格式：channel:chat_id）唯一标识。

会话模型

@dataclass
class Session:
    key: str                        # 会话唯一标识
    messages: list[dict]            # 消息历史
    created_at: datetime
    updated_at: datetime
    metadata: dict                  # 元数据（检查点、摘要等）
    last_consolidated: int = 0      # 上次压缩位置

关键特性

  • 统一会话模式：unified_session 配置可将所有通道的消息合并到同一会话
  • 历史回放窗口：max_messages 和 max_tokens 限制回放给 LLM 的历史量
  • 运行时检查点：工具执行期间保存进度，中断后可恢复部分上下文
  • 文件容量限制：enforce_file_cap 防止会话文件无限增长

💭 Dream 记忆整理

Dream 是一个定时执行的记忆整理处理器，采用两阶段架构：

Phase 1: 分析

将未处理的历史条目和当前记忆文件内容发送给 LLM，生成分析摘要。此阶段不使用工具，仅产生文本分析。

Phase 2: 执行

将分析结果委托给 AgentRunner，配备 read_file、edit_file、write_file 工具，让 LLM 自主决定如何编辑 MEMORY.md、SOUL.md、USER.md 等文件。

→

行龄标注

🔒 安全机制

Nanobot 在多个层面实现了安全防护：

1. SSRF 防护

AgentRunner 检测工具结果中的 SSRF 标记（内部/私有 URL 访问），返回不可重试的错误提示，明确告知 Agent 这是安全边界，不可绕过。

2. 工作空间限制

restrict_to_workspace 配置限制文件操作和 Shell 执行只能在工作空间目录内进行。违反限制的操作会被拦截并返回错误。

3. 重复违规升级

当 Agent 反复尝试相同的安全违规操作时，错误提示会逐步升级，最终强制阻止。

4. 网络安全

nanobot.security.network 模块提供网络安全策略，包括 URL 白名单和私有地址检测。

5. 沙箱执行

Shell 命令在受限环境中执行，支持超时控制、工作目录限制和环境变量过滤。

6. 工具结果截断

max_tool_result_chars 限制工具返回内容的最大长度，防止信息泄露和 token 溢出。
