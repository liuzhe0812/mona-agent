# Mona 官网开发计划

版本：v1.0  
范围：Mona 官网首页重构，不包含 Mona 桌面客户端功能开发  
建议基线：1 名前端独立开发，10 个工作日；如配置 1 名前端 + 1 名视觉动效协作，可压缩为 7 个工作日  

## 1. 项目目标

官网应在三个时间节点完成三件事：

1. 前 3 秒：用户记住 Mona 猫形象。
2. 前 10 秒：用户理解 Mona 不是普通聊天机器人，而是可以进入工作现场执行下一步的 Agent。
3. 前 60 秒：用户找到一个与自己相关的使用场景，并完成下载或观看演示。

核心文案：

> 让 AI 不只回答，还能接着把事做完。

主要转化目标：

- 下载 Windows 版
- 观看 90 秒实机演示

非目标：

- 本期不制作完整 3D Mona 模型。
- 本期不接入 Rive 骨骼运行时。
- 本期不新增后台、CMS、登录或数据采集系统。
- 本期不重构 `/tutorial` 和 `/changelog` 的业务内容。

## 2. 当前工程基线

官网位于 `site/`，当前技术栈为：

- React 18
- TypeScript
- Vite 6
- Tailwind CSS 3
- Framer Motion
- React Router
- Canvas 2D 粒子系统

当前没有 Three.js、React Three Fiber 或 GSAP。

开发前需要先处理三个基线问题：

1. `PageDeck` 只维护 6 个页面 ID，但 `Home` 实际渲染 8 个章节，末尾章节无法通过现有翻页状态正常访问。
2. `HeroSection` 中存在中文乱码，必须在视觉开发前统一文件编码和文案来源。
3. 当前 `ToolsSection` 展示 10 个模块，与设计方案中的 6 个工作现场不一致，需要收束为邮件、浏览器、笔记、终端、数据库、交付。

## 3. 技术决策

### 保留

- 保留 React、Vite、TypeScript 和 Tailwind。
- 保留 Framer Motion，负责普通组件动画、遮罩转场和页面状态切换。
- 保留现有 `Navbar`、`MagneticButton`、`ScrollReveal` 中可复用的部分。
- 保留 Canvas 2D 粒子系统，作为移动端和低性能设备的降级方案。

### 新增

- 只新增 `three`，用于首屏空间轨道和记忆星群。
- Three.js 场景按需加载，同一时间最多运行一个 WebGL 场景。

### 暂不新增

- 不引入 React Three Fiber。
- 不引入 GSAP。
- 不引入新的全局状态库用法。
- 不引入 Rive 运行时；第一版使用透明 PNG、SVG 和动画 WebP。

只有在角色必须实现独立关节跟随、连续表情混合时，才进入 Rive 二期。

## 4. 页面架构

现有全屏强制翻页改为原生纵向滚动。只有“工作轮盘”在鼠标位于组件内部时接管滚轮，避免整站滚动劫持。

| 顺序 | 页面模块 | 主要内容 | Mona 状态 | 核心技术 |
|---|---|---|---|---|
| 01 | Hero | 价值主张、下载、演示 | Welcome → Idle | Three.js、Framer Motion |
| 02 | 工作轮盘 | 六个工作现场 | Think / Work | React 状态、局部滚轮 |
| 03 | 行动链 | 上下文→理解→行动→确认→交付 | Run | Sticky、尾巴遮罩 |
| 04 | 三个场景 | 邮件、运维、成果交付 | Work / Success | 卡片叙事、斜切转场 |
| 05 | 安全控制 | 只读、风险分级、关键确认 | Confirm / Guard | 状态切换 |
| 06 | 记忆延续 | 工作记录与上下文延续 | Think | Three.js 星群 |
| 07 | 最终转化 | 下载、教程、品牌收束 | Success → Sleep | Framer Motion |

## 5. 组件规划

| 组件 | 责任 |
|---|---|
| `MonaActor` | 统一管理 8 个角色状态和静态降级 |
| `HeroScene` | 首屏空间轨道、粒子和鼠标视差 |
| `WorkRoulette` | 六模块轮盘、键盘、拖动和滚轮切换 |
| `ActionChain` | 五步行动路径和奔跑转场 |
| `UseCaseStories` | 三个高价值场景 |
| `SafetySection` | 权限边界和确认机制 |
| `MemoryScene` | 工作成果星群与收束动画 |
| `FinalCTA` | 下载、教程和休息状态 |
| `MotionProvider` | 减少动态偏好和设备能力判断 |

避免建立额外的动画框架或配置中心。每个组件只维护自身动画状态。

## 7. 分阶段实施

### 阶段 0：基线稳定

时间：第 1 天

任务：

- 修复中文乱码。
- 修复章节 ID 与页面数量不一致。
- 将全局强制翻页改为原生滚动。
- 核对下载地址、教程地址和产品宣传事实。
- 建立桌面 1440px、移动 390px 两个验收视口。

验收：

- 所有章节可通过滚动和导航到达。
- 浏览器前进、后退与锚点可用。
- 页面不存在乱码和不可验证宣传。

### 阶段 1：品牌骨架与角色系统

时间：第 2 天

任务：

- 建立品牌色、字体、斜切、网格和间距规则。
- 接入素材包。
- 完成 `MonaActor` 的 8 状态切换。
- 完成减少动态偏好的静态降级。

验收：

- 角色状态切换不发生布局跳动。
- PNG、SVG、WebP 在深色和浅色背景下边缘干净。
- 移动端不加载不必要的大图。

### 阶段 2：首屏

时间：第 3–4 天

任务：

- 完成标题、说明、下载和演示入口。
- 实现 Mona 欢迎、待机、状态灯和轻微视差。
- 实现 Three.js 数据轨道和粒子。
- 实现 WebGL 失败时的 Canvas 2D 降级。

验收：

- 无 WebGL 时首屏仍能完整阅读和转化。
- 首屏动画不会遮挡标题和按钮。
- 首屏资源加载不阻塞文字与 CTA。

### 阶段 3：工作轮盘

时间：第 5–6 天

任务：

- 实现六模块 60° 轮盘。
- 支持点击、拖动、局部滚轮、键盘方向键和触摸滑动。
- 切换 Mona 的 Think / Work 状态。
- 接入六个模块 SVG 图标与对应案例文案。

验收：

- 每次输入只切换一个模块。
- 键盘、鼠标和触摸均可完成完整操作。
- 离开轮盘区域后恢复页面正常滚动。

### 阶段 4：行动链与三场景

时间：第 7 天

任务：

- 完成五步行动链。
- 使用奔跑 WebP 和尾巴 SVG 完成章节转场。
- 完成邮件、运维、成果交付三组案例。
- 每个案例只呈现输入、行动、结果三层信息。

验收：

- 用户不操作轮盘也能顺序理解完整流程。
- 奔跑和斜切转场在移动端可降级为淡入与位移。
- 案例内容与现有产品能力一致。

### 阶段 5：安全、记忆与最终 CTA

时间：第 8 天

任务：

- 完成确认与守卫状态。
- 展示只读查询、风险分级、关键确认等准确边界。
- 完成记忆星群场景。
- 完成最终下载区和睡眠页脚。

验收：

- 安全章节没有“所有操作都会确认”等绝对表述。
- 第二个 Three.js 场景进入视口才加载。
- 离开视口后停止无意义的动画循环。

### 阶段 6：质量与发布准备

时间：第 9–10 天

任务：

- 桌面、平板、移动端适配。
- 键盘、焦点、语义标签和减少动态偏好检查。
- 图片转换与资源压缩。
- 动画帧率和内存检查。
- 构建、类型检查、Lint 和浏览器冒烟测试。
- 下载链接、教程链接和统计事件检查。

验收：

- `build`、`check`、`lint` 全部通过。
- Chrome、Edge、Safari 移动端布局无阻断问题。
- Lighthouse Accessibility 不低于 90。
- 桌面动画目标不低于 55fps，移动端降级后不低于 30fps。
- 首屏即使脚本或 WebGL 延迟，也能看到核心文案与下载按钮。

## 8. 性能预算

- 首屏不预加载全部角色姿势，只加载 Welcome 和 Idle。
- Three.js 独立分包并按需加载。
- 同时最多一个 WebGL 渲染循环。
- 不可见的 Canvas、WebGL 和角色循环全部暂停。
- 移动端粒子数量控制在桌面端的 25% 以内。
- 首屏图片与字体总传输预算不超过 1.5MB。
- 不使用全屏视频作为首屏背景。

## 9. 测试清单

### 功能

- 导航、锚点、浏览器前进后退。
- 下载和教程链接。
- 轮盘六模块的所有输入方式。
- Mona 八状态切换。
- WebGL 加载、失败和降级。

### 视觉

- 1440×900
- 1280×720
- 768×1024
- 390×844
- 深浅背景下的透明素材边缘

### 可访问性

- 全键盘操作。
- 清晰焦点状态。
- 图片替代文字。
- `prefers-reduced-motion`。
- 不依赖颜色单独表达风险状态。

## 10. 主要风险

| 风险 | 处理方式 |
|---|---|
| Three.js 拉低首屏性能 | 延迟加载、限制像素比、Canvas 降级 |
| 全屏动效影响阅读 | 每屏只保留一个主要动作 |
| 轮盘劫持页面滚动 | 只在轮盘聚焦或指针位于组件内时接管 |
| 角色姿势之间存在绘制差异 | 官网尺寸直接使用；超大展示前再做矢量统一 |
| 文案超过产品真实能力 | 开发前建立“能力—证据—文案”核对表 |
| 移动端空间不足 | 轮盘改为横向卡片，Three.js 改为 Canvas 或静态图 |

## 11. 完成定义

只有同时满足以下条件，首页才视为完成：

- 七个章节全部实现并可访问。
- Mona 角色承担导航、状态和转场作用，而不是单纯装饰。
- 工作轮盘可被鼠标、触摸和键盘完整操作。
- Three.js 有清晰业务表达，并具备降级方案。
- 宣传内容与当前产品能力一致。
- 构建、类型检查、Lint、响应式和无障碍验收通过。
- 下载入口在首屏与末屏均可用。
