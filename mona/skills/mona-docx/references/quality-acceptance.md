# Word 质量验收

## 内容和结构

- 开篇明确文档目的、范围和结论或任务；标题具有描述性，全文语气和作者声音一致，普通专业文稿没有被做成无必要的宣传卡片。
- 用户给出的事实、数字、日期、单位和限定条件逐项保留；没有把推测写成事实，也没有为了排版删除原文信息。用户明确要求不损失内容时，用“原文章节/表格/数据项 → 输出块/位置”的覆盖清单逐项核对，再报告完整。
- `outline` 能反映真实章节结构；标题使用正确层级，正文没有靠加粗或字号伪装成标题。
- 段落顺序能支持阅读目的：每段有单一中心，真正并列的内容才使用列表，需要对齐比较的内容才使用表格。
- 表格只包含可比较记录，短字段与描述字段的列宽匹配；长论述在表格外，题注与图片或表格相邻。用 `blocks` 读取表格时，关键单元格与写入意图一致，`rowIndex`/`columnIndex` 没有错位。

## 版式和分页

- 同层级块的字体、字号、颜色、对齐和段落间距一致，强调样式有明确理由。
- 长表和长段落没有因一次性大批操作而被截断；需要分页的章节使用 `pageBreakBefore`，分页后标题没有孤立，表格没有丢行。
- `summary.pageSettings` 中的节尺寸和页边距符合任务要求；表格样式的列宽数组与列数相等，表头行数、底色、边框和内边距符合语义，不靠样式掩盖数据缺失。
- 先通过换行、列宽和布局解决溢出，再检查字号；没有固定行高截断正文或表格文字，多页表头能重复显示。
- 交付前先从 `summary.pageCount` 确认实际页数，再用 `inspect visual` 检查当前版本的完整画面，并结合 `blocks`/`summary` 检查结构。返回 `document:continuous` 时，画面包含连续分页内容，必须检查所有页面分隔处。不要只凭工具返回成功、修改页截图或一张局部截图判断版式完成。
- `inspect review` 的 `[错误]` 必须修复；`[需检查]` 只有在同版本完整连续画面已经观察且有具体保留理由时才能接受。页脚出现“页/页码”文字但没有真实 PAGE 字段属于错误；表格行跨页拆分属于需检查项。
- 视觉 PNG 的 `version` 与结构检查和最后一批 `apply` 一致；版本冲突时重新读取并重做视觉检查。

## 会话和文件

- 每次 `apply` 都使用最新 `version`；只有回执没有提供验收所需信息时才读取受影响块。版本冲突能够通过重新读取恢复，用户修改没有被覆盖。
- 局部编辑只改目标块，保留原文档的结构、样式和未涉及内容；修改后复核相关页，用户要求内容完整时按覆盖清单验收，最终检查范围随任务需要确定。
- `save` 或 `export` 使用最后一批修改后的版本。导出文件能重新由 `office open(path=...)` 打开并读取关键大纲、块和表格。
- 页眉、页脚和页码验收要从实时 summary 的轻量文本/页码状态和 `buildBytes` 导出的实际 DOCX 双重确认；旧版本命令被拒绝后，页眉页脚不能发生变化，历史 checkpoint 要保留对应版本。
- 若用户要求 Word/WPS 外部兼容性，只报告实际打开验证的结果；未在对应应用中验证的内容标记为待验证。

## 未见过的 Word 任务

对新的文档类型至少覆盖一次“打开已有文件 → 选择合适的原文入口 → 局部修改 → 局部复核 → 导出”的闭环；若读回明确为 `partial`，只补读缺失范围，不交叠扫描。验收重点仍是事实完整、语义结构、正文节奏、表格准确和分页可读，而不是套用固定封面、目录或章节数量。
