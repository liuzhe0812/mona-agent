# 案例路由：类别 → 风格 → 场景 → 具体方案

用于需要具体构图或风格参考的生图任务。先找图片的职责，再用用户已指定的风格和场景筛选；需要借鉴案例时，阅读命中的卡片以获得设计方法和完整示范。已有具体方案或普通模板足以完成任务时不必强行套案例；验收以最终提示词的具体内容为准。

卡片是从 awesome-gpt-image-2 实际案例 prompt 提炼的设计方法，示范由 Mona 重新编写；不包含原始图片，不要求联网。来源链接保留追溯关系，并不证明原图由上游 Skill 自动生成。原始分类/标签有混用，以下路由依据案例实际内容核对。

## 如何做选择

- **已有视觉要求优先**：要求无字的 PPT 背景不能因命中“城市”就选 c511；指定“纯摄影”不能被水彩案例替换。系列配图继承已有风格，再借用兼容构图。
- **风格不能只按题材猜**：城市不等于晚霞与地标全家福，科技不等于蓝光电路，中国题材不等于人物水墨双重曝光。选能解释用户目标的具体机制。
- **参考候选而不增加用户负担**：对于“做一张武汉海报”，可内部比较 c511 的字形城市、c497 的单色街景、c464 的城市生活。自主选择一个符合上下文的方向；不要默认生成三张。
- **把有用决策写进最终提示词**：例如采用 c497 时，把街道透视、单色线描水彩、纸白和步行视点落实成句子。案例编号和内部笔记可以辅助工作，但不能代替最终提示词中的这些要求，也不是验收条件。
- **替换有边界**：能换主体、语言、配色与画幅；保留支撑方案的关系。若用户要求使机制失效，改选案例，不能保留案例名却丢掉全部机制。
- **事实来自任务**：不把案例里的数据、坐标、名号、产品规格当成模板变量随意编造。短创意标题可以按任务写；事实性标签需要依据。

## 没有相近案例时

这 17 个案例是精选机制集，不宣称覆盖全部创作类型。软件界面、科学尺度、历史、出版等任务没有恰当卡片时，回到 [22 类模板](template-catalog.md) 的对应条目，再从 [风格系统](style-systems.md) 定义媒介和构图。不得把 c17 当纯 UI 截图、把 c334 强说成尺度科学图，或用人物卡强套无人物场景。

案例卡已经携带完整示范和风格，不需要每次再读取全部模板、风格和示例文件。只有排版、编辑或检查遇到具体缺口时才加载相应补充参考。
