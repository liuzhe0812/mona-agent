## c17：界面交互设计图

**来源核实：** 上游标题为“界面交互设计图”，原 prompt 实际指定的是一张高科技 3D 产品结构海报：中心为纵向分层的 VR 头显爆炸视图，左右有功能标注，上方有品牌与副标题，下方有总结文案和标志。来源类别是 Products & E-commerce，风格含 UI、Infographic、Poster；本卡没有复制其原始 JSON prompt。

**适用：** 需要让一个实体产品同时承担“展示外形、解释内部结构、传达卖点”三项工作的发布会页、产品手册开场页或功能介绍图。

**不适用：** 纯 UI 截图、软件流程图、只展示外观的商品主图，以及需要大量可编辑正文的页面。若标注文字很多，应把长文案留给文档排版，图中只保留少量短标签。

**构图机制：** 让产品沿一条清晰的中心轴分离，外壳、核心模块和接触部件形成从外到内的阅读顺序；两侧标注线连接到对应零件，顶部说明“这是什么”，底部说明“为什么这样设计”。中心产品是主视觉，标注与页眉页脚服务于它，而不是形成平均分配的卡片网格。

**必须保留的设计锚点：**

- 中心主体的装配顺序可一眼追踪，零件不能无缘无故漂浮或交叉。
- 标注线必须落到真实零件或功能区域，左右信息密度可以不对称。
- 页眉、主体、标注、页脚有明确层级；品牌名、口号和说明文案都应来自任务，不自动编造品牌事实。
- 3D 渲染的材质、光源和背景要共同服务产品辨识度；颜色和零件数量随对象复杂度决定。

**可替换变量：** 产品类型、中心轴方向、爆炸层级、标注数量、标注位置、背景色、光照和材质；页眉页脚可以删减，若任务只需要结构图，不必强行保留海报文案。

**完整原创示范 prompt：**

```text
生成一张虚构模块化桌面空气净化器的竖版概念结构海报。机身沿垂直装配轴展开，进风格栅、滤芯和风机位于外壳与底座之间，各部件保持可理解的朝向和位置对应。主体占据中央，左右少量细线分别连接对应部件；顶部唯一标题为“模块化净化器”，侧边短标签仅为“进风格栅”“滤芯”“风机”，底部只写“分层设计”。以深灰、银白区分外壳和内部，青绿光线沿气流方向穿过结构；柔和棚拍光与真实接触阴影统一质感。这是概念展示，不添加性能规格、认证、更多正文、无关 logo 或装饰卡片。
```

**失败征兆：** 零件像散落的装饰品而非可装配系统；标注线错连、穿过主体或指向空白；页眉页脚比产品更抢眼；为了“高科技”加入大量霓虹、代码和无关图标；模型擅自生成品牌、性能数字或过长小字。

## c334：RAG 技术详解图

**来源核实：** 上游标题为“RAG 技术详解图”，原 prompt 只有“帮我生成一张 RAG 技术的详细讲解图”这一句，未规定版式、箭头、模块数量、色彩或文字内容。来源类别是 Charts & Infographics，风格为 Charts。本卡把“详细讲解”转译为可执行的流程构图，但这些具体版式不是上游案例的事实。

**适用：** 需要让读者顺着路径理解一个抽象技术系统、数据管线或检索增强流程的教学图、架构概览和演示页。

**不适用：** 需要展示真实运行指标的监控面板、严格按规范绘制的工程图，或只想要一张抽象科技背景的装饰图。事实、术语和流程顺序应由任务 brief 提供或核对，生图提示词不能替代技术审校。

**构图机制：** 把系统画成从问题到答案的可追踪路径：输入先进入知识来源，再经过检索与筛选，最后与上下文汇合进入生成环节；每个阶段有独立视觉容器或形状语言，箭头只表达真实的方向和回流关系。可把一条主路径和一个侧向知识库层叠，避免所有模块挤在同一横线上。

**必须保留的设计锚点：**

- 读者能从起点走到终点，主路径的方向、节点和回流关系不能含糊。
- 知识库、检索结果、上下文和最终输出需要在视觉上区分，不能只换几个颜色。
- 术语、标签和箭头应少而精；没有经过确认的数字、性能、模型名和结论不能自行补写。
- 颜色承担语义角色并可在图例中解释；模块数量、形状和色数按信息量决定。

**可替换变量：** 输入类型、知识源形式、检索策略、重排节点、生成模型、是否展示评估或反馈回路、版式方向、图例和文字密度。若文字必须准确，应只放用户提供的短标签并在后续文档中排版长说明。

**完整原创示范 prompt：**

```text
制作一张面向产品经理的 RAG 工作原理讲解图。用一条从左到右的主路径表达“用户问题 → 文档库检索 → 相关片段筛选 → 上下文拼接 → 模型生成回答”，在下方单独画出知识库的文档、切片和索引层，并以一条细回流线表示新资料进入索引。每个阶段只保留简短中文标签和必要箭头，主路径突出，侧层作为支撑，不要把节点排成装饰性图标墙。使用浅色工程白底、深石墨线条和少量蓝绿语义色，保持留白、层级与方向清楚；不要添加未经确认的指标、虚构模型名称、长段落、乱码或赛博朋克背景。
```

**失败征兆：** 变成无方向的科技节点云；箭头互相穿越或形成错误闭环；“检索”“上下文”“生成”没有层级差异；用大量渐变和发光效果掩盖逻辑；为了显得详细而加入虚构数据、模型名或不可读的小字。

## c339：Apple 风格自然科普海报

**来源核实：** 上游标题为“Apple 风格自然科普海报”，原 prompt 规定了极简纯白或浅灰背景、放大的真实动物主体、左上标题区、底部轻量信息栏、克制字体层级和避免卡片化的约束。原 prompt 还给出四个信息栏目作为示例；本卡把它视为可变的信息带，不把四列或特定色数当成硬规则。

**适用：** 一个物种或自然对象需要以强主体、少量可靠知识点和高级编辑感呈现的科普海报、展板封面或演讲页主视觉。

**不适用：** 需要同时展示很多物种、复杂生态关系、长篇科普正文或真实野外环境叙事的图。此时应切换到信息图、纪实摄影或多主体布局。

**构图机制：** 用一个极度放大的主体建立视觉中心，把标题和身份信息压缩到顶部留白区，再把少量知识点组织成底部轻量信息带；图像、标题和信息带之间留出呼吸空间，不让卡片框、装饰边框或复杂背景稀释主体。

**必须保留的设计锚点：**

- 主体占据主要视觉面积，姿态和局部纹理必须直接服务识别与科普重点。
- 背景近乎空白，承托物只在帮助尺度或栖息特征时出现。
- 标题、物种名称和知识短句有清晰层级；信息单元的数量、图标和强调色按内容需要变化。
- 采用单一主视觉语言：真实棚拍式光影、干净编辑排版和少量功能色彼此协调。

**可替换变量：** 物种、主体姿态、承托物、标题文案、信息单元数量、强调色、纵横比例和留白分配。若知识点尚未核实，只使用用户提供的事实和短标签，不让模型补写结论。

**完整原创示范 prompt：**

```text
生成一张竖版极简自然观察海报，唯一标题为“玻璃蛙”。让一只具有半透明皮肤与细小趾垫细节的玻璃蛙占据中部大部分空间，以柔和棚光和清楚轮廓呈现；背景为纯白到极浅灰，只保留一小片湿润叶片。顶部标题与主体留出空隙，底部三个轻量观察单元分别用与主图对应的局部细节配短标签“皮肤”“趾垫”“腹部”，单元之间用细线分隔而不使用卡片。黑色标题、灰色标签与少量低饱和绿色点缀，无其他可读文本、分布数据或功效描述。避免主体缩小、旧纸纹理、儿童卡通、无关 logo 与拥挤小字。
```

**失败征兆：** 主体缩小成装饰插图；背景变成热带场景或复杂信息图；底部信息变成拥挤卡片墙；颜色过多且没有语义；标题压住动物；模型补出未经确认的分布、数值或长篇小字。

## c370：Crumple Chair 概念沙发研发板

**来源核实：** 上游标题为“Crumple Chair 概念沙发研发板”，原 prompt 明确采用五段研发逻辑：从皱纸形态观察与折痕映射，经过数字压缩和座舱雕刻，再转向人体工学、正侧顶视图、隐藏骨架、材料选项和最终材质渲染。原案例强调保留不规则性，同时使内侧接触面适合使用。本卡保留这种“从形态来源到可行产品”的关系，阶段数和参数随任务变化。

**适用：** 概念家具、工业产品、材料实验和需要说明设计推演过程的研发板、设计评审页或作品集页面。

**不适用：** 只需要一张最终商品渲染图、只展示外观情绪的 moodboard，或已经确定结构而不需要过程解释的制造图。

**构图机制：** 让一块原始形态在同一张板上逐步变成可用产品：先展示形态观察与几何规律，再展示迭代草模，随后用人体/功能约束翻译它，最后补足结构、材料和成品渲染。每个阶段要能追溯到前一阶段，不能把几张互不相关的效果图拼成流程。

**必须保留的设计锚点：**

- 形态来源、关键几何特征与最终产品之间有连续的视觉证据。
- 不规则或有机特征不能被无理由抹平，同时接触面、受力点或操作区要体现功能翻译。
- 至少有一种能核对结构的视图或剖面，以及能说明材料/骨架的局部细节。
- 研发板的阶段标题、箭头和小注释服务于设计推演；不凭空加入规格、人体数据或制造结论。

**可替换变量：** 原始形态来源、阶段数量、产品类别、功能约束、视图类型、骨架方案、材料候选、背景纸张和标注密度。若用户只要最终图，删掉过程板结构，改用产品视觉卡。

**完整原创示范 prompt：**

```text
制作一张工业设计研发板，主题是由“压缩树叶的脉络”演化出的轻量骑行头盔。按任务需要组织一条连续推演：先展示叶脉的主脉与分叉如何转译为壳体加强筋，再展示几种不对称网格草模，随后将头部贴合、通风和视野约束嵌入形态，最后给出一张带局部剖面的成品渲染与前后左右视图。让每一步都能追溯到上一阶段，外壳保留自然分叉的张力，内侧接触区保持平滑舒适；用中性纸白、石墨线和一处材料色区分研究信息，避免固定模块数量、虚构尺寸、无关品牌和把不同产品拼成一张拼贴海报。
```

**失败征兆：** 所有阶段只是同一产品的重复角度；形态来源与最终形体没有关系；过程图沦为装饰箭头和随机草图；只强调“未来感”却没有结构、受力或使用约束；不规则表面被统一成普通对称外壳，或出现未经要求的尺寸和材料性能。

## c361：手机爆炸拆解图

**来源核实：** 上游标题为“手机爆炸拆解图”，原 prompt 实际只有“生成一张 [subject or object] 的高细节 3D 爆炸装配图”这一句，没有指定手机层级、标注、视角、背景或配色。本卡因此只提炼“爆炸装配图”的核心关系；下面的示范主题与细节都是新写的任务示例，不是上游 prompt 的补写。

**适用：** 需要清楚展示一个对象如何由零件组成、零件沿什么方向装回去的装配说明、拆解展示和技术教育图。

**不适用：** 需要讲述产品品牌故事的广告海报、需要解释多阶段设计决策的研发板，或需要大段文字的说明书页面。

**构图机制：** 以一个装配基准建立秩序，让零件沿轴向或层级关系有间距地展开；每个零件保持真实相对位置、朝向和接触顺序，观看者可以从最外层追到核心，也可以反向想象装回过程。背景、阴影和标注只用于衬托结构，不制造第二个视觉主体。

**必须保留的设计锚点：**

- 爆炸方向、装配轴和零件对应关系明确，不能出现漂移、重叠或无法解释的悬浮。
- 核心零件、外壳、紧固/连接部位和接触面按对象实际结构取舍；不为了“细节”虚构内部件。
- 采用统一的 3D 材质与光照，必要时用少量编号或短标签建立查找关系。
- 视角以能读懂装配关系为优先，是否等轴测、斜视或局部剖切由对象决定，不把某一种比例或颜色当模板规定。

**可替换变量：** 被拆解对象、零件粒度、爆炸方向、视角、背景、标注方式、材质、编号和是否显示局部剖面。若用户只需一张外观图，移除爆炸关系，改用产品摄影方向。

**完整原创示范 prompt：**

```text
生成一张高细节 3D 爆炸装配图，主题是便携式手摇咖啡磨豆机。沿中心轴把上盖、调节环、锥形磨芯、轴承、手柄连接件、外壳、粉仓和底座分层展开，保持每个零件的真实朝向、相互对应的位置和装回顺序，关键接触面用轻微间距与柔和阴影表达。采用中性浅灰背景、统一的金属与磨砂塑料材质、清晰斜视角和少量编号标签；不增加品牌 logo、虚构零件、无关装饰、重复部件或无法辨认的小字，也不要把零件排成没有装配逻辑的散点。
```

**失败征兆：** 零件数量看似很多但无法装回；同一部件重复或镜像错误；爆炸间距不一致导致层级混乱；为了追求“极致细节”出现虚构结构；标注、背景或炫光盖住连接关系，成品看起来像普通 3D 静物而不是装配图。
