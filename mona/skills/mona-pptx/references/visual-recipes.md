# 将视觉设计落实为 Mona 原生页面

新建整稿、产品发布或明显需要设计提升时阅读。以下吸收 Dashi 的主题层级、杂志式构图、主视觉和页面家族方法，用 Mona 现有 Office 操作实现；没有外部模板依赖，不改变实时编辑、版本控制和交付流程。

## 一份稿先固定一个视觉方向

用户的品牌和参考稿优先。没有指定时按内容选择一个方向，整稿沿用字号角色、边距、色彩和图标笔触。下列方向是非穷尽的设计示例，不与场景一一绑定；均不适合时，根据用户目的自行确定视觉方向，继续使用相同的原生操作和验收标准。

| 方向 | 适用 | 实际视觉做法 |
|---|---|---|
| 研究报告 | 经营汇报、比较、证据较多 | 暖白或冷白背景、深色粗标题、细分隔线；图表占主区，仅重点数据着强调色；来源另设细行。吸收色谱图表、冷白调研的层级，避免每项独立彩框。 |
| 产品聚焦 | 产品介绍、发布、客户演示 | 深色或品牌色背景、浅色文字，单个品牌强调色；一张大主图配短主张，功能解释退居次级；少量平面色块替代复杂光效，保持原生编辑稳定。吸收炫光主题的焦点与对比，不复刻滤镜。 |
| 编辑式讲解 | 培训、方案、案例拆解 | 浅底清晰文字，关键转场可用深底；大步骤编号、细线、非对称栏宽；流程和案例画面承担解释，装饰留在边缘。吸收代码风、杂志风的编号、秩序与阅读路径。 |

主色用在主结论、当前步骤或重点数据；辅助对象降低饱和度。图表颜色需要区分系列时，保持同一类别跨页同色。深色背景的说明也要可读，不直接沿用适合浅底的灰字。

无品牌要求时，可从以下原生纯色组合起步，选定后整稿复用：研究报告用背景 `#F5F3ED`、文字 `#20242B`、重点 `#3458B4`；产品聚焦用背景 `#101820`、文字 `#F5F7FA`、重点 `#72DFC1`；编辑式讲解用背景 `#FFFFFF`、文字 `#172033`、重点 `#3859D9`。这些是可调整的起点，不要求照搬 Dashi 的精确颜色或字体。

16:9 页面可从正文 18–22pt、页标题 30–36pt、主张 42–56pt、聚焦数字 64–80pt 起步；正文使用实际可用的中文字体，例如 Microsoft YaHei，标题通过字重和比例形成对比。先检查中文换行和标题高度，再写入正文位置；不要把浏览器 CSS 字号直接当成 Office 磅值。

## 用页面家族组织内容

下列比例以**标题实际底部至页脚之间的正文可用区**为基准，预览像素随页面尺寸缩放，字号单独按磅设置。六种构图是参考，可按页面信息任务组合或另行设计，不要求每页从中选一种；不要为填满构图补无关文字。两行标题会改变正文起点。

### 1. 结论 + 主图表：比较、趋势、差距

- 顶部标题直接说结论；正文左约 2/3 是原生图表，右约 1/3 是一个关键数字和两条含义。左右内容形成共同基线，结论区不需要厚重卡片边框。
- 图表使用 `slide_add_chart` 或已验证的高级图表操作。类别、值、单位是同一事实源；条形长度由数据模型生成，不能只替换标签后保留旧形状宽度。
- 例：A=72%、B=64%、C=58%，主数字是“8 个百分点”，其说明是“A 相比 B 的差距”。“方案 A”是类别，不应填入巨型数字位；8 个百分点也不是增长 8%。
- 数据点多时增大图表或拆页；不要把刻度压成只有近距离才看得清的字。

### 2. 主张 + 大图：产品价值、应用场景

- 左约 1/3：短主张和最多两条用途；右约 2/3：完整产品截图或场景图。产品画面是主视觉，不能缩成文字旁边的小附件。
- 标题可以由普通色前半句与强调色后半句构成，但连起来必须是一句自然、简短的标题。例如“用户画像，一屏掌握”；素材来源不能拼接进标题。
- 截图保留比例和关键 UI，用 `slide_add_image` 的工作区 `assetPath`。整张截图细节过小时，可使用一个明确的局部放大来解释当前功能，原图和放大图各有用途。
- 图片下方只保留必要图注，并分配独立空间；左侧要点已经说明用途时，不在图上重复同一段文字。素材尚未到位，先写不依赖它的标题和结构，按原流程继续。

### 3. 数字聚焦：一个突破、一个关键事实

- 只让一个数字或短主张成为视觉焦点，旁边或下方用两条小证据支撑；明确单位、时间或比较基准。
- 主数字显著大于页标题，类别标签显著小于数字；背景用一个主色或深浅反差，不用多个同等大小的数字抢焦点。
- 数字和单位分开排布时保持邻近，必要时给单位独立文本框；没有可靠数字就使用短主张，不为匹配大数字构图制造数值。

### 4. 有向步骤：流程、培训、执行计划

- 步骤少且短时横向展开；说明较长时用纵向编号轨道，右侧解释每一步。四步就是四个节点，不能为了三栏好看合并“处理”和“复盘”。
- 优先按 [advanced-operations.md](advanced-operations.md) 的 `addSmartArt` 使用 `process`；节点只放短标签，较长解释放到邻近的原生文本区。超过其数量能力就拆成有承接的页面。
- 编号、箭头表达顺序；高亮当前教学步骤。节点可用统一图标辅助识别，不用无关雷达、轨道、星芒替代业务关系。
- 流程形状组保留编辑能力；不要把整幅关系图转成 SVG 后称其节点可逐项编辑。

### 5. 同维度对比：方案、版本、前后变化

- 顶部短结论，下方左右等宽区域；比较项按行严格对齐，两个对象使用相同字段。用一条细分隔线和一处重点色即可建立秩序。
- 表格适合查精确值；原生图表适合比较数值大小；产品截图适合解释界面变化。不要强迫所有比较都变成两张堆满正文的卡片。
- 例：“旧版 / 新版”分别展示操作步骤数、完成时间和关键界面；缺少某项证据时明确空缺，不能用不同指标填满。

### 6. 案例 + 标注：教学解释、操作示范

- 约 2/3 正文区给真实案例、截图或原生示意；剩余约 1/3 放编号解释。编号与画面中的对象一一对应，文字回答“看哪里、为什么、怎么做”。
- 如需展示错误与正确做法，两者保持同一尺度和位置；先说判别标准，再给例子，不把步骤、原理和全部练习挤在一页。
- 图标只用于快速识别概念；每页不强行配图。已有统一静态图标库优先，整稿保持相同线性/填充风格，不用 emoji。

## 整稿节奏与成本

先写每页“主信息 / 主证据 / 页面家族 / 必含事实”，使用一个最终版本即可。不同页面可以共享同一主题，但不要连续把图表、流程和产品图都塞进相同卡片墙。只有内容确有独立转场或大主张时才安排低密度页。

一张代表性内容页在 Mona 真实画面中确认后，再延续其样式。正常工作不生成四倍候选页，也不额外生成整套外部 PPTX 来导入。用户要求比较风格或换版时，只改目标页面。

## 判断是否真正改善

一次观察优先回答：第一眼看到的是否是主信息？图形是否准确表达数据或关系？图片是否足够大到能说明问题？每个必含事实是否保留？

若答案是否定的，调整信息权重、版式或图文比例；不要只换颜色、加阴影或缩字号。最终继续沿用 [visual-review.md](visual-review.md) 的当前版本审核和原生对象验收。
