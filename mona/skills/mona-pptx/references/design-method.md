# 原生 PPTX 设计方法

在写入页面前做一次轻量设计判断。输入是用户目的、受众、场景和资料；输出是每页一句可验证的结论、支持它的证据和适合的页面表达。设计文件不需要复制旧 `mona-ppt` 的项目结构或流水线。

## 先定信息，再定版式

先回答四个问题：

1. 谁会看，观看场景是投屏讲解、会议讨论、培训还是留档？
2. 看完后希望受众理解、相信或决定什么？
3. 哪些事实、数据或例子直接支撑这个目的？
4. 哪些背景可以删掉、合并或放进备注？

页标题写结论或判断，不只写主题名。把论证安排成适合任务的顺序，例如“现状 → 问题 → 证据 → 选择/行动”，或“结论 → 关键依据 → 风险与下一步”。一页只服务一个主信息；如果页面同时需要两个互不从属的结论，拆页或明确主次。

受众影响取舍：面向公众、客户或学员时，用具体例子、视觉重点和少量文字帮助快速理解；面向团队或管理者时，强调比较、趋势和可核查的数据；面向高管、董事会或投资人时，标题先给结论，数据补充上下文、影响和需要的决策。不要用装饰性页数替代缺失的论证。

除非内容或使用场景需要，不要无端添加封面、目录、章节页或“谢谢”页。页数跟随信息，不为凑节奏制造空白页；有独立信息的转场、引用、大数字或单一图像页才算 breathing page。

## 内容到版式

比例跟随信息权重，版式可以组合。下面是起点，不是模板清单：

| 内容任务 | 建议表达 | 好的结果 | 常见坏例子 |
|---|---|---|---|
| 一个结论或一个关键数字 | 居中/偏置的主张 + 一条证据或限定 | 视线先落到结论，留白让它有重量 | 把同等大小的五张卡片当作“重点” |
| A 与 B 的比较 | 对称双栏，同一维度对齐 | 两边可逐项比较，有明确结论 | 左边讲功能，右边讲价格，维度不一致 |
| 多个量化群组的比较 | 图表占主要区域，旁边放 3–5 条解读 | 图表回答“差异/趋势是什么”，文字回答“所以呢” | 只有一个数或两点数据却放复杂图表 |
| 有顺序的流程/步骤 | 左到右流程或纵向步骤 | 箭头表达依赖关系，每步短而具体 | 用无方向的卡片堆表示流程 |
| 时间演进 | 轴线或阶段带 | 节点顺序、时间和变化原因清楚 | 时间节点只是装饰，读者看不出先后 |
| 三个以上同级能力/模块 | 三栏、2×2 或 3×2 网格 | 每个模块同一字段结构、数量适中 | 所有页都套卡片网格，模块没有差异 |
| 分层架构或上下游关系 | 堆叠层、树或带方向连接 | 连接线表达真实关系，层级有语义 | 用颜色和箭头装饰，却没有关系说明 |
| 一个需要情绪或场景的主题 | 图像主导 + 贴近图像的短说明 | 图像解释主题，文字补充情境 | 无关的库存照片占满页面 |

同一种版式可以在一个章节内复用，但整份演示文稿应有变化。页面标题、主视觉、证据区和行动/含义区要形成稳定的阅读路径。

设计验收按结构、视觉和微调进行：先把文本、形状、图片和需要的数据语义对象写入，并用 `inspect slides` 确认页面尺寸、边界、元素类型和稳定 ID；再用 `inspect review` 找出待观察页面，并用当前版本的 `inspect visual` 查看真实 `SlideCanvas` PNG，检查整体层级、裁切、对比度和图文关系；最后只做必要的局部字号、位置、填充或描边微调。微调后必须重新 review 和视觉检查，版本冲突则重新读取页面，不重放旧批次。

## 图表 Pick / Skip

使用图表前先说明它回答的问题。满足以下条件时 Pick：有至少两个可比较的量化组，或有足够的时间点/分布，且坐标、单位、类别和数据来源清楚。图表只突出一个趋势、差距或关系，旁边给出解释和结论。

以下情况 Skip：只有一个关键数、只需查精确值、数据点太少、数据没有可靠单位/来源、关系不明确，或图表会比数字本身更难读。改用大数字 + 限定语、短表格、对比条或文字结论。不要为了“看起来专业”画饼图、雷达图或复杂图表。

原生表格/图表只在用户需要继续编辑或内容确实有数据含义时使用；只为排版展示的表格可以保持自由文本或图片。可编辑的序列、类别、坐标和图例需要原生图表操作；照片、插画、扫描件和外部渲染图才是图片。外部 SVG/PNG 柱状图放进幻灯片后仍是 `picture`，不能当成可编辑图表，也不能在标题中暗示它保留数据模型。图片按页面使用顺序安排，先提交不依赖图片的文字/结构批次，不等待整套图片或不存在的后台生图服务。

## 字体、颜色和图标

先为整份演示文稿固定角色，再逐页使用。推荐用一个正文基线，按比例推导：

| 角色 | 相对正文基线 | 作用 |
|---|---:|---|
| 封面/英雄标题 | 2.5–4× | 只有在内容需要时使用 |
| 页面标题 | 1.5–2× | 说出本页结论 |
| 副标题/小结论 | 1.2–1.5× | 解释范围或方向 |
| 正文 | 1× | 事实、解释、标签 |
| 注释/来源 | 0.7–0.85× | 只放必要限定 |

正文基线跟随密度：内容密集页面宁可减少文字或拆页，也不要长期压到不可读的小字号；轻松讲解页可放大并增加留白。Office API 的 `fontSize` 是磅值，比例保持不变即可。标题与正文可以同一字体不同字重，也可以用有明确对比的安全字体组合；不要在角色之间使用“看似不同、实际相近”的字体。

用户或品牌给出的颜色优先。没有指定时使用一个背景色、一个正文色、一个主色和一个强调色；一页通常不超过 3–4 个颜色。颜色承担层级、状态或数据含义，不用彩色装饰填满空白。通用图标整份稿只用一个风格库，填充与线性风格不要混用；图标应帮助识别模块或关系，不能代替解释。

## 密度、节奏和装饰

可给页面标记三种内部节奏：

- `anchor`：标题和结构稳定，适合章节核心页或结论页。
- `dense`：证据较多，靠分栏、对齐和层级组织，不靠缩小字体。
- `breathing`：一个主意、引用、大数字或图像，保留有意义的留白。

节奏跟随叙事而不是固定配额。连续数据页后可以安排一个独立的解释或强调页，但不制作没有信息的“呼吸页”。装饰只在建立分组、方向或焦点时出现；少用阴影、渐变、边框和重复圆角卡片。复杂图片上的文字要有足够对比和必要的遮罩，图片与说明保持邻近。

一个简单的自检例子：标题“客户续费率上升主要来自 onboarding 改版”比“续费率”更能指导内容；“左侧趋势图 + 右侧三条含义”比把数据、背景和行动混进六张同等卡片更容易讲清楚。
