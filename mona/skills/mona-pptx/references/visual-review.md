# 原生 PPTX 视觉审核

审核同时使用结构数据和真实编辑器视觉捕获。使用 `open` 回执或最近一次结构结果中的尺寸、元素边界、类型、文字、轻量 `style` 和稳定 ID，再调用 `inspect visual` 获取真实 `SlideCanvas` PNG；当前支持的相关模式包括 `summary`、`outline`、`search`、`slides`、`selection`、`visual` 和布局 `review`。`visual` 接受可选 `slideId`，省略时使用当前 selection 页面，返回 `dataUrl`、`width`、`height`、`target` 和 `warnings`。已完整返回的结构不再换入口重复读取；明确 `partial` 时只补读缺失页面或元素。

`visual` 捕获前后都绑定同一 Office 版本。返回 `VERSION_CONFLICT` 时，先重新 `inspect` 页面和 selection，再重新捕获；不要继续使用旧画面或旧元素 ID。视觉结果必须来自真实 `SlideCanvas`，不能用第二套简化绘制替代。

## 0 结构到视觉的顺序

1. **结构**：确认页面数量、稳定页面/元素 ID、边界、元素类型、文字和 style 摘要。
2. **Review**：布局写入或收到布局 warning 后调用 `inspect review`，取得当前版本的 `pendingSlideIds` 和 `warnings`。
3. **视觉**：对待观察页面调用当前版本的 `inspect visual`，检查真实 PNG 中的层级、对齐、裁切、对比度、图表/图片语义和整体节奏。
4. **微调**：只提交局部 `slide_set_geometry`、`slide_set_font`、`slide_set_fill` 或 `slide_set_stroke`；每批使用最新 `expected_version`，任何变更后都要再次 review，并用最新版本重新获取整页视觉画面。
5. **交付**：确认最后一次结构、review 和视觉检查的版本相同，再 `save` 或 `export`。

## 布局 review 门控

布局写入或 `apply` 返回布局 `warnings` 后，调用 `inspect review`。它返回与当前版本绑定的 `pendingSlideIds` 和 `warnings`；对每个待观察页面用当前版本调用 `inspect visual`。`[错误]` 必须通过局部修改消除，整页截图成功也不会解除待检查状态；`[需检查]` 必须结合真实画面判断，非有意或不可读的交叠必须修改。有意且可读的图上文字，必须先用当前版本、不带 `elementIds`/`region` 的 `inspect visual` 获取整页截图；只有确有理由保留时，才用同一页面和版本再次查询，增加非空 `reviewReason` 与 `acceptWarnings: true` 明确接受。缺少同版本整页前置观察、仅有局部/过期截图或存在 `[错误]` 时不能接受；任何变更后都要以最新版本重新 review 和获取整页画面，不能在没有修正操作的情况下把审核标为完成。

普通 `export` 在仍有未审阅布局页时会返回 `REVIEW_REQUIRED`。此时不要重试旧导出请求，先按 `pendingSlideIds` 完成当前版本的 review。`allow_unreviewed` 仅在用户明确要求草稿或跳过审阅时使用；该导出仍标记为未审阅，不能称为已验收。`save` 不受此 review 门控影响。

## 先查硬问题

按下面顺序检查每一页：

1. 所有元素在页面内：`x >= 0`、`y >= 0`、`x + width <= slide.width`、`y + height <= slide.height`。
2. 标题、正文、来源和图例没有互相覆盖，文本没有超出自己的容器；标题换成两行时，先增高文本区域并把正文移到标题实际底部之后。长标题优先改写或调整容器，而不是把字号压到不可读。
3. 图片确实存在、比例合理；人物、证书、截图和数据图不应被无意裁掉。
4. 主信息在视觉层级上最突出，阅读顺序能从标题走到证据和含义；页面没有多个同等“主角”。
5. 文字与背景有足够对比，复杂图片上的文字有遮罩；颜色不是唯一的状态或类别表达。
6. 内容与对象语义一致：标题仍是结论，数字、单位和类别没有错位；每个必含 item 都有可见落点，流程节点数量与步骤一致，没有因版式压缩而合并或丢失内容。

任何硬问题都应在下一次小批次 `apply` 中修复，随后再次 `inspect review` 和 `inspect visual`。先完成一张代表性内容页的检查，再批量延续同一布局；同一问题连续两轮调整仍无改善时报告“待完善”，不虚报完成。不要用重建整页的方式修复一个元素。

## 软问题和一致性

只修明显影响理解的问题，保留有意的留白和非对称：

- 同一列的标题、正文和图形应落在同一网格线上；同类模块的间距和尺寸要有规律。
- 相邻页面保持字体角色、主色、图标风格和边距一致，但不要每页重复相同卡片网格。
- 对普通内容页，可将有效内容外接框覆盖正文可用区高度的 **70%–90%**、最下方有效内容到达正文可用区 **80%** 以后作为纵向平衡的自检参考；封面、章节页、引用页和刻意留白的 `breathing` 页排除在外。这两个比例不是硬阈值，纯背景、页框、装饰线和页码不能用来凑比例。
- 对比对象拆成独立模块，保持相同比较维度和对齐关系；禁止用字符块或空格模拟数据图表。
- 密集页通过删减、分组和留白改善阅读，不持续缩小字号；单一结论页可以更空，但必须有独立信息。
- 图表检查数据类型和表达是否相符；常见 `bar`、`line`、`area`、`pie`、`doughnut` 优先使用 `slide_add_chart`，复杂图表使用 [advanced-operations.md](advanced-operations.md) 的已验证操作；`chart` 类型才是原生图表，`picture` 类型的 SVG/PNG 只能按图片检查。
- 关系图的对象类型和可编辑性按 [advanced-operations.md](advanced-operations.md) 核对；节点是否一一对应内容、图标是否保持统一资源风格按 [design-method.md](design-method.md) 检查。截图只能证明视觉结果，不能替代对象类型和可编辑性检查。
- 图片必须解释或支撑页面内容，说明文字贴近图片；无关库存照片、过度渐变、厚阴影和装饰性线条都应删除或收敛。

好的页面通常是“一个标题结论 + 一个主证据 + 一句含义”；坏的页面常见为主题式标题、六个同等大小的模块、图表没有结论、或文字压在复杂图片上。

## 保留人工编辑

每次 `apply` 前确认 `expected_version` 来自最近一次 `inspect` 或成功的 `apply`。如果版本变化、元素 ID 消失、文字内容已被用户改写，先重新读取并只针对当前状态提出修改。不要覆盖未保存的用户内容，不要把早先完整页面计划再次批量写回。

审核完成的最低标准是：没有越界、覆盖或明显溢出；页面主信息清楚；必含事实和步骤完整；图表、图片和 SmartArt 语义正确且对象类型与编辑需求相符；字体、颜色、图标和节奏在整份稿中保持一致；`inspect review` 没有未处理的待观察页，或已明确披露可接受 warning；最后一次检查的版本已经 `save` 或 `export`。如果问题需要改变论证、增删章节、替换图表类型或修改品牌系统，应报告给用户/主 Agent，而不是在视觉审核阶段擅自重构。
