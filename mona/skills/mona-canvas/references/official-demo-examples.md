# 官方 Demo 级创作样例

这些样例用于学习构图方法和验收质量，不是生成模板。每次任务都从当前内容重新建立对象、关系、边界和视觉角色，不能按关键词复用示例节点、文案、坐标或整份 patch。

四类 Demo 的共同配色是白底、低饱和浅填充、中等明度描边和深灰正文。RAG 用淡色块区分职责；AWS 图大面积留白，只让少量服务和路线带色；Open Innovation 用低透明度环层和层级对比突出中心；Cat 用奶油色主体和赭黄色描边。不能把“多语义色”误解为多个高饱和实心色块。

## Transformer 双列技术图

字段参考资产：[transformer-official-demo.patch.json](../assets/transformer-official-demo.patch.json)。它只用于 L0 回归和理解 Mona 如何表达分区、重复模块、次级路线与文字层级，不得在产品创作中直接应用。

设计选择：内容天然分成 Encoder 与 Decoder 两个重复模块，因此先留出左右分区和中间跨区通道，再安排各列主链。Attention 使用暖色，Add & Norm 使用绿色，位置编码使用黄色，输入/输出使用蓝色；同义节点同色。残差关系沿分区外侧使用灰色虚线，Encoder Output 使用单独的红色虚线和标签。标题、分区标题与 Nx 都是可编辑文字对象。

迁移原则：只有内容确实存在两个并行或对照模块时才采用双列。模块数量、标签长度或主关系变化时重新计算列宽、节点高度和通道，不保留 Transformer 的固定坐标。

## 跨题型迁移

- RAG 架构的关键不是固定节点，而是把在线查询链作为主路线，把离线摄取链收进有标题的次级区域，并让两条路线通过少量跨区边建立关系。
- React/AWS 认证图的关键是边界拓扑：用户和客户端在边界外，网关、计算和数据在边界内，支付等外部服务在另一侧；认证、请求、回调和状态路线使用不同且一致的视觉编码。
- Open Innovation 的关键是同心概念关系：外部环境、内部核心与中心能力用低层级区域表达，进入、授权、孵化和市场反馈用有方向的关系连接。
- Cat sketch 的关键是自由图形组合：圆、椭圆、三角形和旋转线段通过统一描边、填充、层级与比例组成一个可编辑整体。

需要为新题目选择主语法时，再查 [diagram-grammars.md](diagram-grammars.md)，依据内容特征选择主语法；不要判断“最像哪个 Demo”。

## 退款泳道流程

完整源：[refund-swimlane.patch.json](examples/refund-swimlane.patch.json)

设计选择：用户、业务系统和支付系统存在明确责任交接，因此使用泳道。判断节点的两条边都有文字；拒绝路径使用弱红色虚线，正常路径保持主色。中文标签先保证可读尺寸，再由本地布局扩展泳道。

## 从检查到局部修正

若 `canvas.inspect` 返回 `text-overflow`，先针对对应节点使用 `updateNode` 修改 `size` 或插入合理换行；若返回 `edge-through-node`，只更新对应边的 handles/controlPoints，或移动相关节点。每次修正使用最新两个哈希。只改颜色时保持所有位置、尺寸和边路径；不要用 `reflow` 或 `replaceGraph` 处理单对象样式修改。

真实 DOM 检查为 `unavailable` 时，说明还没有完成视觉验收。根据工具的阶段化回执继续；工具负责连接恢复，不要猜测编辑器挂载状态、反复连接或重复同一个失败调用。不要把空 issue 列表当作通过。
