# 画布视觉语法选择

高质量画布不是从题目名称匹配模板，而是把内容模型映射为适合阅读的空间关系。开始写 patch 前，按内容需要从下面几个维度判断。

## 1. 抽取内容模型

只记录用户内容中的事实：参与者、组件或概念，方向明确的关系，系统或责任边界，主路径、反馈路径和需要强调的结论。把同一层级的对象放在一起；细节若会破坏主线，就收进一个次级区域或注释。

## 2. 选择主语法

| 内容特征 | 主语法 | 构图规则 |
| --- | --- | --- |
| 顺序、分支、汇合、数据经过多个阶段 | 连通数据流 | 主链保持单一方向；分支并列、汇合收束；离线或辅助管线放入独立次级区域 |
| 服务部署在平台、网络或组织边界内，外部参与者发起调用 | 边界拓扑 | 先画边界，再按入口、计算、数据和外部系统分层；同步、回调、状态分别使用稳定线型和颜色 |
| 多角色之间交接职责 | 泳道 | 一条泳道代表一个责任主体；跨泳道边代表交接，不用颜色伪装责任归属 |
| 模块之间是上下层依赖或对照关系 | 分层或分列 | 同层保持等宽和对齐；跨层边走预留通道；对照结构只在内容真的对称时使用 |
| 核心、内圈、外部环境或由中心向外影响 | 同心/放射 | 用低层级、低透明度的椭圆或圆建立区域；语义节点置于其上；径向边优先 straight 并显式选择朝向目标的 handles |
| 用户要求符号、草图、角色或非流程示意 | 自由图形组合 | 用圆、椭圆、三角形、矩形、括号等基础形状组合；依靠 zIndex、rotation、opacity 和统一描边形成整体 |

复杂图可以嵌入一个次级语法，例如连通 RAG 主路径下方再放一个有边界的离线摄取管线。不要让多个主语法争夺阅读顺序。

## 3. 先规划空间，再写对象

1. 确定页面边距、标题区、主要区域和连线通道。所有 `position` 都是图形外接矩形左上角，不是圆心或中心点。
2. 为边界或装饰图元预留底层 zIndex；它们使用 `decorative: true`，不进入流程语义、自动布局和普通节点重叠检查。
3. 放置语义节点。规则流程和架构优先 `auto`；同心结构、精确边界拓扑和自由图形使用 `manual`。
4. 最后设计路线。主关系使用连续实线，反馈、异步或弱关系使用次要颜色或虚线；每种线型在一张图中只表达一个含义。

可视节点支持 `zIndex`（-100 到 100）、`rotation`（-360 到 360）、`opacity`（0 到 1）和 `decorative`。自由图形的每个基础形状都应可选中和编辑，不用一张图片替代整个图。

## 4. 自己完成设计选择

用户未指定样式时，根据内容选择结构和视觉角色，不追问颜色。默认使用浅背景、深色正文、一个主强调色和少量状态色。同义对象保持同色；边界用低对比填充；标题、区域标题、节点正文和边标签形成四级字号。品牌图标不可用时选择含义相近的通用图标并保留文字标签，不凭空伪造品牌图形。

官方 Demo 的价值在于证明这些语法能迁移到不同题型：RAG 展示主数据流与次级管线，认证架构展示系统边界和多种回路，开放创新展示同心概念模型，猫草图展示基础形状组合。它们不是可按关键词调用的坐标模板。
