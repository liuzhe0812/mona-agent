# Excel 专业编辑规则

## 决策顺序和保真

- 处理顺序是用户明确要求、现有工作簿的参考结构、适用的业务惯例、最后才是默认做法。已有格式、公式、工作表、表格区域和其它文件特性应先读取并尽量保留。
- 窄范围编辑不擅自新建辅助表、KPI 卡片、批注或其它展示层；只有用户明确要求且当前操作可用时才增加结构。

## 数据、公式和结果

- 先识别原始数据、计算区域和结果区域。分析或改造已有表时保留原始值，不用结果列覆盖来源列；用户没有授权时不删除工作表或历史数据。
- 真实关系用 `set_formula` 表达，公式以 `=` 开头并引用实际单元格或工作表。先读取目标范围和公式，再决定修改；读回已完整覆盖目标时不重复扫描，明确 `partial` 时只补读缺失范围。不要因为预期结果看起来简单就写入硬编码数字。
- 公式结果以编辑器 `inspect` 返回的 `value` 为准。结果为空、错误或与业务逻辑不一致时，重新检查输入、引用和单位，向用户报告不确定性，不凭空补结果。
- 公式、输入和结果都要有清楚的列名。跨表引用、百分比、日期和金额要在标题或说明中表达含义。
- 数字、比例和日期作为可计算的 typed 值写入；当前 Office schema 的单元格值没有 Date 类型，需要日期时使用 Excel 支持的日期序列值并配合 `yyyy-mm-dd` 格式。业务编号、邮编、账号和带前导零的标识保留为字符串。
- 输入、假设、中间计算和输出应能沿单元格引用追踪。优先使用有意义的中间计算或直接引用，不因局部编辑顺手增加辅助表。
- 复制或调整公式时检查相对引用与绝对引用（如 `$B$2`）是否仍指向正确范围；跨表名称含空格或特殊字符时使用单引号，例如 `'月度汇总'!B2`。
- 对预期缺失值先明确业务处理方式；不要用覆盖一切的 `IFERROR` 或伪造的 0 隐藏错误，也不要用显示结果代替真实公式。

## 数字格式和单位

- 数字格式服务于含义：金额使用统一货币或千分位格式，百分比使用百分号格式，日期使用统一日期格式；不要把带单位的文本和可计算数字混在同一列。
- 常用格式可使用 `#,##0`、`0.0%` 和 `yyyy-mm-dd`；格式只改变显示，不把“120,000”“12.5%”或日期文本写进需要计算的单元格。
- `set_style` 的当前字段包括 `fontFamily`、`fontSize`（磅）、`bold`、`italic`、`underline`、`strikethrough`、`color`、`backgroundColor`、`numberFormat`、`horizontalAlign`、`verticalAlign`、`wrapText` 以及 `borderTop`/`borderBottom`/`borderLeft`/`borderRight`。格式写在对应范围，不用手动给每个单元格添加不一致的装饰。
- 边框对象使用 `{ "style": "thin|medium|thick|double|hair|dashed|dotted", "color": "..." }`；边框用于分组和阅读路径，不能用粗框包围每个单元格制造噪声。
- 设置格式后用 `inspect` 且 `include_style: true` 复核关键范围；格式不能改变原始数值或公式。

## 表格结构和可读性

- 第一行或明确的表头区域写清列名和单位，数据列保持同一类型，空值和 0 的语义要区分。重要区域可用加粗、底色和对齐建立层级，但颜色要少且有一致含义。
- `set_range` 的 `values` 必须是与目标范围匹配的矩形二维数组；长表按行块分批写入。单元格文本、数字、布尔值和空值保持真实类型。
- 行列插入/删除操作的 `index` 使用 1-based；`move_sheet.position` 也使用 1-based。结构变化后重新读取受影响区域，确认公式引用和数据位置仍正确。
- `set_column_width`/`set_row_height` 的 payload 是 `{sheet,index,count,size}`，`index`/`count` 从 1 开始；列 `size` 是字符宽度，行 `size` 是磅。调整后用 `range` 的 `include_style: true` 读取 `columnWidths` 和 `rowHeights`，分别按字符宽度和磅检查。
- 合并单元格只用于不参与计算的标题或说明，并在分析和编辑数据前确认合并范围；不要合并数据表的字段、记录或公式区域。
- 来源、口径和必要假设放在可审计的普通单元格或说明区域，保留已有特性和格式；同一数据表的行字体保持一致，列宽和行高贴合内容。
- 长表需要持续看到表头时，可用 `set_freeze_panes` 冻结最小必要的行列；需要筛选记录时，用 `set_auto_filter` 覆盖完整且包含表头的数据范围。紧凑摘要表不默认冻结或筛选。
- 条件格式只表达会随数据变化的状态、风险、差异或异常。优先使用有业务含义的 number/text/formula 条件或克制的 `colorScale`；不为装饰整张表添加彩虹色阶。

## 选择和视觉检查

- 用户选中单元格时优先使用 `open` 回执中的 `selection`，仅在选区过期或缺少详情时再 `inspect selection`，以返回的 `sheet` 和 `range` 为准；不要猜当前活动表或选区。
- `inspect visual` 返回带 `version` 的真实编辑器 PNG，但 Excel 只截取当前 viewport。视觉检查只能说明当前可见区域；全表验收必须结合分块 `range`，必要时配合滚动到其它区域后再次 visual，不能声称一张图覆盖全表。

## 操作边界

- 工作表名称、范围和公式引用取自当前 `inspect`，不依赖默认名称或旧版本快照。
- 原生单元格/范围用于需要编辑和数据含义的表格；仅为排版的自由文本可保持文本区域，不为形式强行增加表格结构。当前 Agent schema 未提供原生图表和数据验证操作；这些功能若未由用户在编辑器中完成，交付时应明确标记未实现。

## 好坏对照

- 好：收入写入 `120000`，再用 `#,##0` 显示；坏：把“120,000 元”作为文本写入收入列。
- 好：缺失成本按业务约定留空并在说明中标记，公式暴露缺失；坏：用 `IFERROR(...,0)` 把错误和未知都变成 0。
- 好：沿用既有工作表、字体和公式，只调整用户指定的列宽；坏：为做一张 KPI 卡片合并数据区并新增未经要求的辅助表。

交付前检查关键公式错误、输入与输出对账关系、单位和精度；不能只看图表或一眼看起来合理的数值。
