# Excel 质量验收

## 数据和公式

- 验收决策遵循用户要求、现有工作簿参考、业务惯例、默认做法的顺序；未授权的新增展示层、辅助表或批注不进入交付。
- 原始输入区域与结果区域边界清楚，用户提供的值没有被覆盖、截断或改成文本；空值、0 和文本的语义保持正确。用户明确要求不损失数据时，用“原文数据项/公式/表格区域 → 输出单元格/区域”的覆盖清单逐项核对，再报告完整。
- 数字、比例和日期是可计算的 typed 值；日期在当前 schema 下使用日期序列值配合格式，业务编号和前导零标识仍是字符串。
- 关键计算单元格通过 `inspect` 的 `formula` 字段确认仍是公式，公式引用了实际输入区域；结果 `value` 来自编辑器计算，没有手工伪造或把预期结果写回单元格。
- 公式涉及跨表、百分比、金额或日期时，工作表名称、引用、单位、除数和精度都经过复核；跨表名含特殊字符时使用单引号。检查关键公式错误和输入/输出对账；若结果报错或无法判断，交付中明确标记问题。
- 复制公式后抽查相对/绝对引用；预期缺值有明确处理，不用 `IFERROR` 统一吞错或用伪零制造完整结果。

## 格式和可读性

- 表头、数据列、结果列和单位容易区分；金额、百分比、日期等关键列的 `numberFormat` 与业务含义一致。
- 需要时使用 `#,##0`、`0.0%`、`yyyy-mm-dd` 等显示格式，显示格式没有代替真实数字、比例或日期值。
- 关键范围的 `include_style: true` 结果符合预期；对齐、字体、字号、边框、自动换行和底色保持一致，格式没有改变数值或公式。
- 实际需要筛选、冻结或动态状态时，`summary`/`range` 返回的 `autoFilter`、`freeze` 和 `conditionalFormatCount` 与界面一致，保存重开后仍存在；不需要时不为形式添加。
- `columnWidths` 按字符宽度、`rowHeights` 按磅数值合理，长标题和关键数值没有被截断；尺寸操作的 `index`/`count` 与目标范围一致。
- 数据区域没有无意义的合并；如使用合并标题，合并范围不参与计算且不会遮挡字段或记录。长表按区域检查，没有明显的空列、错位或重复表头。
- 先用 `range` 分块核对全表的值、公式和样式，再用 `inspect visual` 检查当前 viewport 的真实布局。Excel 视觉图只覆盖当前 viewport，不能把一张图当作全表视觉验收；跨屏区域需结合范围读取，必要时配合滚动后重新截图。
- visual 返回的 `version` 必须与本轮结构检查一致；版本冲突时重新读取并重做视觉检查。

## 结构和文件

- 结构操作后重新读取工作表摘要和受影响范围；工作表名、顺序、行列位置与用户要求一致，引用没有因插入/删除而指向错误区域。
- 每次 `apply` 使用最新 `version`，版本冲突会先重新读取并保留用户修改；失败的原子批次没有留下半套数据。会话断开或暂时失败时，使用原 `session_id` 调 `office open` 恢复同一会话，不新建会话或重建工作簿。
- `save` 或 `export` 使用最后一批修改后的版本。导出的 `.xlsx` 能重新由 `office open(path=...)` 打开，摘要、关键范围、公式和格式仍可读取。
- 既有工作表、公式、格式和文件特性保持不变，除非用户明确要求；同一数据表字体一致，列宽和行高适合内容，数据区没有无意义合并。
- 只有实际在 Excel/WPS 等外部应用中重开并检查过，才能报告对应应用兼容性；未验证的平台或应用标为待验证。

## 未见过的 Excel 任务

至少执行一次“打开 → 选择合适的原文入口 → 小批次修改 → 局部复核 → 导出”的闭环，并根据任务内容决定是否需要结构操作；若读回明确为 `partial`，只补读缺失范围，不交叠扫描。验收标准始终是数据真实、公式可追溯、单位和数字格式清楚、表格可读以及原生文件可重开，不以固定模板或无关图表作为完成条件。

标题保持克制，不能以默认 KPI 卡片代替可审计的表格信息；来源和必要假设应能在普通单元格或说明区域中追踪。
