# 口播动画的创作与审片

这份核心设计知识在视频 Agent 的规划上下文中直接提供。具体艺术配方、
讲解语法和绘图源码按题材选读，不要求用同一画法或同一种工具完成所有视频。
风格负责配色、文字和材料的一致性；构图、镜头和动作由内容决定。

## 把一句话变成可见的事件

先确定观众这一刻应该理解什么，再选择对象与动作。设计需要说清：
起初是什么状态、口播中的哪件事导致变化、变化后观众能看出什么。
进入、放大、淡入、摇摆是实现手法，不是解释本身。

| 讲解内容 | 可以承担解释任务的画面变化 |
| --- | --- |
| 面对多个选择 | 同一个人物实际看向或走近选项，选项呈现不同后果；决定与后悔改变人物行动，而不只是头顶漂浮 A/B/C。 |
| 从混乱变成结构化 | 让原有对象分组、对齐、连接成关系；保留对象身份，让人看见整理发生，而非在乱线旁另外显示一张流程图。 |
| 比较与权重 | 先建立共同标准，权重变化改变贡献、总分和排名，结论从这些变化中产生；没有数据时作明确的条件演示，不编造数字。 |
| 机制与尺度 | 沿同一物体或过程深入，拆出组成部分、跟随信号或改变尺度，说明各部分如何作用。 |
| 数据与趋势 | 建立单位和坐标，再让真实数据发展；标注口播指出的差异，最后留出读懂结果的时间。 |
| 证据与产品 | 让授权文档、截图或视频成为主体，沿证据关系移动，靠裁切、标注和镜头聚焦到正在解释的事实。 |
| 故事与情绪 | 角色姿态、视线、手势和反应景别响应事件；中景交代处境，特写或大全景服务真实的情绪变化。 |

例如讲加权评分：A/B 保持身份 → 标准建立 → 权重影响各项贡献 → 总分变化 →
两方案的位置交换 → 回到具体标准解释为什么。画面简洁也可以完成这些推导。
白板可以逐步建立同一张关系图，几何可以连续变形，真实素材可以组织为连续空间。
按内容选择并组合这些机制，不需要填充特效。

规划时先用这份核心方法和已提供的新 Huashu Motion 创作库形成具体画面事件；需要
进一步理解表现机制时，再选读相关设计卡。详细源码和运行时 API 留到用户
确认后、实现相应动作时按需读取，不为准备分镜先通读大段引擎代码。
已有背景知识无需重复读取。不要用“已经读取资料”代替分镜中的具体设计
决定，也不要搬用例子的题材与数据。

## 用画幅与观看尺度安排注意力

一段内容可以有多个内部镜头。让视线能跟随主体，必要时改变景别，信息密集
时停住，解决后再揭示整体关系。无必要的持续推镜也会形成演示文稿感。
不要把多个微小示意图摆在整幅竖屏上，却留下大面积没有用途的空白。

检查最终显示尺度下的关键文字和动作。1080 宽竖屏里 18 像素的主要流程标签，
缩到手机显示后通常很难读；这不是所有图形都必须采用固定字号的规则。
先确定主次、分镜与观看目标，再选择尺寸。角色应与正在解释的对象发生关系，
不能只是填空的人形图标。
比较与排名变化过程中也要能追踪数值和共同基准；不要为了交换位置，把正在
讲解的贡献条缩成微小卡片或移出刻度。真实界面演示以操作目标和结果为重点，
需要时放大裁切到任务、按钮和状态；旁边的解释大字不能代替读清实际界面。

字幕安全区属于构图条件。重要路线、图表结果和标注要避开字幕；字幕分行
应保持词句易读。先安排主要视觉事件，再给字幕与辅助标注留出位置。
使用实际共享颜色变量。未定义的 CSS 变量可能退回黑色，即使代码没有报错。

## 实际配音后的编排

用实际口播锚点安排动作，而不只把整句开始时间用于统一入场。一个重要动作
应有可理解的起点、发展和结果；观众看完最后一个变化后才开始计算阅读停留。

检查场景时间与口播覆盖区间。若 30 秒场景的最后一句在 18.55 秒结束，后面
11.45 秒需要有明确用途：理解结果、完成推导、过渡或有意的静默。不靠轻微
呼吸、闪烁或漂移把它包装成“全程动画丰富”。时间确实不合适时，按用户已确认的意图
提出具体调整，不能在编码时擅自修改已确认的时长或旁白。

实现可以自由改进布局、对象大小、相机、动作细节和阅读停留，只要沿用已
确认的故事与视觉意图。用户明确要求修改某段时，以这次要求授权局部修改，
更新该段并保留其他内容。更换主题或整体结构时才先返回导演台展示新版方案；
修正遮挡、放大文字或更换更合适的画法无需让用户反复审批。

## 观察输出，然后修订

预览只产生技术观察，不能给出审美合格证。`distinctVisualStates`、
`longStillIntervals` 和脚本无错误都不能证明解释正确、构图合理或动作丰富。
有意的阅读停留可以静止；持续微动也可能没有内容。

审片依据实际时间点画面与完整播放，而不是对照自己写过的代码意图：

- 重要口播点：画面中实际哪个对象发生什么变化，观众因此能理解什么？
- 主体与关系：尺寸是否合适，选项、结果、路线是否清楚，角色动作是否有作用？
- 连续性与节奏：前后对象能否追踪，变化是否有起因，结果是否停得够读，尾段是否有用途？
- 可读性与执行：关键文字、字幕、颜色、遮挡是否正确，截图和反复定位能否验证修订？

简短记录具体时间与观察，例如“12.3 秒权重变化，但排名没有响应”或
“17 秒路线在字幕后面”，再按原因修订。不要把“没有长静止区间”写成
“动画丰富”，也不要只为消除诊断提示增加循环。不能看到实际图像或完整播放
时说明观察限制，不推定创作质量通过。
