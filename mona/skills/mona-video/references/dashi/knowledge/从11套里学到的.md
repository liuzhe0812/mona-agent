## 一、最要紧的 11 条

1. **画面只由 t 决定**：不用 CSS 动画、transition、requestAnimationFrame、Date.now()、不带种子的 Math.random()；要随机用带种子的（mulberry32），并在 seek(t) 里每次重建。逐帧截图时，不跟着 t 走的东西会乱跳。（README 页面约定第 5 条）
2. **满屏颗粒/纸纹会把渲染拖慢 2–3 倍**，慢的是 Chrome 把每帧压成 PNG，不是页面 JS（S44 页面 JS 每帧不到 1 毫秒）。纹理只生成一次缓存；满屏颗粒的风格出片用 `--format jpeg`。（09 日志 01:43【S44】、01:20【S35】、23:06【S47】）
3. **写死的秒数一律不要**：时间全部从 `TL.mark('词')`、`TL.shots`、`TL.cues` 取；S44、S50 交付前都专门把残留的写死秒数改掉了。换一段口播时，写死的秒数就是错的。（09 日志 02:01【S44】、09:24【S50】）
4. **底部约 170 像素只放字幕**：好几套都出过「部件掉下去 / 滚动卡片 / 纸堆穿过字幕区」。（09 日志 09:11【S03】、15:57【11】）
5. **480 宽读字标准**：要观众看清的字，原尺寸 48 像素以上（缩到手机竖屏看横屏视频的 480 宽约 12 像素）；不够就让镜头推近。每次出静帧都看一眼自动生成的 480 宽检查图。（单套任务模板；09 日志 23:11【S06】）
6. **换场时最容易叠字**：上一镜头的标注还没淡完、下一镜头的部件已经进来。扫片时专门看每个镜头交界前后 0.5 秒。（09 日志 01:22【S35】、09:19【S50】）
7. **镜头快速移动时，跟着跑的部件会被甩出画面**：要么按世界坐标让部件比镜头先到，要么逐帧算一遍画面坐标确认不出画。（09 日志 23:04、23:08【S06】）
8. **分段写页面、每段落盘记日志**：11 套里 10 套都碰到过断网或额度用完，接着做时靠「index.html 第 N 段落盘」那行日志知道停在哪。（09 日志 22:41 一组续做记录、09:05【S33】）
9. **每帧开头把画布状态整套复位**（v1.3 补）：上一帧设的 lineCap、lineJoin、setLineDash、globalAlpha 没还原，会漏到下一帧。按时间顺序出片看不出来，单独出某一秒的静帧、或先出后面再出前面，画面就不一样——立体卡通、黑底科技、复古报刊三套的旧示例页都有这个问题，v1.3 用 `动效.resetCtx(g)`（或 `g.reset()` 再设默认值）修好。验法：`render.mjs <页面> --check-determinism auto`。
10. **从画布取画面的部件要跟着镜头换坐标**（v1.3 补）：放大镜这类从主画布截一块放大的部件，镜头推近以后要先按当前变换把位置换成屏幕坐标再截，不然镜片里放大的是别处。（复古剪纸 v1.3）
11. **字体栈第一个是英文字体时，中文的竖直位置会偏**（v1.3 补）：中文落到栈里后面的宋体时，字身比 `textBaseline = 'middle'` 算出来的中线高约 0.27 个字号；镜头推近时标题因此被顶进了页眉带。标题位置按实际渲出来的静帧对，别只信基线。（超现实拼贴 v1.3）

## 二、渲染速度和画质

**现象 → 原因 → 改法**

- S47 第一次成片 222 毫秒/帧 → 页面绘制只要 9 毫秒，慢在 PNG（每帧 3.6 MB，S19 只有 0.4 MB）；主因是 Chrome 给 `createRadialGradient` 加的抖动噪点 → 纹理改在 1/8 分辨率画布上直接算像素再放大，细颗粒半分辨率最近邻放大（2×2 一粒），同一段 256 → 148 毫秒/帧，观感基本不变。（09 日志 23:06【S47】；README「经验补充」）
- S06 第一版 158 毫秒/帧 → 满屏颗粒拖慢截图（有颗粒 146、无颗粒 63 毫秒/帧）；参考图本来是干净印刷 → 去掉颗粒。（09 日志 22:57【S06】）
- S44 PNG 248 / JPEG 99 毫秒/帧 → 颗粒让每帧 PNG 约 3 MB → 颗粒改成 3×3 一块并调淡、纸底去掉逐像素噪点（保留斑驳和纤维），PNG 降到 1.5–1.9 MB。（09 日志 01:43【S44】）
- S35 PNG 284 / JPEG 108 毫秒/帧 → 满屏颗粒做 PNG 编码 → 出片用 `--format jpeg`。（09 日志 01:20【S35】）
- 开 `--gpu` 反而更慢（测试页 82 对 65 毫秒/帧），默认软件渲染。（README）
- 10 套同时渲染时机器负载 50–120，单帧从 51 涨到 280 毫秒；一次渲一套。（事实；09 日志 01:34【S44】）

## 三、画面正确性（扫片时最常见的问题）

| 现象 | 原因 | 改法 | 出处 |
|---|---|---|---|
| 镜头快速下潜时，8 块 Token 跟不上、被甩出画面顶 0.3 秒 | 部件按画面坐标插值，镜头一快就落后 | 改成按世界坐标飞、每块 0.5 秒、比镜头先到；再用脚本逐帧算画面坐标，确认不出画 | 09 日志 23:04、23:08【S06】 |
| 上一处改法的副作用：落定的 Token 被钉在画面顶上，下一个镜头还看得见 | 修一个时刻、没回头看别的时刻 | 每次改动后重出 480 宽检查图和扫描图，整段再看一遍 | 09 日志 23:08【S06】 |
| 消息飞向 AI 的起点比原气泡低 49 像素，像叠了两个 | 飞行物另起坐标，没从原位置出发 | 飞行物从原部件的位置升起，原部件同时隐藏 | 09 日志 23:04【S06】 |

## 四、读字和字幕

- 字幕：底部居中、单行、字号不小于 60 像素，字和背景对比要高；文字和时间一律用 `TL.cueAt(t)`，不改字、不改时间。（分镜「字幕规则」）
- 关键词在字幕里的标法各套不同（马克笔底、色块底白字、撕边纸条上刷笔刷），但两个强调色 A/B 的词，字幕里和画面里用同一种颜色。（各套风格卡）
- 小字：S06 把数据格 42 → 48 像素、消息气泡 34 → 38 像素；S22 把 @分词器 等标签放大到 52 像素；S09 数据短句改到 47 像素——都是看了 480 宽检查图才发现不够大。（09 日志 23:11【S06】、01:37【S22】、22:53【S09】）
- 一条字幕最长约 20 个字（64 像素单行放得下）；`字幕.mjs` 默认按稿子的逗号句号分条，超过 20 个字从中间停顿处切开。

## 五、字体

- 兰亭黑、圆体、手札体、翩翩体、楷体、隶变、魏碑、报隶、行楷、凌慧体是 macOS 按需下载的字体，没下载时系统只带一部分字，一个词里可能一半是这个字体、一半退回苹方。一直都在的是苹方、冬青黑体、宋体-简。查完整字体文件在不在：`node pipeline/自检.mjs`。（README「本机能用的中文字体」10-08 09:15 补）
- 字体族名写错时 Chrome 会悄悄退回苹方，不报错；改完字体一定渲一张静帧看。（README「出错时」）
- 用户自己装的字体（MiSans、思源、Montserrat、Bebas Neue、猫啃什锦黑）要在字体栈里写好系统替代。各套去掉用户字体后的实测：

| 套 | 换成什么 | 实测观感 | 出处 |
|---|---|---|---|
| S19 | 去掉 MiSans → 兰亭黑 Heavy / 苹方 | 几乎不变 | 09 日志 20:59 |
| S03 | 思源黑/宋、Bebas → 兰亭黑 Heavy、苹方、宋体-简、DIN Condensed | 几乎不变 | 09:11【S03】 |
| S44 | 思源宋体、Montserrat → 宋体-简 Black、Avenir Next | 基本不变 | 01:50【S44】 |
| S35 | 去掉兰亭黑、圆体（模拟没下载）→ 苹方 | 版式不变，标题没那么粗、Token 块的字没那么圆 | 01:27【S35】 |
| S50 | 去掉兰亭黑 → 冬青黑体 W6 | 版式不变，粗细轻一档 | 09:21【S50】 |
| 11 | 去掉思源宋体 → 宋体-简 + Baskerville | 几乎不变，只有字幕里夹的西文略窄 | 16:38【11】 |
| S47 | 去掉猫啃什锦黑 → 兰亭黑 Heavy | 像，但少了手剪字的味道 | 23:10【S47】 |

- 验证「所有字都出自这几个字体」的办法：把字体栈里的替补全换成一个很不一样的字体（S22 用 Courier New），渲同样的静帧，逐字节一样就说明没有字掉到替补上。（09 日志 01:40【S22】）
- 只有一个字重的展示字体，先查缺字（S47 查了 276–298 个字全有）。（09 日志 21:32、22:54【S47】）

## 六、配色：两个「全片固定上色的词」（强调色 A / B）

- Token 例子里「成都」「旅行」全片用固定的两种颜色（Token 块、数据高亮、字幕里都一样），观众一眼能跟住这两个词。新内容里对应 `分镜.json`「高亮」的两个词（role A / B），颜色在各套风格卡里。（分镜.md；单套任务模板）
- 10-07 23:20 主会话统一了规则，各套照此改色（09 日志 23:13–23:20 一组、01:30【S03】、01:39【S50】）：
  1. 参考图里本来有红、有蓝 → 用参考图自己的红和蓝（S06 #bb3633 / #1d3d8a、S44 #a02503 / #3aa6c0、S47 #f04f35 / #1c5292、S09 #bb342b / #4177b5）；
  2. 只有其中一种 → 有的那种取参考图的，缺的那种用默认值（红 #d41928、蓝 #2373ce）：S35 成都默认红 + 旅行手套蓝 #569bd0，S03 成都默认红 + 旅行藏蓝 #213e62；
  3. 参考图色板里两种都没有 → 用色板里最醒目的两种对比色：S22 橙 #f8711c / 墨蓝 #15192d（参考图只有墨蓝和橙），11 黑底科技 印章红 #b1312a / 金 #cdac6a（原片没有蓝）；S50 参考图没有蓝，用默认红蓝，表情黄留给 AI 表情，免得撞色。
- 其余关键词的颜色要避开 A/B 的色系：S44 去掉了太像蓝的青绿；S47 把朱红系的部件改成别的颜色、盖章朱红改黄。（09 日志 23:20【S44】、23:16【S47】）

## 七、怎么把一个概念演成画面（换新内容时找类比）

### 通用概念怎么画（v1.1 补）

先把口播里的概念归到下面哪一类，再找一个**看得见、会动**的东西来演；关键动作卡在说这个词的那一刻（`TL.mark`）。

**一次实测里用过的**（2026-10-08 观众实测：23 秒口播「上下文窗口与多模态」、手绘笔记、Opus 5.5 写的；扫片和卡点检查都过了，部件已收进手绘笔记模板）：

| 概念（口播怎么说的） | 画法 | 动作卡在 |
|---|---|---|
| 上下文 = 聊过的内容 | 聊天窗口里一串聊过的话（我 / AI 气泡交替），旁边一个大括号把它们量出来 +「@上下文：聊过的内容」 | 「上下文」 |
| 上下文窗口 | 一个**会缩放的橙色取景框**（四角加粗）框住聊天记录：框住的就是 AI 记得的；字幕和画面里「窗口」用强调色 A | 「上下文窗口」框画出来 |
| 窗口太小 → 失忆 | 框缩小、只框住最后几条，**早先的话掉出框、变灰**；AI 回「呃…你是谁？」，头上冒橙色「?」 | 「太小」框缩、「失忆」冒问号 |
| 窗口太大 → 成本撑不住 | 框放大全框住；旁边**硬币塔**一枚枚叠高、越叠越歪，冒「!!」 | 「成本」叠硬币、「撑不住」歪 |
| 不止聊天 | 机器人头上只有一个「聊天」气泡，占画面一小块，再拉远露出别的 | 「远不止」 |
| 不同类型的信息 = 模态 | 三张**信息小卡**（文字页 / 图片框 / 声波）一张张出来，大括号括住，颗粒章「模态」砸下 | 「不同类型」出卡、「模态」盖章 |
| 只会一种 = 单一模态（文字模态、图像模态） | **两个机器人左右并排**、中间虚线：左边只会聊天（几个气泡）、右边只会画画（画板上一笔笔画出山和太阳），下面各写「文字模态」「图像模态」 | 「文字聊天」「画图」 |
