# 讲解动画通用规则（不随风格变）

> 三种用法都要守。每条注来源：**【标准】** 公开标准或文献（文末列出处）、**【实测】** 我们做 11 套样片和观众实测时量出来的（详见 `从11套里学到的.md`）、**【经验】** 常识推断，没专门验证。画面都按 1920×1080 说。

## 一、字多大

1. 字幕不小于 60 像素，一条一行、约 20 个字以内（64 像素单行放得下）。【实测】
2. 要观众看清的字（关键词、标签、数据）原尺寸 48 像素以上：手机竖着看横屏视频，画面约 480 宽，48 像素缩成约 12 像素，再小就吃力；不够就让镜头推近。每次出静帧看 480 宽检查图。【实测：S06 数据格 42 → 48、S22 标签放大到 52 才读得清】
3. 标题 72 像素以上；装饰小字可以小，但不能放观众要读的信息。【经验】
4. 画面上的额外文字按读速留停留时间：Netflix 简体中文字幕规范每行最多 16 字、最多两行、能一行就一行，成人节目每秒不超过 9 个字。所以一个 12 字的说明至少停 1.4 秒，再加约 0.5 秒反应。【标准 ②；停留时间是据此推的】

## 二、字和底的对比度

1. WCAG 2.2 成功准则 1.4.3（AA）：文字和背景对比度至少 4.5:1；大字（18 pt ≈ 24 像素，或 14 pt 粗体 ≈ 18.5 像素以上）至少 3:1；1.4.6（AAA）要 7:1。视频里的字幕和关键词按 4.5:1 要求。【标准 ①】
2. WCAG 1.4.11：图形和界面部件（箭头、图标、色块边界）和相邻颜色至少 3:1。【标准 ①】
3. 色块上的字也要算：S47 朱红底写黑字 5.3:1、写奶油字只有 3.1:1，所以用黑字；S09 砖红底白字约 5.8:1、灰蓝底白字约 4.6:1。浅色色块（粉笔粉、天蓝）上写深色字。【实测】
4. 颗粒、渐变、纹理底上的字按最不利处算，不够就给字加底（字幕带、色块、纸条）。【经验】
5. 算法（WCAG 相对亮度）：
   ```bash
   node -e 'const L=h=>{const c=[1,3,5].map(i=>parseInt(h.slice(i,i+2),16)/255).map(v=>v<=0.03928?v/12.92:((v+0.055)/1.055)**2.4);return 0.2126*c[0]+0.7152*c[1]+0.0722*c[2]};const[a,b]=process.argv.slice(1).map(L);console.log(((Math.max(a,b)+0.05)/(Math.min(a,b)+0.05)).toFixed(2)+":1")' '#efeee4' '#2f4a3d'
   ```

## 三、字幕安全区

1. 底部约 170 像素（y 908 起）只放字幕，画面里的东西不进来，运动路线也不经过；页眉区一样当禁区。【实测：纸堆、滚动卡片、小人都压过字幕区或页眉】
2. 字和关键图形放在 EBU R 95 的图文安全区里：16:9 画面每边留 5%（1920×1080 下左右各 96、上下各 54 像素）；动作安全区每边 3.5%。【标准 ③】
3. 回剪映还要再叠贴纸、字幕时，四周多留一点。【经验】

（第二节的算法验过：算出 S47 朱红 `#f04f35` 配黑 5.34:1、配奶油 3.12:1，和样片记录一致；粉笔米白 `#efeee4` 在墨绿黑板 `#2f4a3d` 上 8.31:1。）

## 四、颜色预算

1. 一个主色 + 1–2 个强调色；热闹的风格也只让强调色负责「要记住的东西」。【经验】
2. 全片固定两个强调色 A / B 给两个核心名词（画面、数据、字幕里都同色），观众靠颜色跟住概念；其余颜色避开 A / B 的色系。【实测，知识库第六节】
3. 用颜色、箭头、圈、下划线标出关键结构，有助于理解（Mayer 的「提示原则」signaling）。【标准 ④】

## 五、一个镜头只讲一件事

1. 镜头跟着句子切，一个镜头 1.5–5 秒、只讲清一件事，关键字 2–4 个。【实测，用法一分镜规矩】
2. 去掉和要点无关的字、图、声音（「一致性原则」coherence）；画面上别把口播再抄一遍，只放短标签——短、标出关键动作、贴在对应图形旁边的字例外（「冗余原则」redundancy）；字幕是观众习惯，另算。【标准 ④】
3. 图和对应的话同时出现（「时间邻近原则」temporal contiguity）：动作卡在说这个词的那一刻（`TL.mark`）。【标准 ④；做法是实测】

## 六、动效时长

1. 进场 0.2–0.5 秒（弹出 0.2–0.45、标签刷出 0.25、描线 0.3–0.75）；换镜头 0.6–0.7 秒；停住讲时慢推。【实测，手绘笔记风格卡】
2. 动作比关键词提前 0.03–0.1 秒开始；逐字出现的字，静帧取关键词开始后约 0.3 秒才写完。【实测】
3. 出完要停到能读完：字数 ÷ 9 字/秒 + 约 0.5 秒；结论、盖章之后至少停 1 秒再移镜头。【前半据标准 ②推，后半实测：观众实测里盖章 0.35 秒后就移走，读不完】
4. 缓入缓出（slow in and slow out）：进场用减速曲线（outCubic、小幅 outBack），出场用加速曲线，镜头用 inOutCubic；不要匀速。【标准 ⑤】
5. 闪光：任何 1 秒内闪不超过 3 次（WCAG 2.3.1）。换场白闪只在大段落用。【标准 ①；黑底科技骨架 21 秒闪 7 次是反例】
6. 画面只由时间 t 决定（不用 CSS 动画、requestAnimationFrame、不带种子的随机数）。【实测，逐帧截图的硬要求】

## 七、抽象概念怎么变成画面

先把概念归类，再找一个看得见、会动的东西：范围 → 框；太多 → 越堆越高后歪倒；分类 → 几张小卡 + 大括号 + 盖章；能力齐全 → 清单逐项打勾；对比 → 左右两栏；流程 → 编号 + 箭头；增长 → 柱子长高；遗忘 → 掉出框、变灰；输入输出 → 进机器、出来变样。详表见 `从11套里学到的.md` 第七节。同一个概念全片用同一个画法，中途不换比喻。【前面实测 + 推的，见第七节标注；最后一句经验】

## 八、图标和部件风格统一

同一片里：线宽一致（例如 3–4 像素）、端点一致（圆头 / 方头）、圆角一致、透视一致（全平面或全等距）、填充方式一致（线稿 / 平涂 / 渐变选一种）、光源方向一致（立体卡通光都从左上来）。【经验；光源一条是实测】
