# 扁平流程图（S19）

奶油底、琥珀黄标题带、特粗黑字的扁平科普信息图，内容排成一条带编号的横向流程，镜头一站一站移过去。适合讲「先这样、再那样、最后得到什么」的步骤、原理、因果链；不太适合没有先后顺序的观点罗列、情绪表达、人物故事。

## 看起来什么样

- 参考的是一张扁平流程科普信息图（讲鲜肉 8 小时制成粮）：顶部一整条琥珀黄标题带，里面是特粗近黑大字，下面大面积奶油色底。
- 内容按流程组织：琥珀编号圆标（白数字 + 右侧小尖角）+ 粗黑步骤标题 + 暖灰说明；站与站之间用渐变弧形箭头连，尾巴透明、头部深琥珀。
- 东西都是扁平的，体积只靠很轻的渐变和「向右下错开 6–12 像素、不模糊」的浅色投影；颜色少：奶油、琥珀、近黑，外加几个高饱和小色块。
- 解释文字放在琥珀色圆角说明框里，用 2.5 像素细黑折线（端点小圆点）连到被解释的东西上。
- 背景：浅灰钟面圆环（12 个圆头刻度），以 0.5 视差跟着镜头慢慢移；v1.3 起秒针、分针一直转，前面再漂一层浅色扁平小几何（视差 0.3），见「默认动效（v1.3）」。
- 留白多，一屏只放一个主体 + 一个说明框。

## 构图和版式

- 顶部 112 像素琥珀标题带固定不动，标题左对齐（x=84，62 像素，900 字重），带下有 5 像素淡阴影。
- 底部约 170 像素留给字幕；画面焦点固定在 (960, 515)，主体放在 y≈160–880 之间。
- 整张流程图铺在一条横向的「世界」上（世界坐标 x 从 240 到 5400 左右）：聊天框 → ① 提示词 → ② 分词器 → ③ Token → ④ 翻找 → ⑤ 推断。镜头横移到一站停住讲，离开后上一站 0.3 秒淡出，免得画面边上留半截字。

## 动效和节奏

- 出现：outBack 弹出 0.35–0.45 秒（`popS` / `popA`）。
- 箭头、折线按长度画出：0.4–0.55 秒，outCubic；画完后箭头上有小珠一直往前流。
- 镜头：`camAt` 按 `CAM` 关键帧表走，换站 inOutCubic 0.5–0.75 秒；停住讲的时候用 `'sine'` 慢推，或推近 1.15–1.6 倍看刚出来的东西、到下一个关键词再拉开（v1.3 示例页镜头 1、2、5、7）。
- 震屏只给「砸下」的那一下：下刀、盖勾，0.18–0.2 秒、8–11 像素（`动效.shake`）。
- 动作全部卡在 `TL.mark()` 上，提前 0.04–0.12 秒；逐字打出用 `TL.chars` 的字级时间。页面里不写死秒数。
- 挑静帧的秒数：取关键词开始说之后约 0.3 秒（v1.1，观众实测：逐字出现的字要这么久才写完；4.95 秒只写出「失」，5.15 秒才是「失忆」）。

## 默认动效（v1.3）

`模板.html` 脚本第一行 `const FX_DEFAULT = true;`：换任何时间线都自动有下面这些；改成 `false` 就和 v1.2 的模板逐像素一样（实测 6 个时刻 md5 一致）。自己在 `fxBefore` / `fxAfter` 里加的调用照常生效（默认转场画在 `fxAfter` 之后、页眉字幕之前）。

| 加了什么 | 在模板哪里 | 说明 |
|---|---|---|
| 背景远景：钟面秒针、分针一直转，刻度圈慢转 | `drawRings(cam, centers, t)`（167） | 只用钟面灰、投影色，不抢戏 |
| 背景中景：扁平小几何漂浮 | `drawShapes`（196） | 30 个圆点 / 圆环 / 圆角方块 / 加号 / 三角，浅琥珀、浅橙、浅绿、钟面灰（避开强调色 A/B），视差 0.3，往左漂、上下浮、转 |
| 箭头上的流动小珠 | `arrowFlow`（213） | 站与站之间的箭头画完后，每 1.6 秒一颗奶白小珠从尾流到头 |
| 镜头交界的默认转场 | `FX_KINDS`、`fxCamP`、`fxDefaultAfter`（221–277） | 按 `TL.shots` 在每个交界轮换 **沿流程横移 → 色块横扫 → 圆形遮罩**，同一种不连用；横移是镜头沿流程平滑移到下一站，色块横扫、圆形遮罩是切点前后盖住画面（只盖标题带和字幕区之间 y 112–908），镜头在被盖住时直接跳到下一站。开场另有一次琥珀里开圆洞放大（0–0.6 秒） |
| 每句一次推近 / 拉开 | `fxView`、`FX_PUSH`、`FX_DRIFT`（231–246） | 按字幕句子交替「推近 10% + 往右 70 像素」/「拉开 + 往左 70 像素」，句中 sine 缓动一直在动。画面边上有东西被推出画时把 `FX_PUSH`、`FX_DRIFT` 调小 |
| 骨架面板琥珀标题栏、每句一个小站点、色块弹出后轻浮 | `drawStation`、`drawCueDots`（342–384） | 骨架换掉后就没了，写自己的场景时照这个思路给每句一个变化 |

这套适合的转场（知识文件 `动效和画面变化.md` 第三节）：**沿流程横移到下一站**（最常用，这套的招牌）、**形状变成下一个形状**（示例页：输入框里的字变成消息气泡、AI 芯片变成分词器圆台）、**圆形遮罩放大**（开场；示例页镜头 7 → 8 从说明框的加号处开圆，圆里是下一站，要把场景画两遍、见示例页 `render`）、**色块横扫**（琥珀块扫过，示例页镜头 5 → 6 让 Token 块骑在色块上飞进搜索条，把东西画在色块上面能保住前后联系）。

实测（v1.3）：模板 + 一段 33.6 秒的别的口播（4 个镜头、14 句）丰富度判「过」，模板 + Token 时间线判「过」，数字见下面「质感和渲染速度」。骨架本身只有标题和色块，相邻格平均里开场那一格（琥珀盖满 → 打开）占了不少，**换成真正演内容的场景后才算数**。

## 字幕区

- 底部居中，文字中心 y=993；64 像素、800 字重（特粗栈），近黑字直接写在奶油底上，没有底框；每条 0.08 秒淡入。
- 不自动换行：一条字幕最多约 25 个字，再长会顶出画面两边。
- 画面避让：底部 170 像素不放主体；`?nosub=1`（render.mjs `--no-subtitle`）时整段不画。
- 字幕关键词：一张表、长的优先、整词替换——`字幕强调` 里写「多模态」，就整个按马克笔底标，里面的「模态」不再是强调色。
- v1.1 起（模板）：紧接着上一条的字幕直接换字（`subIn`），只有第一条、和上一条中间有空档时才淡入——以前每条都从透明淡入 0.08 秒，换条那一帧字幕是空的或很淡（「眨一下」）。v1.3 起 `示例_Token.html` 也改成这样，不再眨。
- 这套字幕没有底带：`?nosub=1` 时字幕整块不画，画面上不留任何东西。

## 质感和渲染速度

- 没有颗粒、没有纸纹，纯平面；投影是不模糊的错位色块，没有质感缓存。
- 用默认 png 就行，每帧 PNG 只有 0.2–0.4 MB，不用 `--format jpeg`。
- 实测 51 毫秒/帧（M2 Max，load 9；21 秒 636 帧共 33 秒）。v1.3 示例页加了背景三层和转场：同一时段、同样负载（约 15–20，另有 6 个渲染在跑）下旧页 55、新页 56 毫秒/帧，几乎没变慢；模板 + 33.6 秒口播 55 毫秒/帧。

## Token 例子 8 个镜头怎么演

v1.3 重做：背景三层一直在动（钟面秒针、漂浮小几何、箭头上的流动小珠），每 2–3 秒一个看得见的新变化，转场轮换（形状变形、沿流程横移、色块横扫、推近、圆形遮罩）。

| 镜头 | 画面 |
|---|---|
| 1 打开聊天框输入 | 开场琥珀里开圆洞放大，app 图标轻轻浮；「打开」图标变成「AI 助手」窗口；「聊天框」输入框描边亮成琥珀、镜头推近一级；念例句时推近输入框（1.55 倍）、镜头跟着光标往右走，字逐个打出，发送后变成琥珀消息气泡 |
| 2 这是提示词 Prompt | 气泡圈一道琥珀描边跳一下，镜头慢推；「每天听到最多」时窗口两边一个个弹出别人每天发的提示词小气泡往上飘；「提示词」镜头拉开、弹出 ① 说明框，再补「= Prompt」 |
| 3 AI 收到 | 沿流程横移，右边弹出 AI 芯片，箭头伸过去；句子飞出、变成白色长条飞向 AI |
| 4 分词器拆分 | 芯片原地变成圆台（形状变形）；7 刀劈下、震屏一下，长条裂成 8 块变色，掉进台面入口，顺螺旋落下排成一排；镜头慢推 |
| 5 碎片叫 Token | 往下推近一排 Token，8 块依次轻跳、落定后轻轻浮；说明框「最小的语言碎片」；「Token」拉开，括号和 ③ Token |
| 6 去海量数据翻找 | 色块横扫：琥珀块从左扫过，8 块 Token 骑在色块上飞进搜索条，扫走后已在数据面板；短句快速上滚后变慢，放大镜来回扫 |
| 7 成都和旅行常一起出现 | 推近看数据里「成都」亮红、「旅行」亮蓝；「常常在一起出现」拉开，6 句两者都有的变浅琥珀底并连线，其余变淡，说明框弹出 |
| 8 推断出旅行需求 | 圆形遮罩：从说明框「成都 + 旅行」的加号处开圆，圆里是推断站；两块飞到中间加「+」，⑤ 推断弹出，结论卡「旅行需求」盖上黑底白勾（震屏、迸出扁平纸屑），之后轻轻呼吸到片尾 |

## 踩过的坑

1. 兰亭黑只有 Extralight / Demibold / Heavy 三档，只能给 800 以上的特粗字用；正文要是也走兰亭黑，500 字重会掉成 Extralight，所以 `font()` 按字重分两个栈。（做样片时发现的）
2. 聊天框里字太小、打字那几秒镜头不动显得空：窗口和字放大，打字时推近到 1.55 倍。（做样片时自检发现的）
3. 镜头横移后上一站在画面边上留半截字：镜头离开就让上一站淡出（303 行 `leaveA`）。
4. 两块一起飞向推断站会半路叠在一起：让后面那块先走。
5. 数据面板里的普通短句缩到 480 宽只有约 8 像素，手机上读不清；要读清的靠色块认，或者改成更少更大的条目。
6. 画面变化够不够要用 `pipeline/丰富度检查.mjs` 量，不能只看静帧：v1.2 的示例页开头 2.5 秒只有浅色窗口（奶油底上的白窗口，检查里几乎算不出差别），第 5 秒前后窗口和气泡 1.87 秒一动不动，判「不过」。v1.3 给每句一个变化、背景一直动、开头加圆洞放大，相邻格平均 12.2 → 20.5。浅色东西（钟面、小几何）动起来在检查里算不上「在动」，要靠镜头推拉、深色和饱和色的东西移动。（v1.3）
7. 色块横扫、圆形遮罩这类整屏转场要避开字幕区：只盖 y 112–908，底部 170 像素留给字幕。（v1.3）
