# 研究设计

## 选题前的新颖性检查

1. 先读取 `research-evidence`，明确研究问题、对象/人群、时间范围、研究类型、可用资源和用户希望交付的方案边界。
2. 在提出候选选题前必须用 `academic_search` 检索相近论文、预印本、指南和注册研究；需要时补充官方网页，但普通网页只作为线索。记录每个查询、provider、时间、纳入/排除条件和失败来源。
3. 对每个相近工作比较研究问题、人群/数据、方法、主要终点、评价指标和已公开局限，写出具体差异。将状态标为 `unverified`、`candidate` 或 `supported_by_search`；没有检索记录时禁止写成“已验证创新”，不能把“尚未找到”当成“没有人做过”。
4. 通过 `research_record` 关联真实 `source_id`/`claim_id`。检索不完整、全文不可得或标识符无法核验时，列出缺口并降低结论强度。

## 候选选题模板

每个候选必须完整填写以下字段，缺少真实信息时填写缺口原因而不是占位套话：

```text
研究问题：
研究价值：
证据依据：source_id / claim_id
相近工作：论文/预印本/注册研究及具体差异
研究空白：可核验的未解决问题
预期贡献：
新颖性状态：unverified | candidate | supported_by_search
资源需求：设备、样本、数据、人员、预算和时间
失败风险：
```

## 假设模板

每个假设必须是可证伪陈述，并保持待验证状态：

```text
假设：在 [对象/条件] 下，[自变量] 的变化将导致 [因变量] 发生 [方向/幅度]。
证据依据：source_id / claim_id / 现有观察
替代解释：至少一个可区分的替代原因
确认条件：满足什么观测结果才支持假设
否证条件：什么结果会拒绝或削弱假设
待验证状态：hypothesis / planned / tested
```

不得把 `hypothesis`、作者推断或方案预期结果改写成 `fact`，不得声称实验已经证明尚未执行的假设。

## 研究方案模板

实验、观察性研究、调查或算法研究至少包含：

- 研究对象/数据、样本/数据、纳入与排除边界，以及自变量、因变量和控制变量。
- 混杂因素、对照/基线、样本或数据需求、主要终点和评价指标。
- 操作步骤、确认/否证规则、失败模式、替代方案、资源风险和停止条件。
- 预期输出、复现需要的记录字段，以及当前不可确认的设备、样本、数据或参数。

通过 `research_record` 记录方案与证据；没有真实设备、样本、数据或伦理批准时明确“标记为需求”，不写成已经具备，也不擅自给出正式样本量或统计结论。

## 风险与边界

- 涉及医疗、患者、动物、危险实验、临床试验、受管制材料或正式统计方案时，必须列出伦理、隐私、数据授权、专业审核和机构审批要求；只提供研究设计建议，不作患者个体诊疗决定。
- 资料不足、相近工作未完成检索、变量无法测量或终点定义不清时，返回 `insufficient_evidence`/`missing_requirement` 及补齐清单，不用概率词掩盖缺口。
- 设计输出区分已知事实、推断、假设和建议；不虚构可用资源、既有结果、创新性或可行性。
