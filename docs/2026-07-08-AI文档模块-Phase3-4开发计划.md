## Phase 3:视频模块实际功能

### P3-1 视频运行时检测与下载

**目标**:实现 Node.js / FFmpeg / Chrome 三个依赖的检测和延迟下载

**任务**:
1. 新建 `mona/api/video_runtime.py`,实现 `VideoRuntime` 类
   - `check_all()`:检测三个依赖,返回 `{node, ffmpeg, chrome}` 状态
   - `ensure_runtime(component)`:异步下载指定组件到 `~/.mona/runtime/<component>/`
   - Node.js:下载 `node-v22.x.x-win-x64.zip`,解压到 `runtime/node/`
   - FFmpeg:下载 `ffmpeg-master-latest-win64-gpl.zip`,解压到 `runtime/ffmpeg/`
   - Chrome:调用 `npx hyperframes browser ensure`(通过 runtime node 执行)
2. 在 `mona/api/server.py` 注册路由:
   - `GET /api/video/runtime-check`
   - `POST /api/video/runtime-download`(参数 `component`)
   - `GET /api/video/runtime-status/<task_id>`
3. 前端新建 `VideoRuntimeDialog.tsx`:
   - 显示三个依赖状态(✓/✗)
   - 一键下载缺失组件
   - 下载进度条

**验收**:检测到系统已装的 Node/FFmpeg;手动删除后能正确提示缺失;下载流程完整

---

### P3-2 Hyperframes CLI 封装

**目标**:封装 Hyperframes CLI 调用,处理环境变量和路径

**任务**:
1. 新建 `mona/skills/mona-video/scripts/hyperframes_cli.py`
   - `HyperframesCLI` 类,构造时注入 `VideoRuntime`
   - `init_project(resolution)`:创建项目结构
   - `lint()` / `validate()` / `inspect(samples)`:质量检查,返回结构化 JSON
   - `render(output, quality, fps)`:渲染 MP4
   - `preview_server(port)`:启动预览服务,返回长驻进程
   - 所有命令通过 `asyncio.create_subprocess_exec` 执行,设置正确的 PATH 环境变量
2. 更新 `mona/skills/mona-video/scripts/render.py` 调用 `HyperframesCLI`

**验收**:在装好依赖的环境下,能完整执行 init → lint → render 流程

### P3-3 视频项目管理 API

**目标**:实现视频项目的 CRUD 和文件管理

**任务**:
1. 在 `mona/api/server.py` 新增 `/api/video/*` 路由组:
   - `GET /api/video/projects`:列出 `video_projects/` 下所有项目

2. 前端 `webui/src/lib/api.ts` 新增 video API 封装函数

## Phase 4:流程图模块实际功能

### P4-1 draw.io 静态文件集成

**目标**:将 draw.io webapp 打包进 Mona,由 gateway 提供静态服务

**任务**:
1. 从 [jgraph/drawio](https://github.com/jgraph/drawio) 下载 release,提取 `src/main/webapp/` 核心文件
   - 排除:测试、文档、示例、Editor.md
   - 保留:js/、css/、stencils/、shapes/、index.html
2. 放到 `mona/static/drawio/` 目录
3. 在 `mona/api/server.py` 注册 `/drawio/` 静态文件路由
4. 验证 `http://127.0.0.1:{port}/drawio/index.html?embed=1&proto=json&offline=1` 可访问

**验收**:浏览器能加载 draw.io 编辑器,embed 模式正常

---

### P4-2 DrawioEditor 组件

**目标**:封装 draw.io iframe + postMessage 协议

**任务**:
1. 新建 `webui/src/components/doc/flowchart/DrawioEditor.tsx`
   - props: `{ xml, onSave, onExport }`
   - iframe 加载 draw.io embed
   - `DrawioProtocol` 类封装 postMessage JSON 协议
   - 处理 init / load / save / autosave / exit / export 事件
   - 工具栏:撤销/重做/自动布局/导出 SVG/导出 PNG
2. 实现 `DrawioProtocol` 类:
   - `send(action, data)`:发送 JSON 消息
   - `on(event, callback)`:监听事件
   - `load(xml)` / `export(format)` / `layout(type)`:便捷方法

**验收**:iframe 能加载 XML、用户编辑后能回传 XML、能导出 SVG

---

### P4-3 mxGraph XML 生成

**目标**:实现 graph.json → mxGraph XML 转换

**任务**:
1. 完善 `mona/skills/mona-flowchart/scripts/build_xml.py`:
   - 解析 graph.json(nodes / edges / metadata)
   - 生成 mxCell 节点(含 geometry)
   - 应用预设样式(NODE_STYLES 映射)
   - 生成边(source / target / edgeStyle)
   - 输出完整 `<mxGraphModel>` XML
2. 完善 `mona/skills/mona-flowchart/scripts/auto_layout.py`:
   - 层次布局算法(TB/BT/LR/RL 方向)
   - 计算节点坐标,填入 geometry
   - 支持多种图类型(flowchart / er / mindmap 的布局差异)

**验收**:graph.json 能正确转换为带坐标的 mxGraph XML

                      │                 ├── P3-7 (UI) ── P3-9 (进度推送) ── P3-10 (测试)
  P3-4 (soul) ────────┤                 │                 ↑

  P4-1 (draw.io 静态) ── P4-2 (DrawioEditor) ──┐
