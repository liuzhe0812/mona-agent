# 开发模块：原生执行者连接与认证

适用于 `feature/1.8.0-development` 当前实现。本文是使用说明，不代表整个 1.8.0 已通过发布验收。实际验证以 `docs/plans/` 中最新记录为准。

## 进入工作台

更新代码后正常重启完整 dev，使 Python 开发服务与前端使用同一版本。只刷新旧页面不能加载新后端路由。

在“设置 → 模型供应商”连接所需的原生来源，再从“开发”打开已有本地项目。开发任务只选择渠道和模型，不再另选一次执行引擎。打开项目和查看连接状态不会发送模型任务，也不会创建 Git 分支。

Mona Coding 使用应用中选择的模型；Codex、Claude Code、CodeBuddy 使用各自的原生 Agent。执行引擎与模型供应商分别保存。

## 权限模式

输入框底部的权限菜单提供“请求批准、自动审批、完全访问”。权限保存在当前会话，子任务继承；只读任务始终只读。当前轮次、待核对消息或 Mona 后台命令未结束时，先处理或停止，再修改权限。

“自动审批”根据用户授权审核操作，不能完成审核时仍会弹出输入区审批卡。“完全访问”需要明确确认；选择成功后作用于后续执行。旧请求不会因为改档而重放。CLI 版本不支持的档位会明确拒绝，原设置保持不变。

Mona 命令执行使用 DSH 沙箱后端，Windows helper 首次使用会从随应用校验包进入统一运行时仓库。沙箱无法启动时本次命令不执行。Windows 仅提供部分文件写入隔离，读取和网络访问不属于其隔离范围。


### 供应商页的账号与额度

OpenAI 详情从本机 Codex app-server 的 `account/read` 和 `account/rateLimits/read` 读取账号、套餐、周期用量、credits 与重置次数，不发送模型任务，也不消费重置次数。额度读取前后核对账号；接口只返回展示字段，不转发认证材料。

展示口径参考 Cindy 的 `useProviderSubscriptionCard.ts`、`usageCardModel.ts` 和 `codexUsageBuckets.ts`：

- 账号页仅显示通用 `codex` / `__default__` 桶，按此顺序选择；桶表存在时不拿旧单桶或模型专属额度补空。所有窗口过期超过 24 小时才忽略旧桶；缺少重置时间不能推定已过期。
- 条与文案均显示剩余百分比；告警等级根据已用比例计算。保留绝对重置时间、倒计时、展开明细、粗略用量节奏、credits、重置次数及最早过期时间；未知值不显示成零。
- 本机额度或账号事件触发重新读取；每分钟只更新倒计时，不重复查询额度。Gateway 用版本通知等待承接原生事件，等待超时不触发额度读取。断开和账号切换清空旧快照；同账号读取失败保留原值及原更新时间，连接恢复后重新核对。
- 管理菜单的“重置显示偏好”清除覆盖：API 来源保存 `enabled_models=null`，本机来源移除隐藏偏好。关闭显示的模型进入可折叠的“未显示”区，搜索可展开匹配项。供应商顺序可拖拽或用排序把手的上下方向键调整，顺序变化不切换当前来源或模型。


## 模型来源与引擎管理

模型设置使用一个“模型来源”页面。API 供应商模型由 Mona 调用；ChatGPT、Claude Code 和 CodeBuddy 账号来源使用各自原生引擎与模型目录，不为单个模型选择另一引擎。

默认仅启用 Mona。原生来源的开关、程序来源/版本和“引擎管理”入口合并成紧凑状态栏；模型计数、搜索、刷新和显示管理使用一条工具栏。账号连接保留在来源详情顶部。

停用来源只阻止后续调用，保留程序、账号、模型显示偏好和正在运行的任务。引擎管理弹窗分为两部分，不重复放鉴权、来源开关或模型列表：

- **本机已安装**：显示检测到的程序路径；未找到时可浏览选择并保存路径，支持重新检测。
- **Mona 管理**：独立显示 Mona 下载的程序；未下载时提供下载，已有程序时可检查更新或删除。删除只移除 Mona 管理的程序和下载缓存，保留登录、会话与模型设置；程序仍在下载、登录、执行或有结果待核对时，先完成或核对对应操作再删除。

## Codex

Mona 优先使用本机已有的 Codex、Claude Code、CodeBuddy；用户可从对应来源的引擎管理中显式下载独立副本，并管理后续更新。程序路径留空时，Codex 优先定位桌面应用中的 CLI，然后检查 PATH 与已知安装位置，最后使用 Mona 管理的程序；明确填写路径时不会静默切换到其他安装。不要选择桌面启动器、辅助程序或不能访问的 WindowsApps 文件。

刷新连接与模型时会重新检查程序位置。桌面应用升级后，新模型目录由新版 CLI 返回；空闲连接自动更新，进行中或结果待核对的任务保留原进程，直到任务可以安全结束。CLI 程序版本与登录、会话数据分开管理。

日常状态检查只读取会话元数据，不请求完整轮次历史。恢复连接时，对已确认支持的 CLI 版本使用 `excludeTurns`，避免新版桌面 CLI 尚未实现的历史查询阻断正常发送；这不会删除原生历史。完整历史仅用于用户主动核对结果，CLI 不支持时保留原任务并提示人工核对，不自动重新执行。

1. 在“模型供应商”选择 OpenAI，查看本机 Codex 与 ChatGPT 订阅连接状态。
2. 需要认证时点击“连接 ChatGPT”，由系统浏览器打开官方授权页；账户与密码只输入官方页面。
3. Mona 按原生回执显示等待、完成、取消、失败或结果待核对，并在授权完成后同步连接与模型状态，再创建或继续 Codex 开发任务。

登录完成不自动发送开发请求；尚未认证也不会被替换成 Mona 模型执行。

Mona 使用隔离的原生数据目录，不自动复制用户原有 CLI 的行为配置、私有记忆、MCP 或 Hooks。因此在其他客户端已登录，不等于 Mona 的受管环境已经认证。不要向聊天窗口或代码仓库提供密码、API Key、Cookie 或令牌。

## 登录的取消、恢复与多项目

官方登录针对执行者账户，不属于某条代码任务。同一执行者在多个项目窗口中只能有一条正在进行的受管登录；重复打开设置会查询原流程，不会重复启动认证。

关闭设置页或切换项目不会取消登录。“取消连接”只针对界面显示的本次登录标识，不退出已经存在的账户，不取消其他执行者，也不停止开发任务。

连接中断或回执丢失时，先使用“重新检查”或“刷新连接与模型”。程序不会因为没有收到回执就自动发起第二次登录。应用重启后先检查受管环境的实际认证状态，不沿用失效的浏览器链接。

正在进行的登录尚未结束时，修改执行者设置会明确拒绝。结果未知且原连接已经结束时，可以重新检查或显式保存设置重置空闲连接；不会自动重跑历史开发任务。

## 空会话与执行历史恢复

选择模型时分配的 SDK 会话 ID 不代表已有原生对话历史。对尚无任何运行记录的绑定，首次发送前切换模型或重启应用，仍按新对话方式打开同一个原生 ID；一旦存在运行记录，即使未收到回答或结果未知，也不能当作空会话重建。检查按绑定查询全部持久记录，不使用界面的最近若干条消息推断。

Claude Code 或 CodeBuddy 在恢复阶段明确拒绝当前会话 ID、且尚无输出或工具活动时，本轮以失败结束，弹窗提示“连接已失效，本次请求未执行。请重新发送消息，系统会自动恢复连接。”用户下一次正常发送时，系统在原 Mona 会话中恢复连接，保留对话与文件。界面不提供单独的重连入口，也不在对话区插入连接提示；恢复连接不会重放旧请求，结果尚未确认的任务不会被自动重建。

断连、超时、其它错误或已经发生执行活动后的错误，仍为结果待核对，不能通过重建推断原任务未执行。旧版本只保存了笼统“状态待核对”的历史记录，不会仅因升级而被改为失败或成功；历史保留，不自动重发。

## Claude Code 与 CodeBuddy

源码环境需要项目声明的 `development` 配套 SDK 依赖。SDK Python 模块与原生 CLI 是两层依赖：安装 SDK 不等于已选择兼容 CLI，找到 CLI 也不等于 SDK 齐全。

- Claude SDK：`>=0.2.134,<0.3.0`，通过本机 Claude Code CLI 执行。内置 Anthropic 来源的“使用本机 Claude Code 账号”沿用 Cindy 的本机账号绑定流程：Windows/Linux 读取 `CLAUDE_CONFIG_DIR` 或 `~/.claude` 下的 `.credentials.json`，macOS 读取 Claude Code Keychain 条目；Mona 只保存绑定状态，不复制或删除系统凭据。启动 CLI 时注入 OAuth token、scopes 和订阅元数据，项目 HOME、设置、MCP 与 Hooks 继续隔离。凭据缺失或过期时明确要求在本机 CLI 更新登录，不退回 API Key。断开只撤销 Mona 绑定，已打开会话不再接受新任务；不退出系统 Claude Code 账号。
- CodeBuddy SDK：`>=0.3.264,<0.4.0`。支持受管官方认证流程或明确的 API Key 环境变量来源；同样不加载用户配置、自定义 MCP 或 Hooks。

本轮用户确认：Codex 与 CodeBuddy 由用户配合官方账号授权，开发侧负责真实任务自动化；Claude Code 不做账号实测，以 Cindy 源码对照和本地契约回归核对实现。Claude 的未执行项单独注明，不作为本轮账号验收阻塞，也不虚标为已通过。诊断握手和测试对端不冒充真实模型任务。

## CodeBuddy 国内账号与真实模型目录

CodeBuddy 默认连接国内服务，登录、账号检查、目录查询和任务使用同一受管数据目录与地区。模型供应商页中的 CodeBuddy 位于固定来源区域；点击连接后直接打开官方授权页。授权完成后自动同步账号和目录，不要求用户重复授权来修复空模型列表。

“已授权”只表示登录流程完成；“已连接”要求实际账号状态、协议和非空真实模型目录均已确认。目录暂不可用时保留明确状态与“刷新连接与模型”入口，不能用登录成功或默认占位推断连接完整可用。账号检查明确要求授权时，可以重新连接，不被历史的“授权完成”记录锁住。

目录由 `mona/development/executors/codebuddy_catalog.py` 通过同一官方程序的 ACP 元数据接口读取；不读取或复制凭据、不发起生成任务，也不调用工具。独立查询所创建的空原生会话不加入开发任务列表，进程在完成或取消后回收。任务执行仍使用官方 Agent SDK，没有为模型目录另建运行器。

模型 ID、名称、说明及上下文长度来自实际目录，不写死清单。默认模型是额外的自动选择选项，不计入具体型号数量；具体模型可单独显示或隐藏，开发任务保存真实 ID。账号与目录快照在项目间共用，刷新登录历史不反复清空已同步目录；重建管理器后重新检查受管账号，而不是沿用旧页面状态。

`scripts/verify_codebuddy_catalog.py` 使用既有隔离验证授权，自动验证真实目录、两处连接状态、显示开关、具体模型选择及管理器重建后的恢复。它不重新登录、不发送模型任务、不重启用户 dev。实际通过记录见最新验收文档；测试账号的型号数量不代表所有账号的固定目录。

## 项目上下文

四个执行者共用项目 `AGENTS.md` 与 `.agents/skills/` 的授权来源。共享项目资料不等于把同项目所有聊天记录混合到一个上下文中。接力与协作由 Mona 提供必要交接。

同一项目允许多个会话并行；没有项目级单写锁，也不会自动创建工作树。用户自行组织代码并行，工作台负责保证会话与执行结果不串线。

## 维护与验证

系统程序由原应用升级，Mona 不覆盖系统安装；Mona 安装的程序在对应来源的引擎管理中检查更新。三种引擎共用运行时下载器、大小/SHA-256 校验、版本仓库和全局安装任务，不新增专用下载目录。程序更新保留登录与会话，旧程序可能仍被运行中或状态未知的任务使用，因此不自动删除旧引擎版本。

Codex 从 OpenAI 官方发行服务读取完整程序包清单；Claude Code 从官方稳定版清单读取原生程序；CodeBuddy 从官方原生发行目录读取版本和校验和。配套 SDK 版本范围见 `pyproject.toml`，应用仍排除 SDK 内置的第二套 CLI 程序。

`scripts/verify_development_codex_connection.py` 可在新的 `output/` 子目录核对已安装官方 Codex 的实际版本、生产协议与配置检查、无任务状态和主进程回收。它不开始登录、不调用模型，也不修改真实项目或用户认证。

后端认证回归见 `tests/development/test_native_login.py`。这些集成测试使用真实进程和生产宿主，但供应商响应由测试对端提供，必须与官方二进制连接检查、授权账户任务验收分开记录。

## 开发侧自动化与官方授权

`scripts/verify_development_native_accounts.py` 默认只检查连接；显式 `--authorize --open-browser` 才进入一次官方授权。只把已验证的官方链接交给系统浏览器，链接、账户资料和令牌不进入日志或报告。认证成功后核对原生回执并关闭本次宿主，不发送模型任务。

验证使用操作系统本地应用数据下的 `Mona/verification/development-native` 持久目录，与用户正在运行的 dev 数据库分离。不复制其他客户端的凭据，不退出其他账户；后续原生验收复用同一验证目录。

`scripts/verify_development_native_live.py` 必须显式 `--live`，会使用已授权账户产生真实模型请求。项目为新的 `output/` 合成目录；验证修复代码、同会话续作、人工修改保留、配置子任务及原负责人消费结果，独立运行固定测试。禁止用 Mona 模型或测试对端代替官方执行器。没有实际结果时，报告保留失败或未确认，不重放未知请求。

Windows 受管启动显式启用官方非提权的受限令牌沙箱，并核对生效配置；当前项目仍为 untrusted，不导入用户配置或自动提权。实际 thread/start 必须返回要求的 workspaceWrite/readOnly，不能把原生降级后的只读会话当作可写成功。本机 0.156.1 已复现未启用 Windows 后端时返回只读；启用受限后端后的无模型线程核对返回正确范围。真实代码任务另行验证，不能只凭这一核对宣称通过。

本轮以 `makecindy/cindy@92294b7ead54fab8edabbf57cdc11db903c501c9` 的实际源码为参照，不用 README 或示例界面代替实现核对。

| 核对点 | Cindy 已阅读源码 | Mona 对应实现 |
|---|---|---|
| Codex 原生协议 | `packages/maker-core/src/agents/codex/app-server/client.ts`：异步 NDJSON、请求关联、通知与反向工具请求分路、连接退出清理 | `executors/rpc.py`、`codex.py`、`native_service.py` 管理原生任务；配置模型经 `model_bridge.py` 调用所选 Provider |
| Claude 本机账号 | `claude-credentials-store.ts`、`claude-oauth-spawn-env.ts`、`claude-oauth-refresh.ts` 的 reconnect/disconnect 段 | `executors/claude_account.py` 复用原生凭据库与只绑定/撤销语义；不增加 OAuth 浏览器流程 |
| Claude 原生执行 | `packages/maker-core/src/agents/claude-code/index.ts` 的 sdkQuery 启动段（约 3700–3850 行）：原生程序路径、cwd、输入队列、流式事件、resume、权限处理 | Python 官方 SDK 的 `SDKExecutor`/`sdk_worker.py`；独立 owner task 管理连接/关闭与原生会话，不把 API chat 当作 CLI |
| 环境与上下文 | `claude-code/env-builder.ts` 与 `codex/env-builder.ts`：启动环境和原生会话身份分离 | 受管 profile、明确项目规则/Skills、固定宿主协作工具；按 Mona 的要求不继承用户级记忆、自定义 MCP 或 Hooks |

Cindy 使用 TypeScript SDK，Mona 使用 Python SDK；接口形态不必逐行相同。其个人订阅认证、用户配置、MCP 和产品扩展不自动成为 Mona 已实现能力。源码对照用于核实接入结构，官方版本、认证与实际执行以单独报告为准。
