# 用户蒸馏与人物画像系统 - 开发计划

> 基于 [设计方案](./用户蒸馏与人物画像系统设计方案.md) 制定，分三阶段渐进交付。

## 总体策略

- **阶段 1** 优先做，验证"AI 主动用画像"的核心假设，低成本快速验证
- **阶段 2** 在阶段 1 验证有效后启动，补齐多源聚合 + 基础可视化
- **阶段 3** 做完整酷炫可视化，形成产品差异化亮点
- 每阶段独立交付，可回滚，不阻塞下一阶段评估

---

## 阶段 1：工作模式蒸馏（MVP）

**目标**：让 AI 能感知用户工作习惯，验证蒸馏价值。
**验证标准**：用户主观感受"AI 更懂我的工作习惯"。

### T1.1 工具调用历史采集器

**任务**：扫描 session 文件，聚合 tool_call 事件为结构化数据。

**输入**：session 文件目录（`c:\Users\liuzhe\.trae-cn\memory\projects\<proj>\` 或 mona 自有 session 存储）
**输出**：`tool_calls_<date>.jsonl`，每行 `{tool_name, called_at, params_summary, success, session_id}`

**步骤**：
1. 调研 session 文件实际结构，确认 tool_call 事件字段
2. 新增 `mona/distill/collectors/tool_call_collector.py`
3. 实现按时间段聚合 + Top N 统计
4. 实现 tool_call 序列模式提取（A→B→C 链路频次）

**依赖**：无
**产出**：`tool_call_collector.py` + 单元测试

### T1.2 蒸馏任务模块骨架

**任务**：搭好蒸馏任务的基础框架。

**步骤**：
1. 新增 `mona/distill/` 模块
2. 定义 `DistillTask` 抽象接口（输入数据 → LLM 调用 → 写入产物）
3. 实现 `WorkPatternDistillTask`（工作模式蒸馏）
4. 实现蒸馏结果写入 `user_profile.md` 的 `## Work Patterns` 段（通过 `memory_edit` 工具或直接文件写入）

**依赖**：T1.1
**产出**：`mona/distill/__init__.py`, `base.py`, `work_pattern.py`

### T1.3 蒸馏 LLM Prompt 设计与调优

**任务**：设计并调试蒸馏 prompt，保证输出质量。

**步骤**：
1. 用小样本（1 周数据）手动跑 prompt，验证输出合理
2. 迭代 prompt 模板 3-5 轮，调整输出 JSON schema
3. 沉淀 prompt 到 `mona/templates/distill/work_pattern.md`
4. 增加 confidence 评分机制，低置信度结果不写入

**依赖**：T1.1, T1.2
**产出**：蒸馏 prompt 模板 + 调优记录

### T1.4 Cron 任务注册

**任务**：将蒸馏任务接入 cron 调度。

**步骤**：
1. 在 `mona/cron/` 注册每周日凌晨 3:00 的蒸馏任务
2. 实现增量蒸馏（只处理上周新增数据）
3. 失败重试 + 日志记录
4. 手动触发入口（命令行 `mona distill run work-pattern`）

**依赖**：T1.2, T1.3
**产出**：cron 注册代码 + 命令行入口

### T1.5 验证与度量

**任务**：实跑 + 收集反馈。

**步骤**：
1. 用本地真实数据跑 1-2 次蒸馏
2. 检查 `user_profile.md` Work Patterns 段质量
3. 对话测试：问"我最近在忙什么"，看 AI 是否能基于画像回答
4. 用户主观评分（1-5 分）

**依赖**：T1.4
**产出**：验证报告 + 是否进入阶段 2 的决策

## 阶段 2：人物画像 + 基础可视化

**目标**：多源蒸馏出完整人物画像，前端展示画像卡片。
**验证标准**：用户能在 UI 上看到"AI 眼中的我"并能修正。

### T2.1 多源数据聚合器

**任务**：扩展数据采集到 notes + email。

**步骤**：
1. 新增 `notes_collector.py`：聚合笔记分类、标签、技术词汇频率
2. 新增 `email_collector.py`：聚合发件人、主题分类、往来频率
3. 复用 `hoard_collector.py`（如有）：跨源数据聚合
4. 统一输出格式到 `aggregated_<date>.json`

**依赖**：阶段 1 完成
**产出**：3 个 collector 模块

### T2.2 画像蒸馏 Prompt

**任务**：设计画像蒸馏 prompt。

**步骤**：
1. 设计画像 schema：identity / tech_stack / preferences / relationships / knowledge_structure
2. 迭代 prompt 模板，沉淀到 `mona/templates/distill/profile.md`
3. 实现画像蒸馏任务 `ProfileDistillTask`
4. 保留用户手填段落，蒸馏只更新特定段

**依赖**：T2.1
**产出**：画像蒸馏 prompt + task 实现

### T2.3 profile.rich.json 存储

**任务**：实现双存储分离。

**步骤**：
1. 定义 `profile.rich.json` schema（见设计方案 7.5）
2. 实现 rich profile 写入逻辑（facts 镜像 + evidence + visualizations 预计算）
3. 蒸馏任务原子写入两个文件（`user_profile.md` + `profile.rich.json`）
4. 历史版本归档（`profile.rich.<timestamp>.json`）

**依赖**：T2.2
**产出**：rich profile 存储实现

### T2.4 HTTP 路由

**任务**：提供前端数据接口。

**步骤**：
1. 在 `mona/api/server.py` 的 `create_app()` 注册路由：
   - `GET /api/profile` → 返回 `profile.rich.json` 全量
   - `PATCH /api/profile/facts` → 用户修正画像
2. 前端用 `getGatewayHttpBase()` 获取 URL
3. 鉴权 + 错误处理

**依赖**：T2.3
**产出**：2 个 HTTP 路由

### T2.5 前端画像页骨架

**任务**：搭好画像页 UI 骨架。

**步骤**：
1. 新增 `webui/src/components/profile/ProfileView.tsx` 主组件
2. 新增侧边栏一级入口（人物图标，排在日程后）
3. 接入路由系统（`view: "profile"`）
4. 顶部：头像 + 标语 + 蒸馏时间戳
5. Tab 切换骨架（人物画像 / 成长轨迹 / 工作模式，后两个先占位）

**依赖**：T2.4
**产出**：画像页骨架 + 侧边栏入口

### T2.6 画像可视化组件

**任务**：实现人物画像 Tab 的可视化。

**步骤**：
1. 安装依赖：`recharts`, `framer-motion`, `react-force-graph`（或 Cytoscape.js）
2. 实现组件：
   - `TagCloud.tsx`（关注领域）
   - `TechStackRadar.tsx`（技术栈雷达图）
   - `RelationshipGraph.tsx`（人际网络）
   - `KnowledgeStructureBar.tsx`（知识结构堆叠条形图）
3. 数据从 `GET /api/profile` 拉取
4. Framer Motion 入场动画

**依赖**：T2.5
**产出**：4 个可视化组件

### T2.7 用户修正功能

**任务**：用户能在 UI 上修正画像。

**步骤**：
1. 画像卡片支持编辑模式（点击编辑按钮）
2. 调用 `PATCH /api/profile/facts` 提交修正
3. 修正项打标记（`user_edited: true`），下次蒸馏保留
4. 修正后前端立即刷新

**依赖**：T2.6
**产出**：画像编辑功能

## 阶段 3：成长轨迹 + 完整可视化

**目标**：可视化呈现用户成长，形成产品差异化。
**验证标准**：用户能直观看到成长轨迹，产生情感价值。

### T3.1 时间序列存储设计

**任务**：设计轨迹数据存储。

**步骤**：
1. 定义 trajectory 数据点 schema：`{timestamp, focus, score, evidence}`
2. 每次蒸馏追加一个数据点到 `profile.rich.json` 的 trajectory 数组
3. 历史数据保留策略：默认永久，可配置滚动 N 个月
4. 数据点压缩（旧数据按月聚合，新数据按周）

**依赖**：阶段 2 完成
**产出**：trajectory 存储实现

### T3.2 轨迹数据采集与聚合

**任务**：扩展蒸馏任务产出轨迹数据。

**步骤**：
1. 阶段 1/2 蒸馏任务追加：产出当前时间点的 trajectory 切片
2. 关注领域变化检测（与上次蒸馏对比）
3. 技能积累密度计算（按月统计笔记密度）
4. 关键里程碑检测（首次笔记、首次邮件、领域切换等）

**依赖**：T3.1
**产出**：轨迹采集逻辑

### T3.3 前端轨迹页

**任务**：实现成长轨迹 Tab。

**步骤**：
1. 实现 `TrajectoryView.tsx`
2. 安装 `react-calendar-heatmap`
3. 实现组件：
   - `ActivityHeatmap.tsx`（GitHub 贡献图风格）
   - `FocusEvolutionChart.tsx`（多线折线图）
   - `SkillAccumulationChart.tsx`（堆叠面积图）
   - `MilestoneTimeline.tsx`（时间轴）
4. 时间范围筛选器（3个月/6个月/全部）

**依赖**：T3.2, T2.5
**产出**：4 个轨迹可视化组件

### T3.4 工作模式 Tab 可视化

**任务**：实现工作模式 Tab。

**步骤**：
1. 实现 `WorkPatternView.tsx`
2. 安装 D3.js（用于桑基图）
3. 实现组件：
   - `TopToolsChart.tsx`（横向条形图 + 数字滚动动画）
   - `ToolChainSankey.tsx`（桑基图）
   - `ActiveHoursHeatmap.tsx`（24h × 7d 热力图）
   - `CollaborationModeChart.tsx`（环形图）
4. 数据从阶段 1 的 work_patterns 段拉取

**依赖**：T2.5, T2.6
**产出**：4 个工作模式可视化组件

### T3.5 隐私配置

**任务**：实现隐私边界控制。

**步骤**：
1. 设置页新增"画像蒸馏"配置区
2. 按数据源开关：笔记 / 邮件 / hoard / 对话历史
3. 按字段开关：人际网络 / 工作模式（敏感字段默认关）
4. 配置变更后下次蒸馏生效
5. 一键清除画像数据（删除 `profile.rich.json` + 清空 `user_profile.md` 蒸馏段）

**依赖**：T3.4
**产出**：隐私配置 UI + 后端逻辑

### T3.6 视觉打磨

**任务**：整体视觉提升到"酷炫"水平。

**步骤**：
1. 毛玻璃卡片样式（`backdrop-blur`）
2. 渐变色 + 发光效果
3. 大字号关键指标（48px）
4. Tab 切换过渡动画
5. 空状态设计（数据不足时的友好提示）
6. 加载状态骨架屏

**依赖**：T3.5
**产出**：视觉打磨完成

## 里程碑

| 里程碑 | 内容 | 验证点 |
|--------|------|--------|
| M1 | 阶段 1 完成 | AI 能基于工作模式画像个性化响应 |
| M2 | 阶段 2 完成 | 用户能在 UI 看到完整人物画像并修正 |
| M3 | 阶段 3 完成 | 完整酷炫可视化 + 隐私配置 |

## 风险点

1. **LLM 蒸馏质量**（T1.3）：prompt 调优可能耗时较多，需小样本快速迭代
2. **工具调用历史格式**（T1.1）：session 文件结构需先调研，可能字段不全
3. **可视化库兼容性**（T2.6）：Tauri 环境下图表库需验证，可能有 canvas/webview 限制
4. **数据稀疏冷启动**（T2.2）：新用户数据不足，蒸馏结果置信度低，需有降级策略
5. **隐私合规**（T3.5）：敏感字段默认关闭，需明确告知用户

## 技术债务预留

- 蒸馏任务支持手动触发 + 全量重跑（用于调优）
- 画像版本回滚（历史版本归档已设计）
- 多用户隔离（当前单用户，预留扩展）
- 蒸馏任务监控面板（成功率、耗时、LLM 成本）
