# 开发模块多引擎权限与沙箱接入

状态：实现完成；已完成本机 Windows 必要验证

## 目标与范围

开发会话统一使用“请求批准、自动审批、完全访问”三档权限，以及输入区现有审批卡。覆盖 Mona Coding、Codex、Claude Code、CodeBuddy；普通会话与其他模块保持各自现有策略。

复用 Cindy 的审批分层和三态结果，复用 DSH 的沙箱 runner 与平台 profile。Mona 保留 AgentRunner、会话存储、原生执行器和统一运行时仓库。上游核心实现保留来源与许可证，不另写 Windows 令牌、ACL 或命令字符串沙箱。

## 行为约定

- 会话保存一份权限模式，历史会话默认“请求批准”；每个 Run 固定本轮模式。运行中和结果待核对时禁止切档，用户处理现有审批后可在下一轮切换。
- 请求批准：既有项目范围内读取和文件编辑可执行，需要额外权限的动作由用户确认。Mona 命令执行在 DSH 工作区写入沙箱下运行；无法证明可直接执行的动作请求确认。
- 自动审批：沙箱范围保持原策略，由共享审核器判断操作是否属于用户授权，返回允许、阻止或询问用户；超时、服务不可用和无效结果转现有审批卡。审核输入只包含用户授权、实际动作和必要范围。
- 完全访问：用户明确确认后放宽普通执行范围和常规审批。只读任务、会话归属、已取消请求和产品固定边界仍由系统强制执行。
- 子任务继承父会话的权限档；只读子任务始终只读。子任务审批保持原所属会话、Run 和确认 ID。
- Codex 映射原生审批策略和沙箱参数；Claude/CodeBuddy 映射 SDK 模式与审批回调。当前统一自动审批使用宿主审核入口，避免未经核对的原生分类器路由。
- DSH Windows 后端仅报告部分文件写入隔离；读取和网络不在其隔离承诺内。沙箱无法启动时明确失败，不降级成不受限执行，不自动重放已执行或结果未知的命令。
- 页面底部只增加紧凑权限选择器；错误用现有弹窗，不在摘要面板或对话空白处增加说明行。切档成功后才更新显示。

## 实施顺序

1. 共享协议：配置 schema、会话/Run 字段、持久化、权限更新 API 和子任务继承。
2. 共享审批：连接 Mona 工具执行入口与现有 DecisionBroker；移植 Cindy 的有界授权审核与故障兜底。
3. CLI 适配：落实三档映射、下一轮生效、只读保护和模式回执核对。
4. 沙箱执行：保留 DSH runner 核心，制作带版本及许可证的组件，接入 RuntimeComponentStore；Mona 普通与持续命令使用同一沙箱启动路径。
5. 前端：输入框底部权限选择器、完全访问确认、失败反馈和审批期间草稿保留。
6. 验证与文档：补最近边界的回归测试，更新长期不变量和执行器指南。

## 必要验收

- 四引擎选择、保存、重启恢复及实际派发模式一致；错误与旧 revision 不改变已确认状态。
- 自动审核允许/阻止/人工确认三个结果，以及审核不可用时的确认兜底。
- 只读与父子任务归属不因完全访问失效；旧审批不能授权新的 Run。
- 在临时工作区验证 Windows 沙箱允许区内写、阻止区外写，启动失败不执行命令，取消回收子进程；Linux/macOS 按可用平台验证并明确报告未实机覆盖部分。
- 前端只测选择、确认与失败保留；相关 Python 检查、TypeScript 检查通过。通过后不重复全量测试。
