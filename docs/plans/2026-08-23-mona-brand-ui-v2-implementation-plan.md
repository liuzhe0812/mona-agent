# Mona 品牌 UI v2 实施计划

> 状态：首批样板完成，第二批执行中  
> 日期：2026-08-23  
> 目标规范：[`../design/mona-ui-design-system.md`](../design/mona-ui-design-system.md)  
> 品牌依据：[`../design/2026-08-22-mona-app-brand-ui-update-plan.md`](../design/2026-08-22-mona-app-brand-ui-update-plan.md)

## 1. 目标

在已经完成中性配色和黑猫身份统一的基础上，把官网语言翻译为克制的桌面品牌语法，并用三个样板验证卡片、表格、页面布局和动效是否能形成同一套系统。

首批样板：

1. 应用外壳＋新会话欢迎页：验证品牌签名、页面布局和 Agent 动效；
2. 欢迎页工作摘要：验证工作卡片／操作卡片层级；
3. 数据库结果表：验证高密度表格、选择、hover 和业务状态。

## 2. 非目标

- 不复制官网的满屏红黑拼贴；
- 不一次性修改所有业务模块；
- 不重构 Store、接口、数据逻辑或页面信息架构；
- 不新增动画库、组件库或 UI 依赖；
- 不为只有一个使用方的场景提前建立抽象；
- 不改股票涨跌色、危险色和领域语法高亮。

## 3. 冻结规则

- 每屏最多一个品牌视觉中心；
- App Rail 当前项不使用整块背景，以 2px 红色信号＋图标／文字深浅表达；
- 工作卡片 8–10px 圆角、1px 边框、无阴影；操作卡片 hover 使用前景色 5–6% 叠加；
- 品牌卡片每屏最多一张，只允许单个 8–12px 切角；
- 欢迎页品牌表面无外围边框、无默认阴影，内部信息以留白而非连续分隔线分组；
- 数据表、文档正文和各类编辑画布浅色使用纯白 `editor-surface`；
- 表头 36px、普通行 40–44px、仅横向分隔线，行操作按需显现；
- 常规动效使用 80／150／200ms，650ms 只用于单次品牌入场；
- AI 青色只在 Agent 工作时出现；空闲时不播放持续环境动效；
- 浅色、深色和 `prefers-reduced-motion` 必须同时成立。

## 4. 首批开发任务

### UI-V2-01：基础动效与共享控件收口

所有权：

- `webui/src/globals.css`
- `webui/tailwind.config.js`
- `webui/src/components/ui/button.tsx`
- 相关基础组件测试

任务：

- 将动效档位冻结为 80／150／200／650ms；
- 确认 Button 默认变体使用中性反相 `action`，ghost／outline 不引入彩色背景；
- 复用现有组件 API，不创建 `ui-v2` 或单用途 Card 抽象；
- 只补齐首批样板真实需要的 Token。

### UI-V2-02：应用外壳与欢迎页品牌样板

所有权：

- `webui/src/components/shell/AppRail.tsx`
- `webui/src/App.tsx`（仅主内容表面）
- `webui/src/components/thread/ThreadShell.tsx`
- `webui/src/components/thread/NewChatDashboard.tsx`
- `webui/src/components/AgentLogo.tsx`
- 对应测试

任务：

- App Rail 去掉当前项整块背景，增加 2px Mona Red 指示；
- 主内容表面收口为 12px 圆角、1px 边框、默认无阴影；
- 欢迎页保持一个品牌卡片，使用单切角、红色信号和现有黑猫身份；
- 移除欢迎页外围边框、阴影和非必要的内部连续分隔线；
- 工作摘要继续使用分区与留白，不变成等权卡片墙；
- Agent 空闲静止；工作时才显示 AI Cyan 呼吸／扫描；
- 输入区在工作状态显示 2px 青色状态线；
- 保留现有功能、数据和快捷入口。

### UI-V2-03：数据库结果表样板

所有权：

- `webui/src/components/db/ResultPanel.tsx`
- 必要的数据库结果表测试

任务：

- 表头、行高和单元格间距按规范统一；
- 默认只保留横向分隔线；
- hover 与选择改为中性叠加，不使用普通蓝色整块填充；
- 保留主键、编辑、插入、脏数据、成功、警告和右键菜单逻辑；
- 数字右对齐、文本左对齐，空／加载／错误不改变布局。

## 5. 验收门

代码门：

- `npm run build`；
- 首批样板相关测试；
- `git diff --check`；
- `npm run check:ui` 不得在本批文件增加新债务；
- 不新增依赖，不改变公共业务接口。

视觉门：

- 浅色／深色 1280×720；
- App Rail 默认、hover、active；
- 欢迎页 idle／working／reduced-motion；
- 数据表默认、hover、selected、dirty、inserted；
- 页面第一眼只有一个视觉中心；
- 工作正文没有红黑拼贴、持续发光或卡片套卡片。

## 6. 后续推广

首批通过后按模板推进：

1. 笔记／文档：内容工作台、工具栏、AI 侧栏；
2. 邮件：列表—详情、撰写和附件；
3. 工作流画布：中性节点、青色执行线、琥珀确认节点；
4. 设置／系统：表单、分组、Alert 和危险操作；
5. 终端／IDE／浏览器：只统一宿主外壳，不改领域内容；
6. 清理被样板替代的局部样式和 UI 债务。

## 7. 美术资源边界

首批不新增美术资源，复用当前黑猫 Logo 和官网既有人形资产。只有在欢迎页样板确认需要“猫前景＋人形剪影”时，由主代理生成透明背景人形剪影并完成小尺寸／深浅主题验收，开发代理只负责接入。

## 8. 第二批开发任务

### UI-V2-04：笔记／文档工作台

- 内部资源栏使用近白工作表面，不复用应用外壳 sidebar 色；
- 模式切换去掉外框和整块选中背景，通过图标／文字深浅与短指示表达；
- Markdown、思维导图和流程图正文保持 `editor-surface`；
- AI 与属性侧栏只保留单条分隔，不增加卡片壳；
- 不修改笔记存储、编辑、同步和导出逻辑。

### UI-V2-05：邮件列表—详情工作台

- 文件夹栏使用工作表面，顶部工具栏与阅读正文减弱灰底；
- 邮件正文使用 `editor-surface`；
- 邮件选中态使用中性叠加与短标记，蓝色只保留未读／信息语义；
- AI 侧栏使用 card 表面＋单条分隔；
- 不修改同步、删除、移动、撰写和快捷键逻辑。

### UI-V2-06：工作流画布状态语言

- 画布保持 `editor-surface`；
- 普通节点中性、无阴影；running 使用 AI Cyan，waiting approval 使用 Mona Amber；
- 正在执行的连线使用青色和功能性动画，完成后停止；
- 选中态与运行态必须视觉分工；
- 不修改 DAG、拖拽、连线、运行和审批逻辑。

## 9. 第三批开发任务

### UI-V2-07：系统管理工作台

- 系统页签使用中性文字＋Mona Red 短指示，不使用普通蓝色选中；
- 系统优化首页移除渐变 Hero、发光和默认阴影；
- 分类与设置项从卡片墙收口为工作表面上的分组／行；
- 保留风险、兼容、重启、管理员和恢复语义；
- 不修改系统检测、应用、恢复和提权逻辑。

### UI-V2-08：辅助窗口品牌收口

- 通知和快捷提问使用中性浮层表面、Mona Red 信号与现有黑猫身份；
- 入退场使用统一 motion Token，不使用任意 300ms 或泛用蓝装饰条；
- 保留浮层必要的边框和阴影，不增加品牌拼贴；
- 不修改通知动作、自动关闭、快捷提问发送和窗口生命周期。

### UI-V2-09：终端宿主外壳

- 终端工具栏和 Session Tab 使用 card 工作表面，不复用深色 sidebar；
- 文件树、监控与 AI 面板开关用图标／文字深浅表达，不使用整块 active 背景；
- 保留终端、IDE、SFTP、VNC 和虚拟桌面的领域内容；
- 不修改连接、会话、分栏和终端输入逻辑。

## 10. 第四批开发任务

### UI-V2-10：设置外壳

- 设置导航 active 去整块背景，使用 Mona Red 短指示；
- 加载和概览减少无必要卡片／阴影；
- 保留真正独立的 provider、凭证和计划实体边界；
- 不覆盖当前并行设置功能改动，不恢复已删除页面标题。

### UI-V2-11：浏览器宿主外壳

- 地址栏、书签栏和新标签页使用 card／editor 工作表面；
- 输入区与快捷入口取消默认阴影和过大圆角；
- 保留网页 WebView 边到边例外和浏览器交互逻辑。

### UI-V2-12：PPT／视频制作外壳

- 资源栏、历史栏使用 card，不使用深灰 muted 墙；
- 预览／编辑主区使用 editor-surface；
- 模式切换和步骤导航减少阴影、彩色填充与多层卡片；
- PPT／视频两条流程保持同一外壳语言，不改生成、保存和导出逻辑。

## 11. 第五批开发任务

### UI-V2-13：计划／日程工作面

- 日历与周视图使用 editor-surface；
- 右侧当天计划使用 card＋单条分隔；
- 保留日程状态、未读计数和新建主操作。

### UI-V2-14：画像洞察外壳

- 顶部 Tabs 使用无背景文字＋Mona Red 指示；
- 人物摘要从 info 蓝品牌卡收口为中性独立实体卡；
- 数据图表和角色色保留领域语义，不承担页面品牌表达。

### UI-V2-15：多 Agent 管理与房间侧栏

- 房间信息／工作流切换去整块背景，使用红色短指示；
- Agent 管理页的内部导航使用中性文字和指示，不使用卡片式选中；
- 保留成员、目标、产物、权限和 Agent 配置业务逻辑。

## 12. 第六批开发任务

### UI-V2-16：产物与文件预览

- 产物树使用 card 工作表面，行选中只用中性叠加与短标记；
- 文件预览正文使用 editor-surface，顶部工具栏只保留一条必要分隔；
- 去掉普通产物卡的默认阴影和多余容器框；
- 不修改文件扫描、预览、打开、删除和全屏逻辑。

### UI-V2-17：文档制作与 Markdown 阅读外壳

- PPT／视频顶层切换去胶囊填充，使用中性文字＋Mona Red 短指示；
- Markdown 正文继续复用 editor-surface；
- AI／目录开关不使用整块 active 背景，侧栏只保留单条分隔；
- 不修改加载保活、保存、目录定位和 AI 编辑逻辑。

### UI-V2-18：功能 AI 侧栏

- 数据库、邮件、笔记、思维导图、流程图和系统助手统一使用 card 表面；
- 标题区与输入区只保留结构所需分隔，输入框取消默认阴影；
- 状态、风险和确认颜色保留领域语义，不作为普通装饰；
- 不修改消息、工具调用、审批、归档和诊断逻辑。

## 13. 第七批开发任务

### UI-V2-19：核心会话与输入区

- 普通消息正文不新增气泡壳；群聊消息去默认阴影，只保留必要角色边界；
- 输入区保留一个主边界，取消默认阴影，focus 使用克制的中性描边；
- 菜单和悬浮层保留必要阴影，附件和媒体保持领域边界；
- 不修改消息渲染、提及、附件、发送、停止和快捷键逻辑。

### UI-V2-20：订阅与账号品牌收口

- 订阅页移除橙黄渐变横幅，改为中性工作表面＋Mona Red 信号；
- 方案选中使用中性表面、红色短标记或边界，不使用普通蓝；
- Sidebar 的 Pro／更新状态移除橙黄渐变与普通品牌蓝，保留清晰状态语义；
- 不修改价格读取、支付、授权、登录和更新逻辑。

### UI-V2-21：系统概览层级

- 指标卡与问题容器去默认阴影，保留数据实体边界；
- 系统表格继续使用横向分隔和紧凑行，不增加卡片套卡片；
- 图表色、风险色和状态色保留领域语义；
- 不修改采样、排序、诊断和系统操作逻辑。

## 14. 第八批开发任务

### UI-V2-22：顶层标题栏（已撤回）

- 保留改造前的透明标题栏、低对比圆角标签与原选中态；
- 不将 Mona Red 指示语言应用到顶层浏览器式 TabBar。

### UI-V2-23：笔记内部 TabBar

- 笔记标签与关系图谱标签改用中性文字＋Mona Red 2px 底线；
- 去掉 active 的整块背景和普通蓝色指示；
- 工作区叶节点明确使用 editor-surface，不再透出 background。

### UI-V2-24：笔记与画布白色编辑面

- Markdown、思维导图和流程图的编辑根节点在浅色主题统一使用 editor-surface；
- 思维导图只覆盖编辑画布底色，保留节点主题与导出语义；
- 流程图把 `--flowchart-canvas` 实际应用到根画布，允许显式文档背景覆盖；
- 深色主题继续使用既有 editor-surface，不修改编辑、导出、主题和画布交互逻辑。

### UI-V2-25：Mona 固定工作区入口

- 顶层 `Mona` 保留点击返回工作区能力，但不显示浏览器标签式 active／hover 表面；
- 其他浏览器、Markdown 和历史标签维持原 TabBar 交互。
