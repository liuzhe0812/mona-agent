# 股票投研 V6：基金经理 + 量化最佳实践开发计划

## 1. 目标与边界

目标不是让 AI 猜涨跌，而是把可核验数据、确定性量化、专业研究判断、A 股交易约束和个人风险预算组合成可追踪的决策辅助产品。

数据源与合规边界沿用[数据源与合规可行性矩阵](../design/stock-data-source-compliance-matrix.md)；该矩阵是证据层参考，不替代本 V6 产品基线。

本版本必须遵守以下边界：

1. 产品只提供决策辅助，不自动下单，不承诺收益。
2. LLM 不计算价格、仓位、收益率、估值或量化分数；只处理有来源的非结构化事实、解释分歧和生成用户可读文本。
3. 免费数据源没有可靠盘口、真实滑点或完整历史点时财务数据时，不伪造精度；受影响的交易计划必须降为“暂不参与”或“等待确认”。
4. “可生成报告”不等于“可交易”。只有数据、模型、执行和风险四个门槛全部通过，才能输出买入区间和仓位。
5. 保留现有六 Agent 架构和角色，不新增 Agent；通过独立假设、直接证据引用和确定性裁决降低相关错误。

## 2. 用户最终得到什么

每只股票分别给出短线、中线、长线结论，但三个周期使用不同的数据、模型、目标和有效期。

| 用户问题 | 必须回答 | 不满足条件时 |
| --- | --- | --- |
| 当前方向 | 看涨 / 中性 / 看跌 / 回避 | 暂不参与，并说明缺少哪类可交易条件 |
| 当前操作 | 买入、等待、持有、减仓、退出、回避 | 不生成含糊的“自行判断” |
| 什么价格参与 | 突破参与区间、回踩参与区间 | 不满足执行门槛时不显示伪精确价格 |
| 什么价格退出 | 止损、第一止盈、第二止盈 | 必须与方向和持仓状态一致 |
| 多少仓位 | 首仓、最大仓位、单笔风险 | 结合用户风险、现有持仓、行业暴露和流动性上限 |
| 结论何时失效 | 时间边界、价格边界、基本面/事件边界 | 到期自动标记并要求重新投研 |
| 为什么可信 | 使用方法、数据时点、样本外验证状态、关键理由 | 不展示虚构置信度 |

## 3. 三周期模型

### 3.1 短线：1—10 个交易日

- 目标：判断交易时点和执行可行性，不判断长期价值。
- 核心输入：日内/日线量价、20/60 日趋势、短期反转、波动率、成交额、换手率、市场状态、板块相对强弱、涨跌停和停牌状态。
- 模型：市场状态条件化的趋势/反转模型；不同市场状态使用不同信号方向和阈值。
- 交易约束：T+1、100 股整数手、涨跌停可成交性、停牌、ST/风险警示、成交额容量、滑点代理。
- 输出：条件参与、等待、持有、减仓、退出或回避；有效期按真实交易日历计算。

### 3.2 中线：2 周—6 个月

- 目标：判断行业、盈利和估值变化能否形成持续重估。
- 核心输入：盈利增速和质量、经营现金流、行业相对强弱、供需周期、政策传导、事件日历、估值分位、量价确认。
- 模型：盈利/质量/估值/行业周期多因子模型，技术信号只用于时点确认。
- 硬门槛：行业信息、周期信息、财务时点和至少一种可验证估值方法必须可用；新闻不能单独决定方向。
- 输出：参与条件、基本面失效条件、催化时间窗和复评日期。

### 3.3 长线：6 个月以上

- 目标：判断资本回报、现金流和估值是否支持长期持有。
- 核心输入：多期 ROE/ROIC、现金流质量、盈利稳定性、杠杆、治理、稀释、历史估值、同行估值、行业生命周期。
- 模型：行业适配估值，而不是所有公司只看 PE/PB。
  - 银行/保险：PB-ROE、剩余收益；
  - 周期行业：中周期盈利、PB/EV-EBITDA（字段可用时）；
  - 稳定现金流公司：FCFF/股东自由现金流收益率；
  - 成长公司：增长质量、估值分位和情景敏感性。
- 硬门槛：多期财务、现金流质量、公司质量和估值依据必须可追溯。
- 输出：价值区间、长期失效条件、最大配置上限和复评节点。

## 4. 确定性量化层

### 4.1 选股模型

保留“规则筛选 → 因子排序 → AI 解释”的结构，但替换静态未校准权重。

必须实现：

1. 每个周期独立的因子注册表、方向、版本和适用市场状态。
2. 行业内和全市场双重标准化；微盘股不能主导断点。
3. 缺失值不填零，不参与该因子贡献；因子覆盖率进入资格门槛。
4. 股票池必须保留当时可交易状态、上市时间、ST、停牌和退市信息，避免幸存者偏差。
5. 选股结果保存原始值、标准化值、贡献、来源、算法版本和快照哈希。
6. 未通过样本外验证的策略只能显示为“研究策略”，不能生成交易推荐。

### 4.2 历史验证与晋级门槛

建立独立于 LLM 的滚动验证器：

- 按时间滚动训练/验证/测试，禁止随机切分金融时间序列；
- 使用真实交易日历、复权价格、停牌、涨跌停、退市和公司行为；
- 纳入佣金、印花税、滑点代理和换手成本；
- 输出 Rank IC、ICIR、分组单调性、超额收益、最大回撤、换手率、胜率、盈亏比、样本数；
- 记录试验次数并计算过拟合风险；支持 Deflated Sharpe / PBO 或等价的多重检验控制；
- 至少覆盖上涨、下跌、震荡三种市场状态；
- 策略必须通过样本外阈值才能标记为 `calibrated`；任何阈值失败保持 `research_only`。

晋级规则由版本化配置保存，不能由 LLM 修改。第一版不追求找到高收益参数，优先证明无未来函数、无幸存者偏差、成本可复算。

## 5. A 股执行可行性层

### 5.1 硬规则

- 主板、创业板、科创板、北交所、ST/风险警示分别解析价格限制规则；
- T+1：当日新买持仓不能建议当日卖出；
- 数量按交易单位取整；
- 停牌、退市整理、上市初期等特殊状态单独处理；
- 涨停附近的买入计划必须判断不可成交风险；跌停附近的止损必须提示无法成交风险；
- 免费数据不能确认盘口深度时，不展示“立即成交”类措辞。

### 5.2 滑点和容量

- 使用成交额、换手率、波动率和订单状态建立保守滑点代理；
- 仓位不得超过用户资金、产品单股上限、行业上限和流动性容量中的最小值；
- 无真实盘口时状态必须是 `proxy`，不能标记为真实滑点；
- 风险收益比使用成本后的入场、止损和止盈价格计算。

## 6. 方向感知交易计划

交易计划必须由确定性策略根据最终方向、用户持仓状态和执行门槛生成：

| 方向 | 未持有 | 已持有 | 允许显示的价格 |
| --- | --- | --- | --- |
| 看涨 | 条件参与或等待回踩 | 持有/加仓条件 | 买入、止损、两级止盈 |
| 中性 | 等待确认 | 持有或减仓 | 上破确认、下破失效，不主动给买入建议 |
| 看跌 | 回避 | 减仓或退出 | 反弹减仓、止损、重新转多条件 |
| 回避 | 不参与 | 退出或风险处置 | 只显示失效和复评条件 |

禁止看跌/回避结论仍展示普通买入区间。短、中、长周期分别使用独立参数版本；固定 2R/3R 只能作为未校准基线，不能作为已验证最佳参数。

## 7. 用户风险和组合仓位

新增本地风险配置，不接券商账户、不自动交易：

- 总资金区间；
- 风险承受等级；
- 单笔最大风险；
- 单股和单行业上限；
- 当前是否持有、持仓成本和仓位；
- 现有自选/持仓的行业暴露。

持仓录入支持两种方式：

- 按仓位百分比直接录入 0—100%；
- 按总资产（元）和持股数录入，使用实时行情价格换算当前仓位；
- 两种方式统一落为 `current_position_pct`，0% 或 0 股视为未持有；
- 持仓设置仅保存在本地，不连接券商账户、不自动交易。

仓位引擎：

1. 固定风险仓位作为基础；
2. 按波动率缩放；
3. 按成交容量限制；
4. 按现有持仓相关性和行业集中度进一步限制；
5. 未配置用户风险时使用明确标注的保守默认值，不伪装成个性化建议。

## 8. 行业、政策、周期和估值

### 8.1 数据门槛

- 短线：行业/政策可作为增强项；
- 中线：行业和周期是硬门槛，政策在政策敏感行业是硬门槛；
- 长线：公司质量、多期财务、现金流和估值是硬门槛；行业生命周期必须有来源。

不得通过把关键维度改成“增强项”来消除数据不足。门槛不满足时允许生成研究记录，但不生成可执行交易计划。

### 8.2 估值引擎

- 当前同行 PE/PB 分位；
- 可获得历史快照时计算自身历史分位；
- 正常化盈利和现金流质量；
- 支持行业适配方法选择；
- 至少两种方法可用时给交叉区间；
- 只剩单一方法时明确降低估值可信度；
- LLM 只能解释估值输入和风险，不能计算估值结果。

## 9. 六 Agent 改造

不改变六个角色和 DAG：技术、基本面、资讯并行；多头、空头并行；主审最后裁决。

改造要求：

1. 技术、基本面、资讯只读取自己的证据分区并提交结构化事实/推断。
2. 多头和空头共享同一不可变 Evidence，但独立读取原始紧凑证据和三路 Artifact；彼此不可见。
3. 多头必须列出成立假设和确认条件；空头必须攻击同一假设并列出反证。
4. 主审先读取确定性量化、估值、执行和风险门槛，再读取多空论证；不得用语言说服覆盖硬门槛。
5. 最终方向和操作必须通过确定性策略校验；LLM 只能选择受允许的动作并解释原因。
6. 保存分歧矩阵：争议点、双方依据、主审采信、保留风险、改变结论的条件。
7. 每个 Agent 的结果在前端默认折叠，用户点击后查看；不铺满过程文字。

## 9A. P0：语义完整性闭环

本 P0 专门修复“数据缺口被错误归因、基础指标与派生计划混淆、模型自由算术、行业证据不足却声称周期确认、内部状态泄露到用户界面”这类跨 Agent 问题。它不改变六 Agent DAG、Skill 能力或分析维度，只收紧事实边界和用户文本出口。

### 9A.1 统一合同

1. Evidence 是数值唯一真值。Agent 只能原样引用当前 run Evidence 中已有、带 `source_ids` 的数值；引用上游 Artifact 时只能复述其中已经有 Evidence 来源的事实，不能据此二次计算。
2. Agent 禁止自由算术，包括加减乘除、同比/环比、比例、平均、排序、聚合、单位换算、插值，以及自行生成价格、仓位、分数、概率、止盈止损或确认阈值。交易和量化字段只能由确定性系统注入。
3. 基础指标与派生交易计划必须分开表述：K 线、均线、MACD、RSI 和财务原始指标是基础事实；交易计划、执行资格、仓位和量化分数是系统派生结果。派生结果缺失不得表述为基础指标缺失。
4. 缺口只能来自当前 Evidence 明确的 `failure_reasons`/`missing_fields`，并说明业务影响；不得读取 provider、接口、URL、日志或错误文本推断原因，也不得把一个分区缺失扩展为全局缺失。
5. 没有行业供需、产业链、产品价格或行业周期证据时，不得声称行业趋势、行业周期或政策传导已确认；资讯、单一公告或公司单期财务不能替代行业证据，也不能据此推断公司业务发展。
6. `research_ready=false` 时 Agent 只提交结构化状态、缺口和来源，用户可见的不可用摘要由系统按固定映射生成；Agent 不自由编写因果解释。内部字段、英文状态码、接口名、机器码和 HTML 实体不得进入用户文本。

### 9A.2 实现任务

1. 在六个 Agent 的 prompt/Skill、深度投研 workflow 和主审合同中写入同一组语义边界；不得只修复技术分析师。
2. 在提交入口增加跨角色语义校验：来源数字、自由算术/自定阈值、基础/派生混淆、行业周期无证据断言、上游错误传播和用户文本泄露必须可拦截或改由系统生成。
3. 将不可用摘要、缺口标签和数据源失败原因统一映射到业务语言；保留机器状态在内部结构，不让 Agent 自由改写用户文案。
4. 增加负向合同测试：六个角色分别覆盖缺 quote、缺派生指标、缺行业周期、缺公司经营证据、单一资讯来源和多空上游错误等场景。

### 9A.3 P0 验收标准

- 同一 Evidence 下，任一 Agent 不能提交未经来源支持的新数值、自由算术结果或确认阈值。
- 缺少派生交易计划时，用户仍能看到已有基础指标，且不能被写成“技术指标全部缺失”。
- 缺少行业证据时，中线不能声称行业趋势/周期已确认；缺少公司经营证据时，长线不能用新闻代替公司发展结论。
- 多空不得传播上游 provider/接口错误或把上游不可用原因扩大为全局不可用。
- 主审不得以语言覆盖 `research_ready`、`trade_ready`、量化校准和执行资格等确定性状态。
- 最终用户文本不出现内部字段、英文状态、接口名称、HTML 实体或“证据不足/数据不足”这类无业务解释的占位语；不可用状态必须由系统生成可理解的业务说明。

## 10. V6 结果验证闭环

V6 每次报告创建不可变追踪快照，并自动记录：

- 报告时价格、基准和所有条件；
- 条件首次触发时间；
- 1/5/10/20/60/120 个交易日收益；
- 相对中证全指和行业基准收益；
- 最大有利变动、最大不利变动；
- 止损/止盈是否可成交；
- 成本前和成本后 R 倍数；
- 三周期方向命中、行动命中和校准状态；
- 模型版本、Evidence 哈希和数据源版本。

任何报告修改都创建新报告，不回写历史结果。前端只在样本成熟后展示统计，不把小样本胜率包装成能力。

## 11. 前端信息架构

### 11.1 右侧决策雷达

只显示用户立刻需要的结论：

- 短/中/长周期；
- 方向、当前操作、未持有/已持有动作；
- 方向适配的价格计划；
- 首仓、最大仓位和风险预算；
- 当前持仓支持按仓位百分比，或按总资产与持股数结合实时行情换算；
- 有效期、计划失效和最大风险；
- “已校准 / 研究模式 / 执行受限”状态；
- 报告过期或数据变化时的重新投研提示。

无有效计划时保留完整结构，显示“暂不参与”和门槛状态，不留空白、不显示示例数字。

### 11.2 投研页

- 顶部：一句话总结和三周期结论；
- 中部：估值、行业/政策/周期、风险、量化验证的结论卡；
- 下部：六个 Agent 名称、状态和一句结论；点击才展开依据；
- 完整 Evidence、来源和方法版本放在“查看依据”内；
- 不展示工具调用、内部字段名、英文状态码或长篇推理过程。

## 12. 可观测性和运行可靠性

- 数据源字段漂移和页面结构变化告警；
- 主/备数据源差异校验；
- Evidence、算法、Prompt、模型和报告版本全部入快照；
- 工作流成功、失败、重试、取消、耗时和缺失 Artifact 指标；
- 新模型或参数先影子运行，再灰度启用；
- 数据源不可用时读取同交易日缓存，不跨日伪装成实时数据；
- 失败运行不得显示“已完成”。

## 12A. 六类外部 Skill 能力审计与受控接入边界（2026-08-24）

这六个名称不能直接等同于 Mona 已经接入的运行能力。核验到的是 SkillHub/ClawHub 上的独立包；它们必须经过版本、许可、密钥、数据来源和输出合同审查后，才能作为 Evidence 的受控数据适配器或方法参考。任何外部 Skill 都不能绕过 Evidence、确定性量化层、A 股执行规则和 V6 主审。

### 12A.1 统一接入合同

所有允许接入的外部能力必须经过同一条链路：

`外部 Skill/数据源 → 版本与许可检查 → 隔离适配器 → 字段/单位/时间校验 → 来源记录与内容哈希 → Evidence 快照 → 确定性量化/估值/执行计算 → Agent 解释 → V6 报告与雷达`

硬规则：

1. 外部 Skill 不能直接写报告，不能直接提交 Agent Artifact，不能直接生成价格、仓位、收益率、Alpha 概率或“买入/卖出”动作。
2. 每个适配器必须保存来源、抓取时间、数据日期、包版本、包内容哈希、命令参数、原始响应哈希、字段映射版本和失败原因。
3. 包文档版本、实际 npm 包版本、命令名称或返回结构不一致时，适配器进入 `degraded`，不得静默猜字段；必须用现有源或同日缓存回退。
4. 不把“无 API Key”误解为“可商业再提供”；数据源协议、网页接口使用边界和文章版权单独审查，未确认时只做本地研究，不做对外再分发。
5. 外部 Skill 的“评分”“情感”“红狐指数”“大 V 共识”一律先作为来源事实或研究辅助信号；只有经过点时、成本、样本外和结果追踪验证，才允许进入量化晋级候选。
6. 用户未主动启用时，RedFox 类 Key 能力不请求、不计费、不写本地状态；核心投研不能依赖这些可选源才能完成。

## 13. 开发阶段与任务拆解

### 阶段 A：合同和真实闭环

1. 修正 V6 报告、动作、交易计划和结果追踪 Schema。
2. 为 V6 创建不可变 outcome tracking。
3. 建立真实成功、失败、取消、重试的端到端测试。
4. 增加外部数据源注册表：Skill 名称、版本、许可证、密钥、数据源、允许用途、缓存策略、回退源和内容哈希。
5. 验收：固定 Evidence 能生成 V6；真实用户触发的 canary 至少成功一次；结果追踪文件存在且可复算；未登记的外部 Skill 不得进入生产数据链。
6. P0 语义完整性闭环：六 Agent 合同、workflow、提交入口和不可用摘要映射统一；负向合同测试先于真实 canary 通过。

### 阶段 B：量化验证框架

1. 周期化因子注册表。
2. 点时历史数据集和滚动验证器。
3. A 股交易成本、停牌、涨跌停和退市处理。
4. 将市场情绪、资金/筹码、题材映射和公众号舆论聚合定义为候选信号，不得默认进入 Alpha；建立信号版本、覆盖率、点时快照和结果追踪。
5. 校准晋级门槛与版本化结果。
6. 验收：无未来函数测试、成本复算测试、样本外分割测试、确定性重复运行测试全部通过；未通过门槛的策略和外部信号不能输出交易推荐。

### 阶段 C：方向、执行与仓位

1. 方向感知交易计划。
2. 真实交易日历和 A 股规则。
3. 滑点/容量代理。
4. 用户风险和组合约束。
5. 验收：看跌/回避不出现普通买入计划；T+1、涨跌停、停牌和流动性场景有固定测试；仓位可解释、可复算、不突破所有上限。

### 阶段 D：行业、政策、周期和估值

1. 周期门槛重构。
2. 行业适配估值模型，独立实现 DCF/FCFF 或现金流收益率、同行估值、历史估值和敏感性计算；不复制 `valuation-analysis` 受限代码。
3. 历史估值和盈利质量输入。
4. 将 `westock-data` 的行业经营、申万估值/盈利预测、宏观和财报能力接入受控适配器；保留现有源作为回退，字段/版本漂移必须降级。
5. 估值/政策/行业数据来源闭包。
6. 验收：中线缺行业周期不能输出可交易计划；长线缺财务/现金流/估值不能输出可交易计划；至少两类行业估值模型用真实 fixture 通过；估值结论在前端可见且不是“过程信息”。

### 阶段 E：六 Agent 与最终裁决

1. 保持 DAG，隔离多空过程。
2. 引入确定性决策资格和允许动作集合。
3. 主审分歧矩阵和可修复提交。
4. 验收：Agent 不能提交量化字段；硬门槛不能被语言覆盖；相同 Evidence 重跑的结构化动作集合稳定。
5. P0 语义验收：缺口来源、基础/派生边界、行业证据门槛、多空错误隔离和用户文本清洗全部有负向测试。

### 阶段 F：前端交付

1. 右侧雷达接入方向感知计划、校准和执行状态。
2. 投研页改为结论优先和 Agent 点击下钻。
3. 增加三项可感知结论：估值结论、市场情绪结论、市场舆论风向结论；题材催化只在对应场景出现，不把原始新闻或文章铺在雷达。
4. V6 结果追踪与方法说明。
5. 验收：无空白、无示例数据、无内部英文状态、无过程铺屏；三项结论都有真实/缓存/不可用状态和数据时点；320/336/420 像素宽度无截断；所有按钮符合 UI 规范。

### 阶段 F2：外部 Skill 受控接入与四项能力交付

1. WeStock：实现版本锁定、内容哈希、命令输出 Schema、字段单位校验、同日缓存和 EastMoney/公开源回退；先交付 `profile/asfund/chip/technical`，`quote` 未通过合同测试时不得宣称已接入。
2. 估值：在现有 `valuation.py` 上补齐可追溯的现金流估值、情景敏感性和行业适配方法；不引入用户手动上传 PDF 作为主流程前置。
3. 市场情绪：实现确定性市场状态汇总，使用市场宽度、成交额、指数/期货和经核验快讯；关键词情绪只作辅助，来源覆盖不足时输出“暂不判断”。
4. 题材映射：把 `ticai-lieshou` 的直接影响→二阶传导→A 股映射固化为 `theme_mapping` 合同，只在用户主动触发或选股事件模式下运行。
5. 红狐公众号/大 V：默认不启用 Key 能力；若用户主动配置并同意，隔离运行 `gzh-astock-top`，只导入聚合后的舆论方向和覆盖指标；`stock-analysis-redfox` 只保留可选观点参考，不能进入主审。
6. 验收：六类 Skill 均有“可接入/受限接入/不接入”的明确状态；所有允许接入能力有真实或固定 fixture；Key 缺失、许可未确认、版本漂移、数据源失败均不能污染 V6 结论。

### 阶段 G：最终验收

1. 后端相关测试、前端股票模块、类型检查和生产构建全部通过。
2. 使用固定历史数据跑可复现端到端验收。
3. 用户手动启动一次真实六 Agent canary；不得由对话自动触发。
4. 检查 V6 报告、右侧栏、投研页和 outcome tracking。
5. 逐项核对第 12A 节外部 Skill 接入合同和四项能力门槛。
6. 按第 14 节逐项签字；未通过任一 P0 项不得宣称“最佳实践完成”。

## 14. 最终验收矩阵

| 环节 | 通过标准 | 证据 |
| --- | --- | --- |
| 证据管理 | 点时、来源闭包、哈希、未来排除、不可变、主备差异可查 | 自动测试 + Evidence fixture |
| 六 Agent | 独立论证、分歧矩阵、硬门槛不可覆盖 | Workflow 合同测试 + Artifact 检查 |
| LLM 与量化隔离 | LLM 无法提交数值计划，最终字段系统注入 | Schema/Tool 负向测试 |
| 语义完整性 | 缺口不猜来源；基础指标与派生计划分开；无行业证据不确认周期；不可用摘要由系统生成；用户文本无内部语义 | 六 Agent 合同 + workflow + 提交入口负向测试 |
| 外部 Skill 接入 | 版本、内容哈希、许可、密钥、数据源、缓存、回退和字段合同可查；未登记能力不进生产链 | SkillHub/ClawHub 元数据 + 适配器合同测试 + 许可审计 |
| AI 选股 | 周期模型、样本外验证、成本、晋级状态 | Validation report + deterministic tests |

## 15. 完成定义

以下条件同时成立才算完成：

1. 所有 P0 验收项通过；
2. 至少一个 V6 真实运行成功并产生完整追踪快照；
3. 未校准模型不会向用户显示为已验证交易优势；
4. 看跌、回避、执行受限和数据门槛失败场景不会给出误导性买入计划；
5. 估值结论、市场情绪结论、市场舆论风向三项能力在前端有真实数据、缓存数据和不可用状态三类可验收表现；
6. 题材映射只在有来源、可解释、可失效的条件下进入选股/投研，不能越权生成价格和仓位；
7. 所有可接入外部 Skill 都有版本、许可、密钥、缓存和回退记录；受限或未确认的包不进入核心生产链；
8. 前端只展示用户需要的结论，完整依据可下钻；
9. 对本计划逐条复盘，明确已兑现、部分兑现和受免费数据限制未兑现的内容。
