# 文档任务的信息完整性与执行反馈

状态：实现、回归和构建已完成（2026-09-07）。

## 通用问题

- 通用工具输出压缩误把源材料和操作协议当作日志，头尾截取丢失中间信息；二次归一化还可能再次改变内容。
- Office 启动和能力发现需要多轮基础查询，断连错误没有明确指向原会话恢复。
- 布局警告没有进入交付前检查。复核发现错误事件已通过 error phase 记录；此前只统计 end phase 的分析有误，不修改正常事件链。

## 修复边界

1. 工具输出默认保真，仅做语义无损紧凑化。超预算保留全文引用，归一化必须幂等。
2. Office 打开回执包含当前 selection 与版本；能力查询可按具体操作过滤，未知目标明确报错。
3. PPT 新布局和警告进入版本绑定的待观察集合。完整页视觉观察后允许正常导出；显式草稿导出保留未审核状态，保存不受影响。观察不等于自动证明设计质量。
4. 三个文档 Skill 用必要的资料覆盖与领域验收原则约束交付，不规定特定题材、页数或模板。
5. 验证错误与成功事件的现有记录契约，统计时同时计入 end/error。

## 验证

- 用普通材料、JSON 协议、代码和 Unicode 文本验证多轮传递无损、超预算引用可恢复。
- 回归同会话恢复、按操作能力发现、layout review 的修改/观察/过期/删除边界。
- 相关 Python、编辑器与宿主测试、类型检查、构建。
- 不把确定性验证表述为自然语言模型成功率或 token 提升百分比。

## 已确认结果

- 真实失败日志的 document/read_file/三份 Skill 参考原始文本，经新归一化链重复处理后均逐字符相等；JSON 能力回执仅移除无意义空白，字段与值保留。
- 通用回归涵盖 360 行材料中部证据、JSON 所有行/嵌套字段/长小数、HTML/代码、Unicode，以及超预算全文引用的稳定性。
- Office 打开在启动的编辑器就绪后返回 selection；无可用 UI 通道或超时则保留同会话恢复信息，避免让模型自行循环等待。
- 正常导出版本绑定待观察页面；显式草稿导出保留未审核状态；旧版本视觉回执不能清除新版本待观察状态，会话恢复保留该集合。
- 错误日志原本完整存在：50 个 end 事件加 3 个 error 事件；本轮不改错误事件生产机制。
- 最终回归：156 项 Python、70 项编辑器、6 项宿主测试通过；入口契约测试、编辑器和宿主类型检查、Python Ruff、三个 Skill 校验及桌面编辑器资源构建通过。
- 源材料完整传递、正式导出门控、草稿标识与恢复状态已有确定性证据；实际模型的整体耗时、token 和语义覆盖仍需自然语言任务复测，不据此宣称普遍提升比例。
