# Codex 线上执行与共用余额验收（2026-11-06）

## 实现边界

工作台通过 Ubuntu 已登录的 Codex CLI `app-server` 复用桌面 `NativeWorkProvider` 和 `AgentRunner`；原生文件、命令及 MCP 工具不向模型开放，工作区操作经现有 Hosted 工具转到用户 gVisor 容器。模型、价格和凭据仍由工作台单独管理；Qwen 既有免费配置不变。

收费请求先持久记录身份和价格快照，再向独立 Auth sidecar 预留余额并标记派发。服务端收集每轮的真实输入、缓存输入和输出用量，结算按各分项分别向上取整。相同请求不会重派或重复扣款；缺失、倒退、重复旧回执或未确认终态不按零处理，保留待核对状态。工作台日志保存可恢复阶段和不可变用量；重启后仅安全释放确认未派发的预占或幂等重试已保存用量的结算，不重跑模型。

用户会话由原 Auth 实时验证，sidecar 另校验专用服务密钥；钱包和流水仍是原账户的共用数据。用户自行在管理页决定免费或共用余额，工作台不读取应用侧价表。当前 `/credits/usage` 不统计工作台请求，但钱包余额和账单流水包含实际扣款。Codex 会话标题暂使用用户首条消息，避免额外的未确认标题模型调用。
