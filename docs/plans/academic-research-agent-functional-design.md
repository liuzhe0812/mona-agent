# Mona 学术研究 Agent 功能方案

> 文档版本：1.0  
> 状态：待实现  
> 制定日期：2026-08-22  
> 适用范围：Agent Runtime、Agent Skills、科研工具、Artifact 交付  
> 产品边界：单 Agent、现有对话窗口、无独立科研工作台、无默认多 Agent Workflow

## 1. 文档目的

在不新增独立科研 UI 模块的前提下，为 Mona 增加一个可直接对话使用的“学术研究 Agent”，完整覆盖以下八项能力：

1. 领域调研、文献检索。
2. 论文阅读、证据提取。
3. 知识地图、多视角研究。
4. 选题、假设、实验设计。
5. 科研数据库和专业工具。
6. 数据分析、代码实验。
7. 自动提出并验证算法想法。
8. 论文、基金、评审回复。

“最小架构”只约束实现方式，不删减上述能力。最终交付必须通过第 10 节的八项能力验收和第 11 节的端到端验收，不能以“已配置 Skill”“模型理论上能做”代替可运行验证。

## 2. 产品结论

### 2.1 最终形态

用户从 Mona 现有 Agent/会话列表进入“学术研究员”直属会话，在普通对话窗口中提交研究问题、论文、数据、代码或写作材料。Agent 自动判断任务类型、调用相应 Skill 和工具，最终在对话中返回结论、引用和可预览文件。

```text
用户消息 / 附件
        ↓
学术研究员（单 Agent）
        ↓
研究证据 / 研究设计 / 研究执行 / 研究写作 Skills
        ↓
学术检索 + 科研工具 + 本地文件/代码/数据工具
        ↓
对话答案 + 可核验引用 + Artifact 文件
```

### 2.2 UI 边界

本方案不新增：

- `ShellView` 类型。
- 左侧“科研”模块入口。
- 科研项目首页或工作台。
- 文献库、证据表、知识图谱、实验面板等专用页面。
- 用户必须操作的显式 Workflow。

只复用：

- 现有 Agent 分组与直属会话入口。
- 现有消息流、附件上传和运行状态显示。
- `deliver_file` 生成的对话文件卡片。
- 现有文件预览、Markdown、Office、图片和 HTML 预览能力。

UI 验收标准是：八项能力均可仅通过对话和附件完成，且不修改 `webui/src/App.tsx` 的 `ShellView`、不增加侧栏模块或新的一级页面。

### 2.3 单 Agent 边界

- 默认 `canDelegate=false`，不依赖子 Agent 才能完成任何一项验收。
- 长任务使用现有 `long_task`/`complete_goal` 保存目标并支持恢复，不创建多 Agent 房间。
- 多轮检索、反方搜索、查漏和算法迭代是同一 Agent 内部循环。
- 后续只有在独立盲审或并行检索经过测量确有收益时，才另立多 Agent 需求。

## 3. 成功定义

最终交付同时满足以下四项才算完成：

1. **能力真实可用**：第 10 节八个黑盒验收场景全部通过。
2. **证据可核验**：每个关键事实均可回到真实来源；全文证据能定位到页码、章节、图表或原文片段。
3. **实验可复现**：数据、代码、命令、参数、环境、随机种子和指标均有记录；相同条件可重新运行。
4. **失败不造假**：无全文、无数据、无工具、基线失败或证据不足时，明确报告缺口，不生成伪引用、伪结果或伪验证。

## 4. 用户入口与任务识别

### 4.1 支持的输入

用户不需要选择功能模式，可直接提供：

- 一个领域或研究问题。
- DOI、PMID、arXiv ID、ClinicalTrials.gov ID 或网页链接。
- 一篇或多篇 PDF/Office/Markdown 论文与报告。
- CSV、TSV、JSON、JSONL、XLSX 数据。
- 一个本地代码目录或代码文件。
- 实验日志、图表或阶段性结果。
- 论文草稿、基金申请、审稿意见或回复草稿。

### 4.2 自动路由

Agent 根据任务选择最小必要路径：

| 用户意图 | 使用路径 |
|---|---|
| 查领域、找论文、找空白 | 研究证据 Skill |
| 读论文、查引用、比较观点 | 研究证据 Skill |
| 建知识地图、找冲突 | 研究证据 Skill |
| 选题、提出假设、设计实验 | 研究设计 Skill |
| 查科研数据库或运行专业工具 | 研究执行 Skill |
| 分析数据、执行代码 | 研究执行 Skill |
| 自动改进算法 | 研究执行 Skill 的算法实验循环 |
| 写论文、基金、回复审稿人 | 研究写作 Skill |

多个意图可以在一个会话中连续执行，不要求用户重新创建任务或切换页面。

## 5. 最小运行架构

### 5.1 Agent 包

新增一个可见 Agent 包：

```text
mona/agents/com.mona.academic-researcher/
  agent.json
  prompt.md
  skills/
    research-evidence/SKILL.md
    research-design/SKILL.md
    research-execution/SKILL.md
    research-writing/SKILL.md
```

建议定义：

```json
{
  "schemaVersion": 1,
  "id": "com.mona.academic-researcher",
  "displayName": "学术研究员",
  "description": "完成学术调研、证据综合、研究设计、数据与算法实验及科研写作",
  "prompt": "prompt.md",
  "model": "inherit",
  "canDelegate": false,
  "visibility": "partner",
  "skills": [
    "skills/research-evidence",
    "skills/research-design",
    "skills/research-execution",
    "skills/research-writing"
  ]
}
```

最终 `toolAllowlist` 只列实现时已注册且实际需要的工具，至少覆盖：

- 研究：`academic_search`、`web_search`、`web_fetch`、`http_request`。
- 阅读：`read_file`、`materials_read`、`knowledge_search`。
- 本地检索：`find_files`、`grep`。
- 记录与交付：`research_record`、`write_file`、`edit_file`、`deliver_file`。
- 数据与图表：`dataframe_query`、`chart`。
- 代码实验：`exec`、`apply_patch`。
- 专业工具：`scientific_tool`。
- 长任务：`long_task`、`complete_goal`。
- Skill 和记忆：`skill_read`、`memory_edit`。

不把所有浏览器操作和文件写入工具默认开放；只有验收表明 `web_fetch` 无法处理目标来源时，才补充只读浏览器工具。

### 5.2 四个 Skill

| Skill | 覆盖需求 | 强制规则 |
|---|---|---|
| `research-evidence` | 1、2、3 | 保存检索记录；去重；事实必须有来源；全文结论必须有定位；主动查找反证 |
| `research-design` | 4 | 先做新颖性检查；假设必须可证伪；方案必须包含对照、变量、终点、混杂与失败条件 |
| `research-execution` | 5、6、7 | 工具调用可追溯；代码必须实际运行；算法验证必须先有基线、指标和预算 |
| `research-writing` | 8 | 只使用证据账本中的事实；区分事实、推断和假设；不伪造引用；保留作者责任 |

外部 Skill 仓库只作为参考来源。优先挑选并改写 K-Dense `scientific-agent-skills` 中与上述四类职责直接相关的内容，不整库安装，不把第三方脚本默认设为可执行。

### 5.3 新增三个具体工具

为了让能力可测量，而不是只依赖提示词，新增三个工具；不引入第二套 Agent 框架。

#### `academic_search`

统一检索和规范化学术元数据，最小支持：

- OpenAlex：通用论文检索、作者、机构和引用关系。
- Crossref：DOI 与出版元数据核验。
- PubMed/Europe PMC：生物医学文献。
- arXiv：预印本。
- ClinicalTrials.gov：临床试验注册。

提供 `search`、`metadata`、`citations` 三类动作；返回统一字段：

```text
source_id、title、authors、published_at、venue、source_type、
doi、pmid、arxiv_id、nct_id、url、abstract、retrieved_at、provider
```

约束：

- 同一文献优先按 DOI/PMID/arXiv ID 去重，缺少标识时再使用规范化标题。
- 单个数据源失败不伪装为空结果，必须返回失败来源和原因。
- 结果区分同行评审论文、预印本、试验注册、指南和普通网页。
- API 返回内容保持原始数据，不让模型补写缺失作者、日期或标识。

#### `scientific_tool`

为 ToolUniverse 等科研工具提供一个固定、可被 Agent 包允许的入口，避免把大量动态 MCP 工具直接写进静态 `toolAllowlist`。

只提供四个动作：

```text
discover → inspect → run → status
```

约束：

- 默认使用紧凑发现模式，不把全部工具说明注入上下文。
- 每次执行记录工具 ID、版本、参数、数据来源、时间和原始状态。
- 未配置 ToolUniverse 或目标工具不可用时返回 `unavailable`，Agent 不得模拟结果。
- 涉及外部写入、付费调用、患者数据或高风险计算时沿用 Mona 权限和确认机制。
- 实现前审查 ToolUniverse 及被调用数据库/软件的许可证；不能因 ToolUniverse 本身许可宽松而假设所有下游资源可商用。

#### `research_record`

将来源、证据、实验和交付物写入当前会话工作区的结构化 JSONL/JSON Artifact，并在写入时做字段校验。

最小记录类型：

```text
SourceRecord      来源元数据
EvidenceClaim     结论及原文证据
ExperimentRun     基线、候选、命令、指标和结果
DeliverableRecord 论文、基金、报告或回复文件
```

该工具只负责校验、追加和导出，不负责搜索、推理或生成内容。这样既避免新建科研数据库，也避免模型直接编辑一个大型 JSON 文件造成损坏。

### 5.4 直接复用的 Mona 能力

| 能力 | 现有实现 | 用途 |
|---|---|---|
| 普通对话与附件 | `ThreadShell` | 唯一用户入口 |
| Agent 包与专属 Skill | `AgentDefinition`、`SkillsLoader` | 加载学术研究员及四个 Skill |
| 长目标 | `long_task`、`complete_goal` | 长时间调研、实验和恢复 |
| 网页检索与读取 | `web_search`、`web_fetch`、`http_request` | 补充学术 API 与读取全文网页 |
| 本地材料 | `materials_read`、`knowledge_search`、`read_file` | 阅读上传论文和用户资料 |
| 表格分析 | `dataframe_query` | CSV/TSV/JSON/JSONL/XLSX 的只读查询 |
| 图表 | `chart` | 生成分析图表 |
| 代码运行 | `exec`、`apply_patch` | 数据脚本和算法实验 |
| Artifact | `ArtifactRef`、`deliver_file` | 在对话中交付报告、证据、图表和代码 |
| 记忆 | Agent 私有 Memory | 保存稳定偏好和方法，不保存未经整理的完整论文正文 |

### 5.5 不引入的依赖

- 不引入 LangGraph、GPT Researcher 或 Open Deep Research 作为第二套运行时。
- 不复制 STORM 的 UI 或服务端。
- 不直接运行 AI Scientist、RD-Agent 或 Agent Laboratory 的整套系统。
- PaperQA2 不是首个强制依赖；先用 Mona 现有 PDF 能力参加第 10.2 节验收，未通过页码、表格或复杂版式验收时，再以可选适配器补入 PaperQA2。是否加入由验收结果决定。

## 6. 研究记录与交付约定

### 6.1 会话内目录

每个深度研究任务在当前会话工作区下创建一个独立目录：

```text
research/<task_id>/
  manifest.json
  search_log.jsonl
  sources.jsonl
  claims.jsonl
  knowledge_map.json
  knowledge_map.md
  experiments/
    <run_id>/
      run.json
      stdout.txt
      stderr.txt
      change.patch
      metrics.json
  deliverables/
```

`task_id` 由系统生成并校验，不从用户文本直接拼接路径。

中间文件留在任务目录，只有用户需要查看的报告、知识地图、数据结果、图表、代码补丁和写作成果通过 `deliver_file` 显示在对话中。

### 6.2 证据声明

每条 `EvidenceClaim` 至少包含：

```text
claim_id
claim_type: fact | inference | hypothesis
claim_text
source_ids
evidence_text
locator: 页码 / 章节 / 图表 / 表格 / 网页段落
supports: support | conflict | context
limitations
verified_at
```

规则：

- `fact` 必须有至少一个真实 `source_id` 和可核验定位。
- `inference` 必须有来源和明确推理依据。
- `hypothesis` 必须标记待验证，不得写成已有事实。
- 只有摘要时，定位必须标为 `abstract`，不得伪装为全文核验。
- 找不到全文、页码或原文时，对应字段为空并记录 `missing_reason`，不能生成近似引文。

### 6.3 来源优先级

同一问题存在多个来源时，按以下顺序核验：

1. 原始论文、正式指南、试验注册、官方数据库和公开数据。
2. 系统综述、Meta 分析和高质量综述。
3. 机构报告或可信二手资料。
4. 普通网页只用于发现线索，不独立支撑关键学术结论。

引用数量不等于证据强度；冲突证据必须保留，不能按多数票自动裁决。

## 7. 八项能力功能流程

### 7.1 领域调研、文献检索

最小流程：

```text
明确问题与范围 → 生成检索词 → 查询适用学术源
→ 去重 → 阅读摘要/全文 → 查找反证和缺口 → 综合输出
```

必须产出：检索范围、检索式、数据源、检索时间、来源清单、主要观点、争议、证据缺口和未能获取的资料。

### 7.2 论文阅读、证据提取

对单篇或多篇论文提取：研究问题、研究设计、样本/数据、方法、主要结果、统计口径、作者结论、局限和可复现信息。

关键结论必须形成 `EvidenceClaim`；不能只生成一段论文摘要。

### 7.3 知识地图、多视角研究

知识地图不需要专用 UI，交付 `knowledge_map.json` 和可预览的 `knowledge_map.md`。最小节点：论文、概念、方法、数据集、假设；最小关系：支持、冲突、使用、扩展、研究缺口。

多视角研究至少覆盖：支持证据、反对证据、方法差异、适用边界和仍未解决的问题。没有反方证据时必须说明检索范围，不能虚构反方观点。

### 7.4 选题、假设、实验设计

在提出选题前先检查相近论文、预印本和注册研究。每个候选方向必须包含：

- 研究问题和价值。
- 已有证据及真实缺口。
- 可证伪假设与替代解释。
- 自变量、因变量、控制变量和混杂因素。
- 对照、样本/数据需求、主要终点和评价指标。
- 确认条件、否证条件、失败模式、资源与伦理风险。

Agent 只生成设计建议；涉及患者、动物、危险实验或正式统计方案时必须要求专业人员和伦理流程确认。

### 7.5 科研数据库和专业工具

先通过 `scientific_tool.discover` 查找工具，再 `inspect` 参数和限制，最后 `run`。禁止仅凭工具名称猜测参数。

结果必须保留：工具和数据库名称、版本、输入参数、数据更新时间、原始状态和引用要求。

### 7.6 数据分析、代码实验

分析前记录数据文件、字段、缺失值和目标。简单表格查询优先使用现有 `dataframe_query`；需要统计、机器学习或领域软件时才生成脚本并通过 `exec` 实际运行。

每次代码实验必须保存：

- 输入数据及哈希或版本。
- 代码或补丁。
- 完整命令、工作目录和退出码。
- 依赖版本、随机种子和参数。
- 标准输出、错误输出、指标和生成文件。

不允许把“代码看起来正确”写成“实验已验证”。

### 7.7 自动提出并验证算法想法

该能力只在以下条件齐全时启动：

- 可运行的代码或明确算法实现位置。
- 固定数据集或测试集。
- 能成功运行的基线命令。
- 唯一主指标、优化方向和比较规则。
- 最大迭代次数、最长时间或费用预算。

最小循环：

```text
运行并锁定基线
→ 基于证据提出一个候选改进
→ 在隔离实验目录生成补丁
→ 执行同一评价命令
→ 比较同一主指标
→ 记录保留/否决及原因
→ 未耗尽预算时继续下一候选
```

安全规则：

- 默认不直接覆盖用户原始代码；候选修改在独立实验副本或临时 Git 工作树中运行。
- 获胜补丁作为 Artifact 交付，只有用户明确要求时才应用到原项目。
- 基线失败、指标无法解析或评价数据变化时立即停止验证循环。
- 没有候选超过基线时，正确结论是“本轮无改进”，不能选择最像成功的结果。
- 测试集不得用于训练或提示驱动调参；需要时分离开发集和最终评价集。

### 7.8 论文、基金、评审回复

写作必须以当前资料和 `EvidenceClaim` 为事实边界，支持：

- 论文大纲、引言、相关工作、方法、结果、讨论和局限初稿。
- 基金立项依据、研究目标、技术路线、创新点、风险和摘要初稿。
- 审稿意见拆分、证据查找、修改建议和逐条回复初稿。

输出要求：

- 引用必须能解析到 `SourceRecord`。
- 未经证据支持的内容只能作为建议或假设。
- 不替用户声明不存在的实验、伦理批准、数据可用性或利益冲突。
- AI 不列为作者；最终内容由研究者审阅和承担责任。

## 8. 失败与降级行为

| 情况 | 必须行为 | 禁止行为 |
|---|---|---|
| 学术源不可用 | 报告失败来源，继续其他来源 | 把失败写成“无相关研究” |
| 无法获取全文 | 只基于摘要并明确标记 | 编造页码、原文或方法细节 |
| 来源结论冲突 | 并列证据并解释口径差异 | 以引用数量自动投票 |
| 专业工具未配置 | 返回 `unavailable` 和配置缺口 | 模拟工具输出 |
| 数据字段缺失 | 停止对应分析或缩小结论 | 猜测或填补真实数据 |
| 代码运行失败 | 保存命令、退出码和错误 | 把未运行代码描述成结果 |
| 基线失败 | 停止算法自动验证 | 跳过基线直接宣称改进 |
| 指标不明确 | 请求确定主指标和优化方向 | 自行选择对用户有利的指标 |
| 证据不足 | 输出 `insufficient_evidence` 和缺口 | 用概率词掩盖缺失 |
| 医疗敏感数据 | 禁止发送外部服务，要求脱敏与授权 | 上传可识别患者数据 |

## 9. 安全、隐私与科研诚信

### 9.1 文件和代码

- 学术研究员的工具访问默认限制到当前会话绑定工作区。
- 自动实验只在隔离目录执行，不删除或覆盖原始数据。
- 外部仓库、共享索引和序列化缓存视为不可信输入；禁止加载来源不明的可执行对象。
- 依赖安装、外部程序和大规模计算遵循 Mona 现有权限与确认策略。

### 9.2 医院和生物医学

- 产品定位是科研辅助，不提供患者个体诊断或治疗决定。
- 可识别病历、影像、基因和受试者信息不得发送到公共模型、搜索服务或第三方 MCP。
- 涉及患者、动物、临床试验、危险生物材料或受管制数据时，结果必须包含伦理、隐私和专业审核提示。

### 9.3 科研诚信

- 禁止虚构文献、数据、实验、统计结果、伦理批准或审稿意见处理结果。
- 生成的原文引句必须由工具返回并可在来源中找到。
- 事实、推断、假设和建议保持不同类型，不得互相冒充。
- Agent 对研究者负责提供过程记录，但不能成为作者或责任主体。

## 10. 分能力验收标准

所有验收均从“学术研究员”的普通对话发起，不通过开发者直接调用内部函数来代替。验收夹具和预期结果必须随代码进入测试目录，外部服务测试允许使用录制响应，但上线前必须再执行一次真实连通性检查。

### 10.1 能力一：领域调研、文献检索

**夹具**：准备计算机科学、生物医学和一个非医学自然科学主题，各自指定一组可公开核验的目标论文与标识符。

**通过标准**：

- [ ] Agent 自动选择至少两个适用学术数据源；只有一个数据源适用时说明原因。
- [ ] 每个夹具中的目标论文均被检索到，DOI/PMID/arXiv ID 与预期一致。
- [ ] 同一论文的多来源记录被合并，未出现重复结论计数。
- [ ] 交付 `search_log.jsonl` 和 `sources.jsonl`，记录查询、来源、时间、结果及失败。
- [ ] 最终回答包含研究现状、主要路线、争议、空白和检索边界。
- [ ] 抽查的全部引用均可解析到真实来源；出现一个虚构来源即整项失败。

### 10.2 能力二：论文阅读、证据提取

**夹具**：至少三篇固定 PDF，预先标注研究问题、方法、样本/数据、主要结果、局限及其页码或章节；其中一篇包含表格或图表。

**通过标准**：

- [ ] 每篇论文均输出结构化阅读结果，不只输出摘要。
- [ ] 预标注关键证据全部形成 `EvidenceClaim`。
- [ ] 每条全文证据都包含正确页码、章节、图表或表格定位。
- [ ] `evidence_text` 可在原文对应位置找到；出现模型生成的伪引文即失败。
- [ ] 作者事实、作者推断和 Agent 推断被明确区分。
- [ ] 无法解析的图表或版式明确标记为未确认，不猜测数值。
- [ ] 若 Mona 现有解析器不能满足上述要求，必须加入并验证 PaperQA2 或等效适配器后才能通过。

### 10.3 能力三：知识地图、多视角研究

**夹具**：准备一组包含支持、冲突、方法继承和研究缺口关系的固定论文集合。

**通过标准**：

- [ ] 生成 `knowledge_map.json` 和可在现有文件预览中打开的 `knowledge_map.md`。
- [ ] 节点至少支持论文、概念、方法、数据集和假设。
- [ ] 夹具中存在的支持、冲突、使用、扩展、缺口关系均能表达。
- [ ] 每条关系都携带 `source_ids`，并可回溯到证据声明。
- [ ] 输出同时呈现支持观点、反对观点、方法差异、适用边界和开放问题。
- [ ] 不为追求“多视角”生成没有来源的虚假观点。

### 10.4 能力四：选题、假设、实验设计

**夹具**：分别提供一个文献缺口、一个异常数据现象和一个已有方法迁移问题。

**通过标准**：

- [ ] 每个候选选题先给出相近工作的检索结果和差异。
- [ ] 每个假设均包含理论/证据依据、替代解释、确认条件和否证条件。
- [ ] 每个实验方案包含变量、对照、样本/数据、主要终点、评价指标、混杂因素和失败模式。
- [ ] 所有必填项有真实内容或明确缺失原因，不用空泛文字占位。
- [ ] 生物医学夹具包含伦理、隐私和专业审核边界。
- [ ] 方案不包含虚构的可用数据、设备、样本量或既有结果。

### 10.5 能力五：科研数据库和专业工具

**夹具**：一个学术索引查询、一个生物医学数据库查询和一个可确定性执行的科研计算工具。

**通过标准**：

- [ ] Agent 能完成 `discover → inspect → run`，不依赖用户提供内部工具名。
- [ ] 输出包含工具/数据库名称、版本、参数、数据时间和来源。
- [ ] 原始返回与 Agent 总结可对照，关键字段没有被改写。
- [ ] 工具不可用时返回真实 `unavailable`，并给出缺少的配置，不产生替代结果。
- [ ] 至少一次通过 ToolUniverse 或经批准的等效专业工具实际执行成功。
- [ ] 许可证和引用要求已记录；不满足许可的工具不进入发布配置。

### 10.6 能力六：数据分析、代码实验

**夹具**：准备 CSV/JSON/XLSX 表格数据和一个小型 Python 分析项目，预先定义可验证结果。

**通过标准**：

- [ ] Agent 先检查字段、类型、缺失和分析目标，再运行分析。
- [ ] CSV/JSON/XLSX 均能完成至少一次真实查询或分析。
- [ ] Python 代码实际执行且退出码为 0；失败时不报告成功结果。
- [ ] 交付代码、命令、参数、依赖版本、随机种子、日志、指标和生成文件。
- [ ] 在相同输入和环境下重跑，关键结果与预期一致；浮点结果使用夹具定义的容差。
- [ ] 原始数据保持不变，输出写入独立实验目录。

### 10.7 能力七：自动提出并验证算法想法

**夹具**：提供一个可在限定时间内运行的小型算法项目，包含固定开发集、最终测试集、基线命令、唯一主指标、优化方向和最多两次候选预算。

**通过标准**：

- [ ] Agent 首先执行基线并记录真实指标；基线失败时正确停止。
- [ ] 至少提出并实际运行一个有依据的候选改进，不能只给建议。
- [ ] 候选与基线使用同一数据、命令口径和主指标。
- [ ] 每次候选均保存研究依据、补丁、命令、日志、指标和保留/否决理由。
- [ ] 严格遵守迭代、时间或费用预算。
- [ ] 只有主指标按预设方向优于基线时才声明改进；没有改进时如实返回“本轮无改进”。
- [ ] 原始项目未被自动覆盖；获胜补丁作为 Artifact 交付。
- [ ] 最终测试集没有用于候选生成或开发阶段调参。

### 10.8 能力八：论文、基金、评审回复

**夹具**：提供固定证据账本、论文模板、基金要求和一组编号审稿意见。

**通过标准**：

- [ ] 生成论文核心章节初稿，事实性陈述均能追溯到 `source_ids` 或实验记录。
- [ ] 生成基金摘要、研究目标、技术路线、创新点、风险和替代方案。
- [ ] 审稿回复逐条对应原评论，明确“修改/解释/补实验/不同意”及依据。
- [ ] 引用均存在于 `sources.jsonl`，引用元数据可解析。
- [ ] 不声明夹具中不存在的实验、数据、伦理审批或修改动作。
- [ ] 交付 Markdown；需要 DOCX 时复用现有文档能力生成并可预览。

## 11. 跨能力端到端验收

### 11.1 高校计算研究场景

用户提供一个研究主题、三篇种子论文、一个数据集和一个算法代码目录，并要求：调研领域、寻找空白、提出一个算法改进、在固定指标上验证并生成论文初稿。

通过条件：

- [ ] 连续完成能力 1、2、3、4、6、7、8，无需切换 Agent 或页面。
- [ ] 论文初稿中的关键事实链接到文献证据，实验结论链接到真实运行记录。
- [ ] 算法没有提高时仍能完成可信的负结果讨论，而不是伪造改进。
- [ ] 中断会话后能够从 `manifest.json` 和现有 long goal 恢复，不重复覆盖已有实验。

### 11.2 医院科研场景

用户提供一个临床科研问题和若干公开论文，要求调查已有证据、临床试验、研究缺口，并形成回顾性研究方案和基金初稿。

通过条件：

- [ ] 连续完成能力 1、2、3、4、5、8。
- [ ] PubMed/Europe PMC 和 ClinicalTrials.gov 的来源可核验。
- [ ] 研究方案包含人群、纳排标准、变量、终点、混杂因素、伦理和隐私边界。
- [ ] 不输出患者个体诊疗建议，不上传可识别数据。
- [ ] 基金初稿的事实与研究设计均能回溯到证据或明确标记为拟议方案。

### 11.3 对话式交付场景

通过条件：

- [ ] 上述两个场景都只通过现有聊天、附件和文件卡片完成。
- [ ] 不出现新的科研工作台、侧栏模块或必须操作的流程页面。
- [ ] 用户最终能直接预览或下载来源清单、证据表、知识地图、实验记录和写作成果。

## 13. 实施顺序

实施按依赖关系分四段，但任何一段都不是可删减的最终范围：

1. **研究证据闭环**：Agent 包、`academic_search`、`research_record`、`research-evidence`，通过能力 1—3。
2. **研究设计与专业工具**：`research-design`、`scientific_tool`，通过能力 4—5。
3. **数据和算法实验**：`research-execution`、隔离实验目录和运行记录，通过能力 6—7。
4. **科研写作与总验收**：`research-writing`，通过能力 8 和两个端到端场景。

每段完成后运行相关验收；第四段结束前不能把学术研究员标记为完整交付。
