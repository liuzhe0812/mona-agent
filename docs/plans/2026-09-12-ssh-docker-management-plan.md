# SSH Docker 管理开发计划

- 日期：2026-09-12
- 状态：代码实现及六项正确性收口完成；真实 SSH/Docker 与 macOS 冒烟验收待执行
- 修订：范围收敛版，额外能力后置，测试按风险分层并复用阶段结果
- 功能依据：[SSH 会话内 Docker 管理方案](../design/2026-09-12-ssh-docker-management-design.md)
- 范围：终端当前 SSH 会话的 Docker 派生 Tab；覆盖方案 F1–F5

## 1. 交付目标

用户通过现有 SSH 连接，在终端标签栏打开“Docker · 主机名”，完成运行状态查看、容器排障、安全操作、Compose 配置与单项目更新、事件查看及精确清理。关闭 Docker Tab 不断开 SSH；SSH 断开时所有操作停止提交，结果不确定的变更必须复检。

实施使用隔离 SSH/Docker 测试环境，生产部署和产品发布另按明确请求执行。开始每阶段先检查工作树，尤其标签、SSH 与维护执行相关共享文件，不覆盖其他任务的修改。本期通过 Tauri/SSH 接入，不预设 Python/schema 改造。

### 2.1 已完成实现

- SSH 派生 Docker Tab、按父会话去重和关闭、断连状态同步及订阅清理。
- Docker/context/socket/权限/Compose 探测；容器列表、指标、脱敏详情、最近与实时日志。
- 容器启停、重启、删除、独立交互终端；真实退出码、审批、复检和维护记录。
- Compose 项目发现、单文件关联持久化、原文编辑、校验、hash 冲突保护、原子保存、pull/up/stop/restart/recreate/down 和事件流。
- 镜像与卷列表、Docker 空间统计、registry digest 更新检查、单资源引用复查与精确删除。
- 输出上限、参数引用、非本机 context 拒绝、引擎身份复核、同会话变更互斥；修复结构化维护审批可能重复执行命令的问题。
- Compose 按动作等待并复检真实容器状态；维护检查步骤实际执行；Docker 变更接入维护取消信号。
- 重连按连接中→已连接转换并以连接代次屏蔽迟到断线；复杂 Compose 只读且 `.env` 版本参与确认；隐藏 Docker 标签停止轮询和流订阅。

- [ ] 实现容器筛选、运行与异常统计、资源状态、端口/挂载/网络/环境变量摘要和脱敏 Inspect。
- [ ] 接入共享 UI、i18n；复用现有超时，内部限额用后端常量，不新增设置或跨进程配置同步。
- [ ] 验证直连权限、rootless 与 `sudo -n` 的目标探测；需密码/TTY 明确显示限制，未验证的变体不宣称支持。

## 5. M2：流、PTY 与安全变更

- [ ] 在现有结构化 SSH 执行基础上补齐有界 stdout/stderr、任务/订阅 ID 和有序事件；避免长日志无限积累。
- [ ] 分块回调补充 stdout/stderr 来源，Docker 输出按任务或订阅路由；不新增 Python Bridge 接口。
- [ ] 实现最近/实时日志、时间筛选、暂停滚动、退订与缺口显示；关闭或切离资源释放流。
- [ ] 在现有连接新开容器 PTY，处理 bash/sh 探测、resize、退出与无 shell；父交互终端独立。
- [ ] 接入容器启动/停止/重启/删除，复用执行与记录能力；后端自动完成最小操作和复检，用户不需要填写或审批多步骤计划。
- [ ] 实现 Docker 业务风险判定和后端审批绑定；与现有计划审批统一，复用同一审批回执，避免同一动作重复确认。
- [ ] 复用每会话活跃维护任务限制与请求去重，执行前复查目标；不建立跨会话资源锁。
- [ ] 实现操作后 inspect 复检；取消、超时、无退出码和断连结果未知不标成功、不自动重试。
- [ ] Docker 类型化入口覆盖危险操作确认；既有 AI 执行仍沿用原审批和复检，不开展通用 Shell 风险规则改造。
- [ ] 只保存允许的维护摘要；原始日志、命令和凭据不进入持久历史。

出口：用户能从失败容器看日志并安全恢复；拒绝审批不会执行；模拟断连后重新连接只复检、不重复停止/删除；关闭 Docker 页的有限时任务仍能查到结果。

## 6. M3：Compose 项目管理

- [ ] 发现部署项目并合并 labels；关联一个远程 Compose 文件，保存项目名、工作目录与路径，沿用已有 `.env`。
- [ ] 区分“运行项目已发现”“文件已关联”“只读/缺失依赖”；全量 down 后可从原关联重新打开。
- [x] 原文编辑与脱敏预览分开；保持相对路径。同目录 `.env` 进入输入版本；build、env_file、多文件、profiles、include/extends 等复杂项目只读，禁止丢弃参数后部署。
- [ ] 用远端 Compose config 校验单文件草稿；实现 hash 冲突检查、同目录临时文件、原子替换与权限保持；保存失败禁止部署。
- [ ] 展示配置差异、受影响服务、停机提示和明显风险字段；不另建 Compose 解析器或完整部署推演系统。
- [ ] 实现 pull、up、stop、restart、force-recreate、down，统一进度与任务查询；默认不 build、不删除卷、不删除 orphan。
- [ ] 展示 pull 结果并确认重建；up 禁止隐式 build/再次 pull，记录实际运行镜像。避免多轮审批，不生成 digest 锁定文件或发布版本体系。
- [ ] 实现 healthy/running/预期一次性退出复检；应用健康未配置时不报告健康通过。
- [ ] 验证拉取失败不重建、配置外部修改阻止覆盖、up 部分失败显示真实服务状态；不自动 rollback。
- [ ] 失败详情提供状态与日志，用户可返回原终端排障；不新增自动摘要转发或 Docker AI 接口。

出口：一个单 Compose 文件、含 Web 与数据库服务的项目完成“读原文件 → 编辑 → 校验 → 影响确认 → 更新 → 复检”；命名卷数据保留，down 不删除 YAML/卷。相对路径、环境文件与保存边界在此阶段验证，复用为最终验收证据。

### 8.2 验证方法

上表是需求覆盖清单，不要求每一行都建立独立测试套件或在每个平台重跑；一个真实流程可覆盖多行。

1. 单元与契约层：针对新增的参数引用、解析、目标绑定、审批、状态转换、文件冲突与空间/digest 口径测试。前端验证标签、退订、IPC 参数及错误状态；同一逻辑不在每层重复穷举。
2. 真实行为层：在一个隔离 SSH/Docker 环境、一个主桌面平台跑完整 F1–F5 流程，重点确认真实退出码、服务状态和数据保留。拒绝审批、执行失败、断连和保存冲突各选代表失败路径；其余可控分支用单元/契约测试。
3. 兼容性层：另一桌面平台做一次冒烟；rootless、sudo 等按支持声明补必要证据。无法验证的平台明确待验证，不以主平台结果冒充通过，也不阻止主平台阶段交付。
4. UI 层：代表组合覆盖两种主题、三档窗口、中文英文和键盘操作，不做全排列；已复用的共享组件无需重做完整测试。原模块只回归受改动影响的行为。
5. 构建层：每阶段运行相关测试和必要编译检查；M5 在最新代码上完成主平台相关测试及目标桌面构建，另一平台冒烟使用可运行产物。完整 build 若包含 Office 子构建，记录其独立失败，不为 Docker 任务扩展 Office 修复/测试。
6. Python 本期无计划改动；实际确需修改工具/schema 时才追加对应 pytest 与 `ruff check`，不批量格式化。

停止条件：相关检查通过且没有未解决故障即停止扩测。阶段证据附代码版本，最终验收直接引用未受后续改动影响的结果；只有新改动、失败或明确依赖影响才重跑。不能为了填满矩阵反复运行同一命令，也不能用匹配到零测试的命令作证据。

可用命令入口为 `npm --prefix webui run test -- <实际测试文件>`、`npm --prefix webui run check:ui`、`npm --prefix webui run build:tauri`、`cargo test --manifest-path src-tauri/Cargo.toml <实际过滤器>` 和 `cargo check --manifest-path src-tauri/Cargo.toml`。测试文件与过滤器在实现后确认，不能使用匹配到零测试的命令作为通过证据。
