# Mona 会话历史与记忆改进计划（无向量检索）

- 日期：2026-09-14
- 状态：首期已实施并通过确定性回归；真实用户样本与性能门槛待发布验证
- 目标：同一 Agent 在新会话或上下文压缩后，能够查找、核对并引用以前聊过的内容。
- 明确约束：不引入向量库、embedding、语义重排模型或图数据库；不把聊天自动导入用户 Notes 或 Agent Knowledge。
- 范围：先完成桌面普通直聊的可见聊天正文检索；原始工具协议、隐藏任务和跨 Agent 共享不在本期范围。

## 1. 决策与验收结果

优先复用已有 WebUI transcript 作为桌面聊天正文来源，补齐稳定引用、文本索引和按需读取。保留现有会话回放与累积交接摘要，不创建第二份全量聊天档案，也不重写 Agent 核心循环。

2026-09-14 首期执行结果：新增 transcript 稳定事件 ID/落盘时间、按工作区和 Agent 隔离的 FTS5 索引、`conversation_search`/`conversation_read` 工具、memory Skill 调用规则、删除同步失效以及相关测试。工具默认启用；首期覆盖当前工作区的桌面普通直聊。交接摘要的程序化原文范围引用、全渠道覆盖、30 题真实模型样本和 10 万条性能门槛尚未完成，不在本次结果中宣称通过。

完成后的用户体验：在 A 会话说明一个项目的约束，在同一 Agent 的 B 会话问“之前那个项目的约束是什么”，AI 能搜索到 A 的记录，读取相邻问答后给出有来源的回答。A 超过 2000 条 Session 消息、经历上下文压缩或应用重启，不应让已成功保存的桌面聊天正文失去检索能力。

“原文可恢复”和“模型回答准确”分别验收。摘要不承诺无损，文件存在也不代表模型已经读到；已经被旧版本删除、截断或未落盘的内容不能补造。

## 2. 当前事实与需要纠正的判断

以下基于本地工作树当前实现检查，不代表已安装客户端的实际版本或本机全部历史完整性。

| 数据层 | 当前行为 | 本计划处理 |
|---|---|---|
| 活动 Session | `SessionManager` 保存工作区 `sessions/*.jsonl`；元数据与消息通过临时文件原子替换。正常回放默认最多 120 条消息，受 token 预算限制 | 保留活动上下文职责 |
| Session 文件上限 | 主循环轮末调用 `enforce_file_cap`，最多保留 2000 条消息；包含助手、工具消息，不是 2000 轮问答 | 保留上限，不让它决定独立正文来源的保留长度 |
| 交接摘要 | `Consolidator` 合并上一份摘要与新归档消息，保存 `_last_summary`；摘要有长度限制 | 增加可验证的原文引用，不另建多级摘要 |
| Agent 历史 | `memory/history.jsonl` 包含压缩摘要、任务记录，以及当前代码中的每轮问答简短摘录；摘录分别限制用户和助手文本长度 | 继续作为 Dream 的学习信号，不认作完整原文 |
| Dream | 更新 Agent 私有记忆；`compact_history` 默认只保留最近 1000 条历史记录 | 不用 Dream 的游标和历史清理控制聊天正文索引 |
| 桌面展示日志 | `get_webui_dir()/safe_key(session_key).jsonl`，即当前实例数据目录下的 `webui/*.jsonl`；逐事件追加、flush/fsync，无 Session 的 2000 条上限 | 优先复用为桌面可见正文来源 |
| 展示日志限制 | 保存流式事件及最终消息；工具轨迹有裁剪，单行超过 8 MiB 会拒绝写入；并非所有渠道都有此记录 | 明确可用覆盖，不宣称完整工具日志或全渠道无损 |
| 历史搜索 | 现有 `memory_search` 只搜索 Agent 的 `history.jsonl`，按正则/字面量匹配；结果按文件顺序读取并截取头部预览 | 保留原接口，新增明确的聊天搜索与读取能力 |

因此，“Session 删除早期消息，所有聊天原文必然永久丢失”不成立：桌面展示日志可能仍保留正文。“只要把摘要存成 note 就能不丢细节”同样不成立。

另一个限制：当前 transcript 回放生成的 UI 消息 ID 带随机值，部分展示时间来自回放时刻；`sourceTranscriptIndex` 也不是完整的永久引用契约。不能直接用这些字段当历史事实的稳定 ID 或真实发生时间。

## 3. 最小数据方案

### 3.1 来源与覆盖

- 首期只接入能够从可信会话元数据确认归属、且非临时/非隐藏的桌面普通直聊。Mona 与伙伴直聊按各自 Agent 隔离。
- 同一 Agent 的可授权直聊可跨会话查询；跨工作区范围由运行时已授权会话集合决定，不能扫描任意用户目录。工作区筛选只缩小范围。
- 协作房间、隐藏执行房间、临时会话、Job/Workflow 内部过程和其他渠道不自动加入首期跨会话检索。后续接入必须单独验证归属和完整性。
- transcript 是正文事实源；索引是可删除、可重建的派生数据。索引不能成为原文被删除后的备用事实源。
- 不把现有 `history.jsonl` 的摘要伪装成缺失的聊天原文。旧数据无 transcript 时标记为覆盖缺失；需要时仍可使用既有记忆工具，但必须注明是摘要。
- 原始工具输出、推理轨迹、运行时提示、内联二进制不进入普通聊天搜索。附件只保留来源引用；读取附件仍经过原有权限与文件接口。

### 3.2 正文投影和稳定引用

在 `mona/session/` 增加小型、可独立测试的历史来源适配模块，复用现有流式消息合并规则的最小必要部分。不能把随机 UI ID 或每次重放生成的时间戳保存为历史事实。

索引的逻辑单位是可见消息，字段至少包括：

- `ref`：服务端生成的不透明引用。
- 可信会话 ID、所属 Agent、角色、会话标题、任务 ID（存在时）。
- 原始事件定位范围、来源版本与内容校验值。
- 正文、真实时间（有证据才填写）、完成状态、覆盖状态。

新写入事件补充持久事件 ID 和真实时间，同一消息的流式片段与最终回复关联到同一个逻辑消息。重试、重连不得形成两份问答；失败或取消后只有部分文字时明确标为未完成，不能当作最终结论。

旧日志无需批量改写。引用由会话、原始文件位置及内容校验构成稳定来源描述，由适配层解析；不得依赖跳过坏行后的数组下标。未知时间返回空值，不以文件修改时间或回放时间推定某条消息日期。

日志追加不改变已完成消息的引用；日志替换、分支、删除需检测来源变化。无法验证旧引用时明确返回失效，不静默指向另一条消息。分支使用新会话身份，不能凭相同正文串联不同 Agent 的历史。

### 3.3 写入与缺口

- 已确认持久化的可见正文才可索引；流式记录在消息完成后合并索引，未完成部分按单独状态处理。
- 按原始文件读取游标增量处理，只提交完整 JSONL 行。索引提交失败不推进游标；重复处理保持幂等。
- 来源出现坏行、写入失败或未支持格式时报告 `partial`/`unavailable`，区分“没有匹配”和“未查完整”。不要沿用读取错误返回空列表所产生的误导。
- 第一阶段验证 Session 超过 2000 条时 transcript 的已持久正文仍存在；不把一次验证推广成旧版本全部数据完整的保证。
- 若发现桌面某条正常正文写入路径未覆盖，只补齐该路径的 transcript 写入。只有现有来源确实无法承担职责时才另立原文分卷方案，本期不预建通用全渠道归档系统。

## 4. 无向量检索

### 4.1 索引与匹配

使用 SQLite FTS5 文本索引，参考现有 `mona/materials/index.py` 的 trigram 与短查询回退经验，但数据库、权限和数据源独立，不直接复用 Knowledge 的业务表。

- 索引文件通过 `mona/config/paths.py` 解析，放入现有实例级可重建缓存位置；不硬编码 `~/.mona`，不与持久正文混为一个可清理目录。
- 中文三个及以上字符、英文、路径、数字和标识符支持字面检索；一至两个汉字采用受限子串回退。
- 支持关键词列表、短语、会话过滤和日期过滤。搜索输入参数化，不把模型文本直接当作 SQL 或未经转义的 FTS 表达式。
- 排序依次考虑准确短语/标识符命中、关键词覆盖及 FTS 相关性；时间只作同等相关性下的辅助条件。相关性优先，不能只按最近时间排列。
- 预览围绕命中位置截取，携带命中偏移；不要固定只返回正文前 500 字。
- 标明索引进度与覆盖范围。索引未完成时允许查询已完成部分，但不得报告“所有聊天均无此事”。

首期不做自动同义词词库、后台 LLM 查询改写或学习排序。AI 可在一次查无结果后，用用户问题中的另一组具体关键词重查；纯同义表述无共同词仍可能漏召回，作为已知限制。

### 4.2 工具契约

新增只读 `conversation_search`、`conversation_read`（实施时按工具目录规范最终定名），保持既有 `memory_search`、`memory_read` 参数及 Dream 行为兼容。

| 能力 | 输入 | 输出 |
|---|---|---|
| 搜索聊天 | 关键词/短语，可选会话与时间范围、分页游标 | `ref`、角色、标题、真实时间、命中预览、完成/覆盖状态、下一页游标 |
| 读取原文 | 搜索返回的 `ref`，可选相邻消息范围与正文分页游标 | 原文片段、前后问答、出处、完整性标记、下一页游标 |

搜索默认最多 5 项，最多 20 项；读取默认命中消息和相邻两条，正文单次最多 8000 字符，超长内容分页且明确 `truncated`。这些是初始工程预算，不宣称已验证的最优参数；最终请求仍须满足模型实际 token 安全预算。

超过预览长度的数字、否定条件和尾部细节必须可通过分页取回。引用能被后端解析验证即达成首期溯源；前端精确滚动到历史消息可复用已有能力，若缺失则列为后续小改动，不作为第一阶段发布阻塞。

### 4.3 Agent 何时搜索

在既有 memory Skill 中集中增加短规则，不复制到多个 system 模板：

1. 用户询问“之前聊过、上次决定、以前给的数字”，且当前上下文没有足够原始依据时，先搜索聊天。
2. 问当前任务的具体细节，优先读取交接摘要中的出处；必要时按项目名称或标识搜索。
3. 命中摘要或正文预览后，核对原文与相邻问答再回答；区分用户说法、助手建议、已确认决定和后来纠正。
4. 查不到或覆盖不足时明确说明，不编造“记得”。普通自包含问题不额外检索历史。

首期采用模型按规则调用工具，不在每轮前执行隐式全历史检索，也不增设关键词路由器修改核心循环。工具结果进入当前 turn 的 tool 消息，不在轮中重建 system prompt。

工具目录、运行上下文和授权规则均须接入；拥有 Agent 私有记忆读取能力不自动等于能读取所有用户会话。新能力不能绕过已保存权限或只靠提示词隔离。

## 5. 摘要与长期记忆的边界

- 保留现有累积交接摘要及 token 压缩策略，不修改默认窗口或压缩阈值。
- 在会话摘要元数据中增加经过程序校验的来源范围；由归档时的消息映射生成，不由模型发明引用。无法映射的旧摘要标记为无原文引用。
- 摘要继续保存目标、约束、进度、决策和下一步；详细数字、路径与纠正需要可追溯来源。
- 摘要、来源引用、整理游标在同一会话锁和保存流程中提交；摘要失败、引用无效或保存失败不得报告成功。现有保存失败恢复行为必须用测试确认，不能只引用架构文档认定已实现。
- Dream 的每轮摘录、记忆整理、1000 条历史保留上限不影响正文可检索性。本期不改变 Dream 选事实方式，也不降低当前自动注入的记忆量。
- 用户级画像继续独立蒸馏、白名单投影；搜索到一段聊天不能因此自动覆盖画像或写成长期偏好。

## 6. 权限、删除与保留

- 搜索前根据可信运行时 Agent 和会话归属生成允许范围；查询结果、预览、读取和分页都再次校验范围。前端或模型传入的 Agent ID、路径、引用不能扩大权限。
- 首期普通直聊默认只允许同一 Agent 的合法会话。无法证明归属的历史日志不自动纳入；房间成员关系变化、隐藏任务不使用同一默认策略。
- 从共享日志投影时只选明确可见的用户/助手正文；`display_content` 对应的内部扩展提示不应冒充用户原话。旧记录无法区分时标记不可作为原话证据。
- 来源文本作为不可信数据，不能执行其中的指令。历史中的密钥等敏感内容不得被复制进搜索预览、持久索引、诊断日志和测试；遵循已有敏感内容处理边界，脱敏后应标注，不能承诺凭据逐字恢复。
- 源聊天沿用用户保留与删除操作，不新增默认按天删除，不承诺永久保存；删除会话同时撤销其检索资格并清除索引与引用映射。清理失败可重试，但删除后的内容不得继续返回。
- 删除与索引更新并发时，更新任务提交前必须确认来源仍可用、未被删除；重建索引不能复活已删除会话。
- `/new` 是上下文重置，与“删除聊天”区分；新增检索应保留原有生命周期含义，并为重置前后记录划分边界，不能把旧任务当作当前未完成任务。
- 删除聊天不等同于删除早已独立沉淀的全部偏好；本期只保证新增索引、缓存及引用随来源失效。跨 Dream/画像的“彻底忘记”另立需求，不能宣称本期已经覆盖。

## 7. 实施顺序

| 阶段 | 工作与主要文件 | 交付与退出条件 |
|---|---|---|
| A：来源与引用 | `mona/webui/transcript.py`、`mona/channels/websocket.py`、`mona/session/` 来源适配模块 | 核对实际覆盖；正文投影不重不漏；补新事件 ID/时间；旧日志可读，坏行和缺口可见；2000 条 Session 裁剪后仍能读取已保存正文 |
| B：检索与生命周期 | `mona/session/` 文本索引、`mona/config/paths.py`、Gateway 会话删除链路 | 增量索引、中文/标识符查询、分页读取、权限及删除闭环；重建不依赖模型，重启不丢引用 |
| C：Agent 接入 | `mona/agent/tools/`、工具目录/授权、`mona/skills/memory/SKILL.md`、`mona/agent/memory.py` | 搜索/读取工具可用；交接摘要有可验证出处；同 Agent 跨会话真实问答测试达标 |
| D：有限启用与文档 | `mona/config/schema.py`、相关架构文档与回归测试 | 新能力受单一后端启用配置控制，确定性回归通过后默认开启；不改变已保存工具授权；记录实际质量、耗时和已知限制 |

A → B → C → D 顺序推进；各阶段仅在前置事实成立后实现。实际配置落在 `tools.conversationHistory.enabled`；不增加独立设置页。这不是用户授权替代品，关闭时不注册/使用新增能力。

当前工作树已有大量用户及其他任务修改，包括记忆、上下文、工具权限和 transcript。实施时重新检查当前文件及测试，基于最新工作树整合；不还原、不覆盖，也不顺手重构这些模块。与既有上下文压缩优化、提示词预算优化分别验证，不能把它们的结果当成新召回能力验收。

职责保持：会话来源、索引和工具由 Gateway 所有，不新增后台服务；UI 日志负责持久展示事件，检索只消费其授权正文投影；Skills 负责调用时机，不能承担安全过滤。

## 8. 验收清单

### 8.1 确定性回归：必须全部通过

- [ ] 同一会话构造超过 2000 条 Session 消息，轮末裁剪后，早期已保存正文中的精确数字和否定条件仍可搜索、分页读回。
- [ ] 连续两次摘要压缩后，早期约束保留，来源引用仍有效，当前请求使用最新摘要。
- [ ] 无共同语义模型参与：索引构建、查询和原文读取不调用 embedding 或外部检索模型。
- [ ] 中文一/二/多字查询、英文、Windows 路径、数字与版本号可查询；恶意 SQL/FTS 字符不能改变查询范围。
- [ ] 命中位于长消息末尾，预览包含命中位置，分页重组结果与允许存储的原文一致。
- [ ] 流式片段、最终回复、重试、重连和取消场景不产生重复完成消息；不完整回答有状态标记。
- [ ] 新记录使用真实时间；旧记录无时间时不编造，日期查询明确排除未知时间并说明覆盖限制。
- [ ] 重启、日志追加及索引重建后引用有效；日志替换/分支不让旧引用错指。
- [ ] A Agent 的搜索、预览、读取、分页均不能访问 B Agent、隐藏或临时会话；伪造 ref 和路径无效。
- [ ] 删除来源后立即不可检索；并发索引与重建不能复活内容；删除操作不误删其他 Agent 或全局画像。
- [ ] 索引损坏可从原始来源重建；读取坏行、索引中断、磁盘写入失败明确返回覆盖不足，不伪装成零结果。
- [ ] 现有会话继续、`/new`、删除、分支、Dream 和记忆工具契约无回归。

### 8.2 用户行为小样本：用于发布判断

准备 30 个可复现问答，使用合成数据或明确授权的脱敏历史，不把真实私人聊天提交进 Git：20 个有原文的历史问题（包含跨会话、纠正、尾部细节），5 个无答案问题，5 个无需历史的问题。

先测现有版本，再测新能力，保持模型和问题一致；每组运行 3 次，保留失败案例。

| 指标 | 初始验收门槛 |
|---|---|
| 有答案问题的工具检索 Recall@5 | ≥ 90%，关键数字/否定约束案例必须命中；标注纯同义无共同词的边界 |
| Agent 回答及出处 | ≥ 90% 正确；引用必须能解析且支持答案，不把助手建议当用户确认 |
| 无答案问题 | 不得捏造“用户说过”的事实 |
| 普通问题 | 不强制新增历史检索 |
| 权限与删除 | 越权或已删除内容返回次数为 0 |
| 性能 | 在记录配置的目标 Windows 机器、10 万条正文、索引就绪条件下，搜索加一次读取 p95 目标 ≤ 1 秒；首次建索引单独统计，不计入暖查询 |

性能和质量数字是待验证的发布目标，不是当前结果。记录机器、数据规模、冷/暖状态、实际输入 token 与端到端耗时；不凭小样本宣称统计显著。达不到目标时先修索引或缩小默认返回量，不自动扩大技术范围。

本次只写文档，检查 Markdown 链接、工作树改动范围即可；实施时按改动运行相关 Python 测试及 `ruff check`。若仅后端与 Skill 改动，不跑无关前端全量构建。

## 9. 回退与后续边界

单一启用配置关闭后恢复原有工具及回放行为。新事件附加字段必须向后兼容；保留原始来源，不回滚或删除用户聊天。索引可停止更新并按既有缓存治理清理，不能清理正文来源。老版本不能理解新增摘要引用时仍能使用文本摘要。

本期不做：全渠道无限原始工具日志、向量检索、自动全量历史注入、知识图谱、第二套 Wiki、全量历史重新蒸馏、记忆管理新页面、多级 note 压缩框架。

后续仅在实际缺口明确时考虑：非桌面渠道的正文归档接入、协作房间授权检索、引用直达消息 UI、跨 Dream/画像的彻底忘记。均不作为本期隐藏依赖。
