# 股票深度投研 V2 开发计划

依据：[股票深度投研 V2 功能设计](../design/stock-deep-research-v2-functional-design.md)  
日期：2026-08-19

## 1. 开发纪律

- 在现有股票服务、六步 WorkflowRun、Artifact 和 StockView 上升级，不复制架构。
- 工作区已有大量用户修改；任务只修改分配文件，不回退、格式化或清理无关差异。
- 每个阶段先补最小失败测试，再实现，再运行相关测试和构建。
- 新 schema 使用版本号，旧报告只读兼容，不批量重写用户历史报告。
- 无稳定免费来源的数据保留缺失语义，不为“完整”伪造字段。
- 上一阶段验收通过后再进入下一阶段。

## 2. 阶段总览

| 阶段 | 目标 | 退出标准 |
|---|---|---|
| P1 可信证据层 | 消除时间穿越、混合时间语义和无来源结论 | 截止时间过滤、声明类型和阈值约束有自动化测试 |
| P2 分析证据扩展 | 补市场、行业、政策、四周期、公司、资金、事件和交易性 | 每个分区有真实来源、缺失状态和周期门槛 |
| P3 六 Agent 与报告 V4 | 形成短中长独立裁决和周期冲突 | V4 端到端报告三周期完整、证据可追溯 |
| P4 决策卡与关注雷达 | 把报告改为可操作的分层信息 | 第一屏可理解，右栏只显示增量监控 |
| P5 结果追踪与校准 | 验证报告是否产生可实现的判断价值 | 原报告不可变，结果按周期和基准追加统计 |

## 3. P1：可信证据层

### P1-T1 时间模型与截止过滤

**文件范围**

- `mona/services/stock/provenance.py`
- `mona/services/stock/evidence.py`
- 必要时最小修改 `mona/services/stock/provider.py`
- `tests/services/stock/test_evidence.py`
- 相关 Provider 测试

**任务**

1. Evidence schema 升级，增加 `research_cutoff_at` 与 `market_as_of`，保留旧 `as_of` 读取兼容。
2. 建立统一的带时区时间解析和比较函数。
3. 新闻/公告按公开时间过滤；未来来源不得进入 `news` 或 `sources`。
4. K 线只使用截止时间前已经完成的交易日数据计算指标。
5. 行情观测时间晚于截止时间时排除并标记缺失。
6. 财务数据区分报告期与公开时间；历史公开时间无法确认时不得用于历史回放。
7. 数据质量记录 `excluded_future`、`unknown_availability` 等原因，而不仅是 `missing`。

**验收**

- 截止时间为 8 月 18 日时，8 月 19 日公告不进入证据包。
- 收盘后运行可包含收盘后、运行前发布的公告，同时行情时间仍显示 15:00。
- 指标不读取未完成日或未来 K 线。
- 旧 Evidence 文件仍可读取。

### P1-T2 声明与数值约束

**文件范围**

- `mona/services/stock/schemas.py`
- `mona/agent/tools/stock_submit.py`
- `tests/agent/tools/test_stock_submit_tools.py`

**任务**

1. ViewPoint 增加 `claim_type`，推断增加 `basis`。
2. 新增结构化条件类型：人工观察条件与确定性数值条件分离。
3. 数值条件必须引用 Evidence 字段或版本化方法。
4. 没有来源的 `fact`、没有 basis 的 `inference`、数值无方法的条件提交失败。
5. 保持旧 V1/V3 产物读取兼容。

**验收**

- 无来源事实被拒绝。
- 无依据因果推断被拒绝。
- 模型自由生成的价格阈值被拒绝。
- `insufficient_data` 可以正常提交并列出缺失字段。

### P1-T3 工作流约束和回归

**文件范围**

- 六个股票 Agent 的 Prompt/Skill
- `mona/agents/com.mona.a-share-team/workflows/deep-research.json`
- `tests/agent/test_stock_workflow_templates.py`
- `tests/agent/test_stock_hidden_skills.py`
- `tests/e2e/test_stock_module_e2e.py`

**任务**

1. 明确事实、推断、假设规则和时间截止规则。
2. 禁止因数据缺失而补写因果、WACC、目标价和确定性门槛。
3. 主席不得把数据不足改成中性。
4. 建立一条未来公告、无来源阈值和数据不足的端到端回归。

## 4. P2：分析证据扩展

### P2-T1 数据源可行性矩阵

对设计中的八个分区逐项记录：正式来源、字段、时间语义、更新频率、限流、稳定性、是否可商业使用、降级规则。只接入经验证字段。

优先顺序：

1. 市场环境和相对基准。
2. 行业分类、行业相对强弱和同行比较。
3. 正式政策与事件日历。
4. 多期财务、公司质量和治理。
5. 公开资金筹码与可交易性。
6. 有稳定来源的行业供需和产品价格。

### P2-T2 Provider 与领域对象

- 在 `mona/services/stock/` 内按现有薄适配模式扩展。
- 不把抓取逻辑写进 Agent 工具或 Prompt。
- 每个字段携带来源、公开时间、统计期和缺失原因。
- 确定性计算放在服务层并记录方法版本。

### P2-T3 EvidenceBundle V2 分区与覆盖门槛

- 增加八个命名分区和 `evidence_coverage`。
- 实现短、中、长周期门槛函数。
- 周期门槛只由字段状态决定，不由文本长度或 Agent 自评决定。
- 为完整、部分缺失、核心缺失、来源超时建立测试。

## 5. P3：六 Agent 与报告 V4

### P3-T1 三路职责迁移

- 技术 Agent → 市场与交易 Agent。
- 资讯 Agent → 行业与周期 Agent。
- 基本面 Agent → 公司与估值 Agent。
- 保留内部 ID，避免破坏历史运行。

三路产物使用各自结构化 schema，不再只提交通用 `points`。

### P3-T2 多空分周期反证

- 多方和空方分别输出三个周期的最强论证。
- 每个论证公开关键假设、来源、确认和失效事实。
- 没有实质证据时如实为空，不通过扩写补足。

### P3-T3 Report V4

- 增加 `horizon_views`、四周期、情景、冲突解释、覆盖率和追踪 ID。
- 旧 V3 报告继续读取；新运行只写 V4。
- 更新 JSON/Markdown 渲染、报告 API 类型和端到端测试。

**验收样本**

至少覆盖：

1. 短多、中性、长空。
2. 短线数据不足但中长线可判断。
3. 三周期全部数据不足。
4. 政策利好但尚未进入业绩兑现。
5. 行业向上但公司弱于同行。

## 6. P4：决策卡与关注雷达

### P4-T1 三周期决策卡

- 修改 `InstrumentStage` 投研 Tab 和报告类型。
- 第一屏显示三周期观点，中线默认展开。
- 展示相对基准、已计价程度、情景、条件、时间退出和数据盲区。
- 旧 V3 报告使用兼容视图，不伪造三周期结论。

### P4-T2 证据详情

- 按市场、行业政策、四周期、公司估值、资金事件、风险反证分区。
- 多空只显示核心分歧和裁决，不恢复无价值的辩论长文。
- 来源可打开并显示公开时间、统计期和采集时间。

### P4-T3 关注雷达 V2

- 保留现有展开/收起与 336px/48px 布局。
- 只显示报告后的变化、结构化条件、近期事件和重研建议。
- 自由文本条件仍不可自动标记已确认或已失效。
- 完成组件测试、StockView 回归、构建和登录后视觉验收。

## 7. P5：结果追踪与校准

### P5-T1 不可变预测记录

- 报告完成时创建追踪记录，保存三周期观点、条件、基准和证据版本。
- 结果数据追加存储，不修改报告原文。
- 已有 V4 报告可从不可变报告内容补建追踪快照；V3 和复盘摘要不进入追踪。

### P5-T2 确定性结果计算

- 按交易日计算相对收益、MFE、MAE和条件触发。
- 中长线追加催化和基本面里程碑状态。
- 数据缺失或停牌时明确标记，不做前向填充制造收益。
- 使用报告日后首个完整交易日开盘到第 N 个交易日收盘的可实现口径。
- 公共相对市场基准固定为中证全指；报告声明基准缺少可核验代码时保持缺失。

### P5-T3 校准页面

- 展示样本数、各周期结果、相对基准和数据完整度。
- 样本不足时不显示胜率结论，不根据小样本自动调整模型权重。
- 页面先读本地结果；外部行情补算由用户点击触发，不在应用启动时自动刷新。

## 8. Luna 执行和主 Agent 验收

每次只交付一个有独立测试边界的任务，避免多个 Agent 同时修改相同股票核心文件。

Luna 每个任务必须：

1. 先读取本计划和对应现有实现。
2. 明确独占文件，不回退他人修改。
3. 写最小失败测试后实现。
4. 运行定向测试并报告结果、未验证项和实际修改文件。

主 Agent 每个任务必须：

1. 审查 diff 是否只覆盖需求。
2. 检查时间语义、来源约束和向后兼容。
3. 重跑定向测试，阶段末运行股票相关测试和前端构建。
4. 使用真实或固定样本检查报告，不接受只验证 schema 的交付。
5. 发现问题退回同一 Luna 修正，再重新验收。

- [ ] 免费数据无法覆盖的字段真实显示缺失。
