# Mona Harness Token 优化实施计划

日期：2026-09-14  
状态：提示词精简及两批能力按需加载已实施；真实模型配对与生产试用未执行。
目标：在现有能力、权限、任务连续性和交付质量保持一致的前提下，降低模型请求的固定输入开销。  
优先级：业务正确性与安全边界 > 任务完成质量 > 整轮成本与延迟 > 单次输入 Token。

## 0. 实施结果（2026-09-14）

B0–B2 已按低风险范围完成：压缩身份、通用工具契约、Skill 目录、订阅说明和计划说明；精简 `email_search` 与 `grep` 的自然语言 Schema 描述。工具集合、参数名称/类型/约束、执行逻辑、生图 Skill 自动加载、个人上下文和 Recent History 均未改变。

同一开发环境的本机配置快照从前次约 25,018 降至约 21,248 Token，表面降幅约 15.1%。期间工作树中的可见工具由 52 个变为 50 个，因此不能把全部差值归因于本次改动。可直接归因的分块变化为：系统消息约 10,909 → 7,766（约 -28.8%）；在当前相同工具集合下，两个精简 Schema 合计约再减少 298 Token。按这些分块保守估算，本次直接降低完整输入约 13.7%。

已完成的最小验证：提示词预算、上下文构建/缓存、工具描述共 79 项通过；订阅与计划相关测试 45 项中先有 1 项旧短语断言失败，保留同一业务语义和兼容短语后定点通过；生图热更新及 Skill 自动注入定点测试通过。搜索工具整文件中另有一个与本次无关的既有子 Agent 私有 Skill 路径断言失败，未扩大范围修复。改动文件的静态检查见最终交付记录。

根据用户“不要过度测试”的要求，B3 未运行全量测试、桌面构建、真实付费模型、多轮 20×3 配对或生产试用。本次结果证明结构和现有确定性契约通过，不宣称真实模型的所有业务场景已经统计验证零退化。后续高风险实验继续关闭。

后续经用户逐项决策完成第一批业务状态过滤：当时 `my`、Office、图片、视频、Notes 与 Knowledge 仍保持普通会话可用；数据库查询、终端执行子工具和 `complete_goal` 改为可信状态限定；普通画像投影缩为 preferences，画像建议入口保留任务相关投影。同一本机配置快照进一步由约 21,248 降到约 19,959，详见[能力暴露审查表](2026-09-14-agent-capability-exposure-audit.md)。

随后按成熟的延迟工具发现方向实现请求级 `load_capability`：`my` 和 Notes/Knowledge 查询初始可见，专项业务由模型按自然语言加载，活动 UI 上下文直接预加载。最终复测的普通“你好”快照约为 13,007（30 个初始工具，Schema 约 6,811，system 约 6,135），较最初 25,018 的本机快照表面减少约 48.0%。

本批次只运行与加载链、权限/订阅、并发上下文、画像投影、长期目标、终端状态和 Agent 配置相关的窄范围测试，共 106 项通过；改动 Python 文件的 `ruff check` 通过。未运行全量测试、桌面构建和真实付费模型调用。

## 1. 决策与实施范围

### Codex 参考优化批次

参考本地 `D:/liuzhe/Desktop/code/codex` 的 `tools/src/tool_executor.rs`、`core/src/tools/handlers/tool_search_spec.rs`、`ext/skills/src/render.rs` 和 `core/src/context/world_state/tools.rs`。该目录无 Git 元数据，仅作为本地源码机制参考，不将其视为某个已确认的发布版本。

- 保留 Mona 当前的能力加载器，新增 development、http、skill_resources 三个分组；不引入 Code Mode 执行层或新的意图分类模型。
- 文件发现/读取、网页查询、`my`、Notes/Knowledge、记忆、Skill 读取与任务协调保持初始可见。成功 `skill_read` 自动启用配套工具；文档专用 Agent 预加载流水线执行能力。
- `capability_contract.md` 统一存放浏览器、开发、终端、数据库的原完整操作规则。预加载路径在 system 中提供，轮中路径通过加载结果提供，重复加载不重复注入。
- 从保留的 assistant 工具调用恢复下一轮所需能力；共享投递工具不推断所有媒体能力。恢复只改变描述可见性，不重放业务动作，也不绕过当前授权。
- Skill 目录采用显式简短描述，保留原完整描述、Skill 正文与全部入口；不修改 `my` 或 memory Skill 的现有行为。

验收范围：普通自然语言任务经加载后可实际写入文件；Skill 读取后可读取参考资源；文档 Agent 的执行链可用；权限/订阅、并发隔离与 system 稳定性通过相关检查。此次未运行真实付费模型、桌面全量构建或生产操作。

本批次同条件比较（同一本机工具配置、有效订阅、空会话历史，显式排除 bootstrap/画像/长期记忆/近期事件，保留原 `my` 与 memory 常驻 Skill；`cl100k_base` 本地估算）：

| 指标 | 本批次前 | 本批次后 |
|---|---:|---:|
| 初始工具数 | 30 | 19 |
| 工具 Schema | 6,811 | 3,556 |
| System | 4,108 | 3,159 |
| 完整首轮输入 | 10,981 | 6,777 |

该固定样本首轮降低约 38.3%。同一时点保留本机个人上下文后的快照为 system 3,637、完整首轮约 7,255；它与前序约 13,007 的快照不构成严格配对，不能将个人上下文状态变化算成本批次收益。实际 Skill 目录正文的短描述投影为 1,001，相同目录恢复完整描述为 1,104，约节省 103 Token；所有名称和完整 Skill 仍可访问，不强行截断用户或专家的描述。

验证记录：首次相关运行 79 项通过、1 项新增测试因错误参数名失败，修正为真实 `ref_path` 后通过；后续加载链/Skill 身份范围/上下文稳定性 41 项通过，重复加载与文档/文件链路 4 项定点通过，历史恢复异常输入 1 项定点通过，目录渲染 2 项通过。以上存在重复用例，不相加为独立覆盖数。相关 `ruff check`、差异空白及文档链接检查通过。

专项任务仍可能需要额外一次模型调用来加载能力，已使用的能力通过保留历史恢复以减少重复加载。首轮变小不等于真实整轮费用按同样比例下降；当前结果限于离线装配和确定性行为验证。

### 前序批次范围

首期采用“完整能力集合 + 精简说明”的方案：保留当前有效工具集合和参数契约，精简重复的系统规则、工具说明与 Skill 引导。先建立可复现请求基线，再逐批验证收益。

首期没有启用工具按需加载；后续批次已实现请求级能力加载和生图 Skill 延迟注入。长期记忆相关性召回仍属于后续实验。不会为了让“你好”达到 Pi 的约 1,200 Token 而关闭通用工具、省略安全规则或删除业务上下文。

“不影响现有业务”的验收含义是：选定回归场景中无新增功能退化，权限和数据边界全部通过，已有任务可继续，发生回归可按批次恢复。有限测试不能证明所有未来输入零风险；任何已确认的业务回归都阻止该批次启用。

本计划覆盖主 Mona 的请求装配，并检查共享组件对文档 Agent、伙伴 Agent、子任务和协作会话的影响。首期不改工具执行器、服务路由、数据库结构、模型选择、历史压缩阈值、运行时下载与产品 UI。

### 2.2 实施前必须补齐的基线

在 B0 批次固定下面两组样本，不使用未隔离的个人会话作为可提交测试夹具：

1. 产品默认安装：完成初始化、默认权限、空会话，分别覆盖免费与订阅状态。
2. 代表性完整配置：已安装浏览器依赖、生图可用、脱敏画像与记忆、固定 MCP 测试工具；同时覆盖普通会话和活动 Office/数据库/终端上下文。

使用真实装配与 Provider 转换函数，在发送边界截获请求；离线测试替换网络传输，不替换上下文构建、权限过滤或 Schema 生成。记录工具/Skill 清单、状态条件、构建版本、相关文件摘要、模型与 Provider、推理设置、tokenizer 版本、样本版本。真实桌面验证另记录运行二进制版本与启动配置，不能用源码版本替代。

默认诊断只记录分块长度、估算 Token、耗时、版本和状态标识。完整请求仅允许由脱敏合成夹具生成并保存在测试产物中；生产日志不写请求正文、个人数据、参数值或凭据。构造夹具时隔离数据根目录和 Skill 使用统计，防止基线测量更新真实个人状态。

### 2.3 指标定义

| 指标 | 统计方式 | 用途 |
|---|---|---|
| 单请求完整输入 | system + tools + history + current user + runtime + 媒体开销 | 对比固定占用和窗口预算 |
| 本地分块估算 | 统一 tokenizer，同样的序列化与消息开销 | 定位优化来源，不作为账单 |
| 服务端完整输入 | 按 Provider 语义归一化缓存读写 | 验证估算偏差与实际占用 |
| 整轮输入/输出 | 所有模型调用之和，含重试、Skill 读取后的续调和 fallback | 防止首轮变小、整轮变贵 |
| 缓存读/写及未缓存输入 | 依 Provider 返回值分别保留；缺失标为未知 | 计算真实费用，避免重复加减 |
| 首段正文及整轮耗时 | 分别记录；冷/热缓存分开比较 | 判断用户等待是否改善 |
| 业务完成与失败 | 根据文件、编辑器状态、检索证据、任务状态等验收 | 效率收益的前置条件 |

Pi 的 `usage.input` 可能已扣除缓存读写；Mona 的 `prompt_tokens` 通常包含缓存输入。不能直接比较这两个字段。Mona 整轮累计 `prompt_tokens` 与最后一次请求的 `context_tokens` 也不能混用。没有价格或缓存写入信息时只报告 Token，不宣称费用降低同样比例。

## 3. 必须保留的业务边界

| 范围 | 不可回归的行为 |
|---|---|
| 工具授权 | Agent 身份、用户授权、运行依赖、上下文可用性、订阅门控共同生效；发现/缓存/回退不得扩大权限 |
| 必需能力 | 文件、命令、网页、记忆读取、Skill 运行与 Mona 协调能力按现有规则可用；不通过“聊天模式”整体关闭 |
| 专家隔离 | 专家专属工具和私有记忆不泄漏；主 Mona 不获得专属工具，伙伴不继承 Mona 协调能力 |
| 文件与网络 | resolved-path 范围校验、SSRF、外部内容不可信规则继续成立 |
| Office/画布 | 活动文档和会话绑定正确，版本冲突拒绝覆盖；保存、导出、视觉检查和交付归属规则保留 |
| 终端与数据库 | SQL 生成与执行分离；审批及维护步骤、变更后验证完整；命令成功不能代替业务成功 |
| 生图 | 生图工具可用时自动加载既有 Skill；保留完整提示词方法、引用资源、原图约束和不确定提交后的防重放 |
| 记忆与画像 | 用户规则、只读画像白名单、私有记忆范围、未完成任务和来源引用保留；不批量删除或改写个人数据 |
| 计划与自动化 | 简单请求不强制计划；长期目标仅显式 `/goal` 创建；提醒、周期任务及多 Agent 状态使用原有结构化机制 |
| 会话连续性 | system 在单个 turn 内字节稳定；用户追加、中断恢复、摘要和工具配对正确，不重复执行已完成写操作 |
| 缓存与并发 | 原有工具排序保留；请求级组装结果不得写回共享注册表，不能影响另一个并发会话 |

以 [工程边界](../architecture/engineering-boundaries.md) 和 [模块不变量](../architecture/module-invariants.md) 为准。此计划不覆盖这些稳定规则。

## 4. 首期优化设计

### A. 请求分块计量与基线工具

复用现有 `estimate_prompt_tokens`、Provider usage 和请求发送边界，增加最小的脱敏统计。完整输入预算与最终发送请求必须采用同一装配结果；不能测量精简版本却继续发送完整版本，也不能预算遗漏追加说明。

首期不增加新的性能平台或设置页面，不改变已有统计字段含义。新增诊断信息应可选关闭，不额外调用模型。基线脚本用于开发验证，不能触发真实工具操作或后台任务。

交付：可重复的离线请求报告、各块占比、缺失能力列表、冷/热缓存测量方法。先证明观测模式下发送给 Provider 的内容与原路径一致。

### B. 精简系统说明，保留语义

对 `identity.md`、`tool_contract.md`、`skills_section.md`、计划与订阅说明逐条建立“原规则 → 唯一保留位置 → 对应回归场景”的对照表。删除重复表达，精简示例和解释；不能只按字符预算截断。

具体安排：

- 公共安全、工具选择、失败处理、验证和文件交付规则保留在短公共契约。
- 首批先保留各业务段落，仅进行语义去重。再依据已有有效工具清单，在 turn 入口选择确实适用的工具说明；不改变工具清单本身。
- 工具组必须按业务链判断，例如终端维护的一组工具、检索的搜索与读取、Office 的编辑与交付。保留指导正确选择工具所需的说明。
- 工具不可见时仍保留必要的权限/订阅边界说明，避免模型以 `exec`、HTTP 或其他工具绕过限制；不能因为工具被过滤就删除相应业务限制。
- 计划说明保留适用范围、短步骤、状态枚举、同一时间最多一个进行中、调整理由和完成更新；压缩成一处，不把这 481 Token 的全文移到另一个重复位置。
- 检查已知文案漂移：契约中“终端工具始终出现在清单”与注册表过滤行为不一致，应按经验证的真实行为修正文案。此类修正单独标记，不能伪称为纯去重。
- Skill 路由、读取工具和专用 Office 工作流继续明确；首期不更改 Skill 触发条件、正文、目录成员或用户自定义说明。

请求构建依赖的是同一入口取得的有效定义快照，不能仅用 `tools.has()` 代表模型可见性。文档 Agent、伙伴和子任务如使用独立构建器，必须显式覆盖，不能让主会话优化改变其规则或角色。

### C. 精简内置工具 Schema 的自然语言描述

优先检查实际占用较大的 Office、exec、grep、终端、邮件和消息工具。业务协议相同的前提下缩短工具和参数描述，去掉系统契约中已有的长流程讲解。

首期只允许修改经过评审的内置 `description` 文本。不改变工具名称、参数名称、类型、必填项、枚举、默认值、取值约束、嵌套结构、返回契约和执行行为；不删除对安全和正确填写参数有必要的内容。MCP 返回的第三方 Schema 不做改写。

验证时规范化删除 `description` 后，对优化前后的工具定义做深度比较，必须相等；工具名称集合与稳定顺序也必须一致。进一步验证模型实际能正确选择工具、填参、处理失败与完成任务，不能只凭结构比较判定业务无影响。

说明已经清晰简短的工具跳过。不把许多工具合成一个参数不透明的“大工具”，也不依靠 JSON 空白变少推断服务端节省量。

### D. 缓存稳定性

保留现有 built-in/MCP 分组排序和 turn 内稳定 system。先用统计定位前缀变化源，首期只修复已证实的无意义顺序变化或重复拼接。

将画像、近期事件等动态内容移动到 system 末尾或 user runtime context 会改变优先级和信任边界，作为独立实验处理；不在去重批次顺手调整。画像版本、目录变化或工具授权变更导致必要的缓存失效时，接受失效，不复用陈旧状态。

## 5. 已实施能力加载与后续实验

逐项业务分类见 [业务入口与 Agent 能力暴露审查表](2026-09-14-agent-capability-exposure-audit.md)。该表区分固定按钮流水线、真实会话工具和按场景提供的候选；其中画像更新本来就不是会话工具，画像内容注入另行评审。

| 候选 | 收益方向 | 启用前条件 | 首期决策 |
|---|---|---|---|
| 业务工具按需加载 | 最大的 Schema 节省空间 | 完整能力可发现、遗漏可恢复、权限不扩张、混合任务和跨轮续接验证通过 | 已实施请求级加载；真实模型质量待观察 |
| 生图 Skill 延迟加载 | 前次样本普通请求可少约 1.2K | 调用前自动且可靠地加载完整 Skill，覆盖普通/文档/伙伴入口；更新稳定架构规则 | 已实施：预加载走 system，轮中加载走工具结果 |
| Recent History 相关性召回 | 减少不相关个人事件 | 模糊指代、跨任务约束、时间关系、来源和未完成事项均能恢复 | 保留原注入语义 |
| 动态上下文后置 | 提升固定前缀复用 | 可信指令与不可信数据仍分离，角色语义和任务连续性无回归 | 独立验证 |
| “你好”无工具快捷模式 | 降低单个问候样本开销 | 不应把“你好，继续上次的任务”等误分流；无法覆盖通用需求 | 不实施专用特判 |
| 调小压缩阈值/切换小模型 | 可能减少费用 | 属于其他优化变量 | 不纳入本次 |

请求级工具加载已经实现，并遵守以下不变量：

1. “已授权能力”与“本次已加载描述”分开，延迟不等于撤权；加载器只从当前已注册、已授权、订阅和运行上下文允许的集合中返回工具。
2. 模型根据自然语言选择一个或多个分组，混合任务可一次加载多个分组；不要求用户理解内部工具名或模式名。
3. 活动 UI 和媒体附件在 turn 入口预加载；普通专项任务由 `load_capability` 在下一次模型调用扩展工具列表，不在轮中改写 system。
4. 生图在入口预加载时由 system 注入完整 Skill，在轮中加载时由工具结果注入同一份 Skill，之后才允许调用 `generate_image`。
5. 请求级状态通过上下文隔离；没有加载器的内部子 Agent 保持原工具视图，不能因继承父任务状态而意外裁剪。
6. 原有 tool-call ID、执行状态与检查点仍是恢复依据。回退或重试不得重放整轮，不能再次发送消息、生成收费媒体或重复交付。

以下为规划排期，实际以 B0 确认的改动范围为准。首期约 4–6 个开发工作日，不含长期观察与后续实验。

| 批次 | 内容与预计工作量 | 主要位置 | 验收后产物 | 不通过时 |
|---|---|---|---|---|
| B0 | 基线和观测，约 1 日 | `utils/helpers.py`、`agent/runner.py` 发送边界、Provider 转换与测试夹具 | 两类环境的完整请求与分块统计；零业务行为变化 | 保持原装配；先解决基线差异 |
| B1 | 系统说明去重，约 1–2 日 | `templates/agent/`、`agent/context.py`、`agent/loop.py`，必要时独立构建器 | 规则迁移对照表、精简 prompt、对应业务回归结果 | 仅停用精简装配 |

| B3 | 配对验证和有限试用，约 1 日加观察 | 已有测试、隔离桌面环境、发布前配置 | 冷/热缓存与整轮收益报告、启用或保持原版的决定 | 下一轮恢复原版，不中断/重放当前轮 |

执行分工：主 Agent 负责契约判断、共享路径整合和最终验收；边界清晰的规则盘点、脱敏夹具与指定测试可交给 Luna。并行任务必须明确文件所有权，避免改写同一提示词或注册表。

回退策略：

- 本次未增加临时双版本配置，避免为一次性试用扩大配置和兼容面。回退时按独立文件恢复提示模板、计划/订阅说明及两个工具描述。
- B2 与 B1 保持可分辨的文件边界；只恢复模板不能声称同时恢复 Schema 描述。
- 活跃 turn 继续使用其固定版本；回退从下一 turn 生效。不得自动重发上一个用户请求。
- 不迁移用户权限、会话或记忆文件；回退时也不覆盖用户期间的编辑。代码回退只处理本计划批次的改动，不对工作树执行整体重置。
- 最终回退依赖发布版本和独立提交，不对共享工作树做整体重置。
- 生产发布属于后续交付环节；本计划编写与离线测量不等于授权改动生产配置或发送真实业务消息。

## 7. 回归矩阵

每项使用脱敏、隔离环境中的明确结果作为验收依据。下面的矩阵覆盖能力类型，实际用例数由 B0 固定。

| 场景 | 验收结果 |
|---|---|
| 纯问候、普通问答 | 正常语言回复，无多余计划、工具动作或后台任务；工具仍按首期契约可用 |
| 含问候的工作请求、短指代、继续上次任务 | 不误走快捷分支，保留历史目标、纠正与待办约束 |
| 文件查询和局部编辑 | 找到准确目标、只改指定内容；中文路径、精确匹配、失败重读和验证正常 |
| 长命令、交互命令、取消 | 执行/轮询/输入/取消行为和状态一致，退出与失败可区分 |
| 网页搜索、页面读取、HTTP | 证据与引用可用；恶意 URL、跳转和工作区逃逸不能绕过边界 |
| 笔记、Agent Knowledge、邮件 | 来源范围、搜索后读取、证据链接保持；免费/过期订阅拒绝与付费可用均验证 |
| Word、Excel、PPT 创建及后续编辑 | 专用 Skill 路由正确，活动会话绑定、版本冲突、保存与交付正常；PPT 导出审核仍生效 |
| 图像生成、局部改图、文档内插图 | 调用前完整 Skill 自动生效，原图约束、参考资源、输出配置与交付链正常 |
| 视频生成/帧读取、URL 转笔记 | 触发条件、任务状态、素材引用和产物归属保持 |
| 内置浏览器与外部桌面操作 | 正确识别当前实例，观察—操作—复查完整；依赖缺失能明确报告 |
| 数据库和远程终端 | 当前连接/会话正确，审批与维护复检完整，不重复提交变更 |
| 画布首次创建与连续编辑 | 创建意图、版本约束、跨轮绑定和冲突处理一致 |
| 单次提醒、周期任务、显式长期目标 | 使用正确结构化机制；普通聊天不能隐式创建目标或自动化 |
| Mona、文档 Agent、伙伴、子任务和协作房间 | 身份与授权独立，委派、响应归属、取消和恢复一致；学者/音乐人/股票专家能力不串用 |
| 个性化与私有记忆 | 用户纠正、语言偏好和必要约束继续被遵守，跨 Agent 私有内容不可见 |
| 两个会话并发、授权变更、MCP 重连 | 不共享错误的工具集合或运行上下文；连接恢复不自动授予新工具 |
| 多轮压缩、模型切换、fallback、断连恢复 | 完整预算一致，摘要当轮生效，工具配对和中间证据保留，已执行写入不重放 |

离线检查先验证实际装配与执行边界。优先扩展现有 `tests/agent/test_tool_loader_scopes.py`、`test_profile_context_injection.py`、`test_runner_persistence.py`、Office、浏览器与生图相关测试；缺少装配测试时新增小型专用测试文件。仅覆盖本批触及的业务域，同时每批保留权限、turn 稳定和并发隔离检查。

测试不向生产代码增加专用接口，不把 mock 返回“成功”当作业务完成。真实写入类场景使用隔离文档、临时工作区和测试服务；生产账号发送、远程变更、收费媒体生成不作为自动离线测试步骤。

Python 改动运行相关 pytest 与改动文件的 `ruff check`。只有跨进程契约变更才补生产端和调用端验证；首期无前端/Rust 改动时无需全量桌面构建。最终仍需一次具有实际依赖的隔离桌面验证，不能将开发环境缺失工具的结果等同于产品全量验收。

## 8. 启用门槛与目标

### 8.1 硬门槛

- 首期同一环境、权限、Agent、上下文状态下，工具名称集合与排序一致，Schema 除已评审描述外结构一致。
- 原规则迁移表无未承接的安全或业务要求；生图自动加载和 Skill 路由保持。
- 权限、数据边界、并发隔离、turn 稳定、恢复防重放及相关确定性回归全部通过。
- 基线已能完成的关键场景，无候选版本新增失败；发生失败先阻止该批启用，不以平均节省量抵消。

### 8.2 模型行为与效率验证

遵循 harness-evaluation 的受控比较方法：固定模型/Provider/推理设置/工具权限/输入与状态，每次恢复同一隔离初始状态。先运行原版基线，再评估候选版；记录所有试验，不挑选最好的一次。

建议首轮选取不少于 20 个代表性任务，覆盖上述适用业务域，每个版本每任务至少 3 次配对试验。该规模用于发现回归，不宣称统计证明零退化。只报告实测任务的首次成功率、全部重复均成功的任务比例、错误工具选择、参数错误、额外调用与人工修正次数。

真实模型试验使用明确的测试配置与预算；未执行前只能交付离线等价和 Token 估算结论，不能写成已验证业务质量无下降。高风险链路优先用隔离后端验证状态，必要时以真实模型完成规划和填参，不操作生产资源。

以下数值是本项目建议目标，不是已有结果或行业阈值：

- B1+B2 在固定“当前配置类”夹具上的首请求完整输入争取降低 15%–25%；若结构保持和质量门槛限制收益，接受较小降幅。
- 同时观察整轮实际输入/输出、缓存和耗时：首请求变小但额外工具往返、重试或成功成本上升时，不判为优化成功。
- 冷缓存首次请求、热缓存后续请求分别报告。小样本中收益方向不稳定、等待明显增加或调用错误增多时扩大验证，保留原版默认值。
- 前次提出的聊天 ≤3K、普通任务 ≤8K 仍只是后续优化目标；当前约 13.0K 的实测不能表述为已经达成。
