# 系统存储空间 AI 协助开发计划

## 目标

把“存储空间”从扫描结果查看器升级为可解释、可确认、可复检的 AI 协作流程。本批次只实现前两阶段：

1. 扫描完成后主动给出高价值结论，并通过存储专用 AI 分析形成清理闭环。
2. 增强目录级扫描证据，让 Mona 能解释当前目录为什么大、哪些内容值得审查。

不实现重复文件检测、长期增长趋势、自动归档和跨磁盘移动。

## 约束

- 不修改 Agent 核心循环。
- 存储 AI 路由归属 Gateway，因为需要复用当前模型提供商。
- 完整路径和文件名只保留在本机；发给模型的证据使用扫描生成的候选 ID 和脱敏统计。
- AI 不能生成任意路径或命令，只能引用本次扫描中的真实证据 ID。
- 缓存和临时文件继续使用现有 allowlist；个人文件只允许用户从明确清单移至回收站。
- 侧边栏使用现有 `RightSidebarToggleIcon`，打开方式、可访问名称和状态表达与其他模块一致。

## 阶段 1：主动结论与存储专用 AI

- [x] 新增扫描后“Mona 发现”摘要，展示安全可清理空间、长期未使用大文件和当前最大占用来源。
- [x] 新增存储专用结构化分析 API，返回带证据引用的摘要、发现、风险和下一步。
- [x] 修复大文件评估误用系统故障诊断通道的问题。
- [x] 存储页右侧助手优先展示本次扫描和当前目录上下文，保留输入区用于追问。
- [x] 清理建议继续复用现有确认、执行、复测和维护记录闭环。
- [x] 系统右侧栏切换按钮改用统一图标和交互。

## 阶段 2：目录级证据与联动

- [x] 扫描结果增加 `scanId`、目录/大文件候选 ID、目录直接占用、文件类型、修改时间、扩展名和可重建产物特征。
- [x] 目录树单击选择更新 AI 上下文，双击或 Enter 下钻；Treemap 下钻同步当前目录。
- [x] Treemap 与目录树共享选中状态；从 Treemap 下钻后目录树自动展开到当前位置。
- [x] AI 仅接收当前范围的脱敏目录证据，不发送完整目录树、完整路径或文件名。
- [x] 旧缓存通过版本升级自动失效，不被误当作新证据。

## 验证

- [x] Rust：目录证据聚合、候选 ID、可重建产物识别和扫描结果序列化测试。
- [x] Python：存储分析只保留真实证据 ID，拒绝模型编造的动作目标。
- [x] 前端：主动摘要、目录选择同步、统一侧栏图标、存储分析请求和结果渲染测试。
- [x] 运行 system 相关 Vitest、Python 定向测试、Rust system 定向测试和 `ruff check`。

## 完成标准

1. 扫描结束后无需输入即可看到可处理方向。
2. 用户选择任意已扫描目录后，右侧助手明确显示当前分析范围并能生成目录级结论。
3. 每条 AI 发现都引用真实扫描证据；未知 ID 不进入 UI。
4. AI 请求中不包含完整路径或文件名。
5. 清理动作必须确认，执行后展示实际释放空间。
6. 系统侧边栏与其他模块使用同一切换图标和打开方式。
