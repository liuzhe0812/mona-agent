# Agent「知识」改造计划

日期：2026-09-05  
版本：v2，按「每个 Agent 独立 Wiki、首版不共享、必须支持视觉解析」修订  
状态：已实施；自动测试通过，真实桌面与真实模型验收待执行  
范围：Agent 知识入口、独立 LLM Wiki、后台学习、视觉解析与证据保留、旧资料迁移

本文替代上一版「全局文档关联、跨 Agent 共用学习结果」方案，并作为当前实现与剩余真实验收的依据。

## 1. 技术定位与产品目标

技术依据是 [Karpathy 的 LLM Wiki 原文](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)：LLM 持续维护一套相互关联的 Markdown 知识页面，新来源进入时更新已有知识，而不是每次提问才从原文片段重新组织答案。原始来源不可被 LLM 改写；知识组织规则独立于生成内容。

Mona 在此基础上采用「一个 Agent 对应一个独立 Wiki」的产品映射。每个 Agent 的原始资料、证据、概念与实体页面、综合结论和索引独立维护，跨对话持续使用。这是 Mona 的产品决策，不是把 Karpathy 的模式当作固定实现规范。

用户路径：打开 Agent → 知识 → 添加资料 → 后台自动学习 → Agent 在任务中使用知识并引用来源。

用户无需创建、命名或关联知识库。「知识」是 Agent 的配置；「资料」仅是用户添加的文件，不再作为笔记中的独立功能模块。笔记保留记录和写作职责。

必须满足：

1. 每个 Agent 的 Wiki 独立；学习会结合该 Agent 的已有知识，更新相关概念、实体、交叉引用和有来源依据的综合结论。
2. 学习过程使用「读取资料」「整理知识」「可以使用」三段业务状态，并展示当前进度；不向用户暴露编译、模型或证据层内部术语。
3. 添加资料自动异步学习，失败时才提供手动「重新学习」。
4. 解析必须支持视觉；发现解析失败或信息性页面、图片未能读取时，文档为「不可用」，不能只凭文字部分成功就报告可用。
5. 原文件完整保存，完整提取结果和来源位置构成证据层；Wiki 未概括的细节仍能回查。
6. 首版不做跨 Agent 共享；MD5 用于同一 Agent 内的文件内容去重。

## 2. 跨 Agent 共享的取舍

共享原始文件或解析文本在技术上可行，但「复用解析」不等于「复用整个 Wiki 的学习结果」。

同一份文档在 Agent A 中可能需要与 A 的其他资料合并、比较或记录冲突，在 Agent B 中对应的知识上下文不同。不能把与上下文无关的逐文档摘要当成完整 LLM Wiki，也不能直接共用包含另一 Agent 私有来源的综合页面。

首版决策：

- 不提供「共享给其他 Agent」按钮、共享对象管理或全局文档关联表。
- 需要多个 Agent 使用同一文件时，用户分别添加，各自学习并融入各自 Wiki。
- 同一 Agent 内重复添加相同 MD5，不重复解析和学习；跨 Agent 不承诺零重复学习。
- 不新增全局原文／解析缓存、共享权限和生命周期管理。未来只有明确的复用需求与成本证据出现后，再评估仅复用不可变原文及解析结果；独立 Wiki 的整合仍按 Agent 执行。

这明确收窄并替代此前「跨 Agent 共享且不重复编译」要求，依据用户最新指示：共享复杂时不做。代价是不同 Agent 添加同一文件会各自承担学习耗时和调用成本，收益是知识边界清晰、维护逻辑简单。

## 3. 首版界面与状态

### 3.1 Agent「知识」页

Agent 详情增加「知识」页，沿用现有共享组件和语义 Token。说明文案：

> 添加资料，让这个 Agent 在完成任务时参考其中的信息。

主要操作是「添加资料」。列表显示文件名、可用状态、学习进度或失败原因，以及「查看原文」「移除」；失败资料显示「重新学习」。不显示共享操作。

默认不展示知识库选择器、LLM WIKI、MD5、证据覆盖数字、编译参数和额外工具开关。「查看学习结果」作为次级入口，来源引用可直接打开原文对应位置。

对话中的「知识」快捷入口打开同一页面。普通聊天附件不自动进入长期知识；用户通过该入口主动添加后才进入学习流程。

### 3.2 可用状态与过程说明分开

| 情况 | 文档状态 | 过程或原因 | 用户操作 |
|---|---|---|---|
| 已添加并排队 | 不可用 | 等待学习 | 可离开页面 |
| 正在解析 | 不可用 | 读取资料 | 可查看进度、离开页面 |
| 证据已完整写入、正在更新 Wiki | 原文可用 | 整理知识 | 可查看进度、离开页面 |
| 学习完成且发布检查通过 | 可用 | 无需额外提示 | 查看原文、移除 |
| 同一 Agent 内重复添加成功资料 | 可用 | 不重复学习 | 立即使用 |
| 解析失败，包括图片识别失败 | 不可用 | 说明无法读取的页面或图片 | 重新学习，或提供清晰版本 |
| 解析成功、Wiki 学习失败 | 原文可用 | 整理未完成，说明原因 | 从已完成部分继续学习 |

不显示「开始编译」「全部入库」等第二次操作。文件解析和 Wiki 更新都属于用户理解的「学习」，但两者的可用性分别由证据完整性和 Wiki 发布状态决定。

「原文可用」表示解析结果和来源证据已通过检查，可以供 Agent 检索；「已学习」表示 Wiki 也已通过引用检查并发布。两者都不表示每一句原文写进 Wiki，也不宣称模型已永久记住或完全理解全部信息。

### 3.3 导入与移除

- 采用导入文件副本；电脑上的原文件变化不会自动同步。
- 同名不同内容视为不同资料；用户提供更新版时按新内容接收，不静默覆盖旧原文。
- 移除后立即退出当前 Agent 的后续知识查询；不删除电脑原文件，导入存档和旧引用所需证据保留，不新增永久删除和垃圾回收产品。
- 同时撤出引用被移除资料的综合页面和索引项，不能只删文件列表而继续返回旧结论。后台依据剩余资料更新受影响页面，失败时保留隔离并给出可重试的学习失败提示。
- 历史对话里已经出现的信息不会自动抹除；不向用户承诺完全“遗忘”。

## 4. 数据结构与 MD5 去重

通过现有配置路径体系，在每个 Agent 的持久目录下保存知识数据，不依赖笔记 Vault。路径统一由 `mona/config/paths.py` 管理；新增配置显式进入 `mona/config/schema.py`。

每个 Agent 只需以下对象，不增加全局共享服务：

| 对象 | 必要内容与用途 |
|---|---|
| 文档记录 | documentId、MD5、文件名、大小、原文位置、有效状态与失败原因 |
| 学习任务 | 所属 Agent／文档、阶段、执行状态、错误、恢复所需记录 |
| 原文与证据 | 不可变文件、完整提取文本、视觉提取文本、稳定证据 ID 与来源位置 |
| Wiki | 来源页、相关实体／概念／综合页面、来源依赖、目录和更新日志 |
| 组织规则 | 明确 Wiki 结构、合并更新、引用、冲突和查询规则，由产品维护 |

继续使用文件与 SQLite，不新增数据库服务。文档唯一约束与活动任务去重范围均为「当前 Agent＋文档内容」，同一 Agent 的 Wiki 写入串行执行，避免并发学习覆盖彼此结果。

内容去重：

1. 后台流式计算文件 MD5。同一 Agent 内命中成功记录，直接返回已有资料，不再次调用解析器或 LLM。
2. 命中排队／执行中的记录，复用同一个任务。
3. 命中失败记录，显示不可用，由「重新学习」重试；重复导入不是绕过失败规则的入口。
4. 未命中则保存原文、登记文档与待执行任务，自动开始学习。
5. MD5 作为去重键，不作为授权凭证。复用已有 SHA-256 做原文件完整性核对；哈希命中但完整性信息不一致时拒绝直接合并。
6. 文件内容变化产生新身份；重命名、切换对话、修改 Agent 个性或任务模型不触发重新学习。

不只依赖前端判断或进程内字典。并发添加及重复重试必须落到持久唯一约束；正常重复添加不重跑，不承诺崩溃时尚未保存的外部模型响应绝对只请求一次。

## 5. 自动学习与真正的 Wiki 增量维护

Services 是学习任务的唯一执行方。UI 只负责添加、显示进度及失败重试；离开页面、切换 Agent 或关闭对话不取消学习。

正常链路：

保存原文 → 文字与视觉解析 → 保存证据并检查解析结果 → 读取当前 Agent 的 Wiki 目录和相关页面 → 增量更新知识 → 校验引用及页面一致性 → 发布 → 文档可用。

### 5.1 Wiki 不是一份份互不关联的摘要

- 每次学习读取当前 Agent 的知识目录及相关旧页面，而非只把新文件单独交给模型。
- 为来源建立可追溯入口，并按内容更新已有实体、概念和综合页面；同实体尽量更新原页，不靠追加同标题页面代替整合。
- 新旧资料一致时补充证据；有矛盾时保留双方来源、时间和适用条件，不静默覆盖，也不武断选择一方。
- 更新 `index.md` 的页面链接和内容说明，并将本次变更写入 `log.md`。页面链接和来源依赖都限制在当前 Agent。
- 单文档过长时分批处理，已有 Wiki 通过目录与相关页面按需读取；不能为适应上下文上限直接截掉原文尾部或把全部 Wiki 每次重写。
- 发布前检查链接目标、来源引用、被更新页面的旧事实保留或有据变更；不把“有 Markdown 输出”当作成功。

首版维护发生在资料添加、失败重试及移除后的必要更新中。查询时优先目录／Wiki 搜索、阅读页面和沿链接探索；需要细节时回查证据。现有全文搜索仅用于定位页面与证据，不把片段拼接回答当成 Wiki 的全部能力。

不新增向量库、图数据库、独立图谱产品、定时全库 LLM 审计、自动 Error Book，或将每次聊天答案自动写回 Wiki。上述能力不是当前需求的前提。

### 5.2 持久任务与发布

- 文件复制、哈希和解析不阻塞界面；原文与任务可靠保存后即可返回。
- 编译产物先暂存，校验通过后切换当前有效结果；失败不发布半成品，不破坏先前可用资料和页面。
- 新增文档学习失败时，该文档不可用，已有成功文档保持可用。
- 重启后恢复排队和中断的任务，复用已经完整保存且校验通过的阶段；失败任务等待手动重试，不由页面刷新或 reconcile 自动重新入队。
- 重新学习从失败阶段接续；已有有效解析结果不因 Wiki 更新失败而被迫重复视觉识别。解析版本不兼容等需重做时记录原因。
- 不建设通用工作流引擎或完整版本控制产品，只保留任务恢复、发布一致性和旧引用所需的数据。

## 6. 必须支持的视觉解析与证据保留

### 6.1 解析范围与方式

首版支持现有文本格式、PDF、DOCX、PPTX、XLSX，以及 PNG、JPEG、WebP 静态图片。文档中的图片、截图、扫描页和图表属于解析内容，不能默认忽略。动画等尚未支持的格式明确提示不可用，不能只读第一帧就声称完整支持。

- 文字文档保留结构化正文、表格、阅读顺序与来源位置。
- PDF 同时检查页面文字与视觉内容；混合 PDF 不能因某页已有文字就跳过该页图片、图表或其他扫描区域。
- DOCX／PPTX／XLSX 除文字和单元格外，还须处理内嵌图片、图表和承载信息的视觉布局；必要时渲染页面或区域后识别。
- 图片中的文字提取为文本；图表保留标题、坐标、单位、图例与可辨认数值；流程图和示意图补充有图像依据的关系描述。单纯 OCR 不足以覆盖这些内容，需要视觉模型理解。
- 视觉结果区分直接识别的文字／数据与对图形的描述，不把推断写成原文事实。无法辨认的区域明确记录，不能猜出数字补齐。
- 保存待处理页面／区域清单及各项结果，检查遗漏、空输出、调用失败和截断；包含信息的页面或区域未成功读取时，整份文档不可用。空白页可标明为空白，不按解析失败处理。

视觉模型复用已有 Provider 和模型配置体系；资料含图片时必须走确实支持视觉的调用路径。不能回退成删除图片后仅用文字重试，并把这种结果视为视觉解析成功。

不要求每个 Agent 再配一套模型。当前配置无法提供视觉能力时显示明确原因和现有配置入口；不能悄悄跳过图片。若需要可下载解析工具或模型，必须进入统一运行时仓库，不新增功能专用下载器。

### 6.2 不丢原始信息的具体承诺

- 原文件逐字节保留并核对完整性；LLM 无权改写原文件。
- 证据层保存完整文字提取、视觉提取及来源定位，不用 Wiki 摘要替代原始提取，不删去“次要”“重复”或未被 Wiki 采用的内容。
- 每条证据绑定文档身份、内容版本及页／幻灯片／工作表／图片位置，必要时含区域。视觉提取属于派生结果，引用应能回到原始图片或页面核查。
- Wiki 的结论与证据对应，伪造引用不可发布；模型只在 frontmatter 列出证据 ID 不等于已覆盖内容。
- 编译失败、重新学习或移除查询范围不破坏已经保存的原文与证据。索引可重建，索引丢失不等于资料丢失。
- 解析失败时仍保留原文件和已得到的结果供用户查看，但不能通过知识查询工具将该失败文档当成已学习成功的来源。

存储层可验证原文件无损；OCR／视觉模型不能保证所有像素信息都被百分之百正确转写。产品必须做到不静默跳过、可回查、已知失败不可用，并用真实样本验证识别质量，不能以 LLM 自检替代这个限制。

## 7. Agent 查询、边界与旧数据迁移

### 7.1 查询与范围

- 添加资料即纳入当前 Agent 的学习流程，不要求额外开启工具或选知识库范围。
- 所有知识搜索、页面读取、证据读取和链接跳转绑定运行时提供的 Agent 身份及有效文档，不能接受模型传入另一个 agentId 扩大范围。
- 不因另一 Agent 添加了相同 MD5 而授予访问权限；独立目录之外仍须有 resolved-path 和来源依赖检查。
- 普通无独立身份的子任务继承发起方范围；以另一 Agent 身份执行的任务使用其自身知识，不能自动合并两个 Wiki。
- 文档内容只作为不可信数据，不成为系统指令。组织规则由产品提供，动态学习和查询信息不破坏单 turn 的 system prompt 稳定性。
- 知识范围限制知识接口，不宣称能撤回历史对话内容或取代现有通用文件工具权限。

### 7.2 旧资料迁移

迁移代码在 Services 启动时保守复制旧资料；原目录不删除，视觉资料等待用户重新学习。实际用户数据将在升级后首次启动时执行迁移并保留错误记录。

1. 盘点旧 Vault 的原文、证据、Wiki、索引与 Agent 范围配置，兼顾旧根目录与 libraries 目录并存的布局。
2. 将旧 specific 展开为该 Agent 独立知识的明确文档集合；all 只接收迁移时原本允许的文档，不再自动获得其他 Agent 日后添加的资料；none 保持空。
3. 在各 Agent 范围内按 MD5 去重。旧库同时用于多个 Agent 时，各自建立独立副本和身份，不延续共享可变 Wiki。
4. 旧页面只有在来源完整、内容版本一致、引用可验证且全部来源属于该 Agent 时才可复制复用；不能从混有未授权来源的页面裁掉引用就认定安全。
5. 命名冲突时保留旧库命名空间并改写内部链接，不覆盖同名页面。无法安全复用的页面保留存档；确需重新学习的文档说明原因并显示不可用，不因迁移暗中启动全量模型任务。
6. 旧 knowledgeBaseId、materialId 和 `mona:material` 引用建立可确定的映射，结合当前 Agent 校验，不跳到同名文件或别人的 Wiki。
7. 原文和学习结果可从 Agent 知识页及聊天引用打开；Office／PDF 复用现有预览能力。编辑不能改写不可变存档，修改内容作为新版本接收。
8. 迁移核对完成后移除笔记资料入口及旧范围控件；笔记自身功能不变。

迁移可重复执行，失败不标记完成、不删除原目录。索引从目标数据重建，不直接移动运行中的 SQLite／WAL／SHM。迁移前后对照原文完整性、每个 Agent 的可访问集合和旧引用，防止信息丢失或范围扩大。

## 8. 实施映射与验收顺序

以下能力已经进入实现；P6 中依赖真实文件和真实模型的项目仍需在桌面环境验收。

| 已实现能力 | 相关位置 | 实现方式 |
|---|---|---|
| Agent 知识页与引用预览 | `AgentManagementView.tsx`、`AgentKnowledgePanel.tsx`、`materials-open-store.ts` | 知识成为 Agent 设置，笔记资料入口隐藏，引用按 Agent 打开 |
| Agent 独立归属与 MD5 身份 | `mona/materials/knowledge.py`、`mona/config/paths.py` | 每个 Agent 独立目录、状态和索引，同 Agent 去重 |
| 自动学习与持久恢复 | `mona/materials/knowledge.py`、`compile.py` | 添加即排队，失败手动重试，Services 启动恢复中断任务 |
| 文字与视觉联合解析 | `mona/materials/vision.py`、`mona/materials/api.py` | 图片和 PDF 页面走视觉模型，Office 内嵌图片纳入证据 |
| 禁止去图成功降级 | `mona/materials/vision.py` | 视觉调用直接校验能力、空结果、不可辨认和截断 |
| 持续维护 Wiki | `mona/materials/compile.py` | 学习时读取相关旧页面，维护来源、实体、概念、目录和日志 |
| 原文、证据与 Wiki 分层 | `api.py`、`compile.py`、`index.py`、`knowledge_search.py` | 原文件不可变，证据可回查，查询绑定 Agent |

| 阶段 | 工作与完成条件 |
|---|---|
| P1：知识归属 | Agent 独立路径、文档 MD5、持久任务与接口契约；同名不覆盖，范围不串库 |
| P2：解析与证据 | 文字／视觉解析及来源定位；图片不是占位符，任一已知解析失败不可用 |
| P3：Wiki 学习 | 添加自动执行、读取已有 Wiki 后增量更新、校验发布、失败重试和重启恢复 |
| P4：界面与查询 | 从 Agent 添加、学习、查询、回查、移除；不再出现知识库／编译等管理术语 |
| P5：迁移 | 独立副本、有效结果复用、旧引用兼容；验证后撤下旧入口 |
| P6：验收 | 自动回归、桌面操作与真实视觉／学习模型样本，分别报告通过、失败和未验证 |

新增知识业务归 Services；Agent 身份、用户设置和运行时工具归 Gateway。跨进程契约同时验证两端，不重复注册路由或用前端试错回退掩盖归属问题。

核心数据、学习与授权契约由主 Agent 负责；边界明确后，前端和独立回归任务可交给 Luna。集成、迁移与最终验收由主 Agent 负责。

## 9. 必须验证的场景

### 自动回归

1. 同一 Agent 内相同内容改名添加、并发添加、重复点击重试：只有一份有效文档及一个活动任务；成功后再次添加不调用解析或 LLM。
2. 两个 Agent 分别添加同一文件：得到独立知识上下文；A 的其他资料、页面及学习进度不进入 B。
3. 先学习 X，再添加相关的 Y：真实执行链把已有相关页面传入学习，更新原页面与交叉引用；矛盾保留双方来源，不能只生成两份无关联摘要。
4. 解析异常、图片调用失败、图片被调用层丢弃、某一信息页遗漏：整份文档不可用，不能以部分文字成功发布。
5. 长文尾部、图片中的数值、表格限定条件被 Wiki 概括遗漏：对应原文和证据仍完整、可读取和定位。
6. Wiki 输出截断、引用伪造或写入中断：不发布半成品，不损坏先前可用资料；失败仅手动重试。
7. 关闭页面或重启 Services：已保存任务继续或恢复，完成阶段不无故重跑；失败任务不因刷新自动重试。
8. 跨 Agent 搜索、直接 Ref、路径穿越和页面链接访问均不能扩大范围；相同 MD5 不绕过授权。
9. 移除来源 X：含 X 的综合页面立即退出查询，后续更新只用剩余来源；不会影响另一 Agent 的 Wiki。
10. 迁移中断重跑、旧根目录混合布局、同名页面、混合来源旧页面：原文不丢、重复不增加、引用不跳错、范围不扩大。

### 桌面与真实模型验收

- 不配置笔记 Vault，完成「Agent → 知识 → 添加 → 自动学习 → 任务使用 → 原文回查」，不出现第二次学习确认。
- 实测静态图片、扫描 PDF、文字与图片混合 PDF、带图表的 PPTX／DOCX／XLSX，问题必须包含只有图片里才有的信息。
- 用模糊图片、缺少视觉能力、解析连接中断验证不可用与明确重试提示；不能默默退回纯文字。
- 用相关资料验证跨文档知识整合，用矛盾资料验证来源、时间与条件保留；不是只检查目录中出现 Markdown 文件。
- 抽检数值、单位、否定、例外、图表关系和图片来源定位；核查 Wiki 未收录细节仍可回查。
- 同一文档在两个不同语料上下文的 Agent 中验证独立整合，而非要求 Wiki 字节相同。
- 核验浅／深色、常用窗口尺寸，以及可用／不可用、学习中与失败提示的一致性。
- 记录学习耗时与模型调用量，区分文字解析、视觉识别和 Wiki 更新；没有真实模型验收前不宣称语义质量达标。

自动测试证明数据完整性、状态、隔离和调用契约；真实模型样本评估视觉识别与 Wiki 组织质量，两类结论不能互相替代。

## 10. 文档同步与交付边界

实施对应阶段时同步更新 `docs/architecture/retrieval-architecture.md`、`module-invariants.md` 的知识归属和查询不变量，标明旧库配置仅用于迁移。涉及新增运行时组件时遵守 `runtime-component-management.md`；不静默选择与稳定架构冲突的临时实现。

本轮不增加跨 Agent 共享、全局知识管理、文件夹监听、网页连接器、跨设备同步或批量自动授权；不捆绑 Agent 核心循环、笔记编辑器和无关依赖重构。

P1 至 P5 已实现并通过相关自动回归；P6 的桌面真实操作、真实视觉模型识别质量和跨文档知识组织质量尚未验证，发布前必须如实报告结果。
