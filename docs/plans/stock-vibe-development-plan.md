# 股票模块 Vibe 开发实施方案

## 2026-10-20：原生能力产品化目标（当前）

本轮集中在投资工作台和机会选股两个Tab的六项功能：原生方法/团队与策略选择；选股结果、依据和风险；原生可配置回测；历史报告、比较与策略复用；既有个股行情图表；带精确来源的个股研究与追问。所用八类Vibe能力和当前验证范围见[原生能力清单](../design/stock-vibe-native-capabilities.md#41-两个目标tab的六项产品功能)及[机会选股实现记录第18节](../design/stock-vibe-opportunity-implementation.md#18-原生能力产品化映射与当前验收2026-10-20)。股票导航仍有账户与复盘，本轮未扩展其功能。

早期五个Mona自建策略卡片与逐日历史选股评价已归档；其计算不再作为当前产品功能。原生策略回测、AlphaZoo因子评测与选股方法历史表现是不同业务，不能相互冒充。SDM登记策略和AlphaZoo因子分别展示；原生Reports目前只扫描最近100条、无offset。量化团队、ML团队和AlphaZoo计算已在合成输入上实际运行；这不表示真实市场效果、所有团队或所有数据源已验证。统一运行包0.1.16+mona.native.product.1已安装，功能联调、真实Services接口、必要测试和生产构建通过；浏览器／窗口视觉未执行，具体证据与边界见[本轮验收记录](stock-vibe-native-product-goal.md)。

## 2026-10-20：原生回测参数产品化

## 2026-10-20：只接入原生已有能力（最新约束）

## 1 固定技术路线

### 1.1 进程与职责

采用 **Services 按需管理完整 Vibe 原生服务，Gateway 提供纯模型桥接，WebUI 只访问 Mona 的业务接口**。

调用关系：

```text
股票界面 ───────────────┐
                       ↓
Mona会话工具 → Services股票适配 → Vibe原生API与SSE
                                  ├─ 原生AgentLoop与Swarm
                                  ├─ 原生策略与回测子进程
                                  ├─ 原生成交复盘与Shadow
                                  ├─ 原生账户与调度
                                  └─ Gateway纯模型桥接 → 所选模型提供商
```

| 所有者 | 负责 | 不承担 |
| --- | --- | --- |
| Vibe | 金融任务执行、团队、记忆、工具、策略、运行产物、账户快照、Shadow、研究调度 | Mona 产品权限与桌面安装管理 |
| Services | 新股票业务 API、Vibe 子进程生命周期、本地认证、请求关联、事件转发、产物访问、用户界面投影 | Mona AgentLoop 内部对象、二次金融计算、第二套研究调度 |
| Gateway | 模型配置快照、纯模型调用、调用权限、Mona 会话中的金融任务入口、唯一运行时安装任务 | 重新执行 Vibe 的金融工具或专家流程 |
| WebUI | 当前四个产品入口、任务与结果展示、用户输入、状态和操作反馈 | 计算收益或验证结论、后台业务定时器 |

选择独立服务的原因：Vibe 使用通用 `src` 包名、进程环境、全局缓存和服务单例，并存在通过 `sys.modules["api_server"]` 访问宿主的代码。同进程嵌库会引入命名、依赖与运行状态冲突，还会迫使 Mona 重新装配原生运行链。

原生启动形式为：

```text
<受管Python> <Vibe包>/agent/api_server.py --host 127.0.0.1 --port <宿主分配端口>
```

不使用 `--dev`，不启动上游 Vite。沿用完整金融后端，不要求将上游 React 前端混入 Mona 构建。原生监听仅供宿主访问，前端不发现或拼接该端口。

### 1.2 模型接入的硬约束

**不能把 Mona 现有 `/v1/chat/completions` 直接设为 Vibe 的模型地址。** 该入口在 `mona/api/server.py` 调用 `AgentLoop.process_direct`，会形成 Vibe AgentLoop 再进入 Mona AgentLoop。

新增 Gateway 纯模型桥接，使用 `mona/providers/factory.py` 构建明确的模型预设快照，只转换模型协议、传输消息和返回工具调用，不执行 Mona 工具循环。

- 首批明确支持经过契约测试的 API 提供商。原生 CLI 账号模型不因 Mona 已支持就自动进入兼容名单。
- 显式指定预设，避免 `build_provider_snapshot` 无预设时进入 NativeWorkProvider 默认分支。
- 本 worktree 已按用户授权核验 Mona API 的百炼 Coding Plan：`stock_vibe.model_preset="default"` 明确沿用当前 `agents.defaults`，实际配置为 `qwen3.7-plus` / `aliyun-bailian-coding`，桥接后端为 `openai_compat`。这是本次受授权环境的选择和测试证据，不是所有安装的固定模型；`None` 仍表示未选择，不能因桥接不可用自动回退。
- Vibe 继续使用自己的 provider adapter、消息、工具调用和研究循环。

- 新后端直接或通过业务辅助模块依赖 `mona.services.stock`，或旧 `stock_query`、`stock_research`、`stock_selection`、`stock_submit`、`stock_diagnosis_submit` 工具中的金融实现。

### 1.5 分发方式与体积预算

采用统一运行时按需下载。Mona 主包只增加宿主接入和新界面，完整 Vibe 金融依赖位于独立受管组件。A 股范围裁剪针对分发内容和依赖闭包，不拆散已选定的研究、回测和 Shadow 流程。

| 项目 | 当前规划口径 | 实施时必须测量 |
| --- | --- | --- |
| Mona 主安装包增量 | 以 10 MB 内为工程目标 | 同平台、同构建配置下接入前后压缩安装包差值 |
| 股票基础组件首次下载 | 参考范围 200–300 MB，按约 250 MB 准备容量 | 固定版本运行包及首次必需依赖的实际下载字节；不能将 wheel 总和当最终安装包大小 |
| 组件展开后的文件 | 参考范围 500–800 MB | 程序与隔离环境实际磁盘文件，下载缓存和旧版本另列 |
| 首次准备空间 | 暂按约 1 GB 预留 | 解压暂存、保留压缩包及回滚版本造成的峰值 |

以上是 2026-10-16 的 Windows x64 估算和预算，不是已经完成的打包结果；不含券商客户端、尚未确定的券商 SDK、可选本地模型和历史行情缓存。兼容缓存可以减少重复下载，不能直接共享 Gateway 内冻结的 Python 或跨 ABI 借用已安装库。

分发包不携带 Vibe Electron、原前端、wiki、展示素材和开发测试资源。A 股未使用的海外/加密连接及其独有依赖可不随基础组件分发；可选策略依赖单独列入能力包。上游 Windows lock 仍含可选 SMC 所带的 numba/llvmlite，不能照单安装后再把体积算作必要 A 股核心。

裁剪需要生成可用工具、技能、数据源和报告格式清单并逐项验证。自动发现会跳过缺少依赖的工具，服务能启动不能证明裁剪成功；删除顶层耦合依赖也可能破坏 A 股回测。超过预算时先给出实际构成及取舍，不为压缩体积静默删除承诺功能。

## 4 状态与数据契约

### 4.1 唯一事实来源

- Vibe 负责 session、attempt、swarm run/task、strategy artifact、backtest run、shadow profile/result、portfolio snapshot、scheduled job 的原生身份与数据。
- Mona 只持久化恢复需要的关联、请求幂等信息、展示偏好和必要索引。不建立第二套策略或 Shadow 真源数据库。
- 原生字段不统一改名重存。界面可以转换显示名称、数值单位和时区，转换规则必须显式，保留原值与来源。
- 账户研究绑定快照，不拿当前持仓替换历史研究的输入；数值缺失与零严格区分。

### 4.2 拟议宿主协议

新业务路由前缀暂定 `/api/stock-vibe`；它是拟新增宿主协议，不代表上游已有同名接口。

旧历史只读接口与新业务协议分开命名和授权；迁移读取不能伪装成新引擎的研究结果。禁止把新接口代理到旧 `/api/stock/` 业务实现，也不使用“新接口失败再试旧接口”的回退策略。

每个可能创建任务或写数据的请求至少携带稳定 `request_id`。响应保留原生对象引用、真实接收状态和可继续查询的地址。仅在上游确认后报告提交成功。

关联记录至少能回答：请求何时收到、是否已派发、关联哪个原生对象、最后一次确认状态是什么、请求结果是否仍未知。相同请求重复到达要返回同一结果；接收回执丢失后查询或核对，不重新执行。

若上游入口没有足够的幂等支持，在原生服务边界加入最小的稳定请求标识与对象绑定补丁。不能根据相同标题或文本猜测请求身份。

产物访问使用受控的原生对象和产物标识。宿主解析真实路径并验证范围，不接受前端传入任意本机路径；网页输入经过既有或等价的 SSRF 防护。

### 4.3 不同任务的恢复语义

| 类型 | 已核实行为 | 宿主必须处理 |
| --- | --- | --- |
| Session | 重启后恢复部分记录并标为 INTERRUPTED，不自动续跑 | 重新读取原记录，不自动重发最后一条消息 |
| Swarm | retry/resume 可建立关联的新 run 并复用完成节点 | 显示旧新运行关联，不能把 resume 当作同一 run 原地恢复 |
| Alpha 评测 | job 为进程内存态，重启后失效 | 显示需要重新评测；持久恢复是新增任务，不虚报已有 |
| Scheduled | dispatch completed 表示成功入队 | 追踪关联 session/attempt，报告完成后才通知研究完成 |
| 回测 | 独立子进程和自身超时，Agent 超时不等于子进程停止 | 取消后核对实际进程与产物状态，不仅改变 UI 状态 |

- [ ] 关键位置必须关联行情、工具计算或明确策略规则及版本；数据不足时留空并说明缺项，不能由 LLM 凭空生成支撑价、目标价或概率。
- [ ] 按证据表达成立与失效情景，不强制为每个标的凑齐多套路径；图表保留真实行情，可标注有来源的关键位置与条件，一期不绘制伪装成预测的未来价格曲线或概率扇形。
- [ ] 判断更新只追加，保留先前结论与修订理由；更换周期不覆盖旧版本。条件、提醒和报告引用同一产物身份。
- [ ] 后续行情跟踪条件是否发生、判断是否失效及是否到复核时点；到期记录实际观察结果，不能把“触发过条件”计作预测准确或交易盈利。
- [ ] 将判断与实际成交用于后续复盘，明确研究建议与用户真实操作的区别；需要验证规则时转入 T06 或 T07，不继承未经验证的绩效。

**完成条件**：一次真实研究能产生有来源的情景与条件，修订可追溯，后续行情能核对条件状态并用于复盘。**停止条件**：没有来源的关键价位或概率、用事后行情改写历史判断、把情景跟踪当作已验证的数值预测、另起旧量化分析链。

### T10 定时研究与实时条件提醒

**落点**：原生 scheduled research、拟新增条件事件入口、Mona 通知适配。

- [ ] 盘前、盘后和定期策略复验只由原生调度触发，Mona 不再重复创建同一任务的 cron。
- [ ] 将主动程度、关注范围、通知时段及更新频率显式写入 `mona/config/schema.py`，复用现有设置与权限。手动档仅执行用户发起的研究；重要变化档按已关注对象的条件或重要事件触发；持续关注档在所选范围与时段提高检查频率。
- [ ] 初始建议重要变化档，只覆盖用户已选择的对象与可核验条件；空关注范围不启动扫描。调低或关闭主动程度时同步撤销不再允许的后台触发，不自动取消用户已发起的研究。
- [ ] 开发阶段只在隔离测试数据根验收调度。正式启用新调度必须与 T12 停用旧股票自动触发联动，避免同一用户任务被两套系统执行。
- [ ] 调度入队、关联研究进行中、报告完成、通知已送达分别处理，重启不重复投递。
- [ ] 为持仓与观察池定义版本化条件；根据行情或事件计算状态变化，避免每个 tick 都调用 LLM。
- [ ] 持久化去重和状态转换，提醒包含触发事实、影响的计划版本及下一步；数据过期时不产生假触发。
- [ ] 桌面后台运行、正常退出和暂停时的调度行为可预期，不承诺应用完全退出后仍运行。

**完成条件**：三档设置持久生效，手动档无自主触发；一条真实事件只产生对应提醒，恢复后无重复；研究完成通知对应真实报告。**停止条件**：把入队当完成、使用 React 定时器承担后台研究、重连后重复研究或重复通知、持续关注变成全市场逐笔调用模型。

### 7.1 正式切换前的四道门槛

1. **依赖门槛**：新前后端及模型桥接通过禁止依赖检查；负例样本能被检查拒绝。迁移和历史只读模块没有执行旧业务的入口。
2. **真实链路门槛**：至少各完成一次研究/团队、策略回测、Shadow 的真实原生运行，记录宿主请求、原生对象、原始产物及最终界面的对应关系。来源字段必须由服务端产生，并与真实引擎记录核对，不能只在响应里写一个 `engine=vibe` 就算通过。
3. **失败门槛**：新引擎未安装、启动失败、模型失败、断线及数据缺项都返回真实状态；旧接口与旧计算链调用数为零，界面不展示示例结果作为兜底。
4. **执行权门槛**：冻结旧提交后处理旧在途任务，再一次切换；重启和受支持回滚均不复活旧队列、隐藏房间或定时研究。直接调用旧写入口也不能绕过。

四项必须有独立证据，缺一项不切换正式入口。仅修改目录、截图验收或旧测试通过均不能替代这些门槛。
