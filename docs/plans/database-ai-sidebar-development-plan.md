# 数据库 AI 侧边栏后续开发计划

> 状态：待实施（仅保留当前仍未完成的工作）  
> 审计基线：2026-09-02  
> 范围：数据库侧边栏的 AI 只读分析、受控数据变更与结果反馈

## 1. 当前基线

以下能力已经存在，本计划不重复建设：

- 数据库侧边栏可以绑定当前活动连接，并把数据库类型、版本、数据库、表、当前 SQL 和最近错误作为受限上下文传给 Agent。
- `db_inspect` 已支持连接、表结构、索引、执行计划和健康检查。
- `db_query` 已提供面向 Agent 的查询入口，目标是只读，并限制返回行数。
- `db_sql_draft` 已将 SQL 以结构化草稿卡展示，支持插入、替换、复制；变更类 SQL 当前只应由用户在编辑器中手动执行。
- 旧的多入口快捷表单已经收敛为自然语言输入和少量上下文动作。
- 当前真正实现的数据库驱动只有 SQLite 和 MySQL；其他类型不能在本计划中宣称已支持。

当前仍存在的缺口：

1. `db_execute_ai_read` 仍直接进入通用 SQL 执行路径。通用执行器对非查询语句会执行变更，因此“只读”尚未在 Rust/Tauri 边界形成单点强制。
2. `WITH`、`SHOW`、`DESCRIBE` 等语句的只读判断和结果上限没有统一覆盖；模型返回的 `operation_class` 也没有由后端重新裁决。
3. 没有受控 DML 的影响预检、计划审批、事务执行、验证、提交/回滚和取消语义。
4. 没有可恢复的变更任务记录或完整任务快照事件，侧边栏也没有变更任务卡和历史状态展示。
5. 活动连接信息包含数据库配置对象；凭据必须在返回前从 `ConnectionInfo`、Agent 上下文、事件和日志中隔离或脱敏。

## 2. 已确认的产品边界

### 2.1 两项能力

- **自动分析**：在存在活动连接时，Agent 可以自动读取结构、索引、执行计划、健康信息和用户明确要求的数据查询，并直接给出分析结论。
- **受控数据变更**：只有用户明确要求修改数据时，才生成变更计划并进入一次计划级审批、事务执行和验证流程。

### 2.2 安全边界

- AI 只读入口只允许单条、可判定为只读的 `SELECT`、`SHOW`、`DESCRIBE`、`EXPLAIN` 和只读 `WITH`；无法可靠判定时拒绝执行。
- 禁止多语句、注释绕过、事务控制语句、存储过程调用、文件导入导出、用户变量和任何隐式变更。`WITH` 只有在最终操作仍为只读时才允许。
- DML 第一版只支持单条、单表、带明确条件的 `INSERT`、`UPDATE`、`DELETE`。无条件 `UPDATE`/`DELETE`、`INSERT ... SELECT`、多表变更和无法预估影响范围的语句直接阻断。
- DDL、账户管理、权限、索引维护、`TRUNCATE` 等非事务性或高风险语句只能生成草稿，不能由 Agent 自动执行，也不能承诺回滚。
- 用户编辑器的普通 SQL 执行仍是独立的人为操作；本计划只收紧 Agent 通道，不改变用户明确点击执行的现有语义。
- 所有变更必须绑定发起审批时的连接 ID、数据库和目标对象。连接断开、任务取消、超时或上下文过期时不得继续执行。
- 变更前必须显示目标、语句作用、预计影响行数、验证方式和风险；执行结果与预检不一致时中止并回滚。
- 数据库密码、DSN、SSH 私钥和连接配置不得进入 Agent 上下文、任务事件、前端日志或持久化任务记录。只传递不具备凭据含义的连接 ID 和必要的数据库元数据。
- 查询结果、错误文本和任务记录都必须有大小上限；不得把整表数据或原始凭据写入聊天历史。

### 2.3 非目标

- 不做 DDL 自动迁移、跨数据库事务、跨连接批量任务或后台定时任务。
- 不新增通用工作流引擎、独立“数据库维护中心”或第二套数据库连接管理器。
- 不增加新的数据库驱动；未实现的数据库类型继续明确提示不支持。
- 不把模型给出的安全分类当作授权。分类、目标和影响范围必须由后端再次校验。

## 3. 最小实施步骤

### P0：先封住 Agent 只读边界

1. 在数据库执行边界增加唯一的 AI 语句校验入口，`db_execute_ai_read` 必须先经过该入口，再调用查询执行器；普通用户 SQL 入口不复用这套授权。
2. 实现失败即阻断的单语句分类：去除首尾空白后识别语句类型，拒绝第二条语句、危险注释/控制语句及 `WITH` 后的 DML；不能确定时返回可定位的拒绝原因。
3. 统一行数、结果字节数和执行时限。`SHOW`、`DESCRIBE`、健康检查和空结果也必须经过同一上限，避免只限制普通 `SELECT`。
4. 后端根据 SQL 和连接类型重新计算 `read`、`transactional_dml`、`non_transactional_change` 或 `blocked`，草稿中的同名字段只作为展示信息。
5. 返回 `ConnectionInfo` 前清除密码和其他凭据字段；检查 Agent 上下文、IPC 事件、错误日志和历史持久化没有凭据。

P0 完成后，任何 Prompt 或伪造工具参数都不能通过 `db_query`/`db_inspect` 让数据库发生写入。

### P1：受控 DML 闭环

1. 增加一个结构化 `db_change` Agent 工具，仅处理用户明确提出的单条 DML。工具请求至少包含目标对象、语句类型、SQL、预计影响范围和验证查询；没有活动连接时不可用。
2. 后端先执行只读预检，得到目标对象、预计影响行数、当前连接和验证计划，生成待审批任务。预检阶段不得写入目标数据库。
3. 建立最小任务状态：

   ```text
   planning
      -> waiting_approval
      -> executing
      -> verifying
      -> committed
   ```

   另有 `rejected`、`cancelled`、`rolled_back`、`failed` 和“状态未知”终态。没有成功验证不得进入 `committed`。

4. 用户批准一次计划后，由后端在同一连接语义下开启事务、执行 DML、执行验证查询，再决定提交或回滚。审批不授予执行其他 SQL 的权限。
5. 执行失败、验证失败、影响行数超过预检、取消、超时或连接断开时回滚；无法确认回滚结果时标记“状态未知”，不得显示成功。
6. 在本地 Mona 数据库持久化任务的最小元数据：任务 ID、连接/目标快照、状态、预计/实际影响行数、验证结果、时间和脱敏后的语句摘要。不保存密码、原始连接串、完整结果集或终端式输出。
7. 每次状态变化发布完整任务快照事件。应用重启后，未完成的执行/验证任务标记为“状态未知”，要求用户人工核对，不自动重放。

### P2：侧边栏反馈

1. 在现有数据库 AI 侧边栏增加变更任务卡，展示目标、影响范围、验证方式、风险和当前步骤。
2. `waiting_approval` 只显示一次“批准计划/拒绝”操作；执行、验证、提交和回滚状态由后端事件驱动，不能由聊天文本推断。
3. 成功显示实际影响行数和验证结果；拒绝、回滚、失败和状态未知显示原因，并保留草稿供用户手动处理。
4. 提供最小历史查询，能够按连接和最终状态查看任务摘要；历史内容遵循同样的脱敏和大小限制。

## 4. 验收

### Rust/Tauri 边界

- `SELECT`、只读 `WITH`、`SHOW`、`DESCRIBE`、`EXPLAIN` 可以执行；`UPDATE`、`DELETE`、`INSERT`、DDL、多语句和 `WITH` DML 均被 AI 只读入口拒绝。
- 注释、大小写、前后空白和尾部分号不能绕过分类；无法分类的语句默认拒绝。
- 普通查询、`SHOW`、`DESCRIBE` 和健康检查均遵守行数、字节数和超时限制。
- `ConnectionInfo`、运行时上下文、任务事件、错误和持久化记录中不存在密码、DSN、SSH 私钥或未脱敏连接配置。

### 变更任务

- 只读预检不会改变数据；没有审批不能执行 DML。
- 一次批准只对应一份不可变计划；执行期间不能替换 SQL、连接、数据库或目标对象。
- 成功 DML 必须有晚于变更的成功验证并提交；验证失败、取消、超时、断连和影响范围变化都会回滚或进入状态未知。
- DDL、权限、账户、索引维护和其他非事务性语句始终只生成草稿。
- 重启后不会自动重放未完成任务；用户可以看到明确的状态未知提示。

### Python/前端

- 没有活动连接时，数据库工具不会出现在可用能力中，或返回明确的不可用错误。
- Agent 明确要求修改时进入 `db_change`；普通分析不会隐式创建变更任务。
- 任务卡只由任务快照更新，批准、拒绝、取消按钮与后端状态一致；历史摘要不包含凭据和完整结果集。
- 现有只读分析、SQL 草稿、复制/插入/替换和数据库编辑器功能无回归。

## 5. 交付定义

满足以下条件才算本计划完成：

- AI 只读入口在数据库边界被证明不会执行变更。
- MySQL 和 SQLite 各有成功提交、预检不一致、验证失败、取消、超时、断连和重启恢复测试。
- 受控 DML 的审批、事务、验证、回滚、状态未知和事件/界面状态完全一致。
- DDL 与高风险语句仍保持草稿模式，未扩展为自动执行。
- 凭据隔离、结果限制、错误可定位和历史脱敏通过相关测试。
- 未新增重复连接管理、通用工作流或未实现数据库类型的虚假支持。
