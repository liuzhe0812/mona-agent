# 主会话画布工作区实施计划

- 状态：In progress
- 最后核对：2026-09-02

## 1. 产品边界

- 主会话是 AI 交互入口，右侧工作区承载生成状态、可编辑画布和多标签。
- 画布是工作区产物，不进入笔记模块。
- 复用现有 `FlowchartDocumentEditor`、`MindMapDocumentEditor`、文档模型和 patch 校验器，不复制编辑器或创建第二套 schema。
- 普通聊天不创建画布；只有明确出现流程图、思维导图或脑图的创建意图时才创建。

## 2. 已存在的实现基础

- `src-tauri/src/workspace_canvas.rs` 已提供 `.mona-canvas` 持久化入口。
- `webui/src/components/canvas/` 已包含主会话画布状态、文件预览和编辑容器。
- 画布文档已支持 `originChatId`，主会话和工作区产物可以恢复关联。
- `ThreadShell` 已能识别并打开 `.mona-canvas` 产物。

## 3. 必须保持的交互

1. 用户发送明确画布创建请求后，右侧立即建立空白画布骨架，不等待模型完成。
2. Agent 返回结构化结果后，以创建请求时记录的 base hash 校验并原子应用。
3. 当前画布打开时，后续会话请求携带画布标题、语义内容和 base hash；无关请求正常回答。
4. AI 生成期间用户已改变画布语义时，过期 patch 不覆盖当前内容。
5. 每张画布是独立标签，当前激活标签决定默认修改目标；新建画布不覆盖已有画布。
6. 主会话只显示自然语言说明，不展示内部 patch JSON。

## 4. 持久化契约

- 文件扩展名固定为 `.mona-canvas`，只接受 `flowchart` 和 `mindmap`。
- 写入当前工作区的 `canvases/`，保存 `originChatId` 和既有结构化内容。
- 自动保存必须是原子写入；保存成功后刷新工作区产物列表。
- 不依赖笔记仓库或 `notes_save_state`。
- 旧笔记画布迁移时复制到工作区，原文件不删除。

## 5. 剩余核对与收口

- 核对创建请求发送后是否在首个 token 前稳定显示骨架。
- 核对第二轮自然语言修改是否始终作用于当前活动画布。
- 核对用户手工修改与 AI patch 的 base-hash 冲突提示。
- 核对多个画布标签切换、重启恢复和工作区列表再次打开。
- 核对浏览器、终端和画布联合标签不会覆盖彼此状态。
- 为创建、修改、冲突、保存恢复和普通聊天不误触发补齐回归测试。

## 6. 完成标准

- 明确创建请求无需切换模块即可得到可编辑画布。
- 第二轮修改落在当前画布，过期 patch 不覆盖用户编辑。
- 手工和 AI 修改均可自动保存并在重启后恢复。
- 多画布标签互不覆盖，工作区文件可重新打开编辑。
- 普通聊天不创建画布，主会话不显示内部结构化块。
