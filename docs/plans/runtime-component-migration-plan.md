## 本轮开发计划

### 批次 1：全局任务与配置

- 在配置 Schema 中增加“需要时自动下载”开关，默认开启。
- 将安装任务从 Python/Node 专用模型扩展为统一的功能资源任务，并由 Gateway 单一管理。
- 同一资源复用进行中的任务；任务状态持久化，取消、失败和应用重启后可继续使用已有下载分片。
- 提供状态、开始、取消、配置更新和清理接口。

### 批次 2：独立功能资源页面

- 在设置侧栏增加独立“功能资源”入口，不再藏在通用设置中。
- 使用业务名称展示用途、下载大小、版本和安装状态。
- 支持自动下载开关、提前下载、取消、继续、修复和清理。
- 长任务离开设置页后继续，返回页面后恢复进度。

### 批次 3：首次使用接入

- Agent/Skill Python 与 Node 改为通过全局任务管理器按需准备。
- ASR、FFmpeg、yt-dlp、Pandoc、Computer Use 和 WeStock 依迁移顺序接入统一组件仓库。
- 视频渲染只检查系统 Edge/Chrome，删除 `npx` 动态下载浏览器的路径。
- 删除 OfficeCLI 的新下载、设置和新建任务入口；保留旧缓存探测，使升级不打断已有任务。
- 自动下载关闭时返回明确的“需要下载”状态；开启时下载成功后继续原业务操作。

### 批次 4：验证与收尾

- 覆盖配置持久化、任务去重、取消、断点续传、失败重试、修复和清理测试。
- 覆盖设置页加载、开关、安装、取消、继续、修复和错误状态。
- 运行相关 Python、前端测试与构建，并逐项核对完成标准。

## 迁移顺序

1. 建立唯一的全局安装任务管理器和设置页“功能资源”入口，先复用现有运行时目录，支持自动按需下载、提前下载、取消、继续、修复和清理。
2. 完成旧运行时的非破坏导入，再将统一仓库迁移到 OS LocalAppData。
3. 先迁移 ASR、FFmpeg、yt-dlp 和 Pandoc，删除各自生产下载逻辑。
4. 停止 OfficeCLI 和 Chrome 动态下载；迁移 Computer Use，统一任务状态、修复和清理入口。
5. 将 Agent/Skill runtime 的组件安装根迁入统一仓库，保留环境生成语义。
6. 最后迁移 WeStock 等低频模块专用运行时。

## 兼容导入

1. 新版本优先读取统一运行时仓库。
2. 带有 manifest 和 receipt 的旧 `.mona/runtimes` 活动组件执行校验后复制；旧 `resources` 和模块专用目录只做读取兼容，不伪造统一组件 receipt。
3. 复制到新目录的 staging 后复核 manifest、receipt 和入口，再原子激活；迁移阶段不移动旧文件。
5. Agent/Skill 的 Python 虚拟环境、Node 依赖和项目辅助目录不复制，在新根下按需重建。
6. 新组件成功激活后仍保留旧副本，只在用户从设置页主动清理时删除已知运行时目录。
7. 迁移中断、空间不足或复制失败时继续使用旧组件，下次启动重试，不阻断已有功能。
8. 无法验证或没有 receipt 的旧资源不导入统一仓库；自动下载开启时按需下载受管版本，关闭时等待用户在“功能资源”中操作。

## 完成标准

- 所有产品运行时可由同一目录 API 枚举。
- 所有网络下载经过统一大小、SHA 和状态记录。
- 功能首次需要未安装资源时能够自动创建全局下载任务，同一资源不会重复下载，成功后继续原业务操作。
- 关闭自动下载后，首次使用能够说明资源用途和大小，并等待用户确认。
- 设置页以用户可理解的功能名称展示全部受管资源和下载任务，并支持提前下载、取消、继续、修复和清理。
- 冷安装中断后可续传，失败不影响旧活动版本。
- 应用升级不重复下载未变化组件。
- 用户数据与可重建运行时之间没有目录混用。
- 生产业务路径不再使用模块专用下载器。

## 发布门槛

本轮只完成代码、组件制备和本地分发目录验证，不上传正式 CDN、不发布桌面版本。正式发布前需要将 `dist/official-distribution` 上传到配置的运行时分发源，并用发布环境再次验证目录、下载、安装和回滚。
