# Office 专业创作与实时协作

> 2026-09-09 入口整理：移除 doc-writing-guide、mona-office 和独立 docx 入口；PRD 专业内容迁入 prd-document，Word 高级参考、脚本及依赖迁入 mona-docx。下方为原阶段验收记录，当前入口规则以 docs/architecture/module-invariants.md 为准。

状态：代码实现与自动化回归完成；真实模型自然语言质量对比待在重启后的 dev 环境执行。开始于 2026-09-05，完成于 2026-09-06。

## 用户目标

- 将普通 Office 创作拆为 `mona-docx`、`mona-xlsx`、`mona-pptx`。Word 和 Excel 以专业性为先，PPT 以设计为先。
- 将 `mona-ppt` 的内容驱动表达、设计规范、层级、素材和质量检查经验转为可执行规则、操作样例和验收场景。
- 始终通过同一个 Office 编辑会话分批提交，保留真实编辑过程、人工修改与版本校验。

## 实施顺序

1. 三份专用 Skill 与按需参考：内容/设计判断、已实现操作、局部编辑和质量检查；整理旧入口的自动发现范围。
2. 编辑器专业能力：补齐常用 Word 页面/段落/表格排版，Excel 字体、边框、换行和行列尺寸，PPT 完整元素样式与设计检查。
3. 版本绑定的视觉回读和选区上下文：让模型同时读取真实渲染、结构和样式；沿用 Services 权限与 Editor 最终版本检查。
4. 回归与实物验证：Skill 发现/读取、协议、真实格式读写、三类编辑器渲染、人工编辑后冲突/继续、保存重开；记录实际结果与未完成项目。

## 边界

- 不修改旧 AI 文档 PPT 制作流程的职责，不将其确认点和独立预览流程复制到普通会话。
- 编辑器模型是唯一当前内容源。设计指南、SVG 或样例不能覆盖后续人工编辑。
- 三份 Skill 只描述确实可调用的能力；不支持的高级功能不能通过写文案冒充实现。
- 不用新建成品后整份导入替代实时创作，不将截图识别用于覆盖结构化文档读取。
- 保留已有未提交工作；不提交、发布或重启用户的运行任务。

## 验收

- 三份 Skill 能被正确发现，旧通用入口不竞争普通创作。
- Word 的标题/段落/表格与页面设置保持语义；Excel 的值、公式、类型、格式与尺寸保存后仍一致；PPT 的文本/形状保持原生可编辑对象。
- 新建、修改已有文档、局部修改和人工插入修改均走版本绑定的 Office 操作。
- 视觉结果来自当前编辑器并携带版本；无法渲染或能力缺失时返回明确错误。
- 记录定向测试和构建，不将自动化接口检查称为真实模型自然语言验收。

## 结果

- 新增 `mona-docx`、`mona-xlsx`、`mona-pptx`，旧 `mona-office` 退出普通自动发现；`docx` 只承担实时编辑器不支持的高级离线能力。
- Word 增加块级样式回读、页面与表格排版、默认页眉页脚和页码、当前选区与真实页面视觉回读；历史 checkpoint 不替换用户当前编辑。
- Excel 增加字体、字号、对齐、换行、边框、行列尺寸、筛选、冻结窗格和条件格式；范围读取返回尺寸与展示状态，全部进入 revision、rollback 和原生 XLSX checkpoint。
- PPT 增加新建元素的完整字体/对齐/描边、元素样式与选区回读、原生表格/图表/SmartArt 的已验证示例，以及复用真实 `SlideCanvas` 的页面 PNG 回读。图表样式已验证保存重开。
- 三类 visual 都绑定文档版本。浏览器实测成功返回 Word 页面、Excel 当前工作区和 1280×720 PPT 页面；实测发现并修复过 PPT 空白截图问题。
- 自动化结果：Office Python 定向回归 86 项通过；Office editor 31 项通过；三份 Skill 校验通过；Python ruff、Office editor 与主 WebUI TypeScript 检查通过；Office editor Tauri 资源构建通过。
- 已知边界：Excel 普通 Agent 暂不新增原生图表，保留已有图表；首节、偶数页和复杂多节 Word 页眉页脚仍按具体文件验证。真实模型自然语言生成的审美/专业质量需要在 dev 进程重启加载新代码后做同题对比，不能用接口测试替代。
