# Mona 可动形象美术制作与审核

## 当前方向：三种状态和统一表演

2026-11-08 用户补充：区分休息、工作、对话三种状态；休息应有自然 idle，其他状态也不能长期静止。休息姿态已单独绘制并建立技术模型，呼吸和头动可采样，但变形会轻微带动椅背、手和发饰，眨眼中间态有重影。2026-11-09 的单眼重新分层试验消除了两套睫毛交叉，后续蒙版样片也消除了闭眼虹膜残留，但眼白仍有硬边、中间态睫毛悬浮；继续扩大使用前需获得质量可靠的独立眼皮、眼白及睫毛素材。当前动作帧仅用于技术预览。实时渲染、自然动作及语音联动尚未完成，不以静态姿态或预渲染循环代替最终验收。

2026-11-09 休息动作修正：`rest-rig/model-v04` 将呼吸变形限制在独立上衣网格；实际极值采样显示椅背与双手不再跟随呼吸，但幅度很小，头动仍可能轻微影响椅背。新的循环帧用于场景技术预览，眼睛保持睁开；自然眨眼及最终美术质量仍待完成。

2026-11-09 桌沿修正：用户指出休息姿态右手穿入桌面和笔记本。手原本位于椅子扶手上，现使用沿桌沿的休息态专属前景将其遮在桌后；工作与对话仍使用原遮挡，工作时双手保持在键盘前层。

2026-11-06：用户否定连续人椅转身的效果，提出以工作、对话两种姿态为基础，通过渐隐等转场切换；每种姿态只让实际需要的部位运动。先确定整体行为与画面，再按动作需求设计分层。v05 连续转身模型不再作为质量基线，也不继续围绕它做局部修补。

2026-11-07 中断恢复：已找到两姿态的[动态审核片](../../design-assets/11-fullscreen-office/rig/two-modes-v01/final-review-v01/two-mode-dynamic-review.mp4)及[导出记录](../../design-assets/11-fullscreen-office/rig/two-modes-v01/final-review-v01/review-report.json)。审核片由两个模型的动作帧合成，约 10.5 秒，无声音；对话工程 v06 已重新打开并导出。该片用于整体方向审核，尚未通过美术验收，也不代表语音同步或真实交互已接入。检查发现对话手掌与背景笔筒重叠，转场时人物与椅子会短暂消失；对话眼球极限位置可见边缘重影，工作闭眼仍有细色缝。需结合完整动态由用户判断方向和自然度，再确定是否修正，不以单项导出成功代替审核。

2026-11-07 再次纠正：用户指出上一版仅调整大小与位置，没有解决人、椅与笔记本的朝向和纵深关系。已重绘[工作姿态方向预览](../../design-assets/11-fullscreen-office/rig/two-modes-v01/work-pose-perspective-v03/work-pose-perspective-preview.png)：人椅共同朝向电脑，身体位于桌沿后方，手放在键盘上。它是整体静态重绘，背景和电脑位置也有生成偏差，并非已绑定的模型或固定背景合成结果；待方向确认后仍须匹配固定场景、制作分层、遮挡和动作绑定。

### 画面与切换

- 使用同一办公室机位、桌面和电脑位置。工作姿态看向笔记本，对话姿态面向用户；两套图保持同一角色脸型、耳饰、衣服、光线和比例。
- 角色和需要随姿态变化的椅子作为一个表演组，先淡出旧姿态，再淡入新姿态；室内环境、桌面和电脑保持稳定。初始转场约 0.3–0.5 秒，按实际视觉调节。预加载两套资源，避免切换时等待加载。
- 桌面、笔记本和角色按遮挡关系分层；工作手需盖在键盘上时，单独安排对应的前臂/手前景。不能把整张画面直接压在角色上或让身体穿过桌面。
- 两套是独立姿态资源、同一角色；具体是否打包为一个模型或两个模型，以实际质量、运行开销和工具能力验证后决定。

### 按动作决定分层

| 部位 | 首版需要 | 说明 |
|---|---|---|
| 头部 | 脸与必要的遮挡补绘；头部及跟随的发、耳成组 | 只做小幅自然动作；头发或耳饰若需要可见的独立跟随再拆，不追求拆分数量 |
| 眼睛 | 眼睑、眼白、虹膜等支持眨眼和视线 | 两眼可以共用眨眼控制，素材仍按实际遮挡拆分 |
| 嘴 | 上下唇及口腔等支持开合，补足隐藏皮肤 | 有实际语音时驱动口型；静音时保持自然静止或只做表情 |
| 手臂与手 | 工作姿态按键盘遮挡拆必要部位；对话姿态只为确实需要的手势拆一只手/前臂 | 不默认拆十根手指；先确保手型和接触正确 |
| 身体、椅子、固定衣物 | 可随姿态作为静态部分 | 是否拆胸肩用于呼吸、发束用于跟随，以实际效果为准 |

官方素材教程同样要求依据运动范围补全被遮挡区域，并分别处理眼睛与口腔：[Illustration Processing](https://docs.live2d.com/en/cubism-editor-tutorials/psd/)。两套大幅不同的姿态不直接半透明重叠，避免出现双脸、四手。官方对模型内部的部件切换也提醒淡化可能产生重叠与透底；这里的人物组淡入淡出是画面层的另一种处理：[About Fading](https://docs.live2d.com/en/cubism-editor-manual/about-fade/)。

### 行为及触发

| 行为 | 表现 | 事件依据 |
|---|---|---|
| 待机 | 低频眨眼、轻微视线变化，可克制地呼吸 | 空闲和一段时间无交互 |
| 听用户 | 对话姿态看向用户，适度点头 | 输入已接收；实时语音倾听需要后续语音事件 |
| 处理中 | 工作姿态看屏幕，按已知活动选择轻微输入或阅读 | 现有处理中状态；没有细分事件时不臆造具体操作 |
| 回复 | 对话姿态、相应表情和少量手势；只有语音播放时同步口型 | 收到回复及可选表演字段；语音事件后续接入 |
| 需要决定/异常 | 停止当前动作、看向用户并给出相应提醒 | 仅在有明确的待确认或失败事件时触发 |
| 完成 | 短暂的轻松表情或指向屏幕的手势 | 仅在有可靠的任务成功事件时触发 |

远眺、喝水、伸懒腰或与猫互动可作为以后评估的生活化动作；它们需要额外姿态、道具或遮挡素材，不纳入首版。语义行为叠加在两种基础姿态上，不为每种情绪单独做一个完整模型；表演不能改变真实任务执行状态。

### 现有能力与验证顺序

当前独立交互端已具有输入接收、处理中、回复结束、连接错误及可选表演字段；办公室页面尚未接入可动角色。真实工具执行、等待授权、任务成功等独立事件尚未送到该交互端。`interaction/mona_interaction/app.py` 当前将上游失败终态也发成 `reply.completed` 且未透出结果状态，`web/app.js` 将其记为完成；因此不能据此触发成功庆祝。需要后续补齐权威结果状态，不能根据动画或回复文本猜测成功。

先设计和核对两张同场景静态姿态，再按上述动作拆图、补绘和绑定。首个端到端审片同时覆盖工作、一次转场和对话：包含眼神、眨眼、一个可辨认的小手势及口型测试。演示事件和示例音频须明确标注，不视为真实任务或语音接入。验收应看完整动作、原画相似度、手部接触和转场连续性；局部网格、导出成功或高帧率不能替代美术审核。自然度达不到时停止扩大制作。

## 目标与范围

先产出可供用户判断质量的 Mona 可动形象，再决定是否继续交互功能开发。当前只推进原画、分层、绑定、动态修形及美术审核材料。已有交互代码保留，不继续扩展语音、Agent 或部署功能。

制作人员只有用户与 Codex；工具安装、AI 素材处理、自动绑定、可通过代码完成的修形、导出和验证由 Codex 执行。用户负责形象及动态效果审核。确需手动操作时提供具体位置和步骤，不把整套建模学习交给用户。

## 质量检查

- 身份：保持柔和收窄脸型、红棕杏眼、深棕黑长卷发、黑红猫耳和米白耳毛、黑红外套与猫袖章；按用户最新要求，不保留项链，唯一耳环位于画面左侧，采用官网参考的红框镂空菱形及底部小菱形坠饰；不采用历史蓝眼版本。
- 静态：透明边缘干净、耳尖和侧发完整、五官清晰；保持原画的细线与柔和暖色明暗，不通过模糊掩盖问题。
- 眨眼：睫毛与眼皮闭合自然，眼球不会浮出眼框，睁闭过程中没有遮挡穿帮。
- 嘴型：闭嘴可回到自然状态，开口有完整口腔；微笑、说话和转头组合时不撕裂、不拉扯整张脸。
- 转头：先保证日常对话所需的克制角度；检查发际、脸颊、鼻口和耳朵，不以夸大角度牺牲外形。
- 物理：发束、耳饰等运动有轻微滞后与回摆，静止时没有抖动或持续大幅摇摆。
- 验收：动态必须来自真实可动模型；生成的视频或独立表情图片不作为完成绑定的证据。
