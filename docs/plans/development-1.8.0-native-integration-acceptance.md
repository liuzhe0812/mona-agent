## 1. 本批次实际实现

### 1.1 原生执行链路

`DevelopmentView / Pane / Executors / Decisions / Collaboration` → 受保护的 Gateway `/api/development` → `DevelopmentRuntime` → `NativeExecutorManager` / `NativeRunService` → Codex App Server 或隔离的官方 SDK Worker。

普通外部任务直接交给选定执行者；不会先调用 Mona 内置模型重述需求。每个产品会话保留独立原生绑定。外部执行者、内置模型 Provider、产品会话和一次 Run 保持分离。

Codex 由结构化 App Server 管理线程、轮次、消息、确认、取消和可读取的历史；Claude Code 与 CodeBuddy 使用同一个窄 SDK 宿主协议、各自的官方 SDK 类型和独立子进程，不模拟终端文字。

### 1.2 Cindy 的具体参考

本地参考锁定提交：`92294b7ead54fab8edabbf57cdc11db903c501c9`。

- `packages/maker-core/src/agents/codex/app-server/client.ts`：请求与回执关联、NDJSON、连接断开与未知结果边界；参考文件 SHA256 `0bf43f1d54b917fe1aa2f5226353d956359e4a19b58a362c0e68b416b0d20792`。
- `packages/maker-core/src/agents/claude-code/env-builder.ts`：SDK 再次合并父进程环境的问题；参考文件 SHA256 `159e8f2d1fb1814cf23949a7b137edf56d1f5aa4e2ab31ab83967190aae8700a`。

Mona 的区别：启动隔离 Worker 时就构造最小环境，不修改 Gateway 的全局环境；同项目不同会话可并发，不设置项目级单写锁。

### 1.3 续编和恢复

- 空闲连接退出后，下一次任务恢复原生会话，不新建替代任务。状态未知的正在执行任务不能借此重新发送。
- 完整/增量交接保留原生绑定。交接必须在执行者明确接受后才记为交付；拒绝和结果未知分别处理。
- 独立记录 `native_dispatch`，不能把本地分配的 SDK 轮次标识当成供应商已接受的证据。
- 上游返回排队但没有可靠接受证据时，状态归为待核对，而不是永久停在 preparing 或伪称执行中。
- HTTP 未知结果返回可识别的 503，不会被通用业务异常处理提前改成 422，导致前端丢掉原请求标识。
- 同一请求的重试只核对同一 Run，不能自动重放副作用。

### 1.4 协作和结果归属

- 用户可从侧栏创建独立协作任务，选择执行者与只读范围。内置 Coding 有按需委派能力；不要求创建协作房间。
- 首次原生协作请求会收到明确授权的父会话摘录；后续轮次不重复灌入同一份起始资料。
- 交接摘录保留来源说明和完整 JSON；超长时按完整消息移除，并记录省略数量，不截断成失去来源的半段文本。
- 结果绑定最初派发的精确 requestId / runId，而非子会话“最新一轮”。子会话后来继续聊其他问题，不会把后来的答案当成原审查结果返回。
- 同一协作结果只回传一次；收到结果不自动重跑父任务。

### 1.5 原生问题与权限确认

- SDK `AskUserQuestion` 使用专门的问题桥，不被权限布尔值代替。
- 回答绑定具体会话、轮次、问题 ID；未得到全部有效回答时不伪造默认答案。
- 允许/拒绝/取消与用户回答分别处理；确认超时不会把任务永久留在等待用户。
- UI 用 fieldset/legend 组织多问题选项，避免 label 嵌套按钮导致无障碍名称错误。
- 正在提交和提交成功后禁用重复确认；界面等待实际执行事件继续，不因点击就宣称任务成功。

## 2. 内置 Coding 的长会话整理

新增 `mona/development/compaction.py`。这是当前开发会话的工作摘要，不是普通 Mona 的长期记忆或项目画像。

在新一轮入口使用已解析的实际模型窗口、输出预算和现有自动整理阈值估算上下文。只在完整用户轮次边界整理已完成历史，保留当前用户请求原文及原始会话全部记录。

摘要与游标一起持久化，保存成功后才进入本轮请求。空摘要、长度截断、模型失败、取消、磁盘错误、来源历史被修改、整理后仍超预算，均不会静默推进游标或删除历史。整理时追加的后续消息仍保留。

当前范围是轮次入口整理；不宣称已实现所有超长单轮中途的无损压缩，也不把某个模型返回的摘要当成事实审计结果。无法安全整理的单轮超大输入会明确失败并保留原记录。

## 3. 配置与打包

执行者设置保存的是原生程序路径与认证环境变量名称，不保存密钥值。修改尚未保存时，连接检查和登录按钮禁用，避免拿旧路径检查后误导用户。

- Codex：官方 App Server 路径与受管登录。
- Claude Code：官方 SDK 与明确的 API Key 环境变量来源；不伪造个人订阅登录。
- CodeBuddy：官方 SDK 路径，提供官方认证链接入口和 API Key 环境变量来源。
- 项目规则与项目 Skills 共用同一项目来源；用户配置、用户 Skills、自定义 MCP、Hooks 和普通 Mona 私有记忆不自动加载。
- 当前只接受可核对的原生可执行路径；任意 `.cmd/.bat/.ps1` 包装脚本不是受支持的通用启动入口。不能把找到包装脚本视为已兼容。

开发依赖声明与运行检查对齐：Claude SDK `>=0.2.134,<0.3.0`，CodeBuddy SDK `>=0.3.264,<0.4.0`。这是接入基线，不代表每一个区间版本已经做过实机认证验收。

`mona-gateway.spec` 显式收集动态导入的 SDK Python 模块和发行元数据，排除 SDK 自带原生二进制副本。缺失必要 SDK 时构建明确失败，不能打出显示三个执行者却缺少调用代码的安装包。外部原生工具仍须遵守统一运行时管理规则，不新增功能下载器。

真实模型页面验收另外使用生产 Coding 和用户当前配置模型，在 output 隔离项目上进行，不给模型预编排文件修改操作，也不修改用户真实项目。

## 5. 仍不属于完成证据的部分

1. 三家官方 CLI + 受支持 SDK + 用户授权认证的真实任务与隔离验收。
2. 完整桌面 Tauri 原生浏览器、终端、主窗口切换与重启的组合验收；独立 Chromium 页面不能替代这些。
3. SDK 不提供精确轮次历史查询时，unknown 恢复保留明确能力边界，不能假称已核对或自动重跑。原生历史明确失效时的完整替代绑定回退仍需按可靠错误分类补齐，网络/认证失败不得触发回退。
4. 长单轮、大仓库、多任务压力、可访问性与完整安装包/升级发布矩阵。
5. 正式方案剩余验收项逐项覆盖；本文件不是发布完成声明。

## 6. 工作区与使用

所有源码在当前项目工作区；正常重启完整 dev 才会加载新 Python 服务与桌面桥。没有主动重启用户 dev、没有推送远端、没有发布安装包。

提交时只包含开发模块相关源码/测试/设计记录。工作区存在其他模块的并行修改，不能 `git add -A` 整体提交。原有 `src-tauri/Cargo.toml` SHA256 保持 `a0b43ee6d6829c722de456c065174a8cdb0d1bb33a0b099a0694033ac0b2dc68`。

当前仍观察到 `.git/index.lock`，尚未删除、未强制停止 Git 进程；提交状态应以最终 Git 检查为准，不以文件写入成功代替 commit。
