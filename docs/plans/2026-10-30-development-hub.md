# Mona 开发中枢实施计划

日期：2026-10-30

## 目标与范围

用户在 Mona 普通聊天中即可查看开发工作台的项目和会话，创建开发会话，向已有会话派发或补充任务，查询真实开发状态，并在来源聊天接收开发结果。

第一版复用当前 Gateway 开发服务、DevelopmentStore、SessionManager、权限与输入队列。开发会话保持工作台内的正常会话身份；不建立第二套执行器、项目数据或聊天副本，不新增管理页面、下载器、全局文件锁或自动开发流程。

## 实施步骤

1. **主助手工具接入**
   - 提供项目和会话查询、会话详情、项目文件与差异读取、会话创建、任务发送及来源任务查询。
   - 工具只装配到桌面 Mona 主助手；专家、开发子任务和官网隔离 Work 不获得跨项目协调权限。
   - UI 与工具共享唯一的开发运行实例、模型来源校验及发送路径；项目内读取复用规范路径校验。
   - 项目和会话列表返回可分页的简要信息，历史和证据按需读取；不把全部历史注入 system prompt。
2. **来源关联与可靠派发**
   - 来源渠道、聊天和会话身份由可信工具上下文获取，模型只选择目标项目、会话与任务内容。
   - 在现有开发数据库保存来源、请求标识、目标和发送回执；重试相同请求不重复创建或执行，改变请求内容必须拒绝。
   - 空闲会话开始执行；活动会话默认排队后续任务；明确纠偏绑定当前轮次并检查执行者能力。未知执行不重放。
   - 创建会话采用当前开发默认权限，保留只读约束，不提供模型自行升权的入口。
3. **状态观察与结果回传**
   - 后台根据现有更新信号观察所派任务，解析排队输入与实际 Run 的关联。
   - 完成、失败、待确认和结果未知时，向来源聊天保存并发送可追溯通知；通知不作为新的用户开发指令，不自动派发任务。
   - 通知携带真实状态和结果读取引用，明确任务结束不代表测试或交付验收通过。
   - 通知去重并可在重启后继续核对；来源聊天或开发会话删除后不重建聊天，不恢复已删除内容。
4. **验证与文档收尾**
   - 必要测试覆盖工具注册隔离、真实项目/会话读取、项目路径越界、模型和权限校验、幂等创建及发送、活动会话排队和纠偏、未知状态拒绝、结果通知及重启去重。
   - 使用本地临时数据和假模型验证执行链路，不向真实开发项目派发任务。
   - 运行变更文件 Ruff 和对应测试；更新模块长期约束及本计划验收记录。

## 验收场景

- “看看有哪些项目正在开发”：列出工作台实际项目、会话与运行状态，保留未知和读取失败。
- “给这个项目建会话处理登录问题”：创建工作台可见会话，发送一次任务，同请求重试可定位原结果。
- “让刚才那个会话补充验证码处理”：通过来源关联找到目标，会话忙时排队；明确纠偏时绑定实际活动轮次。
- “检查项目能不能交付”：能读取计划、历史、文件和 Git 差异，区分已报告结果与已验证证据。
- 开发任务完成或受阻后，在来源聊天收到一次对应状态通知；通知不触发后续开发执行。

### 2026-10-31 实施说明

- 主助手提供 `development_workbench` 单一工具，支持项目/会话查询、详情、项目文件与差异读取、会话创建、任务发送和来源任务列表。
- 新增 `session_creation.create_session` 供 UI 和工具共用。`hub_requests` 在原开发 SQLite 内记录请求来源、内容指纹与回执；普通 Mona 和原生引擎沿既有发送、权限、审批与排队协议执行。
- 来源聊天删除后的迟到派发在实际开始前拒绝；丢失回执和重启只查询 Run/Input/创建记录，不重放执行。结果通知同时保存在 Agent 历史与 WebUI 独立背景记录，审批仍在开发会话处理。
- 验证使用临时目录、假模型和真实 Runner/API/回放链路，没有向用户现有开发会话派发验收任务。
- 后端主链路、创建和工具相关用例 36 项通过；显示历史与背景结果回放用例 18 项通过。后台观察器自动回传另通过 Gateway 工具与 HTTP 共享运行态的集成用例。
- 前端 4 个相关测试文件合计 203 项通过，`tsc -p tsconfig.build.json --noEmit` 通过；变更 Python 文件的 Ruff 检查通过。
- 普通 Work 的正文和思考流在实时消息与回放间保留 `streamId`。通知触发刷新时保留本地流式消息身份、内容和后续输出，不把相同 taskId 或相同正文的独立答案合并，不结束来源任务。
- 代码由下次 Gateway 启动装配，重启 Mona 后生效；本次实施不涉及安装包发布。
- 扩展回归发现三个已有失败，用内存移除本次相关改动后仍可复现，保留原状：`test_tool_loader_scopes.py::test_exclusive_tool_ownership_rejects_a_forged_expert_allowlist` 的旧股票工具断言；`test_workbench_runtime.py::test_interrupted_dispatched_guidance_does_not_return_as_a_pending_input` 的中断纠偏断言；同文件 `test_readonly_context_and_external_executor_no_model_fallback` 的旧只读工具清单断言。
