# 代码模式会话渲染

- 状态：Accepted / Implemented
- 更新：2026-10-30

## 统一边界

Mona、Codex、Claude Code、CodeBuddy 使用同一条正文渲染链路：

`执行器事件 → 会话记录 → public_message → DevelopmentTranscript → ZCodeMarkdown → MessageResponse / Streamdown`

渲染组件不按执行器选择 Markdown 语法、样式或媒体能力。执行器适配层负责事件身份、文本增量与完成态替换；`display_content` 负责将公开文本和媒体块投影成统一的 `content` / `media` 字段。私有推理和工具调用参数不能因内容兼容而进入正文。

- Codex 的公开 agentMessage 文本继续使用现有 delta / completed 事件。
- Codex 的 userMessage 回显不转换为工具事件；用户消息由 Mona 原记录显示。前端过滤旧记录中误分类为工具的 userMessage，避免出现空参数卡片。
- Codex `imageGeneration` 仅在成功完成时产生图片附件，保留工具事件身份，不作为模型回复确认引导输入。优先读取原生 `savedPath`，复用内容寻址媒体仓保存副本；公开消息仅持久化项目所属的 `mona-media:` 引用，通过已有认证媒体接口读取，不将大段 base64 放入历史或放宽任意文件读取。
- 旧记录中已完成但未呈现的图片，只按原 Run、绑定、原生会话及图片 item 标识读取已有默认产物并补齐附件；恢复不启动模型、不重复插入、不移动或删除原图，附件仍归属原轮次。
- Claude Code 与 CodeBuddy 共用 SDK 内容块转换；完成消息包含媒体时，正文仍存为字符串，附件单独存为 `_display_media`，经过现有原生记录与重放链路持久化。附件字段只用于显示，避免供应商内容块格式进入其他引擎的请求或破坏协作结果回传。
- Mona 的结构化会话内容通过同一 display projection 转换。
- 不推测执行器未提供的附件。已识别但来源不支持的媒体显示不可用提示，不能静默丢失。
- 正文保留完整 Markdown，不在 24,000 字符处切断代码围栏、表格或公式；原有执行器消息准入上限继续生效。工具日志仍有有界预览与完整记录入口。

## 前端

### 待发消息

普通队列与待引导列表按 `delivery.admitted` 分开投影。点击“引导”会沿用原 input ID，将现有队列项原地改为 `guide`，并显示在原任务的待引导列表中；准入和列表显示不代表模型已收到。队列项的来源命令、客户端 ID、顺序及附件显示元数据保持不变。

引导只在合法的模型响应或完整工具批次边界注入。注入时，待引导项转为正式用户消息，并用原 input ID 与正式 message ID 建立映射；正文保留原输入、附件和显示元数据，不重复创建消息。正常结束时若无法安全注入，guide 也以原 ID 改投普通队列，不当作已发送；之后的派发遵循队列授权。

用户在注入前停止时，未注入的 guide 沿原 ID 改回普通队列并暂停，等待用户显式恢复，不会自动执行或被标记为已发送。已经注入的输入保留为正式对话消息，停止后不重新入队。只有明确撤回才取消未注入输入；结果未知时不自动重放。待发项在正文未加载时使用保存的原始文字或附件名称，不能误显示成“0 张图片”。

待处理输入按会话和持久状态查询，不受最近轮次数量或正文分页影响。停用原生来源后，尚未派发的消息保留在原待发队列，可经既有编辑或撤回操作处理；重新启用来源本身不重新发送。宿主重启时，仍处于 `queued` 的 Run 尚未跨过派发边界，以失败结束并释放会话，保留请求身份；已有派发的未知结果仍只核对，不自动重放。

新任务在首次发送时创建正式会话。项目草稿页的文字、附件引用与模型选择使用开发工作台现有持久状态保存，创建期间的新输入不能被较早发送完成后的清理覆盖。创建前持久保存创建请求身份、冻结参数和首条消息身份；响应丢失或窗口重挂载后，用户继续上次提交时复用原记录，不自动换 ID。相同项目和请求 ID 返回原会话，不同参数明确冲突；删除会话后保留最小请求墓碑，不因旧请求重试重新创建。创建回执与原消息在前端一次持久更新后交给原有发送链路，保留新草稿和其他未确认发送；本地存储不可用时不派发创建。

用户可以放弃尚未确认的创建提交。服务端取消按原项目、创建 ID、冻结参数及首条消息 ID 核对，在与创建、Run 和队列接收相同的事务边界登记墓碑；未接收时拒绝迟到创建和原首发，已接收时保留原任务，不删除会话或停止任何 CLI。不同参数的意图由原不可改写的指纹明确拒绝，只结束该意图的本地等待，不改动原记录；相同参数但首条消息 ID 不一致仍报冲突。前端先持久记录取消意图，取消回执未知只允许继续核对取消。为避免另一窗口的旧工作台快照覆盖取消，只有未确认的取消使用按项目和请求 ID 分开的临时 outbox 键，确认后逐项清理；不保存前端永久取消日志，不覆盖其他待确认提交或当前草稿。

引导消息已保存为正式用户消息但没有消费回执时，未知输入仍进入待处理事项，不作为可编辑或可再次发送的队列项。只有原轮次已结束且不再派发时，用户核对任务和文件改动后才能结束该消息的等待；保存 `closed_unknown`，只表示结束跟踪，不表示已消费、已撤回或成功。原始正文与请求身份保留，重试原请求只返回旧记录。开发存储版本升至 5，保留 v3/v4 原有数据、创建回执及新取消记录；旧客户端拒绝读取新版存储，不能绕过输入状态或取消墓碑。

Codex 自动核对原轮次后，只有完整原生历史确认进入 `WAITING_CHILDREN` 才安排既有必要结果整合，继续使用原负责人、绑定和权限。普通成功轮次恢复仍只读观察，不从恢复入口派发后续用户队列；未知或不完整原生历史不启动替代任务。必要结果整合结束后的队列顺序仍遵循正常执行路径，不重放原轮次。

### 任务标题

Code 根任务以第一条用户消息作为初始标题，列表、悬停详情与顶部标题使用同一持久化记录。创建时直接采用输入文字，压缩连续空白，超过 200 个字符时保留前 199 个字符及省略号。已有默认标题在读取时按第一条可见用户消息补齐；附件使用用户输入或可见附件名称，不把解析正文、内部注入和排队占位作为标题。手动重命名、子任务、只读讨论及分叉标题继续保留。

### 任务摘要

摘要按当前会话栏的可用宽度布局，至少保留 640px 对话空间。能容纳右侧卡片与间距时，摘要占用独立列，宽度在 280–300px 之间适配；不足时使用 300px 浮层并受会话栏边界约束。切换位置保留同一对话与输入框，维持输入、焦点和阅读位置。右侧摘要允许继续操作对话；浮层保留外部点击关闭，关闭和 Escape 恢复开关焦点。

已有的结构化计划在任务概览中独立显示，不依赖 Git 是否可用；没有计划时不显示占位或推测步骤。

标题栏与摘要中的鼠标提示使用共享 Tooltip，不使用浏览器原生 `title` 提示。提示仅显示对应动作或已有详情，沿用统一黑底、白字、圆角和阴影。展开摘要保留当前焦点，不强制聚焦关闭按钮；提示由悬停或主动键盘聚焦触发。

### 后台命令

输入框左下角在有运行命令时显示终端图标和数量，点击查看命令与运行时长，选中后在既有右侧终端区持续查看输出或停止。打开详情不创建手动终端；关闭视图、切换任务或隐藏模块不停止进程。数量与状态来自原会话快照，停止精确绑定会话和命令编号，未观察到进程退出不得显示已停止。

首版仅观察 Mona 托管的执行会话，不推测原生 CLI 的后台进程。界面读取使用独立的只读输出投影，不消费模型轮询缓冲，不重发命令或更新工具历史。预览保留最近 50,000 字符并明确标记截断；当前后台运行环境中保留最近 8 条已结束命令供详情读取，不将这些临时记录宣称为重启后可恢复的进程或完整日志文件。

### 上下文用量

对照 Cindy 的 `packages/model-providers/src/modelDiscovery.ts`、`apps/desktop/src/shared/sessionContextWindow.ts`、`apps/desktop/src/main/maker-host/codex-context-window.ts` 和 Claude translator：明确区分目录默认值、已确认容量、原生可用窗口及累计计费。Claude Python 字段同时核对 [SDK v0.2.134 的结果解析器](https://github.com/anthropics/claude-agent-sdk-python/blob/v0.2.134/src/claude_agent_sdk/_internal/message_parser.py#L279)，其将原生 `modelUsage` 保留为 `model_usage`。

Work 和 Code 共用输入框用量显示。计费累计与当前上下文分开：上下文采用最近一次模型请求的输入与输出，Anthropic 输入包含缓存读取和缓存写入，OpenAI 的缓存字段不重复相加。压缩后允许用量下降；没有单次请求数据的旧记录不使用累计消耗冒充占用。

内置模型由 Runner 上报每次请求用量及已确认的生效窗口，Work 通过独立 `context_usage` 消息更新，最终随会话记录持久化；Code 写入 `usage.updated` 事件并按序重放。Codex 使用 `tokenUsage.last.totalTokens` 和原生 `modelContextWindow`（可用窗口），不套固定百分比还原容量。Claude/CodeBuddy 使用主会话流的 `message_start/message_delta` 用量及主模型对应 `modelUsage.contextWindow`，子任务不覆盖父会话。事件携带模型路由，切换后不沿用其他模型或供应商的窗口。

窗口优先采用当前运行时实报，再用当前供应商明确的模型目录/探测字段；未知时不把统一执行预算显示成已确认容量。供应商探测的窗口字段须贯穿模型设置和保存，不可在刷新清单时丢弃。

### 流式工作过程

开发模式以本地 `ZCode` 成熟实现为首版基线，直接移植组件及其依赖；不能先简化重写交互，再以“参考过源码”替代复用。后续变化由实际使用反馈驱动。

`development/zcode/` 包含原版轮次分段、工具分类和分组、Reasoning、ToolLayout、摘要动画、Markdown/代码/表格/图片、diff、滚动锚点与测高缓存。许可证、原始路径、SHA-256 和适配差异保存在各子目录；文件图标保留 Material Icon Theme 的 MIT 归属。

Mona 负责将现有消息、事件和项目资源接到这些组件。文件、链接、完整日志和右侧预览使用真实宿主入口；不增加空回调伪装功能可用。后台执行、授权、会话存储和项目路径范围仍由 Mona 拥有。

原始 `styles.css` 使用独立 Tailwind 4 编译，限制在 `.zcode-stream`；不改全局 Tailwind 3。保留原字阶、颜色、间距与动画，处理两个版本的 CSS 层级和 transform 叠加。图标和 class 合并使用与上游一致的版本别名。`npm run build:zcode-stream-css` 可重建生成样式，开发/构建脚本会先执行它。

- 工作标题在首条正文之前出现；运行中过程展开，完成后过程默认折叠，最终回复保持可见。
- 思考、工具和正文按事件序号及精确消息身份排序；调用开始、增量输出、完成共用同一行。
- 子智能体调用归入同一轮可折叠的执行过程，展开后保留调用时序和详情入口；已有调用行不再重复插入结果回传行，回传不能拆出第二个工作标题。调用行按当前真实子任务状态更新，失败不显示为完成。
- 等待或查询操作失败与子任务执行状态分开呈现，不创建整体协作失败行。子任务详情按原派发 Run 的请求消息 ID 隐藏内部提示词，原始历史与模型输入保留，用户后续交流继续显示。
- 连续查阅/终端调用从第二项起聚合，身份固定到第一项；思考和正文形成分组边界。
- 只在当前实际运行的轮次末尾显示一个加载标记；等待确认、未知结果和结束态不显示旋转标记。
- 已加载事件不再按最近 256 条、活动不再按最近 30 项截断，避免长任务中早期步骤消失。
- 思考使用独立的开始、增量和完成事件：Codex 只接公开 summary，SDK/Mona 接执行器已提供的显示文本，不读取密文、签名或 redacted payload。思考不混入最终正文；没有显示文本的阶段不伪造内容。
- SDK 工具参数增量进入上游原有的部分 JSON 预览，完整参数和完成快照更新同一调用。带 index 的正文块各自保留身份，避免把工具前后的文字合并到同一位置。
- 空参数和空结果不生成展示区块；确认失效等系统确认记录只展示实际状态，不作为工具调用展开内部 JSON。
- 子智能体调用与结果回传在主会话中显示任务图标、中文短标题和实际状态；点击进入右侧子智能体标签的对应详情。完整任务结果继续用于主引擎接续，主会话不展开协作参数、原始 JSON 或结果正文。
- Mona 正文检查点落盘后清除对应的临时流式正文，避免同一段在过程和尾部重复出现。

ZCode 专有的 CUA、工作流、分享和后台子任务协议不进入 Mona 的移植目录。

`DevelopmentMarkdown` 给主会话、侧边聊天、子智能体会话传入各自项目和会话上下文。开发会话走复制的 ZCode 渲染链路，普通 Work/笔记等模块仍使用自己的 Markdown 入口。

- 表格：横向滚动、复制 Markdown、CSV 下载、预览；保留列对齐，CSV 转义单元格并防止公式前缀被表格软件执行。
- 公式：KaTeX；支持美元及反斜杠括号分隔符，普通价格与部分 shell 变量有防误判处理；超宽块公式独立横向滚动。
- 代码：原版 CodeBlock/CodeViewer、Shiki 和 Pierre 渲染；复制、换行和语言预览保留原交互，流式期间延迟高亮和图表渲染。
- 图片：加载与失败状态、相邻图片排版、消息内画廊；项目媒体资源通过 blob URL 展示，源或项目变化、组件卸载时释放 URL。
- 音视频使用原生播放控件；PDF 作为可下载附件。Markdown 中的本地媒体链接可打开预览入口。
- Mermaid、公式和 CJK 使用原版 Streamdown 插件及参数。开发正文不再经过 Mona 的 80/140/220ms 固定节流；每次实际增量直接交给上游渲染器。
- 未完成 Markdown 只在 streaming 模式修复；完成态恢复 static，不修改会话存储、复制内容或引擎输入。
- 单条 Markdown 渲染失败时保留原文，不能导致整个会话消失。
- 会话轮次导航复用同一消息契约，以用户消息 ID 定位；刻度、问答摘要和当前轮次高亮不按引擎分支。按已加载正文生成目录，支持继续加载较早历史并保持阅读锚点；宽度不足 864px 时隐藏刻度，避免挤占正文。点击历史轮次退出自动跟随底部，滚动与媒体引起的高度变化同步更新当前刻度。
- 历史轮次虚拟化，正在运行的末轮保持正常文档流；保留原版测高缓存、用户滚动意图判定、离底恢复等待和 prepend 锚点。滚动 DOM 由 Mona 提供，不能因父 ref 尚未挂载而永久停在非虚拟列表。
- 每页消息和事件批次附带其引用的轮次身份，不因最近 20 轮摘要而丢失旧工具过程或成功回复的分叉入口。前端按 ID 合并历史和实时轮次，较旧 revision 不得覆盖新状态；分叉继承记录仍是只读历史，不注册为可执行 Run。
- 原生活动投影在单次调用中按 Run 建立消息与事件索引，保留各轮原有排序和身份；同一消息或尾部的活动只向本次新建数组追加，不反复展开复制。不修改外部输入、不截断事件，也不引入跨会话长期缓存；活动末轮的布局继续使用原版正常文档流。

### 消息分叉

Code 根任务的成功最终回复使用 ZCode 的分叉图标按钮。点击后创建同项目的独立任务，复制截至所选回复的对话、工具结果与历史活动，直接切换到新任务；来源分隔线位于复制前缀之后，点击返回原任务。历史成功回复在后续轮次运行时仍可分叉。相同请求标识重试返回同一任务。

分叉只复制对话，不回滚项目文件。新任务继承当前模型与权限档位，但不继承排队消息、审批、原生绑定和子任务的执行状态。历史活动作为新任务自身保存的只读记录展示，不注册为可恢复或可重新执行的运行。来源任务删除不影响分叉的历史。历史截取后的会话重新整理上下文，不能沿用包含后续内容的摘要。

Mona 从复制前缀继续执行。原生引擎在新任务首次发送时创建独立会话，通过既有交接机制传入截取前缀的公开文本及执行证据；不恢复原会话。首次分叉交接优先完整传递公开文本，保留 48,000 字符上限，超限继续使用任务资料索引、较近对话和明确的省略计数；私有推理与认证信息不进入交接。展示的原始历史保留完整前缀。

## 项目文件安全与状态

前端把文件 URL、Windows 绝对路径、相对路径转换为当前项目的相对引用；服务端的 `project_path` 对 resolved path 做最终范围校验，包括符号链接和 junction。前端字符串检查不构成授权。

媒体由 Gateway 的已鉴权 `GET /api/development/projects/{project_id}/media` 提供，白名单 MIME、固定读取上限、nosniff、sandbox CSP；不通过后端代理任意网络 URL，不把服务凭据放进图片地址。

文件引用打开项目工作区已有的文件面板，并保留已有未保存草稿。主会话与侧边会话不能依赖普通聊天的全局工作区路径。

右侧文件面板在文件列表与文件编辑视图之间切换，打开文件后不同时展示目录列表。编辑视图顶部返回按钮仅退出当前编辑视图，保留文件草稿及原目录、分页和滚动位置。面板返回列表或切换目录后，过期的面板内读取响应不得重新打开编辑器。

文件列表不显示目录标题栏，子目录首行提供“返回上一级”。文件和目录右键菜单可打开、复制相对或完整路径，并在桌面端的资源管理器中显示；仅文件提供“使用系统应用打开”和引用到当前会话。系统应用打开磁盘中的已保存文件，不写入编辑草稿。链接不允许打开或在资源管理器中显示。

文件列表不显示刷新按钮，编辑器不显示保存和重新读取按钮；用户使用 Ctrl/Cmd+S 显式保存。编辑器按文件类型和当前深浅主题显示语法颜色。

手工文件保存未收到回执时，仅只读核对磁盘当前正文和 BOM；完全匹配本次提交才更新已保存版本，并保留保存期间继续输入的新草稿。内容不同或核对失败保留原草稿和版本保护，不自动重新写入。

## 验证范围

使用同一组 Markdown 验证四个执行器显示一致；SDK 结构化媒体需验证投影、持久化与事件重放；本地媒体需验证鉴权、路径越界与链接逃逸。UI 验证表格操作、公式与价格、无语言代码、图片加载和画廊，以及浅深主题与窄布局。

适配器 fixture 测试不代表真实供应商账号验收。上游未提供的事件类型需先确认公开协议，再接入统一内容契约。
