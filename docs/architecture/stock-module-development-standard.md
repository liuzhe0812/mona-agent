# 股票模块开发标准

- 日期：2026-10-18
- 适用范围：Mona 股票模块的功能规划、原型、接入、开发与验证。
- 建立依据：用户要求先列清 Vibe 原生能力，再规划每个 Tab 用到的能力，最后按该方向逐项开发。
- 关联：[宿主架构](stock-vibe-integration.md)、[工程边界](engineering-boundaries.md)、[原生能力与 Tab 映射](../design/stock-vibe-native-capabilities.md)。

## 0. 最新范围约束（2026-10-21）

用户明确要求“不要再自己设计任何功能，Vibe有对应功能就直接抄过来”。此约束优先于下文先前允许新增扩展的实施口径：

- 先核对锁定上游源码中的真实入口、参数、计算及产物，直接接入已有功能；Mona只做必要的中文展示、鉴权和运行时适配。
- 开发者不得自行新增内置选股方案、因子组合、训练／验证调度、默认检验期限或统计指标。用户通过自然语言创建或修改策略按第0.3节的新授权执行；上游只有工具、模板或计算库时如实区分，不将新接线流程称为上游已有成品。
- 没有对应原生实现的需求明确列为缺项，不用相似但语义不同的功能冒充。需要新增金融或产品流程时，必须有用户新的明确指令。
- 原生回测参数产品化时，默认值由实际运行器、市场引擎和所选策略读取；技能示例值不替代执行默认。用户修改只进入本次新运行，保留原策略／运行及实际配置、代码指纹；策略专属参数仅暴露已有实现可接受的项，不新增通用止损或调仓规则。
- 当前逐日重复完整选股研究的三年标准检验属于Mona扩展，不是Vibe原生要求；本轮核对并迁回已有原生路径，不继续优化或扩大这套自研机制。历史产物和用户数据保留，已有可用功能不加全局启用门槛。

### 0.1 当前原生产品化范围（2026-10-20）

本轮目标是投资工作台与机会选股两个Tab的六项用户功能，不表示股票模块只有两个Tab；账户与复盘保持既有独立入口。八类原生能力映射到这六项功能时，必须区分“目录接入”“代码/组件接入”和“实际执行验证”：当前原生量化团队、ML团队及AlphaZoo计算使用本地合成行情跑通，不能据此声称真实市场有效，也不代表每个团队、市场和数据源均已验证。

早期五个Mona自定策略卡片和逐日历史方法评价是已归档的产品方案，不作为当前实现。历史结果只读保留。原生SDM登记策略与AlphaZoo因子条目是不同对象：因子可供研究或评测，不能因此称为已登记、可直接复用的交易策略。原生Reports列表当前仅读取最近100条且不支持offset，界面及文档不得声称覆盖全部历史。配置项默认值应从本次执行的原生运行器、A股引擎和所选策略真实读取，不从技能示例推定。

### 0.2 本地模拟持仓的单项授权（2026-10-21）

用户明确授权新增“模拟持仓”完整用户流程：普通 A 股账户用户用明确设定的虚拟 CNY 资金记录自己的买卖判断，持续查看持仓/盈亏，并回看当时理由与研究。该授权只覆盖[模拟持仓需求](../design/stock-vibe-paper-account.md)列出的本地单账户、当前股票买卖、资金摘要、交易记录及研究快照；它是对“没有对应原生实现时需用户新指令”的本项例外，不开放其他自创金融流程。

- Vibe 没有通用脱离券商的本地持久 paper 账户；新增能力由 Vibe 的本地 CNY 持久 store/service/API（补丁 0052）承载，Mona 仅做薄路由和中文界面。复用 `ChinaAEngine` 的费用/数量规则及 `BaseEngine` 的持仓状态转换和 `Position`、`FillRecord`、`TradeRecord` 语义；单笔手工买卖不得通过启动回测来冒充账户记账，不调用券商下单服务或开启 hosted 实盘写入。
- 初始资金只在用户明确创建账户时写入；打开、恢复或重试不能自动创建、充值、重置或重复成交。预览、幂等确认、未知结果核对、报价时点、缺价估值和研究快照按需求文档逐项实现并验证；合同字段按实现中的真实契约补齐，不在设计阶段臆造 API schema。

### 0.3 机会选股统一策略库（2026-10-22，最新决定）

用户明确要求：完整展示上游已有策略供小白直接选择；懂的用户通过自然语言调用因子、模型等能力创建/组合策略；所有策略的展示、选股、回测在同一处，“内置 / 自定义”仅区分来源，使用逻辑一致。此决定覆盖同日早先“AI选股 / 策略研发”双入口及“新建研发 / 我的方法”的目标设计；当前已实现状态仍据实施记录核实，不将新设计写成已上线。

机会选股统一为策略列表及选中策略的“选股 / 回测 / 规则”工作区。“用AI创建策略”和“用AI修改”复用已有原生研究对话，成功生成并登记的真实产物回到同库。团队预设作为AI研究手段，因子和组合器作为生成材料，不作为要求小白先选择的成品策略卡。股票一级导航仍为投资工作台、机会选股、账户与复盘。

“全部展示”以锁定源码的[策略盘点](../design/stock-vibe-strategy-source-inventory.md)为依据，完整保留内置示例及用户已有资产，按市场筛选但可查看全部；不能只挑少数已接入示例。示例、完整代码、可执行条件和历史证据分别说明。原生存在缺陷、缺依赖或不支持当前资产的条目保留说明并限制对应操作，不能伪造可用性或给整个模块加验收门槛。期权腿、多空配对不能改名为普通A股候选；登记研究摘要不等于可运行策略。

固定内置策略随应用打包并同步显示名称、说明、规则与策略参数；浏览、搜索和切换内置策略不扫描源码、不获取原生目录/详情，也不等待原生服务。固定数据从同一锁定源码生成并在构建前校验。自定义策略、运行设置和历史单独按需读取；实际执行仍由原生核对来源与版本，不将展示数据作为执行授权。

同一策略的选股与回测固定同一执行版本及实际参数/模型来源，由Vibe执行金融计算。原生没有通用最新选股接口时，可在本次授权范围内补Vibe侧薄扫描与持久结果，复用原生信号、数据加载与受管Runner；Mona不计算公式或绩效。历史回测已移位的执行目标不能冒充最新信号，目标持仓也不等于真实买入指令。

内置策略不提供AI修改或删除；只有自定义策略允许通过AI修改，形成保留来源关联的新版本，旧证据不继承。创建新策略仍由独立创建入口发起。宿主和原生会话入口均校验修改来源，不能仅隐藏按钮；普通内置策略的研究、选股及回测保持可用。只有真实代码/配置和登记回执才能显示代码就绪；回测状态只根据对应版本的实际运行。选择策略或查看历史不调用AI、不发起计算；未知提交只读核对，不重放写入。

自定义策略支持按当前版本确认删除，内置策略不能删除。删除后移出策略库并禁止以该策略发起新执行或修改；保留原生档案、运行及历史报告，查看已删策略的旧结果保持只读。删除沿原生持久请求核对完成，不能从列表消失或提交成功推断执行完成。

普通选股输入以股票范围、数据截止及真实支持的参数为主，自然语言仅用于用户主动创建/修改或研究。参数、数据默认值沿实际策略与原生运行器，不被工作台页面的研究周期重写。历史研究、用户数据和回测保留真实归属。交互、实现职责及未接通项见[统一策略库设计](../design/stock-vibe-unified-strategy-library.md)。

股票范围使用用户能理解的“全A股 / 行业 / 我的自选”，默认全A股；行业支持搜索并选择具体行业。“策略原股票池”不作为用户选项，保存策略时的开发或回测样本不得冒充市场范围。选股与回测共用显式范围，由原生解析完整成员并保存当次快照；目录不完整时报错，行情不足时明确实际覆盖数量。当前成员用于历史回测时标明口径，不冒充历史时点成员。

## 1. 固定顺序

**原生能力盘点 → 各 Tab 能力映射 → 用户流程与原型 → 按 Tab 实现 → 真实流程验证。**

功能来源与用户任务是页面设计的输入。每张卡片、按钮、指标和报告都应能追溯到对应业务操作与产物；没有依据的字段不进入正式设计。检查的是开发工作的完整性，不新增“验收后启用”、执行权切换或测试批准开关。

当前按用户要求先完成投资工作台，再推进其他 Tab。确需共享能力时，只实现本次流程需要的接入，不同时铺开多个没有贯通的页面。

## 2. 先建立原生能力底册

盘点覆盖上游原生页面/路由、工具注册与可用性、技能/团队预设、API/CLI、持久业务对象、主要流程和市场/依赖边界。README 的声明必须与实际入口核对；工具数、技能数、因子数不能代替功能完成度。

每项至少记录：

| 项目 | 要求 |
| --- | --- |
| 来源身份 | 固定版本、源码快照/摘要；没有 Git 提交信息时如实记录 |
| 能力与入口 | 用户能做什么；原生页面、API、工具、CLI 或计算库中的哪一种入口 |
| 证据 | 实现文件/符号及调用链，不能只写目录名或宣传说明 |
| 输入与结果 | 需要哪些输入，产生什么原生对象、报告或文件，如何继续操作 |
| 适用条件 | 市场、数据频率、字段、凭据、SDK、依赖和权限条件 |
| 验证范围 | 代码存在、契约验证、真实来源验证分别记录，附日期与证据 |
| Mona 状态 | 已有专用入口、可由研究调用、尚未接入、缺依赖或需要新增 |

原生能力升级时先更新底册，再调整对应 Tab。发现“只有定义未挂载”“只是技能指导/代码模板”“多个步骤需手动串联”等情况，应明确记录。

## 3. 每个 Tab 先做能力映射

**界面简洁不意味着算法简化。** Tab定义普通用户的入口和结果，不是后台能力的隔离边界。机会选股应调用适用的原生因子、模型、回测、风险和研究证据链；股票研究作为模块共享能力，通过工作台按任务调用 Vibe 原生 Session、技能和工具。策略生成与回测只在具体研究任务需要时调用。不得仅因某个简单API已存在，就把完整AI机会发现缩减成行情排行。

策略接入方案必须记录实际方法、数据与时点、参数/模型来源、费用与交易约束、验证证据及缺口。因子、组合、ML、样本外/随机对照等能力按所选策略或用户研究任务的需要调用，不要求每次固定策略选股重复研究全部因子。已有代码、研究模板/预设与实际产物分别标明；数据缺口列入工程工作，不伪造效果，也不转成全局启用门槛。

当前三个入口为投资工作台、机会选股、账户与复盘。股票研究是模块共享能力，由工作台右栏发起，通用主会话不提供金融研究工具；报告、依据和追问按需进入同一任务详情，不设独立 AI 投研页。策略验证按用户任务进入机会选股中的原生策略回测、因子评测或研究任务；已退役的自研历史批次检验仅供只读查阅，不设独立实验室，也不增加替代入口。每个 Tab 开发前形成以下有界方案：

| 用户任务 | 对应 Vibe 原生能力与证据 | 用户输入 | 原生调用/产物 | 页面展示与行动 | Mona 缺口 | 完成证据 |
| --- | --- | --- | --- | --- | --- | --- |
| 用一句用户语言描述目标 | 写实际入口/技能/预设及代码位置 | 只列该任务必需项 | 说明原生对象及前后关联 | 说明用户看到后能做什么 | 按下节分类 | 用真实流程说明如何验证 |

每项改动必须归到以下一种：

1. **原生复用**：已有金融计算、研究、团队、策略、回测、账户、Shadow、记忆或调度；沿用其业务含义与原生产物。
2. **Mona 接入适配**：入口、中文交互、摘要投影、鉴权、配置、进程/运行时、事件及文件访问；明确适配点，不重写金融核心。
3. **新增扩展**：上游没有完整实现的能力；单列原因、范围、依赖与验证方式，不能包装成原生已有功能。

不能将“保留了源码”等同“用户已能使用”，也不能将“原生没有专门按钮”等同“没有该业务能力”；要检查自然语言、工具、CLI 和完整调用路径。

## 4. 页面围绕用户价值组织

- 默认展示用户任务、真实结果、依据、时点及下一步。整个股票模块禁止通过页内折叠/展开堆放长说明、原始字段或报告详情；详细信息使用图标或文字入口，简短说明可悬停提示，长内容点击后进入可滚动的信息浮窗，不撑开当前页面。研究主内容、实际候选列表和业务对比保留其正常阅读与操作方式。
- 机会选股按第0.3节提供统一策略库；来源筛选不改变执行流程。已选策略的选股、回测、规则与历史保持同一身份和版本，不再以研究团队分出两套界面。
- 策略列表使用紧凑条目，右侧连续工作区呈现参数、结果和按需证据；结果正常分页/滚动，不通过固定少量结果制造大块空白。窗口较窄时列表与工作区使用同页可返回导航，保留选择和任务上下文。
- SDM研究档案只有摘要或缺少代码时据实显示待补全。规则与历史证据直接取原记录，详情不得模型补写缺失规则；创建、完善与修改进入原生对话，真实产物登记后回到同库。
- 统一历史浮窗支持当前策略与全部策略，选股、回测及旧研究各有明确类型和版本来源；打开或切换历史不重新派发任务。长说明、报告与证据按需进入信息浮窗；常用动作可发现，次级快捷动作可在悬停或键盘聚焦时显示。
- 排名、因子数量和覆盖数不能充当入选原因。量化候选使用实际观测特征及原生评分贡献解释支持与反向因素；指标高低与贡献正负分别说明，不把补齐值当观测事实、不从量价因子编造资金流或公司基本面。结果自动只读更新，不为正常读取增加手动刷新按钮。
- 用户要求组合规则时，沿原生因子、组合器和生成能力形成具体策略版本，保留各项实际依据与数据要求；缺资料与冲突不得视为共同满足，不混加无定义的不同分数，不把父方法的回测称为新组合已验证。列表简明展示名称、来源、适用条件与影响操作的状态，详细规则进入选中策略的规则页签。
- 回测只接入Vibe已实现的策略回测流程：已有策略运行目录内的config.json与code/signal_engine.py进入原生backtest工具，沿原生引擎执行和读取报告。没有策略文件时沿原生Agent与strategy-generate技能获取必要信息，不擅自把选股排名、因子IC/IR或示例策略冒充当前方法的交易回测。
- 既有Mona自研历史选股检验只保留档案读取，撤销单日、区间和继续观察的新派发；不保留可误调用的旧金融计算分支。用户已有操作记录、冻结名单、来源和结果不删除、不重算。
- 旧历史结果仍按原产物展示计算口径、缺项、股票范围和来源，不能改名为原生策略回测结果；原生策略回测报告保持原生的交易、持仓、净值和费用含义。
- 投资工作台组织当前标的、行情、已有研究/账户/风险结果及任务入口。右栏优先提炼真实原生产物，并提供有明确结果的行动；不为填满页面而生成通用判断、阈值或状态。
- 普通用户的任务入口可映射到原生技能或团队，例如个股研究、财报/估值、技术检查、风险复核、策略验证；不要求用户先了解工具名或选择全部预设。
- 股票研究入口承载在工作台右栏，提供当前标的的研究发起与摘要，并关联同一原生 Session/任务，报告、依据和追问不分叉。通用 Agent 不注册股票研究工具。仅声明已明确接入的技能、工具和团队可用，不把上游所有原生能力当作已经适配。Host 鉴权、稳定请求 ID 与幂等恢复、附件路径与文件安全及统一运行时边界保持不变；字段存在或调用代码存在不等于真实流程验收通过。
- 需要历史检验的用户任务应先明确检验对象、日期、范围和结果口径；仅在该任务确实运行账户模拟时展示资金、持股数、换股间隔、分配规则及其账本结果。参数必须真正进入原生执行，结果属于明确的任务或账户，不能只给不知归属的收益；旧记录未保存的参数不能补造为用户已确认。
- A 股代码输入只需六位数字；证券身份由系统核实和转换。所有视图保持同一标的、数据时点、研究周期和产物版本。
- 无报告、未连接、缺数据、过期、失败、中断与结果未知应有对应说明和可用操作，不能用原型示例填充真实结果。
- 原型遵循 Mona UI 规范，并通过图像生成制作。原型里的数据、收益和预测仅用于演示，不能作为功能或效果证据。

## 5. 保持上游含义和实现边界

- 金融执行留在 Vibe；Mona 不重建 AgentLoop、团队编排、收益计算、回测或第二套金融调度。
- 接入工具前核对原生参数语义、目录注入、身份校验和证据归档；保持原生接口含义。例如证券参数 `code` 不能装 Python 源码，代码写入沿原生 `write_file(path, content)`，回测沿 `backtest(run_dir)`。适配器可以绑定本轮目录和用户参数，不能通过改名或放宽身份校验掩盖契约错误。
- 跨层回归必须经过实际 Session、AgentLoop、ToolLifecycle 和执行工具；脚本化模型响应可以固定输入，但不能替换执行链。过程事件中的参数可能脱敏或截短，只用于展示；同轮归属与成功证据应来自真实调用标识、执行回执及产物指纹。
- 不使用已删除的旧股票模块、旧评分和旧专家流程，不以换目录方式复活它们。
- IC/IR 是因子评测；相关性/波动率是各自的统计量；它们不自动构成股价预测、上涨概率或买卖指令。
- Shadow 维持原生“成交分析/规则提取/代码/回测/报告/扫描”语义；文件解析不等于在线账户，历史模拟不等于完整真实账户净值。
- 原生记忆和技能修订不自动意味着交易方法会变准；策略适配遵守原生允许修改的范围，不继承未验证的父策略绩效。
- 研究、回测、模拟、提案与实盘执行分开。原生有某券商或市场的入口，不等于本项目的 A 股账户已可用。
- 行情与预测需求保留用户最新约定：默认最近交易日分时，盘中按可用源更新，分时和日 K 均规划独立预测开关。原生 ML 研究/因子/回测应优先复用；持续预测、数据、模型留档与前向评价等缺口按新增扩展记录。
- 配置、统一运行时、鉴权、SSRF、路径范围、未知写入核对和进程归属继续遵循现有工程与宿主架构；本标准不放宽这些边界。

## 6. 按真实使用流程判断完成

每次实现先声明本轮 Tab 与范围，完成后逐项给出当前代码、实际调用、原始产物和必要测试/构建证据。

至少核对：用户输入被正确处理；调用真实原生链路；结果可追溯且跨页一致；下一步行动能继续到同一对象；缺项/失败准确表达；查询和重连不会重复派发未知写入。

页面存在、接口返回 200、模型自称完成、合成数据测试通过，均不能单独表示业务完成。合成样本、真实行情和真实账户验证分别记录。只运行与本次风险相关的必要检查，不以测试数量代替用户流程。

未完成项进入能力表和 Tab 缺口；已有可用功能持续可测试，不把设计、验证状态变成全局封锁。阶段进展更新到实施计划，不能悄悄删除已约定需求。
