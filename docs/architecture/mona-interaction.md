# Mona 独立交互模块

- 决策：Accepted（2026-11-03）
- 当前实现：已实现本机渠道接入、结构化回复解析、连续参数控制器和持久准入；语音提供商、正式 Cubism 绑定与跨机器加密连接尚未完成。
- 范围：角色展示、文字与语音交互、Mona 渠道接入、Windows 开发和 Ubuntu 运行。
- 完整目标：连续实时 2D 表演、可打断的全双工语音、声音与表情的统一时间线；不能以少量固定动画作为成品。
- 详细技术设计：[Mona 连续交互技术方案](../design/mona-realtime-interaction.md)。

## 1. 已确定的边界

交互主体放在 `interaction/`，具有自己的 Python 包、网页资源、依赖和启动脚本。它不导入 `mona`，不读取 Mona 的配置、数据库或内部对象。Mona 的会话、记忆、模型、工具和授权保持由 Mona 主体管理。

```text
交互程序（Windows / Ubuntu）
  角色、输入、声音、动画调度
            ↕ 有版本的消息协议
Mona 渠道适配插件
  连接认证、会话绑定、准入与事件转换
            ↕ 现有消息总线
Mona 智能体
  会话、记忆、模型、工具与授权
```

交互程序退出或升级不应停止 Mona 的任务。更换角色资源和渲染器不应改变智能体的提示词或核心循环。渠道适配器负责输入与权威事件转换；交互运行时持续解释语义、注意力、声音韵律和表现状态，由本地控制器合成连续动作。

任务执行、对话轮次和一次音频话语使用各自的标识及生命周期。打断播音不等于取消业务任务；播放进度与任务状态不能互相替代。表现层不得独立维护另一套长期人格或扩大工具权限。

Mona 侧复用 `mona.channels` 外部插件发现机制。接入插件依赖渠道接口，图形、音频和平台运行依赖留在交互程序。新增宿主配置按 `AGENTS.md` 显式进入 `mona/config/schema.py`；不先建设新的插件市场或通用安装框架。

当前宿主适配器位于 `mona/channels/interaction.py`，通过现有可选渠道机制发现。宿主只增加固定的渠道最终输出契约和按请求启用的通用轮次结束回执，未加入图形、音频或逐帧控制逻辑。契约追加在当前 user 输入投影中，原始用户文字单独保存，system 不因动画参数改变。

## 2. 首个开发基线

本节描述现有演示的实际能力，只作为开发验证工具，不定义完整产品的体验上限。完整目标的媒体、连续表现和插件契约以详细技术设计为准。

`python -m mona_interaction serve` 启动独立的本机 HTTP/WebSocket 服务，默认地址为 `127.0.0.1:17880`。未提供连接文件时等待配置，不返回模拟回复；只有显式 `--demo` 才启用下面的模拟行为。此地址是模块内部部署配置，不作为正式用户界面文案。

- `/health` 标明模块、版本、协议版本及 `mode: demo`。
- 网页显示正式原画 `design-assets/01-master/mona-human-original.png` 的原样副本。
- 文字输入经过接受、回应中、回复片段、完整回复、空闲几个事件。
- WebSocket 恢复时只请求会话快照，不自动重发输入。
- 同一演示会话内、仍在保存范围内的重复消息标识复用原结果；同一标识携带不同内容时拒绝。
- 演示状态仅保存在内存，最多 32 个会话、每会话 100 条记录。进程重启或记录回收后不能提供持久去重保证。
- 当前服务仅允许本机监听，并校验 Host 和浏览器 Origin；没有设备认证前不开放局域网。
- “朗读回复”是浏览器系统中文语音的可选试听，不是最终语音提供商；没有可用中文语音时明确提示。

模拟模式不调用模型、不执行工具。真实模式通过宿主渠道运行 Mona；代码链路已通过隔离外部模型的端到端测试，尚未在用户当前运行实例中启用并验证实际模型请求。原画显示不等于已有眨眼、嘴型或 Live2D 绑定。

## 本机真实接入

- 宿主配置：`channels.interaction`，默认关闭，`127.0.0.1:17881`，单设备绑定且禁用原始 JSON 流式展示。
- 凭据：由宿主在用户数据目录生成连接文件，仅独立服务读取；认证后的服务端绑定设备身份，浏览器不能持有凭据。
- 输入准入：SQLite 先保存消息标识和内容，再提交消息总线；同一会话仅有一条活动输入。
- 完成：普通回复先归集，收到 `_channel_turn_end` 后才发送完整正文与终态；进度不作为最终回复。
- 重启：未完成输入改为 `unknown`，不自动重新派发；恢复终端可继续监听已接受的原请求。
- 人工核对：`input.resolve` 只把原请求标记为 `closed_unknown`，不代表原操作撤销，也不重新执行；之后用户可发新输入。
- 表现：独立端解析 `text + performance`，通过 `mona:performance-decision` 和 `mona:performance-frame` 供可控模型消费。当前正式模型未安装。

## 3. 开发基线消息契约 v1

公共字段为 `version`、`type`、`session_id`、`message_id` 和 `payload`。`message_id` 是调用端创建的稳定标识；回复与状态沿用对应输入的标识。会话归属必须由最终适配器认证和绑定，不能依赖客户端任意指定标识。

| 方向 | type | payload | 含义 |
|---|---|---|---|
| 终端 → 接入端 | `session.sync` | `{}` | 请求状态，不能派发任务 |
| 终端 → 接入端 | `input.text` | `text` | 提交一条用户输入 |
| 接入端 → 终端 | `session.snapshot` | `mode, state, pending_id, records` | 当前会话快照 |
| 接入端 → 终端 | `input.accepted` | `text` | 已接受输入，不代表任务完成 |
| 接入端 → 终端 | `turn.state` | `state` | 当前处理状态 |
| 接入端 → 终端 | `reply.delta` | `text` | 一段文本增量 |
| 接入端 → 终端 | `reply.completed` | `text` | 此次回复的完整正文 |
| 接入端 → 终端 | `error` | `code, message` | 可采取行动的失败说明 |

真实接入时，只有权威轮次终态才能作为结束依据，不能把 Mona 的文字流片段结束直接映射为整轮完成。首版适配可使用非流式完整回复，再逐步补齐流式契约。内部推理、原始异常、凭据和工具参数不属于默认交互数据。

## 4. 真实接入的准入条件

- 设备配对后只取得绑定会话的权限，不能继承桌面全权令牌。
- 消息准入与执行记录在任务派发前持久化；重连沿原标识核对。未确认写入结果不得自动重发。
- 远程传输采用明确配置的加密连接；不修改桌面内部接口的默认监听地址。
- 语音识别与合成由交互模块的提供商边界负责，密钥保存在服务端，不交给网页。Mona 只接收授权的用户输入并输出回复与可用状态。
- 角色动作不得扩大工具权限，点击形象不会暗中触发业务写入。
- 外部 URL 经过 SSRF 防护，配置为可信服务的内网地址也需校验协议和解析结果。用户路径先解析并限制在显式允许范围。
- 模型、解释器、浏览器与原生程序若需要下载，复用统一运行时仓库，不新增下载器。

## 5. 美术与设备

当前已确认原画是人形 Mona；`design-assets/09-esp32-character/mona_neutral.png` 是待确认的正面半身候选，尚无匹配的闭眼、嘴型或分层源文件。其他旧角色素材不能混用。

最终目标是高质量实时 2D，由语义表演导演、本地参数混合器和可控模型共同生成持续表现。不能将少量状态图、动作片段或音量驱动的开合嘴当作完整交付。角色资源准备与程序运行分开验收；专业级拆图、绑定和修形不能视为已经实现的自动化能力。

Ubuntu 目标设备已确认：32GB 内存、RTX 2060、1080P、无触摸屏、有麦克风与扬声器。Ubuntu 版本和最终同机/远程部署方式仍待补充。开发按 Windows 完成主要逻辑、Ubuntu 尽早验证图形与音频、最后实机验收执行；Windows 测试不能替代 Linux 显卡、音频及开机启动验证。
