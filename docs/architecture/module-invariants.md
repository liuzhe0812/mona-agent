# Mona 模块关键不变量

- 状态：Accepted
- 最后更新：2026-10-09

本文保留已落地模块中仍需长期保护的行为边界。历史实施步骤、完成日志和一次性文件清单不在此保留。

## 1. 邮件

- 邮件采用 offline-first：优先读取完整本地 `.eml`，本地缺失或损坏时才请求网络，成功后立即落盘。
- `.eml` 保存完整 RFC822；`.meta.json` 保存本地状态；SQLite 保存索引和同步水位，不保存正文副本。
- `body_fetched=true` 只表示完整 RFC822 已成功落盘，不能表示"发起过请求"或"拿到部分正文"。
- HEADER-only 文件必须保持 `body_fetched=false`。文件写入或数据库更新任一步失败时不得推进完整状态或同步水位。
- IMAP MOVE/COPY/STORE/SELECT 必须检查服务器状态；移动后以目标文件夹新 UID 为准，不能继续使用源 UID。
- Modified UTF-7、UIDVALIDITY、增量同步和目标文件夹同步属于协议正确性，不得由 UI 重试掩盖。
- 正文加载同一邮件最多一个在途请求；已处理错误不重复抛出形成自动重试循环。
- 邮件 AI 提取必须携带本人邮箱身份、To 和 Cc；仅抄送默认知会，只有原文明示本人或包含本人的群体负责/参与时才提取。直接收件也不能替代本人责任判断。
- 广告、公开活动推广、尚未报名的报名邀请、他人任务、普通知会及取消通知不生成日程或待办；时间和本人行动依据必须来自邮件原文，不补造日期或参与意愿。
- 本人定时安排生成日程，本人行动和截止事项生成待确认待办；关系或置信度不足的有效日程只进入收集箱，不自动创建。过期事件和没有原文依据的结果不写入计划。
- 邮件提取的全局设置归属计划页面；邮箱账号设置只提供跳转，两处进入同一设置界面。来源按邮箱和文件夹选择，账户连接、密码及同步设置仍归属邮件模块。

## 2. 通讯录

- 本地联系人、CardDAV 和 Exchange ActiveSync 使用统一的联系人结果模型，但同步协议实现保持独立。
- 联系人索引和同步状态保存在邮件数据库；账户级同步令牌不得跨账户或跨协议复用。
- CardDAV 外部 URL 必须经过 SSRF 校验，XML 解析必须防止 XXE。
- ActiveSync 维持稳定 DeviceID、Provision PolicyKey、FolderSync 和 SyncKey；分页必须有上限。
- 邮件编辑器的地址自动完成读取本地索引，不在每次输入时直接访问远端服务。

## 3. 数据库客户端

- Rust `CellValue` 的 JSON 是 `{ type, value }` 判别联合。新增 variant 时必须同步更新 Rust 序列化、TypeScript 类型和显示函数。
- 每个 `ConnectionManager` 能力必须明确处理 SQLite 与 MySQL；SQLite 同步锁和 MySQL async pool 不得混用假设。
- AI 生成 SQL 与执行 SQL 分离；高风险操作必须经过风险判定和用户确认，凭据不进入模型上下文。
- 查询结果、变更记录和错误使用结构化协议，不从自然语言推断执行是否成功。
- 数据表浏览与 SQL 查询使用独立的标签类型；表身份由连接、数据库、表名确定，不能用标签标题或 SQL 文本推断。切换标签同步显示目标，不重新执行或丢弃修改。
- 数据表筛选、排序和分页作用于数据库完整结果，生成 SQL 必须转义标识符与值；对象摘要批量读取，不逐表精确计数。
- 表格新增、修改、删除先暂存；没有可靠主键的表、视图和普通查询结果只读。多行保存按实际提交结果清理，失败后重试不得重复提交已完成的新增行。
- MySQL 标签指定数据库时，选择数据库和执行语句必须在同一条借出的连接上完成；不能依赖连接池中的隐式当前数据库。
- 表结构编辑使用独立标签和完整结构草稿；字段、索引、外键、触发器和高级选项共享预览与应用入口。后端核对各分区原始快照并重新生成变更，不能直接执行前端提交的 SQL。数据页有未保存修改或正在读取时不能应用结构变更，结构应用期间暂停同表数据编辑。
- 结构变更已经执行但重读失败时必须返回明确结果，前端清除已应用草稿并提示刷新，不能把它当作未执行而重复提交。SQLite 支持的多步结构变更在同一事务内执行；MySQL 将表定义变更合并为单条 ALTER TABLE，触发器按独立语句执行并返回已完成语句数。

## 4. WebView2 浏览器

- Windows 普通浏览器标签共用 `app_local_data_dir()/browser`，与有应用权限的 main WebView 默认资料目录隔离；不得继承 main WebView 的 environment，也不为每个标签创建独立目录。
- CDP 端口固定为 9300；`BrowserState` 保持原生浏览器资源的唯一所有者，自动化通过注入的标签标识匹配目标 Page。
- WebView2 扩展只支持本地解压目录的显式安装、列举、启停和移除；扩展管理命令只允许 main WebView 调用。
- 切换浏览器资料目录不搬迁或删除旧目录；网页可能需要重新登录，原 Work/Mona 数据保留。
- 导航通过 Rust IPC 完成；`target=_blank` 由初始化脚本拦截并交给标签管理器。
- 子 WebView 的创建、尺寸和可见性不得在持有阻塞状态锁时执行。
- 浏览器外壳遵循全局 UI 规范；网页内容本身不做产品 Token 化。

## 5. 可编辑画布

- 流程图和思维导图继续使用既有文档模型和 patch 校验器，不创建第二套 schema。
- 主会话只在用户明确表达创建意图时创建画布；普通讨论不产生画布文件。
- AI patch 必须携带请求时的 base hash。生成期间用户已修改语义时，过期 patch 不得覆盖当前内容。
- `.mona-canvas` 是工作区产物，不依赖笔记仓库；每张画布独立保存并记录 `originChatId`。
- 画布预览和编辑复用同一渲染/几何定义，避免图形库、编辑器和只读预览出现多套实现。
- 连线的连接侧、端口比例与显式控制点属于文档几何，保存、哈希、编辑和渲染一致。自动避障不覆盖显式路线；局部连线修改只调整受影响的边，并避让其它已存在的路线。共线重叠按实际渲染线段检查，不用端点 ID 相同代替几何判定。
- 主会话展示自然语言结果，不展示内部 patch JSON。
- 画布 `open` 只读取文档、版本和选区，不等待字体、动画帧或截图。`apply` 在文档提交后返回，视觉验收由显式 `inspect` 执行；提交成功不等于视觉验收通过。
- 同一画布请求只执行一次；超时、卸载时取消未完成的检查，不自动重放结果未确认的写入。侧栏收起保留编辑器，激活后用状态回执确认可接收操作。
- 画布侧栏激活在轻量 `open` 等待期间可以幂等重发，并携带已校验的工作区文件路径；重新进入会话时从 `originChatId` 恢复该会话画布。同一会话的后续消息未重复携带画布字段时，工具保留该会话最近的画布上下文；切换会话必须清空。
- 生成批次按内容模块决定，不以固定批次数限制创作；Skill 保留设计经验与必要文档协议，连接恢复、超时和熔断由代码负责。
- 主会话流式更新时，未变化的画布编辑器必须保持挂载但跳过重渲染；活动轨迹、工具事件和推理展示数据必须有界，不能因长会话无限累积。
- React Flow 的对象/数组配置和事件回调必须保持稳定引用；动态连接点只在端口集合实际变化时调用 `updateNodeInternals`。禁止用每次 render 新建的 `fitViewOptions`、`proOptions`、`snapGrid` 或内联 Store 回调形成 Store 更新循环。

## 6. Terminal AI 维护

- 终端 AI 会话按连接身份绑定并持久化：面板重新挂载、SSH 重连和应用重启后必须恢复同一会话历史，不能静默新建空会话；只有用户显式「重置会话」才解绑。终端 AI 会话是普通可见会话，不进入隐藏会话集合。
- AI 维护任务使用后端持久状态，而不是根据聊天文本模拟 Todo。
- 命令成功退出不等于任务成功；发生变更后，必须有晚于最后变更的成功复检才能完成任务。
- 高风险或禁止命令的审批边界不能因自动模式而绕过。
- 取消、超时、断连和应用中断必须落为可查询的最终状态。
- IPC 桥的传输超时必须覆盖其所等待的后端工作（步骤超时加上余量），不能用固定值截断更长的命令；调用端必须区分「命令失败」与「客户端停止等待」，后者不能当作失败让模型重跑。
- 包安装与构建这类分钟级命令按同步单步执行，超时默认值必须覆盖它们（当前 600s）。超时与取消都只表示「停止等待」，不表示远端命令已结束：远端进程在真实 OpenSSH 上既收不到 SSH 信号请求，也不因关闭通道或断连被回收（已实测），因此禁止在远端部署终止代理，也禁止向用户宣称进程已终止；结果必须如实报告「状态未知、可能仍在运行」并停下等用户决定。
- 步骤状态必须区分「明确失败」（有非 0 退出码）与「结果未知」（超时/取消/无退出码）。结果未知的变更步骤必须有一次晚于它的成功复检才能确认任务结果；明确失败的变更步骤不能被后续复检确认，因为复检通过不代表变更生效。
- 远端拒绝分配新会话通道时必须停止重试并引导重连，不得按瞬时错误继续打。
- 调用端停止等待必须传播为取消：桥接层探测到连接断开后要取消在途步骤，使执行不再阻塞等待；这不是终止远端进程（见上条），不得据此声称命令已停止。
- 步骤结果未知（超时/取消）时不得继续推进计划，因为下一步可能作用于半完成的变更。
- 步骤状态机等确定性契约错误必须翻译为唯一的下一步动作；原样返回会让模型重复无效调用直至工具被熔断。
- 上传远端文件必须能创建新文件和缺失的父目录：写文件一律使用 `CREATE|TRUNCATE|WRITE` 语义并逐级补齐父目录，禁止使用不含 `CREATE` 的只写打开方式（SFTP `write` 只能覆盖已存在文件）。
- 维护记录保存目标、步骤类型、状态和验证结果，不保存原始命令、完整终端输出或凭据。
- 批量清除维护记录只能删除已结束的任务；进行中的任务与步骤必须保留，判定以存储层状态为准，不由前端列表推断。
- IPC Bridge 必须鉴权，未鉴权请求不能触发终端执行。

## 7. AI 文档工作台与 PPT 工作流

- AI 文档模块以固定开始页和多文档标签工作台为统一产品入口；开始页支持新建 Word、Excel、PPT 和视频，普通 Office 文档在该工作台进入人机实时协作编辑会话。
- 开始页保持为固定标签；文档标签对应具体文档或项目，工作台不依赖左侧模块导航。开始页提供历史和收藏两个列表入口。
- PPT 统一进入 Slides Office 会话，由 Agent 通过 `office` 逐页或分区直接创建、修改、观察和导出；不保留 PPT 专属审批工具、整稿状态机、第二编辑器或专用 Document Agent。
- 主会话右侧"新建 PPT"只创建 `slides` 类型的 Office 会话并打开空白 `.pptx`，不得启动 PPT 制作工作流。
- 主 Mona 使用轻量 `mona-pptx`，新建和已有页面都调用 `office`。Skill 提供设计目标、操作入口和按需参考；叙事、构图、主题与版式复用由模型根据内容决定。
- 视频/PPT 等项目会话是普通会话：进入会话列表并像普通会话一样生成标题，模块自带的历史面板只是额外入口，不得把会话从列表中隐藏。隐藏集合仅保留隐藏房间等不可见执行容器。
- 视频以“描述需求 → 导演台调整并确认 → 制作 → 预览修改”为主流程。导演台是生成前的分镜编辑主界面，包含旁白、画面、动画变化、时长和素材；聊天辅助讨论。只有用户确认当前分镜版本后才能生成，分镜修改使确认失效，不增加逐场景审批。风格和基础设置使用普通语言，不让内部场景类型、编译器和目录成为操作门槛。
- 进入或恢复视频项目时展示对应的导演方案或制作结果，同一会话的制作对话可主动收起。制作状态来自实际执行事件和项目结果：方案整理不冒充画面生成，草稿不冒充预览，等待不冒充正在绘制，完整 turn 结束必须清除运行状态；暂停和补充要求使用现有会话控件。
- 本地视频工作台是受会话与项目范围约束的基础能力，不以软件订阅为门槛，也不因旧通用工具授权列表缺少新能力而失效；上下文之外不可见，模型来源、素材范围和写入结果核验等边界保持有效。
- 视频 Agent 复用完整执行循环，先规划口播和对应动作，确认后根据实际旁白时间编写 Remotion React 动画组件。SVG/Canvas、路径、物理缓动、分层序列和转场用于解释内容；构图和编排由 Agent 设计。内置场景只作为样式预览与旧项目渲染支持，不限制新视频构图；风格提供配色、字体、间距、可读性和动效标准，不自动添加无内容意义的装饰。
- `video` 工具通过鉴权的本地 Services 接口操作绑定到当前会话的项目。Agent 在 `drafts/` 编写修改稿，工具保存规范源码、场景元数据及渲染文档；预览必须把实际画面送给模型。自由场景代码运行于无同源权限的沙盒，素材限定为项目内授权文件，不允许访问宿主凭据或任意本地文件。
- 新动画使用随桌面交付的 Remotion/Player SDK，在无网络、无同源权限的 iframe 中编译并执行 TSX；生成代码不能在宿主 Node 中执行。预览和导出使用相同组件与帧时钟，并等待定位和素材就绪。JS 组件资源由前端构建产出随 Gateway 打包，不新增下载器；原生浏览器和 FFmpeg 仍遵循统一运行时管理。
- 动画检查覆盖动作阶段与旁白时间点，并把字幕排除在画面变化判断外；新动画未经观察或内容一直静止时不能导出。时间点截图、文件检查和帧差异只能证明部分技术行为，不能被声明为叙事、节奏或审美质量认证。
- 自动导出根据场景的执行契约选用渲染路径：自由场景使用与预览一致的本地时刻渲染，旧结构化场景可使用 HyperFrames 检查及渲染；显式选择 HyperFrames 时仍执行其检查，检查失败不得绕过。交付检查验证实际时长、声音、字幕和素材，不等同于视觉质量认证。
- 视频默认旁白所需的语音合成依赖随应用后端交付。开启旁白的项目在合成失败或导出缺少旁白音轨时必须明确失败并保留旧成品，不能降级为无声视频后标记成功；制作阶段的时间轴播放与试听失败使用现有弹窗反馈。
- 配音失败须区分组件缺失、配置无效和服务请求失败，不据此自行更换用户选定的声音。临时重试保持同一声音，不能混入失败流的部分音频。声音、语速与字幕调整保留已确认分镜，只使音频、相关动画检查和导出结果失效；全局配音服务变化也必须进入缓存与合成期间输入校验。
- 选择音色时允许对固定短示例试音，不依赖项目创建或分镜确认；试音不读取、更改场景旁白、项目文件和确认状态。切换音色、语速或关闭选择界面时停止旧试音并取消待返回请求。
- 视频场景时长以项目元数据为事实源；旁白超过预设时长时延长场景并同步规格、字幕与分镜。整片预览先准备旁白，音轨逐场景补齐静音，转场不缩短时间轴；交付前检查实际视频的长度和音轨。
- 视频导出冻结分镜、样式、素材和音频输入。导出期间的编辑不覆盖快照，旧版本导出完成后仍标记需要重新导出；内容改变不能按场景编号继承旧的画面确认或配音缓存，内容检查失败不得通过切换渲染器绕过。
- 单个视频可选择内置风格或复用已保存的自定义风格；复用风格不自动加入系列，风格不限制横屏、竖屏或方形画面。样式编辑按版本顺序保存，离开前完成待保存编辑。
- 委派循环（DocumentAgentLoop、PartnerAgentLoop）必须复用父 AgentLoop 的 `WebuiTurnCoordinator`：turn 由父循环结束、由委派循环执行，各自新建协调器会让标题上下文永远取不到，委派会话因此失去自动标题。

## 8. URL 转笔记

- 网页转笔记是所有 Agent 可配置的通用能力；`url2note` 与内部提帧工具 `video_extract_frame` 共用“网页转笔记”授权。旧配置以 `url2note` 的状态为准，关闭时不得保留独立提帧授权。
- 页面类型判断和内容提取由共享后端负责，浏览器与笔记入口不得复制不同实现。
- 视频优先使用字幕；无字幕时才懒加载本地 ASR。
- ASR 模型只在转写子进程内加载，完成、取消或超时后必须释放进程资源。
- 重点帧最多提取少量高相关时间点，复用已下载视频；无法可靠判断时不强制插图。
- 笔记图片写入笔记仓库 `assets`，运行时模型和任务临时文件不得进入笔记仓库。

## 9. 检索与用户画像

- Notes 与每个 Agent 的 Knowledge 保持独立事实源，统一检索只统一工具和结果契约。
- 每个 Agent 拥有独立的 `raw/text/evidence/wiki/index`；MD5 只在同一 Agent 内去重，不共享可变 Wiki。
- 新资料自动异步学习；文字与视觉证据完整写入后原文即可检索，Wiki 继续增量整理并展示业务进度。Wiki 整理失败不撤销完整证据，用户可手动从已完成部分继续；视觉证据中影响含义的关键信息无法辨认属于失败，装饰图或微小品牌标记可保留次要不可辨认标记，不得因此丢弃整份文档的其他知识。
- 原文件不可变，完整证据不能被 Wiki 摘要替代或删除；Wiki 结论必须能回到来源位置，未进入 Wiki 的细节仍可读取。
- 搜索、读取、证据和链接跳转都必须绑定运行时 Agent 身份。模型构造的 Agent ID、旧知识库 ID、引用和路径不可信。
- 旧 Materials 多知识库只用于迁移和旧引用兼容，新 UI 不暴露知识库范围配置。
- 用户画像属于用户级平台数据，与每个 Agent 的私有记忆分离。
- 画像只接收真实用户信号，排除 assistant 推理、内部任务、系统消息和运行时元数据。
- Agent 只接收白名单、裁剪、带版本的只读画像快照；画像不能扩大 Agent 权限。
- 桌面普通直聊的跨会话回忆使用同一 Agent 范围内的 transcript 正文与 FTS5 关键词索引；不从 `memory/history.jsonl` 的摘要反推原话，不把协作房间、隐藏任务、临时会话或其他 Agent 会话混入默认搜索。
- 会话历史索引是可重建派生数据；读取引用时必须重新验证来源和 Agent 归属。删除来源后搜索和读取都不得返回旧索引内容，旧记录缺少真实时间时不能以回放时间补造。

## 10. Office 实时编辑

- Office 任务由 `mona-docx`、`mona-xlsx`、`mona-pptx` 三个专用 Skill 负责，共用同一个 Office 会话协议和 Editor 权威。PPT 的完整原生示例和可选预设按需加载，不强制整稿匹配、代表页批准或不重复版式；不再保留 `mona-office` 或 `doc-writing-guide` 入口，也不强制普通写作先加载共享指南或默认输出 HTML。PRD 专业参考通过 `prd-document` 按需加载。
- Word 统一进入 `mona-docx`；高级 OOXML、修订、批注和转换说明及脚本归属于该 Skill，不再暴露平级 `docx` 入口。只有确认具体操作不受实时工具支持时才切换离线处理，参数错误、版本冲突或截图失败不等于能力缺失。离线处理基于最新版本导出的副本，保留原文件与用户后续编辑，结果重新打开并验证后交付；不得将打包成功视为版式验收通过。
- `OfficeSessionManager` 归属 Services，负责会话、权限、命令队列、checkpoint 和保存；Gateway 的 `office` 工具只通过受保护客户端调用 Services，并将鉴权读取的 checkpoint 原子写入当前 Agent 工作区作为导出文件。Services 不接收或解析 Agent 工作区路径。
- Editor 是当前文档模型与事务提交权威；Manager 只维护版本镜像。Agent 操作必须同时通过 Manager 预检查和 Editor 最终版本检查。
- 用户编辑、Undo/Redo 和 Agent apply 共用单调 revision；过期操作返回冲突，不能静默覆盖用户修改。
- 幻灯片操作只有实际修改文档后才推进 revision；已满足请求时返回 `unchanged: true`、原版本与空修改目标。未知图表字段必须拒绝，不能静默忽略后报告成功。
- 图表读取和修改使用同一稳定元素 ID；仅修改文字颜色时保留原生图表数据、引用及其它格式，编辑器渲染和保存文件必须读取同一组文字属性。
- PPT 局部读取先确定页面/元素范围，selection 返回可执行修改所需的选中对象摘要；能力参数按需读取。结构化回执携带创建/更新对象与可定位的布局警告。
- Agent 新建 Word 内容使用独立的文档标题角色和中性的显式字体层级；新建表格默认包含可识别的表头、浅色边框、单元格垂直居中、重复表头和禁止跨页拆行。已有文档只按用户要求局部修改，不强制套用新文档默认样式。
- Office 打开回执包含当前选区和其权威版本；新建幻灯片的回执直接携带页面 ID。能力查询默认返回短目录，指定操作时分批返回参数；未知名称显式列入 unsupportedOperations，不能使已知项丢失，也不能伪装为已支持。未知页面/元素和实际写入操作仍严格拒绝。
- 已有 Office 文稿的颜色、文字、字体和布局修改沿用当前会话；open 的 document_type 不覆盖活动会话，新文稿须明确 new_document=true。close 不是编辑失败的恢复手段；恢复始终针对原 session ID，不通过同名空白稿替换完成稿。
- PPT 的 palette 查询读取当前原生对象的显式 RGB，slide_replace_colors 在同一事务内精确替换指定颜色属性。只改颜色节点，保留文字、数据、ID、几何、透明度与未选择对象；同色无匹配不推进 revision。图片像素、母版继承色及不支持的共享图表必须明确边界，不能假称完成整套主题替换。
- 长工具结果落盘后必须可继续读取；单行超长文本使用有界字符窗口、明确下一偏移与源 SHA，不通过增大行数反复读取同一条超长 JSON。
- PPT 布局变更与布局警告进入待观察页集合，随会话保存并恢复。成功且版本一致的完整页视觉捕获不自动清除仍存在的硬布局错误，也不证明内容完整或设计合格；图文交叠等需检查项只有在当前版本整页画面确认后显式接受，才能解除待观察状态。
- Word 修改进入文档验收状态；完整连续文档视觉检查可解除无警告状态，异常页码字段必须修复，表格跨页拆行需观察后明确接受。Excel 修改范围进入验收集合，只有覆盖该范围的 `range` 读取才能解除；本次修改公式返回明确错误时阻止正常导出。两者都不因既有未触及内容扩大自动修改范围。
- Agent 正常导出 Office 文件前必须处理对应待验收目标并消除硬错误。PPT 不接受模型自行设置 `allow_unreviewed` 绕过验收；草稿可以保存，用户可以从编辑器直接导出，不能由模型将草稿宣称为已验收。Word/Excel 的既有草稿契约不由 PPT 改造变更。保存工作副本和用户直接操作编辑器不被 Agent 导出门控阻塞。
- PPT 网格混排必须转换为独立原生对象；静态 SVG 作为可移动缩放的矢量图片保留，不宣称其内部路径可逐个编辑。SVG 不允许活动内容和外部资源引用。
- 原生设计组件通过同一个 `office` 的 `slide_add_design` 生成独立文字、图表和形状；完整页、局部组件、自由构图可混用，不设 PPT 专属工具或审批状态机。参考图只用于校准完成度，不是复刻目标；设计应服务于实际内容、受众和场景，不按图像相似度、模板数量或固定占用率验收。
- 局部指标、列表、图表解读、瀑布和流向组件使用区域实际尺寸与可读字号，不把整页微缩后塞进区域。文字测量复用当前编辑器排版；事实不隐藏截断、数值单位不混淆，超出能力时允许换构图或原生修改。
- 自由路径仅接受有限且归一化的 M/L/C/Z 数据和经验证的颜色，不接受任意 XML/SVG。桑基/瀑布信息图形保存为原生路径、形状与文字，可分别编辑，但不冒充 PowerPoint 标准图表的原生数据表。
- Skill 可用限定于当前解析 Skill 资产目录的预览索引直接返回少量真实图像；路径、字节数、尺寸均受限，不跨 Agent/Skill 取用资产。参考资源读取接受文档中的 `references/` 前缀，但仍使用 resolved-path 范围校验。
- PPT 多页总览由真实 SlideCanvas 生成并绑定文档版本，只用于观察节奏与布局，不解除单页待验收状态，也不替代细节与事实检查。
- PPT 内置预设由受约束数据资源生成原生对象，复用现有 Office 版本、事务和导出协议；内容无可见落点或超过支持容量必须明确拒绝。预设候选只在隔离副本中使用真实 SlideCanvas 预览，不写入用户文稿、不推进版本，也不解除当前文档的待审核状态。
- PPT 预设是可选快捷能力，不是可生成页面的白名单。自动选版无匹配时返回具体原因和原生构图入口，不隐式生成通用双栏页；基础草稿仅在明确请求 `auto-content` 时生成。页面角色是软提示，不限制自定义用途；真实关系与事实不得为迁就模板改变。空白页允许原生创建，既有页面允许局部修改和后补素材，已成功页面不因后续页面失败而重建。
- 常见 PPT 数据图表可用 `slide_add_chart` 或 `slide_compose` 的 chart 项以预览像素创建，并用可选 `style` 在同一命令内应用主题；普通引擎操作及图表样式合计仍受 50 次上限约束；仅受控原生设计组件允许内部展开，同一事务全部展开操作与图表样式合计最多 256 次，公共操作数组仍最多 50 项，不能借组件提高原始操作上限。全部共同提交或回滚，只推进一次用户 revision。内部复用原生 addChart 并保留数据模型。字符条伪图表、长内容单框作为可定位的设计疑点返回；不以图片数量或空间占用比例机械判断质量。接受非阻断提示必须先观察同版本整页画面并给出 `reviewReason`；编辑后观察记录失效。
- 图片资产路径仅由 Gateway 在当前工作区范围内解析并转换；传入编辑器的命令不包含可访问任意本机文件的路径。
- 局部渲染复用未受影响页面；有跨页语义的操作仍走全量路径。版本快照可以延迟压缩，但必须在提交时固定内容，后续修改不能改变旧版本 checkpoint。
- Agent 将结构化 `ok: false` 识别为失败；同一 Office 目标连续无进展时限制继续修改，仍允许检查和处理其它目标。正常版本冲突不计为无效修改。
- 中断恢复保留当前 turn 已完成的各轮工具调用和返回；同一批工具每完成一个就更新恢复记录，不能只保留最后一轮。
- checkpoint 必须绑定精确版本并原子替换工作副本。异常退出只能恢复最近 checkpoint，存在未持久修改丢失时必须明确提示。
- Agent 只接触稳定的 Mona Office Schema，不接触 Univer、ProseMirror、GenOffice AST，也不能发送任意 JavaScript、HTML 或文件路径。
- 视觉检查必须由当前 Editor 的真实渲染生成并绑定精确文档版本；截图补充结构化读取，不能取代段落、单元格、公式、页面和元素检查，也不能作为编辑内容回写。
- 主会话每次发送时只携带当前活动 Office 标签的 session ID、文档类型和显示名称；`office` 工具在未显式指定 session 时默认绑定该活动会话，Services 仍按 owner session 强制鉴权。
- 三个编辑器和 XLSX sidecar 随桌面安装包内置并校验平台、架构、大小和 SHA；不进入可下载运行时仓库。
- 编辑器构建只共享实际公共依赖；Univer 及表格专用依赖按入口加载，不能因手动分包进入 Word、PPT 的静态依赖链。
- 右侧文件栏和 Agent 知识中的 `.docx/.xlsx/.pptx` 统一进入 Office 编辑器；无活动会话时从授权读取的原文件创建会话，同一所有者和文件复用会话，不再保留独立 Office 只读渲染器。PDF 继续使用桌面 WebView 的 PDF 预览。

## 11. 任务计划

- 长期目标只能由用户显式输入 `/goal <目标>` 创建；普通请求不向 Agent 暴露 `long_task`，来源不明的旧 active 状态不得注入上下文或展示在会话中。
- 侧栏任务计划只展示 Agent 通过结构化 `update_plan` 工具提交的计划，不根据用户提示词分句、目标文本或聊天内容推断计划。
- 计划用于复杂、有歧义或包含多个阶段的工作；简单回答和单一步骤任务不生成计划，也不使用填充步骤凑计划。
- 计划由简短的单句步骤组成，每步不超过 5–7 个词；步骤必须有意义、顺序合理，并且能在执行中验证。
- 步骤状态只允许 `pending`、`in_progress` 和 `completed`，同一时间最多一个步骤处于 `in_progress`；后端不得根据回合结束或最终回复自动猜测状态。

## 12. 会话产物

- 概览中的交付物来自当前会话明确交付的记录；当前过程产物来自当前会话、当前任务的成功文件操作记录。共享输出目录的新增时间、修改时间和扫描差分不能证明任务归属。
- 文件操作事件必须保留发起任务的 `task_id`；历史会话只有在恢复出该会话的精确任务 ID 后才能查询过程产物。旧记录只按其所在的用户任务边界恢复，迟到的旧任务事件不能计入新任务。
- 工作区扫描只提供目录清单和文件当前状态；无归属证据的文件保留在工作区，不补入当前过程产物。刷新、任务完成和切换会话不得吸收其它会话文件。
- 独立"工作区"标签与概览是不同视图：目录清单必须保留扫描到的已交付和过程文件，不得减去 `session_files` 或 `task_files`；只有概览内的交付物与当前过程产物互斥。首次目录请求失败必须显示错误，不能当作空目录。
- 工作区目录按资源管理器语义展示：不按文件名、扩展名、隐藏状态、临时状态或依赖/构建目录过滤；文件夹（包括空文件夹）和链接本身也是目录条目。链接只展示而不递归跟随，避免越过活动工作区。条目达到性能上限时必须明确提示截断，不能伪装成完整目录。
- 同一文件以规范化路径去重；明确交付后从过程产物中移出，不因实时事件与扫描使用不同路径格式而重复展示。
- 文件预览与列表中的旧版记录复用本次请求的会话归属，不逐文件重读整份会话；历史读取、目录扫描和文件读取不得同步阻塞消息服务主循环。每次新请求重新校验归属与路径范围；切换或关闭预览时取消过期 HTTP 下载，取消不得触发备用请求，桌面桥接也必须执行取消。
- WebSocket 附件预览按文件内容 SHA-256 和格式后缀复用磁盘副本；读取历史、刷新、重新发送相同媒体和重启不得继续生成随机副本。源文件内容变化使用新地址，已生成的旧版本仍可读取；界面文件名独立于存储名。
- 媒体上传先校验整批，再写入共享副本；失败不得删除其它消息已经引用的文件。启动后在后台回收旧随机命名的重复预览，不阻塞服务就绪；保留每组至少一份、所有历史路径与签名 URL 引用、当前已签发或读取的附件、真实上传及未知文件。引用扫描失败或文件发生变化时停止回收，不按文件名相似、大小相同或年龄直接删除。

## 13. 生图输出尺寸

- 图片设置内置常用分辨率和画面比例，用户选择默认值；Agent 可通过生图工具的可选参数覆盖本次输出，未指定时使用用户默认值，不修改已保存设置。
- 常用分辨率是便捷预设，不代表所有供应商都支持；生图不依赖尺寸发现、缓存或手动维护能力列表。
- 明确像素尺寸优先于默认比例；本次同时指定像素尺寸和比例时必须一致。仅指定比例且与默认像素画布冲突时，以本次比例为准，由供应商决定尺寸。
- 供应商拒绝尺寸时保留可定位的错误和明确返回的替代选项，Agent 可在符合用户需求时调整本次调用。鉴权、余额、限流与服务故障不能伪装为尺寸错误；扩展请求参数不能覆盖本次已选择的尺寸。
- 生图产物记录真实图片宽高及请求尺寸，但不进行生成后的尺寸达标校验，也不产生尺寸不符告警。服务成功返回图片即直接使用，不因尺寸差异自动重生、裁切或放大。提交结果不确定时不自动重新提交；已有任务 ID 继续查询原任务，部分成功保留已生成图片。

## 14. 生图提示词能力

- `generate_image` 在 turn 入口已预加载时，system 自动加载 `image-generation` Skill；由 `load_capability` 在轮中启用时，加载工具的结果必须先注入同一份完整 Skill，再允许后续图片调用。普通对话、文档专用 Agent 和具备该工具的伙伴 Agent 使用同一套提示词方法。
- `awesome-gpt-image-2` 的原始 Skill、风格索引、完整模板章节、22 个模板指定案例和 541 条结构化案例提示词随内置 Skill 保存，并保留来源、许可证和声明。运行时按图片类型和案例查询逐步读取，不能用摘要目录替代完整模板正文。
- 提交生图前，以实际发送的提示词验收主体与任务、构图与版式、风格与材质、文字、输出形式和针对性约束；读取记录、案例编号和计划文本不能代替最终提示词中的具体设计决定。
- 提示词完整且内部一致即通过提示词能力验收。图片模型的渲染效果不反向判定 Skill 失败；用户提出的新修改继续作为新的图片编辑请求处理。

## 15. 乐谱与吉他六线谱

- 五线谱与六线谱使用独立文件和渲染链路：`.abc` 只进入 abcjs 五线谱预览，`.atex` 只进入 alphaTab 六线谱预览；不得用 ABC 注释触发六线谱，也不得从五线谱 SVG 中隐藏五线谱来模拟独立 TAB。
- 六线谱文件直接记录弦号、品位和时值，预览只显示六根弦，并保留拍号、小节号、和弦名、节奏杆与多行响应式排版。
- `music_score` 只校验 ABC；`guitar_tab` 只校验 AlphaTex。音乐人正式交付对应文件前必须通过同格式校验，不能用 Markdown 字符画或指法说明替代可预览谱面。
- guitar-tab Skill 的例谱必须同时通过交付校验和真实 alphaTab 解析；音符技法与拍属性的位置、时值和含义必须一致，不能把未知属性当作无害文本放行。格式校验不代表手型可演奏或音乐质量通过。
- 吉他指弹默认包含旋律、低音与必要和声；弹唱按唱段伴奏和器乐旋律段分别编配。共享节拍网格通过同弦同品 `t` 接续延音，不能把重复拨弦当作持续音；`ac` 表示音符重音，`dy` 表示拍力度。完整例谱必须覆盖旋律持续时其它弦继续起音及器乐段到唱段的衔接。

## 16. 软件卸载与残留清理

- 已安装桌面软件的卸载方式以当前注册表中的卸载信息为准；前端只传稳定条目标识，不能传入或覆盖可执行命令。优先使用静默卸载命令，失败后尝试普通卸载命令，再使用软件目录提供的备用方式。
- 卸载启动器退出不代表卸载完成，必须等待目标卸载登记移除并核验；执行中状态优先于旧失败记录。未能确认的结果不得标为失败或自动重复卸载，重启生效的返回码须保留对应提示。
- 残留候选只由后端根据已卸载软件的可信安装信息生成。删除必须使用短期、一次性的候选标识并再次确认；执行前重新解析路径，拒绝已变化的路径、链接和受保护根目录，前端提交的任意路径不得获得删除权限。
- 残留扫描覆盖固定层级的应用数据、用户隐藏配置、快捷方式、注册表、服务、计划任务和驱动；只默认选择高置信度专属文件。用户资料、共享资源、服务、计划任务和驱动只检测，不进入普通批量删除。

## 17. Agent 工具权限

- 工具和技能是否开启由用户在已有前端设置中主动控制；执行过程中不追加逐技能脚本审批，技能更新不撤销可运行状态。环境准备仅处理依赖，不承载批准流程。

- Agent 设置的"工具"页是工具授权的唯一入口；功能设置、运行时安装状态和 MCP 连接状态只决定能力是否可运行，不能绕过 Agent 授权。
- 工具目录由"所有专家可配置的固定通用工具 + 当前 Agent 专属工具 + 仅 Mona 可用的协调工具"组成。Mona 不因工具属于 `core` 作用域而获得专家专属工具；专家包重复声明通用工具也不能改变平台通用集合。
- 学术检索、研究记录、科学计算、结构化数据分析和图表属于学者；乐谱与吉他六线谱校验属于音乐人；股票研究和流程提交工具属于对应股票专家或内部子 Agent。专属工具必须在后端注册阶段校验 Agent 身份，不能只靠前端隐藏或包清单约定。
- 工具实际可用必须同时满足 Agent 已授权、依赖和连接可用、当前上下文允许以及订阅门控通过。界面应在同一工具项展示不可用原因，不能让用户维护第二套权限开关。
- 浏览器自动操作对 Mona 默认授权；电脑操作自动化对每个 Agent 独立显式授权，首次任一 Agent 授权时按需下载共享驱动，撤销某个 Agent 的授权不删除已安装驱动。
- 动态 MCP 工具必须进入 Mona 的实时工具目录，并以具体工具名持久化授权；专家 Agent 仍受各自包清单和独立用户授权限制，不能继承 Mona 的动态工具权限。
- 产品升级新增的显式授权工具不能因 `granted_tools` 为空而自动开放；旧自动化总开关只用于一次性迁移，迁移后恢复中性值，不再作为运行时权限事实源。
- 编码与加密、模型供应商配置属于"其他"并默认关闭；升级读取旧权限快照时不能把它们此前的默认开启状态当成用户主动授权，用户可在工具页重新开启。
- 未保存过工具权限的用户按当前工具目录应用默认授权；保存过权限的用户保留自己的选择并可在工具页重新配置。历史 `granted_tools` 中已移除的名称不得重新生成工具目录，用户再次保存时只保留当前可配置工具。
- `canvas`、任务状态和 `my` 等运行时上下文工具由系统管理，不显示为用户权限开关，也不能被旧权限清单意外关闭。
- `my` 保留模型与配置修改能力；Notes 与 Agent Knowledge 搜索/读取保持初始可见，支持主动资料查询。专项能力由模型通过 `load_capability` 按自然语言加载，活动 Office/数据库/终端/浏览器上下文和媒体附件可预加载；请求级状态在并发会话间隔离，工具加载不得绕过身份、用户授权、订阅、依赖或后端运行状态。
- 必需能力的授权不等于 Schema 常驻。开发/命令、HTTP、Skill 配套工具可经能力加载提供；`skill_read` 成功后自动启用参考资料/脚本/素材工具。文档专用 Agent 预加载开发与 Skill 配套能力，内部无加载器的工具视图保持完整。保留历史中的工具调用可恢复已发现能力，但不能扩大当前权限或触发执行。
- 文件与命令、Agent 私有记忆读取和技能基础读取/执行工具属于所有 Agent 的必需运行能力，不显示权限开关；用户保存空权限或旧权限清单也不能关闭这些能力。`memory_edit` 和 `skill_create` 仍由 Dream 或明确具备该职责的专家运行，不因此进入 Mona 普通会话。终端维护、外部连接及其它业务工具不因此自动获得授权。
- 网页搜索、网页读取和结构化 HTTP 请求属于所有 Agent 的必需网页访问能力，默认且始终开启，不显示权限开关；浏览器自动化仍是独立的可配置能力。
- 委派、创建子任务、协作流程和即时协作属于 Mona 必需的协调能力，不显示权限开关且不能被旧权限清单关闭；专家 Agent 不能继承这些能力。
- 群聊伙伴和协作步骤只共享公开消息、目标及公开摘要，主 Agent 含私有工具结果的归档摘要不得直接共享。房间压缩单独生成公开摘要；失败时保留原始消息和游标。长历史与上游结果使用当前任务冻结的引用分页补读，不能用引用访问其他房间、Agent 或任意路径；不完整预览必须明确标注。
- `terminal_task`、`terminal_exec`、`terminal_output`、`terminal_upload` 属于 Mona 的终端/SSH 模块，不进入专家 Agent 的可配置或运行工具集。专家保留工作区文件与受控 `exec` 能力，它不绑定用户当前 SSH 或桌面终端会话。
- 工具分类、是否系统管理、是否显式授权和 Agent 所有权由后端目录返回；前端只保留旧后端兼容回退和本地化文案，不能自行扩大工具范围。
- 主 Agent 每轮调用模型前必须确认已授权的电脑操作运行时和 MCP 连接可用；驱动内部会话标签由 Mona 按连接和对话管理，不暴露给模型选择，避免复用已结束会话。
- 电脑操作统一使用前台模式，由执行层控制投递方式；同一时刻只允许一个任务持有桌面。点击、输入等交互绑定最近一次截图的窗口或桌面，元素标识与坐标互斥，坐标不得越界；操作后必须重新观察才能继续。新启动的应用先观察其窗口，再聚焦操作。驱动拒绝和执行结果元数据必须保留，派发成功不能作为界面效果已验证的证据。
- 前台模式同时保留控件接口和截图坐标路径：窗口交互先显式聚焦精确目标，聚焦失败或期间被停止则不继续派发；控件操作保留元素标识及语义参数，不能统一降级为坐标点击。画布、游戏棋盘或控件树未覆盖的区域使用截图坐标，输入投递固定为前台。
- 停止与任务结束必须结束本轮已使用的驱动会话并清理指针；被停止的轮内不得通过连接恢复重新派发操作。停止不能撤销操作系统已接收的输入。前端复用停止入口提供接管提示，运行状态不得从旧任务工具记录推断。



## 18. 内置 Coding 独立装配

- 每个项目内置 `explorer` 与 `worker`，固定名称与标识，支持启停和模型配置，不允许删除；旧项目读取时补齐但不覆盖自定义配置。内置项默认跟随主任务的引擎、模型来源与思考强度，关闭后不可新派发，不中断已有子任务；自定义项维持原路由，仍可添加、编辑和删除。两个内置项不占用原有 32 个自定义名额；保存时省略内置项保留已有配置。`explorer` 默认只读，`worker` 沿用父任务权限，所有子任务均不能扩大父任务授权。
- 两个内置角色的描述与执行指令逐字采用 Codex `codex-rs/core/src/agent/role.rs` 角色说明原文，界面只读，保存接口拒绝修改；旧内置文本读取时规范化，保留用户的开关、模型和权限选择。启用预设授权主任务按需自主委派，不要求用户逐次点名；全部关闭时运行上下文明确标记停用，主任务自行完成后续工作。派发准备期间关闭角色也不得创建新子任务，已派发结果继续可读。角色原文与 Mona 的权限、派发协议分开提供。
- 主 Agent 负责规划、拆分、整合与最终验收，探索和实现优先交给配置的对应角色；子任务须具体、有界、自包含，可承担关键路径工作。仅在下一步需要结果时等待，不重复子任务已承担的工作；简单任务可直接完成。引擎、模型、来源与思考强度由预设路由，主任务不临时替换用户配置。
- 委派原则进入 Mona 主任务 system 与原生 CLI 主任务正式 developer/system 上下文；运行信息只提供可用角色与开关数据。适用的 Codex 原文保留，只有项目授权、跨引擎协调和入口约束按 Mona 需要调整。字段要求放入工具 Schema，不在正文重复。所有原生 agent/task 入口关闭，子任务统一走 Mona 宿主工具并继承父任务权限；Codex 旧上下文只在任务已确认结束后更新，未知执行仍按原身份核对，不重发原请求。
- 内置角色原文用于主任务选人，不作为子任务继续分派的指令；自定义角色的执行指令仍传入子任务。子任务禁止嵌套委派：不装配委派工具，存储事务拒绝继续创建子任务，原生 Agent/Task 入口保持禁用；该边界进入子任务正式 system/developer 上下文。
- 默认仅启用 Mona；原生模型来源按需启用并使用各自模型目录，API 供应商模型由 Mona 执行，不为单个模型选择另一引擎。原生程序按明确路径、本机发现、受管安装的顺序定位；“引擎管理”独立展示本机与受管程序，用户可显式下载受管副本，统一仓库只更新或删除受管程序，不覆盖系统安装。删除仅清理对应程序与下载缓存，阻止下载、登录、运行中或结果待核对的受管程序被删除。停用来源只阻止后续调用，保留已有任务、账号与显示偏好。路径或程序版本变化时只释放空闲宿主；运行中、登录中或结果未知的宿主不因升级而中断或重放任务。
- 内置 Anthropic 来源仅复用本机 Claude Code 账号：读取原生凭据库，Mona 只持久化使用绑定；OAuth 元数据只进入子进程环境，不返回 UI 或写入日志。断开不删除系统凭据且阻止既有会话继续发送新任务。API 模型桥接使用独立的会话凭据，不混用本机 OAuth。
- 新 API 供应商模型始终由 Mona 调用，不接受逐模型引擎覆盖。原生来源使用各自账号与模型目录；旧覆盖数据保留但不再决定后续路由。已有原生会话和绑定保留模型来源，跨来源使用交接，不能因型号同名复用另一来源的绑定。
- 旧模型桥接的会话证据和历史读取代码可以保留，但新配置不再创建跨引擎模型路由；旧任务的未知结果仍需原身份核对，不自动重放。
- 模型思考强度按供应商、模型和执行方式的能力声明提供，不统一猜测档位。运行时声明优先；Mona 托管目录缺少能力字段时，仅按已核实的精确型号使用内置目录补齐，服务端显式空档位不可被覆盖。无可靠能力或不足两档时不显示滑条；发现、保存和选择必须保留同一组档位与推荐值。原生引擎的选择随会话持久化并进入真实请求，同一模型切换强度也必须更新已加载的配置；不支持的档位在派发前拒绝，不能静默忽略。
- Work 与 Code 共用文件编辑、检索、进程管理和基础运行器实现，但 Code 工具实例、允许集合、执行预算和 Exec 配置由 `development.coding` 独立装配。Work 的业务工具、人格、画像、长期记忆和全局 Skills 不进入 Code；明确选择的模型来源和预设仍可共用。
- 普通 Work 的模型选择同时支持 Mona/API 与已连接的原生来源；启动后同步已启用来源的目录，首页不依赖进入 Code 才能读取。原生 Work 使用同一份 Mona 历史、人格与工具授权，原生工具请求交回 Work Runner 执行及落盘；原生内置文件、命令、搜索和任意 MCP 不得绕过 Mona 边界。单轮冻结引擎、型号和思考强度，失败或停止不自动切换来源、重发未知操作。Code 的显式模型来源不受 Work 默认引擎选择影响。
- Code 的读写、检索和命令直接可用；只读装配保留检索但不注册写入与命令。计划和委派通过 Code 专用按需入口启用，不扫描 Work 能力目录，不强制规划或协作，不随加载修改本轮 system。
- Mona 文件工具覆盖已有文件或单次编辑时，必须匹配本会话读取版本或显式来源 SHA256，并在写入前复核；新文件使用独占创建。同文件批量编辑对原始文件做唯一匹配和重叠检查，全部预检完成才原子替换；匹配失败不写入，保留未改区域的 BOM、换行和人工修改。来源重检是乐观保护，不是对其他进程的操作系统级 CAS，不增加项目级写锁。
- 运行中纠偏和后续消息分开：纠偏在完整工具批次或响应边界送入同一轮，未接受可撤回，收到后续模型响应才认定消费。结果不明不自动重放；未赶上结束边界的待发送纠偏以可见延期事件保留为后续输入。
- 主任务可通过宿主协调工具向直接子任务发送有界纠偏，绑定原委派 Run、稳定请求标识和原权限。Mona 与支持纠偏的 Codex 原生轮次沿现有输入协议接受；不支持的引擎明确拒绝。此类消息错过原轮次时只保留待核对记录，不自动转为新任务或移到其它 Run，未知回执不重发。
- Code 可在模型调用前进行语义压缩投影，原始历史与工具记录保留；切点不得拆开工具配对，当前用户目标和已接收纠偏保留原文。提前阈值不是停止合法任务的门禁；完整摘要保存成功后才推进游标，清除读取去重标记但保留文件新鲜度摘要。明确上下文超限只重试模型请求，不重新执行工具。
- 这些连续性扩展在共享 Runner 中默认不启用，普通 Work 保持原执行和消息合并行为。原生 CLI 保留其内部上下文和输入协议，不把内置 Coding 能力假称为所有 CLI 已支持。
- Code 的模型传输由本轮执行拥有，正常结束、异常、中断均显式关闭响应流和客户端；清理完成前不得报告本轮成功或自动启动排队任务，清理失败不能隐藏。Code 不继承 Work 的备用模型链，也不因故障静默更换用户已选模型。
- 开发浏览器验证复用已有浏览器工具、CDP 和截图；仅在用户明确关联本会话目标页后按需装配，不提供跨标签枚举、任意脚本和隐式新建替代页。关联写入要验证当前版本，操作前后重新检查关联、标签和站点；解除关联不关闭用户页面，不撤销已经派发的操作。页面来源检查不是网络沙箱，结果未知不自动重放；原生 CLI 和只读会话不继承该权限。
- 开发终端的视图关闭、会话切换和模块隐藏不结束进程；显式结束确认前保留进程身份和输出，创建中结束须回收同一个迟到进程，失败不允许静默新建替代。自然退出依据原生进程观察与事件更新，不依赖 PTY 输出管道 EOF；状态读取失败保留进程身份并禁止继续输入，核对成功后恢复。Code 复用终端组件但不触发 Work 的 SSH 管理流程。
- 开发预览恢复优先使用当前会话原标签身份，并同步宿主归属；原页面缺失或来源变化不自动新建或重新授权。同一原生标签的布局请求跨组件重挂载共用串行队列，新视图接管后旧视图不得发送隐藏或尺寸操作；卸载后的最终隐藏排在已发出的显示之后，失败的布局状态不能当作已确认事实。
- 协作结果在父会话持久化成功后才能标记已回传；缓存中的未落盘消息不能作为成功证据。工作台审查和委派的原请求标识、已确认正文按会话持久保存，响应丢失、关闭标签或恢复视图不自动更换标识或重新派发；用户核对时先按父会话和原请求精确观察。只读审查不得因预设权限变更获得写权限。
- 委派准备被取消或宿主重启时，没有子任务 Run 的准备记录以失败结束并回传一次；已有 Run 的记录沿原身份观察，不重新派发。首轮父会话摘录按消息标识只传一次，交接预算未容纳时才由运行上下文补齐。
- 普通只读探索按委派目标读取项目，派发前不生成整仓库差异。版本化审查绑定已确认的项目内范围、仓库基准与真实差异；派发前由后端核对并提供资料，不信任前端提交的差异正文。版本查询只读且区分未变、已变和不可核对；检查结果属于注明时间的范围快照，不等同于审查通过、全仓库认证或未来执行授权。主会话接续重新读取版本，已接受请求优先恢复原身份，不因代码变化重新派发；旧记录不得补造历史基准。
- 永久删除按会话 ID 同时删除父子会话记录；运行中、排队中、等待确认、unknown 状态和旧 revision 均不阻止删除。后端取消该会话执行与待发输入，并阻止迟到保存重建记录；执行者或终端清理失败、超时不回滚删除，保留必要资源身份并明确告警，不影响其他任务或项目文件。
- 归档可用于运行中的会话，不得因 Run 状态禁用。
- 普通会话与开发主会话、新任务、侧边聊天共用 `ThreadComposer` 的输入外观、自动高度、用户发送快捷键、停止按钮和队列交互，但执行调度和存储保持独立。普通 Work 的待发项当前由前端保存，已发送追加由服务端内存队列在安全边界消费，不能宣称具有持久 `follow_up` 协议。开发会话运行中输入默认经服务端 `follow_up` 排队；Mona Coding 可将队列条目“追加”为 `steering`，不支持该能力的原生 CLI 不展示此操作。开发输入的编辑和撤回必须以服务端确认成功为准；失败保留原内容及请求标识，不得生成新请求重复执行。附件使用同一“+”入口和上传通道；开发请求保存原始文字与附件引用，收到明确接受回执后才清空，失败、重挂载、切换会话或编辑排队消息不能丢失附件。已接收开发输入重试复用已保存的内容，不重新读取可变化的上传文件。
- 开发会话的三档权限按会话保存、按 Run 固定；只读约束独立，子任务继承权限且不能自行放宽。已启用预设的主任务委派不重复审批，子任务实际操作仍按继承权限审批。活动轮次、待核对输入和 Mona 后台命令阻止切档。审批绑定原会话/Run/确认 ID，自动审核不可用交用户确认；Mona 开发工具和 CLI 回调共用审批入口，沙箱运行时沿用统一组件仓库。平台隔离事实和原生回执须与实际一致，缺后端不裸执行，完整机制见 `development-permissions.md`。
- Codex 原生引导精确绑定原 Run 与原生 turn，不把已经结束的引导目标变为新任务；回执未知保留原输入标识且不重放。沙箱审批显示在输入区，保留草稿与附件，摘要面板不重复提供审批；类似命令授权只使用原生提议的合法前缀。
- 开发图片在受限上传目录中校验实际格式和总大小，转换为不可变的文本/图片内容块；Mona、Codex 与 SDK 执行通道传递真实图片内容，不用文件名说明代替视觉输入。原生协议帧预算与图片总预算一致，畸形或过大输入在派发前拒绝，不能把未传送内容宣称为模型已看到。
- 子智能体详情保持列表、返回、名称/模型和正文结构；仅在运行中或有待处理事项时提供停止/处理入口，完成后不常驻控制面板。父会话可显示同项目、直接归属子任务的审批，提交始终使用子任务所属会话和原确认 ID；停止一个子任务不停止主任务或其他子任务。
- SDK 的同一消息块跨流式片段与分段最终消息保持标识，轮次内工具调用关联不因单条消息清空；事件重放仍核对原始内容。同一命令已排队的相邻输出可在容量限制内无损合并，不跨越状态事件。原生事件处理异常在脱敏日志中记录运行、绑定和异常类别，不输出原始回复或异常正文。
- 无原轮次查询能力的 SDK 任务处于 unknown 时，禁止自动重发。用户核对文件并明确确认后，先结束受管原生会话、取消该轮待发输入，再以 `closed_unknown` 保留原证据；该状态只表示结束跟踪，不表示成功或已撤销外部副作用。只有新的用户请求才建立后续执行上下文；原请求 ID 仍只恢复旧记录。
- 任务结果未知与当前仍在执行分开呈现；重启恢复的 `unknown` 不驱动运行中动画。打开 Codex 会话时系统按原绑定和轮次只读核对，不重发原请求或排队输入；缺少轮次标识或历史查询不可用时，只有派发已结束且原生会话明确空闲才以 `closed_unknown` 结束跟踪，不宣称原任务成功。续接时回放的历史用量不能进入新轮次。停止精确作用于原轮次；Mona 已失去执行句柄时也只结束跟踪，不能声明文件改动已撤销或所有外部进程已停止。
- 任务摘要浮卡只包含项目 Git 操作、子智能体、项目规则与 Skills；任务错误、待处理事项、停止或连接恢复、资源诊断不进入摘要。待处理操作复用已有弹窗，通过既有更多菜单进入；内部自动恢复不创建独立产品入口。
- 启动时原生账号探测不自动登录；同一进行中的初始化去重。探测或退出成功后通知已挂载的供应商页和模型选择器刷新目录，但不改变已有任务的执行引擎、模型或草稿。
- 新文件审查使用相对空文件的真实 Git 差异，遵守忽略规则、路径范围及读取预算，不通过自动暂存获取资料。单文件和有界全部变更复用同一版本化审查确认流程；读取期间内容变化或超限时拒绝，不以截断资料代表完整审查。
- 宿主发起的必要子任务绑定原主轮次；原生或模型返回最终文本不代表尚依赖子结果的任务已完成。未接收必要结果时保留等待状态，历史工作标题同步显示等待或待核对状态，不标记为工作中。结果落盘后由原主执行引擎接续处理；附加调查不自动唤醒已结束任务。结果接续有显式次数上限，不引入隐藏模型。
- 子任务失败以原执行者的明确失败回执或明确的启动拒绝为依据；等待查询超时、参数错误或连接中断不作为子任务失败证据。等待超时保留原任务，查询错误只标记对应操作，不能生成“协作未完成”的独立任务行。
- 结果接续正文先落盘，再原子登记稳定的后续输入并释放等待轮次；只恢复已知未派发的准备，不重放已有未知执行。人工停止等待保留子任务独立生命周期；停止单个子任务必须精确绑定其原执行记录。
- 子任务并发上限按项目在存储事务中校验，重复请求不重复占用名额。文件并行活动仅是带时间的有界提示，不提供项目写锁或独占归属；保存依旧核对当前内容，提示查询失败不得把已保存文件报告为保存失败。
- 长协作结果的预览明确标注截断，后续读取固定到原委派轮次及内容摘要，不能拼接不同版本或后来任务的结果。任务交接保留有界目标、已有摘要与计划状态；陈述、计划和结果返回均不是验证通过的证据。
- 父子交接优先保留尚未摘要的真实用户约束，按字符和 token 双重预算筛选，明确记录省略数量与来源消息标识。协作结果按任务标识和内容 SHA 去重；当前工具结果或接续输入已包含同版本预览时不重复注入，已摘要结果保留读取引用。原生跨轮去重须有同一绑定已成功轮次的预览接收记录，尾页读取或未知回执不能当作预览已送达；切引擎时不把未回放的产品历史算作当前模型已见内容。原始历史和交付记录不删除。
