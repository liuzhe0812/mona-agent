# Mona 模块关键不变量

- 状态：Accepted
- 最后更新：2026-09-08

本文保留已落地模块中仍需长期保护的行为边界。历史实施步骤、完成日志和一次性文件清单不在此保留。

## 1. 邮件

- 邮件采用 offline-first：优先读取完整本地 `.eml`，本地缺失或损坏时才请求网络，成功后立即落盘。
- `.eml` 保存完整 RFC822；`.meta.json` 保存本地状态；SQLite 保存索引和同步水位，不保存正文副本。
- `body_fetched=true` 只表示完整 RFC822 已成功落盘，不能表示“发起过请求”或“拿到部分正文”。
- HEADER-only 文件必须保持 `body_fetched=false`。文件写入或数据库更新任一步失败时不得推进完整状态或同步水位。
- IMAP MOVE/COPY/STORE/SELECT 必须检查服务器状态；移动后以目标文件夹新 UID 为准，不能继续使用源 UID。
- Modified UTF-7、UIDVALIDITY、增量同步和目标文件夹同步属于协议正确性，不得由 UI 重试掩盖。
- 正文加载同一邮件最多一个在途请求；已处理错误不重复抛出形成自动重试循环。

## 2. 通讯录

- 本地联系人、CardDAV 和 Exchange ActiveSync 使用统一的联系人结果模型，但同步协议实现保持独立。
- 联系人索引和同步状态保存在邮件数据库；账户级同步令牌不得跨账户或跨协议复用。
- CardDAV 外部 URL 必须经过 SSRF 校验，XML 解析必须防止 XXE。
- ActiveSync 维持稳定 DeviceID、Provision PolicyKey、FolderSync 和 SyncKey；分页必须有上限。
- 邮件编辑器的地址自动完成读取本地索引，不在每次输入时直接访问远端服务。

## 3. 数据库客户端

- Rust `CellValue` 的 JSON 是 `{ type, value }` 判别联合。新增 variant 时必须同步更新 Rust 序列化、TypeScript 类型和显示函数。
- 每个 `ConnectionManager` 能力必须明确处理 SQLite 与 MySQL；SQLite 同步锁和 MySQL async pool 不得混用假设。
- AI 生成 SQL 与执行 SQL 分离；高风险操作必须经过风险判定和用户确认，凭据不进入模型上下文。
- 查询结果、变更记录和错误使用结构化协议，不从自然语言推断执行是否成功。
- 数据表浏览与 SQL 查询使用独立的标签类型；表身份由连接、数据库、表名确定，不能用标签标题或 SQL 文本推断。切换标签同步显示目标，不重新执行或丢弃修改。
- 数据表筛选、排序和分页作用于数据库完整结果，生成 SQL 必须转义标识符与值；对象摘要批量读取，不逐表精确计数。
- 表格新增、修改、删除先暂存；没有可靠主键的表、视图和普通查询结果只读。多行保存按实际提交结果清理，失败后重试不得重复提交已完成的新增行。
- MySQL 标签指定数据库时，选择数据库和执行语句必须在同一条借出的连接上完成；不能依赖连接池中的隐式当前数据库。
- 表结构编辑使用独立标签和完整结构草稿；字段、索引、外键、触发器和高级选项共享预览与应用入口。后端核对各分区原始快照并重新生成变更，不能直接执行前端提交的 SQL。数据页有未保存修改或正在读取时不能应用结构变更，结构应用期间暂停同表数据编辑。
- 结构变更已经执行但重读失败时必须返回明确结果，前端清除已应用草稿并提示刷新，不能把它当作未执行而重复提交。SQLite 支持的多步结构变更在同一事务内执行；MySQL 将表定义变更合并为单条 ALTER TABLE，触发器按独立语句执行并返回已完成语句数。

## 4. WebView2 浏览器

- 所有 WebView2 标签共享应用默认数据目录，确保登录态、缓存和 CDP 可见性一致。
- CDP 端口在 Tauri 启动前固定；自动化通过注入的标签标识匹配目标 Page。
- 导航通过 Rust IPC 完成；`target=_blank` 由初始化脚本拦截并交给标签管理器。
- 子 WebView 的创建、尺寸和可见性不得在持有阻塞状态锁时执行。
- 浏览器外壳遵循全局 UI 规范；网页内容本身不做产品 Token 化。

## 5. 可编辑画布

- 流程图和思维导图继续使用既有文档模型和 patch 校验器，不创建第二套 schema。
- 主会话只在用户明确表达创建意图时创建画布；普通讨论不产生画布文件。
- AI patch 必须携带请求时的 base hash。生成期间用户已修改语义时，过期 patch 不得覆盖当前内容。
- `.mona-canvas` 是工作区产物，不依赖笔记仓库；每张画布独立保存并记录 `originChatId`。
- 画布预览和编辑复用同一渲染/几何定义，避免图形库、编辑器和只读预览出现多套实现。
- 连线的连接侧、端口比例与显式控制点属于文档几何，保存、哈希、编辑和渲染一致。自动避障不覆盖显式路线；局部连线修改只调整受影响的边，并避让其它已存在的路线。共线重叠按实际渲染线段检查，不用端点 ID 相同代替几何判定。
- 主会话展示自然语言结果，不展示内部 patch JSON。
- 画布 `open` 只读取文档、版本和选区，不等待字体、动画帧或截图。`apply` 在文档提交后返回，视觉验收由显式 `inspect` 执行；提交成功不等于视觉验收通过。
- 同一画布请求只执行一次；超时、卸载时取消未完成的检查，不自动重放结果未确认的写入。侧栏收起保留编辑器，激活后用状态回执确认可接收操作。
- 画布侧栏激活在轻量 `open` 等待期间可以幂等重发，并携带已校验的工作区文件路径；重新进入会话时从 `originChatId` 恢复该会话画布。同一会话的后续消息未重复携带画布字段时，工具保留该会话最近的画布上下文；切换会话必须清空。
- 生成批次按内容模块决定，不以固定批次数限制创作；Skill 保留设计经验与必要文档协议，连接恢复、超时和熔断由代码负责。
- 主会话流式更新时，未变化的画布编辑器必须保持挂载但跳过重渲染；活动轨迹、工具事件和推理展示数据必须有界，不能因长会话无限累积。
- React Flow 的对象/数组配置和事件回调必须保持稳定引用；动态连接点只在端口集合实际变化时调用 `updateNodeInternals`。禁止用每次 render 新建的 `fitViewOptions`、`proOptions`、`snapGrid` 或内联 Store 回调形成 Store 更新循环。

## 6. Terminal AI 维护

- 终端 AI 会话按连接身份绑定并持久化：面板重新挂载、SSH 重连和应用重启后必须恢复同一会话历史，不能静默新建空会话；只有用户显式「重置会话」才解绑。终端 AI 会话是普通可见会话，不进入隐藏会话集合。
- AI 维护任务使用后端持久状态，而不是根据聊天文本模拟 Todo。
- 命令成功退出不等于任务成功；发生变更后，必须有晚于最后变更的成功复检才能完成任务。
- 高风险或禁止命令的审批边界不能因自动模式而绕过。
- 取消、超时、断连和应用中断必须落为可查询的最终状态。
- 维护记录保存目标、步骤类型、状态和验证结果，不保存原始命令、完整终端输出或凭据。
- 批量清除维护记录只能删除已结束的任务；进行中的任务与步骤必须保留，判定以存储层状态为准，不由前端列表推断。
- IPC Bridge 必须鉴权，未鉴权请求不能触发终端执行。

## 7. AI 文档工作台与 PPT 工作流

- AI 文档模块以固定开始页和多文档标签工作台为统一产品入口；开始页支持新建 Word、Excel、PPT 和视频，普通 Office 文档在该工作台进入人机实时协作编辑会话。
- 开始页保持为固定标签；文档标签对应具体文档或项目，工作台不依赖左侧模块导航。开始页提供历史和收藏两个列表入口。
- PPT 统一进入 Slides Office 会话直接编辑，不再保留独立的 PPT 制作工作流、项目阶段或专用 Document Agent。
- 主会话右侧“新建 PPT”只创建 `slides` 类型的 Office 会话并打开空白 `.pptx`，不得启动 PPT 制作工作流。
- 主 Mona 对 PPT 的创建、大纲、视觉方案、逐页制作和修改统一使用 `mona-pptx` 与 Office 工具。
- 视频/PPT 等项目会话是普通会话：进入会话列表并像普通会话一样生成标题，模块自带的历史面板只是额外入口，不得把会话从列表中隐藏。隐藏集合仅保留隐藏房间等不可见执行容器。
- 委派循环（DocumentAgentLoop、PartnerAgentLoop）必须复用父 AgentLoop 的 `WebuiTurnCoordinator`：turn 由父循环结束、由委派循环执行，各自新建协调器会让标题上下文永远取不到，委派会话因此失去自动标题。

## 8. URL 转笔记

- 页面类型判断和内容提取由共享后端负责，浏览器与笔记入口不得复制不同实现。
- 视频优先使用字幕；无字幕时才懒加载本地 ASR。
- ASR 模型只在转写子进程内加载，完成、取消或超时后必须释放进程资源。
- 重点帧最多提取少量高相关时间点，复用已下载视频；无法可靠判断时不强制插图。
- 笔记图片写入笔记仓库 `assets`，运行时模型和任务临时文件不得进入笔记仓库。

## 9. 检索与用户画像

- Notes 与每个 Agent 的 Knowledge 保持独立事实源，统一检索只统一工具和结果契约。
- 每个 Agent 拥有独立的 `raw/text/evidence/wiki/index`；MD5 只在同一 Agent 内去重，不共享可变 Wiki。
- 新资料自动异步学习；文字与视觉证据完整写入后原文即可检索，Wiki 继续增量整理并展示业务进度。Wiki 整理失败不撤销完整证据，用户可手动从已完成部分继续；视觉证据中影响含义的关键信息无法辨认属于失败，装饰图或微小品牌标记可保留次要不可辨认标记，不得因此丢弃整份文档的其他知识。
- 原文件不可变，完整证据不能被 Wiki 摘要替代或删除；Wiki 结论必须能回到来源位置，未进入 Wiki 的细节仍可读取。
- 搜索、读取、证据和链接跳转都必须绑定运行时 Agent 身份。模型构造的 Agent ID、旧知识库 ID、引用和路径不可信。
- 旧 Materials 多知识库只用于迁移和旧引用兼容，新 UI 不暴露知识库范围配置。
- 用户画像属于用户级平台数据，与每个 Agent 的私有记忆分离。
- 画像只接收真实用户信号，排除 assistant 推理、内部任务、系统消息和运行时元数据。
- Agent 只接收白名单、裁剪、带版本的只读画像快照；画像不能扩大 Agent 权限。
- 桌面普通直聊的跨会话回忆使用同一 Agent 范围内的 transcript 正文与 FTS5 关键词索引；不从 `memory/history.jsonl` 的摘要反推原话，不把协作房间、隐藏任务、临时会话或其他 Agent 会话混入默认搜索。
- 会话历史索引是可重建派生数据；读取引用时必须重新验证来源和 Agent 归属。删除来源后搜索和读取都不得返回旧索引内容，旧记录缺少真实时间时不能以回放时间补造。

## 10. Office 实时编辑

- Office 任务由 `mona-docx`、`mona-xlsx`、`mona-pptx` 三个专用 Skill 负责，共用同一个 `office` 工具和会话协议；不再保留 `mona-office` 或 `doc-writing-guide` 入口，也不强制普通写作先加载共享指南或默认输出 HTML。PRD 专业参考通过 `prd-document` 按需加载。
- Word 统一进入 `mona-docx`；高级 OOXML、修订、批注和转换说明及脚本归属于该 Skill，不再暴露平级 `docx` 入口。只有确认具体操作不受实时工具支持时才切换离线处理，参数错误、版本冲突或截图失败不等于能力缺失。离线处理基于最新版本导出的副本，保留原文件与用户后续编辑，结果重新打开并验证后交付；不得将打包成功视为版式验收通过。
- `OfficeSessionManager` 归属 Services，负责会话、权限、命令队列、checkpoint 和保存；Gateway 的 `office` 工具只通过受保护客户端调用 Services，并将鉴权读取的 checkpoint 原子写入当前 Agent 工作区作为导出文件。Services 不接收或解析 Agent 工作区路径。
- Editor 是当前文档模型与事务提交权威；Manager 只维护版本镜像。Agent 操作必须同时通过 Manager 预检查和 Editor 最终版本检查。
- 用户编辑、Undo/Redo 和 Agent apply 共用单调 revision；过期操作返回冲突，不能静默覆盖用户修改。
- 幻灯片操作只有实际修改文档后才推进 revision；已满足请求时返回 `unchanged: true`、原版本与空修改目标。未知图表字段必须拒绝，不能静默忽略后报告成功。
- 图表读取和修改使用同一稳定元素 ID；仅修改文字颜色时保留原生图表数据、引用及其它格式，编辑器渲染和保存文件必须读取同一组文字属性。
- PPT 局部读取先确定页面/元素范围，selection 返回可执行修改所需的选中对象摘要；能力参数按需读取。结构化回执携带创建/更新对象与可定位的布局警告。
- Agent 新建 Word 内容使用独立的文档标题角色和中性的显式字体层级；新建表格默认包含可识别的表头、浅色边框、单元格垂直居中、重复表头和禁止跨页拆行。已有文档只按用户要求局部修改，不强制套用新文档默认样式。
- Office 打开回执包含当前选区和其权威版本；新建幻灯片的回执直接携带页面 ID。能力查询可限定具体操作，未知页面/元素/操作不能返回空的假成功。
- PPT 布局变更与布局警告进入待观察页集合，随会话保存并恢复。成功且版本一致的完整页视觉捕获不自动清除仍存在的硬布局错误，也不证明内容完整或设计合格；图文交叠等需检查项只有在当前版本整页画面确认后显式接受，才能解除待观察状态。
- Word 修改进入文档验收状态；完整连续文档视觉检查可解除无警告状态，异常页码字段必须修复，表格跨页拆行需观察后明确接受。Excel 修改范围进入验收集合，只有覆盖该范围的 `range` 读取才能解除；本次修改公式返回明确错误时阻止正常导出。两者都不因既有未触及内容扩大自动修改范围。
- Agent 正常导出 Office 文件前必须处理对应待验收目标并消除硬错误；用户明确请求未审核草稿时可导出并保留草稿审阅状态。保存工作副本和用户直接操作编辑器不被 Agent 导出门控阻塞。
- PPT 网格混排必须转换为独立原生对象；静态 SVG 作为可移动缩放的矢量图片保留，不宣称其内部路径可逐个编辑。SVG 不允许活动内容和外部资源引用。
- 常见 PPT 数据图表可用 `slide_add_chart` 以预览像素创建，内部复用原生 addChart 并保留数据模型。字符条伪图表、长内容单框作为可定位的设计疑点返回；不以图片数量或空间占用比例机械判断质量。接受非阻断提示必须先观察同版本整页画面并给出 `reviewReason`；编辑后观察记录失效。
- 图片资产路径仅由 Gateway 在当前工作区范围内解析并转换；传入编辑器的命令不包含可访问任意本机文件的路径。
- 局部渲染复用未受影响页面；有跨页语义的操作仍走全量路径。版本快照可以延迟压缩，但必须在提交时固定内容，后续修改不能改变旧版本 checkpoint。
- Agent 将结构化 `ok: false` 识别为失败；同一 Office 目标连续无进展时限制继续修改，仍允许检查和处理其它目标。正常版本冲突不计为无效修改。
- 中断恢复保留当前 turn 已完成的各轮工具调用和返回；同一批工具每完成一个就更新恢复记录，不能只保留最后一轮。
- checkpoint 必须绑定精确版本并原子替换工作副本。异常退出只能恢复最近 checkpoint，存在未持久修改丢失时必须明确提示。
- Agent 只接触稳定的 Mona Office Schema，不接触 Univer、ProseMirror、GenOffice AST，也不能发送任意 JavaScript、HTML 或文件路径。
- 视觉检查必须由当前 Editor 的真实渲染生成并绑定精确文档版本；截图补充结构化读取，不能取代段落、单元格、公式、页面和元素检查，也不能作为编辑内容回写。
- 主会话每次发送时只携带当前活动 Office 标签的 session ID、文档类型和显示名称；`office` 工具在未显式指定 session 时默认绑定该活动会话，Services 仍按 owner session 强制鉴权。
- 三个编辑器和 XLSX sidecar 随桌面安装包内置并校验平台、架构、大小和 SHA；不进入可下载运行时仓库。
- 编辑器构建只共享实际公共依赖；Univer 及表格专用依赖按入口加载，不能因手动分包进入 Word、PPT 的静态依赖链。
- 右侧文件栏和 Agent 知识中的 `.docx/.xlsx/.pptx` 统一进入 Office 编辑器；无活动会话时从授权读取的原文件创建会话，同一所有者和文件复用会话，不再保留独立 Office 只读渲染器。PDF 继续使用桌面 WebView 的 PDF 预览。

## 11. 任务计划

- 长期目标只能由用户显式输入 `/goal <目标>` 创建；普通请求不向 Agent 暴露 `long_task`，来源不明的旧 active 状态不得注入上下文或展示在会话中。
- 侧栏任务计划只展示 Agent 通过结构化 `update_plan` 工具提交的计划，不根据用户提示词分句、目标文本或聊天内容推断计划。
- 计划用于复杂、有歧义或包含多个阶段的工作；简单回答和单一步骤任务不生成计划，也不使用填充步骤凑计划。
- 计划由简短的单句步骤组成，每步不超过 5–7 个词；步骤必须有意义、顺序合理，并且能在执行中验证。
- 步骤状态只允许 `pending`、`in_progress` 和 `completed`，同一时间最多一个步骤处于 `in_progress`；后端不得根据回合结束或最终回复自动猜测状态。

## 12. 会话产物

- 概览中的交付物来自当前会话明确交付的记录；当前过程产物来自当前会话、当前任务的成功文件操作记录。共享输出目录的新增时间、修改时间和扫描差分不能证明任务归属。
- 文件操作事件必须保留发起任务的 `task_id`；历史会话只有在恢复出该会话的精确任务 ID 后才能查询过程产物。旧记录只按其所在的用户任务边界恢复，迟到的旧任务事件不能计入新任务。
- 工作区扫描只提供目录清单和文件当前状态；无归属证据的文件保留在工作区，不补入当前过程产物。刷新、任务完成和切换会话不得吸收其它会话文件。
- 独立“工作区”标签与概览是不同视图：目录清单必须保留扫描到的已交付和过程文件，不得减去 `session_files` 或 `task_files`；只有概览内的交付物与当前过程产物互斥。首次目录请求失败必须显示错误，不能当作空目录。
- 工作区目录按资源管理器语义展示：不按文件名、扩展名、隐藏状态、临时状态或依赖/构建目录过滤；文件夹（包括空文件夹）和链接本身也是目录条目。链接只展示而不递归跟随，避免越过活动工作区。条目达到性能上限时必须明确提示截断，不能伪装成完整目录。
- 同一文件以规范化路径去重；明确交付后从过程产物中移出，不因实时事件与扫描使用不同路径格式而重复展示。

## 13. 生图输出尺寸

- 图片设置内置常用分辨率和画面比例，用户选择默认值；Agent 可通过生图工具的可选参数覆盖本次输出，未指定时使用用户默认值，不修改已保存设置。
- 常用分辨率是便捷预设，不代表所有供应商都支持；生图不依赖尺寸发现、缓存或手动维护能力列表。
- 明确像素尺寸优先于默认比例；本次同时指定像素尺寸和比例时必须一致。仅指定比例且与默认像素画布冲突时，以本次比例为准，由供应商决定尺寸。
- 供应商拒绝尺寸时保留可定位的错误和明确返回的替代选项，Agent 可在符合用户需求时调整本次调用。鉴权、余额、限流与服务故障不能伪装为尺寸错误；扩展请求参数不能覆盖本次已选择的尺寸。
- 生图产物记录真实图片宽高及请求尺寸，但不进行生成后的尺寸达标校验，也不产生尺寸不符告警。服务成功返回图片即直接使用，不因尺寸差异自动重生、裁切或放大。提交结果不确定时不自动重新提交；已有任务 ID 继续查询原任务，部分成功保留已生成图片。

## 14. 生图提示词能力

- `generate_image` 在 turn 入口已预加载时，system 自动加载 `image-generation` Skill；由 `load_capability` 在轮中启用时，加载工具的结果必须先注入同一份完整 Skill，再允许后续图片调用。普通对话、文档专用 Agent 和具备该工具的伙伴 Agent 使用同一套提示词方法。
- `awesome-gpt-image-2` 的原始 Skill、风格索引、完整模板章节、22 个模板指定案例和 541 条结构化案例提示词随内置 Skill 保存，并保留来源、许可证和声明。运行时按图片类型和案例查询逐步读取，不能用摘要目录替代完整模板正文。
- 提交生图前，以实际发送的提示词验收主体与任务、构图与版式、风格与材质、文字、输出形式和针对性约束；读取记录、案例编号和计划文本不能代替最终提示词中的具体设计决定。
- 提示词完整且内部一致即通过提示词能力验收。图片模型的渲染效果不反向判定 Skill 失败；用户提出的新修改继续作为新的图片编辑请求处理。

## 15. 乐谱与吉他六线谱

- 五线谱与六线谱使用独立文件和渲染链路：`.abc` 只进入 abcjs 五线谱预览，`.atex` 只进入 alphaTab 六线谱预览；不得用 ABC 注释触发六线谱，也不得从五线谱 SVG 中隐藏五线谱来模拟独立 TAB。
- 六线谱文件直接记录弦号、品位和时值，预览只显示六根弦，并保留拍号、小节号、和弦名、节奏杆与多行响应式排版。
- `music_score` 只校验 ABC；`guitar_tab` 只校验 AlphaTex。音乐人正式交付对应文件前必须通过同格式校验，不能用 Markdown 字符画或指法说明替代可预览谱面。
- guitar-tab Skill 的例谱必须同时通过交付校验和真实 alphaTab 解析；音符技法与拍属性的位置、时值和含义必须一致，不能把未知属性当作无害文本放行。格式校验不代表手型可演奏或音乐质量通过。
- 吉他指弹默认包含旋律、低音与必要和声；弹唱按唱段伴奏和器乐旋律段分别编配。共享节拍网格通过同弦同品 `t` 接续延音，不能把重复拨弦当作持续音；`ac` 表示音符重音，`dy` 表示拍力度。完整例谱必须覆盖旋律持续时其它弦继续起音及器乐段到唱段的衔接。

## 16. 软件卸载与残留清理

- 已安装桌面软件的卸载方式以当前注册表中的卸载信息为准；前端只传稳定条目标识，不能传入或覆盖可执行命令。优先使用静默卸载命令，失败后尝试普通卸载命令，再使用软件目录提供的备用方式。
- 残留候选只由后端根据已卸载软件的可信安装信息生成。删除必须使用短期、一次性的候选标识并再次确认；执行前重新解析路径，拒绝已变化的路径、链接和受保护根目录，前端提交的任意路径不得获得删除权限。
- 残留扫描覆盖固定层级的应用数据、用户隐藏配置、快捷方式、注册表、服务、计划任务和驱动；只默认选择高置信度专属文件。用户资料、共享资源、服务、计划任务和驱动只检测，不进入普通批量删除。

## 17. Agent 工具权限

- 工具和技能是否开启由用户在已有前端设置中主动控制；执行过程中不追加逐技能脚本审批，技能更新不撤销可运行状态。环境准备仅处理依赖，不承载批准流程。

- Agent 设置的“工具”页是工具授权的唯一入口；功能设置、运行时安装状态和 MCP 连接状态只决定能力是否可运行，不能绕过 Agent 授权。
- 工具目录由“所有专家可配置的固定通用工具 + 当前 Agent 专属工具 + 仅 Mona 可用的协调工具”组成。Mona 不因工具属于 `core` 作用域而获得专家专属工具；专家包重复声明通用工具也不能改变平台通用集合。
- 学术检索、研究记录、科学计算、结构化数据分析和图表属于学者；乐谱与吉他六线谱校验属于音乐人；股票研究和流程提交工具属于对应股票专家或内部子 Agent。专属工具必须在后端注册阶段校验 Agent 身份，不能只靠前端隐藏或包清单约定。
- 工具实际可用必须同时满足 Agent 已授权、依赖和连接可用、当前上下文允许以及订阅门控通过。界面应在同一工具项展示不可用原因，不能让用户维护第二套权限开关。
- 浏览器自动操作对 Mona 默认授权；电脑操作自动化对每个 Agent 独立显式授权，首次任一 Agent 授权时按需下载共享驱动，撤销某个 Agent 的授权不删除已安装驱动。
- 动态 MCP 工具必须进入 Mona 的实时工具目录，并以具体工具名持久化授权；专家 Agent 仍受各自包清单和独立用户授权限制，不能继承 Mona 的动态工具权限。
- 产品升级新增的显式授权工具不能因 `granted_tools` 为空而自动开放；旧自动化总开关只用于一次性迁移，迁移后恢复中性值，不再作为运行时权限事实源。
- 编码与加密、模型供应商配置属于“其他”并默认关闭；升级读取旧权限快照时不能把它们此前的默认开启状态当成用户主动授权，用户可在工具页重新开启。
- 未保存过工具权限的用户按当前工具目录应用默认授权；保存过权限的用户保留自己的选择并可在工具页重新配置。历史 `granted_tools` 中已移除的名称不得重新生成工具目录，用户再次保存时只保留当前可配置工具。
- `canvas`、任务状态和 `my` 等运行时上下文工具由系统管理，不显示为用户权限开关，也不能被旧权限清单意外关闭。
- `my` 保留模型与配置修改能力；Notes 与 Agent Knowledge 搜索/读取保持初始可见，支持主动资料查询。专项能力由模型通过 `load_capability` 按自然语言加载，活动 Office/数据库/终端/浏览器上下文和媒体附件可预加载；请求级状态在并发会话间隔离，工具加载不得绕过身份、用户授权、订阅、依赖或后端运行状态。
- 必需能力的授权不等于 Schema 常驻。开发/命令、HTTP、Skill 配套工具可经能力加载提供；`skill_read` 成功后自动启用参考资料/脚本/素材工具。文档专用 Agent 预加载开发与 Skill 配套能力，内部无加载器的工具视图保持完整。保留历史中的工具调用可恢复已发现能力，但不能扩大当前权限或触发执行。
- 文件与命令、Agent 私有记忆读取和技能基础读取/执行工具属于所有 Agent 的必需运行能力，不显示权限开关；用户保存空权限或旧权限清单也不能关闭这些能力。`memory_edit` 和 `skill_create` 仍由 Dream 或明确具备该职责的专家运行，不因此进入 Mona 普通会话。终端维护、外部连接及其它业务工具不因此自动获得授权。
- 网页搜索、网页读取和结构化 HTTP 请求属于所有 Agent 的必需网页访问能力，默认且始终开启，不显示权限开关；浏览器自动化仍是独立的可配置能力。
- 委派、创建子任务、协作流程和即时协作属于 Mona 必需的协调能力，不显示权限开关且不能被旧权限清单关闭；专家 Agent 不能继承这些能力。
- `terminal_task`、`terminal_exec`、`terminal_output`、`terminal_upload` 属于 Mona 的终端/SSH 模块，不进入专家 Agent 的可配置或运行工具集。专家保留工作区文件与受控 `exec` 能力，它不绑定用户当前 SSH 或桌面终端会话。
- 工具分类、是否系统管理、是否显式授权和 Agent 所有权由后端目录返回；前端只保留旧后端兼容回退和本地化文案，不能自行扩大工具范围。
- 主 Agent 每轮调用模型前必须确认已授权的电脑操作运行时和 MCP 连接可用；驱动内部会话标签由 Mona 按连接和对话管理，不暴露给模型选择，避免复用已结束会话。
- 电脑操作统一使用前台模式，由执行层控制投递方式；同一时刻只允许一个任务持有桌面。点击、输入等交互绑定最近一次截图的窗口或桌面，元素标识与坐标互斥，坐标不得越界；操作后必须重新观察才能继续。新启动的应用先观察其窗口，再聚焦操作。驱动拒绝和执行结果元数据必须保留，派发成功不能作为界面效果已验证的证据。
- 前台模式同时保留控件接口和截图坐标路径：窗口交互先显式聚焦精确目标，聚焦失败或期间被停止则不继续派发；控件操作保留元素标识及语义参数，不能统一降级为坐标点击。画布、游戏棋盘或控件树未覆盖的区域使用截图坐标，输入投递固定为前台。
- 停止与任务结束必须结束本轮已使用的驱动会话并清理指针；被停止的轮内不得通过连接恢复重新派发操作。停止不能撤销操作系统已接收的输入。前端复用停止入口提供接管提示，运行状态不得从旧任务工具记录推断。
