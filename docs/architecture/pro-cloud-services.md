# Mona Pro：设备与个人云工作空间

状态：用户已批准，分阶段实施；没有发布到生产。
日期：2026-10-12

## 产品边界

- 本地基础 Agent、Office 实时协作、资料问答、开发和运维不以 Pro 订阅为使用门槛。工具授权、数据范围、操作确认、模型认证和模型余额检查仍然有效，不能一并放开。
- Token 由用户自有模型来源或预充值承担；Pro 不赠送模型用量。
- 免费账号最多 1 台登录设备，已生效的 Pro 账号最多 3 台；多设备登录是独立权益，不以是否开启同步为条件。普通试用状态不自动增加设备名额，也不赠送云端容量。
- “设备”指同账号中仍有效的桌面设备登录，不是进程、窗口、安装次数或历史设备数量。关闭应用不自动退出；明确退出/移除设备释放名额。网页登录后台不冒充桌面设备，不能使用桌面设备专属云接口。
- 达到上限后，验证账号凭据并展示本人的设备列表；只有用户明确选择退出的设备才允许替换，不静默挤掉其他设备。免费用户可以换机，不设置累计一生一次的换机限制。
- Pro 到期后，云服务按权益降级；设备访问保留最早登记且仍有效的 1 台，其余设备可由用户在再次登录时明确替换。离线设备无法即时被远程注销，联网请求必须重新校验；不删除任何设备本地资料，也不强停正在运行的本地任务。

## 服务与存储

- 复用 `mona-auth/` 的账号、支付和 MariaDB。2核2GB VPS 只负责认证、设备会话、同步目录/版本、配额及对象授权，不运行用户 Agent、模型、文档解析或文件传输代理。
- 用户电脑对选定数据压缩、加密并直接上传七牛私有空间；下载也直连七牛。安装包/专家包/运行时分发与用户私有数据分开，不能拿现有公开下载域名承载私人资料。
- 首期范围（2026-10-12最终收敛）：**仅 Work 模式的普通会话**及其已关联附件/工作文件，另保留笔记及附件、日程/待办、白名单内非敏感配置。会话优先于配置。开发会话、原生 CLI 状态、开发项目目录明确不在首期；不得扫描/打包它们，也不新增开发同步入口。不同账号、Agent 知识与 Notes 的来源隔离保持不变。
- Work 会话保留完整持久对话、必要工具记录、摘要与计划；不从摘要反推原文。内容按完整记录分段，已有分段按密文内容标识复用，不在每次同步重传所有历史。
- Work 文件同步复用上传附件、明确交付和成功文件操作的真实归属记录。用户选定的 Mona 托管工作区支持同步业务文件；未授权目录、凭据和未知归属文件不因会话引用过一个路径而自动上传。文件标识与版本独立保存，会话只关联它，避免跨会话重复占用。
- 新设备先拉取会话及文件目录，文件按需下载，选定范围可保留离线副本。下载后的会话只作为历史，不自动恢复旧 pending 命令/审批/任务运行态；继续执行必须由用户新请求发起并核对当前环境。并发离线编辑保留冲突分支，不覆盖历史或拼成同一轮执行。
- API Key、SSH 密码/私钥、Cookie、CLI 登录信息、运行中的任务、整个代码目录、依赖目录和模型缓存默认不上传。不能通过复制 SQLite、JSONL 或整个配置目录实现同步。
- 同步、备份和历史恢复是不同能力：同步支持多端增量提交/冲突，备份保留不可变快照，恢复建立新的可检查版本而不是覆盖当前未保存修改。
- 内容在客户端加密；开启时建立恢复密钥流程。服务端不持有可直接解密内容的密钥；忘记密码不等于能找回丢失的恢复密钥。
- Pro 空间改为每账号共用 **10GB（10,000,000,000字节）**，不是每台设备10GB。密文、保留的历史版本及回收站计入实际占用，重复引用同一云对象只计一份，上传前事务预留。每月10GB下载、30天历史继续作为容量测算基线。值由服务端配置，不写死在前端；129元/年仅为前述测算方案，不能自动覆盖现有生产价格。
- 下载凭证的重复使用、Range/断点续传、七牛真实流量账单与申请量分别核算，不能把“签发一次URL”当作真实下载一次或严格流量上限。
- 订阅到期不删除本地数据；云端停止新增写入，提供明确的保留/下载期。删除与回收需独立策略和恢复验证，首期不部署自动清理用户数据的任务。

## 日程与待办同步

- 在云同步范围中独立确认“同步现有及后续的日程与待办”，默认不因启用 Work 会话同步而上传。关闭该项不删除本地内容，重新开启后从已有云历史追平。
- Gateway 复用同一账户、密钥、配额、版本日志和后台同步循环；业务数据通过带本地服务令牌的 Services 接口读取和条件写入，Gateway 不直接打开日程存储文件。
- 每条个人日程或待办对应独立云资源，更新、完成和已确认资源的删除按版本同步。只有个人日程参与；AI 自动任务、Cron 绑定、通知队列和运行结果不迁移。已有本地提醒观察状态保留，新设备仅安排未来个人提醒，不补跑错过的自动任务。
- 待办同步业务状态、时间、优先级和来源摘要，不复制邮箱凭据、邮件定位、私人本机路径或关联日程的本地标识；本机已有来源链接不被远端空值清除。
- 同步先核对本地内容指纹再写入，损坏的存储不能被当作空列表。两端同时编辑保留本地原条目和有明确名称的冲突副本；日程冲突副本默认关闭提醒，待办冲突副本不抢占重点排序。
- 删除与并发编辑冲突时优先保留修改，不静默丢弃内容。响应丢失按同一次提交身份核对，未确认创建成功的记录不向云端发送无效删除。
- 日程和待办复用 10GB 配额，正文只在客户端加密对象内保存。同步并不提供新的云端 Agent 或后台模型调用服务。

## 笔记及关联附件同步

- 云同步范围单独确认“同步本机笔记仓库及关联附件”，默认关闭。只处理当前 Notes 仓库的笔记和正文明确关联的 `assets` 文件，不复制 Agent Knowledge、整个工作区、外部链接目标或本地凭据。
- Tauri Notes 是唯一笔记文件所有者；Gateway 通过受账号绑定保护的原生接口读取、分片传输和条件写入，不直接扫描或修改笔记目录。同步开始时绑定当前仓库身份，切换仓库后必须重新确认，旧保存请求和延迟回调不得写入新仓库。
- 每篇笔记独立同步标题、分类、完整正文、类型、别名、收藏及时间；本机聊天绑定、已应用消息标识和知识可见性不跨端授权。相同附件按内容标识复用；分片校验并确认全部附件可用后才发布笔记，不先展示缺图的成功状态。
- 保持现有笔记能力的大小边界：单篇正文最多2MiB、单个关联附件最多10MiB，每篇最多128个附件。超限或引用缺失明确报告并保留原文，不静默裁剪。现有笔记格式的一层分类、普通笔记、思维导图和流程图使用同一正文存储；不以同步为由新建资料库。
- 原生文件写入和本地编辑共享锁，在保存与删除前核对仓库身份和文件版本。批量删除先检查所有选中笔记，任一记录已被其他设备修改则不删除任何一项；不得自动读取新版并代替用户重新确认。前端串行处理自己的保存和删除请求，远端更新到达时保留当前输入；并发修改生成有明确名称的冲突副本，删除与修改冲突优先保留内容。普通保存返回真实文件版本，不用界面状态猜测保存成功。
- 恢复同步或新增同步类别时补读先前未选择的云历史；已确认版本按身份复用，不重新执行 Agent、旧通知或其他任务。Markdown 正文换行和末尾空白原样保留，避免跨端反复产生伪变化。
- 笔记与附件复用个人10GB空间、客户端加密、对象配额与版本日志。关闭同步不删除本地或云数据；明确删除已同步笔记会产生版本化删除记录，但历史保留与回收站仍按独立策略实施。

## 使用偏好同步

- 云同步范围单独确认界面使用偏好，默认关闭。首期白名单仅包含侧栏模块布局、启动默认页面、消息发送按键、快捷问答显示模式，读取和保存均复用 Tauri 原生 `settings.json` 所有者。
- 不复制完整配置文件，不上传模型供应商、API Key、CLI登录、工作区/笔记仓库路径、端口、操作权限、全局快捷键或同步授权本身。主题和语言等其他独立存储的设置不在本阶段白名单，不能泛称全部配置已经同步。
- 首次加入已有云空间时恢复其已保存偏好；后续以最近确认版本逐字段合并，不同字段的两端改动可以同时保留。同一字段发生并发修改时保留本机尚未上传的修改并提交新版本，旧云版本仍受历史策略保护。
- 原生保存共用文件锁与原子写入；远端更新及正常设置保存都核对当前偏好指纹。旧设置窗口不能静默把新同步值改回旧值，冲突时原数据保持不变并要求重新打开设置再确认。
- 同步成功通知只用于刷新侧栏和发送按键，不携带配置正文、凭据或跳转命令；不会切走当前页面或启动任务。默认页面在下一次启动时生效，快捷问答模式在下一次打开时读取。
- 偏好与其他内容共用账号、加密、10GB配额和版本通道。切换账号不自动沿用旧同步授权；关闭该类别不重置本机设置，重新开启会补读先前未选择的云历史。

## 上传残留回收

- 设置的“清理上传残留”只回收未被任何资源或历史版本引用的对象；不是删除会话、精简历史或清空云空间。用户先查看本批数量和预计释放量，再明确确认，不自动执行后续批次。
- 普通候选对象至少创建24小时且最后一次上传/复用凭证已过期5分钟。复用已有对象和上传确认都会延长保护期，避免“已选为残留的文件又被新会话使用”时误删。
- 参考七牛官方[上传策略](https://developer-doc.qiniu.com/products/kodo/development-guidelines/security/1-put-policy)（2026-10-13核对）：`deadline` 在上传完成、空间生成文件时校验，并非只在上传开始时校验。回收仍须等最后授权过期、重新核对引用、删除精确存储键并确认不存在，不凭一次查询失败提前释放配额。
- 服务端预览签名绑定账号、设备、云空间及精确存储代次；客户端只向界面暴露本地确认编号。十分钟后重新检查，不能替换参数扩大范围。账户退出或切换使原确认失效。
- 每批最多10个对象，逐项持久化回收状态后才请求七牛删除；网络调用不占账号事务锁。回收期间禁止其他任务重新上传、确认或提交引用该对象。
- 只有七牛确认对象不存在且本地账目仍匹配原代次时才减少占用或上传预留；失败、超时和未知结果保留计量，可重试同一确认。新上传的同内容对象使用新的存储代次，旧确认不得删除它。
- 有效设备即使Pro到期仍可清理自己的残留，暂停自动同步也不阻止此明确操作。所有现存历史继续保护其引用；历史保留期、回收站、账单流量核算仍是独立待交付能力，不以残留回收冒充已完成。

## 认证与设备

- 新桌面登录使用设备绑定的服务端会话；账户JWT和短期模型JWT同时携带该会话身份及轮换版本，服务器逐次校验所属账号、有效期、撤销状态和设备名额。
- 登录名额检查、明确替换、会话建立在同一账户级数据库事务内完成，避免并发第2/第4台同时越过检查。相同请求重试只恢复同一会话，不重复退出其他设备。
- 设备指纹只是本地设备标识，不声称提供硬件防克隆或抵御恶意修改客户端。客户端只在系统凭据存储保存令牌，React 不接收账户JWT或七牛密钥。
- 设备管理按当前账号列举/撤销；无权限、旧会话、已轮换或已撤销令牌不能获得访问。修改/重置密码撤销旧桌面会话。
- 历史账户登录与离线软件许可证不是新云服务的授权来源。迁移前核对旧客户端和既有设备；仅添加表和兼容字段，不在迁移脚本中登录、退出或删除生产用户数据。
- 新客户端需要配套 Auth API 后才切换设备登录。服务器尚未升级时明确提示升级，不静默退回无限制登录。上线要先迁移和部署服务端，再发布客户端。

## 实施阶段

本地阶段提交只包含桌面应用及已跟踪的相应测试、架构文档。`mona-auth/` 依照现有仓库规则继续排除，服务端部署与数据库迁移必须单独验收；不能把桌面提交误称为 Auth 已发布。


1. 账号设备权益：服务端1/3台、绑定JWT/模型令牌、设备列表与明确替换、桌面登录和管理UI、离线/撤销边界测试。
2. 基础能力开放：移除本地AI的订阅门控与误导文案，保留授权/安全/计费校验；同步更新 Pro 介绍，不宣称未上线云能力可用。
3. 云备份：独立私有存储、客户端加密、限额/直传授权/确认、版本及恢复；先使用本地或协议fixture验证，不读取生产密钥。
4. 增量同步：优先 Work 普通会话及其关联附件/工作文件，再接选定笔记/附件、待办日程和配置白名单；离线队列、版本冲突、删除标记、多端隔离。开发会话和项目数据不在本期。
5. 联合验收与受控上线：真实私有七牛、容量与下载计量、双端/三端、降级恢复、生产迁移演练。线上部署、桶创建/权限调整、价格变更需明确目标和授权。

完整性以各阶段当前源码及测试为准；不得把对象上传成功称为同步完成，或把设备会话测试通过称为全部云服务已上线。
