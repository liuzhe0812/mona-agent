# Mona 可下载运行时组件管理架构

- 状态：Accepted
- 适用范围：桌面端按需下载的模型、解释器、浏览器、原生工具和专家运行环境
- 最后更新：2026-09-09

## 1. 决策

Mona 的可下载运行时必须由一套统一的组件仓库和下载器管理。新增功能不得自行创建资源根目录、下载状态文件、版本指针或重复实现下载逻辑。

统一复用：

- `mona.runtime.manager.RuntimeComponentStore`：安装、版本、激活、回滚与清理。
- `mona.runtime.download.VerifiedDownloader`：多源下载、断点续传、大小与 SHA-256 校验。
- `mona.runtime.catalog.RuntimeInstaller`：解析组件目录、依赖、平台与架构。

## 2. 数据边界

可重建、与当前机器绑定且体积可能较大的运行时，使用操作系统本地应用数据目录。Windows 的规范位置为：

```text
%LOCALAPPDATA%\Mona\runtimes
```

目录结构：

```text
runtimes/
  components/<component-id>/
    versions/<version>/
      runtime-manifest.json
      receipt.json
      ...component files
    current.json
  downloads/<component-id>/<version>.zip
  jobs/runtime-installs.json
  environments/
```

以下内容不进入运行时仓库：

- 用户笔记和附件：保存在用户选择的笔记仓库。
- 用户工作区和交付物：保存在用户选择的工作区。
- Agent 记忆、个人配置和不可重建数据：保存在 Mona 用户数据目录。
- 单次任务临时文件：保存在系统临时目录，任务结束后清理。

## 3. 组件契约

每个组件必须具有不可变清单，至少包含：

```json
{
  "schemaVersion": 1,
  "id": "asr-sensevoice",
  "version": "0.2.6+q8",
  "platform": "windows",
  "arch": "x64",
  "size": 0,
  "sha256": "...",
  "sources": ["https://..."],
  "entrypoints": {
    "transcribe": "bin/llama-funasr-sensevoice.exe"
  },
  "dependencies": ["ffmpeg@6.1.1"]
}
```

约束：

- `id + version + platform + arch` 唯一确定一份不可变内容。
- 下载地址可以有多个，但所有来源必须返回相同字节。
- 清单固定文件大小和 SHA-256；校验失败不得安装或激活。
- 入口文件必须位于组件目录内，不允许路径逃逸。
- 模型、词表、许可证和必要原生程序属于同一组件或显式依赖。

## 4. 下载与安装

标准流程：

1. 解析当前平台、架构和组件依赖。
2. 复用已经通过清单和 receipt 校验的活动版本。
3. 下载到 `downloads` 下的 `.part` 文件，支持 HTTP Range 续传。
4. 按顺序尝试国内源、Mona CDN和官方上游。
5. 校验声明大小和 SHA-256。
6. 解压到同文件系统的 staging 目录。
7. 校验运行时清单、入口和依赖。
8. 原子移动到版本目录并更新 `current.json`。
9. 安装失败时保留可续传分片，不改变当前活动版本。

下载器必须遵循系统代理设置。重定向目标、下载大小和解压路径必须经过安全校验。

## 5. 运行生命周期

- 安装与加载是两个独立概念。组件可以保留磁盘缓存，但只有功能实际调用时才加载进程或模型。
- 大模型和原生工具优先使用短生命周期子进程；任务完成、取消或超时后必须结束并回收。
- 长驻服务必须由统一 supervisor 管理，并声明空闲卸载策略。
- 临时音频、视频、帧图和中间文件必须使用任务级临时目录并在结束时清理。
- 禁止用删除已安装模型的方式释放内存；内存释放和磁盘缓存清理由不同策略负责。

## 6. 版本、修复与清理

- 活动版本由 `current.json` 指向，不通过覆盖目录完成升级。
- 默认保留活动版本和最近一个可回滚版本。
- “修复”重新校验当前版本，损坏时重新下载相同不可变版本。
- “卸载”删除活动指针和可重建文件，不删除用户数据。
- 下载缓存、旧版本和失败任务必须可以在统一设置页查看与清理。
- 应展示组件占用空间、版本、状态、来源和最后使用时间。
- 已完成的根目录迁移以原子写入的状态文件为启动快路径；正常启动不得为展示旧目录容量而递归遍历运行时文件。容量重算只在迁移、显式刷新或清理操作中执行，并复用单次统计结果。

## 7. 全局按需下载管理

设置页提供统一的“功能资源”区域，作为所有受管运行时的全局查看和操作入口。页面使用视频与语音处理、文档转换、AI 编程环境、电脑操作等用户可理解的功能名称，不直接暴露组件 ID、依赖关系和内部目录。

- “需要时自动下载”默认开启，并通过 `mona/config/schema.py` 中的显式配置持久化。
- 功能首次需要尚未安装的资源时，创建全局下载任务；同一资源已有任务时复用该任务，不重复下载。
- 自动下载成功后继续原业务操作；失败时保留可续传文件并提供重试，不静默切换到未经管理的运行时。
- 关闭自动下载后，首次使用时展示资源用途和下载大小，由用户确认后开始下载。
- 用户可以在设置页提前下载资源，并查看当前下载、已安装、可更新、需要修复和失败状态。
- 设置页提供下载、取消、继续、修复和清理操作；清理只影响可重建资源、旧版本和失败下载，不影响用户数据。
- 下载任务离开设置页后继续运行；应用重启后保留任务结果，并允许从已有分片继续下载。

所有运行时安装任务由唯一的全局任务管理器串行更新安装状态和活动版本。业务模块只请求所需功能资源，不自行维护下载任务。

Skill 的环境准备使用可恢复任务编排共享组件安装、Python/Node 依赖准备和最终检查。任务按 Agent、有效 Skill 和执行内容指纹绑定，以保证准备的是当前依赖。已启用技能直接运行，不设置逐技能脚本审批，也不因内容更新要求重新批准；运行时按需准备依赖。技能准备任务只记录业务阶段并复用全局运行时下载任务，不创建第二套下载器或资源目录。离开配置页后任务继续运行；应用重启时未完成任务明确标记为中断并允许重试。

Skill 可以声明不影响基础能力的可选脚本类型。未受管的可选运行时只显示能力限制，不得让已经满足依赖的基础能力持续处于“环境待准备”。

## 8. URL 转笔记 ASR

URL 转笔记是首个按本架构治理的模型组件：

- 组件：SenseVoiceSmall Q8 + FSMN-VAD + FunASR Windows x64 CPU runtime。
- 仅在视频没有可用字幕时安装并调用。
- 权重优先从固定 revision 的 ModelScope 国内源下载。
- 转写使用短生命周期进程并输出带 VAD 时间段的 SRT。
- 转写完成后释放进程与模型内存，保留已校验的磁盘组件。
- 重点帧属于任务输出，不属于运行时组件；保存到笔记仓库的 `assets`，临时副本随任务清理。

迁移现状、顺序和完成门槛见 `docs/plans/runtime-component-migration-plan.md`。

## 9. 内置 Office 编辑组件

Docs、Sheets、Slides 编辑器属于桌面应用的常用内置能力，不属于可下载运行时：

- 三个前端入口、共享依赖、空白 Office 模板和对应平台的 XLSX sidecar 随安装包交付。
- 桌面前端入口由 Tauri 嵌入；Office 模板、许可证、sidecar 及清单从 `src-tauri/resources/office-editor/` 作为构建输入，统一打入 Gateway 的 `_internal/desktop-resources/office-editor/`。安装包和热更新包复用同一份 Gateway 资源树，不再另外发布独立的 Office 资源副本。
- 发布版 Services 从安装目录的 `resources/mona-gateway/_internal/desktop-resources/` 读取 Office 资源；开发环境继续读取 `src-tauri/resources/`。旧客户端更新器会复制完整 Gateway 目录，因此无须先更新旧客户端的更新逻辑，也不能回退读取旧安装遗留的 `resources/office-editor/`。
- sidecar 的清单大小和 SHA 必须对应最终签名后的文件。签名前验证原始清单，签名成功后刷新摘要，再构建安装包及热更新包。
- Office 资源使用固定版本、平台、架构、大小和 SHA-256 清单；Services 只定位并校验资源，不创建 Office 专用下载器。
- Windows 与 macOS 发布构建必须先生成当前平台 sidecar 清单；平台或架构不匹配时明确失败，不能运行另一平台的二进制。
- Office 编辑资源只使用系统字体，不打包字体、Electron、Node runtime、PDF/OCR 或 GenOffice AI。
- sidecar 由 Services 按需启动，并在会话关闭、超时或应用退出时回收。

## 10. 工程准入规则

内置 PDF 的读取、表格提取、页面渲染、新建、合并、提取页面、旋转和表单处理复用 Gateway 自带的 Python 与 PDF 库，通过 `pdf` 工具的固定操作执行。平台 `pdf` Skill 只提供使用指南，不携带脚本运行环境或独立依赖清单，也不触发运行时下载。任意用户 Python 脚本仍使用统一的共享运行时，不能借 PDF 操作执行任意代码。

新增或修改可下载组件时必须：

- 在组件目录中登记版本、平台、架构、来源、大小、SHA、入口和许可证。
- 使用统一下载器和组件仓库。
- 提供冷安装、断点续传、校验失败、缓存命中、升级回滚和卸载测试。
- 验证任务正常结束、取消和超时后没有残留进程或锁定文件。
- 使用国内网络可访问的首选源，并保留相同字节的可信备用源。
- 在设置页可观察状态，但不得要求用户理解内部运行时细节才能完成业务任务。

禁止：

- 在业务模块中直接使用 `requests`、`aiohttp`、`curl` 或包管理器下载运行时。
- 使用 `latest` 或未固定 revision 的生产下载地址。
- 只校验扩展名、HTTP 状态或压缩包可打开，而不校验大小与 SHA。
- 把可重建运行时写入用户笔记、工作区、程序安装目录或仓库源码目录。
- 创建新的 `%LOCALAPPDATA%\Mona\resources` 子目录。
