> 来源：基于 [openhuman-analysis.md](file:///d:/liuzhe/Desktop/code/Mona/docs/openhuman-analysis.md) P0 清单第 1–4 项

## 背景与目标

四项改动都属"小改、收益明确、不引入新抽象层"，预计独立可上线：

| # | 改动 | 核心收益 | 风险 |
|---|------|---------|------|
| 1 | 工具结果压缩层 | 单次工具结果瘦身，降 token 成本与延迟 | 压缩丢信息需可恢复 |
| 2 | 重复工具失败熔断 | 防止 agent 撞墙烧 token | 误判导致工具被禁用 |
| 3 | AI 生成 release notes | 发版说明自动化 | LLM 生成质量不稳定 |
| 4 | KV-cache 契约显式化 | provider 缓存命中降本 | 需审计现有构建路径 |

## 1. 工具结果压缩层（Mona 版 TokenJuice 精简版）

### 1.1 现状

- [runner.py:1080](file:///d:/liuzhe/Desktop/code/Mona/mona/agent/runner.py#L1080) `_normalize_tool_result`：只做 `maybe_persist_tool_result` + 超长截断 `truncate_text`
- [runner.py:1174](file:///d:/liuzhe/Desktop/code/Mona/mona/agent/runner.py#L1174) `_microcompact`：跨多轮把旧工具结果替换为一行省略（按 tool name 白名单）
- [loop.py:1615](file:///d:/liuzhe/Desktop/code/Mona/mona/agent/loop.py#L1615) `_sanitize_persisted_blocks`：落盘前按 `max_tool_result_chars` 截断
- 缺失：**单次工具结果按内容类型智能瘦身**（JSON 转表、日志留头尾、HTML 剥离标签），且截断后原文无法按需取回

### 1.2 设计

新增纯函数模块 `mona/agent/tools/result_compress.py`，提供：

```python
def compress_tool_result(text: str, *, tool_name: str | None = None) -> str
```

- 输入字符串，输出压缩后字符串；**永不放大**（输出 ≥ 输入则原样返回）
- 内容检测顺序：显式 hint（tool_name 先验）→ 结构启发式
- 支持的 kind：
  - `json`：对象数组渲染为 Markdown 表格；超 40 行留 head(5)+tail(5)+错误行
  - `log`：strip-ANSI + 连续重复行去重（保留首尾计数）+ head/tail 各 30 行
  - `html`：线性剥离标签为可读文本（不依赖 html2md，避免内存炸弹）
  - `diff`：保变更行与 hunk 头，长未变区折叠为锚点
  - `text`（兜底）：超长留 head + tail + 中间省略计数
- CJK/emoji 按 grapheme 安全处理（用 `regex` 库的 `\X` 或简单按字符遍历，不切断多字节字符）
- 触发阈值：仅对 > 2KB 的内容启用，小结果直通

**CCR（可恢复原文）**：复用现有 `maybe_persist_tool_result`——它已经把大结果落盘到 workspace。压缩后返回内容追加一行：

```
[原文已保存：可通过 read_file 读取 <path> 取回完整内容]
```

不引入新工具、不引入新缓存层。压缩在 `_normalize_tool_result` 内调用，位于 persist 之后、truncate 之前。

### 1.3 落点

| 文件 | 改动 |
|------|------|
| `mona/agent/tools/result_compress.py` | 新增：纯函数压缩器 |
| `mona/agent/runner.py` | `_normalize_tool_result` 调用 `compress_tool_result` |
| `mona/agent/tools/__init__.py` | 导出（如需） |

不动 loop.py、不碰 hook.py、不改 schema。

### 1.4 验收

- 单元测试：各 kind 的输入→输出样例，含 CJK 安全、永不放大、小结果直通
- 手动验证：一封大邮件 HTML 正文经工具返回后，上下文占用明显下降；原文路径可读回
- 回归：现有 IMAP/web/shell 工具行为不退化

## 2. 重复工具失败熔断

### 2.1 现状

- [runner.py:334](file:///d:/liuzhe/Desktop/code/Mona/mona/agent/runner.py#L334) `_execute_tools` 返回 `(results, new_events, fatal_error)`；`fatal_error` 仅在工具抛异常时触发单次中止
- [runner.py:47](file:///d:/liuzhe/Desktop/code/Mona/mona/agent/runner.py#L47) 已有 `repeated_external_lookup_error`、`repeated_workspace_violation_error` 针对特定错误类型的计数
- 缺失：**同一工具连续多次失败（含返回错误内容而非异常）时，向模型注入"该工具当前不可用"提示并短路后续调用**

### 2.2 设计

在 `AgentRunner.run` 的工具执行段（runner.py:333 附近）维护 per-turn 失败计数：

```python
tool_failure_counts: dict[str, int] = {}  # tool_name -> consecutive failures
```

判定失败的两种来源：
- 工具抛异常（已进 `fatal_error` 路径）
- 工具结果内容以 `Error:` / `错误:` 开头或包含已知失败标记（复用现有 `tool_events` 里的 error 事件）

阈值：默认 3 次（与 OpenHuman `RepeatedToolFailureMiddleware` 一致，可经 spec 配置）。达到阈值后：
- 在本轮后续 iteration 中，从 `messages` 里删除该工具的 tool spec（让模型看不到它），并在 system 侧追加一条 user 消息：

```
[系统提示] 工具 `<name>` 连续失败 N 次，当前不可用。请换用其他方式完成任务。
```

- 计数仅在本 turn 内有效，下一 turn 重置（避免一次失败永久禁用）

### 2.3 落点

| 文件 | 改动 |
|------|------|
| `mona/agent/runner.py` | `run` 内加计数与短路逻辑；`AgentRunSpec` 加 `max_tool_failures: int = 3` 字段 |
| `mona/agent/loop.py` | `from_config` 透传配置项（如配置存在） |

不改 hook.py（这是 loop 内部状态，不是横切关注点）；不引入新中间件层。

### 2.4 验收

- 单元测试：mock 一个总是抛异常的工具，验证第 3 次后该工具从 spec 移除 + 注入提示
- 回归：正常工具单次失败不触发熔断
- 手动验证：IMAP 认证错误场景下 agent 不再无限重试（呼应已记录的"IMAP IDLE 重试耗尽连接配额"教训）

## 3. AI 生成 release notes

### 3.1 现状

- [scripts/release_upload.py](file:///d:/liuzhe/Desktop/code/Mona/scripts/release_upload.py) 只做上传
- 发版说明目前手工整理
- 无 `scripts/release_notes*` 脚本

### 3.2 设计

新增 `scripts/generate_release_notes.py`：

- 输入：两个 git ref（默认 `HEAD~1` 与上一个版本 tag，或命令行传入）
- 流程：
  1. `git log --pretty=format:"%h %s" <from>..<to>` 取 commit 列表
  2. 按 conventional commit 前缀分组（feat/fix/refactor/docs/chore/...）
  3. 调 LLM 生成 Highlights + 友好描述（用现有 `LLMRuntime`，模型可配，默认走主模型）
  4. LLM 失败/超时（默认 60s）→ 回退纯分组列表（确定性）
- 输出：Markdown 文本，打印到 stdout 或 `--output` 指定文件
- CLI：`python -m scripts.generate_release_notes [--from REF] [--to REF] [--output FILE]`

不依赖 OpenAI key 硬编码，复用 mona 的 provider 配置；不强依赖 LLM（回退可用）。

### 3.3 落点

| 文件 | 改动 |
|------|------|
| `scripts/generate_release_notes.py` | 新增：独立脚本 |
| `scripts/release_upload.py` | 可选：发版流程中调用上述脚本生成 notes（不在本期） |

不改 mona 核心包；脚本是边缘工具，符合"扩展放边缘"。

### 3.4 验收

- 手动运行：对最近一次发版生成 notes，对比人工整理质量
- 回退测试：模拟 LLM 不可用时输出确定性列表
- 不影响现有发版流程（纯增量）

## 4. KV-cache 契约显式化

### 4.1 现状

- [context.py:37](file:///d:/liuzhe/Desktop/code/Mona/mona/agent/context.py#L37) `build_system_prompt`：每轮都重新拼接（identity + bootstrap + tool_contract + memory + skills + history + session_summary）
- [context.py:204](file:///d:/liuzhe/Desktop/code/Mona/mona/agent/context.py#L204) `build_messages`：每次都 `{"role": "system", "content": self.build_system_prompt(...)}`
- 问题：**system prompt 内容随记忆/skills/history 变化而变化，provider 侧 KV-cache 难以命中**；动态上下文（时间、channel、sender）已在 `_build_runtime_context` 里以 user 消息追加（这点已对）
- 缺失：契约未文档化；未利用 Anthropic `cache_control` 等显式缓存标记

### 4.2 设计

分两步：

**步骤 A（本期，低风险）**：审计 + 契约文档化
- 在 `.agent/design.md` 增加"KV-cache 契约"小节，明确：
  - system prompt 在单 turn 多 iteration 内不可变（已成立：`build_messages` 在 turn 入口调用一次）
  - 跨 turn 的 system prompt 变化来源：memory 更新、skills 列表变化、history 追加、session_summary 更新——这些是合理的语义变化，但应尽量降低频率
  - 动态上下文（时间/channel/sender/browser 状态）一律走 user 消息的 `_RUNTIME_CONTEXT_TAG` 块，绝不进 system prompt（已成立）
- 审计 `build_system_prompt` 各部分是否真的在 turn 内不变（确认 `memory.get_memory_context()`、`read_unprocessed_history` 不会被工具调用副作用触发更新）

**步骤 B（后续，需 provider 适配）**：显式 cache_control
- 在 provider 层为 Anthropic 等支持 prompt caching 的 provider 注入 `cache_control: {type: "ephemeral"}` 标记
- 标记位置：system prompt 末尾 + 长期不变的工具定义末尾
- 本期不做，仅在 design.md 记录为 follow-up

### 4.3 落点

| 文件 | 改动 |
|------|------|
| `.agent/design.md` | 新增 "KV-cache 契约" 小节 |
| `mona/agent/context.py` | 仅在审计发现违规时做最小修正（预期无需改） |

### 4.4 验收

- design.md 新增小节，明确契约与已知限制
- 审计报告：确认 system prompt 在 turn 内稳定；列出跨 turn 变化来源
- 如发现违规（如某工具调用副作用导致 memory 在 turn 内变化），单独修 bug，不捆绑本次 PR

## 执行顺序

1. **第 4 项（KV-cache 契约）**：纯文档 + 审计，最快、零代码风险，先做
2. **第 1 项（压缩层）**：收益最大，纯函数 + 单一接入点

4. **第 3 项（release notes）**：独立脚本，与核心无关，最后做
