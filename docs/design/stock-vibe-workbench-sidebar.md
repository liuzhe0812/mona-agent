# 投资工作台右栏：分析记录与定时跟进

- 日期：2026-10-19
- 范围：右栏信息组织和交互，保留一屏三栏布局；预测计算、研究执行和调度逻辑不变。
- 分类：Mona接入适配。复用Vibe原生Session、Attempt快照和Scheduled Research能力。

| 区域 | 调整 | 用户操作 |
| --- | --- | --- |
| 分析入口 | 保留四个明确分析任务，右上角提供“分析记录” | 按目标发起分析或查阅历史；资料在具体研究流程中提供 |
| 最近研究 | 保留最新报告摘要和全文入口，追问按钮放在完整报告正文后 | 先阅读报告，再进入该报告原会话继续交流 |

| 定时跟进 | 直接列出综合分析、财报与估值、走势分析、风险检查四项，各有执行时间、开关和设置 | 独立启停；未开启时先保存时间，再用开关启用；已开启时直接调整后续时间 |

## 原生能力与接入

Vibe的`SessionStore.list_sessions(limit)`和`list_attempts()`保存会话及每次执行。原有工作台最多投影100个会话且每个会话只带最后一次执行，通用会话API也没有offset分页，不能拿前100条在浏览器中分页冒充完整历史。

`0040-workbench-history.json`新增只读`/mona/workbench-history`：复用原生Store与`workbench_context`验证归属，在该股票全部Attempt上按标题、任务、状态筛选，再按发起时间和稳定ID分页。没有Attempt的会话明确显示“尚未开始”。列表不返回大段报告、提示词或原始错误；选中后沿用既有Attempt详情接口读取原始快照，不创建研究或调用模型。

Mona Services对同一查询做字段、重复参数、股票身份和响应结构校验，浏览器只请求当前页。返回列表保留筛选和页码；切换股票清除旧上下文；读取失败可重试。

定时跟进的开启、关闭继续使用原有创建、取消协议；修改时间接入原生`PATCH /scheduled-runs/{id}`，只写入时间表达式和北京时间时区，保留计划ID、研究内容、任务归属及历史。宿主首次写入前校验工作台归属，沿用原请求核对与回执机制；结果未知时不重发，也不继续关闭同类其他计划。四项按真实`config.mona_workbench`归组，不靠标题猜任务。关闭状态的默认时间是本地设置，不表示原生已有计划；以列表开关明确启用。普通设置按钮使用中性控件。

调度说明依据原生`scheduled_research/executor.py`及其重启测试：应用运行时执行计划；恢复时仍有效的到期计划会执行一次，不逐个补齐错过周期。周一至周五按日历安排，不等同A股交易日。执行服务暂不可用时准确提示，不显示虚假的已启用状态。

执行频率支持每天、周一至周五、每周指定一天、自定义多个星期。界面将选择转换为原生五段时间表达式，周日沿用Vibe的`0`，不使用不支持的`7`；当前计划及本地默认时间均能回显执行日。自定义未选择日期时在字段旁提示，不提交计划。

跟进设置使用齿轮图标，保留悬停提示与可访问名称。股票模块的文字按钮和报告链接统一使用浅灰色悬停背景，不使用下划线反馈。
