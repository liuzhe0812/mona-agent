# Mona 客户端品牌 UI 更新方案

> 状态：讨论底稿 v1.1，未授权实施  
> 日期：2026-08-22  
> 适用范围：Mona 桌面客户端、WebUI、系统图标、托盘图标、通知、头像与品牌状态组件  
> 上游品牌依据：[`2026-08-20-mona-brand-ui-redesign-proposal.md`](./2026-08-20-mona-brand-ui-redesign-proposal.md)  
> 当前官网双形态主视觉：[`hero-concept-v8.webp`](../../official-site/public/img/hero-concept-v8.webp)

## 1. 文档目的

本文完整记录 Mona 客户端下一轮品牌 UI 更新方向，作为后续视觉讨论、资产制作和代码改造的统一底稿。

本文解决三个问题：

1. 官网已经形成黑猫／女性人形双形态、黑红暖白与青蓝光效，客户端如何建立对应关系；
2. 当前客户端的卡通猫、玩偶猫、紫色机器人和官网 IP 如何收口成一个 Mona；
3. 如何增强品牌识别，同时保持邮件、文档、数据库、终端等高密度工作界面的长期可用性。

本文不直接授权修改代码或正式品牌资产。Logo 母版、颜色样板和首个客户端页面通过评审后，再进入实施。

## 2. 核心结论

### 2.1 品牌与工作界面分层

> 官网负责制造记忆点，客户端负责让人长时间安心工作。

客户端不照搬官网的大面积黑红拼贴、纸张纹理和高对比斜切。统一感来自以下稳定元素：

- 同一个黑猫 Logo；
- 同一套黑、暖白、品牌红、功能蓝和 AI 青色；
- 同一个 M 项圈核心；
- 同一种可靠、敏锐、能干而不过度卖萌的人格；
- 同一套 Agent 状态表达。

### 2.2 配色策略

- 暖中性色承担长期工作表面；
- Mona 蓝承担常规交互；
- AI 青色承担 Agent 工作状态；
- 品牌红承担身份识别和少量品牌强调；
- 语义红继续只承担错误、危险和不可恢复操作；
- 股票涨跌色、成功绿和警告琥珀保持独立语义。

颜色关系固定为：

> 红色负责“这是 Mona”，蓝色负责“这里可以操作”，青色负责“AI 正在工作”。

### 2.3 Logo 策略

- 小尺寸 Logo 只使用黑猫形态，不塞入人形剪影；
- 人形 Mona 只进入启动、欢迎、订阅、About 和其他大尺寸品牌表面；
- App 图标、托盘、favicon、侧栏、会话头像和通知统一来自一个黑猫 Logo 母版；
- 现有 `AgentLogo` 保留状态接口，移除另一套代码绘制猫造型；
- 初期不制作多套角色动画，状态通过同一个 Logo 外围的颜色、光环和轻动效表达。

## 3. 当前状态审计

### 3.1 当前客户端配色

全局 Token 位于 [`webui/src/globals.css`](../../webui/src/globals.css)。当前基础为：

- 浅色模式：纯白／中性灰表面；
- 深色模式：中性黑／深灰表面；
- `--theme`、`--action`、`--info` 主要使用蓝色；
- `--primary` 在浅色模式接近黑色，在深色模式接近白色；
- 品牌红没有稳定、独立的产品 Token；
- 当前蓝色体系已经具备可复用基础，不需要逐页重新设计。

结论：问题不是客户端必须彻底换色，而是中性表面偏通用、品牌 Token 缺失、身份资产彼此冲突。

### 3.2 当前身份资产冲突

| 当前入口 | 当前形象 | 问题 |
|---|---|---|
| [`webui/public/brand/mona_app_icon.png`](../../webui/public/brand/mona_app_icon.png) | 大眼卡通猫 | 与官网半厚涂黑猫气质不同 |
| [`webui/public/brand/mona_avatar_white.png`](../../webui/public/brand/mona_avatar_white.png) | 另一版扁平猫脸 | 与 App 图标也不完全一致 |
| [`webui/src/components/AgentLogo.tsx`](../../webui/src/components/AgentLogo.tsx) | 代码绘制玩偶猫 | 状态完整，但角色造型独立成第三套 |
| [`webui/src/assets/icons/sidebar-mona.png`](../../webui/src/assets/icons/sidebar-mona.png) | 紫色机器人 | 与 Mona 的猫／人双形态无关 |
| [`src-tauri/icons/`](../../src-tauri/icons/) | 旧卡通猫应用图标 | 与官网和客户端内部形象脱节 |
| 官网与品牌内容 | 新黑猫＋女性人形 | 已形成新的品牌母体，但尚未下沉到客户端 |

结论：客户端目前不是一个 Logo 需要替换，而是至少四套身份需要统一。

### 3.3 可复用的现有实现

- `AgentLogo` 已有 `working`、`idle`、`welcome` 状态；
- `AgentLogo` 已有 `scene`、`avatar` 两种裁切语义；
- 多个模块已经统一通过 `AgentLogo` 显示 Mona；
- 浅色／深色主题已经通过 Token 管理；
- `prefers-reduced-motion` 已被现有 Agent 动画支持；
- Tauri 图标清单已经集中在 [`src-tauri/tauri.conf.json`](../../src-tauri/tauri.conf.json)。

更新应复用这些入口，不创建第二套主题系统、组件库或 Agent 状态 API。

## 4. Mona 双形态在客户端的职责

### 4.1 黑猫形态：产品识别主体

用于：

- App 图标；
- 托盘和任务栏；
- favicon；
- 会话与房间头像；
- 侧栏 Mona 入口；
- AI 面板开关；
- 通知；
- 待命、工作、等待和完成状态。

造型冻结规则：

- 黑白礼服猫；
- 额头与头顶保持纯黑，不增加白色刘海或白斑；
- 白色只保留在口鼻、脸颊、胸口和爪部；
- 青蓝眼睛；
- 黑色分段项圈和青色 M 核心；
- 神态柔和、聪明、从容，不做捕猎感或幼儿化大眼；
- 小尺寸减少毛发和光效，保留耳朵、眼睛、口鼻色块和 M 核心。

### 4.2 女性人形：人格与信任主体

用于：

- 启动和登录；
- 首次欢迎；
- 订阅与 Pro 说明；
- About；
- 重要权限、请示和安全解释；
- 更新内容和品牌宣传。

不用于：

- 20–64px 小头像；
- 每个按钮、卡片和工具栏；
- 邮件正文、文档正文、数据库表格和终端输出；
- 每种 Agent 状态各造一套人形动画。

### 4.3 双形态关系

- 两种形态共享青蓝眼睛、M 核心和左红右青轮廓光；
- 官网以重叠投影表达“同一角色两种形态”；
- 客户端不需要反复展示双人构图，只需让角色资产、颜色和 M 核心保持一致；
- 女性人形不是黑猫的主人，黑猫也不是女性角色的宠物。

## 5. 客户端配色系统

### 5.1 颜色职责

| 颜色 | 候选值 | 职责 | 禁止用途 |
|---|---:|---|---|
| Mona Ink | `#070706` | 品牌黑、启动与品牌表面 | 压平全部深色工作层级 |
| Mona Paper | `#F3EAD9` | 暖白文字、浅色品牌表面 | 给所有工作区叠加纸张纹理 |
| Mona Red | `#E51D2A` | 品牌切角、Pro、身份强调 | 普通主按钮、长期焦点、错误状态 |
| Mona Blue | `#087EDB` | 常规交互、链接、选中、主按钮 | 大面积装饰背景 |
| AI Cyan | `#31D6F6` | AI 工作、流式响应、M 光环 | 普通非 AI 控件 |
| Mona Amber | `#FFBD4A` | 等待确认、提醒、短时强调 | 与成功或错误混用 |

### 5.2 Cindy 浅／深色参考结论

2026-08-22 讨论中确认：Cindy 官网的浅色和深色内容页可作为 Mona 客户端主题的重要视觉参考。借鉴的是配色方法和信息层级，不是 Cindy 的具体皮肤。

建议吸收：

- 浅色使用暖米白画布、近黑标题、冷灰正文和稀少红色强调；
- 深色使用带蓝紫倾向的深灰黑，而不是纯黑；
- 两套主题保持相同表面层级和信息结构，只改变明暗关系；
- 红色集中在章节编号、短标签、边线和局部强调；
- 卡片主要依靠细边框和轻微明度差分层；
- 阴影、渐变和圆角保持克制。

Mona 的差异：

- 保留现有 `#E51D2A` 品牌红，不复制 Cindy 的具体红色；
- 普通交互继续使用 Mona Blue；
- Agent 工作状态使用 AI Cyan，这是 Mona 蓝眼与 M 核心的产品延伸；
- 官网式大标题、不规则卡片和纹理不进入高密度工作模块；
- 品牌纹理只进入欢迎、登录、订阅、About 和其他明确品牌表面。

### 5.5 Token 迁移原则

新增品牌 Token：

```css
--brand-ink: 60 8% 3%;
--brand-paper: 39 52% 90%;
--brand-red: 356 79% 51%;
--brand-blue: 206 93% 45%;
--ai-cyan: 190 92% 58%;
--brand-amber: 38 100% 65%;
```

实施时：

- `--theme`、`--action` 继续承担普通交互，映射到 Mona Blue；
- `--brand-red` 仅由品牌表面显式消费；
- `--ai-cyan` 仅由 Agent 状态和 AI 控件消费；
- `--destructive` 不映射为 `--brand-red`；
- `--stock-up`、`--stock-down` 保持行情语义；
- `--success`、`--warning`、`--info` 保持业务状态语义；
- 业务组件不得直接新增品牌 hex，统一通过 Token 使用。

以上色值是视觉样板候选，冻结前必须完成浅色、深色和文本对比度检查。

### 5.6 默认主题

建议继续：

- 首次启动跟随系统；
- 用户选择持久化；
- 不因为官网是深色就强制客户端默认深色；
- 对外宣传截图以 Mona Night 为主，同时保留 Mona Paper 的工作场景。

当前 [`useTheme.ts`](../../webui/src/hooks/useTheme.ts) 已支持跟随系统和持久化，不需要新增主题机制，只需同步窗口底色候选值。

## 6. 品牌浓度与组件使用规则

### 6.1 品牌表面

允许使用较强红黑／暖白关系：

- 启动页；
- 登录与订阅；
- 新会话欢迎区；
- About；
- 更新通知；
- 空状态；
- AI 面板标题和 Mona 身份区域。

可以使用：红色切角、青色 M 光、低密度斜线、角色插画和短时动效。

### 6.2 工作表面

邮件、笔记、文档、数据库、股票和终端遵守：

- 平面色差＋1px 边界建立层级；
- 正文区不放角色插画；
- 表格、编辑器、终端输出不使用红黑拼贴；
- 普通按钮使用 Mona Blue；
- 只有 AI 控制区域使用 AI Cyan；
- 品牌红不承担选中、成功或焦点状态；
- 不为品牌更新引入新 UI 依赖。

### 6.3 侧栏与应用外壳

- 侧栏使用暖中性／深蓝黑表面；
- 当前项使用轻量蓝色表面；
- Mona 入口可以增加一条克制的品牌红切角或 2px 标记；
- 图标继续保持业务模块可识别性，不全部改成猫或红色；
- 顶栏、分隔线和窗口底色必须与主题 Token 同步。

### 6.4 AI 面板

- 面板标题显示统一黑猫头像和 “Mona”；
- 工作中使用青色呼吸光或短进度线；
- 等待用户确认使用琥珀色；
- 完成使用成功绿；
- 失败使用语义红；
- 状态颜色出现在头像外围和状态提示，不染色全文或整个面板。

### 6.5 控件

- 主按钮：Mona Blue；
- 次按钮：中性表面＋边框；
- 品牌 CTA：只在登录、订阅、欢迎和升级中允许使用 Mona Red；
- 输入焦点：Mona Blue／AI Cyan，按控件是否由 AI 驱动区分；
- 危险操作：继续使用语义红＋图标＋确认文案；
- 链接：Mona Blue，不使用品牌红。

### 6.6 数据与图表

- 股票涨跌色不因品牌更新改变；
- 图表主序列优先 Mona Blue，辅助序列使用青、琥珀和中性色；
- 品牌红不覆盖行情红；
- 数据色板必须独立于 Logo 色板，避免品牌装饰影响数据判断。

## 7. Logo 与身份资产系统

### 7.1 单一 Logo 母版

先制作一张 1024px 栅格母版：

- 黑色圆角方形或可适配圆角遮罩的安全底；
- 柔和的 45° 黑猫头像；
- 纯黑额头、白色口鼻；
- 青蓝眼睛；
- 左红右青轮廓光；
- 下方保留可识别的 M 项圈；
- 暖白细内框；
- 无文字、无电脑背景、无复杂人形剪影。

原因：双形态主视觉适合大画面，不适合 16–64px 图标。小尺寸只需稳定识别 Mona 黑猫。

### 7.2 资产层级

| 资产 | 用途 | 内容 |
|---|---|---|
| Brand key visual | 官网、启动宣传 | 黑猫＋人形双重曝光＋环境 |
| App icon master | 安装包、任务栏、商店 | 单独设计的黑猫头像 |
| Avatar | 会话、房间、通知 | App icon 同角色的透明／中性底裁切 |
| Favicon | 16–32px | 极简耳朵、眼睛和口鼻色块 |
| Wordmark lockup | About、登录、品牌页 | 黑猫图标＋排版 `MONA` |
| Human portrait | 欢迎、订阅、权限说明 | 女性人形，不进入小尺寸 Logo |

### 7.3 `AgentLogo` 最小改造

保留现有组件接口：

```ts
type AgentLogoState = "working" | "idle" | "welcome";
variant?: "scene" | "avatar";
```

初期只替换组件内部视觉：

- 使用统一黑猫栅格资产；
- `state` 仅控制外围光环、轻位移或透明度；
- 不再在组件内维护另一套猫的 SVG 身体、眼睛和服装；
- 保留 `prefers-reduced-motion`；
- 不增加动画库。

状态建议：

| 状态 | 表达 |
|---|---|
| `idle` | 静态，无光环 |
| `welcome` | 极轻缩放／摆动，青色常亮 |
| `working` | 青色呼吸环或短扫描线 |
| 等待确认 | 由调用方外围使用琥珀色状态，不扩展角色造型 |
| 失败 | 由调用方状态提示使用语义红，不让角色做滑稽失败动作 |

### 7.4 必须统一替换的入口

| 范围 | 当前入口 | 目标动作 |
|---|---|---|
| Web App 图标 | `webui/public/brand/mona_app_icon.png` | 从新母版导出 |
| favicon | `mona_favicon_32.png`、`mona_icon.png` | 从同一母版简化导出 |
| Apple Touch | `mona_apple_touch.png` | 从同一母版导出 |
| 默认头像 | `mona_avatar_white.png` | 替换为统一黑猫头像 |
| Agent 状态 | `AgentLogo.tsx` | 保留 API，替换内部造型 |
| 侧栏 Mona | `sidebar-mona.png` | 删除紫色机器人，使用统一黑猫图标 |
| Tauri 图标 | `src-tauri/icons/*` | 使用图标工具一次生成全部规格 |
| 通知／工具栏 | 所有 `AgentLogo` 调用处 | 自动继承统一资产 |
| 官网 favicon | `official-site/public/favicon.ico` | Logo 定稿后同步替换 |

不得逐个入口单独重画。所有尺寸由同一母版和明确裁切规则生成。

## 8. 形状、字体与动效

### 8.1 形状

- 保留现有 4／6／8／12／16px 圆角层级；
- 品牌表面可使用少量斜切角；
- 工作卡片、表格和弹窗不改成漫画分镜；
- 不为品牌感重写 Radix／shadcn 基础组件。

### 8.2 字体

- 正文和工作界面继续使用系统无衬线字体；
- 等宽字体继续用于终端、状态码、时间和技术标签；
- 官网式重展示字体只进入启动、欢迎和少量品牌标题；
- 不在邮件、笔记和数据库正文中使用装饰字体。

### 8.3 动效

- 控件继续复用现有 120／180／240ms Token；
- 角色入场可以使用 500ms 级短动画；
- 工作状态使用弱呼吸或扫描，不使用持续大幅摆动；
- 动画关闭后必须仍能通过文字和颜色理解状态；
- 不新增动画依赖。

## 9. 实施范围与顺序

## 10. 验收标准

### 10.1 品牌一致性

- 遮住 `Mona` 名称后，官网、App 图标、侧栏和会话头像仍像同一个品牌；
- 客户端不再出现紫色机器人和旧大眼卡通猫；
- 黑猫形态在 20px、32px、64px 和 512px 都可识别；
- 女性人形与黑猫只通过大画面双形态资产建立关系，不强塞进小 Logo；
- M 核心、青蓝眼睛和红青轮廓光保持一致。

### 10.2 可用性

- 邮件、文档、数据库和终端的信息密度不因品牌化下降；
- 浅色和深色主题均保持明确表面层级；
- 普通主操作与危险操作不会因品牌红混淆；
- AI 工作状态、等待确认、成功和失败可被清楚区分；
- 键盘焦点、禁用态和悬停态仍清晰；
- 文本对比度在实施阶段通过自动工具验证 WCAG AA。

### 10.3 工程质量

- 不新增 UI 或动画依赖；
- 不在业务组件硬编码品牌色；
- `AgentLogo` 公共 Props 不变；
- Tauri 图标通过一个母版批量生成；
- `npm run build`、`npm run lint`、`npm run test`、`npm run check:ui` 通过；
- 每个推广阶段提供浅色、深色和关键状态截图；
- 用户已有主题偏好继续生效。

## 11. 风险与取舍

### 11.1 红色与业务语义冲突

风险：品牌红、危险红和股票上涨红同时存在。  
处理：代码中使用独立 Token；品牌红只进入品牌表面，不作为通用控件状态。

### 11.2 半写实 IP 在小尺寸失真

风险：直接缩小官网角色会糊成深色块。  
处理：单独设计 App icon master 和 favicon 裁切，不从首页插画机械裁图。

### 11.3 客户端过度官网化

风险：红黑拼贴进入工作区后造成疲劳和信息噪声。  
处理：品牌图形只进入启动、欢迎、身份和状态表面；工作区使用暖中性 Token。

### 11.4 一次性全局换色导致回归

风险：大量业务模块存在自定义图表、编辑器和状态色。  
处理：先身份资产，再单页 Token 样板，再按模板推广；不进行全仓机械替换。
