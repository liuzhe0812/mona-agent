# 音乐人 Agent 与侧栏乐谱预览方案

- 日期：2026-09-10
- 状态：待实施；本文交付方案与开发计划，不表示功能已完成。
- 首版目标：音乐人 Agent 能按风格创作、解释和修改短篇器乐作品，交付 ABC 乐谱；右侧栏显示五线谱、源码，并提供钢琴试听。
- 体积目标：Windows 安装包增量约 2.6～3.7 MB；音乐人专家包单独统计，同时报告两者合计增量。

## 1. 需求与范围

两项核心需求：

1. 右侧栏支持乐谱预览，达到用户参考图中“左侧创作对话、右侧完整五线谱、顶部操作栏”的交互效果。
2. 新增“音乐人”官方 Agent，配置懂乐理、能按风格作曲和编曲、能评审与修改作品的 Skill。

首版包含 ABC 生成、单旋律与钢琴双谱表预览、乐谱/代码切换、钢琴播放/暂停/重播、播放音符高亮、ABC 文件交付与 MIDI 导出。只内置一种钢琴音色；吉他作品可以生成，但首版试听统一标明“钢琴试听”。

创作以 8～48 小节器乐作品、旋律与伴奏为主要验收对象。首批风格为流行抒情、民谣、爵士入门、古典小品、氛围配乐。风格能力由写作参考与实际样本验收体现，不宣称覆盖任意风格或达到专业制作水平。

不纳入首版：音频扒谱、人声合成、录音混音、Suno 接入、完整 DAW、多轨音频工程、专业出版排版、MusicXML 导入导出、可视化拖动音符编辑、完整 GM 音色库、多 Agent 编曲团队。吉他六线谱自音乐人 1.2.0 起由 `guitar-tab` Skill 覆盖（见 §6.4），文件直接记录弦号与品位。

## 3. 侧栏体验

用户在音乐人会话提出需求，例如：“写一首 24 小节、3/4 拍的 C 小调钢琴小品，旋律温柔，后半段有推进。”

Agent 先确定曲式和写作方向，生成乐谱并校验，通过现有交付通道交付 `.abc`。当前会话成功交付的新乐谱自动打开右侧预览；点击文件卡片也能打开。后台会话或迟到事件不能抢占当前标签。

右侧布局：

- 复用文件名、标签关闭、侧栏缩放、系统打开/定位等已有操作。
- 乐谱工具栏提供“乐谱 / 代码”“播放 / 暂停”“重播”“导出 MIDI”；源码页可复制文本，首版只读。
- 正文是白色谱纸、黑色记谱，支持左右手谱表、调号、拍号、速度、和弦名、连线与力度记号。
- 谱面纵向滚动。侧栏宽度变化时重新计算分行，避免只缩放导致音符过小；保留现有最大化入口。
- 播放时高亮当前音符。切换文件、隐藏乐谱标签、关闭侧栏或离开会话时停止播放，避免声音残留。
- 生成或读取失败时保留可恢复入口；格式错误显示可定位提示并允许查看源码，不呈现空白页冒充成功。

图中效果作为布局与功能参考，不要求逐像素复制。工具栏复用共享组件与语义 Token；谱纸保持阅读所需的高对比度。

## 4. 技术方案与生成验证

### 4.1 渲染和播放

采用 abcjs，按锁定版本引入并懒加载。新增 `MusicScorePreview.tsx`，负责 SVG 谱面、宽度变化重排、源码切换、播放状态和导出。不让音乐依赖进入聊天首屏静态加载路径。

使用现有鉴权文件读取接口获取 ABC，不新增任意本机路径访问入口。以 `ResizeObserver` 获取容器宽度，配合 `staffwidth`、`wrap` 分行；仅 `responsive: resize` 不足以解决窄栏可读性。

试听由 abcjs 与 Web Audio 完成，首次点击播放时初始化。钢琴 MP3 采样随应用静态资源内置，显式指定本地音色路径，禁止静默访问默认远端音色。只复制实际运行资源与许可证，不打包 npm 示例、源码映射或重复音色格式。

MIDI 由同一份已加载 ABC 生成，保存复用桌面已有文件保存能力。谱面、播放和导出必须绑定相同内容版本，修改后重建播放数据。前端不会把旧内容的播放进度应用到新乐谱。

### 4.2 轻量验证边界

不引入 music21、MuseScore、FluidSynth、独立 Node/Python 运行时。新增小型 `music_score` 工具，运行在现有 Gateway Python 进程中，首版仅提供工作区 ABC 文件校验能力；写文件、修改和交付继续使用现有工具。

验证器使用标准库，明确只检查首版约定的 ABC 子集，不开发完整 ABC 引擎。支持头信息、命名声部、高低音谱号、音符/休止符、时值、和弦、临时升降号、连音线和有限力度标记。首版生成不使用反复跳转、复杂装饰音、变拍号或跨小节特殊结构；弱起等未实现语法明确返回“不支持”，不得猜测通过。

检查内容：必要头字段、调号/拍号/速度取值、语法边界、小节累计时值、声部总长度对齐、用户要求的小节数、所声明乐器的基础音域。时值用分数精确计算。基础音域检查不能宣称已验证吉他指法或钢琴双手可演奏性。

返回结构化结果：`ok`、错误代码、声部、小节、源码位置、说明、内容摘要。摘要绑定被检查的文件字节；修改后必须重新校验。Agent 只有读取到最新版本成功结果后才按正式成品交付，失败可保留为明确标注的草稿。

前端仍用 abcjs 做真实解析与渲染，展示其错误/警告。开发测试使用同一批正反样本同时验证工具与 abcjs，防止出现两套不一致的支持范围。未知结构拒绝通过，而不是自动删除升降号、调整最后一个音符等会改变音乐意图的“修复”。

首批技术验证应确认这一受限验证器能保持简单。如果必须实现大量 ABC 语法才可满足本方案，应先收窄生成语法并报告差异，不能偷偷引入重依赖。

## 5. 音乐人 Agent 设计

显示名称：**音乐人**。建议包 ID：`com.mona.musician`。角色定位：作曲、基础编曲、乐理解释和作品修改助手。模型继承用户选择，不固定提供商，不承诺任何模型都能达到同等创作质量。

沿用官方专家目录安装流程，安装后出现在现有专家入口。首版单 Agent 完成工作，`canDelegate: false`。工具权限仅包含必要的 Skill 读取、工作区读取/写入/修改、`music_score` 和 `deliver_file`；工具名以当前注册表为准。不为作曲开放通用命令执行或新增浏览器权限。

建议源目录：

```text
expert-library/agents/com.mona.musician/
  agent.json
  package-manifest.json
  distribution.json
  prompt.md
  skills/music-compose/
    SKILL.md
    references/theory.md
    references/styles.md
    references/instruments.md
    references/review.md
    references/abc-output.md
    examples/
```

专家包 `runtimePacks` 为空，`requiredTools` 包含 `music_score`。旧客户端没有该工具时沿用兼容性检查明确提示升级，不因装入 Skill 而自行下载安装执行环境。

## 6. music-compose Skill 设计

### 6.1 职责与知识内容

一个核心 Skill 按需读取参考资料，避免过早拆出多个相互调用的 Skill。

| 参考资料 | 内容与约束 |
| --- | --- |
| theory | 调式、和声、旋律动机、声部进行、节奏与曲式；规则注明适用风格，不把古典禁则用于所有音乐 |
| styles | 五种首批风格的节奏、和声语言、旋律句法、伴奏织体、段落发展与常见失败示例 |
| instruments | 钢琴分手与跨度、吉他定弦/常见和弦与基础写作；区分谱面音高和实际音高 |
| review | 主题辨识度、重复与变化、段落对比、主次关系、风格一致性及用户反馈处理 |
| abc-output | 受支持语法、输出模板、文件流程、校验工具调用和错误修正方法 |
| examples | 小而完整的原创/许可明确的乐句与反例，标注写作目的；不得所有作品套同一旋律 |

### 6.2 执行流程

1. **理解需求**：提取用途、风格、情绪、乐器、难度、长度。常规缺口自行给出合理默认；影响作品方向的矛盾再提问。
2. **创作规划**：用简短文字确定曲式、主导动机、和声方向和高潮位置。风格必须体现为实际音符、节奏与织体，不以更换音色代替。
3. **短样与扩写**：较长作品先写 4～8 小节方向样本并自检，再展开；用户要求先听小样时等待反馈，其余任务继续完成，不固定增加多轮确认。
4. **校验与修正**：生成 `.abc`，运行 `music_score`，定位并修改问题。每次修改重新检查；持续无法通过时明确报告，不无限重试。
5. **音乐评审**：检查动机发展、句尾处理、伴奏主次、段落变化与声明难度。审美判断写成具体观察与修改理由，不以一个自评分宣布“专业级”。
6. **交付与后续修改**：交付 ABC，说明风格处理和可继续调整的点。用户要求“副歌更明亮”时定向修改对应段落，保留其余已接受部分并重新校验。

### 6.3 能力诚实性

格式检查通过仅代表已检查规则满足，SVG 显示成功仅代表可渲染。音乐是否好听由实际试听和用户反馈验收。

首版不新增音频理解模型。Agent 可基于乐谱做分析，但不得声称自己已经听过输出。爵士参考应容许合理的调外音；音高不属于调内音不能一律判错。吉他作品只做基础写作检查，不保证所有指法可行。

借鉴 Clef 的“规划—创作—验证—评审—修改”思路和公开风格资料，重新编写适合 Mona 的内容。不要直接复制其 Godot 路径、多 Agent 调度、强制确认或自动改音规则。引用内容保留来源及许可。

### 6.4 guitar-tab Skill 设计（1.1.0）

吉他六线谱使用独立 AlphaTex `.atex` 格式，不再通过 ABC 注释触发，也不从五线谱 SVG 中隐藏五线谱。`music-compose` 仍只生成 `.abc` 五线谱；`guitar-tab` 直接指定弦号、品位与时值，生成 `.atex`。

| 层 | 五线谱 | 六线谱（TAB） |
| --- | --- | --- |
| 文件 | `.abc` | `.atex` |
| 组件 | `MusicScorePreview` | `GuitarTabPreview` |
| 渲染器 | abcjs | alphaTab |
| 校验工具 | `music_score` | `guitar_tab` |
| 布局 | 响应式五线谱 | 纯六线谱、多行自动排版、节奏杆与连桁 |
| 语义 | ABC 音高与声部 | AlphaTex 弦号、品位、时值与吉他技巧 |

六线谱预览固定使用 tab-only stave profile 和带连桁的节奏显示。AlphaTex 文件显式声明六根弦定弦；音符以“品位.弦号.时值”书写，和弦把同时发声的弦品放进括号。这样谱面能直接表达把位，不依赖渲染器猜弦位。

`guitar_tab` 只校验 `.atex`：必要元数据、六弦定弦、拍号、品位范围、逐小节时值和期望小节数。音乐人交付 `.atex` 时，`deliver_file` 再执行相同校验，失败文件不能作为正式成品交付。

首版支持单音、和弦、休止、四分至三十二分时值、和弦名、上下拨弦、击勾弦、滑音与基础推弦。复杂打板、特殊泛音和无法确认的技巧仍需明确说明限制。

2026-09-11 Skill 优化：按吉他角色组织编配，增加开放弦、实际调/指法调、变调夹、持续音冲突与换把复核，来源及改写署名保存在 `guitar-tab/references/arrangement.md`。新增扫弦、分解、Drop D 和技法四组原创例谱，以 Python 交付校验和当前 alphaTab 解析模型共同验证。击弦与勾弦统一使用音符属性 `h`（位于时值前），不再把贝斯 `p` 当作勾弦。子集增加单附点的精确时值和已列技法的属性校验；未实现的节奏/属性应明确拒绝。可演奏性仍是结合乐器与目标速度的编配判断，不用任意数值评分宣称已自动保证。

2026-09-15 编配优化：guitar-tab 按指弹独奏与弹唱吉他声部分流，优先形成旋律乐句，再安排低音和内声；弹唱明确器乐段的主题发展与回到人声的衔接。`complete-examples.md` 提供两首完整短结构示例，原两小节素材仅作技法练习。增加原生音符延音 `t`、音符重音 `ac` 和拍力度 `dy` 校验，通过现有 alphaTab 播放。延音要求紧接前一拍同弦同品，可以跨小节；尚不实现独立 `\voice` 语法或自动审美评分。专家包的新资料与 Gateway 新校验器需要配套交付，单独更新旧客户端的 Skill 不会增加其语法能力。

## 7. 体积预算

前期查到 abcjs 6.7.0 压缩版 JS 为 511,903 字节；FluidR3 单套钢琴 MP3 目录约 1,983,629 字节。这是资源大小，不是 Mona 安装包实测差值。

| 项目 | 压缩后增量预算 | 处理 |
| --- | ---: | --- |
| abcjs、预览 UI、样式 | 0.15～0.30 MB | 锁版本、懒加载、剔除开发资源 |
| alphaTab、Bravura 字体 | 0.55～0.70 MB | 六线谱按需加载，只携带 WOFF2 字体与许可证 |
| 单套钢琴 MP3 与许可 | 1.7～2.1 MB | 只保留一种格式及实际所需文件 |
| 轻量校验工具及打包余量 | 0.05～0.20 MB | 复用 Gateway 标准库 |
| 音乐人专家包 | 0.05～0.15 MB | 文本和少量示例，独立下载并单列 |
| **总预算** | **约 2.6～3.7 MB** | **以真实安装包差值为准** |

MB 按 1,000,000 字节计算。专家包不进入基础安装包，但不得利用分发方式隐去首次使用总增量；同时交付安装包差值、专家 ZIP 大小和安装后磁盘增量。

以相同环境、依赖锁、压缩选项分别构建基线与功能版本，隔离其他任务变更；不比较混有其它功能的两次发布大小。懒加载改善首屏加载，不会自动减少安装包体积。

若实际超过 3.7 MB，先排除重复静态资源、源码映射和多余音色；仍超预算则汇报实测差异和选项，不能静默删掉钢琴试听、六线谱或改成联网加载。

离线验收指已安装客户端与专家后的谱面预览、试听和导出；AI 创作仍取决于所配置模型的可用性。首版无需额外音乐运行时下载。

构建和生成本地专家包属于验收；发布专家目录、上传生产包或发布 Mona 版本不属于本文开发阶段的自动授权。

## 9. 验收清单

### 9.1 侧栏与试听

- [ ] 当前会话交付 `.abc` 后打开正确标签，历史文件点击也能预览；后台交付不抢焦点。
- [ ] 48 小节钢琴双谱表能显示音符、调号、拍号、速度、连线、力度与和弦名。
- [ ] 右栏约 360、560、800 px 三种宽度下完成检查；狭窄处允许必要滚动但不裁掉音符，能最大化阅读。
- [ ] 乐谱/源码切换不丢内容；非法 ABC 有明确错误位置，不出现空白假成功。
- [ ] 播放、暂停、重播与高亮一致；修改、切换文件、关闭侧栏、切换会话不会残留播放。
- [ ] 断网可预览和钢琴试听，网络记录无远端音色请求。
- [ ] 导出 MIDI 可被独立播放器/解析器打开，时长、声部与当前 ABC 一致。
- [ ] 现有 Markdown、PDF、Office 等文件预览未因新增分支失效。

### 9.2 音乐人与创作

- [ ] 官方专家列表可安装音乐人，Skill 可加载，不要求额外音乐运行时。
- [ ] 验证器拒绝时值错误、声部不齐、不支持语法及未授权路径，返回具体位置；修订后结果绑定新内容。
- [ ] 五种首批风格各产出两段 16～32 小节样本，记录模型、提示词、作品与修改次数；所有样本通过技术检查。
- [ ] 同一主题至少做一次两种风格改编，节奏、和声或织体有可说明的变化。
- [ ] 完成一次“保留主题，仅修改指定段落”的对话，未要求改动的段落保持不变。
- [ ] 人工试听每类样本，记录风格辨识、主题连贯与段落变化的通过/不通过及原因；模型自评分不能代替人工验收。
- [ ] 不宣称已听音频、不保证吉他指法、不把生成成功描述成专业音乐制作完成。

### 9.3 包体与交付

- [ ] 安装包功能增量不超过 3.7 MB；专家 ZIP 和两者合计均列出，超预算明确报告。
- [ ] 新静态资源与引用内容许可证可随包交付，无遗漏开发资源或重复前端副本。
- [ ] 前端相关测试与生产构建通过；Python 运行相关行为测试和 `ruff check`，不批量格式化。
- [ ] 保存体积对比、生成样本、验收结果和未解决限制；不得将局部测试描述为全量通过。

## 10. 后续建议（不计入首版）

优先考虑可选的钢弦/尼龙弦吉他音色、MusicXML 互通，以及横按、跨弦和连续换把的进一步自动检查。吉他音色已有资源，但新增采样必须重新核算体积。需要按需下载时复用统一运行时仓库，不创建音乐专用下载器。

只有首版真实作品表明需要更复杂分析时，再评估 music21 等工具。完整歌曲音频、人声与混音是另一阶段，不能把当前 2～3 MB 的预算外推到这些能力。
