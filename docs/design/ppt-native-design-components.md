# PPT 原生设计能力

日期：2026-10-28

## 目标与边界

Mona 通过同一个 Office 编辑器实时生成、修改、观察和导出原生 PPTX。设计指导唯一来自内置 `mona-design`，以内容、受众、用户选定的风格或自定义要求为依据。

风格选择复用普通聊天和图片附件，不新增 PPT 专属审批工具、代表页批准、主题冻结、整稿状态机或另一套偏好存储。编辑与导出保持原生 Office 协议，不引入 HTML/PDF 中转。

## 实现

- `mona/skills/mona-pptx/SKILL.md`：轻量制作入口，设计路由到 `mona-design/references/native-pptx.md`。
- `mona/skills/mona-design/assets/style-specimens/ppt/`：20 组 JPG/HTML 风格样张；总览为 `sheet-ppt.jpg`。它们是视觉参考，不是完整原生 PPTX 模板。
- `mona/agent/skill_previews.py`：按设计包的 `assets/previews.json` 随入口附带真实总览图；资源路径、文件大小和解码尺寸受限。
- `mona/agent/tools/skill_tools.py`：Skill 和相关参考读取可直接返回图像块。参考路径可保留 Markdown 中的 `references/` 前缀，仍做 resolved-path 校验。
- 候选图片通过 `skill_asset_copy` 复制到活动工作区，再由 `deliver_file` 沿现有附件链路展示；仅向模型返回图片不等于用户已看到预览。
- `slides-design.ts`：11 种原生整页表达；其中指标、列表、图表解读、瀑布与流向可在明确区域内作为正常字号组件。完整页、区域组件与自由原生对象可混用。
- `slides-typography.ts`：混合文字片段、数值与单位、基线、字距、行段距及明确文本内边距；测量复用编辑器的布局和字体度量。
- `custom-path.ts`：由有限 M/L/C/Z 指令生成原生自由形状。数据到几何的计算由代码完成，模型不用逐个猜坐标。
- `slides-entry.tsx`、`slides-capabilities.ts` 与跨进程 Schema：原生页面及对象写入共用版本、事务和视觉检查；图片沿用受限资源读取链路。
- `slides-visual.tsx`：真实单页捕获及多页总览，均绑定版本；总览不替代细节检查或清除待审阅页。

## 设计能力的使用

### 新稿风格选择

用户未给定视觉方向的新稿，Mona 根据内容、受众、用途和实际素材推荐 3 种适合且有差异的现有风格，按推荐顺序展示样张、名称及简短理由。不为选风格先制作三套初稿。

用户可以回复序号或名称，也可以不选推荐，直接输入自定义风格提示词。通过通用 `ask_user_question` 在同次工具调用中等待答复，收到答复后再开始制作。用户的组合要求按原意执行，原始内容、页数及未被新要求修改的品牌约束持续有效。

已指定风格、提供品牌模板、当前文稿续编，或明确让 Mona 自行决定并直接制作时不重复选择。只有品牌色时仍可提供符合品牌色的候选；自定义要求无需映射回内置风格。

选定后参考真实样张与源码落实配色、字体层级、间距和版式特征，按内容扩展整稿；不复制样张中的示例事实。HTML 的滤镜、模糊等效果需按 Office 的真实支持适配，不承诺原生无损复现。

主指标、图表、解释和注释具有不同视觉权重；不把所有文字默认装入等权圆角框。但卡片、对称、重复构图本身并非错误，应由内容决定。

### 原生绘制与续编

旧的 12 用途场景分类、场景配色与场景元数据已移除。通用原生页面结构仍可显式绘制，但不承担风格推荐。成熟组件可以组合、调整，也可使用原生对象定制，不为匹配版式改写事实。

配色参数是创建参数，不是已生成文稿的动态主题绑定。完成后改色用当前文稿的 palette 查询和 slide_replace_colors 精确修改已有颜色节点，可按页面、对象、属性范围选择或排除。字体、坐标、文字、形状和图表仍按真实稳定对象 ID 修改，不重新运行整页创建，也不保留一份覆盖用户编辑的第二文档模型。

## 准确性与可编辑性

内容按 label、detail、value、unit 等语义字段传入。文字过长时调整区域、布局或等义表达；不静默截断必含事实，不改变原始关系来匹配设计。零值、负向变化、起终点、单位和小数必须保留含义。

标准数据图表保留原生 chart 数据。SVG/PNG 图片不冒充可编辑数据图表；桑基和瀑布信息图形保存为可编辑原生路径、形状与文字，不声称具有 PowerPoint 标准图表的数据表编辑能力。照片、独立素材和截图仍为图片，不以整页图片替代正文。

公共操作数组最多 50 项；非设计操作及其图表样式仍不超过 50 个内部操作；受控设计组件展开后的整批最多 256 个内部操作。所有写入共用原子事务、版本冲突和回滚语义，只推进一次 revision。

PPT Agent 正常导出要求处理真实硬错误和待检查页。模型不能用 `allow_unreviewed` 为自己授权；草稿可以保存，用户仍可从编辑器直接导出。该约束不阻止制作，也不影响已完成页面的保留。

## 验证范围

样张读取、复制和聊天附件展示与模型选择分别验证。工具链路通过不代表模型每次都遵循指引，也不代表整稿设计合格。

`scripts/verify_ppt_agent_live.py` 使用实际配置模型、生产 AgentRunner、认证 Office API 和真实编辑器，隔离于用户现有会话。模型自行决定内容与操作，没有预先编排页面 JSON。此测试不是整个桌面应用的端到端测试，也不自动证明审美质量。

历史 Dashi 模板已移除，不再使用旧导入结果或包体数据说明当前能力。此前清理记录见 `docs/plans/ppt-huashu-office-cleanup.md`。
