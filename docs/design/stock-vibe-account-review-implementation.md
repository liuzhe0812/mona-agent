# 账户与复盘实施记录

- 日期：2026-10-20。
- 范围：股票模块“账户与复盘”Tab 的默认成交复盘流程、持仓次级视图及 Shadow 进阶入口。
- 原生依据：[Vibe 原生能力与 Tab 映射](stock-vibe-native-capabilities.md)；[股票模块开发标准](../architecture/stock-module-development-standard.md)。
- 当前状态：本轮成交复盘流程实现完成，定向测试、前端构建、组件交互复评与隔离真实模型链路已通过；不代表整个账户或股票模块已验收。

## 1. 默认用户流程

账户与复盘首先服务于一份成交文件的复盘：导入并核对文件 → 查看成交覆盖、盈亏/费用表现与行为总结 → 从原生任务历史重开准确结果 → 导出 Markdown、查看计算解释或沿同一研究上下文追问。普通复盘沿原生 `analyze_trade_journal` 解析、配对和行为分析；不要求先有五组盈利往返，也不要求运行 Shadow 回测。账户页隐藏与成交复盘无关的投资风格选择。

成交结果只说明文件及可识别记录覆盖到的范围。未匹配卖出可能缺少对应买入或期初记录，不能据此推断为做空，也不能把它当成当前持仓。旧结果缺少覆盖或统计字段时保持缺项，不补造数字或历史字段。

持仓放在次级视图，字段只来自实际读取到的持仓来源，并保留来源和可用时点。文件导入和成交复盘不表示已连接东方财富账户，也不生成未经来源支持的余额、持仓或净值。

Shadow 作为按需进阶功能进入独立详情浮窗，用户需精确选择对应的历史结果。现有流程使用固定的5只A股模拟篮子，默认模拟资金100万元；其规则提取、回测、报告和信号扫描属于模拟研究，不表示账户账本重放或真实账户表现。

## 2. 原生能力与最小适配

- 保留 Vibe 现有成交解析、FIFO配对及行为算法。0045 只扩展既有 parse/FIFO 投影：返回覆盖信息、逐币种费用与盈亏、`by_symbol` 汇总、最多200条已配对明细和最多200条未配对明细，同时提供完整聚合统计。明细上限不截断聚合结果。
- 0046 将 Mona 研究 Session 精确绑定到已完成的 `analyze_trade_journal.operation_id`，通过只读 `read_trade_review` 读取原有统计。追问沿用共享研究上下文，不改写用户内容或 system prompt；不依赖标题或浏览器索引猜测历史结果。
- 模型默认读取汇总，行为、逐股及已保存配对/未配对明细按需分页，每次最多10行；完整原生操作结果保留。类型证据只复制原有金额、比率、数量、持有天数及价格，保留原始字段和币种，使用实际调用及精确字段引用；不补算金融指标，不修改或关闭原生数值检查。
- 成交明细、覆盖缺项和计算解释按需打开信息浮窗；主要复盘内容保持直接可读。界面不堆叠嵌套容器，不使用黑色主按钮，也不把长解释平铺在结果区。盈亏颜色遵循股票界面约定：红色为上涨/盈利，绿色为下跌/亏损。
- 交易配对和统计始终来自原生结果；Mona 只处理输入、关联、中文结果投影和导出，不重建金融计算或另设复盘任务引擎。

## 3. 本轮范围外与未验收项

普通东方财富真实成交导出格式、在线持仓与净值流程仍未验收。本轮不扩展在线账户连接、组合风险分析或调仓，也不把普通成交复盘绑定到 Shadow。只有读取到真实来源和字段时才显示持仓内容；缺少来源时明确说明。
