# 软件卸载与残留清理方案

- 日期：2026-09-13
- 状态：设计，作为当前软件管理实现的收敛目标
- 范围：Windows 系统 → 软件管理中的桌面软件卸载、卸载后残留检测与清理
- 依据：[工程边界](../architecture/engineering-boundaries.md)、[模块不变量](../architecture/module-invariants.md)、[UI 设计系统](mona-ui-design-system.md)

## 1. 产品决定

卸载分成“卸载软件”和“清理残留”两个阶段。官方卸载器完成后必须重新扫描，只有复检结果才能决定页面显示“已清理完成”。卸载成功不自动删除文件，所有删除动作都需要用户选择和一次明确确认。

后端是软件身份、卸载命令、扫描范围和删除授权的唯一权威。前端只提交稳定的软件标识和后端签发的候选标识，不提交卸载命令、路径或可执行参数。用户界面使用“软件提供的卸载程序”“系统应用卸载”等产品文案，不显示内部包管理器名称。

首版优先解决高置信度、低误伤风险的文件和快捷方式；系统级资源与用户资料先检测并说明原因，暂不自动删除。这样既能覆盖常见残留，也不会把共享运行库、项目文件或驱动误当成软件垃圾。

## 2. 软件身份

显示名称不是身份。后端读取并保存一次卸载会话的身份快照：

| 字段 | 规则 |
|---|---|
| `softwareId` | 后端生成的稳定条目标识，来源为注册表键、MSI 产品代码或 Appx 包身份；名称匹配不能生成身份 |
| 安装范围 | 区分当前用户和整机安装；分别读取 32 位、64 位注册表视图 |
| 产品身份 | `ProductCode`、`PackageFullName`/包族名、注册表 hive+key、应用商店精确 ID，按实际来源填写 |
| 显示信息 | 名称、发布者、版本、安装日期、安装目录；只用于展示和辅助匹配 |
| 可执行证据 | 安装目录下的主程序、发布者签名和规范化路径；读取失败时不降低为可删除证据 |
| 卸载信息 | `QuietUninstallString`、`UninstallString`、卸载类型和备用卸载方式；只存后端，不下发前端 |
| 别名 | 显示名称、安装目录名、厂商目录名的安全单段形式；去版本号和架构后再用于限定扫描 |
| 快照指纹 | 注册表键/包信息、安装目录和主程序文件的组合指纹，用于执行前复核 |

读取范围包括 HKLM/HKCU 的卸载注册表项、32/64 位视图和当前用户可见的 Appx 包。重复的 ARP 条目按产品代码、包身份或精确注册表键合并；不能只凭同名合并。卸载开始前必须重新读取该 `softwareId`，条目消失、身份变化或出现多个候选时终止并要求刷新。

## 3. 卸载流程

### 3.1 预检查与确认

确认面板显示软件名称、发布者、版本、安装范围、预计占用和将使用的卸载方式。若检测到相关进程、服务或待重启状态，显示影响；首版不强制结束用户进程，让软件自己的卸载器决定是否需要关闭。

确认后后端再次验证身份仍匹配。确认不授权前端传入命令，也不授权删除残留。

### 3.2 卸载器选择

按软件来源执行：

1. Appx/MSIX 使用精确包身份执行系统卸载；不按显示名称模糊查找。
2. 传统桌面软件优先执行当前注册表的 `QuietUninstallString`，失败后执行 `UninstallString`。
3. MSI 使用注册表中的产品代码；将维护安装参数 `/I` 安全转换为卸载 `/X`，保留其余受控参数。
4. 注册表没有可用命令时，只有具有已验证精确应用 ID 的目录条目才允许使用受控应用商店卸载作为最后备用方式。

Windows 命令行使用系统参数解析器拆分，环境变量按当前进程环境展开，禁止拼接 shell 字符串。每次尝试只执行一次，记录方法和结果；退出码 `0`、`1641`、`3010` 视为成功。非零退出但复检确认身份已消失时，显示“已移除，卸载器返回异常码”并进入残留扫描；身份仍存在才可进入下一种方法。所有方法失败时保留软件条目和可重试错误。

### 3.3 卸载后扫描

只有卸载阶段确认软件主体已经消失，才创建本次清理会话。扫描是有界查找，不递归整个用户目录，也不跟随符号链接、联接点或其他重解析点。

扫描根目录和匹配规则如下：

| 类别 | 首版扫描范围 | 匹配依据 |
|---|---|---|
| 安装文件 | 原安装目录、其直接厂商目录下的精确产品目录、Program Files/Program Files (x86) 中的身份别名 | 安装快照路径、主程序和发布者证据 |
| 应用数据 | `%LOCALAPPDATA%`、`%APPDATA%`、`%USERPROFILE%\\AppData\\LocalLow`、`%PROGRAMDATA%` 下的产品目录和 `厂商\\产品` 目录 | 精确产品别名；目录内容存在主程序/发布者关联时提高置信度 |
| 用户隐藏目录 | `%USERPROFILE%\\.<产品别名>`、`.config\\<产品别名>`、`.cache\\<产品别名>`、`.local\\share\\<产品别名>`、`.local\\state\\<产品别名>` | 仅查固定层级和安全单段别名，不删除 `.config`、`.cache` 等根目录 |
| 临时文件 | 当前用户和系统 Temp 下带精确产品别名的文件/目录 | 名称匹配并且最近写入或文件内容关联身份 |
| 快捷方式 | 当前用户/公共桌面、开始菜单和程序目录中的 `.lnk`/`.url` | 解析目标后，目标位于安装快照目录或指向已消失的主程序 |
| 注册表 | 卸载项、App Paths、协议、右键菜单、启动项等对应键 | 精确 hive+key、产品代码、安装目录或可执行目标 |
| 服务/任务/驱动 | SCM 服务配置、计划任务 XML、驱动服务及其镜像路径 | 镜像路径、服务描述、发布者签名与身份快照关联 |
| 用户资料 | Documents、Desktop、Downloads、Pictures、Videos、Saved Games、工作区和项目目录 | 产品别名或文件关联；只作为用户资料候选展示 |

别名必须是安全的单段路径名。对中文显示名优先使用注册表安装目录和可执行文件名；名称模糊、只有厂商名或只有文件扩展名的结果不能进入高置信度集合。

## 4. 候选模型与风险分级

`ResidualCandidate` 从单一目录路径扩展为以下最小字段：

```text
id                   后端签发的短期不透明标识
kind                 file | directory | shortcut | registry | service | scheduled_task | driver
path                 展示用规范化位置；删除时后端不接受前端传入的 path
sizeBytes            扫描时大小，系统项或未知大小为 0，界面显示为“—”
confidence           high | medium
reason               产生匹配的身份依据
recommended          是否建议用户勾选
canDelete            首版是否允许删除
requiresConfirmation 是否必须再次确认
```

置信度和默认行为：

| 级别 | 判定 | 默认行为 |
|---|---|---|
| 高 | 原安装目录，或精确产品目录且有安装/可执行/发布者中的两项以上证据 | `deletable=true`、默认选中；仍需二次确认 |
| 中 | 仅有产品别名、厂商目录下的单一证据，或无法排除其他版本 | 可删除但默认不选中，必须单独确认 |
| 低 | 模糊名称、共享根目录、只有扩展名或无法复核归属 | 仅展示，不允许删除 |

带 `userData` 或 `sharedComponent` 的候选默认不选中；首版不允许批量删除。用户资料、共享运行库、驱动和未知归属项必须在界面标明原因。

## 5. 首版清理范围

### 5.1 自动进入“建议清理”

卸载完成后，以下高置信度项目可以自动进入已勾选列表，但绝不自动执行删除：

- 原安装目录及其中的普通文件；
- 产品专属的 Local、Roaming、LocalLow、ProgramData 和固定层级隐藏配置/缓存目录；
- Temp 下精确归属产品的临时目录；
- 目标解析到该软件安装目录的桌面和开始菜单快捷方式；
- 身份精确匹配、软件主体已消失且没有其他产品引用的卸载注册表项。

删除目录前必须确认目录不是根目录、不是链接、不是重解析点，并且其当前规范化路径和类型与候选快照一致。被锁定的文件单独报告，不通过强制结束进程绕过。

### 5.2 首版只检测、不自动清理

以下项目扫描后显示位置、归属证据、风险和查看入口，但 `deletable=false`：

- Documents、Desktop、Downloads、Pictures、Videos、Saved Games、工作区和项目中的用户资料；
- 可能被其他产品使用的厂商根目录、运行库、SDK、共享缓存和公共组件；
- 服务、计划任务、驱动、驱动包、网络组件和安全软件组件；
- App Paths、协议、文件关联、COM、Shell 扩展、Run/RunOnce 等系统注册表项；
- 只有模糊名称、无法读取权限、路径发生变化或包含未知文件的项目。

这类项目保留“打开位置”和“复制位置”，并说明“检测到但不会自动删除”。后续若开放手动清理，必须为每种系统资源增加独立的风险确认和复检规则，不复用文件删除按钮。

## 6. 授权、删除与复检

每个候选绑定 `softwareId` 和扫描时确认的目标。可删除候选由后端生成一次性随机 ID，有效期 30 分钟；删除命令只接收候选 ID 和确认结果。ID 使用后失效，失败项在有效期内保留授权并在每次执行前重新校验。

执行前后端逐项检查：

1. 软件身份仍处于已卸载状态。
2. 候选 ID 存在且属于当前扫描会话，类型、规范化路径、文件标识和指纹未改变。
3. 路径解析后仍在允许的用户/程序数据根目录内，不能是根目录、链接或重解析点。
4. 注册表候选的 hive、key 和关键值仍与快照一致；文件候选不接受前端替换路径。
5. 需要管理员权限时通过现有受控提权入口执行，失败不降级为不安全的 shell 命令。

用户在页面勾选候选后点击“清理所选”，对话框显示数量、大小、路径类别、需管理员权限的项目和不可恢复提示。清理按候选独立执行，单项失败不回滚已成功项目。结果必须包含已删除、失败、跳过和实际释放空间；失败项保留查看位置和“重新检测并重试”。

删除结束后重新扫描原候选及软件身份：

- 原候选全部消失且没有新的高置信度项目：显示“清理完成”；
- 仍有文件或项目：显示“部分清理”，列出具体原因；
- 仅剩检测但不自动删除的项目：显示“卸载完成，仍有项目需要查看”，不能宣称彻底清理；
- 软件身份重新出现：标记卸载未完成，禁止继续删除残留。

## 7. 页面交互

卸载确认、卸载执行和残留清理使用连续状态，不同时叠加 Toast、Alert 和弹窗。卸载结束后，在“卸载与残留检测”区域展示：卸载结果、扫描时间、候选总数、建议清理数、仅检测数和占用大小。

残留列表支持按“建议清理 / 需要确认 / 仅检测”筛选；每项显示类型、路径、大小、置信度、归属依据和管理员要求。提供“选择建议项目”“打开位置”“复制位置”“清理所选”。清理确认对话框只确认当前选中项目，取消后保留选择。

卸载记录至少显示软件、时间、卸载方式、尝试次数、退出码、卸载复检、扫描数量和清理结果。错误信息可复制但不写入命令行中的敏感参数。按钮、状态和键盘焦点沿用共享组件及语义 Token；危险动作明确写出对象，例如“确认清理 3 项残留”。

## 8. 维护记录

每次卸载生成一个 `operationId`，记录：

- 软件身份指纹、安装范围和扫描规则版本；
- 开始/结束时间、使用的方法、每次尝试的结果和退出码；
- 卸载后身份复检结果；
- 扫描候选的类别、置信度、默认选择和总大小；
- 用户实际选择、删除成功/失败/跳过数量、释放空间和最终复检结果。

记录使用结构化数据，错误按“未找到身份、启动失败、权限不足、被占用、路径变化、卸载器失败、删除失败、复检不一致”分类。维护记录不保存密码、令牌、Cookie 或完整的未脱敏命令行。

## 9. 当前实现的收敛方式

保留现有 Tauri 软件管理入口和短期残留授权机制，按以下边界拆分 `software.rs` 中的逻辑：

1. `read_installed_software` 负责身份快照和卸载方法，不让前端字段覆盖后端值。
2. 卸载执行器只接收已复核的身份，分别处理 Appx、MSI、注册表卸载器和最后的精确应用目录备用方式。
3. 扫描器按根目录和候选类型返回结构化候选；文件扫描不再只返回目录路径。
4. 授权表绑定扫描会话、身份指纹和候选指纹；删除入口只按候选 ID 操作。
5. 删除器按类型执行并逐项返回结果；完成后统一调用复检，不用前端把“已发起删除”当作成功。

前端只扩展 `ResidualCandidate` 和清理结果展示，不在页面实现路径推断、命令拼接或风险判断。后端仍由 Tauri 持有 Windows 注册表、进程、服务和提权边界，不新增独立服务或第二套授权系统。

## 10. 验收标准

- [ ] Lenovo 等传统桌面软件能使用当前注册表卸载器完成卸载；同一失败方法不会被“重试”原样重复执行。
- [ ] MSI、Appx/MSIX 和普通桌面软件分别使用精确产品身份、包身份或注册表卸载信息；同名软件不会误选。
- [ ] 扫描覆盖原安装目录、Program Files、Local、Roaming、LocalLow、ProgramData、Temp、固定层级隐藏用户目录、桌面和开始菜单快捷方式。
- [ ] 扫描能发现卸载注册表项、服务、计划任务、驱动和用户资料；除身份精确匹配的卸载注册表项外，其余系统项与用户资料首版只检测、不自动删除。
- [ ] 高置信度专属文件和快捷方式默认选中；中置信度、用户数据、共享组件和系统资源默认不选中或不可删除。
- [ ] 删除必须经过后端签发的短期一次性 ID 和明确确认；原始路径、命令、链接、根目录、路径变化和过期 ID 均被拒绝。
- [ ] 普通权限和管理员权限路径均有明确结果；单项失败不影响其他项目，失败项可重新检测后重试。
- [ ] 清理后复检能区分“无高置信度残留”“部分清理”和“仍有仅检测项目”，不把卸载成功当成残留清理成功。
- [ ] 维护记录包含身份、方法、结果、候选统计、用户选择和复检信息，且界面不暴露内部执行器名称。
- [ ] 前端通过共享 Button、Dialog、Alert、Table 等组件实现默认、悬停、焦点、禁用、加载和错误状态；在 1440×900、1280×720、1024×720 及中英文文案下保持可用。
