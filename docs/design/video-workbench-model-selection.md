# 视频工作台的模型选择

日期：2026-10-16。状态：实现与以下相关验收完成。范围：新建视频、创建和编辑自定义风格的制作模型选择。沿用既有来源、账号、模型目录和选择器，不改配音、动画渲染或导出方式。

## 用户交互

- 新建视频在底部“准备分镜”旁提供一个紧凑模型选择器；风格编辑页在工具栏提供同一选择器。导演台及视频页继续显示该项目的选择，闲时可更换。
- 初始为“跟随 Mona · 当前模型”。用户直接选择来源下的模型及思考强度，不再分别选择引擎、供应商和模型。
- 可使用已配置 API 模型，以及已启用、已连接的 Codex、Claude Code、CodeBuddy 模型。停用、未连接或消失的模型保留说明，不悄悄更换为默认模型。
- 选择只影响当前制作会话；恢复项目时读取原会话的真实选择，不修改主会话或全局默认配置。风格尚未创建制作会话时，选择随恢复草稿保留。
- 制作运行中禁止切换；完成或停止后可选择供下一次制作使用的模型。切换等待回执时有忙碌反馈，准备分镜和生成样片等待选择确认。
- 默认模型和来源变化使用现有通知刷新；目录读取失败可重试，单个来源失败不隐藏其他可用来源。

## 数据与执行边界

### 新建页不预建会话

打开新建视频只创建本地页面；填写需求、预选模型、选择已有风格或关闭未提交页面均不创建制作会话。“准备分镜”提交有效需求后才创建会话，并同时提交当前模型选择。首次消息由视频工作台使用实际返回的会话 ID 发送，避免父页面尚未更新时把消息发给空 ID 或旧会话。

会话成功后回写工作区标签，制作对话随之显示；项目阶段刷新不会重新展开用户已收起的对话。恢复未提交的标签不创建会话或显示空对话面板，不把空 ID 登记到会话列表。已有会话关联保存失败时重试复用原 ID。

2026-10-16 本次交互修正：视频工作台及主会话导航 74 项、文档工作区 25 项回归通过，视频依赖树 TypeScript 检查通过。全局类型检查当时另有系统模块 `StoragePanel` 的图标导入、`SystemView` 的两个未使用变量错误；本次未修改这些模块，未称全局检查通过。未重新调用模型或导出视频。

复用 `AgentModelBinding`：`executor / provider / model / effort`。显式选择写入视频会话 `metadata.model_binding`；未发送字段表示保持，`null` 表示恢复继承。风格草稿的 `authoring.modelBinding` 只用于尚未创建会话时恢复选择，已有会话以 Gateway 保存值为准。

Gateway 通过既有鉴权 WebSocket 接收 `new_chat.model_binding`、`message.model_binding` 及 `video_model_binding_update`。更新有请求 ID 和成功或失败回执；读取使用受现有 API token 保护的 `GET /api/sessions/{key}/model-binding`，只取视频会话元信息，不读取整段历史或创建未知会话。会话分支保留选择。

每条视频请求携带当时的绑定快照。不同模型的排队消息不能注入正在执行的另一模型；同模型的自然语言追加维持原行为。视频循环按绑定隔离，禁止通过改写共享 provider 实现临时切换。默认继承继续解析父循环的模型预设；显式绑定不被 Mona Agent 覆盖或沿用其他模型的推理强度。

校验复用已有模型目录、原生发现与账号 probe。显式新选择在执行前检查来源、模型和思考强度；幂等或未修改的绑定不重复启动 probe。不得创建新的视频专用账号、下载器或凭据目录。探测只读且有界，不发送模型任务。

前端只在回执成功后接纳新选择。回执丢失后先读取实际值，不自动重放写入；结果仍无法确定时暂停启动新制作并提供重新读取动作。旧会话的迟到回执不能覆盖刚打开的另一视频。
