# Mona 会话列表 UI 改造方案

> 状态：已定稿  
> 更新日期：2026-08-15  
> 适用范围：桌面端会话列表及窄窗口会话抽屉  
> 设计目标：采用企业微信式紧凑列表骨架，强化 Mona 的任务型会话识别能力

## 1. 改造范围

本方案只改造会话列表这一局部 UI，不修改多 Agent 架构、会话数据模型和主工作区布局，不增加新的页面、列表分类或第三方 UI 依赖。

本次改造一次性交付以下内容：

- 顶部搜索及创建工具栏；
- 会话行的尺寸、排版和信息层级；
- 选中、悬停、未读和任务状态；
- Mona 任务、专业 Agent 私聊、协作房间的展示规则；
- 现有项目分组、置顶和归档在新视觉结构中的展示规则；
- 现有列表视图设置的兼容和退场规则；
- 标题、摘要和时间的展示格式；
- 桌面列表和窄窗口抽屉的一致性。

### 1.1 开发决策摘要

| 议题 | 最终决策 |
|---|---|
| 项目分组 | 保留项目分组及组级操作，只删除默认“会话”标题 |
| 列表视图设置 | 废弃 `density`、`show_previews`、`show_timestamps`、`sort`；保留 `show_archived` |
| 置顶与归档 | 保留现有能力；置顶固定在顶部，归档按需显示在底部 |
| 摘要清洗 | Gateway 负责语义过滤，前端负责 Markdown 等展示清洗，存量数据不回写 |
| 任务状态 | 从行尾移入第二行摘要区，第一行右侧只保留时间 |
| 历史未读 | Gateway 随新 schema 版本执行一次性初始化，前端不做批量迁移 |

## 2. 设计原则

### 2.1 优先保证扫描效率

用户应能快速判断：

1. 当前会话正在处理什么任务；
2. 会话属于 Mona、专业 Agent 还是协作房间；
3. 是否存在未读、执行中、等待确认或失败状态；
4. 当前选中的是哪个会话。

### 2.2 标题表达任务，头像表达身份

企业微信主要依赖联系人或群名称区分会话；Mona 中同一个 Agent 可能执行多个任务，因此任务型会话必须以任务主题作为标题，不能连续显示相同的“Mona”。

### 2.3 降低状态噪声

未读、任务状态和选中状态必须分别表达。红点只代表未读，不承担任务完成、运行或失败等含义。

### 2.4 保持单一列表结构

“单一列表”指会话、专业 Agent 私聊和协作房间继续位于同一个滚动区域，不增加“伙伴”“房间”等类型标签页或固定类型分组；它不表示废除现有项目工作区结构。

- 默认未绑定项目的会话直接平铺，不显示无意义的“会话”标题；
- 项目分组及组级的新建任务、移除项目、打开目录、展开和折叠能力全部保留；
- 置顶和归档继续作为具有明确业务含义的特殊区域；
- 最近活动排序作用于各区域内部，不覆盖置顶优先级和项目归属。

## 3. 最终布局

```text
┌──────────────────────────────┐
│ [ 搜索                    ] [+] │  60px
├──────────────────────────────┤
│ 置顶                              │
│ [头像] A股分析师               10:42 │
│        贵州茅台估值分析完成          │  64px
├──────────────────────────────┤
│ [头像] 制作新能源分析报告        昨天 │
│        报告已经生成                  │
├──────────────────────────────┤
│ ▾ Mona项目                         │
│ [组合] 每日投资研究              周三 │
│        研究员：等待确认研究范围       │
└──────────────────────────────┘
```

### 3.1 区域顺序与排序

显示顺序固定为：

1. 置顶区域，仅在存在置顶会话时显示；
2. 默认未绑定项目的会话，不显示区域标题；
3. 项目分组，项目之间按组内最新活动时间倒序；
4. 已归档区域，仅在用户开启“显示归档”时显示。

区域内部均按最后一条用户可见消息的时间倒序，缺少该时间的旧会话依次回退到更新时间和创建时间。置顶会话从原项目或默认区域中移除，禁止重复显示；取消置顶后返回原项目或默认区域。

项目分组标题必须采用低对比紧凑样式，不能与会话标题争夺视觉注意力。项目分组继续支持展开、折叠、新建任务、移除项目和打开目录等现有操作。

## 4. 顶部工具栏

| 属性 | 规范 |
|---|---|
| 高度 | 60px |
| 水平内边距 | 12px |
| 搜索框高度 | 36px |
| 搜索框圆角 | 8px |
| 搜索提示 | “搜索” |
| 搜索与创建按钮间距 | 8px |
| 创建按钮 | 36 × 36px，8px 圆角，浅色背景 |

要求：

- 删除搜索框下方的“会话”标题，工具栏下面直接显示统一列表；
- 搜索范围保持覆盖会话标题、Agent 名称、房间名称和消息摘要；
- 创建按钮继续提供新建 Mona 对话、专业 Agent 私聊和协作房间入口；
- 搜索和创建操作在桌面列表与窄窗口抽屉中使用同一组件。

## 5. 会话行

### 5.1 尺寸与排版

| 元素 | 规范 |
|---|---|
| 行高 | 64px |
| 行水平外边距 | 左右各 8px |
| 行水平内边距 | 8px |
| 头像 | 40 × 40px，8px 圆角方形 |
| 头像与正文间距 | 12px |
| 标题 | 14px，Regular，单行省略 |
| 未读标题 | 14px，Medium |
| 摘要 | 12px，弱化前景色，单行省略 |
| 时间 | 11px，弱化前景色，右上对齐 |
| 行圆角 | 普通状态无圆角；选中或悬停状态为 8px |

普通行不使用卡片阴影或独立边框。底部分隔线从头像左沿开始，到行内容右沿结束；选中和悬停状态下隐藏。

64px 是会话列表的固定组件尺寸，不参与全局密度缩放。全局设计规范中的标准密度和专业密度是组件场景分类，不是会话列表的用户缩放选项。

头像不随选中状态放大，不增加主题色圆环。单 Agent 使用圆角方形头像；协作房间在同样的 40 × 40px 圆角方形容器内显示组合头像，保证所有行的视觉起点一致。

### 5.2 标准结构

```text
[头像] [标题，可用宽度内单行省略] [时间]
       [发言者/状态 · 最新摘要]
```

标题和时间必须位于同一行。时间使用固定宽度且不收缩，标题使用剩余空间并单行省略。

整行（包括头像、两行文字和左右留白）都是同一个选择按钮，点击任意位置均进入会话；不得只让文字区可点击。当前会话通过 `aria-current` 暴露给辅助技术。

### 5.3 滚动条

- 滚动容器延伸到列表面板右边缘，不能被列表内容的水平内边距向内推；
- 原生滚动条不占用布局宽度，使用 4px 覆盖式滑块；
- 轨道始终透明，默认不显示滑块；鼠标进入列表或正在滚动时显示；
- 滑块使用弱化前景色，不设置箭头、阴影和常驻深色轨道；
- 滑块覆盖在会话行背景的右侧区域之上，不能挤压内容、裁切右圆角或扩大右侧留白。

## 6. 会话类型展示规则

### 6.1 Mona 任务会话

- 头像：Mona 头像；
- 标题：当前任务主题；
- 摘要：直接显示最新有效消息，不重复显示 Mona 名称。

示例：

```text
制作新能源行业分析报告
报告和图表已经生成
```

列表中不得连续使用“Mona”作为多个任务会话的主标题。

### 6.2 专业 Agent 私聊

一个专业 Agent 只有一个持续私聊时：

- 头像：Agent 专属头像；
- 标题：Agent 名称；
- 摘要：最新有效消息。

同一 Agent 支持多个独立任务会话时：

- 头像：Agent 专属头像；
- 标题：任务主题；
- 摘要：直接显示最新有效消息；头像已经表达身份，不重复显示 Agent 名称。

### 6.3 协作房间

- 头像：参与 Agent 的组合头像；
- 标题：房间任务名称；
- 摘要：`最后发言 Agent：最新有效消息`；
- 不额外显示“房间”文字标签。

### 6.4 展示标题优先级

1. 用户手动设置的标题；
2. 房间名称或房间任务；
3. 固定专业 Agent 名称；
4. 当前任务标题；
5. 清洗并截断后的首条有效用户消息；
6. “新对话”。

以上规则属于展示层规则，不要求修改底层会话数据。

## 7. 交互状态

### 7.1 普通状态

- 使用透明背景；
- 标题使用主前景色；
- 摘要和时间使用弱化前景色；
- 不显示常驻操作按钮。

### 7.2 悬停状态

- 背景使用 `--sidebar-hover-surface` 的 4% 透明度；
- 圆角 8px；
- 使用 120–180ms 颜色过渡；
- 不改变行尺寸和文字位置。

### 7.3 选中状态

- 背景使用 `--sidebar-active-surface` 的 9% 透明度，形成中性灰整行底色；
- 圆角 8px；
- 标题、摘要和时间保持普通状态的前景色层级，不反白、不变色；
- 头像不增加圆环或额外描边；
- 不使用阴影、渐变、左侧色条或主题色实底；
- 整行只保留一个选中信号，不叠加第二种强调方式。

### 7.4 键盘焦点

- 焦点轮廓使用现有 `--ring` Token；
- 焦点状态不能只依靠背景颜色；
- 会话行应保留明确的可访问名称和当前项状态。

## 8. 未读与任务状态

### 8.1 未读

- 头像右上角显示 8px 红点；
- 标题由 Medium 切换为 Semibold；
- 摘要、时间和行背景不改变；
- 用户进入会话后立即清除该会话未读状态；
- 导航栏未读数只统计真实未读会话。

没有阅读记录的历史会话由 Gateway 在侧边栏状态升级时一次性初始化为已读，不能由前端在每次启动时批量补写。

迁移规则：

1. 用户升级后第一次读取侧边栏状态时，Gateway 获取全部现有会话的当前 `previewAt`；
2. 对缺少阅读记录的现有会话写入 `last_read_at_by_key[sessionKey] = previewAt`；
3. 在返回状态前持久化新的侧边栏状态版本；
4. 迁移只执行一次，升级前的现有会话统一视为已读；
5. 迁移完成后到达的新 Agent 消息正常产生未读；
6. 前端只在用户实际查看会话时向前推进该会话的阅读时间，不得使用本地当前时间覆盖服务端消息时间。

Gateway 已有迁移入口位于 `mona/webui/sidebar_state.py`。由于不完整的 v3 迁移已经进入当前代码，本次统一升级到 `schema_version = 4`：保留已有阅读记录，只为缺失键补种当前 `previewAt`。不能在相同版本下反复补种阅读记录。

### 8.2 任务状态

| 状态 | 展示方式 |
|---|---|
| 执行中 | 主题色旋转图标 + “正在执行” |
| 等待确认 | 黄色提示图标 + “等待你确认” |
| 执行失败 | 红色错误图标 + 失败摘要 |
| 已计划 | 时钟图标 + 计划执行时间 |
| 已完成 | 显示最终消息摘要，不保留永久状态图标 |
| 普通消息 | 只显示消息摘要 |

任务状态确认从现有行尾移动到第二行摘要区域。第一行右侧只保留时间，删除状态图标的行尾空白占位。

```text
[头像] 会话标题                         时间
       [状态图标] 状态文字 · 最新摘要
```

状态存在时显示“图标 + 状态文字”；后面仍有有效摘要时使用 `·` 分隔。任务状态不增加第三行，也不使用未读红点表达。

## 9. 摘要处理规则

摘要采用“Gateway 负责语义、前端负责显示”的职责划分，不修改会话存储格式，也不要求重写历史会话。

### 9.1 Gateway 责任

Gateway 继续作为摘要语义的唯一来源：

- 选择最后一条用户可见消息；
- 排除系统提示、工具调用、推理过程和内部执行日志；
- 将附件转换为图片、文件、报告等语义摘要；
- 返回 `preview`、`previewAt`、作者类型、作者 ID 和消息类型。

现有实现位于 `mona/session/manager.py`，本次不改变 `ui_summary` 存储结构。

### 9.2 前端责任

前端新增一个共享的纯展示格式化函数，会话列表与会话搜索共同复用：

- 去除 Markdown 粗体、标题、列表、引用和代码围栏等符号；
- 合并换行和连续空格；
- 去除仍可能残留的展示噪声；
- 不自动增加表示任务状态的 Emoji；
- 最终结果限制为单行，超出可用宽度后省略。

协作房间的发言者前缀根据 Gateway 返回的作者信息在前端组合。存量 `preview` 直接在渲染时经过同一函数，无需刷新、回写或迁移缓存。

## 10. 现有列表视图设置

新的会话列表使用唯一、稳定的视觉结构，以下四个旧设置不再影响列表：

- `density`：行高固定为 64px；
- `show_previews`：摘要固定显示；
- `show_timestamps`：时间固定显示；
- `sort`：固定按最近有效活动时间倒序。

处置要求：

- 删除设置页、侧边栏或菜单中仍存在的对应入口；
- 删除 `ChatList` 和 `SessionListPanel` 中对应参数透传及条件分支；
- 服务端和类型层可以继续兼容读取旧字段，避免为本次局部改造增加侧边栏状态迁移，但前端不得继续消费；
- `show_archived` 不在废弃范围内，继续保留；
- 项目折叠状态、置顶、归档和用户重命名继续保留。

## 11. 时间格式

| 时间范围 | 显示格式 |
|---|---|
| 1 小时内 | `12分钟前` |
| 今天 | `14:30` |
| 昨天 | `昨天` |
| 7 天内 | `星期三` |
| 当年更早 | `7/30` |
| 跨年 | `2025/12/31` |

同一时间只能匹配一条规则，禁止混用“5天前”“上周”“2周前”等不同粒度。

## 12. 响应式要求

- 桌面端列表宽度为 280px，大屏为 288px；基础窄布局保持 260px；
- 小于 1024px 时继续使用会话抽屉；
- 抽屉复用桌面端的工具栏、会话行和全部展示规则；
- 不维护两套会话列表实现；
- 面板宽度变化时只允许标题和摘要缩短，头像、时间和状态图标不得压缩。

## 13. 明确不做

- 不增加新的会话分类栏或标签页；
- 不增加卡片阴影、彩色类型标签或装饰性渐变；
- 不复制企业微信的具体品牌色；选中态使用现有语义色生成中性灰背景；
- 不新增免打扰等现有范围之外的会话管理功能；置顶、归档、重命名和删除沿用已有能力；
- 不修改多 Agent 架构、会话存储格式和记忆机制；
- 不为本次局部改造引入新的 UI 依赖；
- 不生成独立位图素材，头像沿用 Agent 资产，功能状态使用现有矢量图标。

## 14. 验收标准

- [ ] 搜索工具栏高度、间距和创建按钮符合本方案；
- [ ] 列表中不再显示无意义的“会话”分组标题；
- [ ] 项目分组及组级操作完整保留，项目组内会话使用新的 64px 行结构；
- [ ] 置顶、默认会话、项目分组和归档按照规定顺序显示且不存在重复会话；
- [ ] 所有会话行使用相同的 64px 两行结构和 40px 圆角方形头像；
- [ ] Mona 任务优先显示任务主题，不连续出现多个“Mona”标题；
- [ ] 私聊摘要不重复显示“Mona ·”或 Agent 名称，房间摘要保留最后发言者；
- [ ] 专业 Agent 私聊和协作房间能够通过头像、标题和摘要区分；
- [ ] 摘要不包含原始 Markdown、换行和内部执行信息；
- [ ] 未读、任务状态和选中状态能够独立表达；
- [ ] 任务状态位于第二行摘要区，第一行右侧只显示时间；
- [ ] 已完成任务不保留永久状态图标；
- [ ] 时间格式统一，标题、时间和摘要不会互相覆盖；
- [ ] `density`、`show_previews`、`show_timestamps` 和 `sort` 不再存在可操作入口或影响渲染；
- [ ] `show_archived`、项目折叠、置顶、归档和用户重命名继续有效；
- [ ] 历史会话阅读记录由 Gateway 通过新 schema 版本只初始化一次；
- [ ] 存量摘要无需回写即可获得与新会话一致的前端清洗效果；
