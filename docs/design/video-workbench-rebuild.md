# Mona 视频工作台整体改造方案

> 2026-10-24 更新：创作资源与运行时已统一为 Mona Motion。本文涉及 Dashi、旧 huashu-art-motion 或 Remotion 的实现说明仅保留为历史记录；当前边界以 docs/architecture/module-invariants.md 和 docs/plans/video-huashu-motion-replacement.md 为准。
日期：2026-10-15。状态：核心改造已实施，两类本地创作、局部修改与有声导出验收完成；范围与限制见 [验收记录](../plans/video-workbench-rebuild-acceptance-20261015.md)。

目标是让普通用户通过内容、导演方案和自然语言修改，获得可交付的视频。知识讲解与产品展示同等重要，由 Mona 根据内容选择表达方式。成片必须用动画、真实素材和声音表达内容，并让修改、等待和失败都有清楚的结果。

## 产品边界

Mona 提供风格、横竖屏等基本设置、素材、导演台、预览和交付。交互任务先确认导演方案，再开始制作；生成后的画面、镜头和字幕通过自然语言修改。播放、时间定位、试音与版本回退继续提供直接操作入口。

2026-10-27 增加主会话自动制作：普通会话里的完整制作请求默认由 Mona 通过同一视频服务创建绑定项目，保留实际制作要求作为当前任务授权，准备并批准当前方案后持续制作、审片、导出，最后在原会话交付文件。工作台可用于观察和调整，不是执行前提；工作台创建及明确要求先审方案的任务保留导演确认。不要求用户使用特定的自动化措辞，不新增界面开关或另一套创作流程。

自动授权限定到当前项目和会话，切换会话须撤销，不能被复制或重绑隐式继承。项目计划仍递增修订号并保留 `requirePlanApproval`，只有授权范围内的新版本由服务自动批准，不能通过关闭批准标志跳过过期检查。未知写入先核对结果，不重复创建或导出。

普通会话继续使用自己的工作区和聊天入口。视频项目的会话关联表示归属，不代表会话类型；导航和模型设置以 Gateway 保存的会话身份为准，不能因为视频项目或恢复的工作台标签而把普通聊天转成专用视频会话。视频工具负责受控草稿传入、来源及样例副本和成品回传，预览与导出继续使用同一受管理运行时与声音轨，不依赖工作台页面挂载。

重新进入会话时使用实际运行状态，不把历史过程记录当作未完成任务。请求在入队前被拒绝时明确反馈并解除本次等待，保留未发送成功的内容；不能让输入框持续显示停止按钮，也不能用旧任务的状态覆盖新请求。

风格是色板、字体、画法、材质与运动语言。内置风格帮助开始创作，也支持用户的参考图和描述；风格数量不限制 AI 可设计的画面。工作台控件遵守 Mona UI 规范，成片拥有独立的视觉风格。

自定义风格的创建、真实动画样片、自然语言调整、保存复用及 UI 验收见 [自定义风格创作方案](video-custom-style-authoring.md)。该方案为后续实施设计，不纳入本页已完成能力声明。

整体改造包含项目状态、确认与修改规则、时间线与声音、Agent 创作和审片工具、工作台 UI。沿用已验证的 Remotion 沙盒、TTS、鉴权、运行时管理和项目保存能力。模块内部可以重构，通用会话、模型和系统下载器保持既有所有权。

## 当前实现与改造重点

| 当前代码依据 | 当前能力或缺口 | 改造方向 |
|---|---|---|
| `VideoMakerView.tsx`、`StoryboardPhase.tsx` | 已有导演台与一次确认，但创建、方案、制作的交互和状态分散 | 以同一工作台组织方案与结果，固定主要操作和状态位置 |
| `video_director.py`、`video.py` | 已有自由 TSX、真实画面反馈；Agent 无法指定任意审片时刻 | 支持指定时间审片，并区分局部观察与完整片段检查 |
| `server.py` 视频预览、混音和导出 | 导出支持旁白与音乐，预览主要使用旁白；附加声音契约缺失 | 统一声音编排与预览、导出的输入 |
| `planRevision`、场景编号、源码和声音缓存 | 已有确认、版本和输入冻结，但修改影响与确认范围仍较粗 | 明确内容批准、实施版本和派生产物；只失效受影响内容 |
| `mona-motion`、Huashu 库 | 已有创作知识和运行能力；尚无 Dashi 集成 | 复制 Dashi 源码资源、薄适配，并按内容读取知识 |

此前单个开场样例已验证真实配音、播放和 MP4 输出。整体质量还需要跨内容、跨画幅及修改过程的验收。

## 用户流程与 UI

1. **开始**：用户输入主题、资料或网址，添加素材。Mona 根据上下文推荐风格和表达方式，用户可调整比例、声音及字幕。使用已有声音设置，不把试音变为强制步骤。
2. **准备方案**：逐步显示已整理的片段和真实准备状态。资料不足时只询问影响制作的关键问题；不让空白预览承担所有等待反馈。
3. **导演台**：左侧选择片段；中央显示标题、旁白、画面、画面如何变化、素材和时长；右侧为可收起的制作对话。确认前允许直接调整方案，主要动作只有“确认并制作”。
4. **制作**：保留方案、已完成片段和制作状态。用户可离开再回来、暂停或补充要求；已完成内容不会因后续失败消失。
5. **预览修改**：中央播放视频，底部时间线负责定位。片段和时间位置随修改请求进入上下文，用户可说“这里停久一点”“第 3 段换成真实界面”。新结果提供版本回退。
6. **导出**：对当前版本导出带声音 MP4，按需要提供字幕和封面。导出过程中的修改不会改变正在输出的快照，旧版本导出完成也不会冒充最新结果。

方案与预览是同一项目的两个视图。生成后仍能阅读导演方案，内容修改由 Mona 执行。主要工作区保持稳定，避免在弹窗、聊天和多个阶段页面之间寻找同一内容。

工具栏和底部动作使用共享组件的紧凑尺寸；没有额外副标题、无意义大按钮或重复入口。分栏使用共享可拖动分隔线。滑块沿用共享信息色 Token；视频风格的颜色不进入控件。素材、声音和风格放在与当前内容相关的位置，详细设置渐进展示。

## 确认、修改和状态

交互任务的首次整片制作以导演台确认的内容版本为依据；自动任务以明确授权下服务批准的当前版本为依据。明确的局部自然语言指令授权其指定范围的修改；交互任务涉及主题、主要内容结构或整体方向的重新创作，先展示新版方案。仅修改实现代码、声音、语速或素材文件绑定，不反复要求确认整片。

实施时核对请求基线，记录用户要求、目标片段、时间位置和修改范围。模糊的反馈由 Mona 结合已确认内容提出并执行合理局部调整；需要实质取舍时才追问。请求期间发生其他编辑，过期结果不能覆盖较新内容。

内容、素材、声音与源码分别保留输入版本。片段采用稳定身份，顺序和显示编号可改变；迁移前仍核验编号对应的内容，不能把旧配音或审片结果套给另一个片段。

| 改动 | 需要更新的结果 |
|---|---|
| 某段动画、构图或画面文字 | 该段画面与审片、整片导出 |
| 某段旁白 | 该段声音、字幕、时间编排与画面审片、整片导出 |
| 声音或语速 | 受影响声音与时间编排、画面审片、整片导出，保留导演内容确认 |
| 配乐或音效 | 受影响混音、声音审查与导出 |
| 替换素材 | 引用该素材的片段及其审片、导出 |
| 顺序或整体风格 | 受影响片段及衔接、全片检查与导出 |

项目内容与任务结果由 Services 持久保存；实际 Agent 执行状态归 Gateway。前端通过现有跨进程契约关联任务，不根据聊天文案猜状态。状态至少区分方案准备、等待确认、制作、检查、可预览、导出，以及暂停、失败和结果待核对；部分片段可预览与整片仍在制作可以同时成立。

已知步骤显示数量，未知时长显示当前动作和最后进展。超时与中断先核对已经产生的结果再继续，不重复派发结果未知的写入。错误使用现有弹窗，说明操作、影响和下一步；技术诊断保留在日志和详情中。

## 创作与 Agent 能力

使用 Mona 现有完整执行循环和视频能力，保留当前授权边界。创作入口保持轻量，只加载当前任务需要的风格、画法、素材和 API，不把所有参考资料放入每一轮提示词。

导演方案先说明观众应该理解什么，再描述对象、动作与前后状态。讲解中保留对象身份和因果关系，产品展示采用真实界面或经核验的素材，数据变化必须对应其真实关系。角色、镜头和效果按内容需要设计。

确认后先准备真实旁白或节拍依据，再实现运动。动画可以使用 React、SVG、Canvas，以及已集成的绘制和转场代码；实现不受固定布局或场景类型菜单限制。用户指定的时长与内容冲突时提出具体取舍，不截断声音或用重复停图填时间。

审片工具支持指定时刻，返回实际画面、声音时间、执行错误和可定位的问题。局部截图不证明整片连续性；需检查动作起止、跨段衔接和有声播放。独立审查可复用现有委派能力，在明确输入范围内评价表达、动作、可读性和声画关系。

自动检查负责发现错误、缺素材、字幕遮挡、静音、异常停顿和时序问题。画面差异与光流作为观察依据，不以固定运动量、镜头数、转场数或持续背景动效认证质量。

## Dashi 复制与适配

采用 [dashi-animationstyle](https://github.com/chuspeeism/dashi-animationstyle/tree/aa620f3b859aa5d191b783b2eb0fb59263731c76) 的固定版本 `aa620f3b859aa5d191b783b2eb0fb59263731c76`。代码与文档按 [MIT](https://github.com/chuspeeism/dashi-animationstyle/blob/aa620f3b859aa5d191b783b2eb0fb59263731c76/LICENSE) 保留版权声明；作者示例声音不进入 Mona 资源和成片。

先复制原文件，记录路径和哈希，再做有明确目的的适配。已有的绘图、运动、材质和场景代码直接复用，不根据截图或文字描述重新实现同一效果。原稿保持可追溯，修改记录注明接口和平台差异。

| 上游内容 | 复制与使用方式 |
|---|---|
| `styles/` | 完整保留风格卡、模板、示例及静帧，以原模板绘制底座和场景函数为改稿基线 |
| `knowledge/` | 原样保留创作知识及标准、实测、经验标记，Mona 入口说明适用范围 |
| `pipeline/动效部件.js` | 直接复制数学、绘制和动效代码，薄适配模块导出、画布、时间与字体接口 |
| 其余 `pipeline/` | 保留可复用源码和来源；采用需要的算法，不启动第二套安装、配音或渲染服务 |
| `examples/token/` 的非音频文件 | 保存为完整讲解实现参考，制作新内容时改分镜、对象和动作 |
| `docs/` 动图 | 保留作动态风格参考，按打包体积选择工作台实际使用的预览资源 |
| 作者口播、Mac 字体及安装约定 | 作者口播排除；字体接入 Mona 已有管理，安装步骤不进入用户制作流程 |

该快照包含 7 套完整模板和另一套没有通用模板的风格实验，后者不冒充已验证的完整风格。上游验证范围主要是 Mac、单一模型和短横屏讲解，Windows、竖屏、多段及 Mona 模型需重新验收。[上游范围](https://github.com/chuspeeism/dashi-animationstyle/blob/aa620f3b859aa5d191b783b2eb0fb59263731c76/README.md)

资源进入 `mona/skills/mona-motion/assets/dashi-animationstyle/`；运行适配进入 `webui/video-runtime/dashi/`，随现有运行资源构建交付。Dashi 的秒级 `render/seek` 与 `cue/mark` 接到 Remotion 帧时钟和 Mona 真实旁白数据；无独立时钟和外部素材加载。色板与画法保持源风格，字体、换行和构图按实际画幅调整。

[Wattter](https://github.com/WaterDJiang/Wattter_openSkills/tree/main/wattter_skills/wtt-code-animation-studio) 用作流程参考；不把其未明确授权的代码复制进 Mona。[Shotcraft](https://github.com/Vincentwei1021/video-shotcraft) 补充产品素材、镜头和声音知识，资源按各自授权核对；Huashu 已有库继续提供讲解和艺术表达能力。所有资料由 Mona 统一入口按任务读取。

## 时间线、声音与素材

建立由项目输入计算的统一时间编排，预览与导出使用相同片段时长、转场、字幕与声音。真实配音覆盖估时，视觉动作和阅读停留也参与时长判断；所有起止使用明确的秒或帧，不维持互相独立的多份手填时间表。

声音统一包含旁白、可选音乐、动作音效及授权源视频声音。时间定位、暂停和重播同步所有轨道，旁白需要清楚可听，按需降低音乐。修改声音不覆盖旧结果；合成失败不能把静音片当作带声音完成。

素材需求进入导演方案。用户确认的是素材用途和内容，生成或导入后的文件绑定属于实现；素材生成、取材与替换沿用当前工具授权和来源记录。复用已有图片生成和浏览器能力，补齐视频项目绑定与局部更新，不另建功能专用下载器。

## 模块职责与实施顺序

| 模块 | 改造职责 |
|---|---|
| `mona-motion`、`video_soul.md`、视频上下文 | 统一创作入口、Dashi 资料索引、按内容选法、自然语言局部修改 |
| `mona/agent/tools/video.py`、`mona/api/video_director.py` | 确认和基线校验、局部实施、指定时刻审片、结果回执 |
| `mona/api/server.py` 中视频业务及必要视频模块 | 项目、版本、失效范围、时间和声音编排；只提取具有真实职责的逻辑 |
| `webui/video-runtime/`、构建与打包 | Dashi 源码薄适配、确定性帧、授权素材、许可交付 |
| `VideoMakerView.tsx`、`StoryboardPhase.tsx`、`ProducingPhase.tsx` | 同一工作台、真实状态、紧凑交互、时间定位与修改反馈 |
| 稳定架构与 UI 文档 | 新行为实现并验证后同步确认、声音和工作台约束 |

按以下顺序实施，每一步产物进入同一条最终主路径：

1. 复制 Dashi 资源并接入运行适配，扩展精确审片工具，建立可运行基础。
2. 重构确认与局部修改契约、声音与结果状态，使预览、制作和导出一致。
3. 按新契约整理工作台 UI、自然语言定位和版本反馈，替换旧交互入口。
4. 运行真实创作与修改验收，根据实际画面修正创作入口及适配问题。
5. 核对引用和旧项目，删除已被替代的代码，完成稳定文档和打包检查。

不新增通用 DAG、第二套编辑器、多个制作模式或多个默认渲染服务。需要更换实现时直接替换模块主路径；必要兼容只服务已有项目数据。

## 旧项目与删除规则

保留现有工程、已导出作品、声音、素材和版本历史。迁移先核对内容和输入版本，再处理受影响部分；旧静态场景保留必要读取能力，新创作进入自由动画路径。旧项目修改不能按显示编号误用其他片段的资源。

删除前检查 Git 状态、精确引用、数据读取和打包依赖。无引用的旧按钮、阶段组件、固定场景生成入口、重复资源加载与提示词在替换后删除；仍承载旧用户数据读取或当前渲染的代码不被当作弃用代码直接删掉。

## 验收标准

创作验收固定使用 **GPT 6.1 Sol，推理强度高**（`gpt-6.1-sol` / `high`），通过测试项目参数设置，不改变用户默认模型配置。

| 验收任务 | 观察要求 |
|---|---|
| 知识讲解 | 对象实际变化，机制和因果对应口播，字幕清楚，横竖屏均可读 |
| 产品展示 | 真实素材与操作结果、清楚的镜头重点、合适的声音及节奏 |
| 多段与数据变化 | 对象身份、数据关系、时长和跨段衔接一致 |
| 自然语言修改 | 指定片段和时间的要求被执行，未涉及内容保持，版本可回退 |
| 失败与恢复 | 配音、素材、制作、导出失败都保留成果；暂停和结果未知可核对恢复 |

对照直接 Remotion 创作、当前 Mona 和改造后 Mona，使用相同模型、内容、素材、规格与预算。评价内容表达、动画作用、可读性、风格一致、声音与修改效率，记录实际成片、问题、迭代次数和时间。量化运动不替代真实观感，也不预先承诺分数。

必要工程检查覆盖复制清单与许可证、随机跳帧、字幕与音画同步、预览导出一致、局部失效、过期修改、进度和恢复契约。运行相关前后端测试、类型检查、Ruff、运行资源构建和真实 MP4 检查；不把单个样例或窄测试称为整体质量认证。
