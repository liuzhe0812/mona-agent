- 日期：2026-10-21
- 状态：产品方向已确认；统一策略库、宿主与原生接入已实现，运行包已安装，隔离浏览器流程已验收。实现记录见第10节。
- 覆盖：机会选股内的策略展示、自然语言创建/修改、策略选股、回测与对应历史。
- 依据：[上游策略源码盘点](stock-vibe-strategy-source-inventory.md)、[股票开发标准](../architecture/stock-module-development-standard.md)、[Vibe 宿主边界](../architecture/stock-vibe-integration.md)、[UI 规范](mona-ui-design-system.md)。

## 1. 产品决定

机会选股只有一个策略库。内置与用户生成的策略共享详情、参数、选股和回测的使用流程，来源通过“内置 / 自定义”标签区分；选股和回测按真实资产与接口能力开放。内置策略不允许AI修改或删除，自定义策略允许AI修改及删除。小白从已有策略开始；懂的用户通过自然语言创建、组合或修改自定义策略，产物自动回到这个库。

取消当前“AI选股 / 策略研发”双入口，以及“新建研发 / 我的方法”的第二套使用路径。量化、因子、机器学习、行业轮动等研究能力由 AI 按任务调用；不再作为要求普通用户先选择的四张策略卡。

股票一级导航保持“投资工作台 / 机会选股 / 账户与复盘”。本次不增加策略商城、评级推荐、实盘交易、自动调参或定时执行。

“全部展示”指完整列出上游有来源、明确规则的策略和示例，以及用户已有资产；实际能否执行按该条目的接口、市场、数据与依赖判断。存在源代码、示例身份、能执行、有历史回测分别说明。数据或接口未适配的策略仍可查到，具体操作解释缺项。

## 3. 界面结构

### 3.1 一个列表、一个工作区

左侧为策略列表，右侧为选中策略的工作区。默认恢复上次选择；第一次进入选择当前环境可执行的内置策略。内置列表、说明、规则与策略参数随版本固定打包，在首次渲染直接显示，浏览时不请求原生目录/详情。自定义策略独立异步读取，不能阻塞已有内置内容。查看目录不调用模型、不生成代码、不开始选股或回测。

| 区域 | 内容与操作 |
| --- | --- |
| 页面工具栏 | “策略库”标题、搜索、“用 AI 创建策略”、历史入口 |
| 列表筛选 | 来源“全部 / 内置 / 自定义”；市场默认当前市场，可选“全部市场”看到完整目录 |
| 策略条目 | 名称、来源、示例身份、适用资产/周期、影响使用的状态；选中态明确 |
| 策略标题 | 名称、来源、当前版本；一句话说明规则；“用 AI 修改”文字动作 |
| 工作区页签 | **选股 / 回测 / 规则**，切换只读恢复对应内容，不创建新任务 |
| 历史 | 当前策略的选股与回测记录在同一历史浮窗，保留“全部策略”范围切换；记录明确类型 |

列表采用紧凑行式布局，避免策略卡片墙。条目多时滚动/分页展示完整目录，不做“精选几种”截断。内置搜索与筛选立即在随包数据上完成，自定义查询保留输入防抖。两类按同一分页规则合并，动态部分未返回时不把已有内置内容替换成加载页。

目录按策略身份聚合，版本和每次运行进入该策略的详情/历史。重复回测不创建新的同名策略行；内置示例的运行副本仍关联内置来源，只有用户主动保存改动时创建自定义条目。SDM 的因子类型不进入成品策略列表。

来源与状态分开：内置示例不因标签变成经过效果验证的策略；自定义也不因来源不同而多一道使用步骤。常用操作保持可见，技术源码、详细证据和长说明通过现有信息浮窗按需查看。

### 3.2 选股页签

股票范围位于策略工作区页签上方，由选股与回测共用，提供“全A股 / 行业 / 我的自选”，默认全A股。行业支持搜索并选择具体行业；空自选提供前往工作台添加的动作，不自动切换范围。选股表单保留“数据截止”、已支持的策略参数入口及“开始选股”。当前决定取代早先将策略保存样本作为范围的交互，具体实现见第12节。

日期默认“最近完整交易日”，由数据实际覆盖决定并显示具体时间。当前方案先支持原策略已支持的数据频率；工作台的“超短线”等页面偏好不重写策略自身的日线、20 日观察或调仓规则。

用户点击“开始选股”后，运行已选策略的固定版本。普通规则策略计算不需要配置研究模型，不为每次选股重新调用 AI 发明规则。

| 显示项 | 来源与含义 |
| --- | --- |
| 股票与信号日期 | 本次真实策略输出和证券身份 |
| 目标权重/方向 | 原生信号或目标头寸；仅在原策略提供时展示，不转成上涨概率 |
| 入选依据 | 实际保存的规则命中、因子值或贡献；仅有目标权重时展示规则说明，不补造逐股评分 |
| 数据与生效时点 | 截止时间、来源、信号产生时间、预期生效时点、缺数/跳过范围 |
| 下一步 | 看行情、加自选、询问 AI；均携带策略版本和本次选股来源 |

没有信号时明确显示“本次没有符合规则的股票”。缺字段导致无法计算与确实没有信号使用不同状态。只展示各自实际可计算的范围，不以补零代替缺行情。

正目标权重表示策略期望持有，不等于已成交或立即买入；负信号按原生资产/市场含义显示。多空配对、期权腿等策略保留真实输出类型，不能在普通 A 股界面悄悄裁掉空头或合约腿，改变策略后继续沿用原名称与绩效。

### 3.3 回测页签

始终继承当前策略和版本，取消回测内部再次选择另一套策略的下拉。股票范围及适用配置可从当前选股带入，用户确认本次日期、资金、费用等配置后运行原生回测。

基本项常显；费用、仓位及原生统计检验通过设置入口进入现有弹窗。策略参数只暴露对应策略真实接受的项；未提供参数描述的策略通过“用 AI 修改”生成新版本，不伪装为通用参数修改。

回测完成后，在本页显示原生净值、核心指标和记录。交易、持仓、费用、样本外检验、代码及完整报告沿现有原生报告组件按需查看。选股结果与回测结果在同一策略上下文中，但保留各自日期、范围、配置和数据口径。

回测只说明该版本在该配置下的历史运行结果。“尚未回测”“已回测”和真实的检验记录分别展示，不合成“有效”“稳健”“推荐”等无来源结论。

新运行沿原生持久任务保存策略关联并查询历史，不在前端先取少量报告再冒称完整策略历史。旧原生 Reports 当前最多返回最近 100 条且没有 offset，兼容读取须如实标明范围；完整新目录的承诺不能被误写为已经支持全部旧报告。

### 3.4 规则页签

展示策略要做什么、输入范围、信号/选股规则、退出/调仓规则、参数、适用资产、数据要求及真实限制。内容以源码、显式参数和已保存说明为依据；未保存的信息显示缺项。

长研究报告、因子诊断、来源代码和完整证据通过信息浮窗查看，避免用页内折叠堆成长说明。“用 AI 修改”只对未删除的自定义策略开放；内置策略不提供该入口，服务端同时限制修改来源。

### 3.5 用 AI 创建或修改

复用现有股票研究对话和原生 Session，不新造聊天系统或固定四选一研发向导。创建入口位于策略库工具栏，修改入口只位于自定义策略详情。

| 阶段 | 用户看到什么 | 系统真实动作 |
| --- | --- | --- |
| 描述 | 自然语言输入；修改已有自定义策略时自动带入来源 | 绑定会话、自定义策略版本和当前资产上下文 |
| 补充 | 只询问影响策略定义、市场可用性或执行的缺项 | AI 读取原生技能、目录、数据能力和用户已有规则 |
| 生成 | 实际任务进度与规则摘要 | 调用原生代码生成/写文件，形成配置与可执行策略文件 |
| 入库 | 对话内出现可打开的策略结果，列表出现“自定义”条目 | 服务端根据真实产物核对归属、代码/配置、接口及来源后登记 |
| 使用 | “查看策略”；选股、回测仍是统一工作区的动作 | 自动定位新策略；如用户同时明确要求回测，沿同一策略版本运行并关联结果 |

用户明确要求生成策略即授权保存生成产物，不增加“审批 / 发布 / 激活”步骤。生成失败保留对话与已有产物；只有研究文字时保留为待补全档案，不能出现可运行成功状态。

示例对话：“把我的低波动策略的持股数改为 5，换股间隔改为 10 个交易日。”AI 沿真实可调参数修改并登记；新版本不继承源策略的回测结果。

对更自由的需求，如组合动量、低波动、财务条件或机器学习，AI 可复用原生因子、组合器和模型模板。数据可得性、训练截止、模型产物及推理版本必须落在具体策略中。选股时使用固定模型/代码，不在后台静默重训或修改权重；确需重新训练的原生策略要如实说明执行动作和成本。

## 4. 两条用户路径

### 小白直接使用

进入机会选股 → 选择内置策略 → 看一句话规则与数据要求 → 选择股票范围 → 开始选股 → 查看候选和依据 → 切到回测看历史表现。

缺数据只影响当前操作，给出配置数据或更换范围的实际动作；可执行的内置策略不要求先配置研究模型，也不要求先做一次研发。

### 懂的用户创建/改进

用 AI 创建策略，或选择已有自定义策略后用 AI 修改 → 自然语言说明 → 必要时补条件 → 原生产物登记到同一目录 → 选择新版本 → 按同一流程选股、回测、查看记录。

参数临时修改只进入本次运行快照；自定义策略需要长期修改时通过AI生成并保存新版本。旧代码、参数和历史结果保留原身份，不覆盖原策略。

## 5. 业务对象与事实来源

不在 Mona 建第二套金融策略数据库。Vibe 继续拥有策略、会话、代码、模型、选股运行和回测结果；Mona 保存请求关联及显示偏好。

| 对象 | 最少职责 |
| --- | --- |
| 内置来源目录 | 构建时固定上游路径、源码摘要、入口类、说明、资产类型、参数描述、必要依赖；只提供来源，不能把所有条目预先标记为可运行 |
| 策略资产 | 延用原生 SDM 身份/登记与版本来源；可关联内置来源或用户 Session；研究档案与执行产物分别存在 |
| 执行版本 | 关联已核对的策略代码、配置、模型文件与各自摘要；选择和回测都固定此版本 |
| 选股运行 | 固定策略版本、股票池快照、参数、行情快照、信号/生效时间、原生结果与证据 |
| 回测运行 | 延用原生 run 与配置/代码、净值/交易等产物；关联同一执行版本和本次配置 |

这是逻辑职责设计，不宣称当前 SDM 已具备全部字段，也不在设计阶段虚构已存在的 API schema。开发时在原生对象上补最少关联，沿真实契约同步生产端与调用端。

### 独立呈现的三类事实

1. 来源：内置 / 自定义；内置示例额外标“示例”。
2. 可执行条件：代码已就绪、规则待补全、缺少某项数据/依赖、不适用当前资产或实现待修正。
3. 历史证据：未回测、已有对应版本的回测，以及实际保存的独立检验。

存在一条 SDM 摘要、有一次聊天“完成”、存在旧代码的回测，都不能替代当前版本的可执行条件或证据。

## 6. 最小实现方式

### 6.1 目录与内置实例化

在 Vibe 受管补丁中扩展当前只支持多因子示例的固定目录，逐项列出[盘点表](stock-vibe-strategy-source-inventory.md)中的来源。目录只允许受控来源与入口类，不接受前端提交任意文件路径或 Python 类。

沿现有示例实例化方式，将所选来源复制到新运行目录、保留源文摘要、剥离明确的演示执行段，并核对实际策略定义。期权的五个入口要绑定各自原生类，不能全部落到默认铁鹰别名。ML 文档代码块的提取要固定区段/摘要，不能由模型临时重写成另一套“内置算法”。

先按原生运行器检查接口、依赖与配置再给出该操作是否可用。跨市场双均线已有明确全窗口波动率前视问题；配对策略依赖多空语义；期权使用合成定价。这些逐项写入限制，修正需要独立版本与真实验证，不默默改成 A 股只做多后沿用旧证据。

### 6.2 自定义策略登记

复用原生 Session、`strategy-generate`、`write_file`、SDM 和已有运行档案。当前“保存方法”依赖模型后续执行登记，新流程需让服务端依据已完成的工具回执与产物建立执行版本关联，并通过结构化结果把条目返回 UI。

登记接口/数据能力是本次获授权的产品接入，不能把它写成原生已自动贯通的能力。无策略代码的旧研究档案保留“待补全”，点继续完善回到原会话。

原生 `adapt_strategy` 仅允许受限的名称、证券池及仓位说明变更，不能承担任意信号/买卖规则修改。用户改变规则时沿生成与登记创建新策略/版本，保留 `derived_from`，不放宽原生 adaptation 的证据约束。现有 attempt 完成后的目录重读链可复用；入库成功仍以真实登记回执为准。

现有无股票的策略复用还存在合同断点：`CreateSession.one_context` 要求 `native_research` 必须伴随 `workbench`，而 `StockVibeView` 的方法复用传入 `symbol: null`。应允许独立策略来源的 Session，保留与成交复盘等上下文的互斥，并同步调整 `api.py` 中来源配置的写入条件。只修改按钮无法贯通该路径。

策略来源引用需覆盖实际内置目录身份，不能把内置条目伪装成 `alpha_zoo` 因子 ID 或未经登记的 SDM ID。来源由服务端白名单解析后写入原生会话配置，前端只传受控身份。

### 6.3 同一策略用于选股与回测

回测延用原生 `BacktestTool`、行情加载、市场引擎、配置和报告；只补从策略版本到受控运行输入的解析，去掉 UI 内的第二次策略选择。

最新选股需要一个 **Vibe 侧的薄扫描操作**：解析同一个执行版本 → 取截至指定时点的原生行情及增强字段 → 调用同一个 `SignalEngine.generate` 与适用的原生信号/仓位处理 → 保存本次结果与时间语义。Mona 不实现公式、评分、优化器或收益计算。

扫描代码必须在与回测一致的受控 `Runner` 子进程运行，复用原生 AST/文件边界、超时及进程归属；不能在 API 服务进程直接 import/exec 用户或 AI 策略。第一版可执行范围沿当前已接入的 A 股日线合同；其他资产条目完整可查，扩展其运行能力需要对应真实合同和验证。

原生 `BaseEngine._align` 会把信号 `shift(1)` 后用于下一根开盘；现有 `target_positions.csv` 是已移位历史目标。因此直接读旧回测最后一行无法代表当前最新选股。开发时应在原生处理链上暴露正确阶段的快照，并明确观察时间和可生效时间，禁止把前一日执行目标改名为当日新信号。

扫描不是重新跑一次 AI 团队，也不通过启动完整资金回测冒充当前选股。对有摆动点右侧确认、模型训练或未来数据风险的示例，必须核对原生时间语义；真实实现存在缺陷的条目显示局部限制，不为整个策略库加验收开关。

### 6.4 原生能力、接入与新增职责

| 部分 | 现成能力 | 本次最少工作 |
| --- | --- | --- |

## 7. 恢复、安全与历史

- 查看目录、详情、历史和切换页签只读。任务派发使用稳定请求 ID；超时或断线先核对同一回执，结果未知时不重新运行。
- 策略代码仅由原生受管执行路径运行，不进入浏览器、Mona Gateway 或任意宿主 Shell。复用既有策略代码安全检查与进程归属；不把 AST 检查说成 OS 强沙箱。现有 Tushare 数据凭据流边界保持原义，不透传模型和券商凭据。
- 路径只能从已校验的原生对象/来源 ID 解析，并做 resolved-path 范围检查。外部 URL、附件、身份验证及统一运行时继续遵循现有边界。
- 运行中切换策略可查看其他内容；完成事件按原策略和版本更新，不覆盖当前另一个策略的结果。回测配置更改后保留旧结果及其原配置。
- 当前的选股研究记录、SDM 档案及原生回测保留。可核对代码来源的历史归到对应策略版本；无法确认归属的记录在历史里明确标为“旧研究记录 / 来源待核对”，不靠标题强行匹配，也不新造策略。
- 错误沿现有弹窗反馈，字段错误就近显示；不给用户看原始堆栈或内部进程名。不能计算、没有信号、运行失败和结果未知各有准确说明。
