# Mona 品牌与产品 UI 一体化改造提案

> 状态：讨论稿 v0.7，品牌视觉方向保留；产品价值已改为“开箱即用—长期默契—专业 Agent 团队”三层叙事，未批准，不作为实现依据  
> 日期：2026-08-20  
> 适用范围：Mona 品牌定位、口号、IP、Logo、官网与桌面端视觉关系  
> 目标：先统一品牌母体，再决定是否修订现行 UI 规范和开发计划

## 1. 文档定位

本文用于逐步讨论 Mona 的品牌与产品 UI 改造方向，不直接授权修改代码、官网或正式品牌资产。

当前权威实现依据仍是：

- [`mona-ui-design-system.md`](./mona-ui-design-system.md)；
- [`../plans/mona-ui-refactor-plan.md`](../plans/mona-ui-refactor-plan.md)。

这两份现行文档明确冻结当前新会话首页和整体配色；本提案重新打开了这些决策。只有本提案完成视觉验证并被批准后，才可以同步修订现行规范和执行计划。不得让两个相互冲突的文档同时声称具有最高优先级。

## 2. 为什么需要改造

Mona 当前存在三套没有完全统一的视觉身份：

1. **官网**：深色赛博城市、漫画拼贴、红蓝轮廓光、写实黑白猫；
2. **Logo 与桌面 IP**：圆润、卡通、玩偶感的黑白猫，蓝色大眼睛和黄色服装装饰；
3. **桌面工作区**：中性白灰／深灰表面，以蓝色作为常规操作色，整体偏通用生产力工具。

问题不是官网和桌面端必须长得一样，而是三者没有稳定共享以下品牌识别：

- 女性人形与黑猫形态之间可识别的共享基因；
- 同一个 Logo 结构；
- 同一组主次颜色关系；
- 同一种材质、线条与动效语言；
- 同一种“助手如何行动”的人格表达。

结果是用户可以分别记住官网、Logo 和产品，却不容易把它们视为同一个品牌系统。

## 3. 已确认事实与待验证事项

### 3.1 已确认事实

- 官网主视觉中的黑白猫具有蓝色眼睛、金属项圈、红蓝轮廓光和米白贴纸描边；
- 官网第一、第二屏的现有布局、交互与满屏叙事形式保持不变；本轮只优化内容和视觉资产；
- Mona 对外按闭源商业产品表达，官网不设置 GitHub 或开源共创入口；
- 当前桌面端全局 Token 以中性表面和蓝色操作色为主，浅色背景为白色，深色背景接近中性黑；
- 当前 `AgentLogo` 已经实现 `welcome`、`working`、`idle` 三种状态，以及 `scene`／`avatar` 两种使用形态；
- 现行 UI 规范把当前新会话首页定义为视觉母版，并明确“不更换整体配色”；
- 现有品牌 UI 改造不能只当作局部换色处理，它会影响现行规范的上游决策。

### 3.2 尚未确认

- 官网黑猫源文件、角色设定稿及其可编辑资产是否已归档；
- 官网黑猫是否已有正式的多角度、全身和表情设计；
- 女性人形是否已有历史设定、名称、源文件或商标约束；
- 双形态的世界观机制和对外解释深度尚未确定；本提案先以“同一身份”为设计基础；
- 当前 Logo 是否存在必须保留的商标注册或渠道投放约束；
- 桌面端未来默认使用浅色、深色，还是继续跟随系统；
- 官网与桌面端是否由同一套品牌资产发布流程管理。

以上事项在进入正式资产制作前必须确认，不能靠截图反推正式 Logo 或角色设定。

## 4. 品牌核心假设

### 4.1 一句话定义

> **Mona 是拥有女性人形与黑猫形态的 AI 工作伙伴。**

这句话是设计母题，不是对外口号。它同时约束角色、文案与产品行为：

- **女性人形**承担沟通、判断、陪伴和品牌情感；
- **黑猫形态**承担感知、后台执行、设备穿梭和小尺寸识别；
- **赛博**来自感知、连接和工具能力，而不是大面积霓虹装饰；
- **接手工作**表达 Agent 的主动执行能力；
- 两种形态是同一个 Mona，不是“女性助手带着一只宠物猫”。

### 4.2 双形态关系

双形态用于解决两个不同尺度的问题：

| 形态 | 核心职责 | 主要场景 |
|---|---|---|
| 女性人形 Mona | 建立信任、表达情绪、处理复杂沟通 | 官网主视觉、启动／欢迎、重要请示、品牌内容 |
| 黑猫形态 Mona | 快速识别、表达运行状态、进入设备和工作区 | App 图标、托盘、头像、加载、执行与完成状态 |

对外不需要讲述复杂的变形世界观。用户只需通过共同的眼睛、M 核心、颜色和动作确认“她们是同一个 Mona”。

这一区别也是与 Cindy 的关键边界：Cindy 是“女性角色＋猫”的并列组合；Mona 采用“同一角色的两种形态”。官网构图和宣传文案不得把黑猫画成女性 Mona 的普通宠物。

### 4.3 品牌性格

优先保留四项：

| 性格 | 正向表达 | 应避免 |
|---|---|---|
| 可靠 | 接住任务、汇报过程、按结果交付 | 无所不能式夸张承诺 |
| 敏锐 | 蓝眼感知、快速理解工作现场 | 监视感、侵入感 |
| 能干 | 主动操作工具并持续执行 | 只会卖萌的宠物感 |
| 有陪伴感 | 在需要时出现，语气直接温和 | 过度拟人、频繁打扰 |

“神秘、赛博、酷”只作为表现层，不得压过可靠性和可用性。

## 5. 口号与产品说明

### 5.1 当前口号判断

“工作，不该从重新解释开始”依赖用户预先理解 AI 上下文丢失问题。它适合表达记忆和连续工作能力，不适合作为第一次访问官网时的主要定位。

建议把它降为长期默契章节的文案，并改得更直接：

> 你的做法，Mona 记得。

### 5.2 主口号

> **工具用得好，下班回家早。**

这句话负责吸引和记忆。它有生活感，也能自然连接 Mona 的执行能力。为了避免被理解为普通效率软件，必须紧跟一句直接产品说明：

> 开箱就能干活，越用越懂你，还能带着专业 Agent 一起工作的日常 AI 助手。

### 5.3 产品说明建议

口号下方必须有无需推理即可理解的产品事实：

> 邮箱、笔记、日程、浏览器、终端和数据库，都在一个 Mona 里。

口号负责记忆，产品说明负责解释，两者不能由一句隐喻同时承担。

## 6. IP 角色系统

### 6.1 角色决策方向

- Mona 拥有二次元成年女性人形和黑猫形态；
- 两种形态属于同一个身份，共享人格、记忆和能力；
- 女性人形不是秘书、女仆或偶像，定位为冷静、可靠、有行动力的技术执行者；
- 黑猫形态不是宠物，定位为 Mona 在设备和后台工作中的紧凑载体；
- 角色必须通过动作和状态表达“正在工作”，不能只依靠肖像和世界观背景；
- 不再增加第三个具名角色承担助手职责。

### 6.2 共享识别特征

以下特征作为当前候选，视觉稿验证后再冻结：

- 两种形态共享高识别度蓝色猫瞳；
- 两种形态共享同一个 Mona 图形符号或金属 M 核心；
- 黑、暖白和 Mona 蓝构成稳定的主体色块关系；
- 官网品牌画面可以使用红蓝双侧轮廓光；
- 宣传插画可以使用米白贴纸描边；
- 神态冷静、警觉、可信，不做幼儿化或过度性感化表达。

轮廓光和贴纸描边属于表现手法，不是 Logo 成立的必要条件。

### 6.3 女性人形方向

首轮候选设定已经生成，用于验证以下方向，不代表正式定稿：

- 成年女性，比例和气质明确区别于幼态角色；
- 黑色齐肩发配一束暖白额发，直接映射黑猫的黑白面部色块；
- 蓝色猫瞳与黑猫形态建立直接联系；
- 黑／暖白分区的轻量技术外套或工作服；
- 颈部只保留一个青色 M 核心，不同时堆叠多套识别装置；
- 姿态以观察、操作、确认和交付为主，避免纯站姿展示；
- 不使用女仆、秘书制服、偶像服或高暴露设计表达“助手”。

候选稿见 [`mona-dual-form-character-sheet-v1.png`](../../design-assets/mona-brand-ui-v1/mona-dual-form-character-sheet-v1.png)。发型、服装和年龄感仍需评审；黑发不应与大面积红色服装绑定，以免弱化 Mona 自身的黑／暖白／青色识别。

### 6.4 黑猫形态方向

- 保留官网黑白面部色块和蓝色眼睛作为角色母版候选；
- 金属项圈／M 核心负责表达工具连接和设备身份；
- 全身和动作设计必须支持待命、执行、请示与完成，不能只有头像；
- 小尺寸版本减少毛发和光效，优先保证耳朵、眼睛和面部色块；
- 现有卡通 `AgentLogo` 的状态逻辑可以复用，但目标造型改为与官网一致的黑猫形态。

### 6.5 状态体系

保留现有 `AgentLogo` 的状态思路，扩展为产品级语义：

| 状态 | 用户含义 | 优先形态 | 建议视觉信号 |
|---|---|---|---|
| 待命 | 可以接收任务 | 黑猫／人形均可 | 注视用户，M 核心常亮 |
| 理解 | 正在读取上下文 | 黑猫 | 眼睛短暂扫描，避免长循环 |
| 执行 | 正在使用工具 | 黑猫 | M 核心／界面出现可见进度 |
| 请示 | 需要用户决定 | 女性人形 | 目光停留，动作收住，突出问题 |
| 完成 | 已交付结果 | 黑猫为主 | 明确完成动作，不使用夸张庆祝 |
| 休息 | 当前无任务 | 黑猫 | 克制呼吸或静止状态 |
| 失败 | 执行没有完成 | 女性人形或标准图标 | 保持可靠，不做滑稽摔倒 |

实现时优先复用现有状态组件接口，替换视觉资产与映射。女性人形只在大尺寸品牌表面出现，不能为每个运行状态再造一套高成本动画。

### 6.6 三级资产

| 层级 | 用途 | 复杂度 |
|---|---|---|
| A：品牌主视觉 | 官网首屏、发布海报、启动宣传 | 女性人形为主，可出现黑猫形态；完整环境与轮廓光 |
| B：产品角色插画 | 欢迎、空状态、请示、完成、更新 | 按场景选择一种形态，简化背景和动作 |
| C：识别图形 | App 图标、Logo、favicon、32–64px 头像 | 黑猫 IP 的简化栅格裁切，少细节、高对比 |

女性人形不直接缩小作为 C 级 Logo。黑猫 IP 可以作为 Logo，但必须分别输出主标、App 图标和 favicon 的栅格裁切，不能把一张大图机械缩到所有尺寸。

## 7. Logo 改造方向

### 7.1 目标

Logo 路线已经从抽象符号改为直接使用黑猫 IP。主标必须满足：

- 第一眼就是 Mona 黑猫本人，不需要解释 M、眼罩或猫眼的抽象关系；
- 使用透明 PNG／WebP，不要求 SVG 或单色版；
- 32px、64px 和大尺寸页头分别有适配裁切；
- 在浅色和深色背景上都保持耳朵、青色眼睛和黑白面部色块；
- 只保留一个青色 M 项圈核心；
- 不使用女性人形作为小尺寸 App 标识。

### 7.2 候选结构

- 主 Logo：黑猫上胸以上的三分之四头像，透明背景，暖白贴纸描边，左红右青轮廓光；
- 页头锁定：黑猫 IP 主标＋网页字体排印的 `MONA`，不把字标烘进角色图片；
- App 图标：确认主标神态后，再制作相同 IP 的方形栅格构图；
- favicon：单独生成极简猫脸裁切，保留耳朵、眼睛和黑白分区；
- `ONLINE` 不进入主 Logo，可作为官网氛围文案保留。

最终采用资产见 [`logo-candidates-v2`](../../design-assets/mona-brand-ui-v1/logo-candidates-v2/README.md)：

- C 红黑近景已确认为客户端与网页通用 Logo；
- A／B 候选及其他被否决路线已经删除，不再作为后续设计依据。

三张均为文生图栅格资产，尚未定稿。原 M／眼罩／猫眼抽象方案已进入 `rejected`，不再继续 SVG 化。

## 8. 官网与桌面端的统一原则

### 8.1 一致不等于相同

- 官网负责建立世界观、情绪和第一印象；
- 桌面端负责长时间工作、信息扫描和操作反馈；
- 两者共享双形态角色、Logo、颜色角色、线条和动效节奏；
- 两者不共享相同的视觉浓度和背景复杂度。

### 8.2 官网允许

- 城市、书房、纸张、漫画分镜等环境叙事；
- 红蓝轮廓光和贴纸化角色处理；
- 展示字体与更强的构图对比；
- 有限、可关闭的品牌动效。

### 8.3 桌面工作区避免

- 大面积背景插画和纸张纹理；
- 把红蓝轮廓光扩展为所有控件的发光边框；
- 用漫画分镜切割邮件、终端、数据库和文档正文；
- 让角色持续占据工作内容区域；
- 为品牌感引入新的 UI 依赖或第二套组件库。

## 9. 桌面端视觉方向

### 9.1 借鉴 Cindy 的原则

借鉴的是方法，不是具体皮肤：

- 品牌展示与工作界面分层；
- 使用少量语义表面和 1px 边界建立层级；
- 限制品牌色进入普通操作；
- 减少渐变、阴影和随意圆角；
- 用 Token 统一浅色与深色语义；
- 角色只进入明确的品牌和状态表面。

### 9.2 Mona 的颜色角色

精确色值在视觉样板阶段决定，本阶段只定义职责：

| 颜色角色 | 用途 | 禁止 |
|---|---|---|
| 中性黑／深蓝黑 | 深色外壳与阅读背景 | 使用纯黑压平全部层级 |
| 暖白／米白 | 浅色表面、正文和贴纸资产 | 模拟纸张纹理覆盖工作区 |
| Mona 蓝 | 焦点、链接、AI 感知与执行状态 | 同屏铺满多个主要按钮 |
| 品牌红 | 官网结构线、品牌插画强调 | 普通按钮、焦点和长期选中态 |
| 语义红 | 错误、危险、不可恢复操作 | 与品牌装饰混用 |

品牌红和语义红可以色值相近，但产品代码中必须是不同 Token，避免装饰色误导操作语义。

### 9.3 两套主题

**Mona Night**：作为品牌旗舰样板，使用深色中性层、米白文字和 Mona 蓝交互状态。品牌红只进入受控品牌表面与语义例外。

**Mona Paper**：保留高可读性的浅色工作模式，使用暖白表面、深色文字和同一套 Mona 蓝状态。

是否把 Mona Night 设为默认主题尚未决定；不得仅因官网是深色就强制桌面端默认深色。

### 9.4 形状、材质和动效

- 保留现有 8／12／16px 主要圆角层级，视觉样板证明有必要后再删减；
- 工作区优先使用平面色差和细边界，减少装饰性阴影；
- 官网可以使用轮廓光，工作区只允许在短时 Agent 状态中出现弱化反馈；
- 展示字体只用于官网、启动页和少量品牌标题；正文继续使用系统无衬线字体；
- 所有角色动画必须支持 `prefers-reduced-motion`。

### 9.5 角色出现边界

女性人形建议出现：

- 官网主视觉和品牌内容；
- 启动／登录与首次欢迎；
- 重要请示、权限说明和需要建立信任的时刻；
- 更新说明和关于页面。

黑猫形态建议出现：

- 新会话欢迎；
- Agent 待命、理解、执行和完成；
- 空状态；
- App 图标、托盘和小尺寸身份头像；
- 浏览器 AI 控制状态等需要识别 Mona 身份的位置。

不建议出现：

- 每张卡片、按钮和菜单；
- 邮件正文、数据库表格、终端输出和文档内容；
- 已经由标准状态图标表达清楚的位置。

## 10. 官网页面改造边界

> 产品价值、对外文案和第三屏以后的内容顺序，以 [`2026-08-21-mona-product-value-booklet.md`](./2026-08-21-mona-product-value-booklet.md) 为最新讨论底稿。本节只保留官网结构与视觉边界；此前按邮件、浏览器、数据库、终端逐屏介绍的方案已废止。

### 10.1 第一屏：形式冻结

保留现有满屏场景、左侧主文案、右侧任务选择菜单、下载入口和向下继续提示，不改变主要位置与交互。现有黑猫场景图已经具备可用的主体位置和左右安全区，本轮优先复用。

只允许优化：

- 主口号和产品定义；
- 任务菜单的名称与说明；
- Logo、状态文案和局部色彩细节；
- 黑猫资产的清晰度和品牌一致性。

建议直接使用：

> **工具用得好，下班回家早。**

> 开箱就能干活，越用越懂你，还能带着专业 Agent 一起工作的日常 AI 助手。

右侧五个入口改为“看她接手日常工作、看她如何越来越懂你、认识专业 Agent 团队、三分钟快速入门、更新日志”。下载按钮继续承担唯一主要转化动作，不出现 GitHub。

### 10.2 第二屏：形式冻结

保留现有室内场景、左侧角色立绘、右侧对话框和点击／空格推进机制。候选方案把左侧黑猫头像替换为女性人形 Mona，以承担沟通、判断和建立信任的职责；对话内容改为直接解释 Mona 能接手什么工作。

建议五段对话：

1. “邮箱、笔记、日程、浏览器和数据，都不用再一件件接给我。”
2. “配置好工作账号，我就能在你使用的同一个现场里直接干活。”
3. “你教过我的格式、习惯和边界，我会带到下一次。”
4. “事情复杂了，我会叫上各自擅长的 Agent 一起做。”
5. “你像聊天一样安排，我们把进度和分工留在画布上。”

候选立绘见 [`mona-human-dialogue-portrait-v2.png`](../../design-assets/mona-brand-ui-v1/mona-human-dialogue-portrait-v2.png)。

### 10.3 后续页面：围绕用户价值重构

第三屏以后可以参考 Cindy 官网的主题一致性，但只借鉴原则：

- 黑、暖白和品牌红形成稳定的大色块关系，青色仅承担 Mona 的感知和运行信号；
- 使用扁平表面、明确边框、克制圆角和编辑式非对称排版；
- 用角色、产品截图和短句交替推进内容，避免同质化卡片墙；
- 每一屏只讲一个用户结论，并提供可验证的产品证据；
- 不复制 Cindy 的角色、Logo、具体构图、文案或装饰图形。

后续页面不再使用“核心能力”“Mona 如何工作”这类抽象章节名，也不按功能模块逐页介绍。每一屏必须包含一句用户能复述的结论、一份真实产品证据和一个自然的下一步：

| 屏 | 用户结论 | 必须展示的证据 |
|---|---|---|
| 3 | **别装一堆，装个 Mona。** | 同一个真实任务跨越多个原生工作模块 |
| 4 | **你的做法，Mona 记得。** | 同类任务从首次说明到稳定复用的变化 |
| 5 | **默契不是一句“我记住了”。** | 画像、成长轨迹、工作模式及纠正入口 |
| 6 | **一个 Mona，一群行家。** | 一个完成产品化的专业多 Agent 案例 |
| 7 | **拉个群，专业 Agent 一起开工。** | IM 群聊进入画布工作流的真实运行 |
| 8 | **该她动手时动手，该你决定时停下。** | 只读、工作副本、审批与恢复 |
| 9 | **下一件日常工作，让 Mona 接手。** | 下载、完整案例和快速入门入口 |

邮件、浏览器、数据库、终端、笔记与日程只作为同一任务的证据出现，不再各自占据一个功能页。所有案例必须来自真实产品执行，不使用虚构日志或假数据。

## 11. 改造顺序

### 阶段 0：品牌决策

只讨论并批准：

1. Mona 采用女性人形／黑猫双形态；
2. 品牌更偏长期伙伴还是主动执行者；
3. 主口号方向；
4. 女性人形的职业气质、轮廓和与黑猫的共享特征；
5. 官网黑猫是否作为黑猫形态母版；
6. Logo 的图形标和字标关系；
7. Mona 蓝、品牌红和中性色的职责。

未通过阶段 0，不开始全局换色或组件改造。

### 阶段 1：最小视觉样板

只制作：

1. 官网第一屏内容与品牌资产换肤稿，结构不变；
2. 官网第二屏人形立绘与对话内容换肤稿，结构不变；
3. 官网第三屏“别装一堆，装个 Mona”的价值章节样板；
4. 桌面端一个新会话页样板，主题在 Token 讨论后确定。

所有样板使用同一 Logo 和 IP。官网前两屏不再探索替代构图；变化只发生在文案、角色资产和视觉细节。样板通过评审后再生成完整资产规范。

### 阶段 2：品牌资产包

- 黑猫 IP 主标 PNG／WebP、页头组合和深浅底测试；
- 同一 IP 的 App 图标和 favicon 栅格版本；
- 女性人形的正面、侧面、全身、轮廓和关键表情；
- 黑猫形态的正面、侧面、全身、轮廓和关键表情；
- 两种形态的共享识别特征与禁止偏差；
- 待命、理解、执行、请示、完成、休息、失败状态；
- Logo 与角色的最小尺寸和安全区；
- 官网和产品内的使用边界。

### 阶段 3：最小产品试点

仅修改 Token、品牌资产和一个代表页面，优先选择新会话页。复用现有组件与 `AgentLogo` 状态接口，不改业务结构。

验收后再决定是否修订：

- `mona-ui-design-system.md`；
- `mona-ui-refactor-plan.md`；
- `globals.css` 与共享组件；
- 官网正式页面。

### 阶段 4：按模板推广

设置、笔记、邮件、数据库、终端等模块继续保持各自业务结构，只迁移已经在样板中验证过的 Token、Logo、IP 和共享组件规则。

## 12. 验收标准

### 12.1 品牌识别

- 遮住产品名称后，官网、App 图标和新会话页仍能被识别为同一品牌；
- 用户无需阅读世界观说明，也能看出女性人形和黑猫形态属于同一个 Mona；
- 黑猫 IP 主标与官网、App 和桌面状态中的黑猫为同一角色；
- 女性人形通过青色眼睛、黑／暖白分色和 M 核心与黑猫建立联系，不强行塞进 Logo；
- 用户可以看出黑猫形态是执行工作的主体，而不是女性角色的装饰宠物；
- 女性人形不会被误读为女仆、秘书、偶像，也不会因黑发与红色轮廓光被误读为其他品牌角色。

### 12.2 产品可用性

- 邮件、文档、终端、数据库等高密度内容没有因品牌化降低可读性；
- 浅色与深色主题均保持明确层级；
- 品牌红不会与错误和危险状态混淆；
- 角色动画关闭后仍能理解状态；
- 不引入第二套组件库或仅为装饰新增依赖。

### 12.3 实施质量

- 先完成视觉样板，再修改全局 Token；
- 每次只迁移一种页面模板；
- 每批改动有浅色、深色和关键状态截图；
- 构建、相关测试和人工视觉评审通过；
- 未批准的候选色值和 Logo 草图不得进入正式资产目录。
