> 2026-10-24 更新：创作资源与运行时已统一为 Mona Motion。本文涉及 Dashi、旧 huashu-art-motion 或 Remotion 的实现说明仅保留为历史记录；当前边界以 docs/architecture/module-invariants.md 和 docs/plans/video-huashu-motion-replacement.md 为准。
日期：2026-10-15。状态：本轮实现与相关验收完成，实际覆盖范围和限制见验收记录。

本方案承接 [视频工作台整体方案](video-workbench-rebuild.md)，以 [Mona UI 设计规范](mona-ui-design-system.md)、[模块不变量](../architecture/module-invariants.md)和[工程边界](../architecture/engineering-boundaries.md)为约束。实施与验收范围以 [验收记录](../plans/video-custom-style-acceptance-20261015.md) 为准。

[关键页面图像原型](video-custom-style-ui.png) 用于核对首次创建与样片调整的操作层级；外部导航沿用 Mona 既有工作区，不采用原型中的新增全局入口。

## 1. 产品决定

用户可以从内置风格出发，也可以提供参考图或文字描述，通过观看真实动画样片、直接调整基础样式、与 Mona 对话，制作自己的风格，之后像选择内置风格一样选用。

前端统一使用“风格”“创建风格”“我的风格”。用户不需要理解系列、品牌套件、设计令牌、锁定版本或渲染器。这里的风格包含配色、字体、画法、材质、字幕样式与动画表达规律；新视频的内容、构图和动作仍由 Mona 根据导演方案创作。

最短路径为：**风格画廊 → 创建或选择起点 → 生成样片 → 调整效果 → 保存并使用 → 回到原视频的导演流程**。只需要复用已有风格的用户，在画廊选中即可。

首版集中完成上述闭环。复杂时间线、节点编辑、逐元素拖拽、源码编辑、模板市场和公开发布均不进入本轮。成片仍通过自然语言修改。现有视频的导演确认、配音、播放和导出使用同一套能力。

## 3. 页面与入口

### 3.1 风格画廊

入口仍位于新建视频的“风格”区域。区域内使用“内置 / 我的”两个普通页签，标题旁放紧凑的“创建风格”入口。保留“由 Mona 推荐”的现有能力，不强迫用户创建自己的风格。

- 内置与已保存的自定义风格均展示真实样片图卡：封面、名称、简短描述。选中图卡直接选定风格，边框与小勾表达选中状态。
- 悬停或键盘聚焦时静音播放动态预览；放大后提供正常播放和声音控制。遵循减少动态效果设置，不让整页同时自动播放。
- 内置风格的菜单提供“以此创建”；我的风格提供“编辑、复制、重命名、删除”。管理操作收在卡片菜单，图卡本体始终负责选择。
- “我的”为空时只显示一句说明和“创建风格”，不增加教程页或设置向导。
- 从新建视频进入编辑页时，保留已经填写的主题、素材、画幅、声音和滚动位置。保存并使用后返回原位置，并选中刚创建的风格。
- 未保存的新风格草稿放在“我的”中按需出现的“未完成”列表，使用明确的“继续编辑”入口；不能混成点击即选用的风格图卡。已有风格的未完成修改从该卡片的“编辑”继续。

### 3.2 风格编辑页

在当前文档工作区打开完整编辑页，保留返回来源；创建风格不占用遮挡工作区的大弹窗。主区域看样片，右侧同一个可拖动、可收起的面板提供“对话 / 样式”两个页签，默认打开对话。

| 区域 | 内容与行为 |
|---|---|
| 顶部工具栏 | 返回、可编辑名称、更多菜单；已有样片后提供一个主要保存动作。名称自动建议，不作为开始制作的必填门槛 |
| 中央主区域 | 真实动画样片及普通播放控件；预览画幅用下拉选择；样片保持正确比例，不拉伸填满 |
| 右侧“对话” | 当前风格的制作对话、参考图附件和自然语言修改输入；复用现有制作会话控件 |
| 右侧“样式” | 当前风格实际支持的颜色、字体、字幕外观等少量表单；详细字段按需展开 |
| 更多菜单 | 历史记录、另存一份、放弃当前草稿等低频管理动作；恢复历史后成为可继续编辑的草稿 |

首次生成前不展示保存动作，页面只突出“生成样片”；有当前样片后才突出保存。从新建视频进入时，主动作是“保存并使用”，成功后返回原视频创建页；独立编辑已有风格时是“保存风格”，成功后留在编辑页，可继续修改或返回。没有新修改时不重复生成版本。不再弹出“锁定”“发布版本”确认框，历史编号留在历史记录里。

页面不另外放一列场景类型，不要求选择“封面、内容、比较、结尾”等固定页面。样片本身呈现必要的文字、对象、画面变化与字幕效果。

窄窗口下优先保证样片和主要动作可见，右侧面板通过现有收起方式打开；不能再叠一层永久左导航或挤出横向滚动。面板展开、收起与拖动不重建制作会话。

### 3.3 首次创建

“创建风格”直接打开编辑页。首次状态在主区域提供一处输入区：

- 一段描述，例如“温暖的纸张质感，用图形解释概念，动画自然，少一些装饰”。
- 可选的参考图上传；拖入或粘贴后显示缩略图，可移除。
- 可选的起始风格。来自“以此创建”时已经选好，显示来源预览；普通创建不强制选择。
- 一个主动作：“生成样片”。文字描述、参考图、起始风格有一个有效输入即可开始。

首次输入时暂不展示第二个对话输入框。提交后主区域输入区收起，右侧展开同一对话并保留最初描述与附件；后续修改一直在这里进行，不重复出现另一个需求表单。Mona 默认给出一个完整方向；只有用户要求比较方向时才提供多个候选，不强制先看三套方案再选一套。

从视频创建页带入主题时，可用该主题作为演示内容；没有主题时使用简短的通用讲解。用户可在对话中更换演示内容。默认样片约 10–15 秒，以能看清主要画法和动作变化为准，不用固定镜头数或效果数判断质量。

“生成样片”只授权当前风格样片的制作。保存风格和使用风格都不触发整片生成；正式视频继续经过导演台确认。

## 4. 调整、保存与返回的明确语义

### 4.1 两种调整方式

颜色、字体等可以明确映射到当前样片的设置使用标准字段直接调整；改动画节奏、画法、构图、角色或材质，通过对话说明。前端不提供特效勾选清单或“动画强度”来替代动画设计。

直接字段必须驱动样片实际使用的数据：修改颜色后画面同步改变，修改字体后重新计算布局。不能出现控件已变而样片仍使用硬编码旧值。对确实需要重新制作的修改，保留旧样片并说明“正在更新样片”，新结果完成后再切换。

打开颜色或字体选择器不会调用模型；普通字段修改不反复生成旁白。不新增整套字号、圆角、组件布局、运动曲线等专业参数墙。

### 4.2 草稿与可用风格

- 编辑过程自动保留恢复草稿。成功暂存只在需要时短暂显示“草稿已保留”，不能显示为“风格已保存”或“已经生效”。
- “保存风格 / 保存并使用”将用户已经看过、与当前修改一致的结果保存为可复用风格；内部创建不可变版本，用户不选择版本类型。
- 样片正在更新、当前结果损坏或仍是旧修订时，不能把它保存成已完成风格。禁用保存时，在动作附近说明具体原因，如“样片更新后可保存”。
- 生成或保存失败时保留描述、素材和最后可播放样片。保存失败不能返回来源，也不能选中一个尚未保存的风格。
- 返回按钮文案就是“返回”，保留草稿后回到来源；暂存失败则留在当前页提示重试，不能无声丢失编辑。没有输入的空白页面返回不创建空草稿。不得再以“取消”按钮执行保存；普通字段弹窗中的“取消”仍表示丢弃该弹窗尚未提交的改动。
- 放弃草稿是明确的低频操作，确认后才删除草稿。删除已保存风格前说明影响；已有视频使用自己的快照，仍应能够打开和导出。
- 编辑已保存风格时，其他项目和风格画廊继续使用原已保存结果，直到新结果保存成功。新增修订不自动重做旧视频。

用户只需要分清“我还在修改”和“这套风格可以用了”。修订号、输入哈希、素材绑定和检查流水线均由系统管理。

### 4.3 会话与导航

一个风格绑定一个制作会话，继续编辑、重试和返回不另建对话。主会话列表能识别风格制作入口，点击进入对应风格编辑页；消息、未读与工作区右栏使用同一份记录。

只有当前风格的对话真正可见且读取成功时才推进已读；切到“样式”页签、收起右栏或切走工作区，不提前清除未读。引用失效时仍可查看原对话，不通过重新创建项目掩盖错误。

## 5. 状态、等待与失败

状态来自真实任务，不从模型回复的文字猜测。中央始终保持最后的可用结果；第一次生成才使用空状态。任务与当前草稿绑定，重复点击不创建重复任务。

| 用户所处状态 | 默认看到什么 | 可执行动作 |
|---|---|---|
| 尚未开始 | 描述、参考图和起始风格输入区 | 生成样片、返回 |
| 正在生成或更新 | 当前实际动作，如“正在制作样片”“正在准备声音”；有旧样片就保持显示 | 停止、查看对话、离开后再回来 |
| 已有可播放样片 | 视频与播放控制，保存可用 | 播放、调整、保存 |
| 修改尚未完成 | 保留旧样片并标注“显示修改前的样片” | 等待、停止或调整要求；不能误保存旧样片为新结果 |
| 用户停止 | 已完成部分保留，动作恢复正常 | 继续调整或重新生成；停止提示不常驻 |
| 制作失败 | 现有错误弹窗说明失败操作及保留结果 | 重试未完成步骤；不静默重新执行结果未知的写入 |
| 保存失败 | 留在编辑页，输入与样片保留 | 重试保存 |

运行状态放在既有预览工具栏内，不单独占一整行；停止固定在这段状态文字旁，使用同一任务的取消能力。风格页对话不重复放置第二个停止入口，切换“对话 / 样式”或收起右栏后，停止位置不变。未知工作量不编造百分比，已有真实计数才展示数量。

超时后结束等待并给出可行动的反馈，不能无限转圈。任务中断先核对已经产生的结果，再决定从哪里继续；不把“重试”实现为重做全部声音和全部画面。

## 6. UI 交付约束

下列内容是验收条件，不能以“功能已经接通”代替。

| 项目 | 约束 |
|---|---|
| 控件选择 | 选值使用 Select，开关使用现有 Checkbox 或对应共享控件，连续数值才使用 Slider；普通设置不能做成一排排大按钮 |
| 操作层级 | 一个可见工作区只保留一个强调提交动作；卡片管理、返回、历史使用普通或轻量动作 |
| 尺寸 | 沿用共享组件；视频紧凑工具栏使用现有 24px 规格，普通辅助按钮 32px，表单控件 36px；不逐页写任意大按钮高度 |
| 表单 | 有字段标签，相关设置成组；可选参数渐进展示，不在首屏铺开多组专业配置 |
| 配色 | 控件使用 Mona 语义 Token，滑块沿用共享信息蓝；用户的视频风格颜色只作用于样片 |
| 文案 | 使用“风格、参考图、样片、保存、返回、继续编辑”；技术字段、版本发布和内部角色名不进入主流程 |
| 版式 | 主体为真实预览，内容依赖层级和间距组织；不新增装饰渐变、大阴影、空卡片或无意义副标题 |
| 反馈 | 校验贴近字段，失败沿用现有弹窗，同一错误只反馈一次；成功和停止消息短暂出现，不常驻占位 |
| 键盘与可访问性 | 可用键盘选图卡、打开预览、操作表单和保存；图标有名称、焦点清晰、动画尊重减少动态效果设置 |
| 设置边界 | 样式面板只修改外观；不放导出、重新生成整片、审阅意见或版本发布操作 |

## 7. 让自定义风格具备真实创作能力

保存内容需要覆盖三部分，并在后续视频创作时真正被读取：

1. **视觉规则**：颜色、字体、材质、图形与插画画法、文字层级、字幕及不同画幅的布局原则。
2. **动画规则与可用实现**：对象如何进入、变化和衔接，哪些动作适合解释哪类内容；可复用的绘制与运动代码、必要素材及来源。
3. **经过运行的示例**：样片源码、演示内容、时间安排、实际预览、检查结果和对应输入修订。

新视频继承这些规则和实现依据，重新组织内容和动作。不能只把参考图存成背景，也不能把样片的文字、人物身份和镜头顺序冻结成所有视频必须照搬的模板。

从 Dashi 内置风格开始时，沿用现有固定版本的原始资源和实现，复制必要内容后微调；不根据截图重画整套底座。Huashu 与通用动效知识按当前任务需要读取。自定义风格也能拥有自己的绘制代码，不限于内置七种风格或旧固定场景。

Agent 采用“理解参考与要求 → 建立风格规则 → 创作可运行样片 → 查看实际画面和播放结果 → 修正 → 交付”的内部工作顺序。这不是额外的用户向导。默认使用一个方向，用户发出修改要求后在当前草稿继续。

样片与正式视频共享 Remotion 运行环境、素材读取、字幕和声音时间线。配音使用现有项目声音设置或默认声音；复用未改变的旁白。样片制作不运行独立下载器、配音服务或第二套导出工具。

前端显示的预览与保存的风格必须对应同一视觉输入。颜色、字体、画法等变化必须使过期封面、动态预览和检查结果失效；名称等管理字段变化不要求重做动画。保存时校验当前草稿修订及样片输入，确保画廊预览与新版本一致。迟到的生成结果只能归到其原草稿修订，不能覆盖用户后续修改。

## 8. 实现边界与数据契约

### 8.1 对象与保存

| 对象 | 必须保存的内容 |
|---|---|
| 风格记录 | 稳定 ID、名称、来源、绑定会话、最新已保存版本、草稿引用 |
| 草稿 | 用户描述、参考与授权素材、实际样式字段、创作规则、可编辑实现、当前样片、修订及任务引用 |
| 已保存版本 | 不可变视觉与动画规则、必要实现和素材、来源许可、样片源码、封面与动态预览、关联检查输入 |
| 视频项目中的风格 | 使用时复制的版本快照与来源标识；原风格后续更新或删除不破坏项目 |

继续利用 `video_style.py` 的修订校验、原子写入和不可变版本。底层已有 `video_series` 文件不因前端改名而批量搬迁；读取和适配留在业务边界，新前端按风格语义访问，不需要用户先创建系列。

现有“内置风格”和“我的风格”对制作 Agent 提供同一种可选风格说明：来源、版本、可读取的规则与实现、预览证据。用户固定选择自定义风格后，自动推荐不能悄悄换回内置风格。实际文件与素材权限仍在读取、复制和运行时校验。

### 8.2 模块所有权

| 位置 | 职责 |
|---|---|
| WebUI 风格画廊与编辑页 | 选择、表单草稿、实际预览、导航、保存动作与状态显示；复用现有播放器、对话和分栏 |
| Services 风格业务与视频接口 | 草稿、版本、素材、样片结果、校验、预览及快照；状态以持久结果为依据 |
| Gateway 文档 Agent 与现有视频能力 | 风格制作会话、读取创作知识、生成和修改实现、查看真实结果；通过现有工具与 Services 协作 |
| `mona-motion` 与已有运行资源 | 风格创作指引、Dashi/Huashu 源码使用规则、统一运行约束 |

只扩展实现上述闭环所需的 profile、工具和业务契约，不新增通用工作流引擎。动态草稿、当前样片与修订进入运行上下文，单轮 system prompt 保持稳定。新配置若确有必要，显式进入现有配置 schema。

上传参考图是设计输入，不是可执行指令；保留已选文件的范围校验。参考图不会自动作为素材嵌入未来视频；需要实际复用的素材进入受管理资产及版本快照。复制的 Dashi 资源保留来源与许可，不引入作者示例声音。

## 9. 迁移与旧代码清理

旧自定义风格继续显示和选用，已有视频按现存快照打开。旧参数型风格进入新编辑页后，可以继续调整已有字段；要扩展画法或动画时，Mona 以现有样式为依据创作新样片。不能凭迁移自动宣称旧风格已经具备新增动画能力。

新链路覆盖创建、编辑、预览、保存和再次使用后，删除被替代的旧表单、重复选择入口、固定角色预览入口和不再使用的提示词。删除前核对实际引用与旧项目读取；必要的旧格式读取、编译和运行支持保留，不为清理代码损坏历史视频。

## 10. 实施顺序与交付门槛

按三个批次完成，每个批次都进入最终产品路径，不长期维护两套编辑器。

1. **风格与样片契约**：接入可复用创作规则、实现与资产；贯通真实样片、修订校验、保存快照和项目复用。先验证一套从内置风格复制的结果，避免先做一套无法驱动真实制作的 UI。
2. **完整用户交互**：替换创建与编辑页，统一图卡选择、自然语言调整、少量表单、草稿返回和会话导航；同时覆盖首次使用、编辑旧风格与失败恢复。
3. **质量与实际客户端验收**：检查跨内容复用、画幅适应、播放导出一致、历史项目与自然语言修改；按当前引用删除弃用代码，并同步稳定 UI 和架构文档。

实施前需把本方案的页面、操作层级和关键状态做成图像原型并检查；原型使用图像生成，不用临时 HTML 假页面替代。原型只证明交互方向，不能充当最终 UI 或动态样片验收。已明确的交互按本方案实施，不因普通实现选择反复要求用户确认。

### 10.1 UI 必过场景

| 场景 | 验收结果 |
|---|---|
| 第一次创建 | 能直接找到创建入口；只提供描述或一张参考图即可开始；不用填品牌、系列或版本 |
| 从内置风格开始 | 能看到实际效果、以此创建；原风格不被改写 |
| 调整样片 | 用户说“保留纸张质感、减少装饰、让图形变化更清楚”，新样片体现修改；可见表单字段立即或明确异步生效 |
| 保存并用于新视频 | 回到原创建页，主题与素材不丢，新风格已选中；下一步仍是导演方案 |
| 离开再回来 | 草稿和制作状态恢复，未完成草稿不冒充可用风格，不新建重复会话 |
| 再次编辑 | 进入同一风格和会话；新保存只影响后续选用；旧项目打开与导出不受影响 |
| 失败与停止 | 有具体动作文字和可用下一步；保留旧样片；没有无限转圈、独占状态行或常驻停止提示 |
| 导航与未读 | 主会话可回到风格页；可见对话更新同一已读记录，隐藏对话不提前标读 |
| 常见窗口与键盘 | 实际桌面常用宽度、缩放及右栏拖动后无横向溢出；主要动作可见，键盘可完成选择与保存 |

在真实客户端逐项操作并留截图或操作记录；截图需包含空状态、生成中、样片完成、修改中、失败和保存返回。仅页面截图、组件单测或按钮能点击，均不足以认定 UI 交付完成。

### 10.2 创作质量与工程验收

模型测试使用 **GPT 6.1 Sol，推理强度高**（`gpt-6.1-sol` / `high`），仅设置隔离测试会话，不改变用户默认模型。

以必要的代表案例覆盖：从内置风格修改、从参考图创建、仅文字描述创建；每条入口至少产生一份真实可播放样片。选取已保存风格制作另一段不同内容，覆盖知识讲解与真实素材产品展示，再核对横竖屏适应。案例可合并覆盖，不做七套风格乘所有配置的无差别测试。

质量检查关注实际画法与参考的一致性、口播对应的对象变化、文字与字幕可读性、运动连续性及内容适配。与同等输入的内置风格结果对照；发现退化要修正再交付。固定特效数量、截图像素变化和“编译成功”都不代表创作质量达标，也不预先承诺任意描述都能达到同一审美水平。

工程测试集中覆盖生产端与调用端的契约、直接字段生效、过期结果拒绝、保存失败保留、项目快照、导航与已读、真实媒体声音和时长。复用已验证的配音导出测试，只对本轮改变的接口与行为补验。样片预览与实际输出须来自同一实现和风格输入。

交付包含可操作的 UI、上述代表案例、必要测试与尚未覆盖的限制。不能只交付更整齐的表单，也不能把一个好看的宣传样片当作自定义风格已能稳定复用的证明。
