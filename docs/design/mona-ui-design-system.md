# Mona UI 设计规范

> 状态：目标规范（Target）  
> 版本：2.4<br>
> 基准日期：2026-08-22  
> 红黑交互配色修订：2026-09-13<br>
> 适用范围：`webui/src` 中所有桌面主窗口、辅助窗口、业务模块和共享组件
> 执行计划：[`../plans/2026-08-23-mona-brand-ui-v2-implementation-plan.md`](../plans/2026-08-23-mona-brand-ui-v2-implementation-plan.md)

## 1. 规范目标

这份规范解决一个问题：**Mona 已经统一了配色和身份资产，但卡片、表格、页面布局和动效仍缺少稳定的品牌语法。**

目标不是把官网的高浓度红黑拼贴搬进工作区，而是建立“平时安静、关键时刻 Mona 才显形”的双态工作台：外壳表达品牌，内容保持长期可用，Agent 状态通过克制动效被感知。

因此，本规范负责：

1. 从中性主题与四个品牌签名元素提取可复用规则；
2. 把这些规则扩展到所有页面和状态；
3. 约束新增 UI，防止继续出现局部风格；
4. 给现有页面提供可验证的迁移标准。

### 1.1 规范用语

- **必须**：不满足即视为 UI 缺陷。
- **应该**：默认遵守；偏离时必须有明确的业务理由。
- **可以**：在不破坏上级规则时按页面需要选择。

### 1.2 成功标准

用户在任意页面都应感到自己仍在同一个 Mona 工作台中，而不是进入了另一个独立产品。

一致性不要求所有页面结构相同，而要求以下视觉语法相同：

- 应用外壳与内容表面；
- 字体层级与信息密度；
- 颜色语义；
- 控件尺寸、圆角和交互状态；
- 页面标题、工具栏和分区方式；
- 弹窗、菜单、加载、空状态和错误状态；
- 动效节奏、焦点可见性和无障碍行为。

## 2. 设计定位

### 2.1 核心气质

Mona 是一个**温润、精密、安静的个人智能工作台**。

关键词：

- 温润，而非冰冷；
- 专业，而非企业后台；
- 有陪伴感，而非卡通化；
- 高信息密度，而非拥挤；
- 有材质层次，而非黑白平面；
- 克制的智能感，而非霓虹科幻感。

### 2.2 吸收的通用设计方法

Mona 吸收 Cindy 与成熟桌面工作产品已验证的设计方法：

- 外壳有性格，工作内容保持安静；
- 表面之间优先通过留白、对齐和轻微色差建立层次，仅在必要时使用细边框或短阴影；
- 字号使用命名阶梯，不在页面内逐像素发明；
- 组件使用语义颜色，不直接挑选具体色板；
- 动效短、稳、可关闭；
- 共享控件承担一致性，页面不重复创造控件；
- 自动检查阻止字号和颜色重新漂移。

### 2.3 不复制什么

Mona 不复制：

- Cindy 的具体皮肤、产品术语和信息结构；
- 官网的满屏红黑拼贴、密集斜切和纸张纹理；
- 为展示页面制作的巨型标题、装饰英文和持续环境动效；
- 不适合中文个人工作流的信息密度和文案语气。

### 2.4 视觉母版

视觉母版由四个签名元素组成：

- `Mona Cut`：仅在欢迎、订阅、Agent 状态等品牌表面使用单个 8–12px 切角；
- `Mona Signal`：2px 红色短线或红点表达品牌身份和当前入口；
- `Mona Pulse`：青色只在 Agent 思考、执行和接管工具时出现；
- `Mona Dual`：黑猫承担小尺寸识别，人形只进入启动、欢迎和信任说明等大面积表面。

每屏最多一个品牌视觉中心；工作正文、表格、终端和画布不得同时承担品牌装饰。

### 2.5 与现行规则的差异裁决

下表是对已经落地但与目标视觉冲突的现行规则的最终裁决。UI-00 只负责同步文档，执行时不得再次临场选择。

| 项目 | 现行规则 | 目标规则 | 迁移动作 |
|---|---|---|---|
| 普通单行输入框圆角 | `rounded-full` | 8px（`radius-md`） | 普通表单输入改为 8px；搜索、筛选和真实胶囊控件可保留全圆角 |
| 输入框高度 | `h-8`，32px | 标准 36px；紧凑模式 32px | 表单默认迁移到 36px；专业工具栏明确使用紧凑模式时保留 32px |
| 最小命名字号 | 日程时间 gutter 等使用 10px | `text-micro` 11px 起步 | 日历 gutter、置信度徽章等可读 UI 文字统一提升到 11px；图形内部装饰文字不在此列 |
| 焦点环 | 2px ring＋2px offset | 1px 主题焦点环或边框 | 去除双层高对比焦点环；仍必须保持清晰可见和键盘可达 |

裁决只改变视觉实现，不改变控件语义、业务状态和交互流程。

## 3. 设计原则

### 3.1 先建立层级，再添加装饰

精致度的优先级为：

1. 对齐；
2. 字体层级；
3. 间距节奏；
4. 表面关系；
5. 状态反馈；
6. 装饰和动效。

前五项未完成时，不得用渐变、玻璃、纹理或动画掩盖问题。

### 3.2 内容优先，外壳表达品牌

- 品牌色和材质主要出现在标题栏、侧栏、主表面边缘、Mona 状态和关键动作。
- 文档、邮件正文、数据表、终端、代码和画布必须保持高可读性。
- 不得在主内容中铺大面积品牌渐变。

### 3.3 高密度不等于小字号

专业工具通过紧凑间距、清晰分栏和渐进展示提升密度，不通过持续缩小文字实现。

### 3.4 统一语法，不统一结构

笔记、终端和设置可以使用不同页面模板，但必须共享控件、字号、颜色、状态和表面规则。

### 3.5 一屏一个视觉主角

- 首页主角是个人上下文与输入区；
- 编辑页主角是内容；
- 专业工具页主角是操作区域或数据；
- 设置页主角是当前设置分组；
- 制作流程页主角是当前步骤和产物。

其他元素必须退后，不得同时出现多个高饱和按钮或多个强阴影卡片。炭黑、近白等高对比实心按钮虽然饱和度低，也会形成强视觉重心，必须按整个可见工作区控制数量，不能只逐张卡片验收。

内容丰富的页面应先让用户识别内容和当前任务，再识别可用操作。减少强调不等于隐藏功能：普通动作保持清晰可见，低优先级快捷动作才可按悬停或键盘焦点渐进出现。

## 4. 设计变量

所有页面必须使用语义变量。禁止在业务组件内直接使用 `blue-500`、`#347fca` 等具体颜色表达产品语义。

官网以 `#070706` 墨黑、`#F3EAD9` 纸色和 `#E51D2A` Mona 红构成品牌关系。桌面端不复制官网的大面积色块，而把墨黑用于文字和少量关键执行，把纸色转译为暖灰表面，把红色用于页签、焦点、选中与危险动作。功能蓝只用于明确的信息语义、数据和链接。

### 4.1 表面层级

| 层级 | 变量 | 用途 | 规则 |
|---|---|---|---|
| 0 | `--canvas-top` / `--canvas-bottom` | 应用最外层画布 | 仅外壳可见，使用低饱和象牙灰／中性黑灰 |
| 1 | `--sidebar` | 主侧栏、标题栏背景 | 与外壳同色阶，不与内容争夺注意力 |
| 2 | `--content-surface` | 主工作区 | 浅色为 `#FFFEFA`，深色为 `#1F1F1F` |
| 2A | `--editor-surface` | 文档正文、数据库结果、流程图／思维导图／工作流画布 | 浅色为纯白，深色与卡片表面一致 |
| 3 | `--secondary` / `--muted` | 工具栏、选中行、次级区 | 用小色差分组，不依赖重边框 |
| 4 | `--card` | 必须独立成组的内容 | 仅在需要独立边界时使用 |
| 5 | `--popover` | 菜单、弹窗、浮层 | 对比明确，允许更强阴影 |

规则：

- 页面根节点不得自行设置新的大面积背景色。
- 同一平面上的相邻内容优先用间距、对齐和色差；仍无法区分时才使用单条分隔线，不堆叠卡片。
- 主工作区不得再套一层全尺寸卡片。
- 编辑器和数据画布必须显式使用 `--editor-surface`，不得落到 `muted`、`secondary` 或 `sidebar`。
- 模糊只用于外壳或悬浮层；正文表面不得持续使用玻璃效果。

### 4.2 浅色主题

下表保留 2026-08-22 的浅色基准。页面不得引入偏黄暖色或把所有按钮改成实心蓝色；常规交互按 §4.5 使用暖灰实体表面和墨黑前景，炭黑用于少量最高强调动作，红色用于危险动作与状态信号。

| 变量 | 基准值 | 用途 |
|---|---|---|
| `--canvas-top` | `60 16.1% 93.9%` | `#F2F2ED` 外壳 |
| `--canvas-bottom` | `60 12.8% 92.4%` | `#EEEEE9` 弱表面 |
| `--content-surface` / `--background` / `--card` | `48 100% 99%` | `#FFFEFA` 主工作表面 |
| `--foreground` | `0 0% 10.2%` | `#1A1A1A` 主文字 |
| `--muted` / `--secondary` / `--accent` | `60 12.8% 92.4%` | 次级表面与 hover |
| `--muted-foreground` | `60 1.9% 41.2%` | `#6B6B67` 次级文字 |
| `--border` / `--input` | `60 8.5% 88.4%` | `#E4E4DF` 边框与输入边界 |
| `--sidebar` | `60 12.8% 92.4%` | 主侧栏和标题栏 |
| `--primary` / `--action` / `--theme` | `214.3 5.5% 24.9%` | `#3C3F43` 少量最高强调动作 |
| `--action-hover` | `213.3 8.9% 19.8%` | `#2E3237` 主操作 hover |
| `--action-foreground` | `0 0% 98.8%` | `#FCFCFC` 反相前景 |
| `--ring` | `356 79% 51%` | Mona 红焦点环 |
| `--brand-blue` | `217.3 69.7% 56.1%` | `#417CDD` 信息、链接和数据状态 |
| `--destructive` | `0 84.2% 60.2%` | 危险操作 |

首屏中仍直接写在组件里的蓝、绿、橙必须原值转为语义变量后再扩展到其他页面；不得趁迁移改变视觉结果。

### 4.3 深色主题

深色模式必须保持相同的层级关系，不是将浅色简单反相。现有深色基准如下：

| 变量 | 基准值 |
|---|---|
| `--canvas-top` / `--background` / `--sidebar` | `0 0% 9.4%`（`#181818`） |
| `--canvas-bottom` / `--muted` / `--secondary` | `0 0% 11.4%`（`#1D1D1D`） |
| `--content-surface` / `--card` / `--popover` | `0 0% 12.2%`（`#1F1F1F`） |
| `--foreground` | `0 0% 83.1%`（`#D4D4D4`） |
| `--muted-foreground` | `0 0% 75.7%`（`#C1C1C1`） |
| `--border` / `--input` | `0 0% 19.2%`（`#313131`） |
| `--primary` / `--action` / `--theme` | `0 0% 93.3%`（`#EEEEEE`） |
| `--action-foreground` | `0 0% 8.2%`（`#151515`） |
| `--action-hover` | `0 0% 88.6%`（`#E2E2E2`） |
| `--destructive` | `0 62.8% 30.6%` |

阴影在深色模式中只承担边缘分离；禁止纯黑大面积背景、持续发光描边和未经语义判断的简单反相。

### 4.4 语义色

必须为以下语义建立全局变量，并由组件消费。基准值取自已冻结的中性主题；没有基准值的角色继续复用现有全局 Token，不新造颜色。

| 语义 | 浅色基准 | 深色基准 | 示例用途 | 禁止用途 |
|---|---|---|---|---|
| `info-strong` | `#4F9DE8` | `#4F9DE8` | 日程圆点、焦点标记 | 大面积背景 |
| `info` | `#347FCA` | `#7CB8F0` | 日程时间、信息链接、常规交互前景 | 无语义装饰、大面积实心按钮 |
| `success` | `#0E9F6E` | `#34D399` | 继续、完成、已连接 | 所有主要按钮 |
| `success-indicator` | `#10B981` | `#10B981` | 在线圆点、完成图标 | 正文 |
| `warning` | `#D8852D` | `#F0B273` | 未读邮件、待处理提醒 | 纯提示信息 |
| `danger` | `--destructive` | `--destructive` | 删除、失败、不可恢复风险 | 普通关闭按钮 |
| `ai-active` | `--ai-cyan` | `--ai-cyan` | Mona 工作中、流式输出 | 长时间铺满页面 |
| `module-*` | 模块图标专用 | 模块图标专用 | 侧栏模块身份 | 文本、边框和背景同时着色 |

允许保留当前首屏已经验证的派生状态：`info-strong` 背景透明度 7%、悬停 10%、光环 15%；成功色悬停 `#0B8A5E`；提醒色悬停 `#C2741F`。这些值也必须封装为组件状态，不得在业务页面重复书写。

状态色在一个组件中最多承担一个角色。禁止同时使用彩色背景、彩色边框、彩色文字和发光。

### 4.5 动作色裁决

- 先确定动作在整个可见工作区的层级，再选择颜色；不得因为一个动作是卡片内唯一按钮，就自动使用实心主按钮。
- `action` 是最高强调色：浅色炭黑、深色近白，用于当前任务的关键提交、创建或确认执行。普通列表、卡片、工具栏操作默认使用普通或轻量层级。
- 一个可见工作区通常保留零到一个强调动作；没有明确关键动作时可以全部使用轻按钮。独立任务分栏或模态窗口可有自己的强调动作，但重复列表的每一行不视为独立工作区。
- 常规交互使用暖灰实体表面、墨黑文字和细边框；悬停与按下只使用相邻的中性灰层级。按钮本体不附加装饰线，功能蓝不用于通用按钮。
- `foreground` 用于正文、通用图标和细线；品牌红表达身份与当前一级入口，青色表达 AI 执行，成功／警告／危险色表达真实状态，不能轮流用作普通动作的装饰色。
- 导航、页签、筛选器和单选项的选中态不是“主要动作”：使用文字／图标深浅、暖灰表面或 1–2px Mona 红指示线。一级模块入口继续遵循 §10 的品牌红指示规则。
- 完成勾选、今日日期等需要实心识别的小面积状态可以使用 `info`＋白色前景，但不得扩大为整行或整张卡片。复选框使用常规信息蓝的边界、勾选填充和焦点反馈，不使用品牌红。
- 图表系列色、状态色和动作色必须分工：炭黑表示关键执行，Mona 红表示品牌交互信号，功能蓝表示信息、链接和数据；同一含义在不同页面保持一致。

#### 交互层级与页面密度

| 层级 | 默认表现 | 典型用途 |
|---|---|---|
| 强调 | `action` 实心表面＋反相文字 | 向导继续、创建提交、详情面板关键操作 |
| 普通 | 暖灰实体表面＋细边框＋墨黑前景 | 应用列表获取、查看、编辑、刷新、更新 |
| 轻量 | 无底色的中性文字或图标，悬停／焦点出现浅色反馈 | 工具栏、辅助操作、行内快捷动作 |
| 危险 | 浅红实体表面＋红色文字＋红色弱边框；关键破坏确认使用危险实心面 | 删除、卸载、不可恢复操作 |

- 欢迎页、空状态、简短创建向导可用一个炭黑主按钮聚焦任务；内容丰富的邮件、数据库、软件管理页以普通／轻量动作和内容自身色彩为主。
- 强调程度根据当前可见内容与任务判断，不按模块名称固定，也不因浅／深主题改变动作语义。
- 普通按钮在 Default 状态就必须能被识别为可点击控件：同时具备可见表面、1px 低对比边界和清晰前景色。禁止退化成只有文字、依赖 Hover 才出现背景的伪按钮；这种表现属于轻量或链接层级，不能承载重复的主要列表操作。
- 应用商店卡片的“获取”使用普通按钮，采用 28–32px 高的暖灰实体控件；详情面板的关键“获取”可使用强调按钮。数据库中的编辑、复制、导出使用轻量或普通按钮，当前查询的“执行”可作为工作区强调动作。

#### 语义 Token 与状态

- 沿用 `action`、`info`、`foreground`、`secondary`、`accent` 等基准变量，不新增模块专属主色。普通交互统一使用共享 Token：`interaction-foreground`、`interaction-surface`、`interaction-border`、`interaction-hover`、`interaction-pressed`。
- 普通按钮的 Default 为墨黑前景＋暖灰实体表面＋`interaction-border`；Hover 和 Pressed 仅加深中性表面，不改变为红色或炭黑主按钮；Focus 使用主题焦点环。重复危险动作使用共享 `dangerSoft`，必须有浅红表面、红色文字和弱边框，不能退化为裸文字。
- 浅色基准：`interaction-foreground: 0 0% 12.5%`、`interaction-surface: 60 12.8% 94.5%`、`interaction-border: 60 8.5% 84.5%`、`interaction-hover: 60 12.8% 92.35%`、`interaction-pressed: 60 10% 89%`。
- 深色基准：`interaction-foreground: 0 0% 91%`、`interaction-surface: 0 0% 16.5%`、`interaction-border: 0 0% 27%`、`interaction-hover: 0 0% 19.5%`、`interaction-pressed: 0 0% 22.5%`。
- Loading 保持原尺寸与强调级别，用 Spinner 或真实进度说明状态；Disabled 使用中性弱化状态并真正禁用；“已安装”等完成状态不能只套成另一个高强调按钮。
- 浅色与深色分别验证派生表面；小字号按钮文字和背景的对比度至少 4.5:1，控件必要边界与焦点指示至少 3:1，选中与错误不能仅靠颜色区分。若基准组合不满足实际对比度，在共享交互 Token 中调整，不能逐页另选颜色。
- 本节定义目标语义，不代表共享组件已经完成迁移。实施时先建立共享层级，再按页面显式选择；禁止为更改默认配色而直接全局替换 `action` 或 `primary` 的颜色。

### 4.6 数据可视化色

Mona 的品牌基调是黑／灰／白表面与克制的 Mona Red 身份信号；这不等于图表使用黑白灰。图表使用独立的低饱和数据色板，品牌色、状态色和数据色不得混用。

| Token | 浅色 | 深色 | 默认用途 |
|---|---|---|---|
| `--data-1` | `#527CA8` | `#82ACD6` | 主序列、单序列图 |
| `--data-2` | `#438A7E` | `#70B7AA` | 第二序列、活动强度 |
| `--data-3` | `#BD873C` | `#D8AA6C` | 第三序列 |
| `--data-4` | `#846D9C` | `#B29AC8` | 第四序列 |
| `--data-5` | `#B8667E` | `#D594A7` | 第五序列 |
| `--data-6` | `#7D8354` | `#AEB477` | 第六序列 |

数据色比 Mona Red 更柔和。页面通过中性表面、字体、分隔线和 2px 红色入口信号保持品牌识别，图表不需要退化为黑白，也不得用大面积品牌红证明“属于 Mona”。

图表必须满足：

- 默认不超过 6 个系列色；
- 相邻系列在明度和色相上可区分；
- 状态色不作为普通数据系列色；
- 图例、轴线和网格仍使用全局文字与边框变量；
- 同一指标跨页面保持同色；
- 不靠颜色作为唯一信息载体。
- 单序列默认使用 `--data-1`；同期／上期对比使用彩色实线与中性虚线；热力图使用单个数据色的连续透明度，不使用彩虹渐变。
- 多系列按稳定的业务映射选择 `--data-1` 至 `--data-6`，不得根据当前排序临时换色，也不得用同一颜色的不同透明度冒充不同类别。

## 5. 字体系统

### 5.1 字体族

- 中文优先使用当前平台系统中文字体。
- 英文、数字和符号继承同一无衬线栈；在项目正式内置 Inter Variable 前，不新增远程字体依赖。
- 代码、终端和固定宽度数据使用现有等宽字体栈。
- 正文不得通过局部 `font-family` 制造风格差异。

### 5.2 命名字阶

所有可读文字必须使用下列命名角色。实现时统一使用 `rem`，不得在业务页面出现任意 `text-[…]`。

| 角色 | 默认大小 | 行高 | 字重 | 用途 |
|---|---:|---:|---:|---|
| `text-micro` | 11px | 16px | 400/500 | 时间戳、辅助计数、极次要元信息 |
| `text-caption` | 12px | 18px | 400/500/600 | 分组标签、状态、小按钮 |
| `text-ui` | 13px | 20px | 400/500/600 | 桌面控件、列表、工具栏 |
| `text-body` | 14px | 22px | 400/500/600 | 默认正文、表单、说明 |
| `text-body-lg` | 16px | 26px | 400/500/600 | 对话正文、阅读正文、重要说明 |
| `text-title-sm` | 16px | 24px | 600 | 弹窗标题、区块主标题 |
| `text-title` | 20px | 28px | 600 | 页面标题、洞察页唯一主标题 |
| `text-display-sm` | 28px | 36px | 500/600 | 极少量重点数字，不用于页签和工具栏 |
| `text-clock` | 54px | 60px | 300 | 首页时间，专用 |

规则：

- `text-micro` 不得承载需要阅读和操作判断的信息。
- 中文正文默认不得小于 13px；长篇阅读不得小于 14px。
- 页面内最多同时出现 5 个字阶。
- 同级标题必须使用同一角色，不得因文字长短调整字号。
- 大标题使用轻微负字距；正文和中文标签不使用夸张字距。
- 数据、时间、金额和计数使用等宽数字特性。
- 全局缩放必须能同步缩放所有可读文字；仅原生窗口控件允许固定像素例外。

### 5.3 标题层级

| 层级 | 角色 | 结构 |
|---|---|---|
| 页面标题 | `text-title` | 每页最多一个 `h1`，可带说明和右侧操作 |
| 区块标题 | `text-title-sm` 或 `text-body-lg` | 同页并列区块使用 `h2` |
| 分组标题 | `text-caption`、600 | 表单组、列表组、表头；可使用克制字距 |
| 字段标签 | `text-ui`、500 | 与字段保持固定间距 |
| 辅助说明 | `text-caption` 或 `text-body` | 使用次级文字色 |

设置、系统、画像等页面必须共享 `PageHeader`、`SectionHeader` 和 `SubsectionLabel`，不得各自实现标题样式。

### 5.4 导航与工具栏文字

- 页面级导航使用 `text-ui`（13px）。
- Tabbar、Toolbar、标签和按钮文字统一使用 `text-caption`（12px），不允许按模块缩成 10/11px 或放大到 13/14px；选中与禁用状态只改变颜色、字重和表面，不改变字号。现有 `text-micro` 在 UI 控件与标签场景中同样按 12px 渲染。
- 标签包括 Badge、状态胶囊、计数徽标和状态短语；无论历史类名为何，最终渲染字号均为 12px。
- 页签、导航项和选中项不得通过放大字号表达当前状态，只允许使用字重、浅色表面、文字色或 1px 指示线。
- 同一导航层级的选中与未选中项必须保持相同字号和行高；标题过长使用截断或 Tooltip，不得动态缩放。
- 页面级页签文字不得超过 `text-ui`，文档标签和工具模式切换不得使用 `text-body-lg`、`text-title-sm` 或更大字阶。

## 6. 间距与密度

### 6.1 间距尺度

使用 4px 基础网格，允许 2px 和 6px 作为光学校准值。

| Token | 像素 | 用途 |
|---|---:|---|
| `space-0.5` | 2 | 图标内部和紧邻状态 |
| `space-1` | 4 | 紧凑控件内部 |
| `space-1.5` | 6 | 图标与文字 |
| `space-2` | 8 | 行内控件、紧凑行 |
| `space-3` | 12 | 默认组件内部 |
| `space-4` | 16 | 卡片、工具栏、字段间距 |
| `space-5` | 20 | 小区块 |
| `space-6` | 24 | 页面区块 |
| `space-8` | 32 | 大区块 |
| `space-10` | 40 | 页面段落 |
| `space-12` | 48 | 欢迎区和大留白 |

禁止使用没有明确理由的任意间距。光学校准必须局部、可解释，不能形成新的尺度。

### 6.2 密度模式

Mona 只允许两种密度：

- **标准密度**：首页、设置、画像、制作向导、普通表单。
- **专业密度**：终端、数据库、IDE、浏览器、树、表格和多栏编辑器。

专业密度可以缩小行高和间距，但不改变颜色、圆角、字号角色和交互状态。

### 6.3 推荐尺寸

| 元素 | 标准 | 紧凑 |
|---|---:|---:|
| 普通按钮 | 36px | 32px |
| 小按钮 | 32px | 28px |
| 图标按钮 | 32×32px | 28×28px |
| 文本输入 | 36px | 32px |
| 列表行 | 36–40px | 28–32px |
| 主工具栏 | 44px | 40px |
| 次工具栏 | 40px | 32–36px |
| 触控热区 | 最小 32×32px | 不缩小 |

## 7. 圆角、边框和阴影

### 7.1 圆角

| Token | 建议值 | 用途 |
|---|---:|---|
| `radius-xs` | 4px | 微型状态、代码元素 |
| `radius-sm` | 6px | 紧凑控件、表格行操作 |
| `radius-md` | 8px | 按钮、输入框、菜单项 |
| `radius-lg` | 12px | 卡片、小面板 |
| `radius-xl` | 16px | 大型弹窗和少量品牌表面 |
| `radius-full` | 999px | 状态点、头像、真实胶囊控件 |

规则：

- 主内容表面使用 10–12px 圆角；专业工具主区可以更小或无圆角。
- 默认按钮和输入框不使用全胶囊；只有标签、筛选器、状态和快捷提示可以使用胶囊。
- 同一容器内的子元素圆角必须小于父容器。
- 专业工具区优先使用 4–8px，避免终端和表格“卡片化”。

### 7.2 边框

- **默认无边框。** 先使用留白、间距、对齐、字号/字重和轻微表面色差表达层级，不得为了“看起来完整”添加线或框。
- 边框只用于必须明确边界的输入控件、独立对象、分栏边界，以及焦点、选中、错误等交互状态。
- 同一视觉区域最多保留一层外围边界；父容器已有边界时，内部区块和列表行默认无框，禁止边框套边框、卡片套卡片。
- 必须分隔时优先使用间距或局部色差，其次使用单边或短分隔线，最后才使用四边框。
- 分栏最多使用单条竖线；列表使用悬停面，不默认逐行画线。
- 确需使用的普通边框统一为 1px 低对比中性灰，不得通过加粗边框制造层级。
- 强调态优先改变表面色，其次改变边框色，最后才使用环形描边。
- 分隔线透明度必须低于普通控件边框。

### 7.3 阴影

只保留四个语义级别：

| 级别 | 用途 |
|---|---|
| `shadow-none` | 行、列表、工具栏、内嵌区 |
| `shadow-surface` | 少量需要抬起的输入区和品牌表面，短而柔和 |
| `shadow-float` | 菜单、浮动工具条、小浮层 |
| `shadow-overlay` | 弹窗、抽屉、需要模态层级的表面 |

禁止页面自定义大面积、长距离或彩色阴影。焦点不通过阴影表现。

## 8. 图标与品牌角色

应用商店、集成列表中的第三方应用图标属于内容资产，与下述通用功能图标分开处理：

- 优先使用匹配产品的真实彩色图标或厂商提供的主题版本，保留原有配色；不能为统一中性风格而转成黑色，也不能随意给单色轮廓着色来冒充官方彩色图标。
- 使用产品级标识核对图标，不能用同一厂商的另一个产品代替；普通微信、企业微信、百度网盘与百度智能云不能混用。
- 网络加载失败或找不到可信图标时使用明确的中性占位，不猜测品牌资产。静态映射、在线缓存与搜索结果遵循同一规则。
- 彩色图标本身承担识别，不再给整张卡片、名称和按钮同时套品牌色。保持固定图标槽位与光学尺寸，原有留白不足的图标可局部校准。

### 8.1 通用图标

- 交互图标默认使用 Lucide，同类功能不得混用不同图标家族。
- 默认线宽统一为库的常规线宽；同一工具栏中不得混用粗细。
- 推荐尺寸：12、14、16、20px；24px 仅用于空状态或主要功能入口。
- 图标必须与文字基线光学对齐。
- 只有图标的按钮必须提供可访问名称和 Tooltip。

### 8.1.1 侧边栏切换图标

右侧面板（右侧栏）的收起/展开切换**必须**使用 Mona 自定义的 `RightSidebarToggleIcon`，**禁止**使用 Lucide 的 `PanelRightClose`/`PanelRightOpen` 或其他图标替代。

该图标通过矩形右侧填充区域直观表达面板状态：

- **面板打开**：矩形右侧 1/4 区域实心填充；
- **面板关闭**：矩形仅保留轮廓线。

实现位置：`webui/src/components/notes/RightSidebarToggleIcon.tsx`。

```tsx
import { RightSidebarToggleIcon } from "@/components/notes/RightSidebarToggleIcon";

// 使用示例
<RightSidebarToggleIcon open={rightSidebarOpen} className="h-4 w-4" />
```

左侧面板对应使用 `LeftSidebarToggleIcon`（同目录下），逻辑对称：面板打开时左侧 1/4 区域实心填充。

### 8.2 模块彩色图标

当前侧栏彩色模块图标是 Mona 的身份资产，予以保留，但必须：

- 统一视觉盒尺寸；
- 统一有效图形占比；
- 统一饱和度和光照方向；
- 默认不配彩色文字；
- 选中态通过行表面和文字权重表达，不再增加大色块；
- 状态角标不能遮挡主体轮廓。

### 8.3 Mona 双形态角色

Mona 黑猫（`AgentLogo`）只用于：

- 应用标识；
- 首页问候；
- AI 工作、等待和空状态；
- 有明确 Agent 状态含义的提示。

女性人形只用于启动、首次欢迎、订阅、About 和重要信任说明，不进入 20–64px 小头像或普通工具栏。

限制：

- 一个视觉区域最多出现一个主 Mona 角色；
- 不在每张卡片和按钮中重复；
- 不用黑猫替代标准功能图标；
- 动画必须克制并尊重减少动态设置。

## 9. 动效系统

统一为以下节奏：

| Token | 时长 | 用途 |
|---|---:|---|
| `motion-instant` | 80ms | 按下、悬停、颜色反馈 |
| `motion-fast` | 150ms | 菜单、Tooltip、小状态变化 |
| `motion-standard` | 200ms | 面板、页签、抽屉 |
| `motion-arrival` | 650ms | 冷启动、首次欢迎等单次品牌入场 |

缓动：

- 状态变化：`cubic-bezier(0.25, 1, 0.5, 1)`；
- 入场：`cubic-bezier(0.16, 1, 0.3, 1)`。

规则：

- 常规移动距离不超过 8px；
- 不对大面积背景做持续动画；
- AI 呼吸效果只作用于 Mona 状态、M 核心或输入区 2px 状态线；
- 空闲时不播放持续环境动画；等待用户决定使用静态琥珀色而非循环闪烁；
- 加载超过 400ms 才显示显式进度，避免闪烁；
- 所有非必要动画在 `prefers-reduced-motion: reduce` 下关闭；
- 页面切换不得同时使用淡入、缩放和位移三种效果。

## 10. 应用外壳

### 10.1 标题栏

- 标题栏高度保持 36px 左右。
- 标题栏属于画布，不属于主内容表面。
- 标签页使用低对比选中面，不使用浏览器式重阴影。
- `Mona` 主工作区入口是固定身份入口，不表现为浏览器标签：无选中底色、无标签 hover 表面；可保留点击返回主工作区。
- 窗口按钮遵循平台位置和点击热区；危险色只在关闭按钮悬停时出现。
- 标题栏最多容纳：标签、全局状态、设置、窗口控制。业务工具不得进入标题栏。

### 10.2 主侧栏

- 一级 App Rail 固定 64px；会话／对象列表使用 260–288px。
- 侧栏与标题栏使用同一外壳色系。
- 一级模块行高 32px，图标和文字间距一致。
- 会话列表可采用专业密度，但正文不得小于 `text-ui`。
- 分组标签使用 `text-caption` 或 `text-micro`，不得与可操作项争夺注意力。
- 一级模块选中态使用 2px 红色短线＋图标／文字深浅，不使用整块选中背景；悬停只使用前景色 4–6% 的中性叠加。
- 滚动条默认隐藏，仅在悬停或滚动时显示低对比细滚动条。

### 10.3 主内容表面

- 作为应用外壳中的唯一主表面；使用 10–12px 圆角和细边框，默认无阴影。
- 默认填满侧栏右侧剩余空间并保留当前外壳边距关系。
- 所有业务页面渲染在该表面内部，不得重新创建第二个“应用窗口”。
- 页面可选择有顶栏或无顶栏，但顶栏高度必须使用共享尺寸。

### 10.4 辅助面板

- 右侧 AI、预览、属性和文件面板使用统一面板壳。
- 专业工具内部的资源树／连接栏属于工作表面，使用 `background`／`card`，不得复用较深的应用外壳 `sidebar` 色。
- 面板与主内容用单条竖线或左向短阴影分离，二者不得同时过强。
- 面板标题栏使用共享的 40px/44px 工具栏高度。
- 面板宽度支持拖拽，但必须有最小值、最大值和持久化策略。

## 11. 页面模板

### 11.1 首页模板

适用：新会话。

首页是高品牌浓度样板，但仍必须服务于真实工作：

- 页面最多一张品牌卡片，使用单个切角、红色信号和 Mona 身份；
- 欢迎页品牌表面必须无外围边框、无默认阴影；内部区块优先用留白分组，不使用连续分隔线。
- 时间、今日焦点、邮件和继续工作按信息层级排布，不做等权卡片墙；
- 输入区保持中性，Agent 工作时才显示青色 2px 状态线；
- 猫／人双态只在大面积欢迎表面建立关系，不进入快捷操作和数据卡片；
- 真实数据优先于装饰内容。

### 11.2 内容工作台模板

适用：笔记、Markdown 阅读器、AI 文档、邮件。

```text
模块导航/列表 | 内容编辑或阅读区 | 可选辅助面板
```

规则：

- 左栏负责选择，中栏负责主要内容，右栏只提供上下文辅助；
- 编辑器正文区减少边框和卡片；
- 顶部仅保留当前内容所需工具；
- 保存、同步和 AI 状态放在固定位置，不随页面漂移；
- 三栏之间使用细分隔线和统一拖拽柄。

### 11.3 专业工具模板

适用：终端、数据库、IDE、浏览器。

```text
紧凑工具栏
导航树/资源栏 | 主操作区 | 可选检查器或 AI 面板
状态栏（仅必要时）
```

规则：

- 使用专业密度；
- 工具栏高度、图标按钮、选中标签和分隔符统一；
- 不把查询编辑器、终端、网页或代码编辑器包成卡片；
- 执行、停止、保存等高频操作固定位置；
- 危险操作与普通主要操作明确区分；
- 终端、代码和数据结果允许使用领域专属底色，但外壳仍遵守全局规范。

### 11.4 制作流程模板

适用：PPT、视频、文档生成和其他多步骤创作。

```text
资源/历史栏 | 步骤与主制作区 | 预览/产物区
```

规则：

- 当前步骤是唯一强选中状态；
- 步骤条、保存状态和主要动作位置保持稳定；
- 配置阶段使用标准密度，预览和编辑阶段可使用专业密度；
- 进行中状态必须显示当前动作和可预期的下一步；
- 不为每个步骤重新设计颜色和标题体系。

### 11.5 设置与管理模板

适用：设置、账户、订阅、技能、MCP 和系统配置。

```text
设置导航 | 页面标题 + 分组内容
```

规则：

- 使用统一 `PageHeader`；
- 表单按语义分组，不默认将每组做成玻璃卡片；
- 一般设置使用行或轻表面，只有独立实体和计划才使用卡片；
- 保存操作使用页内固定位置或分组尾部，不能每个区块各有不同按钮布局；
- 说明、风险和重启要求使用统一 Alert。

### 11.6 洞察模板

适用：画像、成长轨迹、工作模式、系统概览。

规则：

- 使用统一页面标题和范围选择；
- 数据、结论和建议明确分层；
- 指标卡只用于关键聚合数据，不把普通文本卡片化；
- 图表遵守数据色板；
- AI 结论必须与原始数据在视觉上可区分。
- 首屏只允许一个视觉主结论；不得用大号彩色头像、多个彩色胶囊和多张等权卡片同时争夺注意力。
- 洞察页默认使用“一个主摘要面＋若干安静数据区”，而不是彩色 SaaS 仪表盘。
- 数据色按 §4.6 使用蓝、青绿、赭金、紫、玫瑰与橄榄六组低饱和 Token；实际系列少于六个时只取所需颜色，不承担页面品牌表达。

### 11.7 辅助窗口模板

适用：快捷提问、邮件撰写、邮件预览、下载、通知。

- 视觉上仍属于 Mona，但减少主侧栏和主内容表面层级。
- 标题、关闭、主要动作和窗口拖拽区位置统一。
- 透明背景只用于真正悬浮的小窗；普通辅助窗口使用标准表面。

## 12. 共享组件规范

### 12.1 页面标题组件

必须提供并复用：

- `PageHeader`：页面唯一 `h1`、说明、右侧主要动作；
- `SectionHeader`：并列区块标题、说明、局部动作；
- `SubsectionLabel`：字段组、表头、眉题。

业务页面不得复制三者的字号和间距字符串。

### 12.2 按钮

先按 §4.5 选择“强调、普通、轻量、危险”层级，再映射到共享组件变体。视觉层级不等于组件的历史变体名称。

现有变体与目标用途：

| 变体 | 用途 |
|---|---|
| `default` | 历史命名，映射为强调层级；显式用于当前工作区关键动作 |
| `secondary` | 普通层级的浅灰表面动作 |
| `outline` | 普通层级的中性描边动作 |
| `ghost` | 轻量层级，用于工具栏、行内和辅助动作 |
| `destructive` | 危险层级的实心确认；行内危险动作使用共享轻量危险样式 |
| `link` | 导航型文字动作 |

普通层级由共享 Button 的 `interaction` 变体提供，重复危险动作由 `dangerSoft` 变体提供；业务页面不得复制其背景、边框和状态样式。后续如将组件 API 的省略变体改为普通层级，须先迁移依赖历史 `default` 的关键动作调用点。

尺寸：常规主按钮 32–36px 高；专业工具栏紧凑主按钮可以使用 24–28px。文字统一使用 `text-caption` 或 `text-ui`，不因模块改变字号。

规则：

- 默认设计选择普通层级，强调按钮必须有明确任务理由；审查整个可见工作区而非每张重复卡片的 `default` 数量。
- 强调层级使用 `action`：浅色 `#3C3F43`＋`#FCFCFC`，深色 `#EEEEEE`＋`#151515`；深色模式中的大批近白按钮同样属于过度强调。
- 禁用态使用同一语义色的弱化版本，不通过改变字号或高度表达状态。
- 图标统一为 16px，紧凑按钮为 14px。
- 按钮文字统一使用 `text-caption`（12px），不因尺寸、模块或状态改变字号。
- 禁止为普通按钮添加渐变。
- 禁用态必须同时在视觉和交互上禁用，并保持文字可辨。
- 加载态保持原按钮宽度，替换图标但不改变文案布局。

### 12.3 输入框与文本域

- 默认 36px 高、8px 圆角、低对比边框。
- 搜索框、筛选胶囊可使用全圆角；普通表单输入不得全胶囊化。
- 聚焦使用 1px 主题焦点环或边框，不使用双层高对比 ring。
- 错误态包含危险色边框、错误文字和可访问描述，不能只靠红色。
- Placeholder 必须比正文弱，但满足可读性。
- 输入框内图标、清除和快捷键提示使用固定槽位。
- 多行文本域最小 3 行，并允许用户调整高度或提供明确的自动增长。

### 12.4 选择器、组合框和日期时间

- 触发器继承 Input 的高度、圆角和焦点态。
- 菜单项使用统一 32px 行高；当前值和悬停态不得同强度。
- 选项超过 8 个或需要搜索时使用组合框，不使用长下拉菜单。
- 日期和时间优先使用平台能力；复杂日程选择才使用定制组件。

### 12.5 页签

只允许两种：

1. **分段页签**：少量互斥视图，使用低对比容器和内嵌选中面；
2. **线性页签**：专业工具或页面级导航，使用文字＋底部指示线。

一个页面不得混用两种页签表达同一层级。页签高度与所在工具栏一致。

页签文字统一使用 `text-caption`（12px）。选中态保持同字号，通过字重、文字深浅或 1px 指示线表达，不得放大文字或使用整块彩色实心底。

### 12.6 Badge、状态与 Chip

- Badge 表示状态或类别，不作为普通按钮。
- 状态文字使用浅背景＋深文字；避免饱和实心色。
- 数字徽标最小可读，不小于 `text-micro`。
- Chip 只用于筛选、已选对象、文件引用和快捷提示。
- 可删除 Chip 必须有明确删除热区和键盘行为。

### 12.7 卡片

卡片仅用于以下情况：

- 独立实体；
- 可单独选择、拖拽或操作的对象；
- 与周围内容有明确边界的摘要；
- 需要浮于背景之上的模态内容。

以下内容不得默认卡片化：

- 普通设置分组；
- 连续表单字段；
- 编辑器和预览器；
- 列表中的每一行；
- 已经处于主内容表面的整页内容。

卡片只允许三种角色：

| 角色 | 用途 | 视觉规则 |
|---|---|---|
| 工作卡片 | 日程、文件、任务摘要 | 8–10px 圆角、1px 边框、无阴影 |
| 操作卡片 | 可点击入口、模板 | hover 使用前景色 5–6% 透明叠加，不上浮、不缩放 |
| 品牌卡片 | 欢迎、订阅、Agent 状态 | 每屏最多一张；单个 8–12px 切角＋红色信号，可带角色 |

- 卡片内边距使用 16–20px，内部区块间距 12–16px。
- 同一内容链最多两层表面；禁止卡片套卡片、边框套边框。
- 选中状态优先使用文字、边框或 2px 标记，不使用整块蓝色填充。
- 欢迎页品牌卡片是边框规则的明确例外：必须无外围框线和默认阴影。

### 12.8 列表、树和表格

列表：

- 行高使用 32/36/40px 三档；
- 选中、悬停、未读和禁用状态必须不同；
- 行操作默认在悬停和键盘焦点时出现；
- 主文本、次文本和右侧元信息保持固定对齐。

树：

- 每级缩进固定；
- 展开图标、类型图标和文本使用固定列；
- 拖放目标提供表面反馈，不只显示细线。

表格：

- 表格直接铺在主工作表面上，不再额外套厚重卡片；
- 表头高度 36px，普通行 40–44px，单元格左右间距 12px；
- 表头保持低对比；默认只保留横向分隔线，不画完整网格；
- 数字右对齐，文本左对齐，操作列固定宽度；
- 排序、筛选和列宽状态必须可见；
- 行 hover 使用前景色 5–6% 透明叠加；操作按钮仅在 hover 或键盘焦点时出现；
- 选中行使用中性叠加＋左侧短标记；AI 处理、等待确认和错误分别使用青色、琥珀色和语义红状态点；
- 默认不使用斑马纹；仅长数据表允许极弱斑马纹；
- 高密度表格仍不得使用小于 `text-caption` 的主要数据文字；
- 空表、加载和错误显示在表格容器内，不改变页面布局。

### 12.9 工具栏

- 页面主工具栏 44px，专业工具栏 40px，次工具栏 32–36px。
- 图标按钮采用固定尺寸，不根据图标形状改变点击盒。
- 功能组之间用 8–12px 间距或一条短分隔线。
- 左侧放导航/对象，中央放视图或上下文，右侧放动作和状态。
- 不得在工具栏中混用胶囊、方形、纯文字三套无关联按钮风格。

### 12.10 分栏和拖拽柄

- 拖拽热区建议 5–8px，视觉线保持 1px。
- 默认线使用边框色；悬停或拖拽时使用主题色的低透明度版本。
- 面板最小宽度必须保护内容可用性。
- 折叠按钮位置固定，并提供 Tooltip 和快捷键提示。

### 12.11 弹窗、Sheet 和侧滑面板

弹窗：

- 标准圆角 16px；
- 标题使用 `text-title-sm`；
- 默认内容间距 24px；
- 遮罩浅色模式使用低透明黑＋克制模糊，深色模式适度加强；
- 主要动作置右，取消在其左；危险确认必须明确说明影响。

Sheet：

- 适合详情、收集箱、移动端导航和持续辅助任务；
- 不用于只包含一句确认的问题；
- 标题栏、内容区和底部动作区必须固定分层。

### 12.12 菜单、右键菜单、Popover 和 Tooltip

- 菜单与 Popover 使用相同浮层表面、边框、阴影和动效。
- 菜单项行高 32px，图标 14–16px，危险项只在文字和图标上使用危险色。
- 子菜单箭头、快捷键和勾选标记使用固定列。
- Tooltip 延迟出现，不遮挡目标，文字保持简短。
- Tooltip 不能代替字段说明或错误信息。

### 12.13 品牌启动场景

- 启动超过 400ms 时显示专用品牌场景，短启动不闪屏、不人为延长等待时间；
- 使用当前确认的黑猫 Logo、Mona Red 身份信号与 AI Cyan 接通状态，不混用旧卡通猫资产；
- 主文案使用人格化状态“`Mona 正在醒来`”，辅助文案说明真实动作“`正在接通你的工作台`”；
- 持续动画只作用于 Logo 外围轨道、眼部扫描线或 2px 状态信号，不动画大面积背景；
- `prefers-reduced-motion: reduce` 下保留静态状态信息，关闭循环与位移动画；
- 服务就绪立即退出；错误、认证和重试仍使用原有独立状态，不被启动动画遮挡。

### 12.13 Toast、通知和 Alert

- Toast 用于短暂结果，不用于需要用户决策的信息。
- Alert 用于页内持续信息，可分为 info/success/warning/danger。
- 系统通知保持标题、摘要、来源和时间四个固定角色。
- 同一结果不得同时出现 Toast、Alert 和弹窗。

### 12.14 加载、进度、骨架和空状态

加载：

- 小于 400ms 不显示显式加载；
- 局部操作使用按钮内 Spinner；
- 页面首次加载使用贴合最终结构的骨架；
- 不使用一个居中 Spinner 代替复杂页面骨架。

进度：

- 已知进度显示百分比或阶段；
- 未知进度使用循环动画，但同时说明当前动作；
- 长任务必须允许离开页面并保留状态。

空状态：

- 说明为什么为空；
- 给出最多一个主要下一步；
- 可以使用克制的 Mona 角色；
- 不用大面积插画填补空白。

### 12.15 错误状态

- 说明发生了什么、哪些内容受影响、用户能做什么；
- 可重试错误提供明确重试动作；
- 不可恢复错误提供诊断或日志入口；
- 错误不应导致整个应用外壳消失；
- 具体错误信息可复制，但不得默认暴露敏感数据。

### 12.16 AI 输入区

AI 输入区是 Mona 的签名组件，所有对话式入口共享同一语言：

- 大输入区锚定当前工作流的底部或侧面，不随内容任意漂浮；
- 默认中性工作表面、10–12px 圆角和细边框；仅在确需抬起时使用短阴影；
- 附件、工作区、模型和发送位于固定区域；
- 空闲、聚焦、拖入文件、AI 工作、禁用和错误状态必须完整；
- AI 工作态只使用青色 2px 状态线、M 核心或克制呼吸反馈；
- 发送按钮仅在可发送时使用明确主要色；
- 辅助提示不得挤压正文输入高度。

### 12.17 Markdown、代码和文件产物

- 阅读正文使用 `text-body` 或 `text-body-lg`；
- 中日韩正文行高不得低于 1.7；
- 标题、列表、引用、表格和代码的垂直节奏统一；
- 代码使用等宽字体和独立表面，不使用高饱和主题；
- 文件卡、预览、下载和打开动作使用统一附件组件；
- 产物类型可用图标色区分，但文件名和元信息保持语义文字色。

## 13. 交互状态矩阵

每个可交互组件必须实现以下适用状态：

| 状态 | 最低要求 |
|---|---|
| Default | 明确可读、可识别 |
| Hover | 表面或文字轻微变化，不造成布局移动 |
| Active/Pressed | 比 Hover 更明确，反馈时间约 120ms |
| Selected | 可持续识别，强于 Hover |
| Focus-visible | 键盘焦点清晰，不能被 `outline: none` 吞掉 |
| Disabled | 不可操作但仍可读，不只降低到难以辨认 |
| Loading | 防止重复提交并保持组件尺寸 |
| Error | 颜色＋文字/图标双重表达 |
| Drag target | 整个有效区域给出反馈 |

禁止使用只有鼠标悬停才能发现的关键动作；键盘焦点时必须同样可见。

## 14. 可访问性与输入方式

- 正文和背景对比度至少 4.5:1；大文字至少 3:1。
- 交互边界和焦点指示与相邻颜色至少 3:1。
- 默认、指针、拖拽、缩放和调整大小等 cursor 使用系统原生样式，不得全局替换。仅当白色 cursor 在白底上不可见时，改用白色内芯＋1px 黑色外轮廓。
- 键盘可到达所有操作；焦点顺序与视觉顺序一致。
- 图标按钮必须有 `aria-label`，状态变化使用适当的实时区域。
- 颜色不得是状态的唯一表达。
- 触控/笔输入热区不小于 32×32px。
- 支持系统缩放和 Mona 的窗口缩放；可读文字必须使用 rem 字阶。
- 支持 `prefers-reduced-motion`、高对比模式和强制颜色模式。
- 禁止全局移除焦点轮廓，除非提供等效 `focus-visible` 样式。
- 正文、输入、Markdown、代码和用户数据允许选择复制；纯应用外壳可以禁止选中。

## 15. 文案与国际化

- 中文文案简短、直接、说明结果；避免拟人化过度。
- 按钮使用动词或明确结果，如“保存”“继续”“重新连接”。
- 危险动作写明对象，如“删除笔记”，不只写“确定”。
- 空状态说明原因和下一步，不使用无意义的“暂无数据”。
- 中文标点、日期和时间格式统一；时间使用 24 小时制。
- UI 不通过硬编码宽度假设中文、英文和繁体长度相同。
- 文案翻译后必须验证截断、换行和按钮宽度。
- 产品名称、模型名、文件名和代码保持原始文本，不强制翻译。

## 16. 模块落地要求

| 模块 | 页面模板 | 必须统一的重点 |
|---|---|---|
| 新会话/对话 | 首页＋AI 输入 | 保持母版；消息、活动、输入状态一致 |
| 笔记 | 内容工作台 | 工具栏、列表、编辑器、右侧 AI 面板 |
| Markdown 阅读 | 内容工作台 | 大纲、正文、查找、阅读字体 |
| AI 文档 | 制作流程/内容工作台 | 顶部页签、步骤、预览、生成状态 |
| PPT | 内容工作台 | Slides Office 会话、原生编辑、AI 协作与保存导出 |
| 视频 | 制作流程 | 步骤条、资源栏、预览、历史、产物状态 |
| 邮件 | 内容工作台 | 文件夹、列表、阅读、撰写、未读状态 |
| 计划 | 内容工作台/洞察 | 日历工具栏、日期选择、日程状态、收集箱 |
| 终端 | 专业工具 | 标签、会话、分栏、AI 面板、状态栏 |
| 数据库 | 专业工具 | 连接树、SQL 工具栏、结果表、执行状态 |
| IDE | 专业工具 | 文件树、编辑器标签、冲突、状态栏 |
| 浏览器 | 专业工具 | 标签、地址栏、工具栏、下载和错误页 |
| 系统 | 洞察/专业工具 | 页面导航、检查结果、风险和修复动作 |
| 画像 | 洞察 | 标题、范围、图表、原始数据和 AI 结论 |
| 设置 | 设置与管理 | 统一标题、导航、表单、Alert、保存操作 |
| 工作区/产物 | 辅助面板 | 标题栏、类型图标、空状态、预览和删除确认 |
| 快捷提问 | 辅助窗口 | 签名输入区、窗口层级、键盘路径 |
| 通知/下载 | 辅助窗口 | 列表密度、状态、时间、批量操作 |

模块可拥有领域专属内容，但不得重新定义基础控件和视觉变量。

当前业务目录已全部覆盖：`browser`、`db`、`deliver`、`doc`、`email`、`ide`、`md-reader`、`notes`、`notification`、`profile`、`quick`、`schedule`、`settings`、`system`、`terminal`、`thread`、`workspace`；`common` 和 `ui` 属于共享组件层，由第 12、19 节约束。

## 17. 响应式与窗口尺寸

Mona 是桌面优先产品，但必须适应窗口缩放。

### 17.1 基准视口

- 视觉基准：1440×900；
- 最小完整桌面验证：1280×720；
- 窄窗口验证：1024×720；
- 高分屏通过系统缩放验证，不单独复制像素布局。

### 17.2 收缩顺序

空间不足时按以下顺序处理：

1. 隐藏次要文字标签，保留有 Tooltip 的图标；
2. 收起辅助面板；
3. 收起主侧栏为 56px 导航轨；
4. 将次要工具移入“更多”；
5. 最后才允许主要内容横向滚动。

禁止缩小基础文字来容纳更多内容。

### 17.3 页面断点

- 设置页在窄窗口将左侧导航切为顶部横向导航或 Sheet；
- 三栏工作台先关闭右侧辅助栏，再收起左栏；
- 表格保留关键列并允许水平滚动；
- 弹窗宽度使用视口减固定安全边距，不能溢出窗口。

## 18. 性能与实现约束

- 模糊、滤镜和大面积透明层必须控制数量；默认只允许外壳和浮层使用。
- 列表、树和表格中的阴影、滤镜和持续动画必须避免。
- 大列表使用现有虚拟化能力，不以减小行高掩盖性能问题。
- 状态切换不得导致布局跳动。
- 图标和图片必须设置固定尺寸，防止加载后位移。
- 动画只改变 `transform`、`opacity` 或必要的颜色，避免大面积布局重排。
- 不为视觉规范引入新的 UI 框架；优先收紧现有 Tailwind、Radix、CVA 和共享组件。

## 19. 代码规范与质量门禁

### 19.1 共享组件是唯一入口

基础控件必须从 `webui/src/components/ui` 使用。页面不得复制 Button、Input、Tabs、Dialog、Dropdown、Tooltip 等基础实现。

新增的全局视觉能力优先顺序：

1. 已有语义变量；
2. 已有共享组件或变体；
3. 已安装依赖的原生能力；
4. 新增最小命名 Token 或共享变体；
5. 最后才允许业务局部样式。

### 19.2 禁止项

业务 UI 默认禁止：

- 任意字号：`text-[13px]`、`text-[0.8125rem]`；
- 任意产品颜色：`text-blue-500`、`bg-[#4f9de8]`；
- 任意圆角和阴影；
- 重复实现共享控件；
- 用 `outline: none` 移除键盘焦点而不提供替代；
- 为普通布局新增第三方 UI 依赖；
- 在页面内注入大段 `<style>`；
- 仅为“看起来高级”添加玻璃、渐变和动画。

允许例外：

- 数据可视化系列色；
- 终端 ANSI 色、代码语法色；
- 用户内容本身的颜色；
- 品牌图片和文件缩略图；
- 平台原生窗口控件所需固定像素。

例外必须使用命名常量或注释说明，不得散落。

### 19.3 自动检查

应新增最小检查脚本，并接入 `npm run check` 或 CI：

1. 禁止新增任意文字尺寸；
2. 禁止业务目录新增直接色板和 Hex 产品色；
3. 检查核心页面是否仍使用共享组件；
4. 检查可交互图标是否有可访问名称。

检查只阻止新增债务；现有债务通过迁移清单逐步消除，不用一次性重写整个前端。

截图不属于自动代码门禁。基准截图由人工采集和评审，用于判断层级、密度、精致度和跨页面一致性。

## 20. 视觉验收

### 20.1 核心截图矩阵

每个代表页面至少验证：

- 浅色默认态；
- 深色默认态；
- 悬停＋键盘焦点；
- 打开菜单或弹窗；
- 加载态；
- 空状态；
- 错误态；
- 1280×720 和 1440×900；
- 中文和英文。

### 20.2 第一批代表页面

| 页面 | 验证能力 |
|---|---|
| 新会话首页 | 全局视觉母版、应用外壳、签名输入区 |
| 设置 | 页面标题、导航、表单、Alert、弹窗 |
| 笔记 | 多栏工作台、工具栏、编辑器、AI 辅助栏 |
| 数据库 | 专业密度、树、SQL 工具栏、结果表 |
| 邮件 | 列表、阅读、撰写、未读和附件 |
| PPT/视频 | 多步骤流程、生成状态、预览和产物 |

### 20.3 视觉检查清单

- 第一眼是否能识别主操作和主内容？
- 第一眼是否先识别内容与当前任务，而非一排炭黑／近白／实心蓝按钮？强调动作是否有工作区层面的理由？
- 同级列表动作是否使用一致的普通或轻量层级，避免每张卡片各自争夺“主要动作”？
- 普通操作在 Default 状态是否已有可见实体表面和边界？如果去掉鼠标悬停后只剩文字，该控件不算普通按钮，必须修正层级或样式。
- 应用品牌图标是否对应正确产品并保留真实配色，功能图标是否保持中性／激活语义？是否把图标请求成功误当作品牌正确？
- Default、Hover、Pressed、Focus、Loading、Disabled 和完成状态是否清晰，浅／深主题的文字与必要控件边界对比度是否达标？
- 页面是否仍明显属于 Mona？
- 标题、工具栏和内容起点是否与同类页面一致？
- 是否出现无必要的卡片、边框、阴影或彩色背景？
- 去掉该线或框后，如果层级和操作仍然清楚，则必须去掉；是否存在边框套边框或连续多层卡片？
- 是否存在新的任意字号或颜色？
- 悬停、选中和焦点是否有清晰强弱关系？
- 空、加载、错误状态是否维持原布局？
- 中文是否有舒适行高，截断是否保留关键信息？
- 深色模式是否保持层级而不是简单反相？
- 关闭动画后是否仍能理解所有状态？

## 21. 迁移顺序

### 阶段 0：冻结基准

- 冻结中性主题、黑猫身份资产和四个品牌签名元素；
- 建立浅色和深色黄金截图；
- 记录欢迎页、笔记和数据库改造前截图。

### 阶段 1：基础 Token 与组件

- 补齐 80／150／200／650ms 动效档位和品牌状态语义；
- 收紧 Card、Button 与 Table 的已有共享入口，不创建平行组件库；Button 按 §4.5 与 §12.2 建立交互层级和主题状态，保留历史调用兼容，禁止全局改色代替逐页迁移；
- 统一 App Rail 当前项、主内容表面、hover 和焦点样式；
- 只在出现第二个真实使用方时新增页面级共享组件。

验收：共享组件示例页覆盖全部状态，构建和测试通过。

### 阶段 2：三个代表样板

1. 新会话：验证品牌卡片、外壳、Agent 状态与输入区；
2. 笔记：验证内容工作台、无背景工具按钮和 AI 侧栏；
3. 数据库：验证专业工具布局、表格密度与行状态。

验收：三页在浅/深色、两种视口和主要状态下通过截图评审。

### 阶段 3：按模板迁移

- 内容工作台：邮件、Markdown、文档、PPT；
- 专业工具：终端、IDE、浏览器；
- 制作流程：视频；
- 洞察：画像、系统、计划；
- 辅助窗口：快捷提问、通知、下载、邮件撰写和预览。

### 阶段 4：删除旧视觉债务

- 删除被共享组件替代的页面局部样式；
- 消除任意字号和直接产品色；
- 删除重复控件；
- 启用“禁止新增”检查为硬门禁。

不建议一次性全局替换 className。每次迁移一个页面模板，验证后再扩展。

## 24. 最终判断原则

遇到规范未覆盖的 UI 决策时，按以下顺序判断：

1. 当前中性主题和四个品牌签名元素已有同类表达吗？有则复用。
2. 共享组件已有同类能力吗？有则扩展最小变体。
3. 官网或参考产品的做法是否能被翻译为低干扰桌面规则？能则吸收方法，不复制皮肤。
4. 平台原生能力能否满足？能则使用。
5. 最后才新增一个命名清楚、可复用且可验收的规则。

如果一个视觉效果无法说明它改善了层级、可读性、反馈或品牌识别，就不添加。
