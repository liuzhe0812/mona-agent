# 视频导演台与口播动画重设计

日期：2026-10-13。依据用户明确纠偏及当前源码审计。

## 产品目标

Mona 提供风格、基本设置、素材和导演台。用户提出主题后，先看到并调整
旁白、画面和画面如何变化；确认方案后才制作。目标产物是解释口播内容的
动画视频。风格不能把创作限制成固定版式，丰富效果不能变成无意义装饰。

核心流程：描述需求 → 准备分镜 → 导演台调整 → 确认并生成 → 预览修改/导出。

导演台是主编辑界面，制作对话只辅助讨论。用户不用理解场景类型、布局枚举、
品牌套件、动画库或渲染器。只保留一次方案确认，不恢复逐场景审批。

## 已验证的退化原因

| 问题 | 源码/运行证据 | 影响 |
| --- | --- | --- |
| 把主题提交当成直接生成 | 原 VideoMakerView 的提示词要求直接制作；非 config 一律展示 ProducingPhase | 用户无法先确认旁白和导演安排 |
| 导演台被藏成“内容”弹窗 | 原 StoryboardPhase 只挂在次级弹窗；聊天侧栏被称为导演台 | 操作位置与用户心智冲突 |
| 没有接入 Remotion | 原 package.json 无 Remotion；video_authoring.py 只生成 HTML 沙盒 | Remotion 的帧时钟、序列、缓动等能力未提供给 Agent |
| 允许静态产出 | 原技能明确写 Static compositions need no animation | 静态页面可以作为合格场景同步/导出 |
| 简化动画助手并不可靠 | 原 fallback GSAP 没有技能声称的 from；同一时间重复 seek opacity 得到 0.5→0.75 | 导出与预览不稳定，效果契约不真实 |
| 检查不足 | 原 preview 只有 8%、50%、92% 三帧；技术报告没有内容变化检查 | 漏掉动作阶段、执行失败和 PPT 感 |
| 先估时后画面 | 实际配音时间在较晚阶段准备，动画没有实际口播锚点 | 对象动作可能与解释错位 |

这些事实说明旧实现限制了模型能力，不能用“AI 本身质量差”解释全部问题。
目前没有同一模型、同一任务的盲评数据，不能给出“从 60 分提高到 80 分”的结论。

## 参考项目与采用原则

| 一手来源 | 可采用的能力/原则 | Mona 的处理 |
| --- | --- | --- |
| [Remotion Player](https://www.remotion.dev/docs/player/player) 与 [动画规范](https://www.remotion.dev/docs/animating-properties) | 同一 React 组件按帧预览、定位；插值和物理缓动驱动画面 | 提供真正的 Remotion/Player 本地运行时，预览与导出共享组件和时钟 |
| [Remotion 路径](https://www.remotion.dev/docs/paths) 与 [转场](https://www.remotion.dev/docs/transitions/transitionseries) | 路径绘制/变形、分层序列和转场 | 供 Agent 自由编排，不做有限效果菜单 |
| [Huashu Design](https://github.com/alchaincyf/huashu-design) | 轻量分镜、艺术指导、镜头语言和动效批评 | 把动作意图放进分镜，并在生成前供用户确认；不照搬多方向选择流程 |
| [HyperFrames Animation](https://github.com/heygen-com/hyperframes/tree/main/skills/hyperframes-animation) | 动作规则、场景阶段、过渡和不同动画运行时 | 借用内容动作编排方法，不继续扩写自制 GSAP 仿制器 |
| [社区 Remotion 动画样例](https://github.com/Liamrjohnston/remotion-motion-graphics-skill) | 连续空间、对象关系和镜头编排的源码样例 | 用作学习资源；不把仓库自称的“广播级”当质量证据 |

Remotion 的表达能力足以支持当前二维口播动画目标。框架及技能不自动提供
导演判断；把静态页包进组件仍可能得到低质量视频。因此需要同时提供真实
运行能力、口播驱动的动作设计指导、可观察反馈及用户的导演确认。

## 本轮落地

1. 主界面显示导演台：场景列表、标题、时长、画面、画面如何变化、旁白、素材。
   配音默认启用。方案整理与画面生成使用不同状态文案。
2. 确认先等待修改保存，并确认用户看过的分镜版本。版本冲突或保存失败保留
   用户输入并阻止制作。编辑、增删、重排及相关设置改变使确认失效。
   声音、语速和字幕调整保留分镜确认，只更新音频及动画同步检查。
3. Agent 的 plan 只写方案；没有确认动作。audio 返回真实旁白、词/字幕时间；
   sync 只发布已确认方案的 TSX 源码，不能顺便改脚本。长配音/采样后的旧结果
   不会覆盖用户的新分镜。配音自然延长时长不撤销既有方案确认。
4. 新场景是默认导出的 React 组件。实际内置 Remotion、Player、shapes、paths、
   transitions；SVG/Canvas 可用于自由构图。cue(口播短语) 使用实际音频时间。
   无匹配短语或场景执行失败会报错，不会静默截出空白成片。
5. TSX 编译和执行在无同源权限、无网络的 iframe 中。只提供内置模块和已授权
   素材，不在宿主 Node 进程运行生成代码。桌面随 Gateway 交付 JS 运行资源，
   浏览器/FFmpeg 继续使用已有统一运行时。最终编码/旁白混音保留现有实现。
6. 预览采样动作阶段和实际口播时间，返回时间标记的连续画面；字幕不计入
   内容变化。未检查、源码已改或内容始终静止的 Remotion 场景不能导出。
   导出前若重建音频导致检查失效，同样要求重新观察。

新制作路径不用简化 GSAP。旧 HTML 场景和结构化编译器仍用于读取旧项目及
风格预览，当前仍有调用，不能作为弃用代码删除。
已无前端调用的旧逐场景确认接口、客户端函数和辅助逻辑已删除；方案确认
使用新的用户确认入口，旧结果仍可读取。

## 验证与限度

真实浏览器回归验证：口播锚点之前对象不移动；同一帧前后往返结果相同；
路径绘制和弹性动作随帧变化；字幕变化不把静态页判为动画；执行失败明确终止。
前后端回归覆盖只规划、保存/版本冲突、用户确认、确认失效、长任务期间编辑
及后续 Agent 发布。脚本模型用于隔离外部推理，其余工具/服务/文件链路真实。

这些验证证明接口和基础运行能力，不能证明实际模型已经具有稳定的导演水平。
时间点图片不能完整评价连续节奏或听觉体验，交付报告只标记技术检查。

后续质量对照应固定同一模型、口播、素材、风格与时长，分别让无 Mona 流程的
Remotion Agent 和 Mona 新链路完成：流程推进、因果/比较、数据/对象变形。
盲评每个口播点是否有正确动作、变化是否讲清观点、节奏/可读性/连贯性，再
记录成功率、人工修改量、耗时和成本。代码运行和“有动效”不能代替这一评估。

当前实现没有向生成场景提供任意外部 npm 包、3D 引擎或自行声明的附加音轨。
旁白与项目音乐由工作台管理；源视频使用静音画面。扩展这些能力须沿用同一
时间线、安全和混音契约，不能让预览能听到、导出却丢失声音。

发布前核对 [Remotion 官方产品许可](https://convert.remotion.dev/docs/license/faq)
是否覆盖 Mona 的组织规模与自动化产品使用方式；本轮没有发布产品。
