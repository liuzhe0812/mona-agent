# 视频导演台与口播动画重设计

> 2026-10-24 更新：创作资源与运行时已统一为 Huashu Motion。本文涉及 Dashi、旧 huashu-art-motion 或 Remotion 的实现说明仅保留为历史记录；当前边界以 docs/architecture/module-invariants.md 和 docs/plans/video-huashu-motion-replacement.md 为准。
整体改造与后续实施见 [Mona 视频工作台整体改造方案](video-workbench-rebuild.md)。本文保留已有修复和实测记录；新方案的能力以实施与验收结果为准。

日期：2026-10-13。依据用户明确纠偏及当前源码审计。

## 产品目标

Mona 提供风格、基本设置、素材和导演台。用户提出主题后，先看到并调整
旁白、画面和画面如何变化；确认方案后才制作。目标产物是解释口播内容的
动画视频。风格不能把创作限制成固定版式，丰富效果不能变成无意义装饰。

核心流程：描述需求 → 准备分镜 → 导演台调整 → 确认并生成 → 预览修改/导出。

导演台是主编辑界面，制作对话只辅助讨论。用户不用理解场景类型、布局枚举、
品牌套件、动画库或渲染器。只保留一次方案确认，不恢复逐场景审批。

## 已验证的退化原因

| 问题 | 源码/运行证据 | 影响 |
| --- | --- | --- |
| 把主题提交当成直接生成 | 原 VideoMakerView 的提示词要求直接制作；非 config 一律展示 ProducingPhase | 用户无法先确认旁白和导演安排 |
| 导演台被藏成“内容”弹窗 | 原 StoryboardPhase 只挂在次级弹窗；聊天侧栏被称为导演台 | 操作位置与用户心智冲突 |
| 没有接入 Remotion | 原 package.json 无 Remotion；video_authoring.py 只生成 HTML 沙盒 | Remotion 的帧时钟、序列、缓动等能力未提供给 Agent |
| 允许静态产出 | 原技能明确写 Static compositions need no animation | 静态页面可以作为合格场景同步/导出 |
| 简化动画助手并不可靠 | 原 fallback GSAP 没有技能声称的 from；同一时间重复 seek opacity 得到 0.5→0.75 | 导出与预览不稳定，效果契约不真实 |
| 检查不足 | 原 preview 只有 8%、50%、92% 三帧；技术报告没有内容变化检查 | 漏掉动作阶段、执行失败和 PPT 感 |
| 先估时后画面 | 实际配音时间在较晚阶段准备，动画没有实际口播锚点 | 对象动作可能与解释错位 |

这些事实说明旧实现限制了模型能力，不能用“AI 本身质量差”解释全部问题。
目前没有同一模型、同一任务的盲评数据，不能给出“从 60 分提高到 80 分”的结论。

## 参考项目与采用原则

| 一手来源 | 可采用的能力/原则 | Mona 的处理 |
| --- | --- | --- |
| [Remotion Player](https://www.remotion.dev/docs/player/player) 与 [动画规范](https://www.remotion.dev/docs/animating-properties) | 同一 React 组件按帧预览、定位；插值和物理缓动驱动画面 | 提供真正的 Remotion/Player 本地运行时，预览与导出共享组件和时钟 |
| [Remotion 路径](https://www.remotion.dev/docs/paths) 与 [转场](https://www.remotion.dev/docs/transitions/transitionseries) | 路径绘制/变形、分层序列和转场 | 供 Agent 自由编排，不做有限效果菜单 |
| [Huashu Design](https://github.com/alchaincyf/huashu-design) | 轻量分镜、艺术指导、镜头语言和动效批评 | 把动作意图放进分镜，并在生成前供用户确认；不照搬多方向选择流程 |
| [HyperFrames Animation](https://github.com/heygen-com/hyperframes/tree/main/skills/hyperframes-animation) | 动作规则、场景阶段、过渡和不同动画运行时 | 借用内容动作编排方法，不继续扩写自制 GSAP 仿制器 |
| [社区 Remotion 动画样例](https://github.com/Liamrjohnston/remotion-motion-graphics-skill) | 连续空间、对象关系和镜头编排的源码样例 | 用作学习资源；不把仓库自称的“广播级”当质量证据 |

Remotion 的表达能力足以支持当前二维口播动画目标。框架及技能不自动提供
导演判断；把静态页包进组件仍可能得到低质量视频。因此需要同时提供真实
运行能力、口播驱动的动作设计指导、可观察反馈及用户的导演确认。

## 本轮落地

1. 主界面显示导演台：场景列表、标题、时长、画面、画面如何变化、旁白、素材。
   配音默认启用。方案整理与画面生成使用不同状态文案。
2. 确认先等待修改保存，并确认用户看过的分镜版本。版本冲突或保存失败保留
   用户输入并阻止制作。编辑、增删、重排及相关设置改变使确认失效。
   声音、语速和字幕调整保留分镜确认，只更新音频及动画同步检查。
3. Agent 的 plan 只写方案；没有确认动作。audio 返回真实旁白、词/字幕时间；
   sync 只发布已确认方案的 TSX 源码，不能顺便改脚本。长配音/采样后的旧结果
   不会覆盖用户的新分镜。配音自然延长时长不撤销既有方案确认。
4. 新场景是默认导出的 React 组件。实际内置 Remotion、Player、shapes、paths、
   transitions；SVG/Canvas 可用于自由构图。cue(口播短语) 使用实际音频时间。
   无匹配短语或场景执行失败会报错，不会静默截出空白成片。
5. TSX 编译和执行在无同源权限、无网络的 iframe 中。只提供内置模块和已授权
   素材，不在宿主 Node 进程运行生成代码。桌面随 Gateway 交付 JS 运行资源，
   浏览器/FFmpeg 继续使用已有统一运行时。最终编码/旁白混音保留现有实现。
6. 预览采样动作阶段和实际口播时间，返回时间标记的连续画面；字幕不计入
   内容变化。未检查、源码已改或内容始终静止的 Remotion 场景不能导出。
   导出前若重建音频导致检查失效，同样要求重新观察。

新制作路径不用简化 GSAP。旧 HTML 场景和结构化编译器仍用于读取旧项目及
风格预览，当前仍有调用，不能作为弃用代码删除。
已无前端调用的旧逐场景确认接口、客户端函数和辅助逻辑已删除；方案确认
使用新的用户确认入口，旧结果仍可读取。

## 验证与限度

真实浏览器回归验证：口播锚点之前对象不移动；同一帧前后往返结果相同；
路径绘制和弹性动作随帧变化；字幕变化不把静态页判为动画；执行失败明确终止。
前后端回归覆盖只规划、保存/版本冲突、用户确认、确认失效、长任务期间编辑
及后续 Agent 发布。脚本模型用于隔离外部推理，其余工具/服务/文件链路真实。

这些验证证明接口和基础运行能力，不能证明实际模型已经具有稳定的导演水平。
时间点图片不能完整评价连续节奏或听觉体验，交付报告只标记技术检查。

后续质量对照应固定同一模型、口播、素材、风格与时长，分别让无 Mona 流程的
Remotion Agent 和 Mona 新链路完成：流程推进、因果/比较、数据/对象变形。
盲评每个口播点是否有正确动作、变化是否讲清观点、节奏/可读性/连贯性，再
记录成功率、人工修改量、耗时和成本。代码运行和“有动效”不能代替这一评估。

当前实现没有向生成场景提供任意外部 npm 包、3D 引擎或自行声明的附加音轨。
旁白与项目音乐由工作台管理；源视频使用静音画面。扩展这些能力须沿用同一
时间线、安全和混音契约，不能让预览能听到、导出却丢失声音。

发布前核对 [Remotion 官方产品许可](https://convert.remotion.dev/docs/license/faq)
是否覆盖 Mona 的组织规模与自动化产品使用方式；本轮没有发布产品。

## 创作知识与动画库接入（2026-10-14）

按用户要求尽量完整继承 Huashu Art Motion 的创作知识和动画能力。来源固定为
`64cb27271ee0ad3375298e2890b33cbec36d4051`，保留 MIT 许可与适配说明。

- `mona-video/SKILL.md` 全文、`creative-direction.md` 核心设计方法和讲解语法索引
  直接进入视频 Agent 的规划上下文，详细资料继续按需读取。专业知识包括：
  核心方法、35 个艺术配方、9 种讲解语法、镜头/角色/审片经验及设计源码参考。
  按内容目标读取，既不一次塞入所有资料，也不变成前端固定模板菜单。
- 17 个通用绘图库静态适配为独立实例，覆盖材料/笔触、图形变换、镜头、白板、
  动态文字、数据、拼贴、UI 和通用角色。`MotionCanvas` 把逐帧 draw 接入 Remotion
  时间；`createMotionToolkit` 供自由组合。舞台、随机、绘图缓存与素材不污染全局。
- Canvas 只读取工作台授权的场景图片，等待解码后才捕获；每帧清空绘图状态。
  使用实际口播 cue、配色/字体和画幅。旁白混音、确认、预览与导出保持同一链路。
  React/SVG/视频仍可与 Canvas 组合，没有新增技术选择界面。
- 不移植上游模型名称分档、配色禁令、固定镜头/字数配额、强制多方案、独立
  渲染器/下载器或服务配置。字体二进制、作者/Clawd 形象和第三方笔顺数据不随
  这次接入分发。中性角色与用户授权图片可用于自己的动画。
- 预览按整段口播选代表时间点，并提供字幕遮罩后的采样变化区间。静止与变化
  只是技术观察，允许必要的阅读停留；不以快速运动比例替代叙事/审美评价。

本轮验收覆盖完整 source 示例在真实浏览器按口播变化、同一帧反复/倒序定位、
授权图片等待与失败、库实例隔离和后段口播采样。它不等同于真实模型的成片
盲评；制作质量还应按前述相同条件对照衡量，不能预先宣称分数提高。

真实图片回归还发现旧 Remotion 外层 CSP 未允许 data 图片，导致 srcdoc 内层
即使允许图片仍被父策略拒绝。现让内外层统一只允许已嵌入的 data/blob 媒体；
网络与同源权限仍关闭。白板跨库闭包引用也由真实捕帧回归修正。
技能源码读物、TSX 实例与原始 MIT 许可均列入包资源；构建运行时自带许可文本。

UI 对齐：导演台继续使用旁白、画面描述和“画面如何变化”三个用户字段，
一段内容可以包含多个内部镜头。时长支持直接输入，滑块不再把已有长段落
夹到 30 秒；配音与动画检查显示不同进度。风格编辑删除新制作链路不采用的
固定入场/强调/切换选项，只保留整体动画节奏与字幕设置。样式示例明确用于
配色和文字参考，不承诺它就是最终动画，也不增加艺术语法或渲染方式选择。

## 默认配音协议更新（2026-10-14）

7.2.8 的真实请求在代理与直连下均出现 WebSocket HTTP 403，音频尚未开始生成。
上游 7.3.0 增加 Sec-MS-GEC v2，7.3.1 修复本地语言影响服务端日期解析的问题。
后端和旧 Skill 环境依赖统一固定为 7.3.1；已知旧组件提前报组件过旧，不再
把该错误描述为稍后可恢复的临时服务故障，也不替换用户声音。

修复使用相同声音验证：真实 Services 试音 HTTP 200；正式场景合成同步生成
MP3 与 provider-boundary 时间数据；音频通过 FFmpeg 解码。验证在本地隔离
场景完成，不更改用户项目或借用其他产品的运行进程。
依据：[上游协议更新](https://github.com/rany2/edge-tts/releases/tag/7.3.0)、
[日期解析修复](https://github.com/rany2/edge-tts/releases/tag/7.3.1)。

## 从接入能力到实际创作（2026-10-14）

竖屏“决策模型”样片暴露出新的退化：已接入绘图库，但两段实际源码仍以
小角色、分离的示意图和循环微动为主。制作记录只读取通用动效和运行时资料，
未读取 Huashu 的详细讲解语法；发现长静止区间后增加呼吸和闪光，再以技术
计数宣称动作丰富。第一段时长 30 秒，最后口播边界为 18.55 秒，尾段有
11.45 秒没有口播。时间点图片还暴露了主体太小、路线被字幕遮挡和文字断行。
这些是该样片的观察，不能推导所有模型或所有题材的制作水平。

改进保持现有导演台和一次确认，只调整 Agent 的设计上下文与审片反馈：

- 规划前直接提供对象身份、因果动作、连续变化、观看尺度和阅读停留的核心
  方法，以及可选讲解语法；不依赖 Agent 偶然打开全部参考文件。
- 核心方法用于先形成导演方案，设计卡按需补充理解；详细源码和运行时 API
  放在用户确认后的实现阶段读取。避免把通读大段引擎代码变成准备分镜的前置任务。
- 详细配方和源码按题材选读，保留自由构图、角色表现和镜头设计。样片数值、
  一句一镜、固定配色与帧库要求不会变成 Mona 的通用创作限制。
- 预览返回口播覆盖及末尾无口播时间，并区分服务返回边界和估算时间；长停顿
  可用于阅读或过渡，工具不擅自缩短已确认的场景。
- 预览补充 DOM/SVG 文本字号、与当前字幕框的相交情况，以及源码中没有回退值
  且任何实际样式作用域都未定义的 Mona 颜色变量。Canvas 绘制的文字、变换后
  的实际可读性和变量作用域误用仍需看图判断，这些观察不能作为完整布局检查。
- 原生预览图像旁直接提醒按时间点检查“对象发生什么变化、解释哪句口播”，
  不得用像素变化数量、消除静止区间或增加循环微动替代创作验收。

必要回归覆盖实际规划上下文、跨进程预览契约、口播时间数据和真实浏览器捕帧。
独立 Agent 用新资料复核原样片，能提出保留选项身份、实际选择与后果、同对象
整理成比较结构的分镜修订。它只验证资料对设计行为的帮助，未生成新成片；
是否稳定提升制作质量，仍须通过相同条件的成片对照与盲评确认。

继续验收发现配音词级边界实际保存在每个字幕 cue 的 `words` 中，而动画
`cue(phrase)` 只读取顶层 `words`，导致多个短语回退到同一句的起点。真实
样例因此出现 Remotion 时间区间不递增错误。现优先读取顶层或逐句词级数据，
没有词级数据时才使用整句边界；保留同一份生成代码重新预览后报错消失。
回归在真实浏览器中验证同一句的两个短语分别使用各自的词级时刻。

真实画面还暴露了未解析的 SVG 路径表达式和字幕单字尾行：预览补充相应
路径观察与字幕行宽，字幕使用平衡换行，并利用词级数据保持词组完整。制作对话错误也改为使用
现有错误弹窗，保留已有预览，并通过“继续制作”继续整片任务；关闭后普通
刷新不重复弹出相同错误。

实际验收使用隔离项目、当前选择的原生 Codex 模型 `gpt-6.1-sol` 和 `xhigh`
推理设置，保留原开场旁白、30 秒竖屏和声音。规划保存后停止，确认前音频
请求被拒绝，确认后完成真实配音、生成、实际帧审片和多次修订；修订保持
计划及确认版本为 1。最终观察无未定义变量、未解析路径或字幕与正文相交。

真实浏览器完整播放到 30 秒：2 秒和 10 秒时，旁白未静音且时间随播放推进；
音频在 19.44 秒结束，画面继续完成剩余阅读/收束，30 秒时正常停止并提供
重新播放。未出现媒体或场景执行错误，音频也通过解码检查。这证明当前
样例的播放链路，不代表已听审音质或对所有题材完成艺术质量认证。

前两次探测缺少测试样例的会话绑定，以及一次检查误用了确认错误的状态码，
不能计入产品可靠性结果。当前样例经历了运行时修复和多轮创作修订；没有
同模型的原链路对照或随机重复，不能据此宣称质量分数、可靠性或效率提升。

最终导出也通过真实文件验证：30 秒、1080×1920、30 fps 的 H.264 MP4，
包含 24 kHz 单声道 AAC 音轨，音轨约 29.995 秒。独立检查确认音频可解码且
非静音（均值 -27.3 dB，峰值 -3.4 dB）；交付包同时生成字幕、封面与技术
报告。这里的技术通过不代表艺术质量通过，也未验证用户当前客户端已加载
本工作区修改。
