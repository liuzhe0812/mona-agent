# 股票深度投研 V2 功能设计

状态：开发基线  
日期：2026-08-19  
适用范围：A 股单股六 Agent 深度投研、投研报告、关注雷达和结果追踪

## 1. 改造结论

深度投研从“六 Agent 生成一篇单周期长报告”改为“基于同一份可追溯证据，分别给出短线、中线、长线条件式判断的决策系统”。

本方案沿用现有 `EvidenceService`、WorkflowRun、Artifact、六步工作流、报告查询和 StockView，不建立第二套股票编排器、状态存储或报告系统。

## 2. 产品目标与边界

### 2.1 目标

一次深度投研必须回答：

1. 当前市场环境是否支持参与该标的。
2. 短线、中线、长线分别由什么驱动，结论是否一致。
3. 行业、政策、四类周期和公司相对同行处于什么状态。
4. 当前价格已反映哪些预期，仍有什么预期差。
5. 满足什么条件才可参与，什么事实会确认、削弱或否定判断。
6. 数据是否足够、来源是否可靠、结论能否复核。
7. 报告发布后发生了什么变化，原判断是否仍成立。

### 2.2 固定边界

- 默认突出中线；短线负责时点和交易风险，长线负责价值锚定。
- 三个周期独立裁决，不生成掩盖冲突的“综合观点”。
- 首版只输出条件式研究动作，不输出确定性买卖指令和个性化仓位。
- 数据不足输出 `insufficient_data`，不得回退为 `neutral`。
- 多空辩论作为内部质检，不把完整辩论作为主页面。
- A 股分析师只能建议用户启用深度投研，未经用户确认不得自动启动。
- 不增加 Agent 数量，不引入新编排引擎，不为单页增加重型依赖。

### 2.3 首版不做

- 自动交易、账户接入、组合仓位优化。
- 无法由公开数据验证的“量化控盘”判断。
- 未经校准的精确情景概率、目标价或黑盒总分。
- 为补齐字段而使用模型猜测、媒体传闻或无来源数字。

## 3. 用户流程

```text
快速分析/普通对话
  → 系统说明深度投研能补充的维度与当前数据缺口
  → 用户明确确认
  → 数据质量预检
  → 生成不可变 EvidenceBundle
  → 三路周期研究
  → 多空反证
  → 三周期裁决
  → 决策卡 + 证据详情
  → 关注雷达持续监控条件和事件
  → 事后结果校准
```

预检必须在运行前说明每个周期能否形成有效判断。缺少某周期的核心证据时，该周期仍可参与工作流，但最终只能输出 `insufficient_data`。

## 4. 三周期定义与输出

时间范围是产品口径，不是收益承诺：

| 周期键 | 产品口径 | 核心问题 | 主驱动 |
|---|---|---|---|
| `short_term` | 1—10 个交易日 | 现在是否有可交易的时点优势 | 市场情绪、板块、资金、量价、事件、可交易性 |
| `medium_term` | 2 周—6 个月 | 预期是否处于持续上修或下修 | 行业景气、政策兑现、盈利预期、资金风格、趋势 |
| `long_term` | 6 个月以上 | 企业价值和竞争力能否持续增长 | 商业模式、现金流、资本配置、治理、行业生命周期、估值 |

每个周期使用相同的结构化输出：

```json
{
  "stance": "positive | neutral | negative | insufficient_data",
  "thesis": "该周期的一句话判断",
  "drivers": [],
  "priced_in": "尚未反映 | 部分反映 | 充分反映 | 无法判断",
  "priced_in_basis": {"claim_type": "inference", "basis": "...", "source_ids": []},
  "benchmark": {
    "name": "所属行业指数或宽基指数",
    "instrument_id": "XSHG:000985 | null",
    "relative_view": "强于 | 接近 | 弱于 | 无法判断",
    "basis": "Evidence 中的相对比较依据",
    "source_ids": []
  },
  "action": "observe | wait_for_confirmation | conditional_participation | reduce_exposure | not_applicable",
  "participation_conditions": [],
  "confirmation_conditions": [],
  "watch_conditions": [],
  "invalidation_conditions": [],
  "time_stop": "未在规定窗口兑现时如何处理",
  "tradeability_risks": [],
  "evidence_strength": "low | medium | high",
  "data_status": "complete | degraded",
  "missing_fields": [],
  "source_ids": []
}
```

`action` 是研究状态，不是个人投资建议。缺少用户资产、持仓和风险偏好时不得输出仓位比例。

## 5. 证据与时间模型

### 5.1 时间字段

现有 `as_of` 混合了研究截止时间和最近收盘时间，V2 必须拆开：

| 字段 | 含义 |
|---|---|
| `research_cutoff_at` | 本次研究允许使用信息的最晚公开时间 |
| `market_as_of` | 行情或 K 线的最近观测时间 |
| `published_at` | 公告、新闻或报告首次公开时间 |
| `period_end` | 财务或行业数据对应的统计期末 |
| `fetched_at` | 系统取得数据的时间 |

所有可用于结论的数据必须满足其公开可得时间不晚于 `research_cutoff_at`。`period_end` 不能代替 `published_at`。无法确认历史公开时间的数据不得进入历史回放。

旧报告继续只读兼容；新报告使用新字段，前端分别显示“研究截止”和“行情截至”。

### 5.2 证据声明类型

关键观点必须分类：

- `fact`：原始数据或正式来源直接表达的事实。
- `inference`：由已列事实通过透明规则推导的判断。
- `hypothesis`：尚未证实、等待验证的假设。

每条声明至少包含 `claim_type`、`text`、`source_ids`。推断还必须包含 `basis`；没有来源的假设只能进入待验证问题，不能成为确认条件或核心结论。

### 5.3 数值和阈值

报告中的价格位、比例和阈值只能来自：

1. EvidenceBundle 中的原始字段；或
2. 带 `method`、`version` 和输入字段的确定性计算。

结构化 trigger 必须用不同的 `observed_metric_ref` 和来自 Evidence 的
`threshold_metric_ref`（例如 `quote.price` 对 `indicators.swing.support` 或
`indicators.swing.resistance`）；不接受模型直接提交的裸 `threshold`，也不接受没有
`metric_ref`/`method_ref` 的数值型条件。自由文本条件只能作为人工观察项，关注雷达不得把它伪装成自动触发。

## 6. 分析维度与四周期

EvidenceBundle V2 在现有行情、K 线、财务和资讯之外，按可用性增加以下命名分区：

| 分区 | 最低内容 | 主要用途 |
|---|---|---|
| `market_regime` | 宽基/风格强弱、市场宽度、成交额、波动、涨跌停生态 | 短线风险环境、中线风格 |
| `industry_context` | 行业分类、行业相对强弱、宽度、同行对比、产业链位置 | 中线、长线 |
| `policy_context` | 正式来源、政策阶段、传导链、受益/受损对象、兑现窗口 | 中线、长线 |
| `cycle_context` | 宏观流动性、行业供需、公司盈利、市场风格四类周期 | 全周期 |
| `company_quality` | 多期财务、现金流质量、资本开支、治理、融资和稀释 | 长线 |
| `capital_positioning` | 换手、融资余额、ETF/公开资金、减持、解禁、质押 | 短线、中线 |
| `event_calendar` | 财报、政策、解禁、减持、产品价格、重大事项 | 短线、中线 |
| `tradeability` | 流动性、滑点代理、涨跌停距离、T+1、跳空风险 | 短线 |

四类周期分别输出阶段、领先指标、确认指标、转折条件、观察窗口和数据可信度：

1. `cycle_states.policy`：宏观与流动性周期。
2. `cycle_states.industry`：行业供需与产品价格周期。
3. `cycle_states.earnings`：公司盈利与现金流周期。
4. `cycle_states.valuation`：市场风格与筹码周期（不是重复估值维度）。

无法从免费正式来源取得的行业库存、产能、产品价格或机构一致预期必须标记缺失。允许用公司公告、业绩预告和多期财务趋势形成透明代理，但必须标记为 `inference`。

## 7. 周期数据门槛

| 周期 | 必需分区 | 缺失处理 |
|---|---|---|
| 短线 | 行情/K线、`market_regime`、行业相对强弱、`tradeability` | 任一核心分区不可用则 `insufficient_data` |
| 中线 | 行业、政策/事件、行业或盈利周期、相对基准 | 行业与周期同时缺失则 `insufficient_data` |
| 长线 | 多期财务、`company_quality`、行业生命周期、同行/历史估值 | 公司质量或多期财务缺失则 `insufficient_data` |

资讯条数、Agent 文本长度和单期财务快照不能提高数据完整度。数据门槛由确定性服务判断，裁决 Agent 只能读取结果。

## 8. 六 Agent 职责

保留现有六步 DAG，替换分析职责：

```text
同一份 EvidenceBundle V2
  ├─ 市场与交易 Agent：短线环境、资金、情绪、量价、可交易性
  ├─ 行业与周期 Agent：政策、行业供需、四周期和中线预期修正
  └─ 公司与估值 Agent：公司质量、竞争力、现金流、治理和长期估值
       ↓
  多方 Agent / 空方 Agent：分别对三个周期构建最强论证和反证
       ↓
  裁决 Agent：逐周期裁决 + 周期冲突解释 + 三情景
```

当前技术、资讯、基本面 Agent 的内部 ID 可以保留以兼容现有运行记录；仅调整名称、Prompt、Skill 和结构化产物职责。

多空输出不得引入上游 EvidenceBundle 之外的新事实。裁决 Agent 不平均三个周期，也不得把 `insufficient_data` 改成 `neutral`。

## 9. 情景、报告和页面

### 9.1 情景

每个周期可包含乐观、基准、悲观三种情景：条件、主要结果方向、关键风险和来源。首版不输出未经历史校准的精确概率。

### 9.2 报告 V4

新报告增加：

- `research_cutoff_at`、`market_as_of`
- `horizon_views.short_term|medium_term|long_term`
- `dimension_views`：`market_environment`、`industry`、`policy`、`cycle`、
  `company_quality`、`valuation`、`capital_positioning`、`event_risk` 八个独立结论；
  每项按 `facts`/`inferences`/`hypotheses` 输入，`points` 由三栏确定性合并。
- `debate_resolution`：短线、中线、长线各一份核心分歧、双方论据、裁决理由和改变结论条件；
  available 时论据必须带来源，缺失必须披露。
- `cycle_states`
- `market_regime_summary`
- `industry_policy_summary`
- `scenario_sets`
- `cross_horizon_conflict`
- `evidence_coverage`
- `outcome_tracking_id`
- `event_calendar`（可选）：由 submit 工具从当前 Evidence 注入，不接受模型改写；保留
  `status`、事件的 `event_type`、`title`、`published_at`、`event_date`、`status`、`url`、
  `source_ids` 和 `missing_fields`。只注入研究截止前通过时点校验的事件；无 `event_date`
  不得标为 `upcoming`，旧 V4 报告可没有此字段。

基准只有在 Evidence 的 `relative_benchmarks` 项中能核验明确的 `instrument_id` 时才可填写
代码；`relative_view` 非 `unknown` 时，`basis`/`source_ids` 必须来自匹配项，并且必须有
与当前周期匹配、状态明确为 `available`/`degraded` 的窗口；证据不足只能为 `unknown`。
`priced_in` 非 `unknown` 时必须提供带 `basis` 与来源的 `priced_in_basis`；系统不按基准名称
猜代码，也不接受裸数值阈值。

旧的 `research_stance`、`time_horizon` 仅用于旧报告兼容，不再作为 V4 主结论。

### 9.3 第一屏决策卡

第一屏只显示：

1. 三周期观点与数据状态。
2. 默认展开的中线主结论。
3. 市场环境、行业/政策、四周期摘要。
4. 相对基准和已计价程度。
5. 参与、确认、失效和时间退出条件。
6. 可交易性风险和关键数据盲区。

原“报告”内容改为按维度展开的证据详情。多空辩论只展示核心分歧、裁决理由和改变结论的事实，不展示冗长过程。

### 9.4 关注雷达

右侧栏继续支持展开/收起，只承担报告后的增量监控：

- 与上次报告相比发生的变化。
- 结构化条件是否触发或接近。
- 即将发生的事件。
- 报告数据是否过期。
- 是否建议用户重新启动投研。

不重复完整投研结论，不自动判定自由文本条件。

## 10. 结果追踪

每份 V4 报告保存不可变的研究截止时间、三周期结论、条件、基准和证据版本。后续只追加结果记录，不回写原报告。

结果回放采用可实现且无未来数据污染的统一口径：报告日期后的第一个完整交易日开盘作为观察起点，第 N 个交易日收盘作为窗口终点；MFE/MAE 使用窗口内最高/最低价。停牌、零成交或缺少交易日时标记数据不完整，不前向填充。

跨报告公共市场基准使用中证全指（`XSHG:000985`）计算相对市场收益；报告中声明的行业或风格基准另行保留，只有存在可核验代码且日期对齐时才计算对应相对收益。不得根据基准名称猜测指数代码。

| 周期 | 默认观察窗口 | 最低指标 |
|---|---|---|
| 短线 | 5/10 个交易日 | 相对基准收益、MFE、MAE、条件触发 |
| 中线 | 20/60 个交易日 | 相对行业收益、催化兑现、逻辑失效 |
| 长线 | 120/250 个交易日 | 相对收益、基本面里程碑、假设兑现 |

统计必须防止未来数据污染，区分“观点正确”和“可交易结果可实现”。积累足够样本前只展示统计，不训练权重或声称预测优势。

校准页默认只读取本地追踪记录，不在应用启动时批量请求外部行情。用户点击“更新结果”后才通过现有免费 K 线 Provider 补算已成熟窗口并追加记录，避免每次启动长时间刷新和无谓占用免费接口。

## 11. 免费数据与降级原则

- 公司公告、监管和政策优先使用交易所、证监会、政府部门及上市公司正式披露。
- 行情、K 线和可公开取得的市场数据继续通过现有薄 Provider 与来源记录进入系统。
- 每个新增分区先完成来源、字段、时间语义、频率、限流和稳定性验证。
- 无稳定免费正式来源的字段保持缺失，不增加付费依赖，不用抓取结果冒充正式数据。
- 商业发布前仍需单独确认数据授权；免费可访问不等于可用于商业再分发。

## 12. 全局验收标准

- [ ] 新报告同时包含三个独立周期结论，允许观点冲突。
- [ ] 核心证据公开时间均不晚于 `research_cutoff_at`。
- [ ] 研究截止和行情截至在数据与 UI 中分离。
- [ ] 关键声明可区分事实、推断和假设并追溯来源。
- [ ] 无模型自由生成的数值阈值或目标价。
- [ ] 三个周期分别执行确定性数据门槛。
- [ ] 行业、政策和四周期不是新闻标题占位，而有字段和数据质量。
- [ ] 右侧栏只展示增量监控，不重复报告。
- [ ] 旧报告和旧运行记录仍可读取。
- [ ] 深度投研保持用户主动触发。
- [ ] 每份新报告可进入事后追踪且原报告不可被结果回写。
