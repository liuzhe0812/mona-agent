# AI 文档模块设计方案

> 日期:2026-07-08
> 状态:方案设计,待实施
> 范围:将孤立的 PPT 模块泛化为"AI 文档"聚合模块,下设 PPT / 视频 / 流程图三个子类型

## 一、背景与动机

### 1.1 现状问题

当前 PPT 作为主菜单独立模块存在,后端有专属的 [ppt_loop.py](../mona/agent/ppt_loop.py) / [ppt_context.py](../mona/agent/ppt_context.py),前端有独立的 `PptMakerView`。这造成两个问题:

1. **模块孤立**:PPT 是唯一建成的复杂文档工作流,视频、流程图等同类需求没有归属
2. **架构技术债**:`agent_kind` 路由在 [websocket.py:3587](../mona/channels/websocket.py#L3587) 硬编码校验只允许 `"ppt"`,委派在 [loop.py:1195](../mona/agent/loop.py#L1195) 硬编码 `if agent_kind == "ppt"`,每新增一个类型都要改核心代码

### 1.2 抽象依据

PPT / 视频 / 流程图本质都是"文档",选这三个作为独立子模块的统一标准是:**管线较长 + 技术路径复杂 + 需要交互**。普通文档(总结、邮件、笔记)走通用对话即可,这三个需要专属工作流 + 专属编辑器壳 + 专属渲染后端。

### 1.3 目标

- 前端:主菜单"PPT制作"升级为"AI文档",顶部 tab 切换 PPT / 视频 / 流程图
- 后端:把 `PPTAgentLoop` 泛化为 `DocumentAgentLoop`,按 `agent_kind` 声明式加载 profile(soul prompt / skill / 工具白名单),核心代码不再为每个类型加 if 分支
- 新增两个 skill:mona-video(Hyperframes)、mona-flowchart(draw.io)

## 二、技术选型

### 2.1 子模块选型表

| 子模块 | skill 产物 | 预览器 | 渲染后端 | 二次编辑 |
|--------|-----------|--------|---------|---------|
| PPT | SVG 逐页 | WebView2 + SVG | svg_to_pptx.py | SVG 编辑器(已有) |
| 视频 | HTML + GSAP | WebView2 直接加载 HTML | Hyperframes render → MP4 | 代码编辑 |
| 流程图 | draw.io XML (mxGraph) | draw.io 嵌入 | 直出 SVG/PNG | draw.io 原生编辑器 |

### 2.2 视频:Hyperframes

**选型**:Hyperframes(HeyGen,2026.4 开源),放弃 Remotion。

**理由**:
- **Write HTML, Render video** — 产物是 HTML + CSS + JS + GSAP,agent 最熟悉,生成质量稳定
- 时间轴用声明式 `data-start` / `data-duration` + GSAP timeline,与 PPT 的 SVG + GSAP 心智模型同构,skill 可大量复用 mona-ppt 的执行范式
- 预览器零成本:产物就是 HTML,WebView2 直接加载即可,不需要额外运行时
- 渲染依赖:Node 22+ + FFmpeg + Chromium(走系统 Edge,缺失则延迟下载)
- 设计哲学对齐:Hyperframes 明确"面向 coding agent"

**与 Remotion 的取舍**:Remotion 时间轴精度更高(useCurrentFrame 确定性帧级控制)、生态更成熟,但要求 agent 写 React/TSX,语法约束多且与现有 SVG 工作流异构。对 Mona 视频模块定位(产品预告 / 数据可视化 / 社交短片),Hyperframes 的 agent 友好度优势更关键。

### 2.3 流程图:draw.io

**选型**:draw.io(diagrams.net),走 C 路线(agent 生成 + 用户可二次编辑)。

**理由**:
- 用户明确要求保证质量,draw.io 的自动布局算法成熟,编辑器功能完备
- mxGraph XML 虽然冗长,但格式开放、生态成熟,agent 可学习生成
- 嵌入方案:draw.io 的 web 嵌入版本可集成进 WebView2

**mxGraph XML 的 agent 生成策略**:
- agent 不直接手写 XML,而是生成逻辑描述(节点 / 边 / 层级)→ 由 `auto_layout.py`(dagre/elkjs)算坐标 → 转换为 mxGraph XML
- 这样既保证布局质量,又降低 agent 的 token 消耗和出错率
- 用户在 draw.io 中编辑后,XML 可被 agent 读取并理解(双向兼容)

**放弃 Excalidraw 的原因**:用户明确要求保证质量,draw.io 的自动布局和编辑器完整度优于 Excalidraw。

### 2.4 渲染后端:WebView2 的定位

**核心结论**:WebView2 不替代 headless Chromium 用于视频渲染,只用于预览。

- **预览**(WebView2 内):PPT 的 SVG 逐页预览、视频的 HTML 直接加载、流程图的 draw.io 嵌入
- **渲染后端**:视频导出走 Hyperframes render(需 headless Chromium + FFmpeg),PPT 导出走 svg_to_pptx.py(纯 Python),流程图直出 SVG/PNG

**视频渲染的 Chromium 来源**:
1. 优先复用系统已装的 Edge/Chrome(Windows 10+ 基本预装 Edge)
2. 缺失时延迟下载 Chrome Headless Shell(~170MB)到 `<userData>/runtime/chrome-headless-shell/`
3. 前端提示:"未检测到所需的 Edge/Chrome 浏览器,需要下载 Chrome Headless Shell(约170MB),是否继续?"

### 3.3 DocumentAgentLoop

`PPTAgentLoop` 泛化为 `DocumentAgentLoop`,构造时传入 `agent_kind`,从 profile 加载配置:

```python
class DocumentAgentLoop(AgentLoop):
    def __init__(self, *args, agent_kind: str, **kwargs):
        super().__init__(*args, **kwargs)
        self._profile = DOCUMENT_PROFILES[agent_kind]
        self.context = DocumentContextBuilder(
            self.workspace,
            profile=self._profile,
            timezone=self.context.timezone,
        )
        self._filter_tools_to_whitelist(self._profile.tools_whitelist)
```

### 3.4 DocumentContextBuilder

`PPTContextBuilder` 泛化为 `DocumentContextBuilder`,soul prompt 和 skill 名从 profile 读取,不再硬编码:

- `build_system_prompt`:渲染 `profile.soul_template` + `agent/tool_contract.md` + `profile.skill_name` 对应的 skill(强制 always-on)
- `_load_bootstrap_files`:返回空串(不加载 SOUL/USER/AGENTS)
- `build_messages`:构建 `[system, *history, current]`,不注入 memory

### 3.5 loop.py 委派点泛化

```python
# loop.py _process_message
agent_kind = session.metadata.get("agent_kind")
if agent_kind and agent_kind in DOCUMENT_PROFILES:
    doc_loop = self._ensure_document_loop(agent_kind)
    return await doc_loop._process_message(msg, ...)
```

`_ensure_ppt_loop` → `_ensure_document_loop(agent_kind)`,按 kind 缓存多个实例:

```python
def _ensure_document_loop(self, agent_kind: str) -> AgentLoop:
    cache_key = f"_doc_loop_{agent_kind}"
    cached = getattr(self, cache_key, None)
    if cached is not None:
        return cached
    from mona.agent.document_loop import DocumentAgentLoop
    loop = DocumentAgentLoop(
        bus=self.bus, provider=self.provider, ...,
        agent_kind=agent_kind,
    )
    setattr(self, cache_key, loop)
    return loop
```

## 六、视频模块的 Edge 检测与延迟下载

### 6.1 检测流程

```
用户首次创建视频项目
  → 后端 check_edge.py 检测系统 Edge/Chrome
  → 命中:记录路径,后续渲染直接使用
  → 未命中:前端弹出提示
     "未检测到所需的 Edge/Chrome 浏览器,需要下载 Chrome Headless Shell(约170MB),是否继续?"
     → 用户确认
     → 下载到 <userData>/runtime/chrome-headless-shell/
     → 后续渲染用此路径
     → 用户拒绝:视频渲染功能不可用,仅可预览 HTML
```

### 6.2 检测策略

- Windows:查找注册表 / 默认安装路径的 Edge 和 Chrome
- macOS:查找 `/Applications/Microsoft Edge.app` 和 `/Applications/Google Chrome.app`
- 缓存检测结果,避免每次渲染重复检测

### 6.3 下载源

- Chrome Headless Shell 官方下载地址
- 校验文件签名 / hash
- 下载进度通过 WebSocket 推送到前端

## 八、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| Phase 1 泛化引入 PPT 回归 bug | PPT 功能不可用 | 保留 ppt_loop.py / ppt_context.py 直到 Phase 2 验证通过后删除;Phase 1 用 DocumentProfile 保证配置等价 |
| Hyperframes 生态年轻(2026.4 开源) | 视频渲染稳定性 | scripts/ 封装层隔离 hyperframes CLI,出问题可替换底层而不动 skill 工作流 |
| draw.io mxGraph XML 对 agent 不友好 | 生成质量低 | agent 不直接写 XML,走"逻辑描述 → auto_layout → build_xml"三步,降低出错率 |

| 视频渲染耗时长 | 用户体验差 | draft 质量预览(--quality draft),确认后出 high 质量;进度通过 WebSocket 推送 |
| 打包体积 | 违反自包含原则 | Chrome Headless Shell 延迟下载,不打入安装包;FFmpeg 走 hyperframes 依赖,不单独打包 |

## 十、决策记录

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 模块划分标准 | 按复杂度+交互性,不按格式 | 普通文档走通用对话,只有复杂工作流才独立 |
| 视频技术 | Hyperframes | agent 写 HTML 比 React 自然,与 PPT SVG 工作流同构 |
| 流程图技术 | draw.io(C 路线) | 用户要求保证质量,draw.io 布局和编辑器更成熟 |
| Chromium 来源 | 系统优先,延迟下载 | 不增加打包体积,首次使用按需下载 |
| 前端入口形态 | 顶部 tab 切换 | 用户指定 |
| 泛化方式 | DocumentProfile 声明式配置 | 核心代码不为每个类型加 if 分支,符合"核心精简"原则 |
