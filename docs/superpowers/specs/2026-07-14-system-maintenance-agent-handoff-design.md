# 系统维护失败交给 Mona 设计

## 目标

当系统维护模块中已有的固定操作失败时，用户可在原报错区域点击“交给 Mona”。Mona 在右侧系统管家区域接管本次任务、直接执行并复核，而不是仅给出处理建议。

## 保留的现有行为

- 右侧系统管家默认仍是现有的系统证据规划与受控执行界面。
- 固定操作继续走当前实现；本功能只处理其失败结果，不增加预先重试或备用命令。
- 主聊天区不跳转、不接收该任务。

## 交互与数据流

1. 固定操作失败时，现有报错区域显示“交给 Mona”。
2. 点击按钮即视为用户对这一次任务的明确授权。
3. 主系统视图创建一个交接任务，包含操作名称、目标、已传参数和错误原文。
4. 右侧系统管家展开并切换到 Agent 对话模式，在自己的系统维护会话中发送结构化任务。
5. 提示词要求 Mona 直接接管、执行、复核并报告真实结果；不允许只输出操作步骤。
6. 用户可在右栏继续追问，或返回原有系统规划界面。

## 范围

覆盖系统维护内当前固定操作的失败路径：存储扫描和清理、软件更新和卸载、启动项开关。读取类失败也可提交为诊断任务，但不伪造可执行目标。

每条交接任务使用同一格式：

```text
系统维护固定操作失败。请直接接管并完成任务，而不是只说明步骤。
操作：<action>
目标：<target>
参数：<arguments>
错误：<error>
完成后复核实际状态，并如实报告执行结果。
```

## 实现边界

- 复用现有嵌入式 Agent 会话、流式消息和工具执行能力；不新增后端执行接口或前端备用命令。
- 右栏增加最小的“规划 / Agent 执行”状态切换；只有交接任务或用户主动进入对话时切换。
- 交接任务在系统视图中提升状态后传给右栏，避免面板之间直接耦合。
- 不修改系统维护动作的权限、确认和执行语义；“交给 Mona”只是针对失败动作的显式再次授权。

## 验证

- 每个失败提示展示“交给 Mona”。
- 点击后任务留在右栏，且不切换主聊天区。
- Agent 收到的任务包含失败操作的真实目标和错误文本。
- 原系统规划界面在未交接时保持可用，且可以从 Agent 对话返回。
