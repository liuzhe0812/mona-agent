# 浏览器原生功能菜单设计

## 目标

点击浏览器工具栏的“选项”时，保持当前网页子视图可见且可交互；同时让无痕标签使用底层 WebView 的真实无痕会话。

## 已确认的约束

- 外部网页由 Windows 子 WebView 承载。HTML 下拉层无法可靠覆盖它，因此当前实现通过 `hide()` 避让，造成网页区域短暂空白。
- Tauri 2.11.2 已提供 `WebviewBuilder::incognito(bool)`，可直接将已有的 `is_incognito` 状态传到底层 WebView。
- 当前功能菜单的动作均为前端回调；无需增加 IPC 命令或权限。

## 范围

1. 将工具栏“选项”菜单替换为 Tauri 原生菜单，并复用现有菜单项及其回调。
2. 菜单打开或关闭不再通知 `BrowserTabView` 隐藏网页子视图。
3. 保留地址建议、书签栏和分享对话框的现有遮挡策略；它们不是系统原生菜单，不能安全复用此实现。
4. 创建标签时将 `is_incognito` 传入 `WebviewBuilder::incognito`。
5. 添加菜单行为的前端回归测试，并执行前端构建与 Rust 检查。

## 不在本次范围

- 将全部自定义覆盖层改为原生窗口或右侧面板：涉及书签、下载、Cookie、分享等多处 UI，需单独统一交互设计。
- 为任意远程网页开放 Tauri IPC：这会扩大远程内容权限，应改用受限的原生桥接方案另行设计。
- 调整广告拦截脚本：关闭时恢复网络 API 的问题需要 WebView 端到端测试，不能与菜单修复混合修改。

## 方案

功能菜单点击后，前端使用 `@tauri-apps/api/menu` 创建系统菜单并在鼠标位置弹出。系统菜单处于子 WebView 之上，不依赖 DOM 的 z-index，也不触发 `webview.hide()`。

非 Tauri 运行环境保留当前 Radix 菜单作为测试和浏览器开发回退。菜单项的可见性、勾选状态和回调与现状一致。

`BrowserTabView` 的覆盖层状态继续只服务于地址建议、书签和分享对话框；原生功能菜单不会写入该状态。

Rust 创建 WebView 时追加 `.incognito(is_incognito)`，使“无痕模式”从界面标识变为底层会话配置。

## 验收标准

- 在 Tauri 环境点击“选项”会调用系统菜单弹出，而不会调用网页子视图隐藏逻辑。
- 每个现有菜单动作仍触发原有回调；勾选项保持正确状态。
- 无痕标签创建的 WebView 带有 `incognito(true)`。
- 新增测试先在旧实现下失败，修改后通过；前端构建与 `cargo check` 通过。
