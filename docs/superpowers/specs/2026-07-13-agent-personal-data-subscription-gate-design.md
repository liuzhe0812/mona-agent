# Agent 个人数据订阅权限设计

## 目标

将“Agent 查询用户个人工作上下文”设为订阅核心权益。未订阅或已过期用户仍可使用基础 Agent、笔记和邮件界面，但 Agent 不得搜索或读取已有笔记、邮件；有效试用与有效订阅均可使用完整能力。

## 已确认的产品边界

| 能力 | 免费/过期 | 有效试用/订阅 |
| --- | --- | --- |
| 手动查看和编辑笔记、邮件 | 可用 | 可用 |
| Agent 新建笔记、保存笔记图片 | 可用 | 可用 |
| Agent 搜索、读取已有笔记 | 禁用 | 可用 |
| Agent 搜索、读取、操作邮件 | 禁用 | 可用 |
| Agent 从统一记忆搜索笔记、邮件来源 | 禁用 | 可用 |
| Agent 从统一记忆搜索浏览器、聊天来源 | 可用 | 可用 |

受限工具为 `notes_search`、`notes_read`、`email_search`、`email_read`、`email_action`。`notes_create` 与 `notes_save_image` 保持免费。

## 方案选择

采用“工具清单过滤 + 执行前共享拦截 + 统一记忆来源过滤”。仅在界面隐藏无法阻止工具调用；启动时直接注销工具又不能及时响应购买或到期。共享工具注册表在每轮对话开始时刷新本机订阅状态，既不向模型暴露受限工具，也在执行入口拒绝残留或重放的调用。

未采用逐个工具复制会员判断，因为容易漏掉新增调用路径。未禁用整个 `hoard_search`，因为浏览器和聊天记忆仍属于免费能力。

## 架构与数据流

1. Rust License 模块提供只读取本机可信状态的 `license_has_access` IPC 命令，不接收前端传入的会员布尔值，也不在 Agent 每轮对话中发起网络请求。
2. 本机状态按现有规则判断：有效导入 License、有效服务端缓存、有效本地试用均返回可用；缺失、过期、设备不匹配或读取失败均返回不可用。
3. Agent 每轮构建模型上下文前读取一次状态，并更新共享 `ToolRegistry`。
4. `ToolRegistry` 不向模型返回标记为订阅专属的工具定义；执行入口对同一标记再次检查，避免历史工具调用或手工调用绕过。
5. 免费状态调用 `hoard_search` 时，查询层排除 `note`、`email` 来源，同时过滤结果里的同类关联来源。显式指定这两个来源时返回订阅提示。
6. 免费状态的模型上下文加入一条简短能力说明：不得声称已经查询笔记或邮件；用户提出此类请求时说明需要订阅；仍可按用户要求新建笔记。

## 错误与降级

- License 状态不可读取时失败关闭，按未订阅处理，不泄露个人数据。
- 受限工具执行返回稳定的 `membership_required` 错误和可读提示，不伪装成“没有搜索结果”。
- 统一记忆过滤发生在数据库查询阶段，避免先取回个人数据再在展示层丢弃。
- 本次边界针对 Mona 官方个人数据工具和统一记忆入口；不扩展为通用文件系统或终端沙箱改造。

## 测试与验收

- 工具注册表在免费状态隐藏并拒绝订阅工具，订阅状态恢复工具；普通工具始终可用。
- 笔记查询和全部邮件工具标记为订阅专属，笔记创建与图片保存不带该标记。
- 统一记忆查询可在 SQL 层排除 `note`、`email`，并不返回同类关联来源。
- License IPC 对有效试用/订阅返回 `true`，对过期、缺失和异常返回 `false`。
- 运行相关 Python 测试、Rust 测试与项目构建；若仓库既有失败与本次无关，单独记录原始输出，不修改无关代码。

## 非目标

- 不改变笔记和邮件页面的免费使用权限。
- 不增加新的会员等级、额度系统或远程授权服务。
- 不重构现有 License、Agent 或 Hoard 模块的无关部分。
