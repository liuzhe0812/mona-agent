# 笔记知识点提取功能方案设计

更新时间：2026-05-28

## 目标

在通用笔记模块内增加“提取知识点”能力：用户在笔记里记录资料、想法、工作内容或复制外部文档后，可以让 Agent 从当前笔记中提炼 1-5 个候选知识点。用户确认后，再把有价值的知识点保存到笔记模块内的知识视图。

这个功能不替代笔记。笔记保留原始内容和上下文，知识视图只保存可复用、可检索、格式统一的知识点。

## 核心判断

知识库不应该把整篇笔记全文复制过去。

原因：

- 原始笔记经常包含临时想法、聊天记录、无关上下文和未确认内容。
- 知识库的价值是沉淀稳定结论，不是再存一份原始材料。
- 知识条目保留“关联笔记”，需要上下文时可以跳回原笔记。一个知识点可以关联多篇笔记，用来表达同一知识在不同场景下的应用、补充材料或后续更新。

因此知识条目只保存 AI 提炼后的结构化内容：

- 标题
- 精简内容总结
- 关联笔记，可多篇
- 来源链接 / 来源说明
- 最后更新时间
- 标签，限制 1-4 个，优先复用已有标签

## 分类原则

知识分类不能固化成运维或技术分类。

处理规则：

- 首次初始化只提供一个 `未分类`，不预置固定分类列表。
- AI 根据笔记内容返回 `categoryName`。
- 提取前会把当前已有分类路径发给 Agent，但只在主题、学科或技术域高度一致时复用已有分类。
- 如果已有分类只是宽泛相关或明显不属于同一领域，Agent 必须创建新的多级分类路径。
- 技术类内容必须从技术领域归类，例如模型量化应进入 `技术/人工智能/模型量化` 这类路径，而不是归到教育技术。
- 如果返回的是新分类，前端自动创建分类；如果 `categoryName` 带 `/`，会按路径创建多级分类。
- 分类支持多级层级，分类数据只保留名称和父级关系，不维护描述。
- 用户后续可以手动新建一级分类、在任意分类下新建子分类、重命名分类、删除分类、把知识点移动到其他分类。

这样可以覆盖通用笔记场景，比如工作资料、读书摘录、产品想法、会议记录、技术资料、生活记录等，而不是强行套到运维分类里。

## 交互设计

笔记模块有两个子视图：

- `笔记`：现有笔记编辑视图。
- `知识`：结构化个人知识库视图。

右侧 Agent 面板提供：

- `总结当前笔记`
- `提取知识点`

流程：

1. 用户打开一篇笔记。
2. 点击 `提取知识点`。
3. Agent 读取当前笔记内容、已有分类路径和已有标签，输出严格 JSON。
4. 前端在本次 `提取知识点` 回复完成后解析 JSON，并自动打开候选知识点确认弹窗。
5. 候选卡片只展示标题、推荐分类、精简内容总结和标签。
6. 用户点击候选卡片里的保存后，按 AI 返回的分类写入知识视图；点击忽略则丢弃该候选。
7. 如果分类不存在，自动创建分类；如果分类名带 `/`，自动创建多级路径。
8. 如果同一分类下已经有同名知识点，不重复创建页面，只把当前笔记追加为关联笔记。
9. 保存后切换到知识视图，并选中知识所属分类。
10. 用户可以在知识卡片里直接查看精简总结、调整分类、编辑删除，或点击关联笔记跳回原始笔记。

## 知识视图

知识视图采用两栏结构：

- 左侧：知识分类目录。
- 右侧：当前分类下的知识卡片列表。

左侧分类目录支持：

- 新建一级分类。
- 在当前分类下新建子分类。
- 重命名当前分类。
- 删除当前分类。

删除分类时不删除知识点。分类里的知识点会移动到父级分类或剩余分类，子分类会向上移动，避免误删内容。

右侧知识卡片支持：

- 查看标题、精简内容总结、标签、来源笔记、更新时间。
- 显示该知识点关联了几篇笔记。
- 直接打开关联笔记，不再进入二级详情页。
- 在卡片内编辑、删除、调整分类。

## 知识卡片

分类页直接展示知识卡片，不再通过“点进去详情页”查看知识。知识卡片只展示 AI 提炼后的精简总结，不复制整篇笔记。

卡片显示：

- 标题
- 精简内容总结
- 标签
- 关联笔记按钮
- 最后更新时间
- 分类下拉
- 编辑、删除

从知识卡片打开关联笔记后，笔记编辑器顶部显示返回入口，可以回到刚才的知识分类页。

这样知识视图更像个人知识库，不像复制了一份笔记原文。

## AI 输出协议

`提取知识点` 要求 Agent 只输出一个 JSON 对象，不输出 Markdown 代码块，不解释。

字段：

```json
{
  "items": [
    {
      "categoryName": "由笔记内容所属领域决定的多级分类路径；需要层级时用 / 分隔",
      "title": "知识点标题",
      "summary": "精简内容总结，2-5 句话，只保留笔记里最值得沉淀的内容，不按固定格式拆分",
      "sourceDescription": "来源链接或来源说明",
      "tags": ["标签1"]
    }
  ]
}
```

约束：

- `categoryName` 先判断内容所属领域，再判断已有分类是否高度匹配。
- 只有主题、学科或技术域高度一致时，才复用已有分类路径。
- 如果已有分类不匹配，必须创建新的多级分类路径。
- 不整篇复制原文，不大段搬运笔记，只提炼可复用知识点。
- 不编造笔记里没有的信息。
- 如果笔记里有多个稳定知识点，可以返回多个候选，但最多 5 个；不要为了凑数拆分。
- `summary` 只写精简内容总结，不拆成“为什么值得保存、关键概念、适用场景、注意事项”等固定分区。
- `tags` 必须是 1-4 个。
- 提取前会把当前已有标签发给 Agent；如果已有标签里有可用标签，必须优先复用，确实没有合适标签时才新增。
- 标签使用领域级或主题级词，不用过细的参数、型号、缩写、版本号堆标签。

前端只会解析本次 `提取知识点` 触发后的 Agent 回复，不会扫描历史回复。解析失败时提示用户，不保存知识点。解析成功也不会直接入库，必须由用户在候选卡片里确认保存。

## 存储设计

继续复用笔记模块的 Tauri SQLite 存储，不新建独立知识库服务。

新增数据：

- `knowledgeCategories`
- `knowledgeItems`
- `activeKnowledgeCategoryId`

后端新增表：

- `knowledge_categories`
- `knowledge_items`

知识条目通过 `sourceNoteId` 关联首个原始笔记。即使原始笔记后续变更，知识条目也保持当时提取出的稳定内容。

为支持一个知识点关联多篇笔记，知识条目增加 `linkedNotes`：

- `noteId`
- `noteTitle`
- `description`
- `linkedAt`

`sourceNoteId` 保留为首个来源；后续同类笔记通过 `linkedNotes` 追加，不自动覆盖已有精简总结。

## 不做内容

第一版不做：

- 向量索引。
- 跨知识库问答。
- 自动批量提取。
- 自动覆盖已有知识。
- 富文本编辑知识条目。

这些都放到后续增强，不影响第一版可用。

## 验收标准

- 右侧 Agent 面板同时存在 `总结当前笔记` 和 `提取知识点`。
- 点击 `提取知识点` 会发送结构化 JSON 输出要求和当前已有分类路径给 Agent。
- Agent 回复后生成候选知识点卡片，不在回复卡片里显示 `保存知识点` 按钮。
- 用户在候选卡片里点击保存后，知识视图出现对应分类和知识目录项。
- AI 返回新分类时，系统自动创建分类；支持用 `/` 创建多级分类路径。
- 用户可以新建一级分类、新建子分类、重命名分类、删除知识分类。
- 用户可以把知识点移动到其他分类。
- 分类页以知识卡片形式显示标题、精简内容总结、标签、关联笔记、更新时间。
- 知识卡片内可以直接调整分类、编辑、删除，并打开关联笔记。
- 再次提取同一分类下同名知识点时，不新建重复详情页，而是把当前笔记追加到该知识点的关联笔记里。
- 从知识卡片打开关联笔记后，可以一键返回知识视图。
- 候选确认使用弹窗；关闭弹窗后，如仍有待处理候选，右侧输入框上方保留入口可重新打开。
- 关闭重开后知识分类和知识条目仍然存在。
